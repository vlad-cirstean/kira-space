## 1. Root cause and verified signals

Status today, end to end:

- TUI session: Claude hooks, shim, Go `/hook` (`internal/harness/claude/hooks/http.go` `handleHook`), `harness.AgentEvent`, then fan out:
  `bridge.EmitAgentEvent` (`kira:agent:event`), `ade.Tracker.HandleEvent`, `agentnotify.Notifier.HandleEvent` (wiring: `apps/kira-space/internal/appwire/wire.go` `wireTracker`).
  Frontend reduces events in `packages/workbench/src/state/agentActivity.ts` `reduceAgentActivity` (store `createAgentSessionsStore.ts`, keyed by terminal id).
  `apps/kira-space/frontend/src/ade/v2/activity.ts` `withTuiActivity` copies the reducer phase into `Session.activity`; `activityKind` maps it to `ActivityKind`.
- Headless session: `TaskBoard.Sessions` / `toWireSession` (`apps/kira-space/internal/ade/runs.go`) sets `activity` `working` while the run process lives.
- Enum today: wire `activity` `'' | input | working | waiting | idle`; `ActivityKind` `input | working | waiting | idle | stopped`.

Bug: TUI only. `reduceAgentActivity` sets `idle` on main-turn `Stop`. Notifier posts "finished" on that same `Stop`.
Headless is not affected: `claude -p` stays alive until every background task ends (verified), so the run stays `working`.

Verified against real CLI 2.1.322 (TUI in tmux, and `-p` stream-json), recording below in §4 fixture:

- `Stop` payload carries `background_tasks: [{id, type: "shell"|"subagent", status: "running", description, command}]` and `session_crons`.
- `SubagentStart`/`SubagentStop` carry `agent_id` (same id as the subagent's `background_tasks` entry) and `agent_type`.
  `SubagentStop.background_tasks` still lists the stopping subagent as `running`.
- Subagent tool hooks (`PreToolUse`/`PostToolUse`) carry `agent_id` and arrive after the main `Stop`.
- Each finished background task triggers a follow-up main turn: `UserPromptSubmit` then `Stop` with a refreshed list. Last `Stop` has `background_tasks: []`.

Mobile `apps/kira-space/frontend/mobile/state/useAgentsModel.ts` uses `withTuiActivity`: same result, no extra work.

Backend `Tracker` (`apps/kira-space/internal/ade/tracker.go`), new per-record in-memory state under `mu`:

- `background map[string]int` set from `Stop`/`SubagentStop`; `wake map[string]bool` (set on main `PreToolUse` with `Wakes`, cleared on `UserPromptSubmit` and `Stop`).
- `HandleEvent` calls `OnChange` when the background count changes (so the wire `background` reaches windows and mobile).
- `func (t *Tracker) Background(recordID string) int`. `forgetLocked` deletes both maps.
- `TaskBoard.Sessions` / `toWireSession`: TUI rows fill `Background` from `Tracker.Background`.

`adewire.Session` (`apps/kira-space/internal/bridge/adewire/wire.go`) and `wire.ts` `Session` gain `background: number` and `unseen: boolean`.

Notifier (`apps/kira-space/internal/agentnotify/agentnotify.go` `HandleEvent`): `Stop` with `Background > 0` posts no finished note; ignore events with `AgentID != ""` for wake arming. The final `Stop` (`background_tasks: []`) posts as today.

Edge cases, decided:

- No timeout. Long jobs (dev servers, watchers) are real work; the session shows working while they live. This is the asked behaviour.
- Count clears on: next main `Stop` (authoritative list), `SubagentStop`, `SessionEnd`, terminal exit (`forgetLocked`), app restart (in memory; PTYs die with the app).
- Restart/resume: a resumed TUI starts at 0; Claude does not resume background tasks.
- Interrupted subagent or killed shell with no following turn: count stays at its last `Stop` value until the next `Stop`/`SessionEnd`/exit.
  Record in ARCHITECTURE Known open items (stuck-running edge). Never guess with a timer.
- Waiting on monitor plus background: `waiting` wins (not idle-looking, more specific).

## 4. `unseen` status

Definition: session finished its work (TUI: main `Stop` with background 0 and no wake armed; headless: run ended `done`, `failed` or `stuck` except a user `StopRun`) and the user has not viewed the session since.

Persistence, migration `apps/kira-space/internal/storage/migrations/0098_p610_session_unseen.sql`, style of 0097:

```sql
-- P610: finished-not-viewed marker for an ADE session; 0 means seen.
ALTER TABLE ade_sessions ADD COLUMN unseen_at INTEGER NOT NULL DEFAULT 0 CHECK (unseen_at >= 0);
```

Regenerate: `go test ./apps/kira-space/internal/storage -run "TestKiraSchema|TestSchemaSnapshot" -update` (kiraschema plus `testdata/schema.sql`).

- `model.AdeSession` gains `UnseenAt int64`. `adesessions.go`: add column to `adeSessionsSelectColumns`/`scanAdeSessionRow`; new `SetUnseen(id string, at int64) error` and `ClearUnseen(id string) (bool, error)` (true when a row changed).
- `StopAllTaskRunning` and `MarkStopped` leave `unseen_at` alone: unseen survives restart.
- Set, TUI: `Tracker.HandleEvent` on main `Stop` with `Background == 0` and wake not armed: `Store.SetUnseen(recordID, nowMs)` then `OnChange`.
- Set, headless: one helper `b.stopHeadlessSession(sessionID string, now int64, out outcome)` in `runs.go` replacing the three copies (`runs.go` `recordOutcomeLocked`, `rebase.go`, `reviewstep.go`): `MarkStopped`, then `SetUnseen` unless `out.noAdvance` (user stop), then `notifySessions`.
- A new busy turn does not clear it; display precedence hides it while busy, next finish overwrites it.
