## Findings (codegraph, checked against source)

- Today (`links/AdeLinkStrip.vue`): each pill is `RovingFocusItem > PopoverTrigger as-child >
  AdeLinkPill`, so click and Space toggle the card. Enter calls `useTaskLinks.openLink(item)`:
  `changeRequest` goes to `useOpenChangeRequest` (`hostview/queries.ts`: `control.hostViewOpen(url)`,
  on refusal or failure `control.openExternal(url)`); every other kind goes to `control.openExternal`;
  no url does nothing. Card title (`AdeLinkCard.openTitle`) calls the same `openLink`. Card footer has
  `AdeLinkOpenExternal` (testid `ade-details-open`).
- Platform modifier: `packages/workbench/src/shortcuts/keys.ts` exports `isPrimaryModifier(e)` (Cmd on
  mac, Ctrl elsewhere, UA sniff) and `primaryModifierName()` ('Cmd' | 'Ctrl'). Used by
  `AdeNotesEditor` (Cmd-click opens a link externally), `CollectionsTree`, `terminalRenderer`. Reuse
  both; no new detection. The UI harness runs a macOS user agent: specs use `modifiers: ['Meta']`
  (as `terminal-file-links.spec.ts`).
- In-app targets that exist:
  - Host view window (`HostViewService.Open`, `hostview/HostViewWindow.vue`): a change request link of
    a registered git host (PR/MR view), or an issue key or link a registered tracker parses and
    can show (`issueProvider`: Jira today, `IssueView.vue`). Anything else is refused
    (`notViewable`). `useOpenHostView` (no fallback) is what `AdeTaskIssueLine.viewIssue` uses,
    with the key when the Jira slot has no url; it also marks the task's `issue` tracked update seen.
  - Branch panel (`AdeBranchPanel`, `ui.selectBranch(taskId, branchId)`): only for a task branch row.
    A branch link carries no branch id: a detected branch artifact (`repoArtifacts`) has title = name,
    url = host tree url (may be ''), ref = worktree path; a stored branch is a pasted url. In the stage
    and Run dialogs the panel sits behind the modal (P613 hid the session button there for the same
    reason).
  - No in-app web view or browser exists (no webview/iframe surface; `window.open` does nothing in
    the Wails webview, ARCHITECTURE terminal links). Not invented here.
- Deployment links (`deploymentArtifacts`) have no url: title = env, ref = short sha.
- Detected issue `PAY-10` in the `ade-details-links` contract has no url, ref `PAY-10`.
- `LinkItem` has no `ref` field; Jira slot label is the key, host slot label `hostLink.ref`.
- `PopoverAnchor` exists in `@theme/components/ui/popover` (46 callers).
- Guards: U22 bans native `title=`; U91 bans a tooltip around truncated text, so the pill gets no
  hover tooltip. `AdeLinkStrip.vue` already has U47 and U62 exemptions (focus moves); the new
  focus return stays under U62.

## Decision per kind

"In app" = host view window. Click = in app where a target exists, else browser. Cmd-click
(Ctrl-click off mac) = browser always. No url and no in-app target = the click opens the card (the
only thing left to do), so no click is dead.

| Kind (origin) | Click | Cmd-click | No in-app target: fallback |
|---|---|---|---|
| issue, Jira slot | issue view: url, else key (`useOpenHostView`); marks the `issue` tracked update seen, as View issue does | browser (url); no url: card | url refused: browser (built-in fallback of `useOpenChangeRequest`); key refused: card |
| issue, stored or detected | issue view: url, else ref | browser (url); no url: card | GitHub/forge issue urls and any tracker without an issue view are refused by `Open`, so they land in the browser; ref refused: card |
| changeRequest (host slot, stored, detected) | PR/MR view (unchanged) | browser | refused (host not registered, not a CR link): browser |
| host slot, any other kind | as its kind | browser | as its kind |
| branch | browser | browser | no in-app target from every place the strip shows (see open question) |
| deployment | card (no url) | card | no url, no target |
| doc | browser | browser | no in-app web view |
| link | browser | browser | no in-app web view |

Kinds with no in-app target, reported to the orchestrator: branch, deployment, doc, link. Their plain
click equals Cmd-click (browser), or opens the card when there is no url.

## Card reach: right-click plus keyboard

Picked: no new visible element. The card opens on:

- right-click on a pill (`contextmenu`; also Ctrl-click on mac, Shift+F10 and the Menu key, which
  browsers deliver as `contextmenu` to the focused pill);
- Space or Alt+Down on a focused pill;
- F2 (card with editor, edit mode) as today;
- a plain click on a pill with nothing to open (deployment, urlless ref-less item).

Why: zero pixels, strip height unchanged, keyboard parity kept (Space was the card key already),
right-click is the app's existing "more on this item" gesture (task cards, `useTaskMenu.open`).
Rejected: hover-revealed info button (reserves width on every pill, so lines wrap sooner and height
grows, or shifts layout on hover; also a second tab stop per pill or an unreachable mouse-only
target); pill tooltip hint (U91: the label is `TruncatedText`); header-line hint text (noise in every
place the strip shows). Edit, remove and kind recategorise stay in the card unchanged; Delete on a
focused pill still removes.

Screen readers: one `sr-only` hint per strip (`ade-links-hint`, id from `useId()`), referenced by every
pill's `aria-describedby`: "Enter opens the link. {modifier}+Enter opens it in the browser. Space
shows its details." (`modifier` = `primaryModifierName()`).

## Changes

### `links/useTaskLinks.ts`

- Add `useOpenHostView` (key or ref, no fallback), `useTaskUpdates` (`pending`) and
  `useMarkTrackedSeen` (both shared/cheap; `useTaskUpdates` is a `createSharedComposable` already on
  the board).
- Replace `openLink(item)` with:

```ts
/** Opens a link: in the host view where one exists, else in the browser; `external` always browser.
 *  Returns false when nothing can open (no url and no in-app ref): the caller shows the card.
 *  `onRefused` runs when the view refuses a urlless ref (no browser fallback without a url). */
function openLink(item: LinkItem, opts: { external?: boolean; onRefused?: () => void } = {}): boolean
```

  Rules, in order: `external` → `item.url ? openExternal(url) : false`. `item.origin === 'jira'` →
  mark `issue` seen when `pending(taskId, 'issue')` (same call as `AdeTaskIssueLine.viewIssue`).
  Kind `changeRequest` or `issue` with url → `useOpenChangeRequest` (view, browser on refusal). Kind
  `issue` without url, with `item.ref` → `useOpenHostView.mutateAsync(ref)`, `.catch` →
  `opts.onRefused?.()` (log through `fireAndForget` as today). Else url → `openExternal`. Else
  `false`. Log scopes: `hostView.open` and `ade.links`.

### `links/linkGroups.ts`

- `LinkItem` gains `ref: string` (in-app lookup key): artifact `a.ref`; Jira slot `jira.key`; host
  slot `task.hostLink?.ref ?? ''`.

### `hostview/queries.ts`

- Doc comment of `useOpenChangeRequest` only: "a change request or issue link". Name and code
  unchanged (AdeBranchPanel and useTaskLinks keep calling it).

### `links/AdeLinkStrip.vue`

- `PopoverTrigger as-child` becomes `PopoverAnchor as-child` (anchor only: click no longer toggles).
  The pill carries what the trigger set: `aria-haspopup="dialog"`, `:aria-expanded="openKey ===
  item.key"`, `:data-state="openKey === item.key ? 'open' : 'closed'"` (open ring style keeps
  working), plus `:aria-describedby="hintId"`.
- Pill listeners: `@click="onPillClick($event, item)"`, `@contextmenu.prevent.stop="openCard(item)"`.

```ts
function onPillClick(e: MouseEvent, item: LinkItem): void {
  const opened = links.openLink(item, {
    external: isPrimaryModifier(e),
    onRefused: () => openCard(item),
  });
  if (!opened) openCard(item);
}
```

  `openCard(item)` = `setOpen(item.key, true)`.
- `onKeydown`: Enter → `onPillKey(e, item)` with the same body (`external: isPrimaryModifier(e)`),
  `preventDefault`. Space (`' '`) → `preventDefault`, `openCard(item)`. Alt+Down unchanged. F2,
  Delete, `+`, Up/Down unchanged. If WebKit still fires the button click after a prevented Space
  keydown (spec below catches it), add `@keyup.space.prevent` on the pill; no other workaround.
- Focus return: with no trigger, `PopoverContent` does not focus the pill on close. Add
  `@close-auto-focus` on `PopoverContent`: unless the close came from a pointer outside (reka marks
  that `defaultPrevented`), `preventDefault()` and focus the pill
  (`root.querySelector('[data-key="…"]')`, `CSS.escape` the key). Esc keeps returning focus to the
  pill (existing spec).
- `<span :id="hintId" class="sr-only" data-testid="ade-links-hint">` with the hint text, inside the
  root, rendered only when there is at least one pill.
- Top comment: "A pill click opens the link in the app (host view) where it can, else in the browser;
  Cmd/Ctrl-click opens it in the browser. Right-click, Space or Alt+Down open its card."
