## 1. Current browse, end to end

- Entry `Server.browseTable` (`apps/kira-space/internal/dbmcp/browse.go`). Gate order: `resolveBrowse`
  (resolve, `HasBrowse` kind check, masked verdict, `checkBrowseShape`), table allow list
  (`allowedPath`), connect, `describeRelation` (kind from parent listing), `maskStateFor`,
  `planBrowse` (`browseRules.project`, `filter`, `order`), `browsePlan.preview`, `browseCall`
  (preview is the bound SQL, mode masked), `claimExemption`, `planBrowseCall` (EXPLAIN of preview
  when `McpAutoExplain` and `queryplan.HasRowEstimate`), `checkLimits`, `awaitExemption` or
  `awaitApproval`, allow list re-check, `executeBrowse` (re-plan, preview must match, `ExecLimit.Apply`
  sets `StatementTimeout` and `TimeoutByEngine`, `Query.Browse`, `execHits` to `refuseByLimits`),
  `renderBrowsePage`, result review (`reviewForMode`).
- `Router.Browse` (`apps/kira-space/internal/adapterhost/browse.go:31`): range check, read lane only
  (`laneKinds`), `RunOp` kind `read` with `Timeout` and `TimeoutGrace`, `adapter.Read` with an offset
  cursor and `Conditions`.
- Browse kinds: postgres, mysql, mariadb, sqlite, clickhouse (`browseKinds`, `permissions.go`; TS
  mirror `BROWSE_KINDS`). Others refuse with "has no structured browse". Unchanged by this phase.
- Limits in place: 50 `in` values, 1000-rune strings, no NUL, offset 0 to 100000, limit 1 to 100,
  20 filters, 5 order terms, 200 columns.
- Masking rules: masked column takes only `isNull`/`notNull`, no order; withheld column refuses as
  filter or order and leaves the projection; view refused on a connection with masking.
- Adapter order today: relational adapters (`PlanRelationalPage`, `ComputeEffectiveOrder`) append the
  tiebreaker (PK, else first unique key, else sqlite rowid) only when directions are uniform and no
  requested column is nullable; it dedups columns already in the sort. ClickHouse has no unique key
  (`PrimaryKey` empty, `unique` false), orders by sorting key else every column, offset only.

## 3. Count design

### Plan and preview

- `browsePlan` gains `count bool`. `planBrowse`: when `sh.count`, skip `project` and `order`
  (no "every column withheld" refusal: a count returns no column), run `filter` as today, skip the
  stable-order step (section 4). View rule unchanged.

  text; no ORDER BY, LIMIT or OFFSET.
- `browseTable`: `rv.maxRows = 1` when `plan.count`, else `plan.limit`.
- EXPLAIN, `checkLimits`, approval (preview shows the count statement), exemption claim, statement
  timeout and result review run unchanged on the count preview. A count of a big table with no
  selective filter is refused as `expensive_query` like a row read; the exemption path lifts it.
- `claimExemption` masked-mode text (`limits_gate.go`): `same connectionId, path, columns, filters,
  order, limit and offset.` becomes `same connectionId, path, columns, filters, order, limit, offset

## 4. Paging design

- Offset paging on all five kinds, kept. Declined keyset/cursor: the preview is what EXPLAIN plans
  and what the exemption binds; an opaque cursor cannot be previewed, and the rows-read estimate
  (`queryplan` max scan rows) ignores LIMIT/OFFSET, so keyset would not change the plan check.
  ClickHouse has no keyset support (`noKeysetMessage`) anyway.
- Keep `browseMaxOffset = 100000` and the 100-row cap.
- Stable order: new `browseRules.stabilize(p *browsePlan)` called at the end of `planBrowse` for a row
  read (not count):
  - key = `meta.PrimaryKey` when non-empty, else the first `meta.Indexes` entry with `Unique` whose
    columns are all `Nullable == false` in `meta.Columns`; else none.
  - none, or any key column masked or withheld: append nothing, `p.stable = false`, `p.pagingNote`
    as below.
  - else append each key column not already in `p.sort.Terms`, direction = last requested term's
    direction, else `asc`; create `p.sort` when nil. `p.stable = true`.
  - The order-term cap (5) applies to requested terms only.
  - Appended terms change the preview: an unordered browse of `people` now previews
    `... ORDER BY "id" ASC LIMIT 50 OFFSET 0`. `TestDbMcpBrowsePrompt`'s pinned `wantSQL` already
    orders by `id`, so it stays unchanged. The adapter dedups a tiebreaker already in the sort.
- `browsePlan` gains `stable bool` and `pagingNote string`. Notes:
  - no key: `no primary or unique NOT NULL key: rows with equal order values can repeat or be skipped across pages; filter on a unique column to page instead`
  - masked or withheld key: `the key column is masked, so it is not added to the order: rows can repeat or be skipped across pages`
- `browseResult` (`render.go:1037`) gains `Order []browseOrder \`json:"order,omitempty"\`` (the
  effective terms, from `p.sort`), `StableOrder bool \`json:"stableOrder"\``, `PagingNote string
  \`json:"pagingNote,omitempty"\``.
- Offset cap in `renderBrowsePage`: when `HasMore` and `offset + RowCount > browseMaxOffset`, leave
  `NextOffset` nil, keep `HasMore` true, set `PagingNote` to `next offset passes 100000: continue with a gt or lt filter on the last row's order value and offset 0` (joined with any existing note by
  a space).
- Known pre-existing gap, record only (docs, section 7): with no requested order, or ties on a
  requested order, the relational adapters' own tiebreaker sorts by the PK even when the PK is
  masked, so row order reveals the masked key's order. Fix needs an adapter-level opt-out; out of
  scope.

## 5. Descriptions and arguments (`internal/llmprompts/registry.go`)

### `DbmcpToolBrowseTable` Default, full new text

```
Example: {"connectionId":"c1","path":"<from list_children>","filters":[{"column":"status","op":"in","values":["open","held"]}],"order":[{"column":"id","direction":"asc"}],"limit":50}. Use it for every plain read of one table or view, no SQL: rows, a row count, or pages. Options: columns; filters, all ANDed: eq, ne, lt, lte, gt, gte, like, isNull, notNull, and in with up to 50 values; order; limit up to 100 rows; offset paging: while hasMore, pass nextOffset back as offset; count: true returns the matching row count instead of rows. The table's key is appended to the order so pages do not overlap; stableOrder false says it could not be. Use run_query only for joins, grouped aggregates or expressions. Masked columns stay masked and can only be filtered with isNull or notNull, never sorted. Columns withheld until masking is reviewed are left out and listed. Needs the connection's masked access (list_connections). A call whose plan estimates at least expensiveQuery.rowsThreshold rows read, or that passes the statement timeout, is refused with an exemption id: filter or order on an indexed column, narrow the scope, or repeat the exact call with `exemption` to ask the user to lift that limit once. The user always decides.
```

Not for plain row reads: use browse_table (rows, counts, in filters, pages). Run one statement per call, not a script, for joins, grouped aggregates or expressions.

### Changed and new `browse_table` arguments

- `filters.op`: `eq, ne, lt, lte, gt, gte, in, like, isNull or notNull. in matches any of values. like: % and _ are wildcards.`
- `filters.values`: `The values for in, 1 to 50: matches rows equal to any of them.`
- `order`: `Sort terms in priority order. At most 5. The table's key is appended when it has one, so pages are stable.`
- `offset`: `Rows to skip, 0-100000. For the next page pass the previous nextOffset; past 100000 filter on the last order value instead. Default 0.`
- `count` (new `arg(DbmcpToolBrowseTable.id, "count", ...)`, required: `InputSchema` panics on a
  schema property without an arg entry): `true returns count and exact for the rows the filters match, instead of rows. Takes filters only: no columns, order, limit or offset. Default false.`
- `exemption`: `Only after a limit refusal: asks the user to lift that limit for this exact call. Same connectionId, path, columns, filters, order, limit, offset and count as the refused call.`
- Unchanged: `connectionId`, `path`, `columns`, `filters`, `filters.column`, `filters.value`,
  `order.column`, `order.direction`, `limit`, `exemption.id`, `exemption.reason`, every `run_query`
  arg.
