## 2. Decisions

- Names: `ui (Linux)` and `db-compat (Linux)`. Neither equals any leg name (`ui (Linux, shard N/8)`,
  `db-compat (Linux, min|max)`) or any other job name; all 12 job names stay distinct.
- Job ids copy the test-matrix pair (`test-matrix-group` matrix, `test-matrix` aggregate): matrix
  job `ui` becomes `ui-shard`, aggregate takes id `ui`; matrix job `db-compat` becomes
  `db-compat-extreme`, aggregate takes id `db-compat`. Check names come from `name:`, so renaming ids
  changes no leg's check name; artifact names (`playwright-report-ui-N`) unchanged.
- `needs: <matrix job>`, `if: ${{ !cancelled() }}`: the aggregate runs even when a leg failed, so
  it reports failure instead of "skipped" (a skipped required check counts as passing). A
  superseded or hand-cancelled run skips it, as today for `test-matrix (Linux)`.
- Assertion: `test "$RESULT" = success` on `needs.<id>.result`. A matrix job's result is `success`
  only when every leg succeeded; failure, timeout or cancel of any leg fails the aggregate.
- `runs-on: ubuntu-24.04`, `timeout-minutes: 5`, one step, no checkout, no setup: same as
  `test-matrix (Linux)`.
- `pr-rerun-flaky.yml`: `gh run rerun --failed` reruns failed jobs plus their dependents, so the
  aggregate reruns with its failed legs and reads the carried-over passed legs. No change needed.
- Cost: one short job after the last shard, about 10-30 s queue plus a few seconds run on the ui
  critical path. Accepted: it is what makes one stable name possible.
- Header comment line 15 generalises to every aggregate.
- Not changed: `scripts/db-compat.sh` header (`pr.yml` `db-compat`, min and max jobs) and
  `cache-warm.yml` line 177 (`pr.yml` `ui`) stay accurate enough; no edit.
