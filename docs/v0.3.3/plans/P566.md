## 1. Before: critique of the current page

Looked at real-shot builds (`bun run screenshots`, then `site:build`), Chromium, 390 x 844 and 1280 x 800, viewport-sized sections.

- No identity. Palette is near-black plus grey cards, a faint green tint and one blue button. Nothing ties the page to the app: the icon's sky-blue, sparkles and cat never appear beyond a 28 px header logo.
- Hero is a template. Left-aligned title, grey summary, three buttons, one flat window. Aurora blobs are so dim they read as noise. A stray grey tagline line sits above the eyebrow and repeats the summary. The h1 "Kira Space" says nothing about what the app does.
- Hero shot is small and alone (about 890 px of 1280), caption "Agents board. Tasks across stages, runs live." in grey under it. No depth, no layering, no glow worth noticing.
- "What you get" is 11 identical grey cards: same size, same green icon tile, same grey text. On phone it is 11 full-width cards, about 2300 px of near-identical scrolling. Zero visuals of the product.
- "Build with Kira" teaser is one more grey card with a thin gradient rim; the plan-to-proof story, the product's strongest idea, looks like a footnote.
- Highlights alternate text and a window at about 520 px wide: shots too small to read, big empty gutters, thin divider lines. Same rhythm three times.
- Install is three stacked grey boxes; terminal glow is barely visible. The page ends flat.
- Rhythm: every section is the same dark ground, same 16 px grey body, same h2 size. No bright or tinted section, no type contrast beyond the h1.
- Phone: hero shot renders at about 320 px wide, so the UI is unreadable; feature list dominates the page.

Reference feel: Linear, Raycast and Warp launch pages (centred display headline, big layered product shot with perspective and glow, bento grid, full-bleed marquee band, scroll-held story), but in Kira's own colours from the app icon.

## 4. Motion rules

- Everything under `@media (prefers-reduced-motion: no-preference)` or `motion-safe:`. Under reduce: `document.getAnimations()` is empty, nothing starts hidden or offset (existing test).
- Scroll-driven animation (`animation-timeline: view()`) only inside `@supports (animation-timeline: view())`; without support, layout is final and visible.
- Animate `transform` and `opacity` only. Exception: the rotating gradient border animates a registered `@property --angle` (one small element per section, 8 s); register it with `@property --angle { syntax: '<angle>'; inherits: false; initial-value: 0deg; }`.
- Infinite animations allowed only for: hero mesh drift (existing), sparkle twinkle, status-dot pulse, marquee, gradient-border spin, hero chip float. All slow (6 to 40 s), all motion-safe. Marquee pauses on `:hover` and `:focus-within`.
- Reveal motion stays vertical (`translateY`, `scale`): horizontal offsets break the image `box.x >= 0` check.
- Cursor-tracking spotlight declined: it needs pointer coordinates, so client JS. Hover glow is a static radial layer faded in on `:hover`.
- Library check: Motion (MIT) and GSAP ScrollTrigger (now free, but needs a client script) both break zero client JS; CSS covers every effect here. No new dependency.
