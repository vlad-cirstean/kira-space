## 2. Performance

### 2.1 Probe

There is no committed fps probe in `site/tests`; P566 measured ad hoc. Use this script from the scratchpad (not committed: it is a measurement, not a test). Serve the build with `cd site && bunx astro preview --host 127.0.0.1 --port 4391`, then `node probe.mjs <webkit|chromium> <path> <width> [ablation]`. Ablation is a selector to hide, or `css:<rules>` to inject.

```js
import { chromium, webkit } from '<worktree>/node_modules/@playwright/test/index.mjs';
const BASE = 'http://127.0.0.1:4391/kira-space/';
const [engine = 'webkit', path = '', width = '1280', ablate = ''] = process.argv.slice(2);
const w = Number(width);
const browser = await { webkit, chromium }[engine].launch();
const ctx = await browser.newContext({
  viewport: { width: w, height: w < 500 ? 844 : 800 },
  deviceScaleFactor: w < 500 ? 2 : 1,
});
const page = await ctx.newPage();
await page.goto(BASE + path, { waitUntil: 'load' });
if (ablate) await page.addStyleTag({ content: ablate.startsWith('css:') ? ablate.slice(4) : `${ablate}{display:none!important}` });
await page.waitForTimeout(1500);
console.log(JSON.stringify(await page.evaluate(async () => {
  const fps = (t) => { const d = t.slice(1).map((x, i) => x - t[i]); const s = [...d].sort((a, b) => a - b);
    return { fps: +(1000 / (d.reduce((a, b) => a + b, 0) / d.length)).toFixed(1), p95ms: s[Math.floor(s.length * 0.95)] }; };
  const idle = await new Promise((r) => { const t = []; const s = performance.now();
    const k = (x) => { t.push(x); x - s < 2000 ? requestAnimationFrame(k) : r(fps(t)); }; requestAnimationFrame(k); });
  const t = []; const H = document.documentElement.scrollHeight - innerHeight; let y = 0;
  await new Promise((r) => { const k = (x) => { t.push(x); y += 40; scrollTo(0, y); y < H ? requestAnimationFrame(k) : r(); }; requestAnimationFrame(k); });
  return { idle, scroll: fps(t), anims: document.getAnimations().length, imgs: document.images.length };
})));
await browser.close();
```

Idle is 2 s of rAF at the top (infinite animations only). Scroll moves 40 px per frame to the bottom (scroll-driven animations, lazy images, paint). WebKit numbers are noisy (plus or minus 5 fps between runs): run each case 3 times and take the median.

### 2.3 Diagnosis (WebKit ablations on `/`)

Single runs, so read the large effects only (noise is about 5 fps). Selectors hide a block; `css:` rules strip one property or loop.

| Ablation | 1280 idle | 1280 scroll | 390 idle | 390 scroll |
|---|---|---|---|---|
| none (baseline) | 37 | 14 | 19 | 11 |
| every animation off | 62 | 42 | 61 | 33 |
| every `box-shadow` and `filter` off | 37 | 34 | 20 | 20 |
| hero backdrop hidden | 43 | 15 | 46 | 12 |
| bento hidden | 42 | 20 | 23 | 13 |
| `breathe` and blob `drift` off | 51 | 14 | | |
| `pulse-dot` off | 33 | 18 | | |
| `gradient-text` sweep off | 42 | 18 | | |
| marquee off | 43 | 14 | | |
| twinkle and float off | 33 | 13 | | |
| `pulse-dot`, sweep, border spin, `breathe`, `drift` off plus every `filter` off | 61 | 46 | 58 | 40 |

Reading:
- Infinite loops set idle cost; filters and coloured shadows set scroll cost. Together they explain nearly all of it: the combined row reaches every-animation-off idle and beats its scroll.
- Biggest single loop cost: `breathe` (opacity on a masked conic layer) and blob `drift` (40rem gradient blobs moved with `will-change`; WebKit in the sandbox composites in software). Backdrop hidden gives the biggest gain at 390 (19 to 46 idle).
- Paint-bound loops (`pulse-dot` on `box-shadow`, `gradient-text` on `background-position`) each cost a few fps; with 9 dots and 6 gradient headings they add up.
- Marquee, twinkle and float (transforms on small or narrow layers) are cheap: keep.
- Chromium holds 60 fps in every case: the problem is WebKit paint and software compositing, which iOS Safari shares in spirit.

### 2.4 Fixes

In order of measured gain. Each is CSS or markup only.

1. Remove the bento minis (section 1): drops 9 `pulse-dot` loops, the caret blink, SVG `drop-shadow` filters on 9 commit dots, about 300 DOM nodes.
2. Hero: one shot, no chips, no back windows, no `drop-shadow` filter, no masked conic `breathe` glow (section 1.2). Hero eager images go from 3 to 1.
3. Paint-bound infinite loops become static. `pulse-dot` animates `box-shadow`, `gradient-text` animates `background-position` under clipped text, `gradient-border` animates a registered `--angle` into a `conic-gradient`, `breathe` animates opacity on a masked layer: each repaints its box every frame in WebKit. Keep the look, drop the loop: `gradient-text` keeps its gradient without `animation`; `gradient-border` keeps a static conic rim (delete `@property --angle` and `spin-border` if no user is left); `pulse-dot` and `breathe` go with their last users.
4. No `mask-image` on large layers (already an ARCHITECTURE rule, still broken in four places): `HeroBackdrop` grid, `HeroStage` glow (removed in 2), `Story` shot glow, `Install` icon ring. Replace each with a `radial-gradient` fill fading to transparent; for the grid, overlay a `radial-gradient` from transparent to `--kira-bg` above it.
5. No CSS `filter` on large or many elements: drop `drop-shadow-[…]` on the header logo, `Story` sparkle nodes and `/build/` step sparkles (a static glow is a `box-shadow` on a small element, or nothing).
6. Hero backdrop: remove the SVG turbulence noise layer (full-width data URI filter); blobs become static (drop `animate-drift-a`, `animate-drift-b`, `will-change-transform`, delete the keyframes); cut sparkles to 4 on phone.
7. Remaining infinite loops after 1 to 6: sparkle twinkle, Install icon float, marquee. Each is a `transform` on a composited layer. Keep them unless the probe shows one still costs over 3 fps; then make it static and record why.
8. Images: hero `fetchpriority="high"`; every other shot `loading="lazy" decoding="async"`. Add an 800 px WebP derivative (`framedThumb`, `getImage` width 800) to `ResolvedWindowShot` and every window `srcset` (`800w, 1136w, full`), so a 560 px bento tile at DPR 1 and a 375 px phone at DPR 2 decode 800 x 530 instead of 1136 x 752 (about half the pixels). ## 5. Clips of the real app: evaluation

Question: replace some stills with short loops of the real app.

- Capture. The shots run on a mocked runtime with a pinned clock: nothing moves by itself. A clip is a scripted sequence of states (type a query, run it, rows appear), so a frame sequence, not real-time video. Playwright `recordVideo` is real-time, ignores the pinned clock (frame timing varies per run, so not byte-deterministic), records the bare page without the macOS frame and at its own bitrate. A frame sequence fits the pipeline: `page.screenshot` per state, frame each with the existing `FRAME` compositor, join with sharp (`sharp(frames, { join: { animated: true } })`, already a dependency at 0.35.5). Deterministic like the stills. New code: a `clip` capture kind in `shotCapture.ts` plus `captureClip` beside `captureShot`, file `anim/<id>.webp`, a fill rule in `shots-fill.ts`, a `<picture>` in `ShotPicture`.
- Format. Measured with sharp on a real shot at 1136 px, lossy q80: still 29 KB; 24 frames with a small moving change 44 KB; 4 frames that each change the whole window 102 KB. An MP4 or WebM would be about the same size, but `<video autoplay muted loop playsinline>` cannot honour `prefers-reduced-motion` without JS (autoplay ignores it, and `<source media>` was dropped for video), and needs a codec step (Playwright's ffmpeg build is capture-only). Animated WebP in `<picture><source media="(prefers-reduced-motion: no-preference)" srcset="anim.webp"><img src="still.webp"></picture>` is zero-JS, shows the still under reduce, and visual tests (reduced motion) keep the still. GIF: 256 colours, 5 to 10 times larger: no.
- Cost. Bytes are fine (under 110 KB per clip). Runtime is the problem: an animated image repaints its whole box every frame while visible. On this page the measured cost of always-on painted layers the size of the hero is 15 to 20 fps in WebKit (section 2.3), and the hero is visible at load. Browsers pause animated images offscreen, so story or bento clips cost only while in view. iOS autoplay rules do not apply to images.
- CI. No workflow change: the shot cache key already covers `apps/kira-space/tests/screenshots/**`, `packages/**` and `shotCapture.ts`. Capture time grows by about 2 s per clip.
- Recommendation: defer. Reasons: the mocked runtime yields slideshows of 3 to 5 states, not live motion; each clip re-adds the continuous paint this phase removes (target 35 fps scroll in WebKit leaves no room for a hero clip); the pipeline work (new capture kind, framing per frame, fill, picture element, tests) is a phase of its own. If the user wants it anyway, the cheapest real candidate is one story chapter, `studio-sql-console` (query typed, run, rows appear: 4 states, about 100 KB), as its own later phase after this one lands and meets its fps target.
