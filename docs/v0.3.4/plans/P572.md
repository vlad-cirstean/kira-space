## Findings (from code)

- Native About exists. `internal/shell/menu.go` `AppMenuHead()` puts `application.About` first in
  the App menu. Wails v3.1.0 renders it as an `NSAlert` (`pkg/application/dialogs_darwin.go`
  `showAboutBox`): title `Options.Name`, informative text `Options.Description` (main.go:124 already
  appends `Version <buildinfo.Version>`), app icon. Plain text only, no clickable link, no hook for
  one. A link there is not possible without forking Wails.
- No in-app About surface: no Settings pane, dialog or window. Settings nav is
  `apps/kira-space/frontend/src/state/settings.ts` `sections`; labels and panes in
  `apps/kira-space/frontend/src/workbench/SettingsDialog.vue`; shell
  `packages/workbench/src/components/SettingsShell.vue` (nav testid `settings-section-<Section>`).
- Version already crosses the bridge: `AppService.Info()` (`apps/kira-space/internal/bridge/app.go`)
  returns `AppInfo{AppVersion, Go, Wails, KiraHome}`. Bound (`appwire.go:693`), binding generated
  (`@bindings/appservice.js`), mock channel present (`tests/ui/support/mockRuntime.ts:350`,
  `ipcChannels.ts:397`). No renderer caller yet. `UpdateService.Status` also carries
  `currentVersion`, but it is the update poll's concern, so not reused.
- Repo URL sources today:
  - Go: `internal/appupdate/checker.go` `repoOwner = "vlad-cirstean"`, `repoName = "kira-space"`
    (unexported, feed `latestReleaseURL`). `internal/appupdate/install.go` `InstallScriptURL` holds
    its own literal; `scripts/verify-packaging.sh` S11 pins that exact literal, so it stays.
  - Frontend app: none.
  - Site: `site/src/data/nav.ts` `REPO_URL`, `site/astro.config.mjs` `REPO_URL` (Astro build, cannot
    read Go). Out of scope, noted in ARCHITECTURE.
- Kira Studio is no longer a separate app (`apps/` holds only `kira-space`). Settings is one dialog;
  Studio sections are panes inside it. Studio is not affected beyond the shared catalog key move below.

## Decisions

1. Where: new Settings section `About`, last in the nav (after `Experimental`). Native About menu
   stays as is: it cannot hold a link. Plain URL text in its Description would not be a link, so no.
2. URL source: export one Go constant composed from the existing owner/name, no new literal:
   `internal/appupdate/checker.go`: `RepoURL = "https://github.com/" + repoOwner + "/" + repoName`
   in the existing `const` block, with a one-line doc comment. `AppInfo` gains
   `RepoURL string \`json:"repoUrl"\``, set to `appupdate.RepoURL`. Renderer never hard-codes it.
3. Opening: `control.openExternal(info.repoUrl)` (existing `createOpenExternal` wrapper over
   `LinkService.OpenExternal`, which validates http(s) shape and announces a failure). Never
   `window.open`, never an `<a href>`: a shadcn `Button` (`variant="link"`, `size="inline"`).
4. Data fetch: TanStack Query, `useQuery({ queryKey: ['appInfo'], queryFn: () => control.appInfo(),
   staleTime: Infinity })`. Info is constant per process. No Pinia store (no shared client state).
5. Pane contents only: heading app name, version, GitHub link. No Go/Wails/home rows (not asked).
6. Copy (catalog rules C3/C4 reject duplicate text, C6 sentence case, C7 no period on label/aria):
   - App name heading: reuse `common.product.kiraSpace.label` ("Kira Space").
   - Version row label: "Version" already exists only as `docker.engine.version.label` (one caller,
     `packages/docker-ui/src/components/EngineOverview.vue:123`). Move it to `common.version.label`
     (C3 says one key), update that caller. Do not reuse `memory.common.version.label`
     ("Version {version}"): different meaning (fact version).
   - New: `space.settings.nav.about.label` = "About";
     `space.settings.about.github.label` = "GitHub" (row label);
     `space.settings.about.github.aria` = "Open the repository on GitHub".
   - Loading: reuse `common.state.loading`. Error: `errorText(query.error.value)` from
     `@workbench/bridge/codedError`, no new key.
   - Implementer greps `en.json` for each new text first; on a C3/C4 hit, reuse the existing key.
