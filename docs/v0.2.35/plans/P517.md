# P517 Multiple worktrees per repo, agent-named branches, branch rename

Ask (user): "creating a new worktree should allow for multiple worktrees for the same repo as a task
can have multiple branches in the same repo. Also the worktree name is a nanoid but the branch name
is required by the mcp tool and chosen by the agent. Also this tool should allow the agent to rename
existing branches with a dialog to approve for me."

Wave B stream, beside P515 and P516. Runs after wave A (P512, P513, P514) lands, so it builds on their
tree. Migration `0075`; 0070 belongs to P512, 0071-0074 stay unused.

## Current model (CodeGraph-verified)

Task, repo, branch, worktree.

## Design

### Schema: `0075_p517_worktree_dir.sql`

```sql
ALTER TABLE ade_task_branches ADD COLUMN worktree_dir TEXT NOT NULL DEFAULT '';
```

Add `{Version: 75, File: "0075_p517_worktree_dir.sql"}` to `storage/migrations/embed.go`.

`worktree_dir` holds the row's reserved folder name `wt_<10 chars>`. Folder name no longer depends on
branch name, so rename never moves a folder and predictions become exact.

- Model: `AdeTaskBranch.WorktreeDir string`. Add to column list in `queryBranches`, `scanAdeTaskBranch`,
  `insertTaskBranch`.
- `repos.ReserveWorktreeDir(ctx, branchID, dir) (string, error)`:
  `UPDATE ... SET worktree_dir = ? WHERE id = ? AND worktree_dir = ''`, then return stored value (first
  writer wins).
- `repos.ReplaceWorktreeDir(ctx, branchID, old, new)` for collision redraw (`WHERE worktree_dir = old`).
- Dir is reserved lazily, at first need (ensureWorktree, automation preview, rebase plan). Legacy rows
  stay '' until then.

### Nanoid helper: `ade/worktreedir.go` (new)

- `const worktreeDirPrefix = "wt_"`; `newWorktreeDirName() string` = prefix + `shortid.New(10)`.
- `validWorktreeDir` regexp `^wt_[0-9a-hjkmnp-tv-z]{10}$` (shortid alphabet). Check stored value before
  every path join; invalid value is replaced, never joined.
- `(b *TaskBoard) worktreeDirFor(ctx, sb, repo) (string, error)`: reserve if empty; path
  `<HomeDir>/wt/<safeSegment(repo)>/<dir>`; if path exists (Lstat) and is not this branch's worktree,
  draw new name, `ReplaceWorktreeDir`, retry up to 5 times.
- Single generator site so P523 folds it into the shared helper with registry prefix `wt`. Note this in
  a one-line comment.
- Remove `freePath`, `idPath`, `newBranchName.idFolder`, `newBranchName.generated`, `agentBranchPrefix`,
  `agentBranchIDLen`, `maxGeneratedNameTries`. `worktreeDir` (setup.go:226) calls `worktreeDirFor` for
  every creation path (user, agent, attach, rebase, automation). Prediction sites (automation.go:121,
  rebase.go:222) call it too; rebase.go:446 path replacement stays (now a no-op in practice; keep for
  rows whose existing worktree lives elsewhere).
- `WorktreeBasePath` stays ignored, as today. No repo settings read (P513 seam).

- `RemoveTaskRepo` (281): already removes every row of the repo; verify loop, no change expected.
- `DeclareRepos`: unchanged (declares a repo once; more branches come from `request_branches`).
- `attachExistingBranch` (board_writes.go:433): fills a draft of that repo if one exists, else
  `AddBranch`. Already correct once the AddBranch check goes.
- `spaceInfo` (agenttools.go:144): already one `TaskRepo` per row; add `Branch` disambiguation text
  in tool description only.
- Frontend: `usedRepoIds` in `AdeMainBranches.vue` and `AdeTaskBranchForm.vue` become
  `draftRepoIds` (repos with a draft row). Add repo can add a second branch in a used repo; the new row

### MCP `request_branches`: agent names every branch

Args (registry `HeadlessToolRequestBranches` schema, `RequireNonEmpty`):

```json
{"branches": [{"repo": "<nick>", "branch": "<name>"}]}
```

1..20 items, both fields required, dedupe by (repo, branch). Drop `repos`. Description: agent picks a
descriptive branch name; several branches per repo allowed; folder is chosen by Kira.

`planRepo` becomes `planItem(repo, branch)`:

- Live row on this task named `branch` with a worktree: outcome `existing`.
- Live row named `branch`, no worktree: `worktree` item.
- `branch` exists in git (local or remote) but not on this task: `failed`, text "branch exists outside
  this task; pick another name or ask the user to attach it".
- Otherwise `checkNewBranchName`, then `branch` item with base (same base logic as today).
- Each item gets id `i<n>` (index in request). `requestSlot` keyed by item id, not codeRepoID.

`createApproved`: per approved item, fill that repo's draft row if any, else `AddBranch` with
`Origin = agent`, `Name = branch`; then `ensureWorktree` with `newBranchName{wanted: branch}`.
Result list keeps one `RequestedBranch` per item (`repo`, `branch`, `outcome`, `worktree`).

`branchDecision.approved` becomes `map[itemID]bool`. `ApproveBranchRequest(id, itemIDs, renameRemote)`.

### MCP `rename_branch` (new)

Args: `repo`, `from`, `to` (required), `renameRemote` bool (optional, default false; user can change
it in the dialog). Tool id added to `agentmcp/tools.go`, description and schema
`HeadlessToolRenameBranch` in `llmprompts/registry.go`, method `RenameBranch(ctx, SpaceCall, args)` on
`SpaceTools`.

Flow reuses the branch-request queue (same prompt kind, run note, 30 min wait, deny, timeout).
Factor the wait loop of `RequestBranches` into `awaitBranchRequest(ctx, call, req) (branchDecision,
outcome)`; both tools call it. Request holds one item kind `rename`.

Refusals at plan time (and again in phase 3, under lock):

- No live mine row on this task named `from` in `repo`.
- `from` is repo main, an integration branch, or protected.
- `to` fails `checkNewBranchName`, or exists in git (local or remote) or on any live row.
- Open change request for `from` (`resolveRepoHost` + `ResolveBranchChangeRequest`): rename would
  detach the PR; text tells agent to ask the user.
- Live run or TUI session sandboxed on the branch (`sandboxTargets`, session sandbox map), except the
  calling run when it is not bound to that ref. Its Seatbelt `ownRef` is fixed, so rename would lock it
  out.
- Running rebase (`RunningRebaseOn`), active step run (`HasActiveStepRunOn`), or setup on the row.

Apply on approve (under task lock, phase 3):

1. Re-run refusals.
2. gitsession `branchRename` op on repo root (rewrites stack-children config already). Worktree folder
   stays (`wt_...`), checkout follows the rename.
3. `repos.RenameBranch(ctx, branchID, from, to)` in one tx: set `name`; set `base = to` on rows of the
   same repo stacked on it (by `base_branch_id`, or `base = from` when id is empty); same for
   `base_pending_from`. On error, run `branchRename to from` to roll git back and return `failed`.
4. Upstream:
   - none: `remote = untracked`.
   - upstream `R/from`, `renameRemote` approved: push `to` with `SetUpstream`, then
     `deleteRemoteBranch R/from`. Push failure: `remote = failed`, local rename stays, upstream unset.
     Delete failure: `remote = failed` with text naming the stale remote branch.
   - upstream `R/from`, not approved: unset upstream via new `UnsetUpstream bool json:"-"` on the
     `branchRename` op (`git branch --unset-upstream`), `remote = kept` (old remote branch stays).
   - upstream `R/other`: keep, `remote = kept`.
   - Protected confirm never applies (refused above).
5. Task `HostURL` equal to old branch URL and remote renamed: rewrite to new URL.
6. Op log entry `opBranchRename` with from, to, remote outcome. Board change event.

Result: `{repo, from, to, outcome: renamed|denied|failed|timeout, remote: renamed|kept|untracked|failed,
worktree, next}`.

Not rewritten (risk list): stored artifact URLs, session history labels, `review_session` rows
(orphaned until idle sweep).

## Risks

- Breaking MCP schema (`repos` removed). Agents mid-session hold stale schema; schema error message
  says to re-read the tool. Commit 3 carries `!`.
- Rename refused with open PR: agent must ask user. Deliberate; GitHub cannot move a PR head.
- Rename refused while a sandboxed run holds the ref; user must stop it first. Matches "sandbox fixed
  at start".
- `review_session` rows and stored artifact URLs keep old branch name; orphaned review sessions clear at
  idle sweep. Listed in Known open items.
- Lazy dir reservation racing two writers: `WHERE worktree_dir = ''` plus re-read makes first writer
  win.
- Folder collision on disk (left-over dir): Lstat check and redraw, capped at 5 tries, then error.
- Real `claude` tests cost tokens; run once.
- Migration numbering: 0071-0074 skipped (gaps allowed by `LoadMigrations`). Later phases above 0075.
