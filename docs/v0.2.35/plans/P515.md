## 2. Design

### 2.1 Backend: one change

`model.ParamValues.MarshalJSON`: one value as a JSON string, else an array (`scripts.StringList.MarshalJSON` twin).
Doc comment: "Mirrors UnmarshalJSON so a decoded file round-trips in its own shape."

Why: form value and YAML file then share one shape (`mode: ci`, `flags: [a, b]`), so `diffLeaves` sees no change
after an apply. YAML written by `RenderYAML` through `FileOf` (migration) also gets the scalar form.

Blast radius (check with `codegraph_explore ParamValues ScriptRef` before editing): JSON of a ref with a
one-value param changes from `["ci"]` to `"ci"`. Regenerate any contract that holds such a ref
(`repo-script-ref.json`, `ade-repo-script.json`, `repo-config-form.json`) with `KIRA_CONTRACT=write`, then rerun
`-count=2`. `UnmarshalJSON` already accepts both, so stored or bridged data stays readable.

No bound method, no rule change. Kind check stays run-time (P513 decision: `repocfg` has no scripts access).

### 2.2 Scripts list: Pinia store, not TanStack Query

Read the list from `useCustomScriptsStore().records`. TanStack Query declined, against a named requirement: the
list is a pushed snapshot (file watcher broadcast `onCustomScriptsChanged`) that one Pinia store already owns and
the workflow inspector already reads. A `useQuery` over `customScriptsList` would be a second cache of the same
list. It would miss pushes unless wired to that same event, which duplicates the store. The CLAUDE.md "one store,
one concern" rule holds: P515 adds no state to the store, only reads.

Normal scripts only: `records.filter((r) => r.kind === 'script')`. Ordered by collection then name, grouped by
collection as native `<optgroup>` inside `NativeSelect` (ungrouped first, label `common.ungrouped.label` or the
key the Automations panel uses; find it with `codegraph_explore AutomationsPanel ungrouped`).

### 2.3 Types and helpers

`repo/state/repoFormTypes.ts`:

```ts
export type RefParamValue = string | string[];
export interface RepoScriptRefValue {
  script: string;
  params?: Record<string, RefParamValue>;
}
```

New `repo/state/scriptRef.ts` (pure, no unit test: lookup plus shape mapping, CLAUDE.md test bar):

- `refParamsToForm(params) -> Record<string, string[]>` (string wraps to one-item list).
- `refParamsFromForm(values, script) -> Record<string, RefParamValue> | undefined`: keeps non-secret params of
  `script` only, drops empty, one value as string, more as list; `undefined` when none (key omitted).
- `normalScripts(records)`, grouped for the select.
- `refStatus(records, ref)`: first match of
  - `{ kind: 'ok', script }` (exactly one normal script named `ref.script`);
  - `{ kind: 'smart' }` (none normal, at least one smart);
  - `{ kind: 'missing' }`;
  - `{ kind: 'duplicate', count }`;
  plus `unknown: string[]` (params the script does not declare) and `secretGiven: string[]` (params given for a
  secret param). These mirror the run-time refusals, so the user sees them before a run fails.

### 2.4 Field table

`repo/state/repoFields.ts`, after the `prepare_script` spec:

```ts
{ path: ['worktree', 'prepare_run'], unsetWhenEmpty: true, clears: [['worktree', 'prepare_script']] },
```

Environments stay one list leaf; the row carries `deployed_sha_run` as part of the spread copy.

Model rule (both script slots): the model holds at most one of the pair.

- Typing a non-empty command sets the text and deletes the ref from the model.
- Picking a script sets the ref and deletes the text from the model.
- Picking "None" in the select deletes the ref.

`RepoConfigForm.vue`: `setPrepare(text)` and new `setPrepareRun(ref | undefined)` apply that rule on
`file.value.worktree`. `RepoEnvRow.vue`: `setScript` already drops the ref; add `setRun(ref | undefined)` that
drops `deployed_sha_script`. Edit order from `diffLeaves` (spec order) is then deterministic; the flow test and the
UI spec rely on it (section 3).

### 2.5 Components

`RepoScriptField.vue` (the seam; `<script setup lang="ts">`, Tailwind only):

- Models: `v-model` (command text), `v-model:runRef` (`RepoScriptRefValue | undefined`).
- `SecondaryTabs` with two items, Command and Run script (`${testid}-mode-command`, `${testid}-mode-run`), the
  `AdeStepAgentFields` mode precedent. Local `mode` ref: starts `'run'` when `runRef` is set, else `'command'`; a
  watch on `runRef` presence resyncs it (YAML edit, Discard, Reload).
- Switching mode alone writes nothing. Command mode shows today's Input or Textarea. Run mode shows
  `RunScriptRefPicker`.
- The old `scriptRef.hint` note goes; delete its i18n key (catalog lint C3 fails on unused keys).

New `repo/RunScriptRefPicker.vue`:

- `NativeSelect` (`variant="bordered"`, `${testid}-run-script`): "None" option (`''`) plus normal scripts by
  collection. A `runRef.script` that matches no normal script is kept as one extra disabled option showing its name,
  so a YAML-typed name is never silently replaced.
- Picking a script emits `{ script: name }`. Params reset, since the old ones belong to another script and would
  fail with "not a param of this script". Picking None emits `undefined`.
- Status from `refStatus`, as `FieldError` (`${testid}-run-error`):
  - smart: "“{script}” is a smart script: a repo file runs a normal script." The picker never lists smart
    scripts; this shows only for a name typed in YAML.
  - missing: "No Run script named “{script}”."
  - duplicate: "{count} Run scripts are named “{script}”. Rename one in Automations."
  - unknown params: "Not params of “{script}”: {names}." plus a Remove link (`${testid}-run-unknown-remove`)
    that drops them.
  - secret given: "{names} is a secret param: save its value in the script, not in the repo file." plus the same
    Remove link.
  These do not block Save. P514's rule stands: only a decode problem blocks form Save. Kind and params stay run-time
  checks (P513).
- Params: `ParamsForm` (`packages/workbench/src/automations/run/ParamsForm.vue`) over non-secret params only,
  wrapped in `div[data-testid="${testid}-run-params"]` so two pickers on one page scope their
  `run-param-input-<name>` testids. `v-model` maps through `refParamsToForm` and `refParamsFromForm`. Placeholder
  hint `FieldDescription`: "Empty uses the script's default."
- Secret params: `FieldDescription` (`${testid}-run-secret`) "Secret params use the value saved in the script:
  {names}." A required secret param with no saved value adds "Save a value for {names} in Automations." (from
  `savedSecrets`).
- Folder note (P513 risk "dir rule surprise"), `${testid}-run-dir`: `useAdeDir` on: "Runs in the worktree" (prepare)
  or "Runs in the repo folder" (environment, prop `place: 'worktree' | 'repo'`); off: "Runs in the script's own
  folder. KIRA_WORKTREE_PATH points at the worktree."
- No store gets empty: no normal scripts gives `InlineState kind="empty"` (`${testid}-run-empty`) "No Run scripts
  yet. Create one in Automations."

Layout: `RepoEnvRow.vue` keeps name and remove on the first line; `RepoScriptField` takes the row's full width
(`flex-col`). Header row label `space.repo.env.command.label` becomes "Deployed SHA" if the current label says
"Command"; keep the key, change text only if it misleads.

i18n (`packages/theme/src/i18n/en.json`, `space.repo.config.scriptRef.*` only): `mode.command.label`,
`mode.run.label`, `mode.aria`, `script.label`, `none.option`, `smart.error`, `missing.error`, `duplicate.error`,
`unknownParams.error`, `secretGiven.error`, `removeParams.label`, `defaults.hint`, `secretParams.hint`,
`secretUnsaved.hint`, `dir.worktree.hint`, `dir.repo.hint`, `dir.own.hint`, `empty`. Reuse existing common keys
where one fits (`common.state.none.option`). Remove `space.repo.config.scriptRef.hint`. Copy rules
(`scripts/copy/check-copy.ts`) apply.

## 8. Risks

- Edit-order coupling between Go args and the UI's `diffLeaves` output. Mitigation: the UI is the producer; the Go
  list is fitted to it (3.1).
- Debounce coalescing (`TIMING.preview`): two quick UI actions can merge into one form call and miss a contract
  key. The spec waits for each result before the next action.
- `MarshalJSON` changes recorded JSON in P513 contracts; regenerate and rerun both P513 halves.
- Store not hydrated (optional boot group failed): picker shows the empty state, and a set ref shows "missing".
  Acceptable: the YAML tab still edits the file and run time stays the authority.
- A script renamed in Automations breaks the ref; the picker shows "missing" with the old name kept, never a silent
  swap.
