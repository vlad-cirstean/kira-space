# P523 Id format: UUIDv7 keys, prefixed nanoid handles

Ask (user, SPEC row): "Every id Kira generates, of any kind, in the Kira apps is a nanoid with a short prefix. The
prefix names the feature the id belongs to. External ids (GitHub, Jira, Docker, etc.) stay unaltered." Plan decides:
inventory of all generators, one shared id helper and prefix registry per language, stored existing ids (migrate or
leave, with reasoning), lint guard against new unprefixed generators. Uses an existing nanoid library. Folds in
P517's `ade/worktreedir.go` helper (P517 plan: "P523 folds it into the shared helper with registry prefix `wt`").

Folds in the frontend id audit (former `P523-fe-ids-audit.md`, deleted; its per-site table is Appendix A). User
approved these folds:

- (a) The 10 MOVE sites leave the frontend inventory. Go mints those op ids; `opId` becomes optional in the
  Read, Count, Mutate and ObjectDownload wire `Validate`. Kibana already accepts an empty one.
- (b) Go rejects a client op id that is not a UUID (v4 or v7). `handleOpEnd` skips `Finish` when `Append` failed,
  so a reused id cannot overwrite history.
- (c) Both apps' `TabsRepo.Save` upsert only rows of the calling `window_key`; no takeover through `ON CONFLICT`.
  `appstorage.ValidateTab` and `terminal.ValidateOpen` get length and charset checks.
- (d) `packages/shared/ids.ts` stays, with 23 frontend callers. N14 bans bare `crypto.randomUUID`.
- (e) §3.4 corrected: Space `state/tabs.ts:70` is the pinned repo-graph tab; the terminal id is the tab id from
  `createTabsStore.ts:388`.
- (f) The 11 cancellable op ids stay client-minted (early cancel needs the id before `RunOp`).

## 0. Scope rules (user, override the row's wording)

The apps must scale onto a real DB server (Postgres) later. TEXT id columns get narrowed to native `uuid` there,
in a later phase, not now. Decision criterion for every generator site, in this order:

1. Secret, credential, token, or content hash: **keep** as is.
2. Stored in a pk or fk column (or an id column that a future `uuid` narrowing covers): **UUIDv7**. A prefixed
   text id cannot go in a Postgres `uuid` column, so a key is never a nanoid.
3. Machine-only identifier that crosses the bridge (IPC, MCP, HTTP, cross-process), not a key: **UUIDv7**.
4. An id the user touches or sees that is not stored in a key column: worktree dir and branch names, file and
   folder names, Docker names, values the user reads or edits in a file: **prefixed nanoid**.
5. Used only inside one DB as pk/fk with no bridge exposure: may stay **autoincrement** integer.
6. UUID an external tool requires: UUIDv7 when the tool accepts any UUID version (verified below), else v4.
7. Name-derived slug: keep.

A user-touched id that is also a key is flagged (section 4.2): keep the key a UUID and add a nanoid handle column
only if cheap, else keep as is with the reason.

Stored ids are never rewritten. Legacy v4 rows stay valid UUIDs; v4, v7 and legacy values coexist in TEXT
columns. No migration.

The orchestrator records these rules on the SPEC row when it accepts the plan.

Runs in parallel with P520 (approvals) and P521 (Scripts MCP) by orchestrator direction. SPEC line 7 still says
"then P523 alone"; the orchestrator updates that sentence when it accepts this plan. Section 7 keeps the three
conflict-free.

## 1. Facts (CodeGraph-verified, re-derived on the current tree)

  (`New(n)`, Crockford lowercase `0123456789abcdefghjkmnpqrstvwxyz`). Three shortid callers:
  `ade/worktreedir.go` (`wt_` + 10), `memory/ids.go` (`km_`/`kg_` + 12), `bridge/proofshots.go` (`shot_` + 12).
- JS: no direct `uuid` or `nanoid` dep. `nanoid@3.3.20` sits in `bun.lock` only as a `postcss` transitive.
- `google/uuid` is imported by 41 non-test Go files: 39 generate (all `NewString`, v4), 2 only parse
  (`memory/memorycli/run.go:39`, `mobileweb/idempotency.go:123`). ADE funnels 30 call sites through
  `TaskBoard.newID()` (`ade/board_writes.go:43`); `gitsession` funnels 7 through `newUndoID()` (`ops.go:996`);
  `connfiles` through `Options.newID()` (`loader.go:48`).
- Frontend: 32 non-test `crypto.randomUUID()` sites, plus a hand-rolled UUIDv4 (`newIntentKey`,
  `apps/kira-space/frontend/mobile/state/useAdeWrites.ts:12`, on `getRandomValues` for the plain-HTTP origin).
  10 of the 33 drop out (fold a); 23 remain (3.4).
- Op ids (Studio): `adapterhost.Host.RunOp` (`host.go:226`) mints an id when `OpSpec.OpID` is empty. The wires
  `ReadRequestWire`, `CountRequestWire`, `MutateRequestWire`, `ExecuteRequestWire`, `ObjectDownloadRequestWire`
  (`adapterhost/wire.go`), `bridge/http.go:69` and `bridge/grpc.go:223` refuse an empty one. Kibana
  `DataViews`/`DataView`/`Suggest` and gRPC describe already accept empty. No format or length check anywhere;
  `RunOp` and `Cancellable` refuse only an id still in `h.running`.
- Op id reuse overwrites history: `oplog.Wiring.handleOpStart` (`oplog/wire.go:168`) stores the op in `inFlight`
  before `Append`; a reused id fails the `INSERT` (logged only). `handleOpEnd` (`:218`) then runs `Finish`, an
  `UPDATE op_log ... WHERE id = ?` (`repos/ops.go:107`), over the earlier op's row.
- Op ids reach engines and logs: ClickHouse `query_id` `kira-<opId>-<n>`, Mongo `comment`, every adapter's
  `cancel(<opId>)` log line. Values are bound, so no injection; a newline can forge a log line.
- Early cancel: `CancelOp` remembers an unknown id for 5 s (`host.go:372`, capped at 1024). MCP
  `cancel_operation` uses `CancelRunning` (no early-cancel memory) and handles `run:<id>` before it, so a
  `CancelOp` UUID gate does not touch MCP.
- Tabs: both apps' `TabsRepo.Save` (`apps/*/internal/storage/repos/tabs.go`) upsert `ON CONFLICT(id) DO UPDATE
  SET ... window_key = excluded.window_key`. A save naming another window's tab id moves that row into the
  calling window. `appstorage.ValidateTab` checks only non-empty. The tab id is also the terminal id: it reaches
  `terminal.ValidateOpen` (non-empty only), `script_runs.terminal_id` and `KIRA_TERMINAL_ID`. No code path
  moves a tab between windows (CodeGraph: no cross-window move in `createTabsStore.ts` or the shell), so a
  scoped upsert breaks no feature. Every frontend tab id is `crypto.randomUUID()` today.
- Non-UUID random ids: `crypto/rand.Text` in Space `oplog/log.go:168` (op ids) and `oplog/foreign.go:55` (owner
  token); hex over `rand.Read` in `gitcred/relay.go:72` (credential prompt), `bridge/gitwindows.go:29` (git stream
  `ConnID`), `internal/docker/edit_apply.go:462` (temp container names), `bridge/memorydistill.go:254` (distilled
  file name). Every other `crypto/rand` user is a secret, token, key or certificate (3.6).
- Shape readers: `mobileweb/idempotency.go:123` (`uuid.Parse` + len 36) and `memorycli/run.go:39` (`uuid.Parse`)
  both accept v7 unchanged. Window-key dispatch reads the `proof-`, `files-`, `hostview-`, `capture-` text prefix,
  not the UUID part. `oplog.OwnerToken` splits a foreign op id at its first `.`. `flowtest/contract.go` `uuidRe` is
  version-agnostic hex, so it already matches v7.
- Truncation hazard: v7's first 8 hex digits are the timestamp. Three sites slice an id: Space
  `ade/v2/activity.ts:32` `shortId = id.slice(0, 4)` (display), `ade/v2/board/workflowForm.ts:48`
  (`step-` + 8 chars of a UUID), `flowharness/docker.go:36` (`uuid[:8]`). Slicing a v7 head collides within a
  millisecond, so none of them may slice a v7.
- External constraints, checked:
  - Claude Code 2.1.318 (installed at `/opt/node22/lib/node_modules/@anthropic-ai/claude-code/cli.js`):
    `--session-id <uuid>` "must be a valid UUID", checked by `/^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-
    [0-9a-f]{12}$/i`. No version nibble check, so v7 is accepted. The Space ADE real-`claude` row (section 6)
    confirms it end to end.
  - Jira ADF `localId`: a free string attribute in Atlassian's ADF schema; Kira sends a UUID by convention. v7
    is fine.
  - OpenCode assigns its own `ses_...` session ids (`SessionLocator`); Kira proposes none.

## 2. Helper and registry

- Go: new package `internal/ids` replaces `internal/shortid` (deleted).
  - `func NewID() string`: `uuid.Must(uuid.NewV7()).String()`. The one UUID generator in Go code. Doc: keys and
    machine identifiers; v7 sorts by creation time; the value fits a Postgres `uuid` column.
  - `func IsUUID(s string) bool`: any RFC 9562 version, so legacy v4 and new v7 both pass.
  - `type Prefix string`; one exported constant per nanoid kind (section 2.1), each with a doc comment.
  - `func New(p Prefix) string`: `string(p) + "_" + gonanoid.MustGenerate(Alphabet, p.size())`.
  - `func Is(p Prefix, s string) bool`; `func Body(s string) string`; `const Pattern` (regexp source for any
    registered nanoid) for the contract normalizer.
  - `init` panics on a duplicate prefix, a prefix outside `^[a-z]{2,4}$`, or a body length outside 10 to 21.
  - Name clash: several converted files have a local `ids` variable. Rename the local where it shadows the
    package in a converted function; do not alias the import.
- TS: new `packages/shared/ids.ts`.
  - `newUuid()`: `v7` from `uuid` (MIT, the standard npm UUID package, maintained by the `uuidjs` org). It uses
    `crypto.getRandomValues`, so it works on the mobile plain-HTTP origin where `crypto.randomUUID` is missing.
  - `isUuid(s)`, `PREFIXES`, `newId(p)` over `customAlphabet` from `nanoid` (v5, MIT), `isId(p, s)`, `idBody(s)`.
  - Add `uuid` and `nanoid` to `packages/shared/package.json`, pinned exactly (repo pins exact versions, e.g. zod
    `4.6.7`). Take the newest release at least two weeks old (`uuid` 11 or later has `v7`; `nanoid` 5.x). Do not
    lean on the undeclared `nanoid@3.3.20` transitive.
- Parity: new check-conventions rule `N13` compares `internal/ids/prefixes.go` (parsed by regex like N6 parses
  `codes.go`) with `PREFIXES`: same prefixes, same body lengths.

## 9. ARCHITECTURE notes (new section "Ids")

- Criterion: every id stored in a pk/fk column is a UUID, because TEXT id columns narrow to Postgres `uuid` later
  and a prefixed text id cannot go in one. New keys and machine identifiers are UUIDv7 (`ids.NewID()`,
  `newUuid()`): time-ordered, index-friendly, `uuid`-column compatible.
- Prefixed nanoid (`ids.New(ids.<Prefix>)`, `newId()`) only for ids the user touches that are not keys: folder,
  file and Docker names, YAML step ids, opaque handles. Registry in `internal/ids` and `packages/shared/ids.ts`,
  kept equal by N13. Kept bodies: `wt` 10, `km`/`kg` 12, `shot` 12.
- Never slice a UUIDv7 head: its first 48 bits are the timestamp. Display a UUID's last 4 characters.
- Integer autoincrement only for keys that never cross the bridge (gitreview, memory `seq`).
- Secrets, tokens and hashes keep their own `crypto/rand` encodings. External ids stay as the external system
  mints them. Claude `--session-id` accepts any UUID version (checked against the CLI's regex), so v7 serves.
- Stored ids are never rewritten: v4, v7 and legacy values coexist in TEXT columns.
- G6/N14 refuse raw UUID, nanoid and `rand.Text` generators outside the helpers.
- Known open items: the 4.2 table (key and id columns holding non-UUID values) blocks a `uuid` narrowing.
- Contract normalizer numbers any UUID and any registered nanoid as `<id:n>`; `wt` dirs as `<wt>`.
- Client-minted ids only where the id must exist before the call returns: cancellable ops (early cancel), tabs,
  stream and exec handles, idempotency keys, correlation tags, user-edited YAML step ids. Go mints the rest.
- Go checks every client id: op ids must be a UUID (`RunOp`, `Cancellable`; `CancelOp` ignores others); tab and
  terminal ids are 1 to 64 bytes of `[A-Za-z0-9_:-]`.
- An op whose `op_log` insert failed (a reused id) never runs `Finish`, so it cannot overwrite an earlier row.
- `TabsRepo.Save` writes only rows of the calling window; an id another window owns fails the save with
  `E_CONTRACT`.

## Out of scope, noted

From the audit. The user has not decided; not SPEC rows, not P523 work.

- Mobile pairing code: the phone chooses the 4-digit match code (`apps/kira-space/frontend/mobile/state/auth.ts:26`)
  and sends it in the long-poll `POST /api/pair`. Anyone who learns it can submit a second request with the same
  code and a forged label. Fix: a server-minted code per request, two-step flow (`POST /api/pair` returns
  `{requestId, code}`, then wait). Protocol change.
- Shared idempotency LRU: `mobileweb/idempotency.go` keys entries `device|key`, so replay stays device-scoped, but
  the 1024-entry LRU is shared. One paired device can evict others' entries and weaken their retry safety. No body
  binding: the same key on the same route replays the first result.
