# P523 Prefixed nanoid for every Kira-generated id

Ask (user, SPEC row): "Every id Kira generates, of any kind, in the Kira apps is a nanoid with a short prefix. The
prefix names the feature the id belongs to. External ids (GitHub, Jira, Docker, etc.) stay unaltered." Plan decides:
inventory of all generators (uuid, ulid, autoincrement-as-id, hand-rolled), one shared id helper and prefix registry
per language, stored existing ids (migrate or leave, with reasoning), lint guard against new unprefixed generators.
Uses an existing nanoid library. Folds in P517's `ade/worktreedir.go` helper (P517 plan: "P523 folds it into the
shared helper with registry prefix `wt`").

Runs in parallel with P520 (approvals) and P521 (Scripts MCP) by orchestrator direction. SPEC line 7 still says
"then P523 alone"; the orchestrator updates that sentence when it accepts this plan. Section 7 keeps the three
conflict-free.

## 2. Id format and registry

- Format: `<prefix>_<body>`. Prefix 2 to 4 lowercase letters. Body from the Crockford lowercase alphabet,
  12 characters (60 bits) by default. `_` is safe in file names, Docker names, URLs, CSS selectors and git refs.
- Kept as already shipped: `wt` body 10 (P517 dirs on disk), `km`/`kg` body 12, `shot` body 12.
- Collisions: 60 bits gives a 1-in-a-million collision only near 1.5 million ids of one kind. No retry
  loops, except the existing worktree-dir redraw (path collision, not id collision).
- Go: new package `internal/kid` replaces `internal/shortid` (deleted). `kid` avoids shadowing the many local
  `ids` variables.
  - `type Prefix string`; one exported constant per entity (section 3), each with a doc comment naming the
    entity.
  - `func New(p Prefix) string`: `string(p) + "_" + gonanoid.MustGenerate(Alphabet, p.size())`.
    `MustGenerate` only fails on bad arguments, which the registry rules out.
  - `func Is(p Prefix, s string) bool`; `func Body(s string) string` (text after the first `_` when kid-shaped,
    else `s`).
  - `const Pattern` (regexp source matching any registered id) for the contract normalizer and guards.
  - `func ExternalUUID() string`: the only `uuid.NewString` left. Doc: for ids an external tool requires as a
    UUID (Claude `--session-id`, Jira ADF `localId`).
  - `func IsLegacyUUID(s string) bool`: for the two validators that must still accept pre-P523 values.
  - `init` panics on a duplicate prefix, a prefix outside `^[a-z]{2,4}$`, or a body length outside 10 to 21.
    Every test binary that imports `kid` then fails loudly.
- TS: new `packages/shared/ids.ts`.
  - `PREFIXES` const object, same entries as Go.
  - `newId(p)` over `customAlphabet` from `nanoid` (v5, MIT, uses `crypto.getRandomValues`, so it works on the
    mobile plain-HTTP origin where `crypto.randomUUID` is missing).
  - `isId(p, s)`, `idBody(s)`.
  - Add `nanoid` to `packages/shared/package.json`, pinned exactly (repo pins exact versions, e.g. zod
    `4.6.7`). Take the newest 5.x at least two weeks old. Do not lean on the undeclared 3.3.20 transitive.
- Parity: new check-conventions rule `N13` compares the Go registry (`internal/kid/prefixes.go`, parsed by
  regex like N6 parses `codes.go`) with `PREFIXES`: same prefixes, same body lengths. Precedent: N6 error-code
  registry parity.

## 4. Stored ids and migration

### 4.1 Leave existing TEXT ids (no rewrite)

Existing UUIDs in Studio, Space and memory TEXT columns stay. New rows get kid ids. Reasons:

- No reader parses shape, apart from the validators listed in section 1. Those get legacy acceptance.
- A rewrite would chase every foreign reference: tabs JSON in settings, workflow YAML, run files, window rows,
  op logs, agent transcripts that quote ids, user notes. One missed reference orphans data, for no user value.
- Mixed formats only change tiebreak order in `ORDER BY ..., id` among equal keys. That is harmless.
- Legacy acceptance stays permanent:
  - mobile `Idempotency-Key`: a phone tab open across an upgrade still sends a UUID.
  - `--import-ref`: import rows stored before the upgrade.
  - Window-key dispatch keeps the old `proof-`, `files-`, `hostview-`, `capture-` prefix too. Those rows are
    "never restored", but a stale row from the old version must still be recognised at boot and not restored as
    a main window. The frontend `main.ts` check mirrors it.

No Studio or Space SQL migration for these. Studio 0058 stays P521's; no number clash.

### 4.2 gitreview integer ids (decision D1, recommended: convert)

- The row's inventory names "autoincrement-as-id", and the ask says "of any kind".
- A type change forces a table rebuild, so old values must change form here. Map them deterministically:
  - New gitreview migration `apps/kira-space/internal/gitreview/migrations/0007_p523_text_ids.sql` rebuilds
    `review_session`, `review_comment`, `review_removed` with `id TEXT PRIMARY KEY`.
  - Old ids become `'rvs_' || printf('%012d', id)`, `'rvc_' || ...`, `'rvx_' || ...`. Digits are in the
    alphabet, so they pass `kid.Is`.
  - `session_id` foreign keys use the same expression. Indexes and the AUTOINCREMENT `sqlite_sequence` rows go.
  - Implementer lists every table and column holding these ids (0003 pin, 0004, 0005 working) with
    `codegraph_explore` first.
- Code:
  - `gitreview.Comment.ID` and the session and removed ids become `string`; `LastInsertId` goes; inserts mint
    `kid.New`.
  - The AUTOINCREMENT "never reused" guarantee (comments.go:47) still holds: a random id is not reused.
  - Wire: `gitrpc` params and results, `packages/git-ipc` TS types, `packages/git-ui` comment state, ADE
    review comment tools (`ade/reviewcomments.go`), exports. Number becomes string.
- Migration test in the package's existing migration-test pattern: old rows survive with mapped ids and FKs
  intact.
- If the user declines D1: these three tables stay integer, listed under 3.6 as storage rowids, and the plan
  loses commit 6.
