# P522 Free-form API request MCP with agent credentials

Base: `chapter/v0.2.35` at `02e97e0c3` (P520 plan committed, P520 and P521 not yet implemented). Runs after P521
lands (shared files, section 9). One sequential Sonnet implementer, no streams.

## 0. Scope (user decisions)

- One free-form request tool. No access to saved requests: no list, get, run or save of collection items.
- The agent builds a request: method, URL, headers, query, body. It may reference environment variables by name
  (`{{base_url}}`, `{{token}}`).
- Each request is approved by the user in the P520 approvals surface, item kind `api.request`.
- Tools stay synchronous. No async, no handles.
- Credentials:
  1. A variable is usable by an agent only when marked available to agents. Opt-in, default off, per environment:
     the flag lives with the variable in the environment file. The agent sees names, never values.
  2. Each opted-in secret carries an allowed-host list, enforced per host. Default: the host of the environment's
     base-URL variable, when one exists.
  3. A credential bound for a host not on its list is blocked with an error to the agent. No prompt, so a
     click-through cannot leak a secret. The user edits the list in the app.
  4. The approval item lists "uses credential: NAME" with the value masked.
  5. Responses and echoes are masked with `secrets.Masker` (plus the placeholder replacer) before they reach the
     agent: headers, body, redirects, final URL. Size-capped.
  6. No reveal path for agents.
  7. Managed in the Environments view next to `ApiSecrets`, edited as form and YAML over one file (P514 pairing).
  8. A redirect to another host re-checks the host list. With a credential attached, an off-list hop is blocked.

## 2. Design

### 2.1 Environment file keys

Variable (environment files only):

```yaml
variables:
  - name: base_url
    value: https://api.example.com
    agent: true
  - name: token
    secret: ${secret:dev.token}
    agent: true
    agentHosts: [api.example.com]
agentAutoApproveReads: false   # optional, top level
```

- `agent: bool`, default false. Available to agents in this environment.
- `agentHosts: [string]`: only on a secret variable with `agent: true`. Required non-empty there.
- Host entry grammar, lowercased on decode:
  - `host`, `host:port`, `*.example.com` (subdomains only, not the apex), `[::1]:8080`.
  - A `http://` prefix allows plain HTTP for that entry.
  - Schema pattern plus Go rule `agentHostRule` (parses with `net/url`; IDNA via `golang.org/x/net/idna`, already
    a direct dependency through `publicsuffix`; rejects path, query, userinfo).
- `agentAutoApproveReads: bool` (top level, default false). See 2.5.
- Collection files reject `agent`, `agentHosts` and `agentAutoApproveReads`: their schema stays unchanged, and
  `additionalProperties: false` refuses them. Collection variables are never available to agents.
- Rules (`rules.go`, environment decoder):
  - `agentHostsRule`: `agentHosts` without `agent: true`, or on a plain variable, is a problem.
  - A secret with `agent: true` and no hosts is a problem: "add at least one allowed host".
  - Problem messages are i18n keys like the existing rules.
- `format.go`:
  - `Variable` gains `Agent bool \`json:"agent,omitempty"\`` and `AgentHosts []string \`json:"agentHosts,omitempty"\``.
  - `EnvironmentFile` gains `AgentAutoApproveReads bool \`json:"agentAutoApproveReads,omitempty"\``.
- No projection or migration change. The agent path reads the store's last good `EnvironmentFile`, the source of
  truth. New `Store.EnvironmentByID(id) (EnvironmentFile, string /*name*/, error)` (stem from `api_environments`)
  and `Store.EnvironmentList() []EnvironmentRef{ID, Name, Description, Color, File EnvironmentFile}`.
- `DuplicateEnvironment` copies the flags with the file. That is correct: it is the same file content.

### 2.2 New package `apps/kira-studio/internal/agentapi`

The policy and execution core. It imports `apifiles`, `apivars`, `httpclient`, `adapterhost`, `secrets`. Never
`bridge` or `dbmcp`.

- `hosts.go`: `type HostRule`, `ParseHostRule(s)`, `(HostRule).Allows(u *url.URL) bool`.
  - Exact hostname, or `*.` suffix match on a label boundary.
  - Port: when set, must equal the effective port.
  - Scheme: `https` always passes. `http` passes when the entry has `http://` or the host is loopback (`localhost`,
    `127.0.0.0/8`, `::1`).
- `policy.go`:
  - `type Available struct{ Name string; Secret bool; SecretRef string; Value string; Hosts []HostRule }`.
  - `Policy.Environment(id)` returns the environment name, colour, autoApprove flag and `map[name]Available` built
    from `agent: true` variables.
- `resolve.go`: `Resolve(env, req Input) (Planned, error)`.
  - `{{$...}}` (dynamic) is refused: "dynamic values are not supported here; send the literal value".
  - Every other `{{name}}` must be in `Available`. Otherwise: "variable X is not available to agents in
    environment E". The same text is returned whether X exists or not.
  - Plain variables resolve through `apivars.Resolve` with the plain values map. URL spans go through the URL
    sanitizer, so plain URL resolution matches the app's own.
  - Secret variables are recorded as referenced, not yet opened.
  - After plain resolution: parse the URL. Scheme `http` or `https` only. Host is required. Userinfo in the URL is
    refused (a credential must come from a variable).
  - Credential check: for each referenced secret, `Hosts` must allow the final URL. Otherwise an error naming the
    variable, the host and the allowed list. Never the value.
- `Planned` holds the method, the URL template with plain variables resolved and secrets left as `{{name}}`, the
  parsed URL, headers, query, body, referenced credentials and the environment. It is the approval payload source.
  No secret value is in `Planned`.
- `send.go`: `Send(ctx, Planned, Limits) (Result, error)`. Called after approval.
  - Re-reads the environment policy and re-runs `Resolve` on the original `Input`. A host removed or opt-in cleared
    during the wait blocks. Same rule as kube re-resolve after approval.
  - Opens every Api secret once (`apifiles.Secrets.All()`, new: `Store.Open(ScopeVariable, SecretOwner)`), resolves
    the referenced secrets with `apivars` pipelines through the `onResolved` callback, and collects `UsedSecret`.
  - Missing or unreadable secret: the existing `apivars` texts (secret name only).
  - Runs through `Router.Host().RunOp` with `OpSpec{Kind: "http", Source: MCP}`. `op.SetCommand(masker(method + " "
    + template URL))`, then `"→ status text"` on return. Never a resolved URL.
  - No response history row: the call has no saved item, and history is a user surface.
  - `httpclient.Options`:
    - `SSLVerify` true, always (user decision 2).
    - `RequestTimeoutMs` from `timeoutSeconds` (default 30, 1 to 300).
    - `MaxResponseMb` = the global setting, at most 5.
    - `FollowRedirects` from the arg (default true), `MaxRedirects` = global, at most 10.
    - `DisableCookieJar` false with `Ephemeral` true: a throwaway jar per call. No cookie crosses calls, and the
      shared app jar is never read or written.
    - `HTTPVersion` = global.
    - `WireMask` from the replacer.
    - `RedirectGuard` (new, 2.3).
  - Response masking, in order:
    1. `apivars.Replacer(used)` (moved from `bridge.secretReplacer`, 2.4): rendered forms to `{{name}}`.
    2. `secrets.NewMasker(all Api secret values...)`: any remaining plaintext of any Api secret to `••••`.
  - Applied to status text, every header value, the body (utf8 only), `FinalURL`, each redirect URL and error text.
  - Masking happens before the agent cap. When `BodyTruncated`, also drop the trailing `maxSecretLen-1` bytes, so
    a secret cut by httpclient's own cap leaves no prefix.
  - Base64 (binary) bodies are not returned: `{binary: true, contentType, bytes}`.
- `Limits`, enforced in `Resolve` before any approval. Each limit has its own error text:
  - URL ≤ 8 KiB, ≤ 50 headers, header value ≤ 8 KiB.
  - Body text ≤ 1 MiB, form ≤ 200 fields.
  - Agent response cap `maxResponseBytes`: default 64 KiB, at most 512 KiB, rune-safe cut with `truncated: true`.

### 2.3 httpclient hook

- `Options.RedirectGuard func(next *url.URL) error \`json:"-"\``.
- `checkRedirectFor` calls it before `closeHop` when set. An error stops the chain: net/http returns it, and
  `classifySendErr` reports it with the timeline.
- `agentapi` passes a guard that applies every referenced credential's `HostRule` to `next`. With no credential:
  nil (normal redirects, existing header stripping).
- Error text: "redirect to H blocked: credential X is not allowed there". No request goes to H.
- Only `agentapi` sets the guard. UI sends are unchanged.

- `bridge/http.go` and `bridge/grpc.go` callers are updated. Their tests (`bridge/http_test.go`, `grpc_test.go`)
  follow the call sites. No behaviour change.

### 2.5 Approval flow

- `dbmcp` new file `api_tools.go`. Consumer interface `APIRequester` (Environments, Plan, Send) implemented by
  `agentapi.Service`.
  - `Config.API APIRequester` and `Config.APISettings func() APISettings{Enabled bool; Approval string}`, read
    fresh per call.
  - Nil `API` leaves the tools unregistered.
- `server()` rebuild key gains `Enabled`: the tool set is rebuilt when the revision or the toggle changes. With the
  toggle off, `api_*` tools are not listed at all.
- Gate order in `apiRequest` (each step its own function, so none passes gocognit 30):
  1. Args and limits.
  2. `Plan`: environment, names, plain resolution, URL, credential hosts, TLS rule.
  3. Approval decision:
     - `approval == "never"`: skip the item.
     - Else when the environment has `agentAutoApproveReads`, the method is GET, HEAD or OPTIONS, and no body:
       skip.
     - Else `ApprovalBroker.Request` with kind `api.request` (P520 broker).
  4. Outcome: deny, timeout, abandon and full queue map through `approvalOutcomeError` with subject "request".
  5. `Send`, which re-plans (2.2).
  6. Render the JSON result.
- Credential blocks happen at step 2 and inside `Send` (re-plan and redirect guard). They never raise an item.
- `ApprovalRequest` gains `API *APIApproval` beside `Cluster`. The broker's `Put` maps it to the P520 item:
  - Target: Name = host, Kind `http`, Color = environment colour (`none` without one), Location = environment
    name or "No environment".
  - Operation: class `request`. Tone: GET, HEAD and OPTIONS neutral; POST, PUT and PATCH caution; DELETE danger.
  - Reason `permission`.
  - Origin from P520 (`User-Agent` client, cwd when verified).

### 2.6 `api.request` payload (final contract; amends P520 2.8)

```json
{
  "method": "POST",
  "url": "https://api.example.com/v1/orders?dry={{dry}}",
  "host": "api.example.com",
  "environment": { "id": "...", "name": "Dev", "color": "blue" },
  "query": [{ "name": "dry", "value": "true" }],
  "headers": [{ "name": "Authorization", "value": "Bearer {{token}}", "masked": true }],
  "auth": { "scheme": "Bearer", "display": "Bearer {{token}}" },
  "body": { "contentType": "application/json", "text": "{...}", "truncated": false, "form": null },
  "variables": [
    { "name": "base_url", "value": "https://api.example.com", "secret": false },
    { "name": "token", "value": "••••", "secret": true }
  ],
  "credentials": [{ "name": "token", "hosts": ["api.example.com"] }],
  "followRedirects": true,
  "timeoutSeconds": 30
}
```

- `url` has plain variables resolved and secrets as `{{name}}`. `query` is parsed from it. Agent `query` args are
  merged into the URL before planning.
- `auth` is derived from an `Authorization` header: the scheme word and the masked display. Absent: null.
- Secrets display as `{{name}}`, never a partial value. P520's `••••3f2a` example is dropped: a suffix of a secret
  is still secret material, and the name tells the user which credential it is.
- `body.text` is capped at 64 KiB for display (`truncated`). The full body is still what is sent.
- zod `apiRequestPayloadSchema` in `packages/shared/domain/approvals.ts`, registered for kind `api.request`.

## 10. User decisions (flagged; plan defaults shown)

1. Listing tool: `api_list_environments` lists environments and available variable names (no values). Without it
   the agent cannot learn the names. Alternative: names only in `api_request` error texts.
2. TLS verification is always on for agent requests, even when the global "SSL certificate verification" is off.
   Self-signed dev servers then fail for agents.
3. Plain (non-secret) opted-in variables have no host list. Their values may appear in response echoes (final URL,
   redirect URLs). Only secret values are masked.
4. Approval modes: global Always ask (default) or Never ask, plus per-environment `agentAutoApproveReads` (default
   off) for GET, HEAD and OPTIONS without a body. Host lists apply in every mode. Say if Never ask should not exist.
5. No response review stage: an approved request's masked response goes straight to the agent.
6. Masking covers every Api secret value, not only the environment's (over-masks, never under-masks).
7. No multipart or file bodies.
8. Plain HTTP with a credential: allowed only for loopback hosts or host entries written `http://host`.
9. Collection variables are never available to agents; only environment variables.
10. Agent response cap 64 KiB default, 512 KiB max; request timeout 30 s default, 300 s max.
