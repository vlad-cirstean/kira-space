## 2. Design rules (derived from what the app already does)

1. Two button looks only: **toolbar** (borderless, chrome) and **outline** (1px border, transparent, `hover:bg-field`).
   No filled button anywhere. Source: P508-iter2's "flat buttons are bordered" plus `dialog`/`dialog-danger`, which
   already are outline.
2. Emphasis by border colour, not fill. Primary = accent border (`border-primary`), text stays `text-fg`.
   Destructive = `border-error text-error`. ADE tone action = tone border and tone text. Source: `dialog-danger` and
   the hand-rolled ADE red outline already do exactly this.
3. One hover for the whole outline family: `hover:bg-field`. Measured (WCAG, on `--kira-bg-elevated #212125`):
   accent text `#3b6ed1` 3.31:1 and focus blue `#5a8ae6` on a /15 accent tint 4.07:1 fail 4.5, so primary keeps
   `text-fg`; `text-error` on today's `bg-error/15` hover is 4.17:1 (fails), on `bg-field` 4.81:1; agent `#d97757`
   5.14 rest, 4.76 on field; status tones 5.8 or more. Accent border vs elevated 3.31:1 (meets 3:1 non-text).
4. One emphasised button per rendered dialog footer (existing rule) stays; it is now the accent outline.
5. A labelled destructive action is `dialog-danger`; an icon or toolbar destructive action is `toolbar` +
   `data-tone="error"` (`TooltipIconButton tone="error"`). The `danger` variant goes.
6. Toolbar toggle state goes through ARIA: `aria-pressed` for toggles, `aria-expanded` for menu/popover triggers.
   The `toolbar` variant gains `aria-expanded:bg-field aria-expanded:text-fg` (mirrors `ghost`), so every open
   reka trigger shows the pressed look with no per-callsite class.
7. Selection inside a control (date picker cells) uses the list selection fill `bg-select text-fg`, as `rowVariants`
   `nav`/`tree`, native-select and table rows do. Not a button emphasis.
8. One floating-surface recipe for dialog, command dialog, text prompt, popover, menu and sub-menu:
   `rounded-kira border border-border bg-elevated text-fg shadow-kira`, from one constant.
9. DialogHeader: title, optional description and badge, optional header action, close. No icon (existing rule).

Exceptions (fills that stay, each with its reason):

- State controls: Checkbox, Radio, Switch checked `bg-primary`; Progress bar. A fill is the state itself.
- Selection: `bg-select` rows, nav items, date cells. Selection, not action.
- Indicators: `StatusDot`, Badge tones (/15 tint) and count, ADE `SOLID_CLASS` indicators (tag icon, needs-row icon,
  session badge, activity icon), ADE step-state pills (`AdeStepBlock` `done/stuck/failed`), docker usage bars.
- `AdeAttention.vue`: a 4.5-unit round "!" marker that is technically a Button but reads as an attention badge
  (same role as Badge `count`). Stays solid amber; listed as user decision D2.
- git-ui overlay detail drawer (`packages/git-ui/src/App.vue` ~1894): keeps `bg-bg`, because it is the same detail
  pane rendered inline at wide breakpoints; only its edge and shadow are floating.

## 9. User decisions

- D1 (default taken, matches the ask): no filled buttons; primary is the accent outline with `text-fg`. Alternative:
  keep the dialog footer primary filled and convert only the rest, which leaves the look the user called out.
  Accent-coloured text was rejected on contrast (§2 rule 3).
- D2: state controls, selection and indicators stay filled (§2 exceptions), including the ADE "!" attention marker.
  Say so if those should go outline too; that is a separate pass.
- D3: dialogs keep the floating tier (elevated fill, 1px border, `shadow-kira`, scrim), same as popover and menu.
  Alternative: drop the dialog shadow for a flatter modal.
- D4: variant names `dialog`/`dialog-primary`/`dialog-danger` stay although about half the callsites are outside
  dialogs. A rename touches about 330 callsites and collides with P520 to P522; propose it as its own phase if
  wanted.
- D5: header icons go per the existing rule, including the ADE agent glyph and the connection engine icon. If the
  user wants those identity marks kept, the rule changes instead and U107 is dropped.
