## 3. Form and YAML over the same file

### 3.1 Decision

One draft text per dialog is the only state that saves. The form is a view of that draft. Form edits become YAML node
edits on the server; a YAML edit re-decodes into the form. Save is each module's existing
`SaveFile(text, baseHash)`, so conflict handling (`E_CONFLICT`, Reload, Overwrite) and the projection path stay as
they are.

Library: `go.yaml.in/yaml/v3` (MIT and Apache-2.0) through the existing `configfs.EditYAML` (yaml.Node set by path).
Comments and key order outside the edited value stay; it is already the one app writer for YAML edits
(`repocfg.Store.Patch`, `connfiles.Loader.Patch`, mask rules). Declined: client-side `yaml` (eemeli, ISC). It keeps
blank lines better, but it would be a second YAML writer whose scalar quoting and block style drift from
`configfs.RenderYAML`, and decode/validation must run server-side anyway (JSON Schema plus Go rules).

### 3.2 Backend (generic, `internal/configfs`)

- `edit.go`: `NodeSet` gains `Unset bool`. Unset removes the key; a parent mapping left empty with no comments goes
  too, recursively. Missing key is a no-op. Extend `TestEditYAML` (edit_test.go) with unset cases: leaf, nested
  pruning, parent with a comment kept, missing path.
- New `form.go`:
  ```go
  // Edit is one form field change, in the file's own key vocabulary.
  type Edit struct {
  	Path  []string `json:"path"`
  	Value any      `json:"value"`
  	Unset bool     `json:"unset"`
  }
  // FormResult is the draft after the edits and its decoded value. Value is nil when Problem is set.
  type FormResult struct {
  	Text    string   `json:"text"`
  	Value   any      `json:"value"`
  	Problem *Problem `json:"problem"`
  }
  func Form[T any](decode DecodeFunc[T], name string, text []byte, edits []Edit) FormResult
  ```
  Applies `edits` through `EditYAML` (none: text unchanged), then decodes with the module's own `DecodeFunc`. A parse
  failure returns the input text and the decode problem (line), never an error. The decoded `T` is the value: JSON tags
  of each file type are the YAML keys, so the form speaks file vocabulary. References (`${secret:...}`, `${NAME}`)
  stay verbatim; `Form` never resolves. Callers enforce their file cap on input and output.

### 3.4 Frontend engine (`packages/workbench/src/config/`)

- New `useConfigFormDraft.ts` (composable; dialog-local state, so no Pinia store; server calls through TanStack Query
  mutations):
  - Inputs: the file query (text, hash, problem, editable), `form(text, edits)`, `save(text, baseHash)`, and a field
    table `readonly FieldSpec[]` (`{ path: string[]; unsetWhenEmpty?: boolean }`). Lists are leaves.
  - State: `tab` (`'form' | 'yaml'`), `draft`, `baseHash`, `dirty`, `model` (edited value), `problem`, `saveError`,
    `conflict`.
  - Form side: a model change, debounced (`TIMING.preview`, VueUse `useDebounceFn`), diffs `model` against the last
    applied baseline over the field table, sends only changed leaves (`Unset` for empty when the spec says so), and
    sets `draft` to the result text. The YAML tab is always current.
  - YAML side: an editor change marks the form stale; showing the form tab (or Save) runs `form(draft, [])` and resets
    `model` from the value.
  - Problem: `errorFor(pointer)` returns the message when `problem.path` equals or sits under it; an unmatched problem
    shows as one Alert at the top of the form with its line and a "Show in YAML" link. While the draft does not decode
    the form fields are disabled with that Alert.
  - Save: flush the debounce, then `save(draft, baseHash)`. Form tab Save is disabled while a problem stands (old form
    behaviour). YAML tab Save keeps today's rule: invalid text saves and is flagged. Reload, Overwrite, discard and the
    query-push-does-not-reset-a-dirty-draft rule move here from the copies in the dialogs.
- New `configForm.ts`: pure helpers the composable uses (leaf get/set by path, leaf diff, empty test). No unit test:
  thin helpers (CLAUDE.md test bar).

## 8. Risks

- `EditYAML` re-encodes the document: indentation becomes 2 and blank lines between keys can be lost on a form save
  (accepted precedent in P474/P475 patches). YAML-tab saves stay byte-exact. Only changed leaves are edited. The flow
  test pins what is kept (comments, order), not blank lines.
- A list edited from the form (environments, params, masks, variables) is replaced whole: comments inside it go; the
  key's own head and line comments stay (`setNode`).
- Monaco inside Reka dialogs: Escape in find/suggest widgets vs dialog close, focus trap, overflow widgets clipped.
  Use the overflow container; verify Escape closes a widget first in the UI spec.
- Swapping textareas breaks every `fill()` spec; all listed in section 5. WebKit typing is slower; use `insertText`.
- Secret leakage: `Form` never resolves references; contracts searched for the test secret values.
- `json any` values: numbers decode as float64; `RenderYAML` prints integers without a fraction. Flow test covers a port.
- Old field components may depend on removed seams (MCP list, folder chooser). Re-add through the module seam; never
  call a removed bound method.
- P513 seam timing (section 6).
