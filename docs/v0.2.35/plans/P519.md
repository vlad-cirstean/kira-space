# P519 Proof window cell editor and multi-file screenshots

Ask (SPEC row): "Proof window gets the cell editor (read-only is fine). Screenshots are split into several files, not
one long PNG."

Base: `chapter/v0.2.35` at `9455311d0` (P517 in flight). Wave C stream next to P518. One sequential implementer.
No migration, no MCP tool change. Discovery via `codegraph_explore` (proof window, screenshot path, cell editor dock,
`ConsoleResultGrid`/`ConsoleSlickGrid` publish, proof boot, `Dialogs` seam).

## 1. Today

- `ProofStepView.vue` renders the result in `ConsoleResultGrid` with `tab-id` = `proofPageKey(...)`, `connection-id`
  null. A tabular click already publishes into `useCellSelectionStore` (`ConsoleSlickGrid.onGridClick`, no `onEdit`);
  a key-value row click publishes too (`ConsoleResultGrid.selectKeyValueRow`). A document row never publishes (by
  design, its tree shows the body). Nobody mounts `CellEditorDock` in the proof window, so the selection is dead.
- `CellEditorDock` reads its height from `useLayoutStore`. `proof/boot.ts` boots no layout store.
- `useProofScreenshot.shoot` captures every tab into memory, then `stackCanvases` stacks them into one tall canvas.
  "Copy all tabs" puts that on the clipboard; "Save all tabs" saves it as one PNG through `ProofService.SavePng`.

## 2. Decisions

D1. Cell editor: mount `CellEditorDock :tab-id="key" readonly` in `ProofStepView` under the result, same placement as
`ConsoleView`. Covers table and key-value steps. Document steps keep no dock (tree already shows the body). Chart
steps have no cells.

D2. Layout: `boot.ts` hydrates `useLayoutStore(pinia).hydrateLayout()`. Dock height is then the app-wide value, and a
resize in the proof window syncs to the main window through the existing `layoutChanged` broadcast. Not hydrating
would read defaults and still write `layoutSet` on resize, clobbering the main window's height with a stale base.

D3. Selection lifetime: the selection stays per step key across tab switches (store entry survives step unmount;
`ConsoleResultGrid`'s `[pageKey, page]` watch has no `immediate`). So a screen with an open dock looks the same after a
"save all" walk restores the active tab. On session change, `ProofWindow` clears every `cellSelection` entry whose
key starts with `proof:<oldSessionId>:`. Add `clearSelectedCellsWhere(pred)` to `state/cellSelection.ts` rather than
iterating `byTab` from outside.

D4. Capture readiness: a capture must not shoot a half-painted dock. `CellEditorView` emits `ready` once each mounted
`MonacoHost`/`MonacoDiff`/`TimestampPane` reported ready (immediately when none renders, e.g. NULL). `CellEditorDock`
re-emits it. `ProofStepView` adds `dockReady` to its ready gate only while `selectedCellFor(key)` is non-null; a
selection change resets it. Existing callers of the dock ignore the event.

D5. Multi-file save: "Save all tabs" writes one PNG per tab into a new folder. Flow:
1. `ProofService.ChooseShotFolder({sessionName})` opens the native folder picker (`Dialogs.OpenDirectory`, title
   `backend.studio.proof.shotFolder.title`). Cancel returns `{canceled:true}` before any capture runs.
2. Go creates `<picked>/<safe session name>` with `os.Mkdir` (not `MkdirAll`). On `EEXIST` it tries `-2` ... `-99`,
   then fails with `backend.studio.proof.shotFolderTaken.body`. A fresh folder means no file is ever overwritten.
3. Go records the folder under an opaque id `shot_` + `shortid.New(12)` (P517's `wt_` precedent, P523-style prefix) in
   an in-memory map on `ProofService`, capped at 8 (oldest evicted). Returns `{canceled:false, id, path}`.
4. Renderer walks the tabs one at a time: activate, settle, capture, encode, `ProofService.SavePngTo({folderId,
   filename, pngBase64})`, drop the canvas. Peak memory is one tab, not all tabs.
5. `ProofService.ForgetShotFolder({folderId})` in `finally`.

`SavePngTo` reuses `SavePng`'s checks (`maxPngBase64`, decode, `maxPngBytes`, `pngMagic`) and `safePngName`. It
refuses an unknown id (`backend.studio.proof.shotFolderGone.body`) and an existing target (`Lstat` first,
`backend.studio.proof.shotExists.body`), then writes with `renameio.WriteFile`. The renderer never sends a path, so a
compromised renderer cannot write outside a folder the user picked. Per-file IPC keeps each payload under the existing
64 MiB cap; one batched call could reach 100 steps times that.

File names: `<NN>-<fileSlug(step description)>.png`, `NN` = 1-based tab position, zero-padded to
`max(2, digits(tabCount))`. Position, not ordinal: compare mode lists removed steps whose ordinals repeat proposed ones.

D6. Clipboard: "Copy all tabs" is removed with `stackCanvases`. A clipboard holds one image, and a stacked image is the
long PNG the ask rejects. Primary action (copy active tab) and "Save tab as PNG" (single file via `SavePng`) stay.
Orchestrator: if the user wants a copy-all that puts several files on the clipboard, that is a new phase (native
file-list clipboard, no Wails API today).

Progress: after the walk, announce `studio.proof.shot.savedAll.announce` (`{count, path}`). A failure mid-walk stops,
keeps the files already written, and announces the existing failure text plus how many were saved
(`studio.proof.shot.savedPartial.error`).

## Result

- Ready gate (D4): only `MonacoHost` emits `ready`; `MonacoDiff` and `TimestampPane` have no such event and render synchronously, so `CellEditorView` waits on the main and decoded hosts only (`useDockReady.ts`, split out to keep `CellEditorView.vue` under the 600-line N10 limit). A selection change while the dock stays mounted does not reset `dockReady`; the existing two-frame settle covers it. `ProofStepView` now also `unmarkReady`s when a cell is selected after the step was ready.
- `tests/ui/proof-chart.spec.ts` (not on the owned list) used copy-all; it now asserts save-all writes six PNGs of one tab height each. `copiedImageSize` removed from `support/proof.ts` (dead).
- `shot_` folder map is `proofShotFolders` in `proofshots.go`; `ForgetShotFolder` is best effort in the renderer (`finally`, errors swallowed with a reason comment).
- Contract fixture `ProofService.ChooseShotFolder` added to `tests/contract/proof.json`; UI fills `id`/`path`.
- Pre-existing, unfixed: `cell-editor.spec.ts` "owned by the view", "autodetect...", "UUID generate..." fail on the base commit too. Cause: unmocked `kira:connectionConfig:form` (E_FIXTURE_MISS, 422) logged as a console error. Outside this phase (connection-config fixtures).
- Not run: `bun run test:claude:studio` (no MCP tool change; orchestrator decides). `golangci-lint` not run locally.
