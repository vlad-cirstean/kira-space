## 2. Saved-but-empty decision

`SecretInput` never receives a stored value (P514 contract). With `set` true and an empty field there is nothing in
the renderer to show. Decision:

- The eye always toggles the value in the field: `type="password"` and `type="text"`. Pure client state, no IPC.
- A saved value is fetched only where a gated reveal API already exists and already covers that exact secret: the
  connection password and URI, through `ConnectionsService.Reveal` (`control.connectionsReveal`, wrapped by
  `project/state/connectionReveal.ts` `revealConnectionSecret`). It runs the P14 `localauth` gate (OS prompt,
  confirm fallback, 5-minute process grace). E3 and E4 pass it as the `reveal` prop. E4 today already reveals the same
  value through a separate button; this moves that call onto the eye, so the reveal surface count stays the same.
- Everywhere else the eye is disabled while the field is empty and `set` is true, with tooltip
  `common.secret.notRevealable.tooltip` ("Saved values can’t be shown. Type a new value to replace it."). Reasons:
  - Run secret params (E5, E6, E8) and agent settings secrets (E7): no bound reveal exists. Values are write-only by
    design ("A value goes in once and is never shown"); `scripts.Repo.SecretValues` only feeds a run. A new
    plaintext-out bound method is a security design decision, not a UI toggle.
  - Api secrets (E1, E2): `VariablesService.Reveal` is keyed by variable row id; these dialogs are keyed by secret
    name. A name-keyed reveal would be a new decrypt path, and the module deliberately caps reveal surfaces
    (`VariablesOverviewPanel.vue` comment, ARCHITECTURE "A secret's plaintext never leaves api_variables except
    through a gated reveal"). The variable set row (D1) already reveals each saved value through the gate.
  - E9 git prompt: no saved value; git's own askpass prompt is answered once. Kira never reads git's credential store
    (CLAUDE.md "Never touch a credential a driven CLI owns"); the eye only shows text the user just typed.
- No new Go, no new IPC, no new bound method anywhere.

## 3. Shared component

### 3.1 `packages/workbench/src/components/SecretInput.vue` (rewrite, same file)

`<script setup lang="ts">`, Tailwind only, shadcn-vue `InputGroup`, `InputGroupInput`, `InputGroupAddon`
(`packages/theme/src/components/ui/input-group/`), theme `TooltipIconButton` for the eye (tooltip, `aria-label`,
`pressed`), VueUse `useToggle` and `useTimeoutFn`.

Props (existing kept): `id?`, `set?`, `disabled?`; new `placeholder?: string` (overrides the computed one; E8 keeps
`automations.run.secretSaved.placeholder`), `reveal?: () => Promise<string | undefined>` (fetch the saved value;
`undefined` means cancelled or failed, the caller shows its own error). `v-model` string, required.

Attrs: `defineOptions({ inheritAttrs: false })`. `class` goes on the `InputGroup` root (callers pass layout classes
like `min-w-0 flex-1`). Every other attr (`data-testid`, `aria-label`, `@keydown`) goes on the input, so every existing
`getByTestId(...).fill()` keeps working. Eye testid: `${attrs['data-testid']}-reveal`, or `secret-input-reveal` when
no testid is passed.

State:
- `visible` (`useToggle(false)`).
- `savedPlain: Ref<string | null>`, local only (never emitted, never in a store, never logged).
- Shown value: `value` when non-empty, else `savedPlain ?? ''`. Input is `readonly` while `savedPlain` shows.
- `type`: `visible ? 'text' : 'password'`. Keep `autocomplete="new-password"`, `font-data`, plus
  `autocapitalize="off"`, `spellcheck="false"` (text mode must not feed the spellchecker).

Eye click:
1. Field has a typed value, or empty and not `set`: toggle `visible`.
2. Empty, `set`, `reveal` given, nothing shown: `await reveal()`; a string sets `savedPlain` and `visible = true`
   and arms the re-mask timer. Guard staleness with a sequence counter (a reveal that resolves after hide, after
   typing or after unmount is dropped).
3. `savedPlain` showing: hide, `savedPlain = null`, `visible = false`.
4. Empty, `set`, no `reveal`: button disabled with the `notRevealable` tooltip.

Re-mask rules:
- `savedPlain` drops on: hide, typing (value turns non-empty), `set` or `reveal` identity change, `disabled` turning
  true, unmount, and after `TIMING.revealGrace` (`useTimeoutFn`). The last mirrors P21 finding 5: a revealed plaintext
  re-masks once the grace it came from expires.
- `visible` resets to false when `value` goes back to `''` with no `savedPlain` (a save clears the field, so the next
  value starts masked).

Expose `defineExpose({ focus })` (focuses the inner input) for E9's focus-on-mount.

Labels: `common.secret.show.label` "Show value", `common.secret.hide.label` "Hide value", `aria-pressed` from
`visible`. Icons `eye` / `eye-closed` (codicons, same as `CredentialPastePanel.vue` and `VariableRow.vue`).

## 9. Risks

- Attr split: a caller relying on `class` reaching the `<input>` (e.g. width on the input) now styles the group. The
  group is `w-full`-capable and `min-w-0`; check every caller in section 4 visually in its spec screenshot on failure.
- `InputGroup` inside a disabled `<fieldset>` (connection dialog): the eye disables with it. Intended.
- Readonly preview of a revealed saved value must never enter `v-model`; the spec asserts Save stays disabled after a
  reveal with no typing (connection Secrets row) and no `SetSecret` call is logged.
- Grace mismatch: `TIMING.revealGrace` is a hand-kept copy of `localauth.GraceWindow`, as before.
- Password managers: `data-1p-ignore`/`data-lpignore` are not added (the old `SecretInput` had none); unchanged.
