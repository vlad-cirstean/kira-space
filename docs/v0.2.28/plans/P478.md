### 4.2 Bound holds keep the window's Conn — `gitwindows.go`, `gitservice.go`

Problem: after P478 direct callers hold repos with no git stream. `attachStream`'s last detach closes
the Conn and drops every hold, including theirs (one hold per repoId per Conn). Example: workspace A
closes (last stream) while an expanded worktree row of B holds B; B's `repo.changed` stops and
`worktree.list` answers `E_CONFLICT` (repoNotOpen).

Fix:

- `gitWindow` gains `bound map[string]struct{}` (repoIds held through `GitService`).
- `GitService.RepoOpen`: on `Kind == "ok"`, `windows.noteBoundOpen(key, res.Repo.RepoID)`.
- `GitService.RepoClose`: after the call, `windows.noteBoundClose(key, gitpath.CleanNFC(p.RepoID))`
  (the handler's own normalisation).
- `attachStream` detach: `last := w.streams == 0 && len(w.bound) == 0 && g.byKey[key] == w`.
- Both note methods take `g.mu`; they look up `byKey[key]` and no-op when the window is gone.
- `Close(key)` unchanged: window close releases everything.
- Consequence until P479: a page reload (no dispose, no window close) keeps that window's bound holds
  until the window closes. Holds do not multiply (`Conn.Open` is idempotent per repoId). P479's
  `ResetWindow` (P476 plan 8) ends it; P479 deletes `attachStream` and this check with it.

### 5.2 `repo/git/repoHolds.ts` (new) — window repo holds

One registry per page (window key). Replaces `state/repoOpenHold.ts` (deleted) and the transport's
own bound open/close.

```ts
export interface GitRepoHold {
  /** Bound repo.open's result; rejects when the open failed. */
  readonly ready: Promise<ResultOf<'repo.open'>>;
  /** Idempotent. The last release of a repoId sends bound repo.close. */
  release(): void;
}
export function holdGitRepo(path: string): GitRepoHold;
/** Scope-bound hold for a composable or component (tryOnScopeDispose releases). */
export function useGitRepoHold(path: () => string): { ready: () => Promise<unknown> };
```

- Keyed by the path given (every caller passes the gitRepoId; git-ui opens with the same id).
- First hold: `callBound('repo.open', { path })`. A failed open drops the entry; the next hold retries
  (the `repoOpenMemo` rule).
- Last release: bound `repo.close { repoId }`, fire-and-forget, after `ready` settles (a release
  before the open answers must not leave the hold behind).
- `useGitRepoHold`: re-holds when the path getter changes (watch), releases the old one.

### 5.3 `repo/git/reviewRepaint.ts` (new)

- Moves `ReviewRepaintEvent`, `onReviewRepaint`, `notifyReviewRepaint` out of `transport.ts`.
- Adds `afterReviewWrite(method, params)`: the repaint rule today inside `transport.request`

- Importers updated: `reviewSource.ts`, `reviewDecorations.ts`, `useReviewComments.ts`,
  `AdeReviewFiles.vue`, `AdeReviewAgentPanel.vue`.

### 5.4 `repo/git/gitCall.ts` (new) — direct calls

```ts
export function gitCall<K extends BoundKey>(
  method: K,
  params: ParamsOf<K>,
  signal?: AbortSignal,
): Promise<ResultOf<K>>;
/** Window-addressed git event for one repo; the window must hold it (repoHolds). */
export function onGitRepoEvent<K extends 'repo.changed' | 'autoFetch.changed'>(
  event: K,
  gitRepoId: string,
  handler: (payload: EventPayload<K>) => void,
): () => void;
```

- `gitCall` = `callBound` with a module-level inflight set (no dispose owner), then `afterReviewWrite`
  on success. Errors stay `RpcError` (callers branch on `.code`, e.g. `E_CONFLICT`).
- Caller holds the repo first (`holdGitRepo`/`useGitRepoHold`, await `ready`). No hidden auto-open:
  a missing hold is a bug the flow and UI tests catch (`E_CONFLICT`).
- `onGitRepoEvent` = `onGitEvent` filtered by `payload.repoId === gitRepoId`.
- Lands in commit 5 with its first callers (knip runs in the hook).
