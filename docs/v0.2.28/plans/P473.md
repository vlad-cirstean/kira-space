## Today

- Api module is Kira Studio only (ARCHITECTURE "only Kira Studio hosts an Api module"). State and
  config share `kira.db`: `api_collections`, `api_items` (folders and requests, `request_json`,
  `origin_json`), `api_environments` (`is_active`, `color`, `description`), `api_variables` (owner is
  a collection or an environment, `secret_value` sealed under `secrets.ScopeVariable`),
  `api_variable_history`, `api_response_history` and `grpc_call_history` (FK `item_id` cascade).
- Writers: `repos.CollectionsRepo` (create, save, rename, move, delete, reorder, import) and
  `repos.VariablesRepo` (environment CRUD, duplicate, reorder, variable upsert, bulk, history, lazy
  pre-P5 promotion). Bound through `bridge.CollectionsService` and `bridge.VariablesService`. Every
  write emits `kira:api:dataChanged` (`bridge/apidata.go`).
- Interpolation: `{{name}}`, two stages (renderer stage 1 leaves secret names deferred; Go
  `apivars.Service.ResolveRequest` stage 2 decrypts via `VariablesRepo.SecretsFor`). Unchanged rule.
- Foundation (P450): `internal/configfs` `Folder[T]`, `YAMLSchema`, `Rule`, `Projection`,
  `WatchDir`, `RenderAgentsMD`, `${secret:name}` refs (`secretNameRe` `^[a-z0-9][a-z0-9_.-]{0,63}$`),
  `configsvc` Open/Reveal. Studio has no `ConfigFilesService` yet; Space does
  (`apps/kira-space/internal/bridge/configfiles.go`).

## Decisions

### Config versus state, per field

| Field | Kind | Home |
|---|---|---|
| collection name, variables (name, value, description, secret ref), item tree (folders, order, nesting), HTTP and gRPC saved requests, item names | config | `<id>.collection.yaml` |
| environment name, description, color, variables | config | `<id>.environment.yaml` |
| secret variable values | state, sealed | `secret_values` (scope `variable`, owner `api`) |
| active environment (`is_active`) | state | `api_environments` projection column, kept across syncs |
| `origin_json` (Postman provenance, collection and item) | state | projection columns, kept across syncs, shed on change |
| response history, gRPC call history, variable history, tabs | state | unchanged tables |
| `api_collections`, `api_items`, `api_environments`, `api_variables` rows | derived projection | written only by the load path |
| last good JSON per file | derived | `config_last_valid` folders `api-collections`, `api-environments` |
| `AGENTS.md` | derived | written at Studio start |

Collection and environment display order: by name (case-insensitive), projection sets
`sort_order`. Item order: file order. Reorder actions go.

### Layout and format

- Folder `~/.kira-studio/api/` (`<KiraHome>/api`). Direct child of the app home, per P450. Studio
  only: Space has no Api module, so no Space folder, watch or docs. State stays in Studio `kira.db`.
- Two kinds in one folder, as the shared agent folder does (context plus settings): two
  `configfs.Folder` values on the same `Dir`, `Ext` `.collection.yaml` and `.environment.yaml`.
  Id is the file name minus the suffix. `Name` regexp `^[a-z0-9][a-z0-9-]{0,63}\.collection\.yaml$`
  (environment likewise). `Folder.visible` matches by suffix only, so a file whose stem breaks the
  pattern is still listed: `Decode` refuses it with a Problem (line 0,
  `backend.studio.apiFiles.fileName.body`).
- YAML, snake_case keys (as `settings.yaml`), file types separate from `model` types; conversion in
  `apifiles/format.go`. The writer omits defaults (`enabled: true`, empty strings, empty lists).
- Cap: foundation 1 MiB. Bodies inline as block scalars.

Collection file:

```yaml
name: Orders API
variables:
  - name: base_url
    value: https://api.example.com
    description: Base URL
  - name: token
    secret: ${secret:orders-api.token}
items:
  - id: list-orders
    name: List orders
    http:
      method: GET
      url: "{{base_url}}/orders"
      headers:
        - name: Accept
          value: application/json
        - name: X-Debug
          value: "1"
          enabled: false
      param_descriptions:
        page: Page number
      body:
        mode: none
  - id: admin
    name: Admin
    items:
      - id: create-order
        name: Create order
        http:
          method: POST
          url: "{{base_url}}/orders"
          body:
            mode: code
            language: json
            code: |
              {"sku": "A1"}
      - id: health
        name: Health
        grpc:
          target: localhost:50051
          tls: plaintext
          descriptor: reflection
          service: grpc.health.v1.Health
          method: Check
          message: "{}"
          metadata:
            - name: authorization
              value: "Bearer {{token}}"
```

- Item: `id` (required, `^[a-z0-9][a-z0-9-]{0,63}$`), `name` (required, minLength 1), exactly one
  of `items` (folder, may be `[]`), `http`, `grpc` (schema `oneOf`).
- `http`: `method` (required), `url`, `headers[]` {`name`, `value`, `enabled` default true,
  `description`}, `param_descriptions` (map), `body` {`mode` enum none|raw|code|urlencoded|formdata|file
  default none, `raw`, `code`, `language` enum javascript|json|html|xml with the default of
  `defaultHttpSavedRequest` in `packages/shared/domain/collections.ts`, `urlencoded[]` {`name`,
  `value`, `enabled`, `description`}, `formdata[]` {`name`, `kind` enum text|file, `value`, `path`,
  `file_name`, `file_size`, `content_type`, `enabled`, `description`}, `file` {`path`, `name`,
  `size`}}. Maps 1:1 to `model.SavedRequest`; both `raw` and `code` buffers kept.
- `grpc`: `target`, `tls` enum plaintext|tls, `ca_file`, `server_name`, `descriptor` enum
  reflection|proto, `proto_path`, `import_paths[]`, `service`, `method`, `message`, `metadata[]`
  {`name`, `value`, `enabled`, `description`}. Maps 1:1 to `model.SavedGrpcRequest`; defaults from
  `defaultGrpcSavedRequest`.
- Variable: `name` (required), exactly one of `value` (plain, never interpolated at load) or
  `secret` (`x-kira-secret`: whole value one `${secret:name}`), `description`.
- Environment file: `name` (required), `description`, `color` (palette enum from
  `model.ValidPaletteColor`, default `none`), `variables[]` as above.
- No `x-kira-ref` field: `${NAME}` env refs are not part of Api files. `{{name}}` substitution in
  request fields stays the apivars two-stage rule; the file text holds `{{...}}` verbatim.
- Rules (each with `Doc`, rendered into `AGENTS.md`): item ids unique in the file; variable names
  unique in the file. Duplicate variable names were allowed (P5 D12 first-wins); files refuse them
  with the duplicate's line.

### Ids and state links

- Projection rows keep surrogate uuid ids, bound on first sight to the file id: new columns
  `api_collections.stem`, `api_environments.stem` (unique), `api_items.item_key` (unique per
  collection), `api_variables.secret_ref`. Sync upserts by stem, by `(collection, item_key)`, by
  `(owner, name)` for variables. Response history, gRPC history, variable history and tab state keep
  pointing at the same uuid; no tab blob rewrite.
- Renaming a file or an item `id` is a delete plus a create (P450 rule): history of the old id
  cascades away (existing FK `ON DELETE CASCADE`, same as a delete today). Changing `name` keeps
  everything. `AGENTS.md` says so.
- `model.Collection` and `model.Environment` gain `File` (`json:"file"`), so the renderer can open
  the file through `configFilesOpen({folder: 'api', file})`.

### Sync direction and load path

- Files to DB only (P450). `apifiles.Store.Sync()`: under the store mutex, `List` both folders,
  then delete rows whose stem has no file on disk (covers `Forget` and rows never projected), then
  report changes. Runs at start, on every debounced watch event, and inside every app write after
  `Folder.Save`.
- Projection type `apifiles.projection` implements `configfs.Projection` per kind. `Snapshot` reads
  `config_last_valid`. `Record(file, json)` runs one transaction: upsert `config_last_valid`, then
  sync the domain rows of that one file:
  - collection row by stem (insert sets `variables_promoted = 1`, `origin_json` from the pending
    import origins map when present, else `'{}'`);
  - items: upsert by key with `parent_id`, `kind`, `name`, `sort_order` (index within parent),
    `method`, `url`, `protocol`, `request_json`; delete keys not in the file. When `request_json`
    changes on an existing row, `origin_json` becomes `postman.ShedOrigin(origin, request)` (D6 kept
    for UI saves and file edits alike); `created_at` kept;
  - variables of the owner: upsert by name (`value`, `is_secret`, `secret_ref`, `description`,
    `sort_order`); a plain value change records the old value through the existing
    `recordHistory`/trim logic (moved from `VariablesRepo`, same limit); delete names not in the
    file (their history cascades);
  - environment row by stem: `name`, `description`, `color`; `is_active` untouched.
- `Forget(file)`: delete the `config_last_valid` row and the domain row by stem (cascades).
- Changes collected per Record: tree, `savedRequest` per item whose `request_json` changed,
  variables per owner, environments, plus `config` whenever any entry's problem set changed.
  `Store.OnChange func(Changes)` is set by the bridge, which emits one `kira:api:dataChanged`.
- Invalid file: no DB change, last good stays in use (P450). A file that never was valid projects
  nothing and shows only in the problems list.

### Watch and external edits

- One `configfs.WatchDir(<home>/api, ".yaml", store.Sync)` (suffix `.yaml` covers both kinds),
  started in Studio `appwire` after migration and the first Sync; stopped at shutdown. Debounce
  200 ms from the foundation.
- External edit while a UI write is in flight: writes read text plus hash, edit, `Folder.Save`
  with that hash. `configfs.ErrConflict` retries the read-edit-save once, then returns `E_CONFLICT`.

### App writes (small edit actions)

Principle: keep only actions that save or create requests (the request tab is the request editor),
import and export, secret values and the active environment. Names, order, nesting, deletion and
plain variable values are edited in the file.

- Edit helper `apifiles/edit.go`: parse `yaml.Node` (`go.yaml.in/yaml/v3`, as `adeflow/writer.go`
  and `agentport` do), locate the item mapping by key path, replace its `http`/`grpc` value node or
  insert a new item node, encode with indent 2. Comments and order outside the replaced node stay.
- A write into a file that currently has a Problem is refused: `E_BAD_REQUEST`
  `backend.studio.apiFiles.fileBroken.body` naming file and line. Never edit a broken node tree.
- A write naming an item key no longer in the file: `E_NOT_FOUND` (tab falls back to Save as, as
  today for a deleted row).

Bound methods kept, reimplemented over `apifiles.Store` (signatures unchanged unless stated):

- `CollectionsService`: `List`, `GetRequest`, `GetGrpcRequest`, `Export` (read rows, unchanged);
  `SaveRequest`, `SaveGrpcRequest` (replace the item's protocol node and `name`); `CreateCollection`
  (new file `name: <name>` and `items: []`, stem slug of name, de-duplicated `-2`, `-3`);
  `CreateItem`, `CreateGrpcItem` (append under the parent's key; key slug of name, de-duplicated in
  the file); `Import` (below).
- `VariablesService`: `ListEnvironments`, `SetActiveEnvironment` (state, emits itself), `List`,
  `History`, `Reveal`, `RevealHistory`; `CreateEnvironment` writes a new file from its existing args.
- New `ApiConfigService` (`bridge/apiconfig.go`): `View()` returns `{dir, files: [{file, kind, path,
  name, problem {line, message} | null, lastGood}], secrets: [{name, set, referenced}], storage}`;
  `SetSecret({name, value})` and `DeleteSecret({name})` (write-only, `E_SECRET_STORE` without a
  keychain, emit `config` change). Mirrors `agentcfg.Service` (P453).
- Deleted bound methods: `CollectionsService.Rename`, `DeleteMany`, `MoveItems`,
  `ReorderCollections`; `VariablesService.UpdateEnvironment`, `DeleteEnvironment`,
  `DuplicateEnvironment`, `ReorderEnvironments`, `Upsert`, `Delete`, `Reorder`, `ApplyBulk`. Their
  repo methods, arg types, contracts and specs go with them.

### Secrets

- `${secret:name}` names a module-wide secret: scope `secrets.ScopeVariable`, owner `api`, in
  Studio `kira.db` `secret_values` (P447 store, keychain-sealed). Two files may share a name. The
  file never holds a value.
- `apifiles.Secrets` mirrors `agentcfg.SecretStore`: `Put`, `Delete`, `Names`, `Snapshot()`
  (`configfs.SecretSource`, one decrypt pass per send).
- Stage 2: `VariablesRepo.SecretsFor` becomes name to secret ref (environment over collection, as
  today); `apivars` resolves each referenced ref through `configfs.Resolver` with the snapshot. An
  unset secret fails the send naming the secret (`backend.studio.apiFiles.secretUnset.body`); an
  unreadable one fails with "set it again". This replaces the old leave-literal behaviour, per the
  P450 rule "never an empty string". `Used` values feed the existing masker unchanged.
- `apivars.Service.Reveal(variableID)` reads the row's `secret_ref` and opens that secret; same
  `localauth` gate. `RevealHistory` unchanged (old sealed history rows stay readable).
- No auto-prune: a secret stays until `DeleteSecret`; `View` flags unreferenced names. Setting a
  secret records no history.

### Bad edits shown to the user

- Each file's Problem (line plus catalog message, never the value) reaches the renderer through
  `ApiConfigService.View`. Shown in: a problems strip at the foot of `CollectionsPanel` (every file
  with a problem, one `ConfigFileBar` each), the variable-set tab of that collection or environment
  (`ConfigFileBar` at the top), and the environments tab rows.
- Log: foundation Warn once per new hash (file and line only).

### Migration of existing rows

One-shot, Go, at Studio start, before the first Sync (`apifiles/migrate.go`):

1. SQL migration `0055_p473_api_files.sql`: add `stem`, `item_key`,
   `secret_ref` columns and the unique indexes (partial, `WHERE ... IS NOT NULL`).
2. Steps 3 to 6 run inside `configfs.MigrateOnce(db, "api", fn)` (P472): marker set, skip.
3. Run the existing pre-P5 promotion for every collection with `variables_promoted = 0`
   (`VariablesRepo.PromoteImported`), so no variable stays hidden in `origin_json`.
4. In one transaction: assign stems (slug of name, unique against each other and files already on
   disk) and item keys (slug of name, unique per collection); for each secret variable copy its
   sealed `secret_value` envelope verbatim into `secret_values` (scope `variable`, owner `api`, name
   slug `<owner-stem>.<variable-slug>`, de-duplicated), set `secret_ref`, set `secret_value` NULL.
   Same scope, so no decrypt and no keychain prompt.
5. Write each file with `configfs.WriteAtomic` (overwrite is safe: stems are already fixed in the
   DB). Dead duplicate variables (later rows of a name, never applied under first-wins) become YAML
   comments: plain ones keep their value, secret ones only their name; their rows drop on the first
   Sync.
6. `MigrateOnce` sets the marker last. A crash before it re-runs steps 4 to 6 with the stored stems.
7. A collection over 1 MiB is still written (WriteAtomic, Warn). Its rows stay as they are until
   the user makes the file valid; the problem shows as "too large". ARCHITECTURE Known open item
   until no such file can exist.

### Import and export

- Postman collection import builds the file from `postman.Tree` (keys from names), registers the
  item and collection origins in the store's pending map keyed by `(stem, key)`, then `Folder.Save`;
  `Record` inserts the rows with their origin in the same transaction. Collection `variable[]`
  secrets arrive valueless (`blankSecretVariableValues`): written as
  `secret: ${secret:<stem>.<var>}`, unset.
- Postman environment import: `Put` each secret value first, then write the file. Keychain
  unavailable: `E_SECRET_STORE`, nothing written. Warnings and report shapes unchanged.
- Export reads rows through `LoadTree`, unchanged; secret rows export valueless as today.
