# P481 Frontend RAM: implement the proven wins

Source: `SPEC.md` row P481, `plans/P480-ram-findings.md` (proven = §2 threshold: median saving ≥2 MB V8
heap or ≥10 MB renderer RSS, ≥5x spread, Pass B attributes the bytes, P433 kept). Base: `4cd2e998`.

Scope: findings ranks 1, 3, 5 (proven), plus a bounded investigation of rank 4 (ADE first-mount
retention). Out of scope, untouched: kept graphs and their cap (P433, rank 6), git graph store (rank 7),
Discover (rank 8), Monaco models (rank 9), docker/kube log cap (rank 10), i18n (rank 11), and every
§7 no-cost item (TanStack `gcTime`, Pinia, images, SlickGrid, idle timers).

Rank 2 (xterm scrollback 5000 to 1000) declined: user kept scrollback at 5000, leaving about 40 MB
RSS at 10 full terminals on the table by choice. `terminalRenderer.ts` stays untouched.

## 0. Corrections to the findings prose (source re-read)

- No `apps/kira-studio/frontend/src/views/docker` and no `apps/kira-space/frontend/src/memory` exist.
  Docker UI lives in `packages/docker-ui` (Studio only); the memory module in
  `packages/workbench/src/memory` (Space only, `apps/kira-space/frontend/src/workbench/modes.ts`).
- Rank 1 is not the side-panel container list. `ContainerList.vue` already virtualizes through
  `packages/docker-ui/src/components/VirtualList.vue` (`useVirtualRows`). The cost is
  `ContainerTable.vue`, the engine overview table: `v-for` over every container, no virtualization,
  about 40 component instances per row (3 `TooltipIconButton`, `StatusDot`, `Spinner`, `UsageBar`).
  Evidence: at `logs0` the panel list is still mounted and the overview is replaced by
  `ContainerDetail`; heap falls 64.5 to 16.3 MB.
- Rank 5 retainer, read from source: `useReviewWorkingDiff(() => workingBranchId ?? '', () => props.tab.path)`
  in `RepoDiffView.vue` passes two arrow functions created in `<script setup>`. V8 gives all closures of
  one function a shared context, so those getters (stored in the TanStack `Query`'s key and `queryFn`
  closure) keep the whole setup context alive: `canNext`, `diffNavigation`, `diffEditor`. The query is
  created even for tabs with no working branch (`enabled: false`), so every closed diff tab hits it.

## 2. Candidates

### 2.1 Docker engine overview table (rank 1, Studio)

Files:

- `packages/workbench/src/behaviour/virtualRows.ts`: add optional `scrollMargin?: () => number` to
  `UseVirtualRowsOptions`. Pass it to `useVirtualizer` as a getter (`get scrollMargin()`, default 0),
  like `count`. In the composable's own `scrollToIndex`, add the margin to `rowTop` before comparing
  with `scrollTop`. No other caller changes (optional field).
- `packages/docker-ui/src/components/EngineOverview.vue`: `ref="scrollEl"` on the root
  `overflow-auto` div. Wrap its children in one inner `<div class="flex flex-col gap-3">` (the root
  keeps `h-full overflow-auto p-3`), so one ResizeObserver sees any height change above the table.
  Pass `:scroll-el="scrollEl"` to `<ContainerTable>`.
- `packages/docker-ui/src/components/ContainerTable.vue`:
  - Prop `scrollEl: HTMLElement | null`.
  - Rows container becomes `<div ref="bodyEl" class="relative" :style="{ height: totalSize + 'px' }">`
    holding only the virtual window; header row stays outside it.
  - `scrollMargin`: `bodyEl.top - scrollEl.top + scrollEl.scrollTop` from `getBoundingClientRect`,
    held in a ref. Recompute on mount and from `useResizeObserver` on `scrollEl` and on
    `scrollEl.firstElementChild` (the new wrapper).
  - `useVirtualRows({ count: () => rows.length, rowHeight: () => useRowHeight().double.value,
    scrollElement: computed(() => props.scrollEl), scrollMargin, pinned: active index })`.
  - Each rendered row: existing classes plus `VIRTUAL_ROW_CLASS`, `:data-index`, `:ref="measure"`
    (`virtualizer.value.measureElement`), `transform: translateY(vi.start - scrollMargin)`. Rows keep
    `h-auto min-h-row py-1`; measurement keeps today's heights (one or two lines per layout), so no
    visual change.
  - `useListNavigation`: add `scrollToIndex: (i) => scrollToIndex(i)` and
    `rendered: () => virtualItems.value`.
  - Unchanged: `data-testid="docker-table"`, `docker-table-row`, `data-name`, `data-state`, sort
    order, click, dblclick, Enter, stats cells, row actions.
- Behaviour risk (findings): off-screen rows are not in the DOM, so webview find and screen readers see
  the window only. Same as every other virtualized list (ARCHITECTURE line 196). Focus survives scroll
  through `pinned`.

checkpoint `list` (400 containers).

## 3. Measurement procedure

Same probe and host rules as `plans/P480.md` §"Run" (lines 202-227): one run at a time, host idle,
the Chromium CPU-busy gate on. Another worktree's suite on this host invalidates a run: check
`ps` for other `playwright`/`go test` processes first, rerun if any overlapped.

1. Before, on the base commit (same host conditions as after), Chromium `heap` project, 3 repeats:
   `bun run build:test:studio`, then
   `KIRA_RAM_WORLD=docker bunx playwright test --config=apps/kira-studio/playwright.perf.config.ts --project=heap heap-ram --repeat-each=3`.
   `bun run build:test:space`, then
   `KIRA_RAM_WORLD=memory,diff,ade bunx playwright test --config=apps/kira-space/playwright.perf.config.ts --project=heap heap-ram --repeat-each=3`.
   Use these as "before" in the Results; findings numbers are the cross-check (flag any row off by more
   than 3x its spread).
2. After all fixes land, same commands. WebKit (`--project=heap-webkit`, 3 repeats) for `docker` only
   (RSS story).
3. Pass B once after: unminified build (`plans/P480.md` line 206), `KIRA_RAM_SNAPSHOTS=1`,
   `KIRA_RAM_WORLD=diff` (Space). Plus the ade runs of 2.4.
4. A fix whose after numbers miss its threshold is not done: find why, fix, re-measure that world.
