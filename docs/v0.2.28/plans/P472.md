## 1. Today

- Runs config = custom scripts (normal and smart) plus collections. Shared Go in repo-root `internal/scripts`
  (`Repo`, `Service`, `Validate`), run engine in `internal/scriptruns`. Both apps, each its own DB
  (`custom_scripts`, `custom_script_collections`, `script_runs`, `secret_values`).
- Each app's `bridge.CustomScriptsService` builds a fresh `scripts.Service` per call. Mutations: `Create`,
  `Update`, `Delete`, `CreateCollection`, `RenameCollection`, `DeleteCollection`, `Move`, `Reorder`,
  `ReorderCollections`. Every mutation broadcasts `Snapshot` on `kira:customScripts:changed`; `Changed` reloads
  the scheduler.
- Readers of rows: `scriptruns.Service.Scripts` (`Repo.Get/List`), `Scheduler` (`Repo.List`), terminal open with
  `scriptId` (stored command is Go-authoritative), restore hash, ADE workflow steps (smart script by name).
- UI: `ScriptDialog.vue` (three tabs: Script, Parameters, Schedule) plus `ParamsEditor`, `ScriptBodyField`,
  `ScheduleFields`, `smart/*Field*`, `scriptErrors.ts` (client mirror of Go checks). Panel: collections CRUD,
  drag across collections, Move to.
- Secrets (P447): sealed in `secret_values` (scope `script-param`, owner `custom_scripts.id`, name = param).
  Record holds `savedSecrets` names only. Pruned in the same tx on param remove/rename/un-secret and script delete.

## 2. Decisions

### 2.1 Per field: config or state

| Field | Class | Lives in |
|---|---|---|
| id | config (identity) | file stem `<id>.yaml` |
| name, kind, command (script) / prompt (smart), collection, color | config | file |
| dir (`kira`, `fixed`), path | config | file |
| use_ade_dir | config, Space only | file |
| params[] (name, type, options, default, required, secret) | config | file |
| smart (model, max_budget_usd, no_cost_cap, timeout, tools, bash_patterns, mcp[]) | config | file |
| schedule (cron, timezone, enabled, confirm, timeout, params) | config | file |
| schedule target task and branch (Space) | state | `custom_scripts.schedule_task_id`, `schedule_branch_id` |
| script order, collection order | state | `custom_scripts.sort_order`, `custom_script_collections(name, sort_order)` |
| saved secret values | state, sealed | `secret_values` (P447 keychain layer), unchanged keying |
| savedSecrets, created_at, updated_at | derived | projection row |
| last valid file value | derived projection | `custom_scripts.config_json` |
| run records, logs, restore flags, next fires | state | unchanged tables |
| `<home>/automations/<id>` | runtime data | unchanged |
| collapsed groups | UI pref | localStorage, unchanged |
| `AGENTS.md` | derived | `<home>/runs/AGENTS.md` |

Why the schedule target is state: it names an ADE task and branch by runtime id. A user cannot find that id
by hand, and P450's rule is state references config by id, not the reverse. A small Space action sets it.

Why order is state: it comes from drag in the panel, not from typing. Files carry no order.

Collections stop being rows a user creates: a collection is the `collection:` name in a file. A group exists
while one file names it. Collection rename, delete, "New collection", "Move to" and drag across groups go away;
edit the files. Order rows are keyed by name; a renamed collection appends at the end.

### 2.2 Format and layout

- Folder `<home>/runs/` (Studio and Space each their own home). Registered with `configsvc` as folder `runs`.
  Implementer confirms no `<home>/runs` exists in either app today (`ade/runs` is a subfolder, no clash).
- One run per file, YAML, `<id>.yaml`. Id pattern `^[a-z0-9][a-z0-9_-]{0,79}$` (lowercase UUIDs fit, so
  migrated ids keep their stems). A visible `.yaml` not matching is a `Problem` ("rename the file"), never
  projected, not editable in-app (Open/Reveal only).
- No `.local.yaml` overrides (`DocModel.LocalOverrides` false). No `${...}` references: no field is `x-kira-ref`.
- Keys snake_case, as `agentcfg`. Shape:

```yaml
# Kira run. Options: AGENTS.md in this folder.
name: Deploy staging
kind: script            # script | smart, default script
command: |              # kind script only
  ./deploy.sh "$KIRA_PARAM_ENV"
collection: Ops         # optional
color: blue             # palette name, default none
dir: kira               # kira | fixed, default kira
path: /abs/folder       # dir fixed only
use_ade_dir: false      # Space only
params:
  - name: env
    type: select        # text | select | multiselect
    options: [staging, prod]
    default: staging    # string or list of strings
    required: true
  - name: token
    type: text
    secret: true        # value never in a file; set in Kira
smart:                  # kind smart only; prompt: replaces command
  model: sonnet
  max_budget_usd: 1
  no_cost_cap: false
  timeout: 15m
  tools: [Read, Grep, Glob]
  bash_patterns: []
  mcp:
    - server: github
      all_tools: false
      tools: [get_issue]
schedule:
  cron: "0 9 * * 1-5"
  timezone: Europe/Bucharest
  enabled: true
  confirm: true
  timeout: 30m          # kind script only
  params: {env: staging}
```

- `default` and schedule `params` values: string or list of strings (`"type": ["string","array"]`); a string is
  one value. Normalized to `[]string` on decode.
- `dir: home` is retired: migration rewrites it to `dir: fixed` with the resolved home path. `DirModeHome`,
  `errHomeRetired` and the `ResolveDir` home branch are deleted.

### 2.3 Schema, validation, messages

- New `internal/scripts/run.schema.json` (embedded): structure, descriptions, `additionalProperties: false`.
  `assembleSchema(Options)` writes every enum and numeric bound from Go: `smart.model` from
  `harness.Catalog.Aliases`, `smart.tools` from `BuiltinTools`, `color` from `palette`, limits from the
  `Max*`/`Min*` constants. Studio strips `use_ade_dir`. So AGENTS.md lists real models and limits, and the
  schema cannot drift from Go.
- `CustomScriptFields.Validate` stays the one authority, used by `Create` (IPC) and as a `configfs.Rule`
  (file). Refactor its errors to `*ValidationError{Path, Key, Args}`: `Path` a JSON pointer in file vocabulary
  (`/params/1/name`, `/smart/max_budget_usd`, `/command` or `/prompt` by kind), `Key` a catalog key
  `backend.core.runs.*`, `Error()` renders `i18n.T`. No message echoes a value (P450); point at the line
  instead (e.g. "This parameter name is used twice.").
- Rules (each with `Doc` for AGENTS.md, each bound to a check):
  1. `kind: script` needs `command`, no `prompt`, no `smart`; `kind: smart` needs `prompt`, no `command`.
  2. Param names unique, not a built-in (`task`, `jira`, `repo`, `branch`, `base`, `worktree`).
  3. Text param: no `options`, at most one default; secret param: no default.
  4. Select/multiselect: options set; defaults among options; select at most one default.
  5. A secret param never appears in the prompt.
  6. `dir: fixed` needs an absolute `path`; `dir: kira` has no `path`.
  7. Smart: budget in range unless `no_cost_cap`; timeout 1m to 2h; `bash_patterns` only with `Bash`; MCP limits.
  8. Schedule: valid 5-field cron; known timezone; `timeout` 1m to 24h for scripts, absent for smart;
     `params` name non-secret params with valid values.
  9. Stem matches the id pattern.
- Dropped from file validation (they depend on state, so they cannot make a file invalid):
  - `checkScheduleSecrets` (run without asking needs saved secrets). The fire path already skips with
    "no value for X". The panel row shows a warning computed client-side from `schedule`, `params` and
    `savedSecrets`.
  - Built-in vars without a task (`validSchedule`). Implementer checks `scriptruns` `plan` for a scheduled run
    with no task and a built-in var: it must yield `Missing` or a `Blocker`, so the scheduler records a skipped
    run with the reason. Add a `Blocker` (`backend.core.scriptRun.needsTask.body`) if it does neither.
- Decode is `configfs.YAMLSchema[File]` wrapped by a stem check. `File` is the file shape (snake_case json
  tags); `File.Fields()` and `FileOf(CustomScript)` convert. The rule calls `Fields().Validate(models)`.

### 2.4 Sync direction, projection, load

- Files to DB only (P450). `custom_scripts` becomes the module's `configfs.Projection` (hot paths keep reading
  rows; `scriptruns`, scheduler, terminal open, restore unchanged):
  - `Snapshot`: `id + ".yaml" -> config_json` for rows with `config_json <> ''`.
  - `Record(file, json)`: one tx. Upsert by id: config columns, `config_json`, `updated_at`; on insert also
    `sort_order` (`sqlitex.NextSortOrder`) and `created_at`. State columns (`sort_order`, schedule target) are
    never written by `Record`. Insert the collection name into `custom_script_collections` if absent (next
    order). Prune `secret_values` of this owner whose name is no longer a secret param (P447 prune rule, now on
    load).
  - `Forget(file)`: one tx. Delete the row and every `secret_values` row of the owner. Run records stay; they
    already show "script gone".
- `scripts.Loader` (new, long-lived, built once in appwire; bridge holds it, no more per-call `Service`):
  - `Start()`: migrate once (2.7), `Reload()`, `WriteDocs`, start `Folder.Watch(Reload)`. Watch or docs
    failure is a Warn, non-fatal (agent settings precedent). `Close()` stops the watch.
  - `Reload()` under a mutex: `Folder.List()`, rebuild the in-memory problems map, delete collection rows no
    row names, then emit `Snapshot` and call `OnChange` (scheduler `Reload`).
  - Called at start, on each debounced watch event (200 ms, foundation), and after each app write (`Create`,
    `SaveFile`, `Delete`). A write's own watch echo is a no-op (unchanged JSON skipped).
- App writes never touch config columns. Every config change is a file write then `Reload()`.

### 2.5 External edits and bad edits

- Any editor, any time. Change applies within the debounce.
- Invalid file: no DB change; the row keeps the last good value and keeps running with it; saved secrets
  untouched; one Warn per new hash (foundation); the problem (line, message) reaches the UI.
- Invalid file with no last good (new broken file, or a bad stem): no row; the panel lists it as a broken entry.
- File deleted: `Forget` (row and saved secrets go). A rename is a delete plus a create: the new stem starts
  with no saved secrets, no order and no run-history link. AGENTS.md says so.
- The kira folder `<home>/automations/<id>` is removed only by the in-app Delete (as today). An external delete
  leaves it; noted in ARCHITECTURE Known open items.
- `SaveFile` writes even invalid text (foundation rule: user text is never refused) and returns the problem.

### 2.6 Snapshot and bound surface (`internal/scripts.Service`, wrapped per app)

- `Snapshot{dir, collections, scripts, problems, secretStorage}`.
  - `Collection{name, sortOrder}` (no id, no timestamps).
  - `CustomScript`: `collectionId` becomes `collection` (string, "" ungrouped). `schedule.taskId`/`branchId`
    filled from the state columns.
  - `problems []FileProblem{file, id, line, message, lastGood}`; `id` "" for a bad stem.
- Kept: `List`, `Create` (the New action and test seeding: validate, render, write `<slug>.yaml`, reload,
  put secret values, set the schedule target when given), `Delete` (remove file, reload, `RemoveDir`),
  `Reorder{collection, ids}`, `ReorderCollections{names}`.
- New: `File{file}` -> `FileView{file, id, path, text, hash, problem, lastGood, editable}`;
  `SaveFile{file, text, baseHash}` -> `FileView` (`baseHash` required; missing file `E_NOT_FOUND`; changed file
  `E_CONFLICT`, mapped as `agentcfg.Service` does); `SetSecrets{id, values}` (string saves, null clears; a name
  that is not a secret param of the effective record is `E_BAD_REQUEST`; no keychain `E_SECRET_STORE`);
  `SetScheduleTarget{id, taskId, branchId}` (Space bridge only; the Studio wrapper omits it).
- Removed: `Update`, `CreateCollection`, `RenameCollection`, `DeleteCollection`, `Move`, and their Repo
  writers and args types. `Repo` keeps reads, `Reorder`, `ReorderCollections`, `SetScheduleTarget`, and the
  projection methods.
- New-file stem: slug of the name (lowercase, non `[a-z0-9]` runs to `-`, trimmed, max 60, empty -> `run`),
  `-2`, `-3` on collision. Rendered by `configfs.RenderYAML` with the header comment.

### 2.7 Migration of existing rows

- SQL (Studio `0054_p472_runs_files.sql`, Space `0064_p472_runs_files.sql`):
  - Rebuild `custom_scripts` (SQLite refuses `DROP COLUMN` on an FK column): drop `collection_id` and the
    `dir_mode` CHECK; add `collection TEXT NOT NULL DEFAULT ''` (copied from the collection name),
    `config_json TEXT NOT NULL DEFAULT ''`, `schedule_task_id`, `schedule_branch_id` (copied with
    `json_extract` from `schedule_json`). Keep every other column and row.
  - Rebuild `custom_script_collections` as `(name TEXT PRIMARY KEY, sort_order INTEGER NOT NULL) WITHOUT ROWID`
    from `MIN(sort_order)` per name (two collections with one name merge into one group).
  - No `script_runs` or `secret_values` change: owners stay the same ids.
- Go, one-shot, in `Loader.Start` before the first `Reload`, through new `configfs.MigrateOnce(db, "runs", fn)`
  (settings row `config.migrated.runs` = `true`; `appsettings.Leaf` reads only known keys, so the row is inert):
  for each row with `config_json = ''`: build `FileOf(row)` (`home` -> `fixed` + `os.UserHomeDir()`), store its
  JSON in `config_json` (this seeds last good), write `<id>.yaml` unless it exists. Then set the marker. A crash
  before the marker reruns idempotently. A legacy row the new rules refuse keeps running on its seeded last good
  and shows its problem.
- Secret values are never exported (P450): files hold param declarations only.

### 2.10 AGENTS.md (`<home>/runs/AGENTS.md`)

Generated with `configfs.DocModel{App, Title: "Runs", Intro: runs_intro.md, Pattern: "<id>.yaml",
Format: "YAML"}` from the assembled schema and rule docs, written by `Loader.Start` when bytes differ.
Intro (embedded `internal/scripts/runs_intro.md`, prose only, no option facts):

- One file per run; the stem is its id. A normal script runs `command` in the login shell; a smart script runs
  `prompt` in headless Claude Code.
- Variables: `{name}` in a prompt, `KIRA_PARAM_<NAME>` in a command; Space adds built-ins from the ADE task.
- `dir: kira` runs in `<home>/automations/<id>`.
- Secret params: values never go in a file. Set them in Kira (Edit file, Saved secret values). They stay in the
  keychain-sealed store.
- `collection` groups runs in the panel. Order comes from drag in the panel and is not in files.
- Space: a schedule's task and branch are set in Kira (Schedule target), not in the file.
- Run history lives in Kira's database. Deleting a file removes the run and its saved secret values.
  Renaming a file is a delete plus a create.
- Schedules fire only while the app is open; a missed fire is skipped.

Foundation appends options, rules and "How changes apply". Studio and Space docs differ only by the Space keys.
