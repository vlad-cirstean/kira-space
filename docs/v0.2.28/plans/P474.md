## 1. Today

Per-repo config lives in two stores, both Space `kira.db`:

- `git_repo_settings(repo_id, key, value)`: 11 leaves of `model.GitRepoSettings`, keyed by RepoID (worktree
  root; git dir for a bare repo; a linked worktree has its own RepoID). Read through
  `gitsession.Registry.RepoSettingsGet` (fresh on every call: graph page size and scope, stash, review base,
  pull strategy, host provider, checkout auto-stash) and `ade.TaskBoardDeps.GitRepoSettings` (prepare script,
  timeout, base path in `ade/setup.go` and `Repos`). Written by `repoSettings.set` (git stream, git-ui
  `RepoSettingsDialog`) and `Router.SetRepoSettings` (in-process, ADE `UpdateRepo`). Both paths emit
  `repoSettings.changed` from `Router.setRepoSettings`.
- `ade_repo_config.nickname`, `ade_repo_integration`, `ade_repo_envs` (FK target of `ade_env_state`), keyed by
  `code_repos.id`. Written only by `TaskBoard.UpdateRepo` (`AdeTaskService.UpdateRepo`, from
  `RepoConfigForm.vue`), which also writes the prepare script, timeout and base path through
  `SetRepoSettings`, prunes marks, refreshes env scripts and notifies.
- Guard: `bridge.guardRepoSettingsSet` wraps the git stream's request handler and refuses (`E_READ_ONLY`,
  `backend.space.gitrpc.fieldUnavailable.body`) a `repoSettings.set` whose patch has `worktreePrepareScript`
  or `worktreeBasePath`. Inside, `handleRepoSettingsSet` refuses `worktreePrepareScript` again
  (`prepareScriptSpaceOnly`). Bindings (ADE `UpdateRepo`) can write all three worktree leaves; the git stream
  cannot.

## 2. Decisions

### 2.1 Per field: config or state

| Field | Class | Lives in |
|---|---|---|
| repo identity `path` (RepoID) | config key | file, `path:` |
| nickname | config | file |
| integration branches | config | file |
| environments (name, deployed SHA script) | config | file |
| worktree prepare script, prepare timeout, base path | config | file |
| graph page size, graph scope | config | file |
| stash show in graph, include untracked | config | file |
| review base candidates | config | file |
| pull strategy | config | file |
| git host provider | config | file |
| checkout auto-stash | config | file |
| last valid parsed file | derived projection | `config_last_valid` folder `repos` (`configfs.TableProjection`) |
| effective config per path | derived | in-memory index in `repocfg.Store` |
| code repo registration: id, name, root, repo_id, sort order, color, hidden, hidden_rev, created_at | state | `code_repos`, unchanged |
| import source, watched folders, folder hidden | state | `ade_repo_config.source`, `ade_folders`, unchanged |
| env results (sha, prev sha, error, checked at) | state | `ade_env_state` |
| branch marks (targets, envs) | state | `ade_branch_marks` |
| heads, fetch and auto-fetch state, holds, walks, undo slot, change request cache | state | unchanged (memory and existing tables) |
| `AGENTS.md` | derived | `<home>/repos/AGENTS.md` |

- Repo color stays state: assigned automatically at import (`palette.AutoRepoColor`), never empty, one swatch
  click, part of the repo list with name, hidden and order. The file holds behaviour config.
- `code_repos.name` stays state (repo list label, `RenameRepo`). `nickname` is ADE's display override, typed
  text, so config.
- Integration branch "is the main branch" depended on git state (`mainShortName`), so it cannot make a file
  invalid. Consumers ignore an entry equal to the repo's main branch (implementer adds the skip where
  integration branches are read: `board_facts.go`, `base.go`, `agenttools.go`, `runs.go`; one helper).
  AGENTS.md says so.

### 2.2 Identity: files keyed by `path`, not stem

- P450 makes the stem the id. A repo's id is its RepoID, an absolute path no stem can hold. So the file
  carries `path:` and the stem is free (a readable slug). Nothing in state references the stem.
- `path` is matched against RepoID after `gitpath.CleanNFC`. It works for registered code repos
  (`code_repos.repo_id`), linked worktrees and repos git-ui opens without registering, as today's
  `git_repo_settings` does.
- A repo without a file uses defaults. Removing a repo from Kira leaves its file; re-adding picks it up.
  Changing `path` moves the settings to another repo (the old one falls back to defaults). Renaming a file
  changes nothing. AGENTS.md says all four.
- Two files naming one path: the first by file name applies; each later one is a loader `Problem` on its
  `path` line (`backend.space.repoFiles.duplicatePath.body`, names the winning file) and applies nothing.
- `configfs` change owned by P474: `DocModel.KeyedBy string`. When set, `writeFileDoc` prints
  "One item per file. The `<KeyedBy>` key names the item; the file name is free." instead of the stem line.
  `docs_test.go` gets one case. This is the only existing `internal/configfs` file P474 edits.

### 2.3 Folder, format, shape

- Folder `<KIRA_SPACE_HOME>/repos/` (`~/.kira-space/repos/`). Implementer confirms no existing `repos` entry
  in the Space home. Registered with `configsvc` as folder `repos`.
- YAML, `.yaml`, any visible name (`Name` regexp `^[^.].*\.yaml$`). No `.local.yaml`. No field is
  `x-kira-ref` or `x-kira-secret`: no `${...}` interpolation, no secrets (the prepare and env scripts are shell
  text, never interpolated, as P450 requires for command fields).
- Keys snake_case, grouped like the `kiraSpace.*` setting ids. Absent key = default. Shape:

```yaml
# Kira repo settings. Options: AGENTS.md in this folder.
path: /Users/me/src/shop            # required, absolute: the repo root (bare repo: its git dir)
nickname: Shop                      # ADE label, '' = repo name
integration_branches: [develop]     # besides main
environments:
  - name: staging
    deployed_sha_script: curl -fsS https://staging.example.com/version
worktree:
  prepare_script: |
    bun install
  prepare_timeout: 15m
  base_path: /Users/me/wt
graph:
  page_size: 5000
  scope: all                        # all | head
stash:
  show_in_graph: true
  include_untracked: false
review:
  base_candidates: [main, master]
pull:
  strategy: auto                    # auto | ff-only | merge | rebase
git_host:
  provider: auto                    # auto | off | a provider id
checkout:
  auto_stash: true
```

### 2.4 Schema, rules, messages

- `apps/kira-space/internal/repocfg/repo.schema.json` (embedded), `additionalProperties: false` at every level,
  a description per field. `assembleSchema(hosts)` fills bounds and enums from Go so AGENTS.md cannot drift:
  defaults from `model.DefaultGitRepoSettings()`; `graph.page_size` 100 to 50000; `graph.scope` and
  `pull.strategy` enums from `ValidGraphScope`/`ValidPullStrategy` (turn both into exported value lists);
  `git_host.provider` pattern from `appsettings.ValidProviderID` plus `auto`/`off`, description listing the
  registered ids (`githost.Registry.Infos`); `worktree.prepare_script` maxLength 64 KiB;
  `integration_branches` maxItems 10, items minLength 1; `environments` maxItems 10, `name` pattern
  `^[A-Za-z0-9][A-Za-z0-9_.-]{0,31}$`, `deployed_sha_script` 4 KiB. The limit constants move from
  `ade/repoconfig.go` to `repocfg` (exported).
- Rules (`configfs.Rule`, each `Doc` rendered into AGENTS.md):
  1. `path` is absolute; no `~`, no relative segment.
  2. `nickname` at most 40 characters on one line.
  3. Integration branch names unique, not blank after trim.
  4. Environment names unique; script not blank.
  5. `worktree.prepare_timeout` is a Go duration above 0 and at most 2h (`model.ParsePrepareTimeout`).
  6. `worktree.base_path` is absolute when set.
- Loader-level: duplicate `path` (2.2).
- Messages: catalog keys `backend.space.repoFiles.*`, no value echoed (P450). Schema-level failures use the
  foundation's `backend.core.config.*`.
- `repocfg.File` is the file shape (snake_case json tags); `File.Config()` returns
  `repocfg.Config{Path, Settings model.GitRepoSettings, Nickname, IntegrationBranches, Environments}` with
  defaults filled; `FileOf(Config)` writes only non-default leaves (migration, new files).

### 2.5 Sync direction, projection, load

- Files to DB only (P450). Projection: `configfs.TableProjection{DB, Folder: "repos"}` over the existing
  `config_last_valid` table (P452). Last good survives restart.
- Hot paths read `repocfg.Store`'s in-memory index `map[path]Config` (RWMutex), rebuilt by `Reload`. A map read
  replaces today's SQL read per `RepoEntry.RepoSettings()` call.
- `repocfg.Store` (new, built once in Space appwire):
  - `Start()`: migrate once (2.8), `Reload()`, `WriteDocs`, `Folder.Watch(Reload)`. Watch or docs failure is a
    Warn, non-fatal (agent settings precedent). `Close()` stops the watch.
  - `Reload()` under a mutex: `Folder.List()`, rebuild the index from each entry's value (last good when the
    file has a problem), apply the duplicate-path rule, keep a problems list, diff against the previous index,
    call `OnChange([]Change{Path, Old, New, FromPatch})` for each path whose effective config changed.
  - Reads: `Settings(repoID) model.GitRepoSettings` (defaults when absent), `Repo(repoID) Config`,
    `Files() []FileState{file, path, problem, lastGood}`.
  - Called at start, on each debounced watch event (200 ms), after `SaveFile`, after `Patch`. A write's own
    watch echo is a no-op (unchanged index).
- Wiring (`appwire/wire.go`):
  - `gitRegistry.RepoSettingsGet = func(id) { return store.Settings(id), nil }`,
    `gitRegistry.RepoSettingsSet = store.Patch`.
  - `ade.TaskBoardDeps.GitRepoSettings` = same getter. `TaskBoardDeps.SetRepoSettings` is deleted.
  - `repos.AdeRepoConfigRepo` gains `Files interface{ Repo(repoID string) repocfg.Config }`; `List` fills
    `Nickname`, `IntegrationBranches`, `Environments` from it by `code_repos.repo_id`. No caller of `List`
    changes. `Upsert` is deleted.
  - `store.OnChange` hook, per change:
    1. not `FromPatch`: `git.router.EmitRepoSettingsChanged(path, new.Settings)` (new exported method in
       `gitrpc/settings.go`, the same emitter `setRepoSettings` uses);
    2. `TaskBoard.RepoConfigChanged(changes)` (new, in `ade/repoconfig.go`): for each code repo whose
       `repo_id` is the path, prune target marks not in the new integration list and env marks not in the
       new env names (`Facts.DeleteMarksNotIn`, as `pruneMarks` does today), delete `ade_env_state` rows of
       removed env names (new `Facts.DeleteEnvStateNotIn`), refresh env scripts when environments changed
       (`goTracked(refreshEnvScripts)`), then `notifyRepos` and `notifyBoard` once;
    3. one `kira:repoConfig:changed` broadcast (payload-free) per `Reload` with any change or any problem-set
       change.
- `repoSettings.changed` keeps its behaviour: exactly one event per `repoSettings.set` (emitted by
  `setRepoSettings` as today, `FromPatch` suppresses the hook's copy), plus one per external file change that
  moves a path's settings. A bad edit changes nothing, so it emits nothing.

### 2.6 How a file edit passes the guard

- The guard protects one property: no git stream client chooses what the prepare script runs or where
  worktrees go. It inspects `repoSettings.set` params on the stream, before storage.
- A file edit never travels the stream. The user edits the file in an editor, or Kira's Repos dialog saves it
  through the new `RepoConfigService` binding. Bindings could already write all three worktree leaves today
  (`AdeTaskService.UpdateRepo`); `RepoConfigService.SaveFile` replaces that binding at the same trust level.
  So a file edit passes the guard by not crossing it, as ADE writes did.
- The stream's only write path stays `repoSettings.set` -> `Registry.RepoSettingsSet` -> `store.Patch`. The
  guard and `handleRepoSettingsSet`'s own check still refuse before `Patch` runs, so a refused patch never
  touches a file. `bridge/gitstream.go` is not edited in this phase.
- `Router.SetRepoSettings` (ADE's in-process writer) and its test
  `TestRepoSettings_SetRepoSettingsWritesPrepareScriptInProcess` are deleted: no caller remains.

### 2.7 App writes and bad edits

- `store.Patch(repoID, model.GitRepoSettingsPatch) (model.GitRepoSettings, error)`: `patch.Validate()`
  (kept), then under the store mutex: find the file for the path; none -> render a new file
  (`configfs.RenderYAML`, P472) with `path:` and the patched leaves, stem slug of the path's base name
  (lowercase, non `[a-z0-9]` runs to `-`, trimmed, max 60, empty -> `repo`, `-2`, `-3` on collision); file
  with a problem -> refuse, `ipcerr` `E_BAD_REQUEST` `backend.space.repoFiles.fileBroken.body` naming file and
  line, file untouched; else set each patched leaf by key path in the `yaml.Node` tree (create missing
  parent mappings, keep comments and order), `Folder.Save` with the read hash, `configfs.ErrConflict` retries
  read-edit-save once then `E_CONFLICT`; `Reload(FromPatch)`; return `Settings(path)`.
- Node edit helper: implementer first checks for a reusable set-by-path `yaml.Node` helper
  (`adeflow/writer.go`, `agentport`, P473 `apifiles/edit.go`) and reuses it; otherwise
  `repocfg/edit.go`. Leaf key paths live in one table next to `GitRepoSettingsPatch`.
- External edits: any editor, any time; applied within the debounce.
- Invalid file: no index change, last good keeps applying, one Warn per new hash (foundation), the problem
  (line, message) reaches the UI. Invalid with no last good: nothing applies for that file (its path keeps
  defaults or another file's config); listed under "Other files" in the dialog.
- File deleted: `Forget`; the path falls back to defaults; `OnChange` fires (marks and env state of removed
  targets and envs pruned).
- `SaveFile` writes even invalid text (foundation: user text is never refused) and returns the problem.

### 2.12 AGENTS.md (`<home>/repos/AGENTS.md`)

`configfs.DocModel{App: "Space", Title: "Repos", Intro: repos_intro.md, Pattern: "<name>.yaml", Format:
"YAML", KeyedBy: "path"}` from the assembled schema and rule docs, written by `Store.Start` when bytes
differ. Intro (embedded `repocfg/repos_intro.md`, prose only, no option facts):

- One file per repository; `path` names it. The file name is free. A repo without a file uses defaults.
- Changing `path` moves the settings; deleting the file restores defaults; removing a repo from Kira keeps
  its file, and adding it again applies it.
- Kira reads repo settings only from this folder, never from inside a repository (`.git/config`, tracked
  files). The prepare script runs in each new task worktree with its timeout; environment scripts run in the
  repo root on board refresh.
- `integration_branches` lists branches besides main; main is ignored if listed.
- The git window's Repository settings dialog edits the graph, stash, review, pull, host and checkout keys
  in this file; it cannot set `worktree` keys.
- Repo name, color, order and hidden are set in Kira, not in files. Branch heads, fetch state and task data
  stay in Kira's database.

Foundation appends options, rules and "How changes apply".
