## 2. Decisions

### 2.1 Per field: config or state

| Field | Class | Lives in |
|---|---|---|
| identity | config key | file stem `<stem>.yaml`, bound to the row by `connections.stem` |
| name, kind, color, read_only, mode | config | file |
| host, port, database, username, options | config | file |
| password (fields mode), uri (uri mode) | config reference | file holds `${secret:name}` only |
| secret values | state, sealed | `secret_values`, scope `connection` / `connection-uri`, owner `connections` |
| preconnect command, sidecar, delay | config | file `preconnect:` |
| auto_explain, throttle_per_sec | config | file |
| MCP: enabled, description, read/write/ddl modes, auto_explain, review_results | config | file `mcp:` |
| mask rules (table, column, kind, keep_hint, correlate) | config | file `masks:` |
| tree visibility (hidden kinds, hidden paths) | config | file `tree:` |
| pasted DDL | config | file `schema_ddl:` |
| row id (uuid), sort_order, created_at, updated_at | state / derived | `connections` |
| last valid file value | derived projection | `connections.config_json` |
| mask_correlation_key | state, sealed | `connections`, unchanged (`MaskKeysRepo`, `RegenerateKey`) |
| connection status, server version, caps | runtime | memory (`connections.Service.states`), unchanged |
| metadata cache, filter history, saved queries, op log, tabs | state | unchanged tables (FK to `connections.id`) |
| `AGENTS.md` | derived | `<home>/connections/AGENTS.md` |

- Order is state (drag in the tree, `Reorder`), as P472. Files carry no order.
- Saved queries, filter history and Discover saved states are user content per connection, not connection
  config: they stay in SQLite.
- Kubernetes clusters (`kube_clusters`, P439/P440 MCP) are not connections: out of scope.
- Surrogate ids (P473 pattern): every state table keys on `connections.id` (uuid), and tabs, layouts and dbmcp
  carry it. The row keeps its uuid; `stem` binds it to the file. A file rename is a delete plus a create: the
  old row and its cascading state (metadata cache, saved queries, filter history, mask rule rows) go. Changing
  `name` keeps everything. AGENTS.md says so.

### 2.2 Folder, format, shape

- Folder `<KiraHome>/connections/` (`~/.kira-studio/connections/`). Implementer confirms no `connections` entry
  exists in the Studio home today. Registered in Studio's `configsvc.New` map as folder `connections` (P472 adds
  the Studio `ConfigFilesService`; P473 adds `api`).
- One connection per file, YAML, `<stem>.yaml`. `Name` regexp `^[a-z0-9][a-z0-9-]{0,59}\.yaml$`. A visible
  `.yaml` breaking it is a `Problem` (`backend.studio.connectionFiles.fileName.body`), never projected. No
  `.local.yaml`.
- Keys snake_case. Absent key = default. Shape:

```yaml
# Kira connection. Options: AGENTS.md in this folder.
name: Orders prod
kind: postgres                  # connection kinds from Go
color: blue                     # palette name, default none; paints the row rail in the left panel
read_only: true
mode: fields                    # fields | uri
host: db.example.com            # fields mode
port: 5432
database: orders                # sqlite: absolute file path; sqs and s3: AWS region
username: app                   # sqs and s3: AWS profile
password: ${secret:orders-prod.password}   # fields mode only; never a literal
# uri: ${secret:orders-prod.uri}           # uri mode only; the whole URI is the secret
options:
  sslmode: require
preconnect:
  command: ssh -N -L 5432:db:5432 bastion
  sidecar: false
  delay_sec: 0
auto_explain: false
throttle_per_sec: 0
mcp:
  enabled: true
  description: Orders, read replica
  read: allow                   # deny | allow | prompt
  write: prompt
  ddl: deny
  auto_explain: true
  review_results: inherit       # inherit | review | send
masks:
  - table: users                # "*" any table, default "*"
    column: email
    kind: email                 # name | email | text | number | date | redact
    keep_hint: true
    correlate: false
tree:
  hidden_kinds: [sequence]
  hidden_paths: [public/audit_log]
schema_ddl: |
  CREATE TABLE users (id int, email text);
```

- `password` and `uri` are `x-kira-secret` (whole value one `${secret:name}`, P450). A literal is a schema
  `Problem`, so a plaintext secret never projects. No `x-kira-ref` field: `preconnect.command` is shell text,
  never interpolated (P450).

### 2.3 Schema, rules, messages

- `apps/kira-studio/internal/connfiles/connection.schema.json` (embedded), `additionalProperties: false` at every
  level except `options` (values string, number or boolean). `assembleSchema()` writes enums and bounds from Go:
  `kind` from `model.connectionKinds` (export a sorted list), `color` from `paletteColors`, MCP modes and review
  values, `port` 1 to 65535, `throttle_per_sec` 0 to `throttlePerSecMax`, `preconnect.delay_sec` 0 to
  `preconnectDelaySecMax`, `preconnect.command` maxLength 2000, `mcp.description` 1000, `name` 120,
  mask `kind` from `model.maskKinds`. Constants move from `connections/input.go` to exported names so schema and
  validator share them.
- `Input.Validate` becomes `connfiles.Fields.Validate()` (the one authority, used by the file `Rule` and by
  `Create`). Errors become `*ValidationError{Path, Key, Args}` with file JSON pointers (`/host`, `/port`,
  `/mcp/read`, `/masks/2/column`), catalog keys reused from `backend.studio.connection.*` where the text fits,
  no value echoed. Rules (each with `Doc`):
  1. `mode: fields`: sqlite needs `database` as an absolute path; sqs and s3 have no `host`/`port`; every other
     kind needs `host` and `port`. `uri` absent.
  2. `mode: uri`: `uri` required; `host`, `port`, `database`, `username`, `password` absent.
  3. `password` absent for sqlite, sqs and s3.
  4. `options` has no key in `secretOptionKeys` (case-insensitive, `connections/uri.go`); point at the key.
  5. Mask rules unique per (`table`, `column`) case-insensitively; `column` not blank; `correlate` false for
     `number`.
  6. `tree.hidden_kinds` and `hidden_paths` unique; paths not blank.
  7. Name not blank after trim.
- Decode: `configfs.YAMLSchema[File]` plus the stem check. `File` is the file shape; `File.Fields()` returns
  `model.ConnectionFields` (+ refs, masks, tree, ddl); `FileOf(row, masks, tree, ddl, refs)` writes only
  non-default keys (migration, `Create`).

### 2.4 Secrets

- Store: Studio `kira.db` `secret_values` (P447) through `secrets.Store`. Password refs: scope `connection`, owner
  `connections`. URI refs: scope `connection-uri`, owner `connections`. The field decides the scope, so migrated
  envelopes keep their AAD (P473's verbatim-copy argument: `Scope.aad` binds only the scope).
- `connfiles.Secrets` mirrors `agentcfg.SecretStore`: `Put(kind, name, value)`, `Delete(kind, name)`,
  `Names()`, `Snapshot() configfs.SecretSource` (namespace = kind; one decrypt pass per connect). Module-local,
  like P473's `apifiles.Secrets`.
- Use: `connections.resolve` reads the effective record's ref and resolves it through `configfs.Resolver` with
  the snapshot, replacing `SecretsRepo.Get/GetURI`. Unset secret: connect fails naming the reference
  (`backend.studio.connectionFiles.secretUnset.body`); unreadable: "set it again". Never an empty password.
- `Reveal(id)`: same `localauth` gate, opens the ref the effective record names.
- Names are module-wide: two files may share one secret. No auto-prune on file delete (P473 rule); the secrets
  section flags unreferenced names with Clear.
- `repos.SecretsRepo` is deleted. The `password` and `uri` columns are dropped by the migration (2.8).

### 2.5 Sync direction, projection, load

- Files to DB only (P450). `connections` becomes the module's `configfs.Projection` (P472 pattern; hot paths keep
  reading rows: `KindOf`, `resolve`, dbmcp `list_connections`, maskrules):
  - `Snapshot`: `stem + ".yaml" -> config_json` where `config_json <> ''`.
  - `Record(file, json)`, one tx: upsert by `stem` (insert: uuid id, `sqlitex.NextSortOrder`, `created_at`,
    whatever `mask_correlation_key` handling `InsertWithSecret` does today; update: config columns,
    `config_json`, `updated_at`; `sort_order` and key untouched). Then mask rule rows of that connection: upsert
    on the unique key keeping `id` and `created_at`, delete rules not in the file.
  - `Forget(file)`: hook `OnForget(id)` first (2.6), then one tx deleting the row (cascades state).
- `connfiles.Loader` (new, built once in Studio appwire):
  - `Start()`: migrate once (2.8), `Reload()`, `WriteDocs`, `Folder.Watch(Reload)`. Watch or docs failure is a
    Warn, non-fatal. `Close()` stops the watch.
  - `Reload()` under a mutex: `Folder.List()`, problems map, diff old vs new effective records, call
    `OnChange([]Change{ID, Old, New})`, emit `kira:connections:changed` (list) and
    `kira:connectionConfig:changed` (payload-free) when anything or the problem set changed.
  - Runs at start, on each debounced watch event (200 ms), and synchronously after every app write. A write's own
    watch echo is a no-op (unchanged JSON skipped).
- In-memory effective record per id (`Fields`, refs, masks, tree, ddl) for `FiltersService.List`,
  `SchemaService.Get` and the change diff. `connection_tree_filters` and `connection_ddl` are dropped (2.8).

### 2.6 Change hook (what a file edit does to a live connection)

`connections.Service` gains `ConfigChanged(id, old, new)` and `Removed(id)`; the loader calls them:

- Changed and (connected or connecting) and (`!destinationUnchanged(old, new)` or read-only changed or refs
  changed): `Disconnect` then `Connect` (today's `Update` tail, moved). Else connected: `SetThrottle`.
- Masks changed: `maskrules.Service` invalidates that connection's cache; bridge emits `kira:maskRules:changed`
  (`broadcastRules`).
- DDL changed: emit `kira:schema:changed` with the new DDL (SchemaService's payload).
- Tree changed: emit new `kira:connection:filtersChanged {connectionId, visibility}`; the tree store applies it.
- `Removed(id)`: today's `Remove` head (abort in flight, disconnect, stop preconnect, drop state), then `Forget`'s
  delete.
- A bad edit changes no record, so it calls nothing and only the problem set event fires.

### 2.7 App writes (small edit actions) and bad edits

Principle: the file is the editor; keep only actions that need app knowledge (tree nodes, grid columns,
secrets) or create files.

### 2.11 AGENTS.md (`<home>/connections/AGENTS.md`)

`configfs.DocModel{App: "Studio", Title: "Connections", Intro: connections_intro.md, Pattern: "<id>.yaml",
Format: "YAML"}` from the assembled schema and rule docs, written by `Loader.Start` when bytes differ. Intro
(embedded `connfiles/connections_intro.md`, prose only):

- One file per database connection; the stem is its id. Kira Studio's left panel lists them.
- Passwords and URIs are secrets: write `password: ${secret:<name>}` or `uri: ${secret:<name>}`; set the value in
  Kira (Edit file, Secrets). The file never holds it. An unset secret fails the connect naming it.
- Renaming a file deletes the connection's saved queries, filter history and cached metadata; change `name`
  freely. Deleting a file removes the connection; its secret values stay until cleared in Kira.
- `color` paints the row rail; `tree` hides object kinds and paths in the left panel; Filters… in Kira edits it.
- `masks` hide column values from the DB MCP server; `mcp` sets what an AI client may do.
- A saved change to the destination, credentials or `read_only` reconnects a live connection.
- Order in the left panel comes from drag and is not in files. Connection status stays in Kira.
- Foundation appends options, rules and "How changes apply".
