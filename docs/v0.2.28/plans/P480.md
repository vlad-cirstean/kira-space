# P480 Frontend RAM measurement, both apps

Report-only. Probe code plus one findings file. No app code changes: nothing under `apps/*/frontend/`,
`packages/*/src/` outside `packages/workbench/src/testing/ui/`, and no Go. One sequential Sonnet
implementer. It runs the expensive probe once (below) and writes
`docs/v0.2.28/plans/P480-ram-findings.md`. P481 then fixes only findings above the threshold in §7.

Runs beside the config-as-files streams (P472-P475) in other worktrees. File ownership in §2 overlaps
none of their code. `package.json`, `bun.lock` and `docs/v0.2.28/SPEC.md` are shared: rebase, never
force. Record the base commit in the findings header. If P479 has landed, the Space graph fixtures
follow its data plane. Use whatever `tests/ui/support` graph helpers exist at base.

## 1. What P433 already gives

- `HeapSampler` (`packages/workbench/src/testing/ui/heapProbe.ts`): `usedSize` after two
  `HeapProfiler.collectGarbage`. Noise about 0.3 MB between runs.
- `runHeapScenario`: open tabs, switch rounds, six fake minutes away, close all, reopen and close.
  Leave it and the `heap-tabs.spec.ts` files unchanged, so P433 numbers stay comparable.
- `perfProbe.ts`: `webkitRssMb()` (ps over WebKit processes), `RssSampler`.
- P433 results to compare against (heap MB): Studio boot 12.6-22.4 by world; first open of grid
  9.9, document 10.1, Discover 17.2, Space repo file 14.9 (mostly module code). Close-all vs baseline:
  Discover 18.5, Space repo 15.5, postgres 12.8, mongo 9.0. Open item: Discover grows about
  0.6 MB per round after round 2 (`docs/ARCHITECTURE.md` Known open items, JIT code suspected).
- Studio debug build (`KIRA_DEBUG_HOOKS=1`) already exposes `window.__kiraRetention`,
  `__kiraRetainedBytes`, `__kiraGridRetainedBytes`. Read them; do not add hooks to app code.

Gaps this phase fills: no RSS on Chromium, no attribution (which constructor or store holds the
bytes), no per-unit slopes (per tab, per 1k log lines, per 10k graph rows), no coverage of modes
without tabs (Docker, Kubernetes, ADE, memory) or of terminals.

### Library

`heap-snapshot-toolkit` (Nolan Lawson, Apache-2.0, no runtime deps): the Chromium DevTools heap
snapshot model re-exported, so retained sizes, dominators, per-constructor aggregates and diffs come
from DevTools' own code. Hand-rolling a dominator tree is the non-trivial infrastructure CLAUDE.md
rules out. Declined: `@memlab/core` (MIT), because it depends on `puppeteer` 24 and downloads a second
browser on install. Confirm the license at the package level before adding it. Pin an exact version.

## 3. Instruments (`memProbe.ts`, `heapSnapshot.ts`)

Discovery first: `codegraph_explore` (ToolSearch "codegraph" to load it) before Read or Grep for every
symbol the probe touches: event names fed through `emitWailsEvent`
(`packages/workbench/src/testing/ui/mockRuntime.ts`), fixture builders, tab menu test ids.

Per checkpoint, record one `MemPoint` and print it as `RAM <app> <world> <checkpoint> <json>`:

1. **JS heap.** `HeapSampler.sampleMb()` (reuse, do not copy).
2. **DOM counters.** CDP `Memory.getDOMCounters`: documents, nodes, jsEventListeners.
3. **Process RSS.** Browser-level CDP session (`browser.newBrowserCDPSession()`),
   `SystemInfo.getProcessInfo` gives each process's `type` and `id` (pid). Then
   `ps -o pid=,rss= -p <pids>`. Report `rendererMb` (sum over `type === 'renderer'`) and `totalMb`
   (all). If the headless shell does not answer `SystemInfo.getProcessInfo`, fall back to `ps -axo
   pid=,rss=,command=` matching the Playwright Chromium path under `/opt/pw-browsers` plus
   `--type=renderer`. Say which path ran in the findings header. Sample after the GC: wait 2 s, take
   3 readings 250 ms apart, keep the minimum (freed pages lag). Under `heap-webkit` the RSS is
   `webkitRssMb()` and items 1, 2, 5 and 6 are skipped (no CDP).
4. **Suspect DOM counts** (`page.evaluate`): `.monaco-editor`, `.monaco-diff-editor`, `.xterm`,
   SlickGrid roots (find the root class with codegraph in `kiraSlickGrid.ts`), `img` (and summed
   `naturalWidth * naturalHeight * 4` as decoded bytes), `canvas`, and the element count of the
   largest scroller.
5. **Store and cache introspection**, from outside app code. Vue sets `#app.__vue_app__` in
   production builds. From it:
   - Pinia: `app.config.globalProperties.$pinia`; per store id, the retained size of
     `pinia.state.value[id]` (item 6 named roots).
   - TanStack Query: the client from `app._context.provides` (key `VUE_QUERY_CLIENT`); per query:
     key, `gcTime`, observer count, `dataUpdatedAt`, and its `state.data` as a named root.
     Also count queries with no observers (inactive but retained) and with `gcTime` Infinity.
   - i18n: `app.config.globalProperties.$i18n` messages object as a named root.
   - Studio only: `__kiraRetention()`, `__kiraRetainedBytes()`, `__kiraGridRetainedBytes()`.
   If a path does not exist in the built app, say so in the findings; never add an export to make it.
6. **Heap snapshot** (attribution pass only, §5). `HeapProfiler.takeHeapSnapshot` with
   `reportProgress: false`, chunks streamed to
   `test-results-perf/heap/<app>/<world>/<checkpoint>.heapsnapshot`. Before the snapshot, resolve each
   named root: `Runtime.evaluate` to an object id, `HeapProfiler.getHeapObjectId` to a snapshot id.
   After parse: retained size of each named root (look the node up by id; if the toolkit has no
   lookup, scan node ids once). Then top 30 constructors by retained size and by self size, with
   counts. Print as `HEAPSNAP <app> <world> <checkpoint> <json>`. Diff two checkpoints by constructor
   (count and size delta) with the toolkit's `diff`. Delete `.heapsnapshot` files after parsing
   unless `KIRA_RAM_KEEP_SNAPSHOTS=1`; they are large.

Constructor names of interest in the unminified build: `TextModel`, `CodeEditorWidget`,
`StandaloneEditor`, `DiffEditorWidget`, `SlickGrid`, `Terminal`, `BufferLine`, `Query`, `QueryCache`,
`Map`, `ArrayBuffer`, `(compiled code)`, `(concatenated string)`, `(sliced string)`, `system / Context`.

## 4. Matrix

Both apps, Linux only, Chromium (`heap` project) for everything; WebKit (`heap-webkit`) for RSS only.
Viewport 1440 x 960 (fixture default). Clock pinned as `heap-tabs.spec.ts` does.

### Checkpoints per world

`boot` (status bar visible plus 2 s), `mode` (world's mode entered, nothing opened), `open1`,
`openN`, `round` (every open tab activated once), `closed` (close all or leave the mode), then two
more open-N/close cycles: `closed2`, `closed3`. Derived numbers per world: per-unit slope
`(openN - open1) / (N - 1)`, retention `closed - mode`, leak per cycle `(closed3 - closed) / 2`.

N is 10 for tab kinds. Get N tabs with the tab menu's duplicate item (`duplicateTab`); a pinned kind
refuses it, so build distinct ones. Where the fixture offers distinct paths, prefer them.

### App-level idle

- Studio and Space: `boot`, then `boot60` 60 s later with no input (timers, polls). Then every mode in
  `MODE_ORDER` (Studio `studio, api, automations, docker, kubernetes`; Space `ade, automations,
  memory, git`): enter, sample `mode:<m>`, return to the first mode, sample `back:<m>`. Gives each
  module's first-load cost and what stays after leaving.

### Per-suspect recipes

- **Monaco instances and models.** `.monaco-editor` count vs `TextModel` / `CodeEditorWidget`
  counts in the `round` and `closed` snapshots of console, definition, repo-file, diff, discover.
  Cost = retained size of `TextModel` instances. Leak = models alive after `closed`.
- **SlickGrid grids and row caches.** grid world: `SlickGrid` count after `round` (1 expected, views
  remount), `__kiraGridRetainedBytes` and `__kiraRetention` per tab, retained size of the page store
  root per tab. Cost = per-tab slope.
- **TanStack Query `gcTime`.** At `closed`: queries with zero observers, split by `gcTime` (default
  5 min vs Infinity), summed `state.data` retained size. Then `page.clock.fastForward(6 min)` and
  re-sample: what default-`gcTime` eviction frees. Cost = bytes held by inactive queries after
  close-all.
- **Pinia stores with large data.** Retained size per store at `openN` and `closed`. A store holding
  over 1 MB at `closed` is a candidate.
- **Kept-alive or hidden panes.** kept-graphs world; Space ADE over a kept `MainView`; any `v-show`
  pane found by codegraph (`v-show` plus `keepMounted`). Cost = heap with panes kept minus heap after
  eviction (open a 5th repo).
- **xterm.** terminal worlds: per-terminal heap at full scrollback, `.xterm` count vs open tabs,
  `Terminal`/`BufferLine` retained size, freed after close.
- **Large lists.** documents-list, docker list, kubernetes, ADE 200, memory 500: per-row slope;
  DOM nodes should stay flat if virtualized.
- **Images.** `img` count and decoded bytes in every world at `openN`. Expect none; say so.
- **i18n catalog.** Named root `$i18n` messages retained size at `boot`; separately, in a blank page,
  heap after `JSON.parse` of `packages/theme/src/i18n/en.json` (460 KB) with a held reference minus
  before. Plus vue-i18n compiled message cache: constructor diff `boot` vs after every mode visited.
  Fix to price: per-module lazy catalog chunks; saving = bytes of namespaces unused at boot.
- **Git graph store.** graph world: retained size of the graph store root, per-10k-row slope,
  freed after closing the tab (pinned: close by removing the repo workspace or leaving it, whichever
  the UI offers).
- **ADE board.** Board query `state.data` and ADE stores at 20 vs 200 tasks; after leaving `ade`.
- **Memory module.** Memory queries and stores at 50 vs 500; after leaving `memory`.
- **Docker and Kubernetes logs.** Retained size of the log store or query at 1k, 10k, 50k lines;
  cap present or not; after leaving the mode.
- **Discover open item.** Unminified snapshots at `round3` and `round5`, constructor diff; name the
  retainer path of the top growing constructor (toolkit retainer edges), or state it is
  `(compiled code)` and so V8 JIT.

## 5. Running it (sandbox)

Chromium ships at `/opt/pw-browsers` (`chromium-1243`, headless shell). WebKit is not preinstalled:
`bunx playwright install webkit` per `docs/DEV_ENVIRONMENT.md`. Fixtures and mocks are the UI tier's
own (`tests/ui/fixtures.ts`, `mockRuntime.ts`); no Go, no containers.

Two passes, never mixing their numbers:

- **Pass A, headline numbers.** `bun run build:test:studio` (minified, debug hooks). Then
  `bunx playwright test --config=apps/kira-studio/playwright.perf.config.ts --project=heap heap-ram
  --repeat-each=3`, same for Space after `bun run build:test:space`. Then the same with
  `--project=heap-webkit`. No snapshots in pass A (`KIRA_RAM_SNAPSHOTS` unset).
- **Pass B, attribution.** `cd apps/kira-studio/frontend && KIRA_DEBUG_HOOKS=1 bunx vite build
  --minify false` (class names survive), then `KIRA_RAM_SNAPSHOTS=1 bunx playwright test ...
  --project=heap heap-ram` once. Same for Space. Snapshot and named-root numbers come from here only.
  Rebuild minified after (`build:test:*`) so `dist` is left as other tiers expect.

`KIRA_RAM_WORLD=<name>` narrows to one world (P481 reruns one candidate). Use `-g` as well.

### Noise control

- `workers: 1` (configs already). Each world is its own test and its own `relaunch()` page.
- Before each test, wait until `load1 <= 1.0` (P311 precedent; poll `/proc/loadavg`, give up after
  120 s and log the load). Another worktree's suite on this host invalidates a run: check, rerun.
- Every sample is after two forced GCs (heap) plus the 2 s settle and min-of-3 (RSS).
- 3 repeats in pass A. Report median and spread (max - min). A number whose spread exceeds 20 % of
  its value is flagged as noisy in the findings and cannot make a candidate proven alone.
- Renderer RSS includes Chromium's spare renderer, if any: compare deltas only, never absolutes
  across worlds.
- Chromium V8 is a proxy for the shipped engines (WKWebView, WebKitGTK). Rank on V8 heap; the
  `heap-webkit` RSS deltas confirm direction. A candidate whose WebKit RSS delta has the opposite sign
  is noted, not dropped.

The run is expensive (estimate 1.5-2.5 h for both passes). It runs once. Fix any probe bug, then rerun
only the affected worlds and say so.

## 7. "Proven" threshold

A candidate is proven, and goes to P481, when all hold:

- Pass A median saving on V8 heap of at least **2 MB** in the scenario where it applies, or at least
  **10 MB** renderer RSS, or a leak of at least **0.5 MB per open/close cycle** growing across
  `closed`, `closed2`, `closed3` in all 3 repeats.
- The saving is at least 5 times the measured spread of that number.
- Pass B attributes the bytes (constructor, named root or retainer path) to the code the fix
  changes.
- The fix keeps P433's rule: switching tabs never loses state or refetches only because of UI
  interaction.

Expected saving is an estimate from measured bytes (e.g. "drop 4 kept graphs at 3.1 MB each, keep
1"), not a guess. Everything below threshold is listed with its numbers and "not proven".

## 8. Findings file format

`docs/v0.2.28/plans/P480-ram-findings.md`, terse per CLAUDE.md:

1. Header: base commit, host (`nproc`, RAM), Chromium and WebKit builds, RSS path used (CDP pids or
   ps match), load during runs, repeat count, measured noise.
2. Threshold (§7, restated with the noise actually measured).
3. Idle tables per app: `boot`, `boot60`, `mode:<m>`, `back:<m>`: heap MB, renderer RSS MB, WebKit
   RSS MB, DOM nodes. Median [spread].
4. World tables per app: one row per world, columns `mode`, `open1`, `openN`, slope, `round`,
   `closed`, `closed2`, `closed3`, leak per cycle. Heap and renderer RSS; WebKit RSS deltas.
5. Attribution per world (pass B): top constructors by retained size at `openN` and at `closed`,
   named roots (stores, queries, i18n), retainer path for any leak.
6. Candidates, one table, ranked by expected saving: rank, suspect, scenario, measured cost (with
   unit slope), evidence, fix (file and change), expected saving, proven yes/no, behaviour risk.
7. No real cost: every §4 suspect without a measurable cost, with its number (e.g. "images: 0 `img`
   in every world").
8. Discover open item: what the snapshot diff found.

Every suspect in the SPEC row appears in 6 or 7. Raw `RAM`/`HEAPSNAP` lines stay out of the file; the
tables carry the numbers.
