# P479 Git graph data plane; remove the git stream protocol

Plan for SPEC row P479. Last of four phases (P476 to P479). Planned against `63d4d917` (P478 landed).
One sequential implementer (11).

## 1. Goal and invariants

- Move the last four graph request methods (`graph.status`, `graph.loadMore`, `graph.refresh`,
  `graph.reportFailure`) onto `GitService` (3).
- Keep the FlatBuffers graph bulk path as a bulk-only data plane, Studio engine style: one named Wails
  stream per page, JSON text requests, binary chunk responses (5).
- Delete the git stream protocol: `ServeGitStream`, `internal/rpcstream`, git-ipc `rpc.ts` and
  `validate.ts`, `gitrpc.ContractVersion`/`CONTRACT_VERSION` and their tests, UI fake git stream (4, 6).
- Fix P478 caveats: doubled `repo.changed` under `-tags server` (two Conns per non-main tab), and holds
  kept past page reload until window close (`GitService.ResetWindow`, 4.2).
- Behaviour unchanged: graph rows, chunk sizes (`ChunkRows=500`), resume/range semantics, errors and
  i18n keys (one renamed, 10), events, op log records.
- Keep `gitwire.fbs`, `codec.ts`, `graphChunkCodec.ts`, `blobFrame.ts`, git-ipc `transport.ts`
  (`Transport` interface) and `streamChannel.ts` (both still used, 6.1). `BridgeClient` unchanged.

## 3. Method partition

- Bound (new, `bridge/gitservice_graph.go`, each `callGit[T]` over `Handlers.Request`):
  - `GraphStatus(ctx, GitGraphStatusArgs) (gitrpc.GraphStatusResult, error)`
  - `GraphLoadMore(ctx, GitGraphLoadMoreArgs) (gitrpc.GraphLoadMoreResult, error)`
  - `GraphRefresh(ctx, GitGraphRefreshArgs) (gitrpc.GraphRefreshResult, error)`
  - `GraphReportFailure(ctx, GitGraphReportFailureArgs) (struct{}, error)`
  - Args shape as the other 60: `{WindowKey string; Params gitrpc.Graph*Params}`.
- Bound (new, not a request method): `ResetWindow(ctx, GitResetWindowArgs{WindowKey}) (struct{}, error)`
  (4.2).
- Data plane (not bound): `graph.stream` only (5).
- Totals after P479: `GitService` 65 methods; `BOUND_METHODS`, harness table, `BOUND_GIT_WIRE` 65 each
  (`ResetWindow` is not a `RequestKey`, so not in those tables). `requestHandlers` keys = 64 `callGit`
  method strings + `gitHost.providers`.

Why not chunks over bound calls or events: Wails bound results and events are JSON only. A `[]byte`
becomes base64 (+33% bytes, an extra copy, no zero-copy `Uint8Array` views into the frame), and events
carry no backpressure. Graph chunks are the one bulk path; a stream is the right primitive.

### 4.2 `ResetWindow`

- `GitService.ResetWindow(ctx, GitResetWindowArgs{WindowKey})` calls `s.windows.Close(a.WindowKey)`.
  Next call on that key builds a fresh Conn.
- Called once per page load before any other git call (6.2). Reload keeps `?window=` key, so the
  previous page's Conn (holds, walks, op slot, event routing) is released at once, not at window close.
- Same trust as every bound method: a page can only name a key, and a key reset only drops that key's
  holds and walks. No cross-window effect beyond what `RepoClose` per repo already permits.
- In-flight plane streams on the closed Conn end through `conn.Done()`/walk cancel (existing
  `Conn.Close` behaviour); the plane sends `end` with the existing closed-conn error.

## 5. Graph data plane wire

One Wails stream `gitgraph` per page, opened lazily on first `graph.stream`, redialed after close.
No version envelope (one producer, one consumer, built together; P479 removes the version handshake).

Inbound (text JSON):

- `{"t":"open","id":<n>,"windowKey":"<key>","params":{repoId,resumeThroughRow?,range?},"credit":2}`
- `{"t":"credit","id":<n>,"n":1}`
- `{"t":"cancel","id":<n>}`
- Undecodable frame or unknown `t`: dropped. `open` with a live `id`: `end` with error on that id,
  first stream untouched. `credit`/`cancel` for unknown id: dropped.

Outbound:

- Chunk: blob frame `0x00|u32BE headerLen|{"t":"chunk","id":<n>,"chunk":{...}}|KIG1 blob`. `chunk`
  object byte-identical to today's payload (`repoId,seq,from,to,source,remaining,exhausted,commits`).
- `{"t":"end","id":<n>}` or `{"t":"end","id":<n>,"error":{"code","message","key"?,"params"?}}`
  (same error shape the bound bridge maps to `TransportError`).

Backpressure: client grants `credit` 2 in `open`, +1 after each awaited `onChunk`. Server blocks the
walk's emit on the credit gate (ctx-aware). `sendCh` 16 bounds queued frames.

Cancel:

- Client abort: send `cancel`, resolve the promise (as `rpc.ts` today). Pre-aborted signal: reject
  `cancelled` without sending `open`.
- `onChunk` throws: send `cancel`, reject with the thrown error.
- Plane close (socket close, page unload): server cancels every stream on that plane; client resolves
  every pending stream (as `rpc.ts` dispose), then next `stream` redials.
- Transport dispose: aborts its own streams through `linkAbort`.
- Cancel releases `w.mu` (walk lock) through ctx; next `open` or `GraphStatus` answers.
