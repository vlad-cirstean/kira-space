# P476 Git on bound services: connection lifecycle, events, read methods

Plan for SPEC row P476. First of four phases (P476 to P479) moving git IPC off the custom stream onto
bound Wails services. Planned against the tree after P472 to P475 (P472 to P475 plans read, code
state at `dcef708`). One sequential implementer.

## 1. Goal and invariants

- Add bound `GitService`. Move the per-window `gitsession.Conn` behind it. Move 14 read methods.
- Git events become window-addressed app events `kira:git:<event>`.
- The git stream keeps serving every method until P479. Both transports share one Conn per window.
- Behaviour unchanged: same results (byte-identical JSON), same error codes and i18n keys, same
  events and payloads, same credential prompts, op log records and `guardRepoSettingsSet` refusal.
- No `packages/git-ui` state change. No spec assertion change. No contract version bump.

## 4. Go: bound service and window lifecycle

### 4.1 `bridge.GitWindows` (new, not bound) — `internal/bridge/gitwindows.go`

Owns one Conn per window key. Not a bound service: `Close` must not be callable from a page.

```go
type GitWindows struct {
    router *gitrpc.Router
    relay  CredentialAsker
    events appevent.Emitter // the app emitter every bound service uses
    mu     sync.Mutex
    byKey  map[string]*gitWindow
}
type gitWindow struct {
    conn     *gitsession.Conn
    handlers gitrpc.Handlers
    streams  int
}
```

- `get(key) *gitWindow` creates lazily, under `mu`, exactly what `ServeGitStream` does per stream
  today: `NewConn(newStreamConnID(), nativeClientID, nativeLabel, nil)`, `Module = oplog.ModuleGit`,
  `RouteCredentials` to `relay.AskFrom(ctx, key, nativeLabel, req)`, `DisableAutoFetch()`,
  `handlers = router.ForConn(conn)` (once per Conn; ForConn's `repoSettings.changed` queue and
  goroutine end on `conn.Done()`), then `conn.SetEmit(func(method, payload) { events.EmitTo(key,
  "kira:git:"+method, payload) })`.
- `Close(key)`: remove from map, `conn.Close()`. Wired into `main.go` `winDeps.OnWindowClosing`.
- `attachStream(key) (detach func())`: `streams++`; detach does `streams--` and, at zero, `Close(key)`.
  Keeps today's release-on-stream-close (page reload, `-tags server` tab close) while the stream
  exists. P479 replaces it (8).
- Empty key is a valid key (flow harness, server build fallback, see 4.4).
- Keep the explanatory comments from `ServeGitStream` (auto-fetch opt-out, attribution).
- `CredentialAsker`, `nativeClientID`, `nativeLabel`, `newStreamConnID` move here from gitstream.go.

### 4.2 `bridge.GitService` (new, bound) — `internal/bridge/gitservice.go`

- `type GitService struct{ windows *GitWindows }`. FQN `GitService.*`. One method per row of 3.1.
- Every method takes one args struct with explicit window key, per repo convention (`adewire`,
  `hostview`, `tabs`):

```go
type GitStatusGetArgs struct {
    WindowKey string                  `json:"windowKey"`
    Params    gitrpc.StatusGetParams  `json:"params"`
}
func (s *GitService) StatusGet(ctx context.Context, a GitStatusGetArgs) (gitpreflight.StatusSummary, error) {
    return callGit[gitpreflight.StatusSummary](ctx, s.windows, a.WindowKey, "status.get", a.Params)
}
```

- `callGit[T]`: `json.Marshal(params)`, `w := windows.get(key)`, `res, err := w.handlers.Request(ctx,
  method, raw)`. Error: `ipcerr.Wrap(err)` — same mapping as `rpcstream.wireErrorFrom` (ipcerr passes
  through; anything else becomes `E_INTERNAL` with `err.Error()`). Result: type-assert to `T`; a
  `json.RawMessage` (the two size-capped handlers) unmarshals into `T`. Anything else is
  `ipcerr.Internal("gitservice: <method>: unexpected result type")`; the bound flow test (7.2) calls
  every method, so a wrong `T` fails there.
- Handler bodies run unchanged through `handlers.Request`: params validation, `validRefArg`,
  `MaxResultBytes` cap, `mapGitError`/`mapDetailError` stay single-sourced in `gitrpc`.
- Size cap: the capped body re-encodes to the same JSON the stream sent; Wails' HTTP response has no
  32 MiB frame limit, so the cap stays the only bound, as today.
- `RepoSettingsSet` runs the guard before the handler: if `repoSettingsSetTouchesRestrictedField`
  (moved to gitwindows.go, shared) is true, return `ipcerr.T(ipcerr.CodeReadOnly,
  "backend.space.gitrpc.fieldUnavailable.body", nil)`. Typed args make the check a field test on
  `a.Params.Patch`; keep the raw-JSON helper for the stream guard and have both call one predicate.
- Cancellation: the Wails call ctx cancels on `CancellablePromise.cancel()`; reads honour it as they
  honour the stream's cancel frame today.
- `ctx` window (`application.WindowKey`) is not used; explicit key as in every other service.
- `Wired.GitWindows` and `Wired.GitSvc` fields; `GitSvc` appended to `Bound()` (update its count
  comment). `Wired.GitRouter()` stays (stream, harness) until P479.

### 4.3 `ServeGitStream` coexistence — `internal/bridge/gitstream.go`

```go
func ServeGitStream(windows *GitWindows, conn StreamSession, windowKey string)
```

- `w := windows.get(windowKey)`; `defer windows.attachStream(windowKey)()` (attach before Serve).
- `rpcstream.NewSession(conn, Handlers{ContractVersion, Request: guardRepoSettingsSet(w.handlers.Request),
  Stream: w.handlers.Stream, MaxFrameBytes})`; `sess.Serve()`.
- No `NewConn`, no `SetEmit`, no `defer gconn.Close()`. Stream close cancels only that stream's
  in-flight calls (rpcstream already does this); Conn release is `attachStream`'s detach.
- The stream sends no `evt` frames any more. `rpcstream` keeps `Emit` (unused by git until P479
  deletes; Studio does not use it either — leave it, P479 decides).
- `appshell.RegisterGitStream(app, windows)`: key is `c.Window().Name()`, or `"main"` when the window
  is nil (`-tags server`), matching `packages/workbench/src/lib/window.ts`' fallback.

### 4.4 Shared-Conn correctness

- One Conn per window is safe for holds: `code_repos.repo_id` is UNIQUE, so one page has at most one
  shared client per git repo (`leaseOf`), and Conn `Open` is idempotent per RepoID.
- Two pages on one key (webview reload, server tab without `?window=`): the reload case is covered by
  `attachStream` release. Server-build multi-tab on `"main"` already shares broadcasts today; it is
  not a native path. State in ARCHITECTURE.
- Server build, minted key on a non-main tab: stream key (`"main"`) and bound key differ. 6.1's
  dual open keeps both Conns holding the repo, so stream-routed methods keep working. Cost in that
  mode only: both Conns emit `repo.changed` (broadcast), so the page refetches twice. Accepted until
  P479; noted in ARCHITECTURE.
- Ordering: today one stream carried responses and events in order. Now events (app events) and
  stream responses travel separately. Checked consumers: `ops.ts` shows `remoteProgress` only while
  `activeRemoteOp` is set and clears it at op start, so a late `remote.progress` is invisible;
  `stack.ts` clears `progress` at restack start. `repo.changed` consumers only refetch. Implementer
  re-checks `stack.ts` render gating; any fix there is P477's file, so report it, don't edit.

## 6. Frontend

### 6.1 Hybrid transport — `apps/kira-space/frontend/src/repo/git/transport.ts` + new `boundGit.ts`

Decision: **adapter, not direct calls.** `BridgeClient`, `Transport` and every `packages/git-ui`
state module stay as they are. The Space transport is the one choke point every consumer
(`gitTransportFor`) already goes through, so routing there moves all callers at once with no
call-site edits.

- `repo/git/boundGit.ts` (new): `BOUND_METHODS: Record<string, (windowKey, params) =>
  CancellablePromise<unknown>>`, 14 entries, each a generated `GitService` binding call with
  `{windowKey, params}`. Imports bindings directly, not through `bridge/index.ts`: `unwrap` returns a
  plain Promise and loses `.cancel()`, and git errors must surface as `RpcError`, not `CodedError`.
- `callBound(method, params, signal)`:
  - error → `new RpcError({ code, message })` from `toCodedError(err)` (same `code`/`message` the
    stream delivered; `git-ui` branches on `RpcError.code`).
  - `signal` abort → `promise.cancel()`, reject `TransportError('cancelled')`.
  - transport dispose → cancel every in-flight bound call, reject `TransportError('transport-closed')`.
- `createNativeGitTransport`'s `remote.request(method, params, signal)`: `method in BOUND_METHODS` →
  `callBound`, else the stream rpc as today. `stream()` stays on the stream.
- `ensureOpen` (auto `repo.open` before a repo's first request or stream): send `repo.open` bound
  **and** over the stream, once per repo per client (4.4). In native both hit the same Conn
  (idempotent). The bound result is the one returned to the caller.
- `remote.on(event, cb)` for the five server events: subscribe `kira:git:<event>` through
  workbench `on()`. Filter `repo.changed`, `autoFetch.changed`, `remote.progress`, `stack.progress`
  to repoIds this client opened (`opened` map); `repoSettings.changed` passes unfiltered (as today:
  ForConn fans it to every Conn). Local events (`review.target`, `ui.action`) unchanged.
  Unsubscribe on dispose.
- Dispose (`disposeGitTransport`, and the `channel.onClose` eviction path): call bound `RepoClose` for
  each repoId in `opened`, fire-and-forget, before closing the stream. This replaces the release
  today's per-stream Conn did on close; without it a closed repo tab keeps its hold until the window
  closes. `forgetRepoOpen` stays.
- `app.init` (`hostHandlers.ts`): proxies the bound `AppInit`, drops `serverVersion` as today.
  `contractVersion` still returns 58, so `BridgeClient.init()`'s check is unchanged.
- No contract-shape validation on the bound path: `assertContractShape` only checks method-name
  membership, which `BOUND_METHODS`' keys typed as `RequestKey` already guarantee at compile time.
