# P736: Proof data auto-expanded, compact proof window, selectable text

Spec: `docs/v0.3.24/SPEC.md` § P736. Base: `8e9dfd474`.

## Terms

- **Proof view**: proof window (`studio/proof/ProofWindow.vue`): summary, step header, step result
  (`ProofStepView.vue`, also mounted by `ProofCompare.vue`), change panel.
- **Proof tab**: proof entries in task panel Details tab (`ade/v2/details/AdeProofEntry.vue`,
  `AdeProofDiagramStep.vue`), rendered by `AdeTaskChain.vue` inside `AdeDetailsTab.vue`.
- **Kira screenshot**: proof window's shot menu (`useProofScreenshot.ts` `shoot()` captures
  `ProofWindow`'s `centre` pane through `screenshot.ts` `captureElement`).

## Findings (codegraph)

- Console document results default collapsed: `ConsoleResultGrid.vue` expands only ids in saved
  `viewState.expanded` (lines 236-244). Nested fields of an expanded document open only per path:
  `views/shared/document/rows.ts` `expandedPathsFor`/`isPathExpanded`/`togglePath`, empty set = first
  layer only.
- Key-value rows are fixed `rowHeight` virtual rows (`kvVirtual`, inline `height` style); value cell
  is `whitespace-pre-wrap` plus `overflow-hidden`, so long values clip.
- Proof summary capped `max-h-32` (`ProofWindow.vue:107`). Change panel step rows `truncate`.
- Proof tab: diagram fixed `h-64 overflow-hidden` (`AdeProofDiagramStep.vue:26`); proof name and step
  descriptions `truncate` inside `<Button>`s (`AdeProofEntry.vue:58,100`).
- `packages/theme/src/base.css:37`: `body` is `select-none`. Only inputs, contenteditable,
  `.cm-editor` (Monaco/CodeMirror) and KV cells (`ConsoleResultGrid.vue:554,573`) opt back in. Text
  inside a `<button>` is not selectable in WebKit, so the proof tab's name and step text cannot be
  copied today.
- Proof window size: `bridge/proof.go` `OpenWindow` creates an ephemeral record without bounds;
  `main.go` `BindProofShell` sets `rec.Bounds = shell.CascadeFrom(app.Window.Current())`, which copies
  the current window's full size (often 1280x800 or larger, a maximized main window included). Row is
  deleted on close (`proof.IsWindowKey` in `ephemeralWindowKey`, `closeDecision`), so every open uses
  that copy. `internal/shell/window.go` `MinWidth/MinHeight` floor every window at 1024x640.

## Decision: screenshot size

Choice: **keep the proof window small**, not shrink at capture time.

Why: capture-time shrink means re-laying the pane out at a narrower width before `domToCanvas`, then
restoring it. The pane holds SlickGrid (own resize observers and column math), Monaco (async layout),
two virtualizers with exact heights, ECharts and Mermaid SVG, each with saved scroll restored per
step (`whenSettled` waits on `data-ready`). Forcing a second layout per tab and restoring it is error
prone (stale virtual windows, scroll drift, flicker on screen). Downscaling the canvas alone keeps the
image small but shrinks the text, which defeats "easy to see". A compact window gives a small
capture with unchanged, readable text and zero new capture code.

Size: 1024x640, the existing global floor. Lowering below it needs per-window `MinWidth` in shared
`shell.Options`; the floor is already small and keeps the step header, query and result usable.
Capture code (`screenshot.ts`, `useProofScreenshot.ts`) stays unchanged: it already photographs only
the centre pane as shown, scroll included, so the shot fits the viewport by construction. Auto-expanded
data (below) makes each shot show details at once.

## Changes

### 1. Compact proof window (Go)

- `apps/kira-space/internal/proof/service.go`: next to `WindowKeyPrefix`, add exported constants
  `WindowWidth = 1024`, `WindowHeight = 640` with a one-line comment: proof window opens compact so
  its screenshots stay small and readable.
- `apps/kira-space/main.go` `wired.BindProofShell` closure: after `rec.Bounds =
  shell.CascadeFrom(app.Window.Current())`, when non-nil set `rec.Bounds.Width, rec.Bounds.Height =
  proof.WindowWidth, proof.WindowHeight`. Nil (no current window) keeps `DefaultBounds`. Cascade wrap
  check ran against the larger source size, so the smaller window stays on screen.
- No `shell` package change.

### 2. Document results: every document and nested field open (frontend)

- `apps/kira-space/frontend/src/studio/views/shared/document/rows.ts`:
  - `registerDocumentRows(scope, source, opts?: { openNested?: boolean })`; keep a module-local
    `openScopes = new Set<string>()`, add on `openNested`, delete in `unregisterDocumentRows` and
    `dropRows`.
  - `isPathExpanded`: `openScopes.has(tabId) !== expandedPathsFor(tabId, row).has(path)` (set holds
    toggled paths; for an open scope a member means collapsed). `togglePath`, `walk`,
    `visibleLines`, `rowHeight`, `fillLineCounts` stay as they are and follow automatically.
  - `primeLineCounts`: return early for an open scope (worker counts first layer only; the window's
    exact `fillLineCounts` and running-mean estimate cover the rest). Update the doc comment.
  - Update the `expandedPaths` field comment to say "toggled from the scope's default".
- `apps/kira-space/frontend/src/studio/proof/pages.ts` `mountProofPage`: pass `{ openNested: true }`.
  Console and Mongo document tabs keep current behavior (no flag).
- `apps/kira-space/frontend/src/studio/views/console/ConsoleResultGrid.vue`:
  - New prop `autoExpand?: boolean` (name avoids the exposed `expandAll` function). Doc comment: proof
    window, every document opens expanded on mount and key-value rows grow to their content.
  - Restore block (lines 236-244): when `props.autoExpand && page.value?.kind === 'document'`, call
    `consoleViewStore.setAllResultDocsExpanded(tabId, pageKey, rowIndices.value.flatMap((row) =>
    documentId(pageKey, row) ?? []), true)` instead of looping `saved.expanded`. Saved
    `selectedRow` still restores. Collapse stays possible during the visit; a remount (tab switch,
    screenshot walk, reload) opens everything again. That is the ask: auto-expanded, and every
    screenshot shows full data. `ProofStepView` mounts the grid only after `pageMounted`, so the page
    exists at setup.
  - Key-value branch, only when `autoExpand`: drop the inline `height` style, bind each row with
    `:data-index="vi.index"` and a ref callback calling
    `kvVirtual.virtualizer.value.measureElement(el)` (TanStack dynamic rows; `useVirtualRows` already
    returns `virtualizer`). Field cell: replace `overflow-hidden text-ellipsis` with
    `whitespace-pre-wrap break-words`. Value cell: drop `overflow-hidden`. Without `autoExpand` the
    branch renders exactly as now (console unchanged). Compute both class sets with `cn()`; no scoped
    style.
  - `document-body` div: add `select-text` (benefits console too, harmless).
- `apps/kira-space/frontend/src/studio/proof/ProofStepView.vue`: pass `auto-expand` to
  `ConsoleResultGrid`.
- Tabular steps: SlickGrid rows stay one line. Requirement it cannot meet: SlickGrid's virtual
  viewport uses one fixed `rowHeight` for all rows, so wrapped multi-line cells are not supported.
  Full cell value already shows in the read-only cell editor dock on click, and copy works through
  grid selection plus ⌘C and the Copy menu (`ConsoleSlickGrid.vue` `onCopy`, D9).
- Query editor keeps `QUERY_MAX_HEIGHT` (240 px, scrolls inside Monaco). The query is the step's input,
  not its result; uncapped, a long query would push the result out of the compact 640 px window and
  out of every screenshot. Monaco text is already selectable.

### 3. Proof view: full text, selectable

- `ProofWindow.vue` summary `<p>`: replace `max-h-32` with `max-h-[40%]` (relative to the centre
  pane; typical summaries show in full, a very long one still leaves the step visible) and add
  `select-text`.
- `ProofStepView.vue` `DetailHeader`: add `class="select-text"` (falls through to its root; covers
  title and source badge).
- `ProofDiagram.vue` scroller div: add `select-text` (SVG labels).
- `ProofChangePanel.vue`: reason `<p>` gets `select-text`; step row description `<span>`: replace
  `truncate` with `whitespace-normal break-words` so a long description shows in full. Rows stay
  buttons (navigation, not data).
- Not selectable on purpose: tab strip (tab drag/activation), title bar (`ProofHeader` is a window
  drag region; the folder path is also in the Details tab, selectable there).

### 4. Proof tab: expanded, selectable

- `ProofDiagram.vue`: new prop `fit?: 'pane' | 'content'`, default `'pane'` (current `size-full`
  scroller). `'content'`: figure and scroller without `size-full`, scroller `overflow-x-auto` (wide
  diagram scrolls sideways, height follows the SVG); error branch wraps `MonacoHost` source in a fixed
  `h-48` box, because Monaco needs a definite height.
- `AdeProofDiagramStep.vue`: container drops `h-64 overflow-hidden`, keeps `rounded-kira-sm border`;
  pass `fit="content"`.
- `AdeProofEntry.vue`:
  - Proof name: plain `<span class="min-w-0 break-words font-medium select-text"
    data-testid="ade-proof-name">`. Open action moves to a `TooltipIconButton` (icon
    `link-external`, label `t('space.ade.proof.entry.open.tooltip')`, `data-testid="ade-proof-open"`,
    `:pending`-equivalent disabled while `open.isPending`) in the header row before the delete button.
  - Folder path span and summary `<p>`: add `select-text`.
  - Non-diagram step row: `<div class="flex items-start gap-1.5 ...">` with icon, `#ordinal`,
    description `<span class="min-w-0 flex-1 break-words select-text">`, source, then a
    `TooltipIconButton` (icon `link-external`, same label, `data-testid="ade-proof-step-open"`) that
    calls `open.mutate()`. Description no longer truncates.
  - Diagram step: markup unchanged (diagram carries its own aria label); only its size changes (above).
  - Reuse existing i18n keys only; no catalog change.
- Inline rendering of table/document/key-value data in the Details tab is not part of this phase: the
  spec asks those to be expanded where they render, which is the proof window; the tab lists them and
  opens the window.

## Tests

Backend half: payloads are unchanged. `internal/flows/proofflow` `TestProofCloseAndRead` already
writes `tests/contract/proof.json` (`ProofService.Step#document` holds nested `{"a":{"nested":true}}`,
plus `#keyvalue`, `#table`) and `TestProofDiagram` writes `proof-diagram.json`/`ade-proof-chain.json`.

Go test. Window size lives in `main.go` wiring the flow harness does not reach (its `ProofShell` fake
records the bounds-free record `OpenWindow` passes); two constants and a two-line assignment earn no
unit test (working agreement).

     bodies again.
