## Findings (codegraph)

### Why links wait on Jira

- Strip `links/AdeLinkStrip.vue` wraps every pill in `<QueryState :query="links.query">`;
  `links.query` is `useTaskArtifacts` (`queries.ts:601`), one IPC `AdeTaskService.Artifacts`. Until it
  answers, only a skeleton shows: even the Jira and host slot pills, which come from the board's
  `task` (`linkGroups.ts:126-153`), wait.
- Backend `TaskBoard.taskArtifacts` (`ade/artifacts.go:83`) runs every `ArtifactSource` in an errgroup
  and returns after `g.Wait()`. Each source gets `artifactSourceTimeout` = 5 s.
- `trackerSource.Artifacts` (`ade/issuetracker.go:49`) calls `p.Issue(ctx, ref, false)`. Jira path:
  `client.ready` (acli `--version`, `jira auth status`) then `workitem view` through acli. Cold cache:
  seconds; held acli: the full 5 s, then a `timeout` gap. So the whole list waits for acli: root cause.
- The tracker row this buys is never shown. `linkGroups` drops it (`linkGroups.ts:163`: issue row whose
  title or ref is the task's Jira key), because the task's own Jira slot pill stands for it. Only the
  tracker gap (`ade-links-gap`) is used.
- Jira details already have their own query. `useTaskLinks` calls `useTaskIssue` (same key as the
  card's `AdeTaskIssueLine`), and overlays `status`/`tone` on the `jira` item (`useTaskLinks.ts:62-80`).
  `TaskBoard.TaskIssue` answers a kept copy at once (P592), else reads acli under 10 s.
- Other `TaskArtifacts` consumers need no Jira data: `AdeTaskChain` timeline uses stored rows only
  (`taskTimeline.ts:48`); `AdeHandoverPrompt` waits at most 400 ms ("Artifacts can be slow (issue
  tracker)"). Agent finish reply uses Quick mode, already static (`issuetracker.go:54`).

### PR tooltip (reproduced)

Throwaway spec on the `ui` project (board fixture, task `T_bill`, hovered the Main tab PR line glyph
`ade-task-branch-pr-state` and the board row glyph `ade-branch-pr`), screenshots in the session
scratchpad. Result:

- Task view (Main tab PR line, `PrGlyph variant="tooltip"`): one row, `Open  Checks failed  No conflicts`,
  box 206x26 px. Board row (`variant="button"`): one row, `Usage-based billing  Open · → main  Checks
  failed  No conflicts`, 379x26 px.
- Cause: `TooltipContent` default variant is `inline-flex items-center gap-1.5`
  (`packages/theme/src/components/ui/tooltip/index.ts`). `PrGlyph` puts title, state and each
  `PrStatusLines` part in sibling `<div>`s, meant to stack (`PrStatusLines` comment: "`div` stacks the
  lines (tooltip)"). Inside the row flex they run side by side, separated only by the 6px gap; with
  `max-w-sm` a long title wraps per column.
- State line reads `Open · → main`: `common.dotPair` joins the state and `space.ade.mainTab.prBase`
  (`→ {base}`), a dot then an arrow.
- Existing spec `ade-v2-pr-glyph.spec.ts` "one tooltip lists every reported part, one line each" counts
  parts only, so the row layout passed.

## Design

### Part 1: links first, Jira after

Backend, `ade/issuetracker.go`:

- `trackerSource.Artifacts`: return `[]Artifact{staticIssueArtifact(...)}` for any task whose link the
  provider parses, Quick or not. No `p.Issue` call, no gap. Drop the Quick branch (same result). Update
  the comment: the row is the stored link only; title, status and failure reason come from
  `TaskIssue`, the UI's own query. `artifactSourceTimeout` comment stays (host and git sources).
- No wire change: `ArtifactGap.Reason` stays (still a field of the type; trackers no longer set it).
  Check with `codegraph_explore` whether anything else sets or reads tracker gaps (`Reason`, `Count`)
  before touching the struct; leave the wire type as is either way (P143 freeze).
- `builtinArtifactSources` comment: tracker source lists the static row only.

Frontend:

- `useTaskLinks.ts`:
  - `gaps`: artifact gaps plus the tracker gap from `issue.data` (same rule as
    `AdeTaskIssueLine`'s `gap`: none for `noTracker` or empty reason, else
    `{ source: issue.provider, repo: '', reason }`). Strip keeps showing "Jira CLI not installed" and
    friends, now without waiting.
  - Jira item while `issue.isPending` (query enabled, no data yet): `pending: true`. Loaded with a
    title: `status`, `tone` as today. Loaded without title or with a reason: neither.
  - Return `issue` is not needed by the strip; keep the return shape plus `pending` on items.
- `linkGroups.ts` `LinkItem`: optional `pending?: boolean` ("Jira details still loading").
- `AdeLinkPill.vue`: `v-else-if="item.pending"`: `StatusDot tone="muted" pulse`,
  `data-testid="ade-links-pill-dot-pending"`, plus `sr-only` text `t('common.state.loading.loading')`.
  Same 8px slot as the real dot, so the pill keeps its width when the status lands (no jump). Failure
  drops the dot (rare; the gap line explains it).
- `AdeLinkStrip.vue`: pills no longer sit inside `QueryState`. Render the hint span and the
  `RovingFocusGroup` from `links.groups` always: slot pills (Jira, host) show on the first frame,
  artifact pills join when `Artifacts` answers. Below the group keep
  `<QueryState :query="links.query" variant="inline">`: `#loading` slot is the existing
  `ade-links-loading` row with one `ade-links-skeleton` (now under any slot pills); default slot holds
  gaps, action error and the empty state. Empty state (`ade-links-empty`) only once the query has data
  and `groups` is empty. Tracker gap must show even while artifacts load: render the gap `<p>` outside
  `QueryState`, fed by `links.gaps` (artifact gaps join when loaded). Keep testids unchanged.
- `AdeHandoverPrompt.vue`: comment no longer blames the issue tracker (host and git can still be
  slow); grace logic unchanged.

TanStack Query: two independent queries, `useTaskArtifacts` and `useTaskIssue`, neither awaits the
other. No aggregate query, no `placeholderData` coupling.

Declined: a quick-then-full artifacts pass (`ArtifactScope.Quick` exposed over the wire). The ask names
Jira as the wait; host and git sources answer from the persisted change-request index and board fact
caches, and a split needs a wire arg on a frozen contract plus a second IPC per mount. Slot pills now
show at once regardless.

### Part 2: PR tooltip

`PrGlyph.vue`, both hover variants:

- Wrap tooltip body in `<div class="flex flex-col items-start gap-0.5 text-left"
  data-testid="pr-glyph-tip">`: button variant (default slot of `TooltipIconButton`) holds title
  (`font-medium`), state line, `PrStatusLines as="div"`; tooltip variant holds state line and lines
  (the PR line already shows the title beside the glyph). One element per line, stacked, left aligned.
  Local wrapper, not a theme variant change: `default` stays inline for every other tooltip.
- State line: new key `space.ade.pr.stateBase.label` = `"{state} into {base}"` (`Open into main`),
  replacing `dotPair` + `→ {base}` inside the tooltip only. `inline` variant (host view sidebar,
  phone) keeps its current text; it is not a tooltip.
- No colour change: `PrStatusLines` stays untinted in tooltips, per its comment.
