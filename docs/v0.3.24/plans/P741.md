# P741: Code review window: correct diff colours after a file is marked reviewed

Spec: `docs/v0.3.24/SPEC.md` § P741. User: "the diff against the base is colored properly, but after
I mark a file reviewed and there are some new changes over, the changes shown are correct but it's
all green and the changes a different shade of green ... like added over added". Base `e30b078c9`
(chapter head with P740). Stream E, parallel with P739 (Stream A, review window speed).

Overlap verdict: **none semantic, one shared doc file, no ordering dependency**. Code files here
(`reviewDecorations.ts`, `review-decorations.css`) are outside P739's ownership table (P739 touches
`FileTree.vue`, `ReviewFilesPane.vue`, `reviewFiles.ts`, `difftree.go`, `incremental.go`,
`gitreview/*`). Only `docs/ARCHITECTURE.md` is shared: one bullet here (review layer, line ~2154),
separate hunk from P739's (lines ~1448, ~2146, ~2147, Diff semantics). New tests and contract are new
files. No serialization needed.

## Reproduction (done by planner, implementer reconfirms first)

Scratch Playwright `ui` spec (review window, `reviewControl`/`GIT` from `support/reviewHunkDiff.ts`;
deleted after use), WebKit test bundle:

- Committed, since-review: `review.files` one file `{kind:'partial', changedSinceReview:true,
  reviewedAtSha}`; `file.read` left `a b c d e`, right `a b C! d e f`; `review.fileDiff` (sinceReview)
  hunks `c`->`C!` and `+f`, `reviewedRanges [1-2, 4-5]`, `lineCount 6`.
- Uncommitted: contract `ade-review-working-review` `ReviewWorkingFile#reviewed` (`reviewedRanges
  [3-3]`, the changed line).

Result, both cases, side by side and inline alike:

- Diff sides are right: left shows the reviewed text, right the tip; Monaco marks only the real
  change (`.line-insert` on `C!` and `f`, `.line-delete` on `c`). **No backend or side error.**
- Every reviewed unchanged line of the right pane carries `.kira-review-line-reviewed`, a whole-line
  background `color-mix(--kira-ok 15%)` = `rgba(87,188,138,.15)`, green. Changed lines carry Monaco's
  `line-insert` `rgba(155,185,85,.2)` (yellow-green) plus `char-insert`. Screenshot: right pane all
  green, changes a second green. That is the user's picture.
- Uncommitted partial (reviewed range on an added line): the line stacks reviewed tint over
  `line-insert` over `char-insert`: literally "added over added".

A base (range) diff of an unreviewed or fully reviewed file shows no tint (`paint()` skips the tint
when coverage is `full`, P75), hence "base colours properly". The tint appears exactly when a file is
partial, which is what "marked reviewed, then new changes" produces: the projected reviewed ranges
cover every line but the new ones.

## Root cause

`apps/kira-space/frontend/src/views/repo/reviewDecorations.ts` `paint()` (lines 305-329) paints the
partial-review coverage as a whole-line content background (`className: 'kira-review-line-reviewed'`,
`packages/theme/src/review-decorations.css:41`) in `--kira-ok` green. The diff editor already uses
green line backgrounds to mean "added". Two meanings, one hue, same layer: reviewed context reads as
added, and a reviewed added line stacks both.

Checked and not a cause:

- Since-review sides (`useDiffEditor.ts` `loadDiffSides`): left = `review.snapshot` text when its
  `reviewedAtSha` equals the tab's `left`, else `file.read` at `reviewedAtSha`; right = `file.read` at
  branch tip. Correct in the repro and in the backend (`ReviewSnapshot`, `ReviewFileDiff`,
  `incremental.go:640-718`). The flow test below pins it.
- P740's empty-side special case (Monaco `DefaultLinesDiffComputer.computeDiff` one-empty-line
  branch): reached only when a side is `''`. A since-review left side is the reviewed text, never
  empty, unless the reviewed file itself was empty. An added file (left missing) in range mode hits
  it: one char mapping over the whole text, so every line shows `line-insert` plus `char-insert`.
  That is the same two layers Monaco paints on any pure inserted line (`diffWholeLineAddDecoration`),
  i.e. a normal all-added diff. No change; the UI spec below asserts the added-file case equals a
  normal added line once the tint is gone.
- Monaco theme: no `diffEditor.*` colours overridden in `monacoTheme.ts`; defaults are fine.

## Fix

Coverage of a partial review moves out of the code background into the gutter, as a rail (the app's
state vocabulary, ARCHITECTURE "State shows as rail, border, outline or chip colour"). The diff keeps
Monaco's colours untouched, so a since-review diff colours exactly like a base diff.

### 1. `apps/kira-space/frontend/src/views/repo/reviewDecorations.ts` `paint()`

In the `reviewedLineCollection.set(...)` decoration options:

- Replace `className: 'kira-review-line-reviewed'` with `marginClassName: 'kira-review-line-reviewed'`
  (whole-line margin decoration: rendered in `.margin-view-overlays`, never in `.view-overlays`).
- Keep `isWholeLine: true`, the overview ruler entry (`--kira-ok`, left lane) and the
  fully-reviewed skip unchanged.
- Update the P75 comment above to say the rail, not a tint.

Margin, not `linesDecorationsClassName`: the diff editor's `+`/`-` indicators already occupy the
lines-decorations column (`insert-sign`), and `lineNumberClassName` is taken by the add mark and the
comment tint (`kira-review-ln-*`), which would fight over `color`.

### 2. `packages/theme/src/review-decorations.css`

Replace the `.kira-review-line-reviewed` rule and its comment:

```css
/* Partly reviewed file: a rail at the gutter's left edge on each reviewed line
   (reviewDecorations.ts, marginClassName). Never a content background: green there means "added"
   in the diff editor (P741). */
.monaco-editor .margin-view-overlays .kira-review-line-reviewed {
  box-shadow: inset 3px 0 0 var(--kira-ok);
}
```

No background, so Monaco's `gutter-insert` margin colour on a changed line stays as in a normal
diff. Global CSS: Monaco owns the node (same reason as the file's other classes). The implementer
checks the rail is visible over the line numbers in both layouts by screenshot; if
`.margin-view-overlays` stacking hides it, raise only this rule (e.g. `position: relative; z-index`)
and say so in the commit.

### 3. `docs/ARCHITECTURE.md`

Bullet "A fully-reviewed file's whole-line tint is skipped..." (line ~2154): partial review shows as
a gutter rail (`marginClassName`) plus the overview ruler, never a content background, because diff
colours own the content area (P741); a fully reviewed file shows no rail. Separate hunk from P739.

No i18n, no store, no new component, no Go change.
