# P740: Code review window: collapsible uncommitted changes, readable removed files

Spec: `docs/v0.3.24/SPEC.md` § P740. Base: `aecbc8faa`. Stream B, parallel with P739 (Stream A,
review window speed) and P742 (Stream C, Studio MCP).

Overlap verdict: **small, additive, no ordering dependency**. Three files likely shared with P739
(`ReviewFilesPane.vue`, `useDiffEditor.ts`, `RepoDiffView.vue`); each edit here is a self-contained
hunk (new branch, new block, new returned field) listed below. Serialize instead only if P739's plan
rewrites `useDiffEditor.mount()`/`loadDiffSides()` or `RepoDiffView.vue`'s `mount()` wholesale, or
replaces the uncommitted `<section>` in `ReviewFilesPane.vue`. Nothing shared with P742. P741 (diff
colours after reviewed) untouched: no Monaco theme or `diffEditor.*` colour change here.

## Reproduction (done by planner, implementer reconfirms first)

Scratch probes, deleted after use:

- Go: `review.fileDiff` (both modes, before and after a mark) on a file deleted on the branch, and
  `ReviewWorking`/`ReviewWorkingFile`/`ReviewWorkingMark`/`ReviewWorking` on a deleted uncommitted
  file. Every call succeeds with the right shape: body is one all-`del` hunk (`newStart 0`), `lineCount
  0`, worktree side `missing`, mark goes `full`. **No backend error.**
- Playwright `ui` (review window, mocked `adeTaskReviewWorkingDiff` head `found` 30 lines, worktree
  `missing`): no error banner. Rendering is the defect:
  - Side by side: the old text is squeezed into the left half of the narrow centre pane; the right
    half is an empty hatched pane.
  - Every char sits on two stacked reds (line background plus char background): text reads poorly.
  - A phantom changed line: left shows line 31 `−` (the trailing newline's empty line), right shows
    line `1 +` painted as an insertion. A deleted file reads as "31 removed, 1 added".
  - Review layer still offers "add comment" on line 1 of the empty right side.

So: **not a real error, unreadable rendering.**

Uncommitted section: header in `ReviewFilesPane.vue` is a plain `<div>`, no trigger; it always takes up
to 40% of the left pane. Confirmed in the same run.

## Root causes

1. Readability: Monaco 0.57 `DefaultLinesDiffComputer.computeDiff`
   (`node_modules/monaco-editor/esm/vs/editor/common/diff/defaultLinesDiffComputer/defaultLinesDiffComputer.js:30`)
   special-cases a side that is one empty line: it returns a single mapping covering both whole files
   with one char-level `RangeMapping` over the entire text. Hence the stacked char+line red, the
   phantom `+` line on the empty side, and the phantom `−` trailing line. Any deleted file hits it:
   `useDiffEditor.ts` `loadDiffSides()` turns a `missing` worktree/right side into `text: ''`
   (`toDiffSide`, backend `DiffSide`), then `mount()` (`useDiffEditor.ts:297-317`) feeds it to
   `createDiffEditor`. Same path for committed (`file.read` at branch tip answers `missing`) and
   uncommitted (`ReviewWorkingDiff` worktree `missing`). Not fixable by options; a diff against an
   empty model is the wrong view.
2. Not collapsible: `ReviewFilesPane.vue` uncommitted `<section data-testid="review-working">`
   (template, after the committed `FileTree`) has no Collapsible; header is static.

## Changes

### 1. Uncommitted section collapsible (`packages/git-ui/src/components/review/ReviewFilesPane.vue`)

Additive hunk, only inside the `review-working` `<section>` and its script support.

- Import `Collapsible, CollapsibleContent, CollapsibleTrigger` from `@theme/components/ui/collapsible`
  (shadcn-vue, same as `AdeReviewRemoved.vue`), `ref`, `watch` from vue.
- `const workingOpen = ref(true);` Watch `() => props.cursor?.section`: when it becomes `'working'`
  set `workingOpen = true`, so stepping (Alt+F8, `useReviewStepping`) or a centre-tab follow onto an
  uncommitted file never lands in a hidden list.
- Replace `<section …>` with `<Collapsible v-model:open="workingOpen" as="section" …>` keeping
  `data-testid="review-working"`, the `flex flex-col min-h-0` classes, and the existing
  `committed ? 'max-h-[40%] shrink-0' : 'flex-auto'` binding, but apply the 40% / flex-auto sizing
  only while open (closed: `shrink-0`, header height only). The committed tree is `flex-auto`, so it
  takes the freed space with no other change.
- Header `<div data-testid="review-working-header">` becomes `<CollapsibleTrigger as-child>` around
  a `<button type="button">` with the same row classes plus `w-full text-left`, keeping the testid.
  First child: `CodiconIcon` `chevron-down` / `chevron-right` (12px), then the existing edit icon,
  label, changed count, reviewed count. Reka sets `aria-expanded`/`data-state`.
- Hint `<p>` and working `FileTree` go inside `<CollapsibleContent class="flex min-h-0 flex-auto flex-col">`.
- Tailwind utilities only; no `<style>`.

No IPC crossed: pure UI state, so no flow half. Not persisted (Collapsible default open matches
today; nothing asked for persistence).

### 2. Removed files read as the old file (`apps/kira-space/frontend/src/views/repo/useDiffEditor.ts`)

A one-sided deletion renders as a single read-only code editor of the old side, full width, normal
syntax colours, every line tinted removed. Added files (head `missing`) hit the same Monaco special
case mirrored; out of P740 scope (ask names removed files only): orchestrator decides on a follow-up.

- New exported helper `isDeletion(diff: { head: DiffSide; worktree: DiffSide }): boolean`:
  `head.kind === 'found' && worktree.kind === 'missing'`.
- `DiffEditorHandle` gains `deleted: Ref<boolean>` and `codeEditor: ShallowRef<StandaloneCodeEditor | null>`
  (the single editor; `editor` stays the diff editor, null when `deleted`).
- `mount()`: after the binary/tooLarge/bothMissing checks and the `container`/`isCurrent` guard, if
  `isDeletion(diff)`:
  - `const model = getOrCreateModel(mod, headUri.toString(), diff.head.text, language)` (same URI as
    the diff's left model, so a later diff mount of the tab reuses it).
  - `mod.editor.create(container.value, {...})` with `readOnly`, `domReadOnly`, `automaticLayout`,
    `minimap off`, `scrollBeyondLastLine false`, `glyphMargin false`, `renderValidationDecorations
    'off'`, font settings, `fixedOverflowWidgets` + `overflowWidgetsDomNode` (mirror `createDiffEditor`
    options and `useReadonlyFileViewer.createEditor`; that composable is not reused: it carries tab
    markdown-reading state this view has none of).
  - `created.createDecorationsCollection([{ range: model.getFullModelRange(), options: { isWholeLine:
    true, className: 'kira-diff-line-removed' } }])`. Skip the decoration on the trailing empty line:
    end the range at the last line with content (`model.getLineCount()` minus one when the last line
    is empty and count > 1).
  - `registerEditor(editorKey, headUri.toString(), created)` (editors.ts; `unmountEditor` in
    `dispose()` already covers it). View-state restore across diff/code editor types is safe: both
    `restoreViewState` implementations guard their own shape.
  - `codeEditor.value = created; deleted.value = true; contentHash.value = diff.contentHash;
    goToFileImpl = null; state.value = 'found'`; return. No `rememberRead` (worktree side has no
    stat), no `createDiffEditor`, no layout watch.
- `dispose()`: also null `codeEditor`, reset `deleted`.

`apps/kira-space/frontend/src/views/repo/RepoMultiDiffView.vue`: no edit. A deleted file's section
gets the same single-pane view (state stays `'found'`); its go-to-file becomes a no-op, as the target
does not exist at `right`.

### 3. `RepoDiffView.vue` (`apps/kira-space/frontend/src/views/repo/RepoDiffView.vue`)

- `const deleted = ref(false);` set from `handle.deleted.value` after `handle.mount()`.
- `mount()`: when `deleted`, register `view.find` against `handle.codeEditor.value`, skip
  `registerCommand('repo.goToFileFromDiff')`, `attachReviewDecorations` and `attachDiffNavigation`,
  then return. Toolbar prev/next stay usable: with no `diffNavigation`, `canNext`/`canPrevious` and
  `onNextChange`/`onPreviousChange` already fall through to `hasAdjacentFile`/`crossFile` (next file
  in the review list). Review layer skipped on purpose: comments and hunk marks anchor to new-side
  lines (backend `LineRange`s), a deleted file has none (`lineCount 0`, no `hunkChangeBlock`);
  whole-file review stays on the list checkbox.
- Template toolbar: `v-if="deleted"` `Badge variant="error"` (exists in
  `packages/theme/src/components/ui/badge/variants.ts`) `data-testid="repo-diff-deleted"`
  with new key `space.repo.view.deletedFile.label` ("Deleted"). Hide the layout `SecondaryTabs` and
  the Go to file button when `deleted` (`state === 'found' && !deleted`).
- `workingDiff` watch: when `diffEditor` is mounted and `isDeletion(diff) !== deleted.value` (file
  restored on disk, or deleted after the tab opened), re-mount: run the same teardown as
  `onUnmounted` (extract it to `teardown()`, called by both), reset `state = 'loading'`, `await
  nextTick()`, `mount()`. When both deleted: `handle.codeEditor.value?.getModel()` `setValue(diff.head.text)`
  if it differs (HEAD moved), set `contentHash`. Otherwise today's diff-model rewrite.
- `data-review-ready` stays false for a deleted tab (no review layer); specs below wait on
  `repo-diff-deleted` instead.

### 4. Tint class (`packages/theme/src/review-decorations.css`)

Append:

```css
/* A deleted file's lines in its single-pane view (useDiffEditor.ts): one removed tint, the
   counterpart of the diff editor's line background without its char layer. */
.kira-diff-line-removed {
  background-color: color-mix(in srgb, var(--kira-error) 15%, transparent);
}
```

Global CSS, not a Tailwind utility: Monaco decoration `className`s land on Monaco-owned nodes, and
this file is the established home for them (`kira-review-line-reviewed` precedent).

### 5. i18n (`packages/theme/src/i18n/en.json`)

Add `space.repo.view.deletedFile.label`: "Deleted". Additive key.
