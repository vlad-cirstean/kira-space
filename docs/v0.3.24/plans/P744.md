## Findings

Verified against the repo at tag `v1.2.1` (cloned), the release assets and a real install of the oss
binary under the scratchpad (isolated `HOME`/`XDG_*`). Docs pages read from the repo's `docs/guide/`.

### Edition and licence

- Latest release `v1.2.1` (2026-11-19). Assets `rtk-oss-<target>.tar.gz` hold exactly `rtk` and `LICENSE`
  (Apache-2.0). `checksums.txt` lists them; the downloaded linux x86_64 musl archive matched.
- Package level: crate `rtk` and `rtk-text` are Apache-2.0. `rtk-engine`, `rtk-plugin`, `rtk-proxy` are
  BUSL-1.1. Feature `engine` is default; oss is `--no-default-features`, which drops `rtk-engine` and
  `rtk-plugin` from the graph. Upstream CI job `oss` asserts no `rtk-engine` in that graph.
- `cargo tree --locked --no-default-features -e normal,build` (musl target): every crate MIT, Apache-2.0,
  BSD, ISC, Zlib, Unlicense, MPL-2.0, Unicode-3.0, CDLA-Permissive-2.0 or Boost (`BSL-1.0`, not BUSL). No
  BUSL. Passes the open-source-only rule.
- Per feature used: PreToolUse rewrite hook (`rtk hook claude`), command filters, `rtk bypass`,
  `rtk recall`, `rtk telemetry disable/status`. All in the Apache crate. Engine-only and absent from oss:
  `rtk pipeline`, `methods`, `tasks`, PostToolUse compression (`hooks/posthook.rs`, rewrites Read/MCP
  output), pipeline files. Not used and never installed: `rtk-proxy` (BUSL), `rtk llm-proxy`.
- Edition probe: oss `rtk pipeline --help` exits 2 (no such subcommand); full edition has it. `rtk
  --version` prints `rtk 1.2.1` for both, so version alone cannot tell editions apart.
- Name collision: crates.io has another `rtk`. Never `cargo install rtk`.

### Provenance

- No signature or attestation on releases; `checksums.txt` sits in the same release. Upstream
  `install.sh` (read in full) resolves latest via redirect, downloads `checksums.txt` and the archive,
  checks SHA-256 against that same file, rejects path-traversal entries, moves `rtk` to
  `$HOME/.local/bin`. It does not run `rtk init`. Same-release checksum guards transport only.
- Plan: no `curl | sh`. Own script pins version and per-target archive SHA-256 in repo (trust on first
  use, then tamper-evident), same steps as `install.sh` otherwise. Pins for `v1.2.1`:
  - `x86_64-unknown-linux-musl` `44aa460c4827d206d11405c652832c9f7082edccfbc3a9f15a69a851e8a9e8b4`
  - `aarch64-unknown-linux-musl` `b01860ae2d3f44e0f7fc4431a95dd66b29b4bd87ec7f5e60aff13681b05db5dd`
  - `aarch64-apple-darwin` `5a37e5e8e016b559597024900e7b21cff7a0015aa189ac6ac80d461cbb4be65b`
  - `x86_64-apple-darwin` `5e39ee8c4613c798f8d62868d4851bacca5aefcc134301052841e458ed71c797`
- `github.com/rtk-ai/rtk/releases/download/...` is reachable here (302 to the asset host, followed).
  `releases/latest` and `api.github.com` are blocked by the egress proxy: the script never needs them.

### What `rtk init` writes (real `--dry-run`, isolated HOME)

- `rtk init --dry-run` (project): adds rtk instructions to `CLAUDE.md`, creates `.rtk/filters.toml`. No
  hook. Rejected: bloats `CLAUDE.md`, no rewrite.
- `rtk init -g --dry-run`: creates `~/.claude/RTK.md`, adds `@RTK.md` to `~/.claude/CLAUDE.md`, patches
  `~/.claude/settings.json` with `PreToolUse` matcher `Bash`, command `rtk hook claude`, creates
  `~/.config/rtk/filters.toml`; also offers the proxy and the telemetry consent prompt.
- rtk has no project-scoped Claude Code hook. Claude Code reads the same hook shape from the project's
  `.claude/settings.json`, so the repo commits it there, like `.mcp.json` and the `codegraph
  prompt-hook`. Every session in every worktree gets it; nothing user-global changes except the binary.
  Never run `rtk init`.
- Project-level also keeps rtk out of sessions Kira itself drives on this machine and out of real
  `claude` tests (`apps/kira-space/tests/claude` runs in `t.TempDir()`, outside the repo); a global
  hook would alter both, the details benchmark included.

### Hook behaviour (from `hooks/hook_cmd.rs`, `hooks/decision.rs`, `rtk rewrite` probes)

- Output: `updatedInput.command` rewritten; `permissionDecision` omitted by default, so Claude Code's own
  permission flow judges the rewritten command. `allow` only when a `permissions.allow` rule in a settings
  file matches the original; a deny rule leaves the command untouched. Allow rules passed on the CLI or by
  `create_session` are invisible to rtk: in `default` mode the rewritten `rtk …` form can then prompt.
  Never add a `Bash(rtk:*)` allow rule (it would allow `rtk bypass <anything>`).
- Fail-open: parse error or unknown command emits nothing, exit 0. Cost about 26 ms per Bash call (50
  hook runs in 1.29 s).
- Rewritten: `git status/diff/log/show/commit/push`, `go test/build/vet`, `golangci-lint`, `bun run`,
  `bun test`, `bunx`, `npx tsc`, `ls`, `find`, `grep`, `rg`, `cat` (to `rtk read`), `head`, `wc`, `jq`,
  `curl`, `docker`, `gh <sub>`. A grep that consumes a pipe is rewritten too.
- Not rewritten: `gh auth status`, `gh auth token`, `env`, `printenv`, `az …`, `sh <script>`, redirects
  to a file, a pipe into `wc`, any command prefixed `RTK_DISABLED=1`, `rtk bypass …`.

### Fidelity (measured)

- `cat` via `rtk read`: byte-identical on `docs/ARCHITECTURE.md` (915,016 B), a Go test file, `package.json`.
- `git diff`: lossy. `git diff HEAD~3` 23,833 to 14,808 B; prints `... (231 additions truncated)` and
  `[full diff: rtk git diff --no-compact]`. `rtk bypass git diff HEAD~3` is byte-identical to raw.
- `grep -rn`: caps 25 matches per file, tail line `+314 more ... [+314 hidden: rtk recall <hash>]`.
  `grep -c` and a grep piped into `wc -l` stay exact (339 = 339, 42 = 42).
- Commit with a failing pre-commit hook: full hook output and exit 1 kept (61 lines). Passing commit:
  hook output dropped, `ok <sha>` only.
- `go test` failing: decisive line `a_test.go:10: Sum() = 2, want 3` and panic head kept, exit 1, `[full
  output: rtk recall <hash>]`. `bun test` failing: assertion diff and file:line kept, exit 1.
- Exit codes preserved in every case tried; `rtk bypass` preserves them too.

### Telemetry, credentials, local data

- Telemetry is consent-gated and off by default; `rtk init` asks, nothing else enables it. The oss binary
  still compiles the daily ping (release build bakes the endpoint). `RTK_TELEMETRY_DISABLED=1` blocks it
  regardless of config; `rtk telemetry status` then prints `enabled: no` and `env override:
  RTK_TELEMETRY_DISABLED=1 (blocked)`. `rtk telemetry disable` writes `consent_given = false` locally,
  no network.
- Other outbound HTTP in oss: `rtk llm-proxy` (unused). No update check.
- Credentials: `rtk gh` runs `gh` and filters its stdout (`resolved_command("gh")`); rtk never reads
  `hosts.yml`, `GH_TOKEN` or any az token (source grep: the only token names are a dotnet output-scrub
  list). `gh auth token`/`status` pass through unrewritten. Matches the CLI-credentials rule (run the CLI,
  read its output). G5 is a Go AST guard over Go dirs only; it never sees the new sh/json/md files.
- Local data under `~/.local/share/rtk` (owner-only, `rtk verify` checks it): `history.db` (command
  names and token counts, 90 days), `recall.db` (elided output, so `rtk recall` can restore it). Never
  leaves the machine.
- Missing-hook nag: rtk probes only `~/.claude/settings.json`, so with a project hook every rtk command
  prints `[rtk] /!\ No hook installed — run rtk init -g …` once a day into the agent's output.
  `RTK_SUPPRESS_HOOK_WARNING=1` silences it (verified).

## Design

### Decisions

1. Edition `rtk-oss` `v1.2.1`, prebuilt archive, pinned per-target SHA-256. Building from source
   (`cargo build --release --no-default-features` at the tag) declined: needs a Rust toolchain on every
   dev machine for no licence gain; the archive is the same build.
2. Hook project-level, committed in `.claude/settings.json`, through a guard wrapper. Binary user-global
   in `${RTK_INSTALL_DIR:-$HOME/.local/bin}`, installed by an idempotent `scripts/rtk-setup.sh`, run once
   per machine (worktrees share it) and by `scripts/prepare-dev-environment.sh`.
3. Wrapper fails open: no `rtk` on PATH, or the full edition on PATH, means exit 0 and the command runs
   unchanged. The repo never runs BUSL code, and a CI or fresh machine without rtk is unaffected.
4. Telemetry off twice: `env` block in project settings (every Bash command) plus the wrapper's own
   export (hook process), and `rtk telemetry disable` in setup. Never `rtk telemetry enable`.
5. Raw output by rule, not by config: `rtk bypass <cmd>` where every line counts. rtk's per-command
   exclusion (`hooks.exclude_commands`) lives only in user-global `~/.config/rtk/config.toml` (no project
   config, `RTK_CONFIG_DIR` covers only engine pipelines), so it cannot be committed. A wrapper that
   parses the command to skip `git diff` would re-implement rtk's shell splitter; declined. rtk marks
   every cut with its recovery path, so a truncated result is visible.
6. No `RTK.md`, no `rtk init`, no `.rtk/` filters, no proxy, no pipelines.

### `scripts/rtk-setup.sh` (new, POSIX sh, sources `scripts/lib.sh`)

Header comment in the style of `codegraph-setup.sh`: what, why oss, run once per machine, never a
SessionStart hook. Steps:

1. `set -eu`, source `lib.sh` (`sha256_file`, `require_cmd`). `RTK_VERSION=1.2.1`.
   `INSTALL_DIR="${RTK_INSTALL_DIR:-$HOME/.local/bin}"`, `BIN="$INSTALL_DIR/rtk"`.
2. Map `$(uname -s)-$(uname -m)` to target and pinned SHA-256 (the four above; `Linux-aarch64` and
   `Linux-arm64` both to aarch64 musl). Anything else: error naming the platform, exit 1.
3. `is_pinned_oss <bin>`: `"$1" --version` equals `rtk $RTK_VERSION` and `"$1" pipeline --help` fails.
4. If `$BIN` passes `is_pinned_oss`: print `rtk-setup: rtk-oss $RTK_VERSION already at $BIN`, skip to 7.
5. If `$BIN` exists and fails: allowed to replace only an oss build of another version (`--version`
   starts `rtk ` and `pipeline --help` fails). Full edition or foreign binary (crates.io collision):
   error telling the user to remove it, exit 1. Never touch a binary outside `$INSTALL_DIR`.
6. Download `https://github.com/rtk-ai/rtk/releases/download/v$RTK_VERSION/rtk-oss-$TARGET.tar.gz` with
   `curl -fsSL` into `mktemp -d` (trap removes it). Compare `sha256_file` with the pin, mismatch exits 1.
   `tar -tzf` must list exactly `rtk` and `LICENSE`, else exit 1. Extract `rtk`, `mkdir -p`, `mv` to
   `$BIN`, `chmod 755`.
7. Re-check `is_pinned_oss "$BIN"`. `command -v rtk` must equal `$BIN`; else error naming what PATH
   resolves and asking to put `$INSTALL_DIR` first, exit 1.
8. `RTK_TELEMETRY_DISABLED=1 "$BIN" telemetry disable >/dev/null`; then `"$BIN" telemetry status` must
   contain `enabled: *no`, else exit 1.
9. Print `rtk-setup: rtk-oss $RTK_VERSION at $BIN, telemetry off`.

No `rtk init`, no write inside the repo.

### `.claude/hooks/rtk-pretooluse.sh` (new)

```sh
#!/bin/sh
# PreToolUse(Bash) hook: rtk-oss rewrites the command so its output reaches the agent filtered.
# Fails open: no rtk on PATH, or the BUSL full edition, leaves the command unchanged.
# Setup: scripts/rtk-setup.sh; docs/DEV_ENVIRONMENT.md "rtk".
command -v rtk >/dev/null 2>&1 || exit 0
rtk pipeline --help >/dev/null 2>&1 && exit 0
RTK_TELEMETRY_DISABLED=1 RTK_SUPPRESS_HOOK_WARNING=1 exec rtk hook claude
```

Stdin (the hook payload) passes through `exec`. The edition probe never reads stdin.

Add, keeping existing keys:

"PreToolUse": [

### `CLAUDE.md`: new `## rtk` section after `## CodeGraph`

Standing rule only, terse:

- PreToolUse hook in `.claude/settings.json` rewrites Bash commands through rtk-oss (Apache-2.0); output
  arrives filtered. Setup: `docs/DEV_ENVIRONMENT.md`.
- Raw output where every line counts: code review diffs, verifying a subagent's claim, a failure the
  filtered output does not explain. Run `rtk bypass <cmd>`. Count with `grep -c` or `| wc -l`, never by
  reading a listing (rtk caps it per file).
- Reviewer and verifier prompts restate the bypass rule; CLAUDE.md on disk does not make a subagent
  follow it.
- Never `rtk init`, `rtk telemetry enable`, `rtk llm-proxy`, `rtk-proxy`, or the default (BUSL) `rtk`.

### `docs/DEV_ENVIRONMENT.md`: new section "rtk — filtered shell output"

Right after the CodeGraph section. Facts, terse:

- What: rtk-oss `1.2.1`, Apache-2.0 edition (full `rtk` links BUSL `rtk-engine`). Licence check
  method: release archive holds only `LICENSE`; `cargo tree --no-default-features` has no `rtk-engine`.
- Setup: `sh scripts/rtk-setup.sh`, once per machine (binary user-global, hook per repo);
  `prepare-dev-environment.sh` runs it. Pinned version and SHA-256; no `curl | sh`, no `rtk init`.
- Committed: `.claude/settings.json` `PreToolUse` hook and `env`; `.claude/hooks/rtk-pretooluse.sh`
  fails open. Hook settings load at session start: a session started before setup needs a restart.
- Raw output: `rtk bypass <cmd>`, or `RTK_DISABLED=1 <cmd>` (skips the rewrite); `rtk git diff
  --no-compact`; `rtk recall <hash>` restores an elided block.
- Behaviour to expect: the fidelity bullets above (diff truncation, grep cap, commit success `ok <sha>`,
  failure output kept, exit codes kept).
- Permissions: allow rules in settings files respected; CLI or `create_session` allow rules are not, so
  in `default` mode a rewritten command can prompt. Never allow `Bash(rtk:*)`.
- Telemetry: off (env in project settings, wrapper, `rtk telemetry disable`); verify with
  `RTK_TELEMETRY_DISABLED=1 rtk telemetry status`. Local data `~/.local/share/rtk`.
- Upgrade: bump `RTK_VERSION` and the four pins from the release `checksums.txt`; recheck licence (archive
  contents, `cargo tree --no-default-features` at the tag) and the edition probe.

## Checks (no unit tests beyond these)

1. Idempotency: run `sh scripts/rtk-setup.sh` twice. First installs (or reports present). Record `stat`
   mtime and `sha256_file` of `$BIN`; second run prints `already at`, same mtime and hash, exit 0, and
   still passes with `HTTPS_PROXY=http://127.0.0.1:9` (proves no download). `git status --porcelain`
   empty after both.
2. Guard cases: `RTK_INSTALL_DIR=<scratch>` with a fake `rtk` script printing `rtk 9.9.9` and accepting
   `pipeline`: setup exits 1 with the full-edition message, fake untouched. Same with a fake printing
   `something else`: foreign-binary message.
3. Hook: `printf '%s' '{"tool_name":"Bash","tool_input":{"command":"git status"},"cwd":"'"$PWD"'"}' | sh
   .claude/hooks/rtk-pretooluse.sh` prints JSON with `"command":"rtk git status"`. With `PATH` lacking
   rtk: no output, exit 0. Same payload with `gh auth token`: no output.
4. Telemetry: `RTK_TELEMETRY_DISABLED=1 rtk telemetry status` shows `enabled: no` and the env override.
5. Before/after bytes on this worktree, raw vs `rtk <cmd>` with `RTK_SUPPRESS_HOOK_WARNING=1`: `git
   status`, `git log -20`, `git diff <base>` (base = phase start), `go test -count=1 -v
   ./internal/agentsandbox/ ./internal/conventiontest/ ./internal/gitremote/ ./internal/approvals/`, `bun
   run lint`. Plus one failing `go test` in a scratch module: decisive line present in rtk output, exit 1.
   Numbers go in the Result.
6. Live hook: a session started after this lands runs `git status` through the Bash tool and gets the
   `* <branch>` form. Implementer cannot see its own session reload hooks; orchestrator confirms it in the
   next spawned session (P745) and notes it in the Result, or reports it as unconfirmed.

## Needs a user decision

- Diffs: default here is the `rtk bypass` rule. Alternative: each developer adds `exclude_commands =
  ["git diff", "git show"]` under `[hooks]` in their own `~/.config/rtk/config.toml` (user-global, cannot
  be committed), which keeps every diff raw and loses those savings.
- Pin age: `v1.2.1` is 4 days old (2026-11-19). Releases are unsigned; the in-repo pin is trust on first
  use. Say if an older release or a source build is preferred.
