# P742: Studio MCP tools: agent can force an approval prompt for an allowed operation

Spec: `docs/v0.3.24/SPEC.md` § P742. Base: `aecbc8faa`. Stream C, parallel with P739 (Stream A, code
review window frontend) and P740 (Stream B, code review window backend).

User's words: "The studio MCP tools should also allow the agent to issue a prompt even if that op is
allowed. This can be used when the agent wants to show the user a more sensitive action that he needs a
confirmation for."

Overlap verdict: **small, additive, no ordering dependency**. Only shared files: `en.json` (new keys
under `workbench.approvals.risk`), `docs/ARCHITECTURE.md` (new bullets in Studio MCP sections),
`docs/v0.3.24/SPEC.md` (own row only), and possibly `internal/llmprompts/registry.go` /
`testdata/budget.tsv` (only `dbmcp.*` entries here). P739/P740 touch code review window code, none of
the Studio MCP or approvals files below.

No approval mechanism: `list`, `describe`, `operations` (cancel is ungated). Out of scope.

Approval data path: `ApprovalRequest` (`approval.go:264`, `Reason` = `permission` | `exemption`) ->

dialog and phone `PhoneApprovals.vue` both render it). Card's `risks` computed
(`ApprovalItemCard.vue:91`) is one generic spot for every kind.

Response stage copies the pre-run request: `holdResult(ctx, req, ..)` (`held.go`) sets
`Stage = response`; `kubeFinish` -> `holdKube` passes `areq`. A confirm note/reason must not leak onto
the held-result item or its audit row.

Audit: `dbaudit/recorder.go:269` records `req.Reason` free text (column `reason TEXT`, no CHECK). New
value `confirm` needs no migration.

Token budget (P733): `TestToolListWithinBudget` (`toollist_budget_test.go`) measured **3990 / 4000**
tokens at base. Rule in file: "Lower it with the texts; never raise it to fit." Five new properties cost
about 120 to 135 tokens, so existing texts must shrink first (see "Budget").

Scripts: kube and API prepare scripts return request fields (`kubeRequest`, `agentapi.Input`); `confirm`
lives outside both, so no script can set or clear it.

## Design

### Parameter

One optional string arg, same name and text on all five tools: `confirm`.

- Go: `Confirm string \`json:"confirm,omitempty"\`` on `runQueryArgs` (covers `run_query`, explain and
  `browseCall`'s synthetic args), `browseTableArgs`, `kubeReadArgs`, `runScriptArgs` (start only),
  `apiRequestArgs`.
- Arg entry per tool in `internal/llmprompts/registry.go`, next to each tool's other args:
  `_ = arg(DbmcpToolRunQuery.id, "confirm", studioApp, NextCall, \`Ask the user to approve anyway; say why.\`, NoVars{})`,
  same for `DbmcpToolBrowseTable`, `DbmcpToolKubeRead`, `DbmcpToolRunScript`, `DbmcpToolAPIRequest`.
  One string carries both the force and the card text: no boolean plus reason pair (token cost). No
  schema `maxLength` (16 chars x5 of budget); the handler enforces the cap.
- No instructions paragraph: the arg text is self-sufficient.

Semantics (one helper, `confirm.go` in `dbmcp`):

```go
// maxConfirmRunes caps the agent's confirm sentence.
const maxConfirmRunes = 300

// confirmText trims s; refusal is non-empty when it is over the cap. "" means no confirm.
func confirmText(s string) (text, refusal string)
```

Refusal text: `confirm is one sentence for the user, at most 300 characters. Nothing ran.` (wording
per tool where "ran" does not fit: kube "Nothing was read.", API "Nothing was sent."; reuse each tool's
existing nothing-happened suffix constant where one exists, e.g. `kubeNothingRead`). Checked first in
each handler, before connect, plan, scripts or any card. Whitespace-only = absent.

Rules:

1. Non-empty `confirm` turns an allowed op into a prompt. It never relaxes anything: `deny`, read-only
   connection, table allow list, column review, limits, exposure, scripts switch, API deny rules and
   `apiDefault: deny` refuse exactly as today, before any card.
2. Policy already asks (or exemption, or API missing input): card raised as today, `Reason` unchanged,
   agent note shown on it.
3. Only `confirm` raised the card: `Reason = ApprovalReasonConfirm` (`"confirm"`).
4. Everything after approval is unchanged: rechecks (`recheckAfterApproval`, `kubeApprove` re-resolve,
   `approveScript` exposure check, `recheckAPISwitches`), review offer, kept values, held result.
5. Deny/timeout/abandon/full queue: existing `approvalOutcomeError` text.

### Backend changes (`apps/kira-space/internal/dbmcp`)

- `approval.go`: add `ApprovalReasonConfirm ApprovalReason = "confirm"` (comment: agent asked for an
  op its policy allows). Add `AgentNote string` to `ApprovalRequest` (the agent's confirm sentence; set
  on pre-run items only). Update `Reason` field comment.
- `confirm.go` (new): `maxConfirmRunes`, `confirmText`, and
  `func confirmReason(policyAsks bool) ApprovalReason` (permission when policy asks, else confirm).
- `tools.go`:
  - `runQuery`: `confirmText(args.Confirm)` first; refusal -> `errResult`. Store trimmed text back in
    `args.Confirm`. Pass `Confirm` into `explainQueryArgs` (new field).
  - `awaitApproval`: proceed when `rv.verdict == "prompt" || args.Confirm != ""`; request gets
    `Reason: confirmReason(rv.verdict == "prompt")`, `AgentNote: args.Confirm`. Approval error subject
    unchanged.
  - `explainQuery`: case `"allow"`: if `args.Confirm != ""`, run `awaitExplainApproval` with reason
    confirm; case `"prompt"`: permission. `awaitExplainApproval` takes the reason and sets `AgentNote`.
- `limits_gate.go` `awaitExemption`: add `AgentNote: args.Confirm` (Reason stays exemption).
- `browse.go`: `browseTable` runs `confirmText(args.Confirm)` first; `browseCall` copies the trimmed
  text into the synthetic `runQueryArgs.Confirm`, so `awaitApproval`/`awaitExemption` need nothing else.
- `kube_tools.go`/`kube_script.go`: `kubeCall` gains `confirm string`; `kubeRead` validates
  `a.Confirm` first and sets it. `kubeRun` sets `areq.Reason = confirmReason(c.Mcp.Approval != "allow")`,
  `areq.AgentNote = call.confirm`. `kubeApprove`: skip only when `c.Mcp.Approval == "allow" &&
  call.confirm == ""` (keep the fail-closed comment).
- `script_tools.go`: `runScript` validates `a.Confirm` in the start branch (with `runId`, a non-empty
  `confirm` is refused like `params`: "confirm applies when starting a run with scriptId; drop it").
  Gate: `es.Run != "allow" || confirm != ""`; `approveScript(ctx, es, plan, reason, note)`.
- `api_tools.go`: validate `a.Confirm` first (after the enabled check). `policy := needsAPIApproval(..)
  || plan.MissingInputs() > 0`; gate `policy || confirm != ""`; `approveAPI(ctx, plan, sc, reason,
  note)` sets both on the request. `needsAPIApproval` unchanged.
- `held.go` `holdResult`: before `Request`, `req.AgentNote = ""` and, when
  `req.Reason == ApprovalReasonConfirm`, `req.Reason = ApprovalReasonPermission`. One choke point
  covers db, browse and kube held results. `api_review.go` builds its own request (no change).
- `approval_item.go` `itemOf`: `AgentNote: r.AgentNote` on the item (pre-run only; `holdResult` already
  clears it). `promptTitle` unchanged.
- `internal/approvals/queue.go` `Item`: add `AgentNote string \`json:"agentNote,omitempty"\`` (comment:
  the agent's own sentence asking for this item; "" for none). Update `Reason` comment list with
  `confirm`.

### Frontend

- `packages/shared/domain/approvals.ts`: `agentNote: z.string().default('')` in `approvalItemSchema`.
- `packages/workbench/src/approvals/ApprovalItemCard.vue` `risks` computed: before kind risks,
  - `item.agentNote` non-empty: `{ text: t('workbench.approvals.risk.agentConfirm.status', { note }),
    tone: 'warn', testid: 'approval-agent-confirm' }`;
  - `item.reason === 'confirm'`: `{ text: t('workbench.approvals.risk.agentRequested.status'), tone:
    'neutral', testid: 'approval-agent-requested' }`.
  Generic, so every kind and the phone get it; no per-kind code in `kinds.ts`. Existing Tailwind/risk
  list markup, no new component.
- `packages/theme/src/i18n/en.json` under `workbench.approvals.risk` (additive):
  - `agentConfirm.status`: `Agent asks you to confirm: {note}`
  - `agentRequested.status`: `Your settings allow this; the agent asked for this prompt`
  Wording passes `bun run lint` copy checks; adjust only as those checks demand.
