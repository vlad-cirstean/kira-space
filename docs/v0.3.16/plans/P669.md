## Design

### Scope decision: registry rows (needs user confirmation, default below)

`list.moveUp/Down` are shared. Deleting them from the registry (spec row acceptance) also deletes
Alt+Up/Down reorder in four lists outside the left panel (ColumnsMenu, EnvironmentsView,
AdeShelfSection, AdeTaskStatuses). None of those has a menu item or any other keyboard path, so that
removal loses a capability the user did not mention.

- Option A (default, implement first): remove every left-panel menu item and every left-panel
  Alt+Up/Down binding (four menus, three trees, Automations lists, Git repo list). Keep the two
  registry rows for the four non-left-panel lists. Spec acceptance "no Move up/down in ... the
  shortcut registry" is then only partly met: the rows stay, no left panel binds or prints them.
- Option B (spec-literal): Option A plus commit 6 below: delete the registry rows and vertical
  keyboard reorder in those four lists (drag stays there).

Option A is a strict subset of B, so implementation starts with A; commit 6 lands only if the
orchestrator confirms B with the user.
