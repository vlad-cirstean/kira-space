# P670 Remove connection Secrets section

Spec row: `../SPEC.md` P670. Batch 5, Stream B (`plans/batches.md`). Base: `chapter/v0.3.16` at
`09ee8957`. Frontend plus one dead Go bridge method; flow test adjusted, no new flow.

## CAPABILITY LOSS (small; orchestrator confirms with user before implementation)

Removing the block loses exactly one capability: **Clear**, which deletes a saved password or URI
value from Kira's secret store (`secret_values`) while the connection file keeps its
`${secret:<name>}` reference. Its only UI path is the Clear button in `ConnectionSecrets.vue`. After
Clear, Connect fails with "secret … is not set" until a new value is typed. Nothing else in the UI
deletes a connection secret. Delete connection removes only the file and leaves its sealed value
behind (`connfiles.Loader.Delete`, pre-existing, unchanged here).

Not lost (evidence below): entering or rotating a password or URI, revealing it, the set/unset
state, the storage-off condition (moves to General tab), per-kind coverage.

Options for the user:

- **A, recommended: remove fully.** Clear gone. To connect without a password, delete the `password:`
  line on the YAML tab (sealed value stays, unused). Matches "Remove it".
- **B: remove block, keep Clear on General tab.** A small Clear button beside the password and URI
  fields when a saved value exists, same confirm. Keeps `ConnectionConfigService.DeleteSecret`,
  `useDeleteConnectionSecret` and the clear-confirm i18n keys. Delta in "Option B delta" below.

Plan body implements A. B is a delta on top.

## What the block does (read via codegraph)

UI. `ConnectionFileDialog.vue:357-363` renders `<ConnectionSecrets>` after the tab content, outside
the `section` switch, whenever `detail.id` is set. So it shows under General, Advanced,
Pre-connect, MCP, Privacy and YAML alike: the "on every tab" the user saw. Heading reuses
`space.ade.settings.secrets.title` ("Secrets").

`connection/ConnectionSecrets.vue` lists `detail.secrets` (`ConnectionSecret[]`: kind, name, set,
referenced). Per row: name, kind badge (URI or Password), set/unset badge, `SecretInput` with gated
reveal, Save (`useSetConnectionSecret`), Clear (`useDeleteConnectionSecret` after a danger
confirm). Storage-off warning (`connection-secrets-storage-off`) when
`config.storage.available` is false; "references no secrets" hint when the list is empty.

State. `studio/state/connectionConfig.ts`: `useSetConnectionSecret` /
`useDeleteConnectionSecret` (TanStack mutations, `refreshAfterSecret` writes the view and
invalidates file queries). Reveal: `project/state/connectionReveal.ts` `revealConnectionSecret`.

Go. `bridge/connectionconfig.go`: `SetSecret(ConnectionSecretArgs)`,
`DeleteSecret(ConnectionSecretNameArgs)`, both `validSecret` then `connfiles.Loader.PutSecret` /
`DeleteSecret`, emit `kira:connectionConfig:changed`, return `View`.

Storage. `connfiles.Secrets` seals into `secret_values`, scope `connection` (password) or
`connection-uri`, owner `connections`. A file references a value by whole-value
`${secret:name}` in `password` or `uri` (`connfiles.SecretName`, `refsOf`). `Loader.detail` fills
`FileDetail.Secrets` with only the file's referenced pairs (`secretViews(only)`). Connect resolves
through `connections.resolve` / `openSecret`; an unset name errors `secretUnset` by name.

Overlap with the General tab (`connection/ConnectionGeneralTab.vue`):

| Block feature | Other path | Lost? |
|---|---|---|
| Set/rotate password | General `connection-password` SecretInput; typed value held in `secrets`, `typeSecret` adds `${secret:<stem>.password}` when the file has none; `ConnectionFileDialog.flushSecrets` calls `useSetConnectionSecret` after file save. Also `CredentialsUpdateDialog` (`UpdateCredentials`). | no |
| Set/rotate URI | General `connection-uri` SecretInput, same flow | no |
| Reveal | General eye: `revealSaved` with the same `revealConnectionSecret`, same confirm and errors (`connection-secret-reveal-error`) | no |
| Set/unset state | `SecretInput :set` placeholder: "Saved" (`common.secret.saved.placeholder`) or "Not set" (`docker.edit.unset.status`); fed by `savedSecret(kind)` from `detail.secrets` | no |
| Storage off | General inputs `:disabled="!storageAvailable"`, but no explanation | moves: hint added to General tab |
| Value for a secret of the inactive mode (URI secret in fields mode) | YAML tab, or switch mode | no (inactive value is unused) |
| Clear (delete sealed value) | none | **yes** |

Kinds without a password field in fields mode (SQLite file kinds, SQS/S3 AWS kinds) never read
`Password`: `adapters/sqlite`, `adapters/sqs`, `adapters/s3` have no `cfg.Password` use. So no kind
depends on the block to enter its credential.

Other dependents. `ConnectionSecret` type, `detail.secrets` and `revealConnectionSecret` stay
(General tab, `menu.ts:363` URI copy). `Loader.DeleteSecret` stays: `connections/service.go:330`
(create rollback) and `dbflow/sqlite_test.go:436` call it. `View.Secrets` (Go and
`ConnectionConfigView.secrets`) has no UI reader before or after this phase; it stays, out of
scope (flow test asserts it; not a path only the block used).
