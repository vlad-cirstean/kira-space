# P672 Part 1 UI inventory and uniformity rules

Spec row: `../SPEC.md` P672 Part 1. Batch 6 (`plans/batches.md`), sequential: Part 1, then Parts
2..9. Base: `chapter/v0.3.16` at `6527aec4`. Analysis only: no app code changes, no tests.

## Goal

User feedback: nothing in the UI is uniform, across modules and inside one module (dialogs,
menus, cards, how information sits in them: alignment, colours, fonts). Part 1 delivers:

1. an exhaustive inventory of element types and every variant in use, with counts and file
   references;
2. a small set of canonical patterns per family (token values, component, markup shape);
3. a mapping of every variant to its canonical pattern or a justified exception;
4. the cut of the apply work into Parts 2..9, each sized for one planner and one implementer.

All four live in `P672-inventory.md` (rules, rankings, migration items, appendix). This file is the
method and the Part cut.

## Method

- Scope: 716 `.vue` files under `apps/` and `packages/`, excluding `ui/` primitives, tests,
  testdata. Mapped to 14 modules (inventory §0).
- Template scans (quote-aware tag and attribute parse) count every primitive and composite use, its
  `variant`/`size` props and its `class` overrides; class-token histograms for type, colour,
  spacing, radius, border. Class strings built in `.ts` (cva, ADE `tones.ts`) read by hand.
- Each family: inventory (uses, variants, per-module split), divergences, canonical rules with
  rationale, migration items. Rules extend the existing contract, never contradict it, and add a
  new shared piece only where a pattern is hand-copied many times.
- Ranking: visibility × spread × count (inventory §18).
- Parts re-run the same scans against their own base before applying; the appendix line numbers
  are at `6527aec4`.

## Output format (`P672-inventory.md`)

- §0 method, §1 baseline (what primitives already fix), §2-§17 one family each: Inventory and
  Canonical rules. Rule ids `R<family>.<n>`: RD dialogs, RB buttons, RF forms, RM menus/popovers,
  RL lists, RH headings/detail/KV, RC cards, RS status, RE states, RT tooltips, RCo colours, RTy
  type, RSp spacing, RI icons, RBo borders, RTa tabs/choice.
- §18 ranked inconsistencies, §19 user decisions, §20 migration items M1-M36 tagged with their Part.
- Appendix A.1-A.13: every dialog (size, flags, footer, rule broken), popover, card, bare-`Label`
  file, heading, restyled checkbox, ADE tone line, `SecondaryTabs` host, hand error text,
  `EmptyState #media`, menu host, list/row/table host, form file.

## Canonical rules in brief

- Dialogs: size table, one emphasised footer button rightmost, header title only, intro is
  `DialogDescription`, sections as `FieldSet`/`SectionHeading`.
- Buttons: size by host (form commit `kira-lg`, bars and rows `kira`), outline only to commit or
  decide; everything else `toolbar`.
- Forms: one label (`FieldLabel`), two layouts (stacked, columns via new `Field
  orientation="responsive"`), checkbox rows via `Field horizontal`, fixed width and textarea steps,
  primitive checkbox indicator.
- Menus/popovers: data menus (`MenuItems`), muted 13 icons, two popover shapes (default form,
  new `flush` list), four widths.
- Headings: fixed roles (`PanelHeader`, `SectionHeading`, `FieldLegend`, `CardTitle`, new
  `DetailHeader`); `KeyValueList` only, two densities.
- Status: one status-to-tone map (running = info); ADE pastels per decision D1.
- States: `EmptyState` / `InlineState` / `Alert` / `FieldError` by scope, no toned media, three
  skeleton shapes, toasts only for off-screen outcomes.
- Type/spacing/icons/borders: size roles, `font-data` only for data, pane `p-3`, container spacing
  table, icon 13/12/16/24 by host, radii `kira-sm` controls vs `kira` containers.
- Tabs: role picks `choice` / `tabs` / `segmented`; `ConnectionEnginePicker` onto
  `RadioGroupCard`.

## Decisions for the user

- D1 ADE palette: (a) pastels stay board/card-only, theme tones elsewhere (recommended), or (b)
  retire the ADE palette app-wide.
- D2 New shared pieces (`DetailHeader`, `Field orientation="responsive"`, `PopoverContent flush`,
  `KeyValueList density`, `DetailSection` and `TextTooltip` in theme): accept or name any to drop.
- D3 Toasts: background outcomes only (recommended) or app-wide.
