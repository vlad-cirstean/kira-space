# P668 Single-select toggle groups

## Goal

Round RadioGroup becomes a ToggleGroup (type single, segmented, solid selected fill) on 9 groups in 8
files. A value always stays selected: a click on the selected item changes nothing. Runs params
`select` wraps and falls back to a Select past 5 choices. Existing data-testids kept. Stay radios:
`ConnectionEnginePicker`, `AdeTaskStatuses` colours, `EnvironmentsView` active env. Not touched
(Stream B, P667): `ResetDialog.vue`, `CherryPickDialog.vue`, `RevertDialog.vue`,
`AdeWorkflowReviewPanel.vue`.

### ToggleGroup and its one wrapper

- shadcn-vue ToggleGroup is in the theme already: `packages/theme/src/components/ui/toggle-group/`
  (`ToggleGroup.vue`, `ToggleGroupItem.vue`, `index.ts`), over reka-ui 2.11.0 `ToggleGroupRoot`
  (MIT, fully open source; the feature used is core reka, no paid tier). No dependency to add.
- Lint U4 (`scripts/check-ui-primitives.sh:157`) forbids `<ToggleGroup`/`<ToggleGroupItem` outside
  `packages/theme/src/components/SecondaryTabs.vue`. ARCHITECTURE line 772: "Use SecondaryTabs
  (variant tabs|segmented) for secondary tabs and segmented pickers, never raw ToggleGroup".
- `SecondaryTabs.vue` is the shared wrapper this phase needs. It renders `ToggleGroup type="single"`
  and its `onUpdate` drops an empty value, so a click on the active item never deselects (P262 §2.3).
  Props: `items: SecondaryTabItem[]` (`value`, `label`, `icon`, `count`, `disabled`, `testid`,
  `tooltip`), `variant: 'tabs' | 'segmented' | 'text'`, `size: 'kira' | 'kira-lg'`, `ariaLabel`,
  `countBadge`. Root attrs fall through to the group div (precedent: `RefsPopover.vue:445`
  `data-testid="branch-tabs"`). 33 files use `variant="segmented"`.
- `segmented` = ToggleGroup `variant="outline"`, spacing 0: one connected bordered strip.
  `toggleVariants` (`ui/toggle/index.ts`) idle `bg-transparent`, text inherited; hover `bg-field
  text-fg`; selected `data-[state=on]:bg-field` and `aria-pressed:bg-field`. Hover and selected
  render the same fill. No own focus style: global `:focus-visible` outline (`tailwind-core.css:216`)
  plus `focus-visible:z-10` on the item.
- ToggleGroup root: `flex w-fit flex-row`, no wrap. `spacing` prop is read once at setup
  (`resolvedSpacing`); non-zero spacing gives separate chips, each with full border and
  `rounded-kira-sm` (the `data-[spacing=0]` joins stop applying).

### reka semantics (from `node_modules/.bun/reka-ui@2.11.0.../dist/ToggleGroup`, `Toggle`, `RovingFocus`)

- Root: `role="group"` inside `RovingFocusGroup` (`loop` true, `orientation` undefined: both arrow
  axes move). Item: `<button aria-pressed data-state="on|off">`, `RovingFocusItem active=pressed`.
- Keyboard: Tab enters on the pressed item (one tab stop); Arrow Left/Right/Up/Down move focus only,
  looping; Home/End jump; Space/Enter press. Radio differs: arrows move and select. Screen readers
  announce "toggle button, pressed", not "radio, checked". This is the user's chosen trade.
- `data-state` changes from `checked|unchecked` (RadioGroupItem) to `on|off`; `toBeChecked()` does
  not apply to `aria-pressed` buttons. Specs must assert `data-state` `on` or `aria-pressed` `true`.

## Design

### Shared wrapper: SecondaryTabs gains `choice` and `wrap`

No new component: SecondaryTabs is the single ToggleGroup wrapper (U4) and already ignores the empty
update. Two additive props in `packages/theme/src/components/SecondaryTabs.vue`:

1. `variant: 'choice'`: form single-select. Same as `segmented` (ToggleGroup `variant="outline"`,
   connected strip) plus item classes
   `CHOICE_ITEM = 'max-w-full text-muted-foreground hover:text-fg data-[state=on]:bg-select aria-pressed:bg-select data-[state=on]:text-fg'`.
   Default label span gets `min-w-0 truncate` under `choice` only.
   - Why not plain `segmented`: its selected fill equals its hover fill (`bg-field`), so it is not a
     clearly selected solid fill. Restyling `segmented` would change 33 callers and their baselines
     (settings row density among them), which is P672's job, not this row.
   - Why `bg-select`: the selection token (selected rows, NativeSelect `option:checked`). ARCHITECTURE
     line 1416 allows fills on selection; U106 forbids filled buttons, which `bg-primary` would read as.
2. `wrap?: boolean` (default false): adds `flex-wrap` to the root class and passes `:spacing="1"`, so
   items become separate bordered chips 4px apart (density scale 1) and a wrapped row keeps every
   border. Without `wrap`, spacing stays as today (`undefined`, outline resolves to 0).

Item states (all tokens, Tailwind only, no scoped style):

| State | Look |
|-------|------|
| idle | transparent, `border-border` strip, `text-muted-foreground` |
| hover | `bg-field`, `text-fg` |
| selected | `bg-select`, `text-fg` (also while hovered: `data-*`/`aria-*` variants sort after `hover`) |
| focus-visible | global `--kira-focus` outline, `z-10` over neighbours |
| disabled | `opacity-50`, no pointer (toggleVariants) |
| wrapped | `wrap`: chips 4px apart, each fully bordered and rounded, next row left-aligned |
| Select fallback | ParamsForm only: `NativeSelect` bordered `kira-lg`, see below |

Sizes: every call site passes `size="kira-lg"` (dialog/form density, ARCHITECTURE line 773). No raw
`h-*` class (U38).

Click on the selected item: reka emits `undefined`, `onUpdate` drops it, controlled `model-value`
keeps the item `on`. Already true for every SecondaryTabs; the specs below assert it per group.

### Per call site

Every site: drop `RadioGroup`/`RadioGroupItem` imports, the per-item `<Label for>` wrappers and the
item `id`s; drop `Label` import where nothing else uses it. Items come from a `computed`
`SecondaryTabItem[]` (labels via `t()`, so locale changes rerender). Group testid goes on
`<SecondaryTabs data-testid="...">` (falls through to the group div). `ariaLabel` = the visible label
text (same key), since a `FieldLabel` cannot label a `role="group"` div. Typed refs get
`:model-value` plus `@update:model-value="(v) => (x = v as T)"`: `defineModel<string>` cannot bind
`v-model` to a narrower union under vue-tsc.

1. ParamsForm (`p.type === 'select'`):
   - `const MAX_TOGGLE_CHOICES = 5;` comment: past this a toggle row gets too long; Select instead.
   - `choices(p).length <= MAX_TOGGLE_CHOICES`: `<SecondaryTabs variant="choice" size="kira-lg" wrap
     :aria-label="p.name" :data-testid="run-param-input-<name>">`. Items map `''` to a sentinel
     `NONE = '\u0000'` (SecondaryTabs drops an empty value, so None needs a non-empty one); testid
     stays `run-param-option-<name>-<o>` with the raw option (None: `run-param-option-<name>-`).
     Update maps `NONE` back to `[]`.
   - Otherwise: `<NativeSelect :id="<idBase>-<name>" variant="bordered" size="kira-lg"
     :data-testid="run-param-input-<name>">` (U10: NativeSelect is the select primitive; the theme
     has no reka Select). Options: first `<option value="">` labelled `common.state.none.option`,
     `disabled` when `p.required` (an unset required param reads None and cannot be picked back),
     then one per option. Update: `''` to `[]`, else `[String(v)]`. The existing `FieldLabel :for`
     now labels it.
2. RunMcpTab run: `data-testid="script-mcp-run"`, items `prompt`/`allow` with their testids, update
   `patch({ run: v === 'allow' ? 'allow' : 'prompt' })`.
3. RunMcpTab mode: `data-testid="script-mcp-mode"`, items `short`/`long`, update
   `patch({ mode: v === 'long' ? 'long' : 'short' })`.
4. ClusterMcpDialog: `data-testid="kube-mcp-approval"`, items `prompt`/`allow`, update as today.
5. RunFolderTab: `data-testid="script-dialog-dirmode"`, items `kira`/`fixed`, update `setMode(v)`.
6. AdeAddPopover kind: `data-testid="ade-nw-kind"`, items `task`/`orchestrator`, `aria-label`
   `common.field.kind.label`; the hint below stays.
7. AdeStageDialog: new group testid `ade-stage-close-choice`, items `close`/`keep` with
   `ade-stage-close`/`ade-stage-keep`, `aria-label` the sessions label text.
8. WorktreeDialog: inside the existing `FieldSet`/`FieldLegend`, new testids `worktree-mode` (group)
   and `worktree-mode-existingBranch|newBranch|detach`. `modeId` goes if unused.
9. StashDialog save: inside the existing `FieldSet`/`FieldLegend`, `wrap` on, new testids
   `stash-save-source`, `stash-save-source-workingTree`, `stash-save-source-entry`. Items: working tree
   always, entry only when `saveSourceEntry`; the entry item carries `tooltip` = its full label (a long
   stash message truncates). The untracked `Alert` moves after the group. `saveSourceId` goes if
   unused.

Spec row sizes: AdeAddPopover sits in a `grid-cols-[auto_minmax(0,1fr)]` cell; the strip is
`w-fit`, so it stays left-aligned and content-sized.

## Open points for the user

None blocking. Decisions taken, open to override:

- Selected fill is `bg-select` (selection token) on a new `choice` variant, not the existing
  `segmented` look, whose selected fill matches its hover. Alternative: accent fill (`bg-accent`),
  rejected as a filled-button look (U106 spirit). Folding `choice` and `segmented` into one look is
  left to P672.
- Keyboard follows reka ToggleGroup: arrows move focus, Space/Enter select; screen readers announce
  pressed toggle buttons, not radios.
- Select fallback threshold: more than 5 choices, None counted.
