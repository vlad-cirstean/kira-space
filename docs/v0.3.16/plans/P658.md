## Design

Display-only column filter. Never touches projection, query or `tab.state`; no bridge call.

UX:

- `FilterToolbar.vue` row gets a `SearchField` after Clear, separated by `ToolbarSeparator`, so
  Clear stays grouped with the query pair (`WHERE`, `ORDER BY`) it clears. Width `w-48 shrink-0`.
  Placeholder "Filter columns". `data-testid="column-filter-input"`.
- Match rule: case-insensitive substring on column name. Query splits on whitespace and commas into
  terms; a column matches when any term is a substring (OR). `email phone` shows both.
- Primary-key columns stay visible while a filter is active (row identity context; same rule as
  `ColumnsMenu` "Primary key, always shown"), unless nothing matches.
- No match (zero columns match, PK included): grid keeps every column, field gets
  `aria-invalid="true"`, status text "No match" beside it. Never renders a zero-column grid.
- Active filter with matches: status text "`{shown} of {total}`" beside the field
  (`data-testid="column-filter-status"`), `text-kira-sm text-subtle`. Hidden when field is empty.
- Esc in field: clears (SearchField built-in); second Esc bubbles. × clears and refocuses.
- Keyboard entry: palette command `data.filterColumns` "Filter columns" focuses the field. View-
  scoped like `data.generate` (registered by `DataView.vue` while mounted). No global chord: chords
  go through `shared/domain/shortcuts.ts`'s closed map and the seven-file accelerator path
  (`studioCommands.ts` comment); out of scope.
- Clear (query) does not clear the column filter: different concern, own × and Esc.
- Columns popover (`ColumnsMenu.vue`) unchanged: list filtering would fight the sortable's index-
  based `moveId` reorder over hidden rows. Grid filter already finds the column.
- Row search jump to a match in a filtered-out column clears the column filter first, then jumps.

State (P660 seam):

- `DataViewRuntime.columnFilter: string` (default `''`) in `grid/state.ts`, next to `whereDraft`.
  Setter `setColumnFilter(tabId, text)` via `ensureRuntime`. Typed text is the single source of
  truth: the field binds to it directly (no local copy), so it survives tab switches today and P660
  persists or restores it by covering this one runtime field. Session-only, never in `tab.state`
  (a narrowed grid silently surviving restart reads as lost columns). Dropped with the runtime on
  tab close.

Grid application:

- New `grid/columnFilter.ts` (pure, no Vue):
  - `columnQueryTerms(query: string): string[]`: lowercase, split `/[\s,]+/`, drop empties.
  - `matchesColumnQuery(name: string, terms: readonly string[]): boolean`.
  - `visibleColumnOrder(page: TabularPage, stored: string[] | null, query: string): string[]`:
    `order = resolveColumnOrder(page, stored)`; no terms: return `order` (same reference). Else
    `matched = order.filter(matches)`; empty: return `order`. Else
    `order.filter(n => isPk(n) || matches(n))`. Memoize: `WeakMap<string[] (order), Map<string
    (normalized terms joined by '\u0000'), string[]>>`. `order` is reference-stable per
    (page, stored) via `resolveColumnOrder`'s cache, and display order is read per cell, so the
    cached array must be returned on repeat calls (same O(1) rationale as `columns.ts:324`).
  - `columnFilterSummary(page, query): { shown: number; total: number; noMatch: boolean } | null`
    (null when no terms); `shown = visibleColumnOrder(...).length`, `total = page.columns.length`.
- `SlickGridHost.vue`:
  - Component-local `let appliedColumnFilter = rt()?.columnFilter ?? ''` (read at setup; host
    remounts per tab). New `displayOrder(p)` helper:
    `visibleColumnOrder(p, tab()?.state.columnOrder ?? null, appliedColumnFilter)`.
  - Replace `resolveColumnOrder` with `displayOrder` in `currentOrder()`, `rebuildAndSetColumns()`,
    `onMounted`, the `pageVersion` watch. Keep `currentSortTerms()` on full `resolveColumnOrder`
    (sort terms can name a filtered-out column). Remove the then-unused import only if no caller
    is left.
  - Applied filter is component-local, not read from the store per call, so `currentOrder()` and
    the built SlickGrid columns never disagree during the debounce window.
  - Extract the rebuild core of the `pageVersion` watch (orderKey check, `rowNumberBase`,
    `dataSource.setState`, `setColumns`, `updateRowCount`, `invalidateAllRows`, `lastCssLayerBand`
    reset, `render`, `syncSortIndicators`, `refreshSearchLayer`) into
    `applyPageAndOrder(): boolean` (returns whether it rebuilt). `pageVersion` watch calls it,
    then keeps its own focus-request and mask-tag tail only when it rebuilt.
  - New `watchDebounced` (VueUse, `debounce: 120`) on `() => rt()?.columnFilter ?? ''`: if equal
    to `appliedColumnFilter` return; `flushOpenEdit(props.tabId)` (stage an open inline edit;
    `setColumns` would destroy it); `selectionModel?.setSelectedRanges([])` (display-column
    ranges would point at other columns; this also clears `rt().selection`); set
    `appliedColumnFilter`; `applyPageAndOrder()`.
  - New exposed `revealPageCell(row: number, pageCol: number): boolean`: name =
    `getPage(tabId)?.columns[pageCol]?.name`; `idx = currentOrder().indexOf(name)`; `-1` returns
    false; else `grid.scrollCellIntoView(displayPositionOf(...), idx + 1)`, returns true. Fixes the
    page-vs-display index mix `scrollCellIntoView` had under a stored column order too.
    `scrollCellIntoView` stays (still exposed); `DataView` stops calling it.
- `DataView.vue` `onGoToMatch`: `if (!dataGridRef.value?.revealPageCell(m.row, m.col)) {
  gridViewStore.setColumnFilter(tab.id, ''); }` then on clear wait for the host's applied filter:
  expose from host `applyColumnFilterNow(): void` (cancels debounce: runs the same apply body
  immediately) and call it, then `revealPageCell` again. No `setTimeout`.
- `FilterToolbar.vue`: `SearchField` `v-model` through a computed get/set over
  `rt.columnFilter`/`setColumnFilter`. Summary computed reads `pageVersion.n` then
  `getPage(tab.id)` and calls `columnFilterSummary` on the typed text (immediate feedback; grid
  follows after debounce). `:aria-invalid="summary?.noMatch ? 'true' : undefined"`.
  `defineExpose({ focusColumnFilter })` calling the SearchField ref's `focus()`. Update the
  "LAW 02" template comment: two query inputs, one verb, then the display-only column filter.
- Tailwind utilities only; no scoped `<style>`.

Library check: shadcn-vue `InputGroup` (via existing `SearchField`), VueUse `watchDebounced`, Pinia
`gridView` store (grid view per-tab state; one concern, unchanged). TanStack Query not applicable: no
server state. Nothing hand-rolled.

## P660 compatibility

P660 must keep `runtime[tabId].columnFilter` when it restores module state; nothing else holds the
filter. `SlickGridHost` seeds `appliedColumnFilter` from it at mount, so a P660 keep-alive or
restore needs no extra hook. If P660 keeps the host mounted (keep-alive) instead of remounting, the
debounced watch already applies store changes; no mount-time dependency remains.
