### How the editor is built

Native control plus mirror overlay, no contenteditable, no CodeMirror, no Monaco instance:

- `.input-wrap` holds `.highlight-overlay` (absolute, `inset-0`, `v-html` from `paintOverlayHtml`:
  Monaco `colorize()` base runs merged with `{{var}}` ranges into `<span class="mtk1 kira-ed-var…">`)
  and the real `<input>`/`<textarea>` above it with `relative z-1 text-transparent caret-fg`.
  Visible glyphs come from the overlay div; caret and selection come from the invisible control.
- `grow`: `.p-input.is-grow` (`packages/theme/src/primitives.css:24-70`) sizes a grid track with an
  `::after` replica of `attr(data-value)`, clamps at 4 lines, textarea stretched, padding 0,
  `pre-wrap`/`overflow-wrap: anywhere`; overlay `whitespace-pre-wrap wrap-anywhere leading-[inherit]`.
- Scroll mirrored on the control's `scroll` event (`onInputScroll`).
- Key handlers: `AutocompleteField.onKeydown` (wrap/auto-close on bracket/quote/Backspace only;
  popup nav Up/Down/Enter/Escape only, `activeDescendant.ts` `KEYS`); `FieldRowsTable.
  onContainerKeydown` (Left/Right only at field edges to change column; Up/Down always change row).
  No IME/composition handling anywhere: native.

### Measurements (this container, discarded probe specs, real built app)

Run against `bun run build:test`, project `ui` (Playwright WebKit WPE) plus a Chromium replica:

- `selectionStart` after each ArrowRight/ArrowLeft moves by exactly 1 on `http-url`,
  `http-header-name`, `http-header-value`, `http-param-value`, for typed and filled values with
  double spaces, `{{x}}`, `\n`, 9-line scrolled values.
- Overlay `textContent` equals control value; computed font, line-height, width, padding,
  `white-space`, `overflow-wrap`, `tab-size` identical.
- Pixel diff of control glyphs vs overlay glyphs (each drawn red alone, compared by mask): 0 at font
  sizes 11, 12, 13, 13.5, 14, 15, 17 px; 0 for serif, sans-serif, DejaVu Sans, JetBrains Mono
  (ligature pairs `-> => != == www :: && || <= >=`); 0 for CRLF, lone CR, LF, tab, NBSP, ZWSP, CJK +
  emoji, combining marks.
- Caret x with JetBrains Mono steps a uniform 7.2 px per ArrowRight, through ligatures.
- Scroll mirror: overlay `scrollTop` equals textarea `scrollTop` at every step of a 9-line value.
- One real defect reproduced: param value with a lone CR (`?k=one%20{{x}}%0Dtwo…`): control shows 2
  lines, box stays 1 line (22 px; LF case 40 px), second line scrolled out of view.

The reported drift does not reproduce on WPE or Chromium. Product ships WKWebView (macOS-first
`FONT_CHOICES`, `packages/workbench/src/settings/fonts.ts`) and WebKitGTK.

### Ranked hypotheses

1. H1, root cause class: two independent text layouts. The caret is laid out by the transparent
   native control, glyphs by the overlay div of `<span>` runs. Any per-glyph advance, space width,
   wrap width, line-height, scroll or content difference between the two puts the caret between
   visible glyphs ("stops on spaces not in the string") or past several ("moves more than one"),
   growing with distance, worst on long or multi-line values. Evidence: the symptom is exactly
   cumulative drift; the model offsets are correct (measured); this pair already needed three
   alignment fixes (v1.3 overlay not painting on textarea plus `line-height: inherit`, P71 grid
   replica, P90 UA `padding: 2px`), and `http-request.spec.ts` "a grow field wraps its textarea and
   overlay onto the same lines" guards one of them. The remaining divergence is engine and font
   specific (CoreText shaping of one text node vs span-split runs, user data font), so it cannot be
   measured here. Fix: stop depending on the two layouts agreeing.
2. H2: ligature fonts. `FONT_CHOICES` offers Fira Code, JetBrains Mono, Cascadia Code. Overlay
   spans split runs at `{{`/`}}` and class boundaries, the control shapes one run, so ligature
   formation and caret slots inside a ligature can differ per engine. WPE showed no diff. Monaco
   (request body) runs with `fontLigatures` default off; the fields do not. Fix: ligatures off.
3. H3, measured: CR in model text. Textarea/input value sanitization and the `v-html` parser
   normalize CR/CRLF to LF, but the grow replica reads raw `attr(data-value)` where CR is a space:
   box too short, lines hidden, and `hoverAt(text, offset)` offsets drift by one per CRLF.
   Sources: imported curl/Postman/HAR values, URL-decoded `%0D` in Params.
4. H4, code evidence: `FieldRowsTable.onContainerKeydown` sends ArrowUp/ArrowDown to the next row
   even inside a multi-line or soft-wrapped value, so line movement inside a cell is impossible.
   Its comment ("no cell value can contain a newline") is false: paste inserts `\n`, imports and
   URL-decoded `%0A` carry it, soft wrap makes visual lines.

Ruled out, with evidence: custom Left/Right caret code (only field-edge column jumps; deltas
measured 1); NBSP from `colorize()` (`decodeEntities` maps back, overlay built from model text,
`textContent === value` measured); auto-close/wrap (bracket/quote/Backspace keys only); popup nav
(Up/Down/Enter/Escape only); async repaint lag (arrows do not change text); Params URL round trip
(`encodeQueryComponent`/`decodeComponent` lossless for tested values; caret unaffected); scroll
mirror (equal at every step); IME (no handler, native).

### Fix design

Principle: the native `<input>`/`<textarea>` (the well-maintained primitive) paints the glyphs and
the caret in one layout; the overlay only paints tints behind it. Worst case a tint is off by a
fraction of a glyph, never the caret. No hand-rolled caret code. Rejected: CodeMirror/contenteditable
per cell (dependency removed in P60a, breaks every `toHaveValue`/`fill` spec on these testids);
Monaco per cell (one editor instance per table cell, dozens per request).

F1 `packages/workbench/src/components/AutocompleteField.vue`, ranges-only underlay mode:

- Add `const underlay = computed(() => !highlighted.value && !!props.rangeHighlights);` with a
  one-line why comment (native control paints glyphs and caret; overlay tints behind).
- `fieldOverlayClass`: `!showOverlay` → `'text-fg'`; `underlay` → `'relative z-1 text-fg'`; else
  today's `'relative z-1 text-transparent caret-fg'`.
- Overlay `<div>`: add `:class="underlay ? 'is-underlay text-transparent' : ''"` beside
  `overlayClass` (overlay stays `aria-hidden`, `pointer-events-none`, below the control; control has
  `bg-transparent` so tints show through).
- `repaintOverlay`: in `underlay` mode set `overlayHtml.value = paintRangesHtml(displayText.value,
  props.rangeHighlights(displayText.value))` synchronously and return; no Monaco wait. Keep the
  existing path for `highlighted`.
- Monaco load only when needed: replace `onMounted(loadMonaco…)` with
  `watch(highlighted, (h) => { if (h && !monacoMod.value) void loadMonaco().then((mod) => { monacoMod.value = mod; }); }, { immediate: true })`.
- F3 in same file: `const displayText = computed(() => text.value.replace(/\r\n?/g, '\n'));` used by
  `:data-value`, both paint paths, and `onInputMouseMove`'s `props.hoverAt(displayText.value, offset)`.
  The model keeps its raw text (no silent rewrite, no dirty tab).
- F2 in same file: add `[font-variant-ligatures:none]` to the `<textarea>`, `<input>` and overlay
  class strings (Tailwind arbitrary property; no ligature utility exists).

F1b `packages/workbench/src/editor/paintSpans.ts`:

- Extract the run-to-HTML loop (lines 173-181) into `function runsToHtml(text, merged): string`.
- Add `export function paintRangesHtml(text: string, ranges: readonly HighlightRange[]): string`:
  `''` for empty text, else `runsToHtml(text, mergeHighlightRanges(text.length, [{ from: 0, to:
  text.length, classes: [] }], ranges))`.
- `paintOverlayHtml` calls `runsToHtml`; its plaintext fallback branch calls `paintRangesHtml`.
  Behaviour unchanged. No new unit test (thin wrapper; `mergeHighlightRanges` already covered by
  `tests/unit/studio/paint-spans-merge.spec.ts`).

F1c `packages/workbench/src/editor/edDecorations.css` (the established home of the `v-html` classes;
Tailwind cannot reach classes inside `v-html`, and a layered utility loses to these unlayered rules):
append underlay rules at (0,3,0), so they beat the (0,2,0) colour rules:

```css
/* Underlay (AutocompleteField ranges-only): the native field paints the glyphs, so a reference is a
   tint behind them, never coloured text. */
.highlight-overlay.is-underlay .kira-ed-var,
.highlight-overlay.is-underlay .kira-ed-var-secret {
  color: transparent;
  background-color: color-mix(in srgb, var(--kira-var-resolved) 22%, transparent);
  border-radius: 2px;
}
.highlight-overlay.is-underlay .kira-ed-var-unknown {
  color: transparent;
  background-color: color-mix(in srgb, var(--kira-warn) 18%, transparent);
  border-radius: 2px;
}
```

Secret dotted and unknown wavy underlines stay from the existing rules (decoration colour is
explicit, so it draws under transparent text). Visible result: `{{var}}` glyphs render in `fg` on a
tint instead of in colour. State in Result.

F4 `apps/kira-space/frontend/src/studio/views/shared/fields/FieldRowsTable.vue`
`onContainerKeydown`:

- Before the ArrowUp/ArrowDown row move: `if (!isSingleLine(el)) return;` so a multi-line or wrapped
  cell keeps native line movement.
- `function isSingleLine(el: HTMLInputElement | HTMLTextAreaElement): boolean`: `true` for
  `HTMLInputElement`; `false` when `el.value` contains `\n`; else
  `el.scrollHeight < 1.5 * Number.parseFloat(getComputedStyle(el).lineHeight)` (one line box).
- Replace the false "no cell value can contain a newline" comment (lines 178-180) with the real
  contract: row stepping applies to one-line cells only.
- Left/Right edge column jumps unchanged.

Not changed: `primitives.css` grow math, `TabStrip.vue`, `TabStripNewButton.vue`.
