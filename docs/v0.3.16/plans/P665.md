# P665 Cmd+F search in left panels

Spec row: `../SPEC.md` P665. Batch 3, Stream C (`plans/batches.md`). Base: `chapter/v0.3.16` at

## Goal

Focus anywhere in the left panel (header button, tree row, list row, the search field itself) plus
Cmd+F (mac) / Ctrl+F (other) reveals that panel's search bar, focuses it and selects its text, so
typing starts at once. Covers every left panel with a search bar. Shortcut registry entry, palette
entry, UI spec per panel.

## Design

### "Focus in left panel"

`document.activeElement` (or a keydown `target`) is inside the left panel slot. Mark the slot: add
`data-slot="side-panel"` to the panel div in `packages/workbench/src/components/WorkbenchShell.vue`
(beside `data-testid="project-panel"`; logic never keys on test ids). A panel root takes part only
while `root.closest('[data-slot="side-panel"]')` holds, so git-ui `FileTree`/`ReviewView` reused in
the main area, the review window or graph detail panes keep today's Cmd+F (main view find).

Nested panels (GitPanel > RepoSearchView, GitPanel > RepoReviewView > ReviewView > FileTree):
innermost searchable panel containing focus wins. A non-searchable panel (Git Review tab outer
GitPanel, Docker with engine down, FileTree with `showToolbar: false`) defers to its nearest
searchable ancestor; none searchable means fall through to `view.find`.

### Shortcut registry

`packages/shared/domain/shortcuts.ts`: add scope `'panel'` to `ShortcutScope` and
`'panel.find': { scope: 'panel', chord: { key: 'F', cmdOrCtrl: true } }` after `'view.find'`.
Comment: left-panel search; same chord as `view.find`, routed by focus. Conflict spec passes (panel vs
view, neither global). No Go change: `accel.go` mirrors menu accelerators only, and the menu keeps one
Find item (`view.find`), routed below.

### panelSearch.ts (one implementation, both paths)

In `packages/workbench/src/behaviour/panelSearch.ts`:

1. `focusField(container, testid, select)`: after `nextTick`, query `[data-testid=<testid>]`
   (an `input`, or the `input` inside it), `focus()`, and `select()` when `select`. Replaces the two
   inline `querySelector(...).focus()` calls in `onPanelKeydown` (type-ahead keeps `select: false`:
   the typed key is already appended).
2. `openSearch()`: `revealSearch()`, call new optional `opts.onReveal?.()`, then
   `focusField(root, testid, true)`. Idempotent: a second call refocuses and reselects, nothing else.
3. Local chord: `useShortcut(rootEl, ['panel.find'], (_, e) => { e.stopPropagation(); openSearch(); },
   { when: () => opts.searchable() && inSidePanel() })`. Bubble phase, not capture: the innermost
   root sees the key first and `stopPropagation` keeps an outer panel root from reacting. Not
   `ignoreTextFields`: Cmd+F inside the panel's own field reselects it. A non-searchable inner
   panel does not match (`when` false), so the event bubbles to its ancestor.
4. Registry for the menu and palette paths: module-level `Set<PanelFindEntry>` with
   `{ root: () => HTMLElement | null, searchable, open: openSearch }`, added on setup, removed with
   `tryOnScopeDispose`. Plain module state like `commands.ts`, not Pinia: a handler registry, not
   shared UI state, and git-ui mounts have no Pinia.
5. Exports:
   - `openFocusedPanelSearch(): boolean`: from `document.activeElement`, pick the entry whose root is
     in the side-panel slot, contains the active element, is searchable, and is deepest (root
     contains no other candidate root). Calls `open()`, returns true; false when none.
   - `openActivePanelSearch(): boolean`: the outermost searchable entry in the side-panel slot (the
     module panel itself); for the palette, where focus sits in the palette input.
6. Options type gains `onReveal?: () => void`. `ReviewView.vue` passes
   `onReveal: () => { filterVisible.value = true; }` (its toolbar watch already focuses; the extra
   `focusField` is harmless and adds the select).

### Menu path

`apps/kira-space/frontend/src/App.vue:168`: `control.onViewFind(() => { if
(!openFocusedPanelSearch()) runCommand('view.find'); })`. When WKWebView delivers the keydown before
the menu accelerator, the local chord opens the search and the later menu event finds focus inside
the panel field: `openSearch()` again, same result. When the menu eats the key, the menu path alone
does it. Either order converges on one idempotent `openSearch()`.

### Palette

- New entry in `apps/kira-space/frontend/src/shortcuts/appCommands.ts` `workbenchOnly()` (the files

  movesFocus: true, run: () => void openActivePanelSearch() }`. Hidden panel: no registered root,
  `openActivePanelSearch` returns false, no-op. Entry stays listed, same no-op rule as `runCommand`.
- Focus restore fix, scoped to commands that move focus: `PaletteCommand` (palette.ts) gains optional
  `movesFocus?: true`. `CommandDialog.vue` forwards reka `DialogContent`'s `closeAutoFocus` event

  `CommandPalette.vue`: for a `movesFocus` command, store it as pending and close; on
  `closeAutoFocus`, `event.preventDefault()` (skip restore) and run it. Other commands keep today's
  run-then-close order. No timer (U46 stays clean).
