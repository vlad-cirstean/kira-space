### C1. Resize tokens (`packages/theme/src/tokens.css`)

```css
  /* P663: pane/column resize bar, neutral grey, never blue. Idle line = the one border line;
```

### C3. Handle look (`packages/theme/src/components/ui/resizable/index.ts`)

Base string becomes:

```ts
'relative shrink-0 bg-transparent before:absolute hover:bg-resize-hover focus-visible:bg-focus focus-visible:outline-none data-[state=drag]:bg-resize-active',
```

Both compound `line` classes: replace `var(--kira-border)` with `var(--kira-resize)` (same pixel).
Comment lines 7-10: replace "`bg-focus` on hover, keyboard focus and drag" with "grey
`bg-resize-hover` on hover, `bg-resize-active` while dragging, `bg-focus` on keyboard focus (the bar
is the focus ring)".

Decisions:

- Idle framed handle stays transparent. It sits in the gap between floating panels; painting it
  would add a new always-on line app-wide. Only the line variant has a visible idle bar, and it now
  reads `--kira-resize`. So every visible state is a grey resize token.
- `focus-visible:bg-focus` stays. P122 (check-theme-classes.sh:683) makes `--kira-focus` the one
  focus ring, and here the bar is the ring. Pointer use never shows it: `useDraggable`
  `preventDefault: true` stops pointerdown from focusing the handle.
- Drag must beat hover while the pointer is over the bar. Tailwind v4 emits `data-*` variants after
  `hover`, same specificity, so `data-[state=drag]` wins. UI spec T1 asserts this. If it fails,
  change hover to `hover:not-data-[state=drag]:bg-resize-hover`. Never use `!important`.

### C7. Move update widget (`apps/kira-space/frontend/src/workbench/StatusBar.vue`)

Cut the `<UpdateAvailableItem .../>` block (lines 113-120) from `#right`. Paste it as the first child
of `#left-extra`, before the blame `StatusBarItem`, with comment
`<!-- P663: app-wide, first so module items never shift it. -->`. No prop or handler change.

Order reasoning. New left group: update, blame, agent usage.

- Update is app-wide and stays put across modules. Blame (git file only) and agent usage (ADE only)
  come and go with module and cursor. Blame text width changes per cursor line (`max-w-80 truncate`).
  An item after them would jump left and right; first in the group it holds the bar's left edge.
- Left edge is where a persistent, actionable notice is seen first. Tone `info` already marks it.
- Right group keeps its live readouts (agents, ops, runs, metrics). Removing update from between runs
  and metrics changes nothing for metrics: it was already last and stays last.
