# P661 Agents module memory efficiency

Spec row: `../SPEC.md` P661. Batch 2, Stream B (`plans/batches.md`). Base: `chapter/v0.3.16` at
`2ffa59ed`. Builds on P650/P657 metrics (App/Agents/Scripts split) and P480 RAM probe harness.

## Goal

App sits near 1.1 GB with only the agents (ADE) module open and few tasks and sessions. Measure where
that memory lives, name the biggest retainers, fix them, report before/after in Result. Measurement
drives the fix list: fixes F1-F6 below are ranked hypotheses, each gated on what step M shows.

## Current state (read via codegraph)

Process tree (what "App" and "Agents" in the status-bar tooltip sum):

- `internal/metrics/sampler.go` `Sampler.Sample`: RSS per process via gopsutil, grouped App / Agents
  / Scripts (`ProcessSets`, `groupProcesses`). RSS sums double-count shared pages (WebKit helpers
  share libs with each other; every `kira-space` child shares the binary's text). The 1.1 GB figure is
  this sum, so part of it is not real cost.
- Agents group: each agent root (`agentproc.Track`) plus its whole tree. A Claude TUI or headless
  session spawns the MCP stdio servers in the user's Claude config. Kira installs one of them itself:
  `apps/kira-space/internal/bridge/memory.go:384/405` `InstallStdio(memoryServerName, exe,
  []string{"memory-mcp"})`, routed by `apps/kira-space/internal/appwire/wire.go:65`.
- `internal/memory/memorycli/run.go` `Run`: every `memory-mcp` process is a full Go runtime with its
  own `embed.NewClient(embed.ClientOptions{Spec: embed.Default, Home: memory.Home()})`.
- `internal/memory/embed/client.go`: on first semantic search the client spawns `kira-space
  memory-embed --model-dir …` (`workerproc.Start`), an ONNX worker holding the model; it stays up
  `DefaultIdleTimeout = 5 * time.Minute` after its last request (`armIdle`/`onIdle`). N sessions mean
  N `memory-mcp` processes and up to N embed workers, each with its own model copy.
- No `debug.SetMemoryLimit`, no `GOGC` tuning, no pprof endpoint anywhere in Go code.

Renderer (App group, WKWebView on Mac, Playwright WebKit/Chromium on Linux):

- `packages/workbench/src/terminal/terminalRenderer.ts:169` `new Terminal({… scrollback: 5000,
  cursorBlink: true, scrollOnEraseInDisplay: true …})`. Module-level `byTabId` map keeps every
  Terminal alive across unmounts; `term.open(host)` on a detached div builds the full DOM renderer
  even for a terminal never shown. Disposed only by `registerTabRuntimeCleanup`.
- `packages/workbench/src/state/createTerminalsStore.ts` `openTerminalSession`: calls
  `attachHeadlessTerminal(tabId)` when no sink exists, so every running agent session gets an xterm
  whether or not its pane was ever opened. Pre-attach drain capped at `DRAIN_LIMIT_BYTES = 256 KiB`.
- `apps/kira-space/frontend/src/ade/v2/state/adeTerminals.ts`: reaps a stopped session's terminal
  (`closeTerminalSession` plus `cleanupTabRuntime`). Running sessions keep theirs indefinitely.
- xterm buffer cost: about 12 B per cell, `cols × (scrollback + rows)`. At 200 cols that is
  roughly 12 MB per full buffer. Claude Code redraws with ED2, and `scrollOnEraseInDisplay` pushes
  each redraw into scrollback, so a working agent fills 5,000 lines fast.
- `internal/terminal/service.go`: output coalesced at `coalesceInterval = 16ms` /
  `coalesceMaxBytes = 64 KiB`, base64 per event, `EmitTo` per window. A working agent emits up to
  60 events/s; each one allocates a base64 string plus a decoded `Uint8Array` in JS.
- `packages/workbench/src/state/queryClient.ts`: `staleTime: Infinity`, `KEEP_WHILE_OPEN = Infinity`
  gcTime for app-lifetime keys; input-keyed keys keep the 5 min default.
- `apps/kira-space/frontend/src/ade/v2/readQueries.ts` `useBoard`: one shallow query whose payload
  carries `history` (every archived task, `adewire.Board.History`). `useBoardHistory` is documented
  as its sole reader "so history can move to a query of its own". `readSignals.ts`
  `installAdeReadSignals`: every board push refetches the whole board, history included, through
  `createRefetchGate`. Server side the history slice is memoized (`internal/ade/history_memo.go`,
  30 s TTL) and the board snapshot is single-flight (`boardcache.go`). The cost is the wire and JS
  side: each push re-serializes, re-sends and re-parses the full history into a fresh array. Old
  arrays are garbage, but the heap high-water mark scales with archived tasks times push rate.
- `apps/kira-space/internal/ade/runs.go:1972` `Sessions` lists every task session via
  `AdeSessionsRepo.ListTask` (`internal/storage/repos/adesessions.go:69`, no `LIMIT`). Stopped rows
  each `os.Stat` their cwd. Every sessions push (each session start/stop/state change) re-reads all
  of it. The rows grow forever with use.
- `packages/workbench/src/editor/monaco.ts` `loadMonaco`: memoized, never released, one editor worker.
  `packages/workbench/src/approvals/ApprovalsSurface.vue:57` calls `loadMonaco()` as soon as any
  approval is pending, and `ApprovalsSurface` is always mounted (`App.vue`). An agent asking for a
  file-edit approval loads Monaco plus its worker for the rest of the app's life.
- `apps/kira-space/frontend/src/ade/v2/shell/AdeShell.vue` `onMounted` `prefetchNotesEditor()`
  (tiptap): fixed cost with a stated requirement (stage dialog must find it loaded). Kept.
- `apps/kira-space/frontend/src/workbench/WorkbenchShell.vue`: full modules sit over `MainView`
  with `v-show`; ADE itself mounts via `AdeView.vue` (`ModuleStart` or `AdeShell`).
- `internal/sqlitex/sqlitex.go`: single connection, default page cache (about 2 MB). Not a suspect.
- Harness: `apps/kira-space/tests/perf/heap-ram.spec.ts` worlds `idle`, `ade` (20/200 tasks),
  `terminal`, `memory`; `support/ramWorlds.ts`; projects `heap` (Chromium, heap snapshots) and
  `heap-webkit` (RSS only) in `apps/kira-space/playwright.perf.config.ts`.

## Ranked hypotheses

Ranking is from code and arithmetic; M decides the order.

- **H1 Kira-owned children per agent session (Agents group).** Each session runs its own
  `memory-mcp` Go process (about 15-30 MB each) and, after one semantic search, its own ONNX
  `memory-embed` worker holding the model (model plus runtime typically 100-300 MB each). 4 sessions
  can reach 0.5-1 GB here alone, and the worker lingers 5 min after the last search. Biggest candidate
  by arithmetic. Evidence: `memorycli.Run` creates one `embed.Client` per process; `Client.spawn`
  starts a worker per client.
- **H2 WebKit renderer baseline plus JS heap high-water.** Every board push re-parses the whole board
  including unbounded history; every sessions push re-parses every session row ever recorded; each
  working agent sends up to 60 terminal events/s. Retained size is small, but the high-water mark and
  the allocator's retained pages (WebKit rarely returns them to the OS) grow with history size and
  session count.
- **H3 xterm per running session.** `cols × (5000 + rows) × ~12 B` per session, about 12 MB at 200
  cols, built even for panes never opened (headless attach plus DOM renderer on a detached div).
  `cursorBlink: true` keeps a timer per terminal. 4 sessions about 50 MB plus DOM.
- **H4 Monaco loaded by an approval and kept for app life** (plus its worker, tens of MB). Loaded by
  `ApprovalsSurface` whenever an agent asks for approval, whether or not a diff is ever opened.
- **H5 Go heap high-water in the app process.** No `SetMemoryLimit`; default `GOGC=100` lets the heap
  reach twice live after a burst (board builds, log reads). Expected tens of MB, measure first.
- Not suspects (checked): SQLite (single connection, default cache), `historyMemo` (one shared
  slice), board snapshot (one shared value), pre-attach drain (256 KiB cap per tab), Pinia (ADE
  stores hold UI state; payloads live in TanStack queries, shallow), tiptap prefetch (stated
  requirement).

## Fixes

Each fix lands only if M shows its retainer above 5% of the total or above 20 MB, whichever is
smaller. A fix whose retainer measures below that is dropped and named as measured-and-small in the
Result. If a measured top-3 retainer is not in this list, record it, stop, and ask for `P661-iter2`
before fixing it.

### F1. One shared embed worker per user (H1)

- `internal/memory/embed/client.go`: add a socket mode. Client dials
  `<memory.Home()>/embed.sock`; on dial failure takes `flock` on `<memory.Home()>/embed.lock` and
  spawns the worker in serve mode, then dials again. Request/response format stays the existing
  NDJSON (`worker.go` `RunWorker`), one connection per client.
- `internal/memory/embed/worker.go`: serve mode accepts connections on the unix socket and serves
  each with the existing loop, one inference at a time (shared mutex; the worker is already
  single-request). Idle exit when no connection and no request for `DefaultIdleTimeout`; removes the
  socket on exit. Stale socket (connect refused) is removed by the lock holder before listen.
- `internal/memory/memorycli/run.go`: `memory-mcp` uses socket mode. The main app's in-process
  client (`bridge/memory.go`) uses socket mode too, so the app and all sessions share one model.
- `internal/memory/workerproc/workerproc.go`: unchanged API; serve mode is a flag of the
  `memory-embed` command.
- Go supports `AF_UNIX` on macOS, Linux and Windows 10+, so one code path. If dial and spawn both
  fail on a platform, fall back to today's private worker.
- Expected: N workers become 1. Saving `(N-1) × worker footprint`, about 300-900 MB at 4 sessions.
- `memory-mcp` mode also sets `debug.SetMemoryLimit(64 << 20)` and `GOGC=50` (only when not set by
  the environment): its heap is small and short-lived, so a soft limit trims each process. Expected a
  few MB per process; keep only if M4 shows a gap.

### F2. Bound the sessions list (H2)

- `apps/kira-space/internal/storage/repos/adesessions.go`: `ListTask` becomes
  `ListTaskBounded(stoppedLimit int)`: every running row, every row with `unseen_at` set, then the
  newest `stoppedLimit` stopped rows, same order as today. One query with `UNION ALL` or two queries;
  pick the one the existing index serves (check `EXPLAIN QUERY PLAN`).
- `apps/kira-space/internal/ade/runs.go:1972` `Sessions`: call it with `sessionsStoppedLimit = 200`;
  the `os.Stat` loop then runs on at most 200 stopped rows.
- Consumers: `frontend/src/ade/v2/board/taskSessions.ts` `taskSessionsOf`,
  `ade/v2/sessions/sessionView.ts`, `frontend/mobile/state/useAgentsModel.ts`. Before changing,
  confirm with `codegraph_explore` what each reads from stopped rows. If a task's indicator needs its
  own latest stopped session even past the limit, add "newest stopped row per non-archived task" to
  the query instead of raising the limit. Record the consumer check in the commit message.
- Expected: wire and JS parse per sessions push bounded; saving proportional to session history
  (small on a fresh install, tens of MB of high-water after months of use).

### F3. History out of the board payload (H2)

- `apps/kira-space/internal/bridge/adewire/wire.go` `Board`: drop `History`. New
  `adewire.HistoryResult{Entries []HistoryEntry}`.
- `apps/kira-space/internal/ade/board.go` `buildBoard`: stop calling `historyEntries`. New
  `TaskBoard.History(ctx)` returns `historyEntries()` (memo stays).
- `apps/kira-space/internal/bridge/adetask.go`: new `AdeTaskService.History`. Mobile HTTP route
  beside the board route, same pattern as `Sessions`. Regenerate bindings (`bun run setup`).
- Board push: the `BoardChange` already says what changed. Add `history bool` to the change set
  (`internal/ade/boardcache.go` `boardChanges`), set by every path that calls `touchHistory`.
- `apps/kira-space/frontend/src/ade/v2/readQueries.ts`: `historyKey = ['adetask','history']`;
  `useBoardHistory` becomes its own `useQuery({ queryKey: historyKey, shallow: true, gcTime: 30_000,
  queryFn: () => reader.history() })`. Callers (`plan/usePlanModel.ts:375`, `board/timeline.ts:339`
  via its input) need no change; the seam was built for this. `timeline.ts` reads
  `input.history ?? board.history`: drop the `board.history` fallback.
- `apps/kira-space/frontend/src/ade/v2/readSignals.ts`: on a board push with `change.history`,
  invalidate `historyKey` (only refetches while a history view is mounted, because it is inactive
  otherwise).
- `apps/kira-space/frontend/src/ade/v2/reader.ts` and both reader implementations (desktop bindings,
  mobile HTTP): add `history()`.
- Expected: board push payload shrinks by the history share (200 archived tasks is most of the
  payload in the `ade 200` world). JS high-water during push bursts drops accordingly. History memory
  is freed 30 s after leaving the timeline/plan.

### F4. Release terminals nobody looks at (H3)

- `packages/workbench/src/terminal/terminalRenderer.ts`:
  - `cursorBlink` on only while focused (`term.textarea` focus/blur listeners): no timer per hidden
    terminal.
  - New option `scrollback` from deps; agent sessions pass `AGENT_SCROLLBACK = 1000`, plain terminals
    keep 5000. Claude Code keeps its own transcript; 1000 lines covers what a user scrolls back in a
    TUI. Saving 80% of each agent buffer, about 10 MB per session at 200 cols.
  - Do not open the renderer for a headless attach: `getOrCreateTerminal` creates the Terminal (parser
    and buffer, needed so output is never lost and `tailTerminal` works) but calls `term.open(host)`
    only on first mount (`useTerminalMount.ts`). Saves the DOM renderer (rows × spans, canvas
    measure) for every never-viewed session.
- `packages/workbench/src/terminal/TerminalHostView.vue` / `useTerminalMount.ts`: call the new
  `openTerminalIfNeeded(tabId)` before appending `host`.
- `apps/kira-space/frontend/src/ade/v2/sessions/AdeTuiPane.vue` (or the deps factory it uses): pass the
  agent scrollback.
- No change to terminal reaping in `adeTerminals.ts`: stopped sessions already release.
- Coalesce window for hidden terminals (larger batches, fewer events): only if M2 shows terminal
  event garbage above the gate. Otherwise not done.
- Expected: about 10 MB per running session plus DOM per never-opened pane.

### F5. Monaco only when a diff is shown (H4)

- `packages/workbench/src/approvals/ApprovalsSurface.vue:57`: remove the eager `loadMonaco()` on
  pending count. Load it where the approval diff editor mounts (the component already awaits
  `loadMonaco()` on mount; confirm with `codegraph_explore` before removing). If the eager load exists
  to avoid a visible delay on first open, keep it but trigger on approval panel open instead of on
  count, and name that requirement in a comment.
- Expected: Monaco plus worker (tens of MB) not loaded in an agents-only session unless a diff is
  opened.

### F6. Go heap soft limit in the app (H5)

- `apps/kira-space/main.go` (or `appwire` start): `debug.SetMemoryLimit` from the observed live heap
  (M4) with headroom, only when `GOMEMLIMIT` is unset. Keep `GOGC` default. Only if M4 shows heap
  total above twice live after the M1 fixture. Expected tens of MB.

## P660 compatibility

P660 (Stream A) keeps module and tab view state. If it keeps module views alive (`KeepAlive` or
`v-show`), the ADE DOM stays mounted while another module shows. P661 stays compatible because:

- Terminals already live outside components (`byTabId`); keep-alive changes nothing for them, and
  F4's lazy `open` still runs on first visible mount.
- F3's history query is inactive when no history view is mounted; under keep-alive a hidden mounted
  view stays an observer, so its data stays. Bounded by one history array, refetched only on history
  change. Acceptable.
- P661 adds no module keep-alive and no unbounded retention. If P660 uses `KeepAlive`, it should set
  `max` (bounded retention); P661's measurement records DOM node count so a P660 regression shows.
- No P661 change depends on P660 code, and P660 needs nothing from P661.
