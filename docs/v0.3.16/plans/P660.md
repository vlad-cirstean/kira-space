# P660 Keep module state across tab switches

Stream A of batch 2 (`plans/batches.md`). Frontend only. Base: `chapter/v0.3.16` with batch 1
(P657, P658, P659) landed.

## Root cause

How modules mount (`apps/kira-space/frontend/src/workbench/WorkbenchShell.vue`):

- Left panel: `<component :is="activeModePanel" />`. Every module switch unmounts the old module's
  panel and mounts the new one cold.
- Main area, panel modules: `MainView` stays mounted. It renders the active workspace's active tab
  with `v-if` + `:key="activeTab.id"`; only kinds with `keepMounted` (only `repo-graph`) stay
  mounted (`v-show`, `KEPT_MAX = 4`). A module switch changes `activeWorkspace`, so the previous
  module's tab view unmounts. An in-module tab switch does the same.
- Main area, no active tab: `<slot name="empty">` renders `modeStart` with `v-if`. Memory detail,
  Docker and Kubernetes main views are `start` components, so they unmount on every module switch.
- Full module (ADE): `<component :is="fullView" v-if="isFull" />`. `AdeView` unmounts on every
  switch away. Inside ADE, `AdeShell.vue` switches pages with `v-if` on `ui.view`.

Where state lives:

- Pinia stores (survive): tree/collections/docker/kube/memory search text, tree expansion, tab
  model, ADE page and panel tab, kube tabs, repo panel tab, repo search query.
- `tab.state` (persisted): grid `scrollTop/scrollLeft` (`SlickGridHost.vue` `persistScroll`), HTTP
  request/response pane and view, page index, filter, sort.
- Per-tab runtime stores (session, P375): grid/doc/kv/stream find input, filter drafts,
  `columnFilter` (P658), HTTP field/header/cookie filters, console caret/scroll
  (`views/console/viewState.ts`, `useResultScrollState.ts`).
- Component refs (lost on unmount): everything else, listed below.

Why the asks keep coming back:

1. P375 (v2.8, `docs/history/06-v2.8.md` line 490) moved tab-view filter inputs into runtime
   stores. Its spec (`tests/ui/studio/tab-filter-state.spec.ts`) switches tabs inside one module.
   It never covered a module switch, module panels, start views or the ADE full view, which
   unmount through `WorkbenchShell`, not `MainView`.
2. `usePanelHeaderSearch` (`packages/workbench/src/behaviour/panelSearch.ts`) keeps `showSearch` as
   `ref(false)`. The text lives in a store, the visibility does not. After a round trip the bar is
   hidden while its text still filters the tree (Studio, API, Docker, Kubernetes): the user sees
   "search bar lost" plus a mysteriously filtered list.
3. Scroll is saved only by the SQL grid (`tab.state`) and console. Every virtual list and page
   scroller restarts at 0 on remount.
4. Each fix was per field, with no shared seam and no guard. Later surfaces added new component refs
   (`GitPanel` `local.repoSearch/fileSearch`, `AutomationsPanel` `search`, Docker/Kube log filters)
   and regressed silently.
5. Keep-alive was tried and dropped: v1.3 graph `KeepAlive` became dead code (v1.9), replaced by
   `keepMounted` for `repo-graph` only (v2.8). P139 (v2.0) user decision: no tab caching for Studio
   tab switches.

## Mechanism decision

One session-only view-state store with two composables, applied to every surface. No KeepAlive.

Declined: KeepAlive (or `v-show`) for module panels, start views, ADE and tab views.

- Memory (P661 goal): it retains each visited module's DOM: ADE board and panels, SlickGrid
  instances, Monaco editors (several MB each), docker/kube tables. `KeepAlive max` bounds the count,
  not the size; the largest subtree (ADE) is the one P661 shrinks.
- Hidden subtrees stay live: TanStack Query observers keep refetching on invalidation, watchers run,
  `registerCommand` bindings made in `onMounted` (`CollectionsPanel`, `GitPanel`) stay active in
  other modules. Every component would need an `onActivated`/`onDeactivated` audit.
- P662 coupling: a Studio subtree that freezes the UI would keep freezing outside Studio.
- Contradicts the P139 user decision for tab views.

Chosen cost: remount stays as today (P139 measured ~113-125 ms p50 tab switch, WebKit sandbox).
P660 adds only state reads at mount. Memory: one LRU-capped map of short strings, booleans and two
numbers per key, capped at 400 keys (well under 100 KB). No DOM retained.

Pinia, not `usePersistedState`: state is session-only UI state (survive a switch, not a restart),
and per-device prefs belong to `usePersistedState`. Restart persistence stays where it is
(`tab.state`).

## Design

### Store: `packages/workbench/src/state/viewState.ts` (new)

`useViewStateStore = defineStore('viewState', () => { ... })`. One concern: view state of
unmounted surfaces.

- `values = reactive<Record<string, unknown>>({})`: kept refs (search text, toggles, ids).
- `scrolls = new Map<string, { top: number; left: number }>()`: plain, non-reactive (nothing
  renders from it; a scroll event writes two numbers, no reactivity cost, no timer).
- `lru = new Map<string, true>()`: touch on every write (delete, set). Over `VIEW_STATE_MAX = 400`
  evict the oldest key from `values` and `scrolls`.
- Actions: `read<T>(key, fallback): T`, `write(key, value)`, `scroll(key)`, `setScroll(key, pos)`,
  `drop(prefix)` (deletes every key starting with `prefix` from all three maps).
- `registerTabRuntimeCleanup((tabId) => drop(\`tab:${tabId}:\`))` (`packages/workbench/src/state/
  tabRuntime.ts`). Covers browse preview keys (`tab:<id>::preview:...`).

Key scheme (export helper `tabViewKey(tabId, surface)`): `<mode>:<surface>[:<id>]` for module
surfaces, `tab:<tabId>:<surface>` for tab views. Per-entity keys (container, pod, task) rely on
the LRU cap.

### Composables: `packages/workbench/src/behaviour/viewState.ts` (new)

- `useKeptState<T>(key: MaybeRefOrGetter<string>, fallback: T): WritableComputedRef<T>`: get reads
  `store.read(toValue(key), fallback)`, set calls `store.write`. Reactive key: a key change reads the
  new entry (per-repo, per-container).
- `useKeptScroll(key: MaybeRefOrGetter<string | null>, el: Ref<HTMLElement | null>, opts?: {
  ready?: () => boolean })`:
  - `useEventListener(el, 'scroll', save, { passive: true })`; `save` writes
    `{ top: el.scrollTop, left: el.scrollLeft }` and marks the key settled. The scroll event the
    restore itself fires saves the same position: harmless, so no `restoring` flag and no timer.
  - Restore once per mount and per key: `watch([el, () => toValue(key), () => opts?.ready?.() ??
    true], ..., { immediate: true, flush: 'post' })`. When el exists, ready is true, the key is not
    settled and a saved position exists: assign `scrollTop/scrollLeft`, mark settled.
  - A user scroll before restore marks the key settled, which cancels the pending restore. A key
    change resets settled.
  - Null key disables it.
- `useKeptEditorScroll(key)`: returns `{ initial: number, save(top: number) }` for `MonacoHost`
  (`scrollTop` prop seeds once, `update:scrollTop` emits). `save` writes `store.setScroll` directly
  (sync, no debounce: a map write).

### Shared seams (one change reaches many lists)

- `packages/workbench/src/behaviour/virtualRows.ts` `UseVirtualRowsOptions`: add
  `keepScroll?: MaybeRefOrGetter<string | null>`. In `useVirtualRows`, when given:
  `useKeptScroll(opts.keepScroll, opts.scrollElement, { ready: () => totalSize.value > 0 })`.
- `packages/workbench/src/behaviour/treeVirtualRows.ts`: pass `keepScroll` through.
- `packages/docker-ui/src/components/VirtualList.vue`: new optional prop `keepScrollKey?: string`
  forwarded as `keepScroll`.
- `packages/workbench/src/behaviour/panelSearch.ts`: new required option
  `stateKey: string | null`. Non-null: `showSearch = useKeptState(\`${stateKey}:showSearch\`,
  false)`. Null: `ref(false)` (git-ui's own Vue app has no Pinia; see Part 2). Both: at setup, if
  `opts.getSearch() !== ''` then `showSearch.value = true` (never a hidden active filter). Required
  so every caller decides; typecheck finds them all.

`mount`, no Pinia) with `NullViewStateStore`. `GitPanel` unmounts on module switch, so the
in-flight review, file filter and scroll are lost. Fixing it changes git-ui's mount contract
(`ViewStateStore` is versioned for the graph's `PersistedViewState`), a different subsystem with
its own design decision. Per WORKING_AGREEMENT "Phase numbering", rename this row
`P660 Part 1: Keep module state across tab switches` and add `P660 Part 2: Git review panel state
across module switches` right after, with its own plan. Part 1 passes `stateKey: null` for the
git-ui callers (`ReviewView.vue`, `FileTree.vue`), which still gain the "reveal when text is
non-empty" rule.

## Tests

No backend half: every new piece of state is frontend, session-only, never sent over IPC or stored
server-side. The only persisted view state (grid scroll in `tab.state`) is unchanged. No flow test;
say so in Result. No unit test (the LRU is one rule; restore gating is covered end to end).

UI specs, one test per module, each a round trip: set state, switch to another module, switch
back, assert. Scroll assertions use `expect.poll(() => el.evaluate((e) => e.scrollTop))` (restore
waits for `ready`). Shrink the viewport (`page.setViewportSize`) so existing fixtures overflow;
extend a fixture's rows in the spec's own snapshot only where it still does not scroll.

first, P662 after it.
