# P667 Single-select cards

Spec row: `../SPEC.md` P667. Batch 4, Stream B (`plans/batches.md`). Base: `chapter/v0.3.16` at

## Goal

Round radio dots that carry a description become selectable cards. Whole card is the radio and the
click target: title plus description, selected state from theme tokens. Keyboard and aria radio
semantics stay on reka's RadioGroup. One new theme component, four surfaces: Reset mode, Review
route, Cherry-pick mainline, Revert mainline.

## Design

### Library check (CLAUDE.md Frontend)

shadcn-vue has no card-radio component; its "choice card" is a composition over `RadioGroupItem`.
Built here on reka `RadioGroupItem` (same primitive as the theme dot), so roving focus, arrow keys,
Space, `role="radio"`, `aria-checked`, `data-state`, `data-disabled` come from reka. Tailwind
utilities only, no `<style>`. `useId` (Vue) for title/description ids. No new dependency, no Pinia,
no TanStack Query (no new state or fetch).

Rejected: shadcn choice-card shape (`FieldLabel` wrapping `Field` + visible dot). User decision and
mock (`scratchpad/radio/mock.html`, option 4) replace the dot; card border/tint carries selection.

### New component: `RadioGroupCard.vue`

File: `packages/theme/src/components/ui/radio-group/RadioGroupCard.vue`; export
`RadioGroupCard` from `radio-group/index.ts`. Use inside the theme `RadioGroup`.

Script (`<script setup lang="ts">`):

- Props: `RadioGroupItemProps & { class?: HTMLAttributes['class'] }` (value, disabled, id, ...).
- `reactiveOmit(props, 'class')` + `useForwardProps`, same as `RadioGroupItem.vue`.
- `const titleId = useId(); const descriptionId = useId();`
- Slots: `title` (required), `description` (optional). `useSlots()` only to skip
  `aria-describedby` and the description span when the slot is absent.

Template:

```vue
<RadioGroupItem
  data-slot="radio-group-card"
  v-bind="forwardedProps"
  :aria-labelledby="titleId"
  :aria-describedby="slots.description ? descriptionId : undefined"
  :class="cn(
    'flex w-full min-w-0 flex-col items-start gap-0.5 rounded-kira border border-border bg-bg px-2.5 py-2 text-left text-kira-md text-fg transition-colors',
    'not-data-[disabled]:not-data-[state=checked]:hover:bg-field',
    'data-[state=checked]:border-focus data-[state=checked]:bg-select',
    'data-[disabled]:cursor-default data-[disabled]:opacity-50',
    props.class,
  )"
>
  <span :id="titleId" class="font-medium"><slot name="title" /></span>
  <span v-if="slots.description" :id="descriptionId" class="text-kira-sm leading-normal text-muted-foreground">
    <slot name="description" />
  </span>
</RadioGroupItem>
```

`RadioGroupItem` here is reka's (import from `reka-ui`), not the theme dot. Attrs fall through to
the button, so `data-testid` and `data-*` set by callers land on the radio element.

States (acceptance):

- idle: `border-border bg-bg`, title `text-fg` medium, description `text-muted-foreground`.
- hover (not checked, not disabled): `bg-field`.
- selected: `data-[state=checked]` `border-focus bg-select` (both theme tokens; `bg-select` is the
  neutral selection fill ARCHITECTURE line 1416 allows; not a solid tone fill, so U106 does not
  apply).
- focus-visible: base `:focus-visible` rule applies `focus-ring` to the natively focused button
  (`tailwind-core.css` `@utility focus-ring`); no extra class.
- disabled: reka `disabled` prop sets `data-disabled` and native `disabled`: `opacity-50`,
  `cursor-default`, no hover, skipped by roving focus.

Rules: no `h-*` (U38; height comes from padding), no stock `text-xs/sm`, no `rounded-md`, weights
400/500 only. `components/ui` is not scanned by `check-ui-primitives.sh`, but keep the rules anyway.

Group layout: callers keep the theme `RadioGroup` (`grid gap-2 w-full`); pass `class="gap-1.5"`.
One column everywhere: Reset descriptions run about 100 characters and the review panel is narrow.
