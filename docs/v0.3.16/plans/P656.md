# P656 Release retention deletes whole releases, never tags

Spec row: `../SPEC.md` P656. Base: `origin/main` at `4cf84a7b` (v0.3.15).

## Goal

Retention deletes a release that fails the keep rule whole, through `DELETE
repos/{repo}/releases/{id}`. That endpoint leaves the git tag. Retention never calls `git/refs`, never
uses `gh release delete` (whose `--cleanup-tag` removes tags), never deletes assets one by one. Keep
rule unchanged.

### 4. `.github/workflows/release-retention.yml`

- Header comment: deletes releases the updater no longer needs, whole, with their assets; git tags,
  drafts, prereleases and `releases/latest` never touched; `releases/{id}` is the one delete endpoint.
- Apply step:

  ```sh
  COUNT="$(grep -c . deletes.tsv || true)"
  if [ "$DRY_RUN" != false ]; then
    echo "dry run: would delete $COUNT releases (tags kept)"
    exit 0
  fi
  ERR="$(mktemp)"
  # Whole releases: releases/{id} is the one endpoint this job deletes through. It leaves the tag.
  while IFS="$(printf '\t')" read -r ID TAG; do
    [ -n "$ID" ] || continue
    case "$ID" in *[!0-9]*) echo "bad release id '$ID' for $TAG" >&2; exit 1 ;; esac
    if gh api -X DELETE "repos/$GH_REPO/releases/$ID" 2>"$ERR"; then
      echo "deleted release $TAG (id $ID); tag kept"
    elif grep -q 'HTTP 404' "$ERR"; then
      echo "already deleted: release $TAG (id $ID)"
    else
      cat "$ERR" >&2
      exit 1
    fi
  done < deletes.tsv
  ```

- Fetch, Plan, triggers, permissions (`contents: write` covers release delete), `RELEASE_RETENTION`
  gate: unchanged.

## Behaviour checks (no code change expected)

- Updater (`internal/appupdate` `listReleases` → `releaseline.NextStep`): lists `/releases` only. A
  deleted release is absent; an asset-stripped one (old rule) was present but not `Eligible`. Both
  drop out of `Lines` identically, so stepping is unchanged. Keep set always holds each line's first
  and last eligible release, the only step targets. Running version need not exist as a release.
- `install.sh` JXA `nextStep` filters on `hasAsset` the same way: same result.
- `install.sh --tag` on a deleted release: `releases/tags/<tag>` returns 404; script dies with `no
  published release vX.Y.Z` (step 5). Clear enough; no change, no contract bump. `Installer.Stage`
  only passes a `NextStep` target, always kept. `install-smoke` passes the just-published tag, kept as
  latest.
- `/releases/latest` is in the keep set, never deleted, so it never moves.
- Tag-only versions (`v0.2.x`, `v0.3.0`..`v0.3.2`, and future deleted releases) matter nowhere:
  updater and install.sh read `/releases`; `release-on-merge.yml` takes the version from the branch
  name; CLAUDE.md version fallback reads tags, which stay.
