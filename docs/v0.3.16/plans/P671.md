### Why paths fail today

1. Extension gate. `Resolve` rejects any extension outside the OS file-association vocabulary even
   inside an imported repo: `Dockerfile`, `src/Makefile`, `.env.example`, `notes.txt`, `index.html`,
   `go.mod`, `go.sum`, `.gitignore`, `LICENSE`. The repo file tab reads any file
   (`CodeWorkspaceService.ReadFile` > `codeworkspace.ReadFileIf`: no extension check, binary sniffed).
   So the gate is needed only for standalone files (`Service.Read` keeps it).
2. Single cwd. Live cwd wins outright. A path printed relative to the start folder no longer
   resolves once the shell `cd`'d or while a tool with another cwd holds the foreground (agent or
   script running a subprocess). `fallbackCwd` is used only after exit.
3. Shapes the grammar misses: `a.ts:12-30` (Claude Code line ranges: whole token sent, never exists),
   `a.ts#L12`, `a.ts(12,5)` (tsc), Python `File "x.py", line 12`, `file:///abs/a.ts`, quoted paths
   with spaces, `My\ Docs/a.ts`, git diff `a/src/x.ts` / `b/src/x.ts`, paths glued to Unicode
   framing (`│src/a.ts`, `“src/a.ts”`, `src/a.ts…`, `⎿ src/a.ts`).
4. Right mouseup with Cmd opens (no button check).

### 1. Right-click link menu

New `packages/workbench/src/terminal/linkMenu.ts` (pure, no xterm import):

  | { kind: 'file'; target: FileLinkTarget; abs: string };

- File: `open-file` "Open" > `actions.openFile(target)` (line/col kept); `copy-path` "Copy path"
  (`common.action.copyPath.label`, icon `copy`) > `actions.copy(abs)`: absolute, `~` expanded, no
  `:line` suffix.
- Test ids come from `MenuItems.vue`: `menu-item-open-link`, `menu-item-copy-link`,
  `menu-item-open-file`, `menu-item-copy-path`.

`terminalRenderer.ts`:

1. `let hovered: HoveredLink | null`. Web `linkHover.hover(e, uri)` sets `{kind:'web', uri}`; file
   handler `hover(e, link)` sets the file link; both `leave` clear it. Hint unchanged.
2. `activate` and file `open` return early when `event.button !== 0`.
3. In `open()` after `term.open(host)`, only when `deps.linkActivation === 'modifier'`:
   `useEventListener(term.element, 'contextmenu', onContextMenu, { capture: true })` (VueUse). Capture
   on `term.element` runs before xterm's bubble listener on the same element. `onContextMenu`: no
   `hovered` > return (xterm default stays). Else `preventDefault()`, `stopPropagation()` (no word
   select, no native menu), `hint?.hide()`, then
   `useContextMenuStore().openContextMenu(e, linkMenuItems(hovered, actions))`.
   Opening on `contextmenu` matches every other app menu (CollectionsTree, ProjectTree), so reka's
   pointer-up behaviour is the proven path.
4. `actions`: `openLink: (u) => isWebUrl(u) && deps.openLink(u)`; `openFile: (t) =>
   deps.fileLinks?.open(tabId, t)`; `copy: (text) => copyText(text).catch((err) =>
   announceApp(errorText(err)))` (`behaviour/clipboard`, `behaviour/liveRegion`, `bridge/codedError`).
   The menu store captures and restores focus (xterm textarea gets it back).

Direct store import, no new dep plumbing: all three desktop creators get the menu, phone (`'tap'`)
never touches Pinia. ContextMenu.vue is mounted in the main and files windows (`App.vue`).

Hint text (`workbench.terminal.link.tooltip`): "{modifier}-click to open, right-click for more".
Existing specs assert `-click to open`, still true.

Known limit (document in ARCHITECTURE): xterm clears its hovered link when output rewrites that
link's rows; a right click there without moving the pointer gets xterm's default until the next
move. xterm exposes no public "link at point" API.

Library check: no xterm addon offers a link context menu or file-path links (official addons:
web-links, fit, search, serialize, unicode, image, clipboard, ligatures, webgl). `registerLinkProvider`
is xterm's public seam for custom links, kept. `@xterm/addon-clipboard` handles OSC 52 from the
program, not user copy of a link; not needed. Menu from shadcn/reka via the existing
`ContextMenu.vue`; listener via VueUse; menu state via the existing Pinia store.

### 2. Path finder rules (`filePaths.ts`)

Rewrite `findFilePaths` keeping `FilePathMatch`, `MAX_MATCHES_PER_LINE`, `toCellRange`, `CellRow`
unchanged. Rules, applied in this order at each scan position:

1. Breaks. `TOKEN_BREAK` adds U+2500-U+25FF (box drawing, blocks, geometric: `│ ┃ ● ■`), U+2018-U+201F
   (curly quotes), `«`, `»`, U+2026 `…`, U+23BF `⎿`, U+23FA `⏺`. `TRAILING_PUNCT` adds `…`.
2. Quoted span. At an ASCII `"`, `'` or `` ` ``: find the same quote later on the text (within
   `MAX_PATH_LEN`). Content holds a space and parses (rules 5-7) and qualifies: emit it
   (`start` = after the opening quote), continue after the closing quote. Otherwise the quote is a
   plain break and scanning goes on inside (today's behaviour, so `"src/a.go:2"` keeps working).
3. `file://`. Token starting `file://` with empty host or `localhost`: path = percent-decoded rest
   (`decodeURIComponent`; a throw drops the candidate), must start with `/`. Range covers the whole
   URL. Checked before the `://` web-link exclusion; any other scheme stays excluded.
4. Escaped space. Inside a token, `\` followed by a space continues the token; the path unescapes
   `\ ` to ` `. Range covers the raw text.
5. Position suffix at token end, first match wins: `:L:C`, `:L`, `:L-L2` (line L), `:L:C-C2`
   (line L, col C), `#LL`, `#LLCC`, `#LL-LL2` (line L). Out-of-range or zero falls back to the bare
   path, as today. `TRAILING_PUNCT` strips first.
6. Paren position. Token immediately followed by `(L)` or `(L,C)` (tsc, MSBuild): attach; `end`
   covers the `)`.
7. Python position. A rule-2 or quote-broken token whose closing `"` is followed by `, line L`:
   attach line L; range stays the path only (the clickable part is the path).
8. Qualify (unchanged): non-empty, at most 1024, not dots-only, not `-flag`, has `/` or an extension.
   A bare word without either (`Makefile`, `README`) is not sent: a backend round-trip per word on
   every hovered row would cost more than it finds.

Comment header lists what stays unsupported (below).

### 3. Backend resolve (`openedfiles`, `bridge/openedfiles.go`)

`apps/kira-space/internal/openedfiles/openedfiles.go`: split `Resolve` into unexported
`resolve(path string, repos []model.CodeRepo, anyTypeInRepo bool)`. `Resolve(path, repos)` =
`resolve(path, repos, false)` (OS open path unchanged). With `anyTypeInRepo`, the extension check
applies only when no repo root contains the real path: repo files open as repo tabs, which read any
file; standalone files keep the vocabulary (`Service.Read` guard unchanged).

`apps/kira-space/internal/openedfiles/terminal.go`:

- `terminalCandidates(raw string, cwds []string, home string) []string`: `TerminalPath(raw, cwd,
  home)` per cwd (abs and `~` give one), then, when `raw` is relative and starts `a/` or `b/`, the same
  for `raw[2:]`. Deduped, order kept.
- `Openable(cwds []string, home string, paths []string) []string`: repos listed once
  (`s.repos()`); per path the first candidate whose `resolve(c, repos, true)` succeeds; its absolute
  path (`Target.Path`, or `filepath.Join(repo.Root, RelPath)` for a repo target: expose the abs from
  `resolve`), else `""`.
- `OpenAt(abs, line, col)` uses `resolve(abs, s.repos(), true)`. Implementer confirms with codegraph
  that `TerminalOpen` is its only caller; if another exists, add `OpenTerminalAt` instead.

`apps/kira-space/internal/bridge/openedfiles.go`:

- `termCwds(id, fallback) ([]string, error)`: live cwd (when the session is live and non-empty), then
  `fallback` when non-empty and different. Same `fallbackCwd must be absolute` check.
- `OpenedFilesTerminalResolveResult` gains `Paths []string `json:"paths"`` (absolute or `""`);
  `Openable[i] = Paths[i] != ""`. Field `openable` kept so existing callers and contract keys stay.
- `TerminalOpen`: first candidate across `termCwds` that resolves (shared helper with `Openable`, one
  `firstOpenable` func), else `ErrNotOpenable` as today.

Regenerate Wails bindings (`wails3 task common:generate:bindings`, DEV_ENVIRONMENT).

Frontend:

- `TerminalFileLinks.resolve` returns `Promise<(string | null)[]>` (absolute per path, `null` when not
  openable). `apps/kira-space/frontend/src/bridge/index.ts` maps `{openable, paths}` to it.
- `fileLinkProvider.ts`: link when non-null; closure holds `abs`; `hover(event, matched, link)`

- Reveal is not added: the app has no reveal-in-Finder for an arbitrary path (only Studio's
