### fsevents stream limits (library code and docs)

- Library: no stream cap. `Start` registers the stream in an unbounded `registry` map and creates one serial
  dispatch queue per stream (`wrap.go` `start`). GCD pools threads; an idle queue costs no thread.
- README and `TestIssue48`: macOS refuses `Start` when one stream names more than 4096 paths. Seam passes at
  most 2 paths per stream.
- Apple documents no per-process stream count. Field reports (Watchman, editors) of `f2d_register_rpc` errors
  come at hundreds to thousands of streams.
- Expected live streams: open repos (~20) + watched folders (~5) + tasks with a live grant (~20) + config
  modules (8) = ~50. Two orders below any reported failure.
- `Start` error reaches the caller, which degrades as today (git: `Acquire` fails; task: unwatched, finish
  flush applies; folder and config: warning).

Decision: one stream per `Watcher`, no sharing. Sharing needs a process-wide multiplexer with refcounts,
per-subscriber filters and teardown ordering across owners; nothing at ~50 streams needs it. Revisit only on
a Mac-observed `Start` failure.

### Contract (doc comment on `Watch`, kept short)

```go
type Op uint8
const (
	Create Op = 1 << iota
	Write
	Remove
	Rename
	Meta // chmod, owner, xattr, inode metadata
)
func (o Op) Has(x Op) bool

type Event struct {
	Path   string // caller's spelling of the matched root + rel, Clean + NFC; "" when Rescan
	Op     Op     // hint only: FSEvents coalesces several ops into one event; stat for current state
	Dir    bool   // FSEvents ItemIsDir; fsnotify: Lstat on Create/Rename, false otherwise
	Rescan bool   // something changed, unknown what: rescan everything you care about
}

const Unlimited = -1

type Options struct {
	Roots    []string                // existing directories; nested roots allowed
	MaxDepth int                     // deepest watched dir below a root (root = 0); Unlimited for none
	SkipDir  func(path string) bool  // dir below a root (caller spelling): true = not watched, its subtree dropped; nil = none
	Latency  time.Duration           // FSEvents coalescing latency; fsnotify ignores it; 0 = deliver at once
}

func Watch(o Options) (*Watcher, error)
func (w *Watcher) Events() <-chan Event
func (w *Watcher) Close() error
func Backend() string // "fsevents" or "fsnotify", for one log line per consumer
```

Rules:

1. **Roots.** Each root: `os.Stat` must succeed and be a dir, else `Watch` fails wrapping `fs.ErrNotExist`
   (or the stat error). Zero roots fails. `filepath.EvalSymlinks` resolves each root (keep the cleaned path if
   it fails), then `norm.NFC`. Backends watch resolved roots. FSEvents gets top-level resolved roots only (a
   root nested in another is covered by the recursive stream).
2. **Re-rooting.** Event path from a backend is cleaned and NFC'd, then matched to the deepest resolved root
   that equals it or prefixes it at a separator. Reported `Path` = caller's root spelling (Clean + NFC) joined
   with the rel. On darwin only, when no exact prefix matches, retry with a case-insensitive prefix (APFS
   default volumes are case-insensitive; FSEvents reports on-disk case). No match: drop. Callers compare
   against the paths they passed and never call `EvalSymlinks` themselves.
3. **Scope.** A dir below a root is *decided* once: watched iff its depth <= `MaxDepth` (or `Unlimited`), every
   ancestor below the root is watched, and `SkipDir` returns false. The verdict holds until an event for that
   dir carries `Remove` or `Rename`, or a Rescan; then it and its subtree are forgotten and decided again when
   next met. Decision points, same on both backends: initial walk at `Watch` (bounded by depth and verdicts),
   a dir `Create`/`Rename` event, and lazy top-down decision of unknown ancestors when an event arrives below
   them. fsnotify maps "watched" to `fsw.Add` (failure: `slog.Warn`, scope `fswatch`, skip that dir).
   FSEvents keeps the verdicts in the decided set and drops events whose parent is not watched. Why decided
   once, not live: matches fsnotify, where a watch stays once added. Example: `git init` inside an already
   watched plain folder must still deliver the `.git` Create (folderwatch needs it).
4. **Delivery filter.** An event is delivered iff its path is a root, or its parent is a root or a watched dir.
   A dir's own events are delivered even when its verdict is "not watched" (its parent is watched). Example:
   cloning a repo into a watched folder delivers the repo dir's Create.
5. **New dirs.** A new dir delivers one event for itself. Files created in it before the backend watched it
   (fsnotify) may raise none. Consumers that need contents walk the dir (taskwatch and folderwatch do).
6. **Dropped events.** Three sources, one outcome, a single `Event{Rescan: true}`:
   fsnotify `ErrEventOverflow`; FSEvents `MustScanSubDirs | KernelDropped | UserDropped | RootChanged | Mount |
   Unmount`; seam output buffer full. Buffer: `out` channel, cap 1024. Backend goroutine never blocks on `out`:
   non-blocking send; when full, set `pendingRescan`, drop path events until a Rescan send succeeds (select
   case on `out` armed only while pending). On any Rescan the seam forgets all verdicts and re-walks (fsnotify
   re-`Add`s missing dirs) before sending, so after a Rescan the watch covers the current tree. Other fsnotify
   errors: `slog.Warn`, not delivered.
7. **Ops mapping.** fsnotify: Create, Write, Remove, Rename, Chmod to Meta. FSEvents: `ItemCreated` Create,
   `ItemModified` Write, `ItemRemoved` Remove, `ItemRenamed` Rename, `ItemInodeMetaMod | ItemChangeOwner |
   ItemXattrMod | ItemFinderInfoMod` Meta, `ItemIsDir` Dir. `HistoryDone` and `EventIDsWrapped` ignored.
8. **FSEvents stream.** `Flags: FileEvents | WatchRoot`, `Device: 0` (nonzero gives device-relative paths),
   `Resume: false`, `Latency: o.Latency`, `NoDefer` and `IgnoreSelf` unset (keep the existing reasons from the
   gitclient file's comments, trimmed).
9. **Goroutines.** One goroutine per `Watcher`, owned by the seam: sole reader of the backend source
   (`fsw.Events`/`fsw.Errors` or `es.Events`), applies scope and re-rooting, sole writer of `out`. The FSEvents C
   callback runs on the stream's dispatch queue and blocks on unbuffered `es.Events`; the goroutine always has a
   receive case on it, so the callback can always complete. `SkipDir` runs on this goroutine (keep it cheap:
   name checks, at most a few `Lstat`). Consumers own their own reading goroutine.
10. **Close.** Idempotent, safe from any goroutine, the reading one included. Order: stop forwarding, stop the
    backend (FSEvents: D10 drain, `es.Stop`, done, join), join the goroutine, close `out`. On return no
    goroutine of the watcher runs. `Events` then yields only events already buffered and closes; a consumer
    that is stopping ignores them. `Close` returns the backend's close error (fsnotify) or nil.

### Debouncer

```go
type Debouncer struct{ /* Quiet, MaxWait, fn; mu, timer, first, stopped, running WaitGroup */ }
func NewDebouncer(quiet, maxWait time.Duration, fn func()) *Debouncer // maxWait 0 = none
func (d *Debouncer) Schedule() // (re)arm: wait = quiet, capped at first+maxWait-now, floor 0; no-op after Stop
func (d *Debouncer) Stop()     // no fire after return; waits for an in-flight fn
```

Replaces three hand-rolled copies: `configfs.debouncer` (200 ms, no max), `folderWatcher.schedule/rescan/stop`
(500 ms), `taskWatch.queue/fire` timer part (300 ms quiet, 2 s max). `first` resets when `fn` starts. gitclient's
leading window stays in its `run` loop (different rule, tested). `internal/shell/debounce.go` untouched (not a
watcher; different API).
