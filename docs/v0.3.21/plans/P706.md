# P706: Pull request icon: one glyph for every PR status

Spec row: `docs/v0.3.21/SPEC.md` `## P706`. Base: `chapter/v0.3.21` at `8687f07ef`. Stream branch
`stream/p706`.

User decisions: keep the generic PR icon (no GitHub brand mark, Codicons only). One glyph reflects
all status: state shape, checks badge (pending animated, passed shown too), review state, conflicts,
auto-merge, one tooltip. One shared glyph model for branch row, host sidebar and mobile.

Discovery used `codegraph_explore` (index in `/home/user/kira-space`, older checkout) and Read in this
worktree for every hit. Line numbers are at the base commit.

## 2. What the icon shows

### 2.1 Ranking

1. State: icon shape. Always.
2. Checks: corner badge dot. Open and draft only (GitHub reports rollup for open only; a badge on a
   merged PR is noise).
3. Conflicts: shape tone red.
4. Changes requested: shape tone amber.
5. Auto-merge on: shape tone purple (board purple already means merged, `board/actions.ts:425-431`:
   "on its way to merged").
6. Approved: shape tone green.
7. Nothing of 3-6: state tone (open blue, draft grey).

Items 3-6 apply to open and draft only, first match wins for the tone. Merged is purple, closed
grey. Every reported item, shown in tone or not (an approved PR that also has conflicts), gets its
own tooltip line. Review required and comment counts stay tooltip-only: review required is the
default for most PRs, so tinting it would colour every open PR.

### 2.2 Glyph parts

- Shape (Codicon, 13px): open `git-pull-request`, draft `git-pull-request-draft`, merged `git-merge`,
  closed `git-pull-request-closed`, unknown state `git-pull-request`.
- Shape tone: board pastel `Tone` (`ade/v2/tones.ts` `TONE_TEXT_CLASS`). `tones.css` loads in desktop
  (`src/styles.css:5`, host view windows included) and mobile (`mobile/styles.css:3`).
- Checks badge: `StatusDot` (theme primitive; U23 allows `animate-pulse` only there) in the
  `TooltipIconButton` `#badge` slot, positioned like `RefreshButton.vue:85-91`
  (`absolute`, bottom right). Success `ok`, failure and error `error`, pending and expected `warn`
  with `pulse`. Passed checks keep the dot; no second icon.
- Reduced motion: `base.css:95-112` already sets `[data-slot="status-dot"] { animation: none }` under
  `prefers-reduced-motion: reduce`. Pending keeps a static amber dot, distinct from green and red by
  colour, so it stays visible. No new CSS.

### 2.3 Tooltip

One tooltip, one line per part, in order: title (bold, branch row only), state plus base (existing
`common.*.status` via `prStateLabel` and `space.ade.mainTab.prBase.label`), checks, review,
conflicts, auto-merge. Lines are separate elements, never concatenated strings. Aria label: the
button keeps one key with the status folded in (section 4.4).

### 4.2 `pr/prGlyph.ts` (the one table)

- `PrStatus`: `{ state: string; checksState?: string; reviewDecision?: string; mergeable?: string;
  autoMerge?: boolean }`. Both `adewire` `ChangeRequest` and `ChangeRequestDetail` satisfy it.
- `PR_STATE_GLYPH: Record<'open'|'draft'|'merged'|'closed', { icon; tone: Tone; label: MessageKey }>`
  and `prStateLabel(state)` (moved from `prState.ts`, same behaviour: unknown state shows raw).
- `CHECK_GLYPH: Record<CheckKey, { icon; tone: StatusTone; label: MessageKey; rollup?: MessageKey;
  dot?: 'ok'|'error'|'warn' }>` keyed lower case: `success`, `failure`, `error`, `pending`,
  `expected`, `skipped`, `neutral`. `checkKey(raw)` lowercases, unknown gives `null`. Per-check rows
  read `icon`/`tone`/`label`; the glyph reads `rollup`/`dot`. Pending tone becomes `warn` everywhere
  (one meaning; the host view check rows turn amber).
- `REVIEW_GLYPH: Record<ReviewKey, { icon; tone: StatusTone; label: MessageKey }>`: `approved`,
  `changesRequested`, `reviewRequired`, `rejected`, `commented`, `pending`. `reviewKey(raw)` maps
  `APPROVED`, `CHANGES_REQUESTED`, `REVIEW_REQUIRED` and passes the per-reviewer camelCase keys.
- `MERGEABLE_GLYPH: Record<'mergeable'|'conflicting', { tone; label }>`.
- `prGlyph(s: PrStatus): PrGlyphModel` with `{ state, icon, tone: Tone, checks: { key, dot, pending }
  | null, review, mergeable, autoMerge, lines: MessageKey[] }`, applying section 2.1. `lines` is the
  status part after the state line.
- Deleted: `CHECKS_GLYPH`, `PR_GLYPH` (`glyphs.ts:94-129`, drop the now unused `MessageKey`,
  `checkTone`, `TONE_TEXT` imports), `REVIEWER_ICON`, `REVIEWER_TONE`, `CHECK_ICON`, `reviewerLabel`,
  `checkLabel` (`HostViewSidebar.vue`), `CHECK_TONE`/`checkTone` (`statusTone.ts:46-57`, no callers
  left), `panel/prState.ts` (callers import `prStateLabel` from `pr/prGlyph`; `PR_TONE` gone).

### 4.3 `pr/PrGlyph.vue` (the one component)

`<script setup lang="ts">`, Tailwind only. Props: `status: PrStatus`, `variant: 'button' | 'tooltip'
| 'inline'`, optional `title`, `baseRef`, `ariaLabel`, `testid`. Emits `open` (button only).

- `button`: `TooltipIconButton` (`size="inline"`, `class="relative size-4.5"`, tone class), checks
  `StatusDot` in `#badge`, tooltip body as in 2.3. Branch row.
- `tooltip`: `span role="img"` with `CodiconIcon` plus dot inside `TextTooltip`-style `Tooltip`; aria
  label is the folded status. Task panel PR line (the title link beside it opens the PR).
- `inline`: glyph (`role="img"`, aria-hidden text duplicates avoided) followed by the visible lines
  in a `flex flex-wrap gap-x-2` row. Host sidebar and mobile, where hover tooltips do not work.
- Root data attributes for specs: `data-pr-state`, `data-tone`, `data-checks` (check key or absent),
  `data-review`, `data-mergeable`, `data-auto-merge`. `data-testid` from `testid`.
- No `defineComponent`, no Options API, no scoped style.
