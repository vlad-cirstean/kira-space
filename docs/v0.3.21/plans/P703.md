# P703 plan: Edit prompts only for another agent's notes; the watcher raises them, no `submit`

Row: `SPEC.md` `## P703`. An agent's task-file edit asks the user only when it touches content another
agent wrote. The file watcher raises that approval itself; the `submit` MCP tool, its `reason`
argument and every line that mentions it go. The finish flush stays.
Planner discovery: `codegraph_explore` over `submit` tool, `Decide`/`approvalCause`, `submitRun`,
`judge`, detail handlers' `Diff`, `SubmitFiles`, `SyncTaskFiles`, `taskwatch`, `addPending`/`putItem`;
index is the older checkout, so every hit was re-read in this worktree (line numbers below are the
worktree's).

## Reconciled rule table (one table replaces P643 matrix, P694 wording, P695 rules)

Author of the target a change touches, from the calling session's view:

- **none**: nothing written yet (create), or written by the user, Kira or an orchestrator pass
  (`source` `user`/`pass`, link `source=user`, proof link `source=user`), or a Jira/PR slot.
- **self**: agent-written with `session_id` (proof: `kira_session_id`) equal to the caller's key.
- **other agent**: agent-written (`source` `agent`/`run`/`orchestrator`/`child`, link or proof
  `source=agent`) with any other session id, including "" (legacy rows, child mirrors, proofs made
  before this phase).

Age: **latest** is P695's newest by creation, any author (`DetailsCache.LatestRel`,
`ProofCache.LatestSlug`); else **older**.

| Row | Who edited | Kind | Author | Age | Op | Outcome |
|-----|-----------|------|--------|-----|----|---------|
| R1 | user (UI, banner Accept, approval adopt) or Kira | any | any | any | any | apply |
| R2 | agent | `README.md`, `task.yaml`, `state.yaml` | Kira | n/a | any | restored (unchanged) |
| R3 | agent | draft of another step | any | n/a | any | rejected, file removed (unchanged) |
| R4 | agent | draft of current step | any | n/a | any | apply (unchanged) |
| R5 | agent | note, link entry, proof | none | n/a | create | apply (P695 asked on note create) |
| R6 | agent | note, handed handover, link entry, proof | self | any | edit, delete | apply |
| R7 | agent | note, handed handover, link entry | none (user, pass) | any | edit, delete | apply (P694/P695 asked unless latest) |
| R8 | agent | Jira/PR slot | none | n/a | set, replace, clear | apply (P643 asked on replace) |
| R9 | agent | note, handed handover, proof (any file of it) | other agent | latest | edit | apply (P695 Latest rule kept) |
| R10 | agent | note, handed handover | other agent | older | edit | approval: cause `note` / `handover` |
| R11 | agent | accepted proof (any file) | other agent | older | edit | approval: proof `proof.review` revision (cause `proof`) |
| R12 | agent | link entry | other agent | n/a | edit, delete | approval: cause `link` |
| R13 | agent | note, handed handover | other agent | any | delete | approval: cause `note` / `handover` |
| R14 | agent | accepted proof | other agent | any | delete | approval: cause `proofdelete` |
| R15 | agent | any content file | `accepted_by` another agent session after caller's last sync | any | edit | approval: cause `collision`. A user or Kira acceptance is no collision. |
| R16 | agent | as R9 to R15 | unknown agent (agent source, no session id) | as row | as row | treated as other agent |

Who saved, and when the rules run:

| Row | Situation | What happens |
|-----|-----------|--------------|
| W1 | One live Space grant on the task, save seen by the watcher | `SyncTaskFiles` pass as that agent runs R1 to R16. A pending change raises the `details.edit` item at once; nothing is told to the agent (it sees it in `state.yaml` `pending`, kind `details.edit`). Parse errors still go to `fileErrors`. |
| W2 | No live grant (user saves in an outside editor, no agent running) | No watcher exists, so no pass and never an approval. The disk banner shows the change; Accept adopts as the user (R1), Discard restores. |
| W3 | Several live grants | No pass (a save cannot be attributed), board push only; banner shows it. The next finish flush of either agent applies it as that agent (R1 to R16). |
| W4 | Finish flush (`state` `step.finish`, `finish_step` of a rebase run) | Same rules as W1; reply lists the pending lines ("`<rel>`: waiting for the user (another agent's note)."). |

Known limit (ARCHITECTURE "Known open items", new): under W1 a user's outside-editor save of another
agent's older content is attributed to the live agent and raises an approval; Deny restores the
file, losing that edit. The row shows the diff, so the user sees it is theirs. P695 deferred such
saves only because the agent then had to resend them with `submit`; with no tool there is no other
path for an agent edit.

## Approval explanation (decision)

None. No `reason:` line in files: notes and handovers are free Markdown, and a parsed header line
would leak into bodies, mirrors and child copies, and drafts would need a format rule. The row
explains itself by: cause label (reworded to name the other agent's content), the unified diff
(`text`), the collision line, and `origin.source` (editing agent's role). Payload drops `reason`
(item and top level); `detailsPending.reason` goes. Pending items live in memory only, so no legacy
data needs the field. Proof revisions keep the `proof_revisions.reason` column and its display:
older revisions hold real reasons; new file edits write "". `ProofEdit.Reason` is removed and
`Propose` writes ''.
