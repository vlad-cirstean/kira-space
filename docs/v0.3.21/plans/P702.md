# P702 plan: Agents remove worktrees; no prompt for worktree create or delete

Row: `SPEC.md` `## P702`. Agents get a Kira MCP action that removes a task worktree through the UI's
code path. Creating or deleting a worktree shows no approval prompt or confirm dialog, whoever starts
it. Real safety stays as server refusals plus one explicit, label-named discard action for the user.
Planner discovery: `codegraph_explore` over agentmcp state actions, `SpaceTools`, branch request
engine, `RemoveTaskBranch`/`detachRow`/`removeWorktree`, worktree remove preflight, git-ui
`WorktreeList`; every hit re-read in this worktree.

## Safety rule (stated once; ARCHITECTURE copies it)

Kira never deletes a worktree that holds uncommitted work (anything the preflight counts as dirty:
staged, unstaged, untracked) unless the user takes an explicit discard action whose label names the
loss. Those actions are exactly:

1. Task tab row menu: `Discard {count} changes and remove branch` / `... and remove repo`.
2. Change branch form: inline `Discard {count} changes and change` button after the inline refusal.
3. Git module worktree row: inline `Discard changes and remove` button after the inline refusal.
4. Archive task confirm (unchanged, task-level).

The server re-reads dirty state at apply time. The client flag (`discardChanges`, `confirmToken`)
only permits a discard; it never forces one, and a worktree that turned dirty after the client read
it is refused. Agents never discard: `worktree.remove` has no discard argument and fails on a dirty
worktree.

Other checks, all refusals (error text, no dialog):

- Main checkout: never removed (`mainWorktree` blocker; agent action refuses a row whose branch sits
  in the repo checkout or nowhere, so it never detaches a row without removing a Kira folder).
- In use: prepare script, open TUI session of **any** task with cwd in the worktree (tightened: drop
  the `s.TaskID == taskID` condition in `editableRow`'s cwd match), a TUI bound to the row, pending
  session start, running run, rebase, script claim, live sandbox (`rowBusyRefusal`), archiving,
  `locked`, `openInAnotherWindow`, `currentWorktree`.
- Calling agent's own working directory (agent only): refused with its own text before the generic
  checks.
- Unpushed or unmerged commits: **not** a block. Worktree removal keeps the git branch; commits stay
  on it. The old unmerged confirm goes. The agent reply says the branch stays.

## Part A: agent create without approval

  hold.

## Part B: `state` action `worktree.remove`

Shape (decision 2): a `state` action, not a new tool, so the schema cost stays inside
`TestToolSchemaBudget` and it matches rename/change. Space grants only (`spaceOnly`), so runs,
sessions, orchestrators and sandboxed Space runs list it; review grants do not.

- `internal/agentmcp/state.go`: `stateActions` row after `branch.change`:
  `{"worktree.remove", []stateField{{"repo", true, kindString}, {"branch", true, kindString}},
  `"repo": "app", "branch": "feature/x"`, llmprompts.HeadlessStateWorktreeRemove, spaceOnly}`.
  `runState` case calls `stateWorktreeRemove`: blank repo or branch is an `invalid` item; engine
  error goes through `stateFail`; result maps to one item, id `<repo>/<branch>`, status `done` or
  `failed` (no `pending`: nothing waits), message from the result, `next` empty.
- `internal/agentmcp/space.go`, appended at the end of the file and of `SpaceTools` (after
  `CancelOperation`, away from P703's `Submit` lines): `RemoveWorktreeArgs{Repo, Branch}`,
  `RemoveWorktreeResult{Repo, Branch, Outcome, Worktree, Next}`, const `BranchRemoved = "removed"`
  (failed reuses `BranchFailed`), interface method `RemoveWorktree(ctx, call SpaceCall, args
  RemoveWorktreeArgs) (RemoveWorktreeResult, error)`. Update the `SpaceTools` doc line that lists
  blocking methods only if needed (this one does not block).
- `internal/llmprompts/registry.go`: `HeadlessStateWorktreeRemove = defineStateAction(
  "worktree.remove", `worktree.remove: args {repo, branch}: remove your branch's worktree; the branch
  stays in git. Refused while it has uncommitted changes or anything works in it.`)`.

Engine, new file `apps/kira-space/internal/ade/worktreeremove.go`:

1. `taskMu` lock. `spaceCtx`, `spaceWritable`. Resolve repo with `resolveRepoRef(args.Repo,
   b.taskCandidates(tc, cfgs), "task")` and the row with `taskRepoRows` (as `renameTarget`). Missing:
   `ToolError("Branch %q is not on this task in that repo.")`. Kind not `mine`: failed "not yours to
   remove".
2. `linkedBranchOf`: not linked: failed `Branch %s has no Kira worktree (it is checked out in the repo
   checkout or nowhere); nothing to remove.`
3. Own working directory: new helper `callerCwd(call)`: session row `Cwd` for `SessionID`, else the
   run's worktree path for `RunID` (read the run row's path field the launch stored). Equal after
   `filepath.Clean` to the linked path: failed `This is your working directory; you cannot remove it.`
4. `rowBusyRefusal(ctx, sb, "removing it waits")`, then `editableRow(ctx, taskID, sb.ID)`: either
   refusal becomes a failed item with its text (convert `invalid` errors with `toolMessage`).
5. `branchRisk`: `Blocked` != "": failed with the human blocker text (step 7); dirty: failed
   `Worktree %s has %d uncommitted changes (%s). Commit them first, or ask the user; only the user can
   discard them.` (first 3 paths, then a count).
6. `op := b.startAgentOp(ctx, opAgentWorktreeRemove, taskID, nick+"/"+branch)`; call the shared
   `removeRowBranch(ctx, tc, sb, false)` (below); finish op ok or error; `notifyBoard`. Done reply:
   `Removed worktree %s. Branch %s stays in git; check it out again with branch.request existing: true.`
7. Blocker text: export from gitsession `WorktreeRemoveBlockedMessage(pf)` (the strings
   `worktreeRemoveBlockedError` already holds) and use it here and in `detachRow`, which today puts
   the raw kind into its error.

Shared path (same code as the UI, `ade/taskbranches.go`):

## Decisions for the user (plan picks the first option)

1. `adopt` (taking a branch from another worktree or the main checkout) keeps its approval; only pure
   creates (new branch, named-row worktree, free existing branch) skip it. Rename and change keep
   theirs (alternative: adopt applies at once too).
2. Agent removal is a `state` action `worktree.remove {repo, branch}` that takes the branch off the
   task like the UI's Remove branch; the git branch stays (alternative: a separate MCP tool, or
   remove the folder and keep the row, which `ensureWorktree` would recreate on next launch).
3. Unmerged or unpushed commits never block or confirm removal: the branch survives.
4. Explicit discard is a label-named action (menu item, inline button), no dialog and no typed token
   (alternative: keep the git-ui typed token inline).
5. Archive keeps its confirm and risk dialog: it is the task's action, not a worktree delete.
6. Agents can never discard uncommitted work.
7. Wire fields `requiresTypedConfirmation` and `confirmToken` keep their names.
