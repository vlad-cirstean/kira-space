## Options weighed

**(a) Re-pin to another GitHub release asset (for example 1.32.0).** Hashes not obtainable here: no
download reaches GitHub assets from this sandbox. It needs a CI or user step to compute hashes, and it
keeps the same failure mode: release assets are mutable and deletable, which is what just broke the
release. 1.32.0 also changes the shipped runtime for no functional gain and touches 8 version
mentions. Rejected.

**(b) Self-host the archive** (own GitHub release asset or LFS). Needs: a pinned release excluded from
`release-retention.yml`'s pruning (it deletes own releases whole), a manual upload step nobody can do
from this sandbox, MIT compliance (ship `LICENSE` and `ThirdPartyNotices.txt` beside it: easy), and
it puts us in charge of a 30-160 MB binary's provenance. Keep as fallback only if nuget.org ever
fails. Rejected now.

**(c) NuGet source, same version (chosen).**
- nuget.org does not allow deleting or overwriting a published version's content (only unlisting,
  which keeps the flat-container URL working). The failure that broke v0.3.16 cannot recur there.
- Same version: `ORT_API_VERSION 31` is met exactly, `ORTVersion`, S12 and every dylib file name stay
  as is. Zero Go or Taskfile change.
- Hash computed from a real download and cross-checked against the registry's own SHA-512.
- Licence: MIT `LICENSE` and `ThirdPartyNotices.txt` ship in the package, copied into the bundle as
  today.
- Cost: package is 160 MB (all platforms in one) versus a per-platform tgz. Release job downloads it
  once per build from NuGet's CDN; seconds on a GitHub runner. Local idempotence (stamp) unchanged.
- npm `onnxruntime-node` 1.31.1 also has the dylib, but it is 308 MB unpacked and its postinstall
  downloads more: worse on every axis.

### Package-integrity rationale

Source changes from `github.com/microsoft/onnxruntime` releases to `api.nuget.org`
`Microsoft.ML.OnnxRuntime`, the same publisher's official distribution of the same tag. Checksum
changes from two per-platform tgz SHA-256s to one nupkg SHA-256, because one archive now serves both
platforms. The pin still verifies the whole downloaded archive before extraction, so integrity is
no weaker: a swapped or truncated package fails the check before any byte reaches the bundle. The
SPEC's "both SHA256s" becomes one archive SHA-256 by this design; per-platform library hashes are
recorded above as facts, not pinned (the archive hash already covers them).

```sh
ORT_VERSION="1.31.1"
# Microsoft.ML.OnnxRuntime from nuget.org: one package holds every platform's library, and nuget.org
# never replaces a published version (P673: the GitHub release tgz returned 404).
ARCHIVE_SHA256="6871ccbc97f3d5bdb4095a1dcec33aa78d56f6ed8de5980ef5fa1d9f2e7c679a"
PLATFORM="${1:-osx-arm64}"

case "$PLATFORM" in
  osx-arm64)
    SRC="runtimes/osx-arm64/native/libonnxruntime.dylib"
    LIB="libonnxruntime.$ORT_VERSION.dylib"
    ;;
  linux-x64)
    SRC="runtimes/linux-x64/native/libonnxruntime.so"
    LIB="libonnxruntime.so.$ORT_VERSION"
    ;;
  *)
    echo "fetch-onnxruntime: unknown platform '$PLATFORM' (want osx-arm64 or linux-x64)" >&2
    exit 1
    ;;
esac
```

local copies refetch once. `require_cmd unzip "install unzip"` after the curl one.

Replace lines 53-65 with:

```sh
URL="https://api.nuget.org/v3-flatcontainer/microsoft.ml.onnxruntime/$ORT_VERSION/microsoft.ml.onnxruntime.$ORT_VERSION.nupkg"
PKG="$TMP/onnxruntime.nupkg"
if ! curl -fsSL -o "$PKG" "$URL"; then
  echo "fetch-onnxruntime: download failed: $URL" >&2
  exit 1
fi
GOT="$(hash_file "$PKG")"
if [ "$GOT" != "$ARCHIVE_SHA256" ]; then
  echo "fetch-onnxruntime: checksum mismatch for $URL: got $GOT, want $ARCHIVE_SHA256" >&2
  exit 1
fi

unzip -q "$PKG" "$SRC" LICENSE ThirdPartyNotices.txt -d "$TMP/x"
rm -rf "$DEST"
mkdir -p "$DEST"
cp "$TMP/x/$SRC" "$DEST/$LIB"
cp "$TMP/x/LICENSE" "$TMP/x/ThirdPartyNotices.txt" "$DEST/"
printf '%s' "$ARCHIVE_SHA256" >"$STAMP"
echo "$DEST/$LIB"
```
