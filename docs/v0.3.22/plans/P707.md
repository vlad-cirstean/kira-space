# P707: Installer without GitHub API rate limit

Spec row: `docs/v0.3.22/SPEC.md` P707. Base: `ffa8d2f92`. Stream: independent of P708, P709.

## Goal

`scripts/install.sh` (first install and self-update) and the in-app checker resolve release, tag,
size and sha256 with no `api.github.com` call on every normal path. Every guarantee stays: sha256
check, draft/prerelease exclusion, `--tag`, minor stepping (`internal/releaseline` NextStep),
S16. The API stays only in one transitional fallback (latest release predates the index), and a
403/429 there dies with an error naming the rate limit. The v0.3.20 smoke sleep/retry goes.

## Findings (current tree)

- `install.sh` reads from release JSON (`parse-release.js`): `tag_name`, `draft`, `prerelease`,
  asset `browser_download_url`, `size`, `digest`. Endpoints: `releases/latest`,
  `releases/tags/<tag>`, `releases?per_page=100&page=N` (stepping, self-update without `--tag`,
  apps up to 0.3.14). Stepping runs a JXA `nextStep` twin; S16 (`scripts/check-install-step.ts`)
  replays `internal/releaseline/testdata/next_step.json` through it.
- Only the API carries the sha256 today: GitHub's server-computed asset `digest`. No checksum
  asset exists; release notes are static text. All 11 live releases (v0.3.3 to v0.3.21) are
  plain, published, with `digest` (checked v0.3.21 via API read).
- `internal/appupdate/checker.go` `listReleases`/`fetchPage` poll `api.github.com/.../releases`
  unauthenticated (6 h cache). Same rate-limit wall on shared IPs. `internal/updates` does not
  exist. `install.go` fetches the script from `raw.githubusercontent.com` (not API; unchanged).
- `release.yml` publish verifies exactly one asset (`length == 1`); install-smoke has the
  `sleep 5` plus 3-attempt `install()` loop.
- Retention (`scripts/releaseretention`) keeps each line's `.0`, first, last, 5 newest of current
  line, and latest. NextStep only ever targets first or last of a line.

## Design decisions

1. **Release index asset, served from the latest release.** Each non-prerelease publish uploads
   `kira-space-releases.txt` to its release. Installer and checker fetch
   `https://github.com/vlad-cirstean/kira-space/releases/latest/download/kira-space-releases.txt`
   (web redirect to the asset CDN, not the REST API, no 60/h limit). Disk image comes from
   `https://github.com/vlad-cirstean/kira-space/releases/download/<tag>/kira-space-macos-arm64.dmg`.
   Reason: one file gives tag list, sizes and digests for every eligible release, including old
   ones without any per-release checksum asset. A per-release `.sha256` asset was rejected: old
   releases lack it, and stepping still needs a list.
2. **Format** (text, parseable by POSIX sh/awk, no JSON, no JXA on the normal path):
   ```
   # kira-release-index 1
   v0.3.3 kira-space-macos-arm64.dmg 43912345 sha256:<64 lowercase hex>
   ```
   One line per eligible release, ascending semver, fields separated by one space. Readers never
   trust order (compute max themselves) and reject the whole file on any malformed line,
   duplicate tag, missing/other header, or over 1 MiB. Fail closed.
3. **Index holds eligible releases only**, built by Go from `releaseline.Eligible` plus a sha256
   digest requirement. Draft/prerelease exclusion therefore moves into the index: `--tag` of a
   tag not in the index dies ("not a published release"). Served only from GitHub's latest
   release, which is never a draft or prerelease. Generator fails (release fails) if an eligible
   release lacks a `sha256:` digest, instead of silently dropping it.
4. **Digests come from GitHub's own asset `digest`** (server-computed) via authenticated
   `gh api` in the publish job, plus the existing local sha256 cross-check. Trust equals today's:
   anyone able to rewrite the index can rewrite the API digest too (repo write). Ad-hoc codesign
   stays corruption-only.
5. **Rejected sources**: `releases.atom` (about 10 entries, no prerelease flag, no digest, XML);
   git tags (tags outlive retention-deleted releases; `/usr/bin/git` is a CLT stub on clean Macs);
   `releases/latest` 302 alone (tag but no digest); scraping `releases/expanded_assets` HTML
   (fragile). Index makes the 302 unnecessary: newest tag is the index max.
6. **Interactive install takes the index max** (equals checker's `Newest`). Self-update without
   `--tag` steps with an awk `next_step` over the index; unknown/empty current version or no step
   falls back to index max, as today.
7. **Transitional API fallback, only on index HTTP 404.** Between the PR merge (main's script
   changes) and v0.3.22 publish, and if that release fails, latest (v0.3.21) has no index. Then the
   script lists `api.github.com/.../releases` (paged, max 10, no `--retry`), converts the JSON to
   index text with one JXA function `apiToIndex` (same rules as Go `FormatIndex`), and continues
   on the same index path. HTTP 429, or 403 (any; say `x-ratelimit-remaining: 0` when the header
   shows it) dies with: `GitHub API rate limit reached for this network (HTTP <code>, unauthenticated).
   The latest release predates the release index; try again in an hour.` It logs
   `release index not found on the latest release; using the GitHub API` (smoke greps for it).
   Any other index failure (5xx, network) dies without touching the API. Data lives nowhere else
   for releases up to v0.3.21, which is the spec's allowed case. Drop the fallback, its JXA and its
   parity check at the v0.4 minor bump (CLAUDE.md "Minor bumps drop legacy code"); PACKAGING.md says
   so. Backfilling the index onto v0.3.21 by hand was rejected: manual production write, window
   reopens if forgotten.
8. **Checker moves to the index too** (`internal/appupdate`). Same data as the installer, so the
   app never offers a target the installer rejects, and shared-IP users get update checks. No
   fallback: a v0.3.22+ app only runs once v0.3.22 (with index) is latest. 429, or 403 with
   `X-RateLimit-Remaining: 0`, still map to `errRateLimited`.
9. **Test seam in `install.sh`**: helpers move to top-level functions reading globals `GH_WEB`,
   `GH_API`, `CURL_PROTO` that only `main` sets (hard-coded https URLs, `=https`); last line
   becomes `[ "${KIRA_INSTALL_SOURCE_ONLY:-}" = 1 ] || main "$@"`. Tests source the script and set
   the globals to a local fake. No env var changes a real run's URLs. Contract marker stays `2`
   (flags and fd-3 handshake unchanged).
10. **curl flags**: github.com fetches keep `--retry 3 --retry-delay 2` (transient network; not the
    rate-limit fix) and add `--proto-redir "$CURL_PROTO"`; index fetch adds
    `--max-filesize 1048576`. API fallback drops `--retry` (curl retries 429). Status read with
    `-w '%{http_code}'`, headers via `-D`, so 404/403/429 branch cleanly.
11. **No new dependency.** Go stdlib + existing `x/mod/semver`; bun, curl, awk, shasum already
    used. License rule satisfied by construction.

## Work items (in order, one commit per group)

### 1. `internal/releaseline`: index format (commit `feat: release index format in releaseline`)

- `releaseline.go`: `Asset` gains `Digest string \`json:"digest"\``. Package doc names the index.
- New `index.go`:
  - `const IndexHeader = "# kira-release-index 1"`.
  - `DecodeReleases(data []byte) ([]Release, error)`: moved verbatim from
    `scripts/releaseretention/main.go` `parseReleases` (handles `gh api --paginate --slurp`).
  - `FormatIndex(rels []Release, asset, publish string) (string, error)`: candidates are
    `Version`-valid tags with `Eligible(r, asset)`, or `r.Tag == publish && r.Draft &&
    !r.Prerelease && HasAsset(r, asset)` (the draft being published). Asset digest must match
    `^sha256:[0-9a-f]{64}$` else error naming tag. Error on duplicate tag, on `publish != ""` not
    found, on zero entries. Sort by `semver.Compare`. Output header plus lines, trailing newline.
  - `ParseIndex(r io.Reader) ([]Release, error)`: strict inverse; reads at most 1 MiB (error past
    it); returns `Release{Tag, Assets: []Asset{{Name, State: "uploaded", Size, Digest}}}`. Rejects
    bad header, wrong field count, non-plain tag, size not `[1-9][0-9]*`, bad digest, duplicates.
- `scripts/releaseretention/main.go`: call `releaseline.DecodeReleases`, delete `parseReleases`.
- Tests (`index_test.go`): parser with several interacting rules, earns a unit test.
  - Table: `FormatIndex` filters draft, prerelease, missing/empty asset, non-plain tag; includes
    `publish` draft; errors on missing digest, duplicate, unknown publish, empty.
  - Table: `ParseIndex` rejections (one row per rule) and round trip.
  - Golden: `TestIndexGolden` runs every `testdata/next_step.json` case through `FormatIndex`
    (helper sets each asset's digest to `sha256:` plus 64 `0`), asserts `ParseIndex` then
    `NextStep` gives the case target, and compares against
    `testdata/next_step_index.json` (`[{name, current, index, target}]`); `-update` rewrites it.
    Both Go and S16 read this golden.

### 4. `install.sh` on the index (commit `feat: installer resolves releases without the GitHub API`)

  - `index_next_step FILE CURRENT`: awk twin of `NextStep`; current parsed like JXA `nextStep`

    tag or nothing.
  - `fetch_index`: GET `$GH_WEB/releases/latest/download/$INDEX_ASSET` to `$WORK/index.txt`.
    200: `index_check` or die `release index is malformed`. 404: `fetch_api_index`. Else die

## What only a real release run proves

- `releases/latest/download/kira-space-releases.txt` and `releases/download/<tag>/<asset>`
  answer from a shared macOS runner IP with no 403/429, immediately after publish (latest redirect
  not cached stale). Smoke steps 1 to 4.
- Publish job: `gh api` lists the draft with its digest, generator output uploads, both assets
  verify, publish makes the index visible as latest.
- macOS system curl honours `--proto-redir`/`--max-filesize` across the CDN redirect; BWK awk
  runs the index functions (also covered by S16/S17 in the release build's `verify:packaging`).
- Self-update stepping against real releases (smoke step 3); in-app checker against the real
  index (§4 manual check after v0.3.22 ships).
- Not proven anywhere live: API fallback success against real GitHub (only S17 case 12 on macOS
  against the fake); it only runs in the merge-to-publish window.

## Risks

- Merge-to-publish window and a failed v0.3.22 release use the API fallback; rate limit still
  possible there, now with a clear error.
- Index snapshot staleness: retention-deleted intermediates stay listed until next publish;
  `--tag` of one dies with the 404 message. Step targets are never deleted.
- A manual draft/prerelease flip after publish is not reflected until next publish (documented).
- GitHub serving a stale `latest` redirect right after publish would fail smoke step 1; then
  report it rather than add a wait.
- awk portability (BWK vs mawk/gawk): S16/S17 run on Linux in PR CI and on macOS in the release
  build.
- Contract marker unchanged: older apps (0.3.15 to 0.3.21 pass `--tag`, up to 0.3.14 do not) keep
  driving the new script; their own in-app checkers keep using the API until they update (out of
  reach).
