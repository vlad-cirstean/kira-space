## Root cause

CLI 2.1.330 shows a per-directory trust dialog at TUI start for every `--add-dir` path not covered
by a trusted `projects[...]` entry in `.claude.json`. Kira's TUI launches pass the task folder
(`withTaskFolderArgs`, `ade/taskfolder.go`, every manual, ad hoc, resume and review session since
v0.3.14) as `--add-dir`. Multi-repo worktrees (`launchDirs`) and sandbox grants (`applyTUISandbox`)
also go as `--add-dir`. The dialog blocks the TUI before SessionStart. The tests seed trust only for
the repo and cwd, so they wait 60 s and fail.

Real users get the same dialog on every ADE session: the answer "holds for this session" only. Kira
injects the first message only after SessionStart, so nothing reaches the TUI until the user picks
"Yes, add it". Answering with Enter picks the default, "No, exit", and kills the session. This is a
product bug, so seeding more trust in the tests is not the fix. Writing trust into the user's
`~/.claude.json` is not the fix either: Kira never edits user CLI config (`TestRealClaudeSettingsUntouched`).

Unknown, not checkable here: whether 2.1.316 (last recorded green CLI) already had the dialog, or
the v0.3.14 task-folder `--add-dir` first exposed it. No older CLI is installed, and installing one
is out of scope. The fix holds either way.

## Fix design

A claude TUI launch passes its extra dirs as `permissions.additionalDirectories` in its single
`--settings` source, never as `--add-dir`. The CLI honours only the last `--settings` flag
(`hermetic.go` comment), and the claude hook listener already owns that flag on every launch: it
merges into the app settings file (`ComposeInto`), else appends its own `--settings`. The dirs
therefore travel to the listener, which writes them into the one file. Headless keeps `--add-dir`.
OpenCode is untouched: its interactive builder maps `AddDirs` to its own permission config.

No listener running (hooks failed to start, e.g. curl missing): the dirs are not granted. The TUI
then asks the user per access outside cwd. That is degraded but working, and better than a dialog
that exits on Enter. Log one `slog.Warn` in that case. Do not fall back to `--add-dir`: it brings the
blocking dialog back.

## Risks

- Sandboxed TUI (`sandboxTUI` with bwrap or seatbelt): the per-terminal settings file sits in the
  listener's `ln.Dir`, next to `hooks.json`, which sandboxed launches already read via `--settings`.
  The ADE sandbox rows confirm it. If the profile lists files rather than the dir, add the new file.
- The grant moves from argv to a file. `oplog` `SetCommand` and UI fixtures that show the command
  (`tests/fixtures/ade-v2/review-agent-launch.json`, a static mock) no longer show `--add-dir`.
  The fixture is cosmetic; leave it.
- Future CLI change to `additionalDirectories` semantics (e.g. it starts prompting too). The real
  rows catch it; the ARCHITECTURE entry names the version.
- Signature widening touches four flow-test helpers. The change is mechanical; `go vet` catches
  misses.
- No-listener degradation: no dirs granted, so the agent asks the user per read outside cwd. This is
  accepted and logged (see Fix design).
