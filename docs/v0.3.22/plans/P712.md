# P712: show every shortcut (button tooltips, context menus, menu bar)

## 1. Goal

User ask: "Make sure the shortcut is shown. In tooltip for buttons, on the right for context menu or
menu bar." Every control that runs the same action as a registry chord shows that chord. Buttons:
tooltip. Context-menu items: right-aligned. Menu bar: right-aligned. One source: `SHORTCUTS`
(`packages/shared/domain/shortcuts.ts`), formatted per platform. No rebinding; none added.

Base: `stream/p712` at `afd940012` (P707-P711 landed). CodeGraph index is v0.3.17; every ref below
was re-read in the worktree. Re-read each file before editing.

## 2. Facts the design rests on

- Formatter: `formatShortcut(id)` in `packages/workbench/src/shortcuts/keys.ts:41`. UA sniff
  `isMac` (`:6`); mac glyph order ⌃⌥⇧⌘, mac override `binding.mac` (`resolveChord`, `:18`); other
  platforms `Ctrl+Shift+Alt+Key`, `KEY_DISPLAY` (`:31`). Playwright WebKit reports a Mac UA on every
  host (`tests/ui/studio/support/chord.ts:3-4`).
- Today a hint is a caller-formatted string: `kbd?: string` on `TooltipIconButton.vue:40`,
  `TextTooltip.vue:15`, `Button.vue:18` (inline chip); 28 callers pass `formatShortcut('<id>')`.
  Nothing forces a hint to come from the registry and nothing forces a bound chord to have one.
- Context menus: every app menu renders through `packages/workbench/src/components/MenuItems.vue`
  (no other `DropdownMenuItem` user outside `components/ui`). `MenuItem.shortcut?: ShortcutId`
  (`state/contextMenu.ts:53`) renders `DropdownMenuShortcut` (`ml-auto pl-4`, right-aligned) with
  testid `${tid}-shortcut` (`MenuItems.vue:203-205`). Only `type: 'item'` carries `shortcut`.
- Menu bar: native only. No in-app menu bar exists (grep `MenuBar|menubar` finds none). Go builds
  it (`apps/kira-space/internal/appshell/menu.go:18-79`, `internal/shell/menu.go:132-138`); every
  `shell.Shortcuts` id (`internal/shell/accel.go:39-60`) is an item `Accelerator`. macOS (the only
  target, ARCHITECTURE `:31`) draws accelerators right-aligned natively; Linux GTK also does.
  Menu bar needs no rendering work, only a guard that no global id loses its menu item.
- N11 (`scripts/check-conventions.ts:391-417`) checks the reverse: a printed menu shortcut is bound.
  No guard checks "bound chord is printed".
- ARCHITECTURE `:1230`: icon tooltip and aria-label share one catalog key, no shortcut text in copy.
  Catalog holds no chord text today (checked: no value contains ⌘/⇧/⌥/⏎ or `Cmd+`).
- Module actions: `MODULE_ACTIONS` (`apps/kira-space/frontend/src/shortcuts/moduleActions.ts:28-51`)
  lives in the app; automations' "+" menu (`packages/workbench/src/automations/panelMenus.ts:51-68`)
  is in a package that cannot import the app.

## 3. Design

### 3.1 Formatter moves to theme

`packages/theme` already imports `@shared/domain/shortcuts` (`DialogContent.vue:2`); workbench
depends on theme, never the reverse. New `packages/theme/src/shortcutText.ts`:

- `IS_MAC` (UA sniff, moved from `keys.ts:6`, keep its comment), `resolveChord(id)`,
  `formatShortcut(id)` (moved verbatim with `MAC_KEY_GLYPH`, `KEY_DISPLAY`), and
  `ariaKeyShortcuts(id)`: WAI-ARIA form (`Meta+N`, `Control+Shift+P`, `Alt+F8`, `Meta+Backspace`).
- `keys.ts` imports `IS_MAC`, `resolveChord` from it and drops its own copies; `formatShortcut` is no
  longer exported from `keys.ts`. Update the remaining direct callers (`MenuItems.vue`,
  `treeShortcuts.ts`) to the theme import. No re-export shim.

### 3.2 One display primitive, `shortcut` prop replaces `kbd`

- New `packages/theme/src/components/ShortcutKbd.vue`: props `{ id: ShortcutId }`; renders
  `<Kbd :data-shortcut="id">{{ formatShortcut(id) }}</Kbd>`. The single place a chord chip renders.
- `TooltipIconButton.vue`: `kbd?: string` becomes `shortcut?: ShortcutId`; tooltip body
  `<slot>{{ label }}</slot><ShortcutKbd v-if="shortcut" :id="shortcut" />`; button gets
  `:aria-keyshortcuts="shortcut && ariaKeyShortcuts(shortcut)"` (both branches, `:75-100`).
- `TextTooltip.vue`: `kbd` becomes `shortcut?: ShortcutId`. Renders the tooltip when `text`,
  `parts` or `shortcut` is set (a shortcut alone shows a key-only tooltip, e.g. a disabled-reason
  tooltip whose reason is empty). Passes `aria-keyshortcuts` on `TooltipTrigger` (as-child merges it
  onto the child).
- `Button.vue`: `kbd` becomes `shortcut?: ShortcutId` (inline chip via `ShortcutKbd`, plus
  `aria-keyshortcuts`). Kept only for dialog footers, see 3.4.
- `SearchField.vue`: new `shortcut?: ShortcutId`; while the field is empty, an `inline-end`
  `InputGroupAddon` shows `ShortcutKbd`; `aria-keyshortcuts` on the input. Field hint, not a
  tooltip: a tooltip would pop open when the chord itself focuses the field.
- `MenuItems.vue:203`: keep `DropdownMenuShortcut` (plain right-aligned text, macOS menu style, not a
  chip); add `:data-shortcut="item.shortcut"`; import `formatShortcut` from theme.
- `DialogHeader.vue:30-53`: the X gets a tooltip `common.action.close.label` + `ShortcutKbd`:
  `prompt.hide` (⇧⎋) inside a prompt `DialogContent`, else `form.cancel` (⎋). Both X and Esc call
  `requestClose` (`DialogContent.vue:92-128`), so the action is identical. `DialogContent` provides a
  `DIALOG_PROMPT_KEY` boolean next to `DIALOG_REQUEST_CLOSE_KEY`; the plain `DialogClose` branch
  (no `DialogContent`) shows `form.cancel`. Footer Cancel buttons get nothing: they are a plain
  `DialogClose` without the dirty guard, not the same action as Esc.
- `SaveBar.vue`: new required prop `shortcut: ShortcutId`; Save button wrapped in `TextTooltip
  :shortcut`. All 6 callers bind `form.save` and pass `shortcut="form.save"` (explicit, so the
  guard in 3.6 sees it in the binding file).
- Removing `kbd?: string` everywhere makes typecheck reject any free-form hint string. All 28
  `:kbd="formatShortcut('<id>')"` sites become `shortcut="<id>"` (conditional ones keep their
  condition: `:shortcut="routed ? 'form.submit' : undefined"`).
- `CaptureWindow.vue:148` and `ScriptBodyField.vue:76,81` (`<Kbd>{{ formatShortcut(...) }}</Kbd>`
  inside copy slots) become `<ShortcutKbd id=... />`. `ScriptBodyField.vue:25-26` names
  `view.run` but its dialog (`RunFileDialog.vue:235`) binds `form.submit`: same chord, switch to the
  id that is bound. `DiscoverSavedControls.vue:157` and `RefreshButton.vue:36` drop their consts.

Frontend rules: Tailwind classes only, shadcn-vue `Tooltip`/`Kbd`/`InputGroup`, Composition API,
no store (display is pure). Declined: a new `ShortcutTooltip` wrapper component. Extending the two
existing tooltip components is the ask's "extend the existing mechanism" and avoids a third tooltip
shape next to `TextTooltip` and `TooltipIconButton`.

### 3.3 Module actions: hint follows `MODULE_ACTIONS`

New `packages/shared/domain/moduleShortcuts.ts` (data only, importable by packages):

```ts
export type ModuleAction = Extract<ShortcutId, 'app.new' | 'app.newAlternate' | 'app.import' | 'api.environments'>;
export const MODULE_SHORTCUTS = {
  studio: ['app.new', 'app.import'],
  api: ['app.new', 'app.newAlternate', 'app.import', 'api.environments'],
  automations: ['app.new', 'app.newAlternate'],
  ade: ['app.new'],
  git: ['app.new'],
} as const satisfies Partial<Record<AppMode, readonly ModuleAction[]>>;
type Mapped = keyof typeof MODULE_SHORTCUTS;
export function moduleShortcut<M extends Mapped, A extends (typeof MODULE_SHORTCUTS)[M][number]>(
  _mode: M, action: A): A { return action; }
```

- `moduleActions.ts`: `ModuleAction` moves here (re-imported). `MODULE_ACTIONS` typed
  `{ [M in Mapped]: Record<(typeof MODULE_SHORTCUTS)[M][number], () => void> }`: a handler missing
  from, or extra to, the table is a type error. `runModuleAction` unchanged.
- A control the chord triggers passes `:shortcut="moduleShortcut('studio', 'app.new')"`. Naming an
  unmapped pair is a type error, so a hint can never claim a chord its module does not dispatch.

### 3.4 Where each form applies

- Icon button: `TooltipIconButton shortcut`.
- Text button with a tooltip already: add `shortcut` to its `TextTooltip`.
- Text button without one: wrap in `TextTooltip :text="<its own label key>" :shortcut`.
- Dialog footer commit button: inline `Button shortcut`, the established form (UpdateDialog,
  ScheduleConfirmDialog, GitCredentialDialog, PairingRequestDialog, ApprovalItemActions,
  MaskingReviewPrompt, ProofReadyPrompt, AdeStageDialog all show it inline today). See §11 Q1.
- Field: `SearchField shortcut`.
- Menu item: `shortcut: '<id>'`.
- Print rule: a control or item shows a chord only when the chord runs the same handler with the
  same target. Precedent kept: `tab.close` printed on the tab menu though it closes the active tab
  (`TabStrip.vue:77-79`); same for the workflow step menu Remove (row 52).

### 3.6 Guard N19 (`scripts/check-conventions.ts`)

Two halves, both in `check-conventions.ts` with tests in `check-conventions.spec.ts` (extend, no new
mechanism; header comment lists N19):

1. Registry coverage: every `SHORTCUTS` id has at least one display site in non-spec sources under
   `packages/*/src`, `apps/kira-space/frontend/src`, or the Go menus. Display site regexes:
   `shortcut: '<id>'`, `shortcut="<id>"`, `:shortcut="'<id>'"` (also inside a ternary),
   `moduleShortcut('<mode>', '<id>')`, `<ShortcutKbd id="<id>"`, and Go
   `Shortcuts["<id>"].Accelerator()` in `internal/shell/menu.go` / `apps/kira-space/internal/appshell/menu.go`.
   Else the id must be in `SHORTCUT_NO_CONTROL` (map id to reason string). A new registry id with no
   hint fails lint.
2. Bound means shown: each non-spec `.ts`/`.vue` file calling `useShortcut(`, `shortcutKeydown(`
   or `registerCommand(` with a literal registry id (non-global scope, not in `SHORTCUT_NO_CONTROL`,
   not `tree.*` bound via `useTreeShortcuts`, which N11 pairs with menus) needs a display site for
   that id in the same directory, or an entry in `SHORTCUT_SHOWN_ELSEWHERE` (map
   `bindingFile -> displayFile`, verified to hold the display site). Heuristic by design: it cannot
   prove the displayed control runs the same handler; the UI spec does.

Initial `SHORTCUT_NO_CONTROL`: `menu.open` (context-menu key, OS convention like right-click; a
"More" button opens its own anchored menu), `list.moveUp/Down/Left/Right` (keyboard reorder; no
control moves an item, drag only), `editor.suggest` (completion popup, no control), `tree.selectAll`
(no Select all control). Native-only ids (`view.commandPalette` and the like) are not listed: the
Go menu display site covers them.
Initial `SHORTCUT_SHOWN_ELSEWHERE`: `packages/git-ui/src/lib/useReviewStepping.ts ->
packages/git-ui/src/components/review/ReviewFilesPane.vue`, `packages/workbench/src/behaviour/panelSearch.ts ->
apps/kira-space/frontend/src/studio/workbench/panels/ProjectPanel.vue`, plus file-local exemptions the
implementer finds for chords with no control in that view, each with a reason as a trailing comment
(expected: `views/repo/RepoDiffView.vue` and `views/repo/useReadonlyFileViewer.ts` `view.find`, Monaco
find widget, no toolbar control; `studio/views/shared/celleditor/CellEditorView.vue`
`form.save`/`form.submit`, value auto-stages, no Save button). Exemption entries for a file use
the target `null` with the reason.

Rename `registerCommand('view.run-all')` (`ConsoleView.vue:242`) and `runCommand('view.run-all')`
(`App.vue:201`) to `'view.runAll'` so the guard sees the registry id.
