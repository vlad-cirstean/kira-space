# P749: Proof window images fit the window, larger default size

Spec: `docs/v0.3.25/SPEC.md` § P749. Base: `78b88fcac` (stream/P749 off chapter/v0.3.25, P747, P748,
P752 landed).

## Terms

- **Proof window**: `studio/proof/ProofWindow.vue`. Centre pane (`ref="centre"`, `proof-centre`) holds
  summary, tab strip and the active step (`ProofStepView.vue`; `ProofCompare.vue` mounts it too).
- **Image step**: view `image`, drawn by `studio/proof/ProofImage.vue`.
- **Kira screenshot**: `useProofScreenshot.ts` `shoot()` clones the `centre` element as laid out
  (`screenshot.ts` `captureElement`), live scroll included.

## Findings (codegraph)

- `ProofImage.vue:64-81`: `<section class="h-full overflow-auto">` around
  `<img class="mx-auto block h-auto max-w-full" :width :height>`. Width fits, height does not: a tall
  image (contract step 4, 64x2000) scrolls, so a view and every screenshot show only its top part.
  The component saves and restores that scroll (`useScroll`, `seed`, `update:scroll`), wired in
  `ProofStepView.vue:210-220`; `useStepViewState` stores it as `resultScrollTop/Left`.
- Window size: `internal/proof/service.go:22-26` `WindowWidth = 1024`, `WindowHeight = 640`, read
  only by `apps/kira-space/main.go:56-66` `proofBounds`, called from `openProofWindow` (`main.go:49`),
  bound through `wired.BindProofShell` (`main.go:218`). `proofBounds` takes
  `shell.CascadeFrom(app.Window.Current())` and overwrites width and height; with no current window
  (Linux) it uses the primary work-area origin. No screen clamp.
- `internal/shell/window.go`: `minWindowWidth/Height = 1024/640` floor every window (`Options`
  `MinWidth/MinHeight`), so today's proof size equals the floor. `DefaultBounds` holds the clamp
  arithmetic (`min(max(min(def, work-40), floor), def)`), tested by `window_test.go`
  `TestDefaultBounds`. `cascadeRect` wraps to the work-area origin when the cascaded rect overflows,
  judged at the source window's size.
- Proof window row is ephemeral (deleted on close, P736 findings), so every open uses this default;
  a resize lasts while the window is open.
- No frontend size constant exists for the proof window (`studio/proof/` has no width or height
  literal). Visual spec `tests/visual/studio/proof-window.spec.ts` and shot `proof.shot.ts` have no
  image step.
- P736 (v0.3.24, plan recovered from `ef5bae6de^`): kept the window small instead of shrinking at
  capture time. Capture code unchanged: it photographs the centre pane as shown, so a shot fits the
  window by construction.

## Interaction with P736

- Capture stays as P736 left it: no change to `screenshot.ts`, `useProofScreenshot.ts`,
  `ProofWindow.vue`. The shot is the centre pane as laid out. Once the image fits the pane, the
  shot holds the whole image with no capture-time work. That is the spec's "(so Kira's screenshots
  show everything)".
- P736's goal (small shot, readable text) holds: text size does not change, and the size grows only
  12.5% per side. P736 chose the floor because it was the smallest allowed, not because a larger
  size failed.
- Auto-expand (P736) and `lined` (P748) untouched.

## Decisions

### Image fit

- Scale down to fit both pane width and height, aspect kept, never upscaled (a small image stays at
  natural size, as today). Centred on both axes. No scroll: the image always fits, so
  `overflow-hidden`.
- CSS only, no JS measuring: `max-w-full max-h-full` with `w-auto h-auto` on the `<img>`. `w-auto`
  is required: the `width` attribute maps to a fixed CSS width, and with only height clamped the
  image would distort. Attributes stay so the box holds its aspect ratio before load.
- Section becomes `absolute inset-0` inside `proof-step-result` (already `relative min-h-0 flex-1`),
  so its height is definite and `max-h-full` resolves. `flex items-center justify-center`; img gets
  `min-h-0 min-w-0` so flex auto minimum never beats the max. If WebKit still overflows in the UI
  spec, use the fallback: section `absolute inset-0 overflow-hidden`, img
  `absolute inset-0 m-auto max-h-full max-w-full` (abs-positioned replaced element, auto margins
  centre it). Pick whichever passes; same assertions.
- Scroll state for image steps goes: drop `useScroll`, `seed`, `update:scroll` from `ProofImage`
  and the two bindings in `ProofStepView`. Leaving them would be dead code. Old saved
  `resultScrollTop` values for image steps are ignored; no migration (view state is a cache of UI
  positions). `useStepViewState` stays (diagram, chart and grid use it).
- Very tall images (full-page captures) shrink a lot. Spec asks the whole image in one view; zoom
  is out of scope.
- `ProofCompare` side by side gets the same fit (shared `ProofStepView`).

### Window size

- New default **1152x720**. Why: +12.5% per side (+27% area), "a bit" over the 1024x640 floor that
  felt too small. Same 16:10 ratio as the floor and the main window's 1280x800 default. Stays below
  1280x800, so the cascaded proof window does not fully cover a default main window. Centre pane
  gains about 128 px width and 80 px height for steps and fitted images; a 2x capture grows from
  about 2048x1280 to 2304x1440 at most, still a small JPEG.
- Clamp to the screen: on a small work area the proof size shrinks to `work - 40` (same margin as
  `DefaultBounds`), never under the global floor. Today's code has no clamp; at 1024x640 it never
  mattered.
- Cascade wrap judged at the proof size, not the source window's. The old invariant (proof window
  never larger than its source, so the source's wrap check sufficed) breaks once the proof window is
  larger than a 1024x640 main window. Reuse `cascadeRect` with the fitted size.
- Shared code goes in `internal/shell` beside `DefaultBounds`/`cascadeRect`; `DefaultBounds` becomes
  a call to the generalised clamp, so its arithmetic has one home and its test keeps covering it.

### Stale open proof window after an agent's silent edit: out of scope

Evidence: an accepted agent edit of the newest proof goes `SubmitFiles` (`ade/detailssubmit.go:195`)
-> `taskfiles.Service.unit` -> `unitApply` (`taskfiles/proofunit.go:295`) -> `unitTx.edit`
(`:429-465`), accepted branch. `unitApply` calls `ProofEvents.ProofReview` only when `a.review != nil`
(set only for a pending edit, or an accept that clears one). `detailsEvents.Accepted`
(`ade/detailssubmit.go:36`) fires only for `NotifyProofReady` (new proof). So no path reaches
`proof.Service.emit` (`RaiseReady`, `RaiseReview`, `WithdrawReview`, `AcceptEdit`, `RejectEdit`,
`Delete` are its only callers); only `notifyBoardNow(taskChanged(taskID))` runs. The proof window
listens to `kira:proof:changed` only (`studio/proof/queries.ts` `useProofSync`).

The fix belongs in Go: a proof-changed hook from `unitApply` on every accepted unit, through
`taskfiles.ProofEvents`, `ade/proof.go` `ProofLinks`, `proof/service.go` (new emit method),
plus the flow harness fake and a proofflow test. None of that is the proof window's own files, and
`ade/` sits next to P750's files. Frontend workaround declined: subscribing the proof window to the
board push would tie it to the ADE board channel and refetch every proof query on each unrelated
change of that task. Recommend a follow-up phase (orchestrator's call): "Proof window refreshes after
an accepted agent edit of a proof".

### 2. Larger proof window (Go)

`internal/shell/window.go`:

- New exported `FitSize(work *application.Rect, width, height int) (int, int)`: the body of
  today's `DefaultBounds` with `defaultWindowWidth/Height` replaced by the arguments. Nil or empty
  work area returns `(width, height)`. Doc comment: shrinks a wanted size to the work area minus
  `windowSizeMargin`, never under the app floor, never grown.
- `DefaultBounds(work)`: `return FitSize(work, defaultWindowWidth, defaultWindowHeight)`. Trim its
  doc comment to what stays true (first-launch size, shrinks only); keep the UX reason.
- New `workAreaOf(from application.Window) *application.Rect` (the `GetScreen` lookup now inline in
  `CascadeFrom`); `CascadeFrom` uses it, behaviour unchanged.
- New exported `CascadeFromSized(from application.Window, width, height int) *WindowBounds`: nil when
  `from == nil`; else `cascadeSized(from.Bounds(), workAreaOf(from), width, height)`.
- New unexported `cascadeSized(from application.Rect, work *application.Rect, width, height int)
  *WindowBounds`: `from.Width, from.Height = FitSize(work, width, height)`, then
  `return cascadeRect(from, work)`. Doc comment: the wrap is judged at the new size, so a window
  larger than its source still lands on screen.

`apps/kira-space/internal/proof/service.go:22-26`: `WindowWidth = 1152`, `WindowHeight = 720`.
Comment: "proof window default: a step above the 1024x640 window floor, room for fitted images,
screenshots still small (P749)."

`apps/kira-space/main.go`:

- `openProofWindow`: `rec.Bounds = proofBounds(app.Window.Current(), app.Screen.GetPrimary())`.
- `proofBounds(from application.Window, primary *application.Screen) *shell.WindowBounds`:
  1. `if b := shell.CascadeFromSized(from, proof.WindowWidth, proof.WindowHeight); b != nil { return b }`
  2. Else: `b := &shell.WindowBounds{}`; `var work *application.Rect`; when `primary != nil`, `work =
     &primary.WorkArea` and `b.X, b.Y` = work origin; `w, h := shell.FitSize(work, proof.WindowWidth,
     proof.WindowHeight)`; set `b.Width, b.Height` as float64; return.
  Update both doc comments (cascaded from the current window at the proof size, fitted to the
  screen; no current window, Linux, falls back to the primary work-area origin).
