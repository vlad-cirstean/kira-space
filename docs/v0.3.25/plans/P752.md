# P752: task detail title no longer overlaps the colored bar

Spec row: task detail title overlaps colored bar right after it. Never overlap, at every title length
and window width. Fix in Tailwind utilities. UI spec asserts no overlap with long title.

## Cause (measured)

Probe: temporary Playwright spec (deleted, not committed) on test bundle, task `T_alerts`, short and
117-char title, viewport 1440 and 900, `--kira-font-size` 12, 16, 20, title focused.

Structure:

- `apps/kira-space/frontend/src/ade/v2/panel/AdePanelFrame.vue:19-22`: header wrapper
  `relative shrink-0` holds header slot plus `<ColorLine variant="under">`.
- `packages/workbench/src/components/ColorLine.vue:14`: `under` is
  `absolute inset-x-0 bottom-0 h-0.75`. Line overlays bottom 3px of header; takes no layout space.
- `apps/kira-space/frontend/src/ade/v2/panel/AdeTaskPanel.vue:156`:
  `<DetailHeader flush class="px-3 pt-2 pb-0.75">`. Bottom padding 3px equals line height exactly
  (P738 cut title-to-tabs gap to 7px this way). Same at `AdeBranchPanel.vue:296-298`.
- `AdeTaskPanel.vue:165-175`: title is `<Input appearance="inline">` with
  `text-kira-lg font-medium`. `packages/theme/src/components/ui/input/index.ts:14`: default size
  `kira-lg` gives fixed `h-control-lg` (26px, `--kira-h-md`, not font-scaled).

Measured, default font (12px, title 13px/19.5px):

- title box y 76, bottom 102; line y 102, bottom 105; header bottom 105. Gap title to line: 0px.
  Any fractional zoom or DPR rounding makes it overlap by up to 1px; existing
  `expectLineUnderTitle` (`tests/ui/ade-v2-task-panel.spec.ts:91`) tolerates exactly that `- 1`.
- Focused (or hovered inline field): `focus-visible:border-border` plus inset focus ring draw on
  title box bottom edge, flush on the line: reads as title running into bar.

Measured, larger app font (Settings appearance font size, `createSettingsStore.ts:90` writes
`--kira-font-size`):

- 16px: title 17px/25.5px in 26px box. 20px: 21px/31.5px in same 26px box. Box stays 26px, text
  overflows it vertically; descenders land on the bar.

Long title: `<input>` never wraps. 117 chars at 900: `scrollWidth` 763, `clientWidth` 387. Text
cut mid-word at box edge, no ellipsis. Not an overlap itself, but spec asks every title length.

Branch panel: same `pb-0.75` header, wrap `h2` title (`DetailHeader` `wrap`, `leading-snug`), so a
wrapped long branch name's last line also sits flush on the line. Same fix covers it. Archived panel
passes no `color`: no line, unaffected.

## Fix

Three changes, Tailwind utilities only, no `<style>` block. `ColorLine` stays untouched (other
callers overlay title bars on purpose).

1. Reserve line space structurally. `AdePanelFrame.vue:19`: header wrapper gets bottom padding only
   when a line shows: `class="relative shrink-0"` plus `:class="color && 'pb-0.75'"`. Line keeps
   `absolute bottom-0`, now inside that 3px; header slot content can never reach it, whatever its
   own padding.
2. Gap between title and line. `AdeTaskPanel.vue:156` and `AdeBranchPanel.vue:298`: header class
   `px-3 pt-2 pb-0.75` becomes `px-3 pt-2 pb-1` (4px clear gap, keeps focus border off the bar).
   Title-to-tabs box distance grows 7px to 11px; visible text gap stays tight because input text is
   centered in its box. Probe with these values (inline styles): gap 4px at every width and font
   size tested.
3. Title field follows font size and shows truncation. `AdeTaskPanel.vue:171` Input class adds
   `h-auto min-h-control-lg py-0.5 text-ellipsis`. `Input.vue` merges `props.class` through `cn`
   (tailwind-merge), so `h-auto` replaces variant `h-control-lg`. Probe: box 26px at default font
   (unchanged look), 31.5px at 16px, 37.5px at 20px; row `min-h-control-lg items-center` grows with
   it, leading badges stay centered. Unfocused long title ends with an ellipsis; focus scrolls text
   as now.

Wrap versus clamp decision: task title stays single-line, ellipsis at rest. A wrapping title needs
`<textarea>` plus autosize (VueUse `useTextareaAutosize`) and re-wiring `useInlineEdit` Enter
handling for one header. Real requirement it fails: panel header height must stay stable while tab
content scrolls under it, and card titles (`AdeTaskTitle`) are single-line too. Branch title already
wraps (`DetailHeader wrap`); step 1 and 2 keep it clear of the line at any line count. No clamp
added there: branch names are bounded by git and wrap to at most a few lines.

No other caller changes. `DetailHeader` (30 callers) untouched.

## Test

UI only. No backend half: pure layout, no IPC, no state change; nothing to assert in a flow test.
Say so in Result.

New spec `apps/kira-space/tests/ui/ade-v2-task-title-line.spec.ts` (own file, keeps
`ade-v2-task-panel.spec.ts` out of this phase). Uses `openPlan`, `openTask`, `adeBoardSnapshot` from
`tests/ui/support/adeV2.ts`.

Helper `expectClear(page)`: bounding boxes of `ade-panel-title`, `ade-panel-head ade-task-line`,
`ade-panel-head`, first `ade-panel-tab-*`. Assert:

- `line.y >= title.y + title.height + 2` (strict, no `- 1` tolerance);
- line bottom equals head bottom (within 1px);
- first tab top at or below line bottom;
- title box height at least title's computed `line-height` (no vertical text overflow).

Tests:

1. Task panel, long title (about 120 chars, with descenders `gyp`), for each of viewport width 1440
   and 900 (900 is narrowest the plan layout keeps panel beside list, per `ade-v2-plan.spec.ts:156`),
   and `--kira-font-size` 12px and 20px (set on `document.documentElement.style`, same as
   `createSettingsStore`). Assert `expectClear`; assert title `scrollWidth > clientWidth` (title
   really is long) and computed `text-overflow` is `ellipsis`. Then focus title, assert
   `expectClear` again.
2. Branch panel `b_cart` with long branch name (about 120 chars, wraps), width 900: `expectClear`
   with `ade-panel-title` h2; skip ellipsis check (wraps by design).

Loop over cases inside test bodies or as generated tests; keep under 4 tests total.

## Result

Done as planned. Header wrapper reserves 3px under the line when `color` set; task and branch headers `pb-1`; task title Input `size="fluid"` (new `inputVariants` size `min-h-control-lg px-2 py-0.5`) plus `text-ellipsis`. New spec `ade-v2-task-title-line.spec.ts` (2 tests: task title at 1440/900 and font 12/20px, rest and focused; wrapped branch name at 900).

Tests: `bun run build:test`, then playwright `ui` `ade-v2-task-title-line ade-v2-task-panel`: 10 passed. Typecheck and lint via pre-commit hook. No backend half: pure layout, no IPC or state change.

Deviation: spec title is about 330 chars, not 120. At 1440 the panel fits 120 chars, so `scrollWidth > clientWidth` failed.

Deviation: guard U9 forbids `h-`/`py-` classes on Input, so the plan's `h-auto ... py-0.5` became a new `fluid` size in `packages/theme/.../input/index.ts`. Everything landed in one commit (hook runs about 15 min under load).
