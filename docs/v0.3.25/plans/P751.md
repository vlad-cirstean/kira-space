## Decisions

- Every PR, merge request and Jira link opens in the OS browser through `control.openExternal`
  (`LinkService.OpenExternal`). No in-app window for either, on GitHub, Azure DevOps or the fake forge.
- Change request tracker stays whole. It never touched the viewer: `ade/updates.go:307`
  `crObservations` reads `gitsession.RepoEntry.ResolveBranchChangeRequest` (sync index), and the UI
  reads `useChangeRequests` (`readQueries.ts:42`). Only the click target of a PR changes.
- Task Jira slot stays: `ade_tasks.jira_key/jira_url`, `adewire.Jira`, `parseJira`
  (`frontend/src/ade/v2/jira.ts:4`), `{jira}` built-in var (`internal/scripts/smart.go:59`), prompts
  (`llmprompts` Jira line), board menu copy/open Jira (`board/menu.ts:121,462`), phone chips. It shows as
  a plain stored link: key, URL, copy, open in browser, edit, remove. No title, status or PR count.
- Jira key and link recognition stays, without acli: the pure parser `jira/parse.go:23 parseRef`
  (bare key, `/browse/KEY`, `/issues/KEY`, `selectedIssue=KEY`) moves to `internal/ade/jiraref.go` as
  `ParseJiraRef(raw) (JiraRef{Key, URL, Site}, bool)`. Callers: `ade/linkclassify.go:131,151` (AddLink
  files a Jira link into the Jira slot, a bare key as a stored issue) and `bridge/capture.go:338`
  (clipboard capture of a Jira link). Without it `TestDetailsOpenExternal` (`adeflow/detailsopen_test.go:38`,
  `jira.example.com/browse/PAY-9` files to the Jira slot) would break.
- Capture keeps recognising change request links: githost keeps a narrow `ChangeRequestLinks` role
  (`ParseChangeRequestLink` only). The detail read (`ChangeRequestDetail`) and comment write roles go.
- CLI tools pane stays for gh and az; `Tools` moves from `IssueTrackerService` to `GitHostService`.
- `markdown-it` stays (repo reading view, `views/repo/markdownReading.ts:35`). `markdown-it-github-alerts`
  and Go `goldmark` go (viewer-only).
