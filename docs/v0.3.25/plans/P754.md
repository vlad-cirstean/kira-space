# P754 plan: checkboxes and toggles, blue checked state

Owner ask: on and checked state of checkbox, switch, radio, toggle and segmented buttons and option
toggles keeps today's look (border plus faint background tint) in blue instead of grey. Change
primitives and tokens once; no per-screen overrides. Styling only: no backend half, no flow test.

Context: v0.3.22 P710 made selection and on-state neutral grey; v0.3.23 P730 split on-state into six
`--kira-toggle-*` / `--kira-progress-fill` tokens. Guard N18 (`scripts/check-conventions.ts`) holds
both greys. P754 moves only the on-state family to blue. Selection (`--kira-select*`, rows, list
items, chips, Monaco and xterm selection, focus ring) stays grey and N18 keeps guarding it.

## 1. Scope

In scope (turns blue):

- Checkbox (checked and indeterminate), Switch (on), RadioGroupItem (checked), RadioGroupCard
  (checked card).
- Pressed toolbar buttons (`aria-pressed`, mostly `TooltipIconButton :pressed`): SearchOptionToggles
  (match case, whole word, regex), find/filter/history/search-open toggles, incognito, reveal value,
  row edit toggle, repo hide toggles, VariablesMatrix lock. About 45 call sites, all through
  `buttonVariants` `toolbar`.
- Pressed `dialog` buttons (`aria-pressed`): mobile terminal latched Ctrl (`KeyBar.vue`).
- `Toggle` (single text toggle): ReviewLog wrap/timestamps/line numbers, OperationsPanel background,
  kube LogsView previous/follow/timestamps/wrap.
- `SecondaryTabs` `segmented` (30 files) and `choice` (form single-select) on item.
- Monaco's own find-widget option toggles (`inputOption.active*`): same family as
  SearchOptionToggles, so they follow it.

Out of scope (stays grey or as is), with reason:

- `SecondaryTabs` `tabs` and `text` variants, `tabChipVariants`, `ModeSwitcher`: navigation, the
  selected tab is selection, not an on-state (P710).
- `title` button variant (title-bar panel toggles, keep awake, ADE review agent panel): window
  chrome beside the mode tabs; panels are on most of the time, so a permanent blue strip would mark
  nothing. Pressed stays `bg-elevated`. One-line follow-up if the owner wants it (section 9).
- Rows that misuse `aria-pressed` for selection (`ConfigSyncUnitRow`, `PreviewCommandPanel`,
  `TimePicker`): `rowVariants` selection, grey. No class change.
- Dropdown menu checkbox and radio items: a bare check glyph, no box, border or fill.
- Progress: not a toggle; `--kira-progress-fill` and track stay grey.
- Off state (`--kira-toggle-off-edge`, `--kira-toggle-knob`, `bg-field`) and mark
  (`--kira-toggle-mark` #f4f4f5): unchanged. Mark has no hue today, so "only the hue changes" leaves
  it white.
- Swatch radios (`SwatchPicker`, `connColor.ts`, `ade/v2/statusColors.ts`): checked paints the data
  colour by design; their `data-[state=checked]:bg-conn-*` classes already win today and keep
  winning (precedence unchanged by a value change).

## 3. Blue choice

No new hex and no new token name. Retarget the two existing on-state tokens to the existing blue
family:

```css
--kira-toggle-on: color-mix(in srgb, var(--kira-accent) 20%, transparent); /* on fill: faint accent tint (P754) */
--kira-toggle-on-edge: var(--kira-info); /* on border (P754) */
```

Why:

- Edge `--kira-info` #69a1e8: 5.57:1 on field, 6.01 elevated, 6.43 bg, 6.89 dialog, 6.95 chrome
  (WCAG 1.4.11 needs 3:1). `--kira-accent` #3b6ed1 as edge is 3.07:1 on field and 2.52:1 against
  its own tint, too weak for a 1px line; `--kira-status-blue` #8ebaf4 is a data-palette colour.
- Fill: accent at 20% alpha is the "faint" lift of today's #33333a (1.19:1 over field). Composited:
  field #2b354d (1.22:1 vs field), elevated #263047, bg #212c42, dialog #1c263b, chrome #1b253b.
  Alpha, not a solid mix, so the tint reads the same on every surface the control sits on, and
  `dialog-primary`'s `hover:bg-primary/15` already uses this "accent at low alpha" look.
- Edge against the fill: 4.57:1 (field) to 5.72:1 (chrome). Mark #f4f4f5 on fill: 11.1:1 (field)
  to 13.9:1 (chrome). Text `--kira-fg` on fill: 8.26:1 to 10.3:1; `text-muted-foreground` 4.77:1
  minimum.
- Focus ring `--kira-focus` #a1a1aa vs blue edge is 1.04:1 luminance; distinct by hue and by
  placement only, so checked controls keep `outline-offset-2` (section 5).

Monaco `cssVar` resolves the custom property, then canvas-normalises it to `#rrggbbaa`; color-mix is
a valid canvas `fillStyle` in Chromium and WebKit. Fallbacks `#3b6ed133` and `#69a1e8`.

`tailwind-core.css` needs no edit: `--color-toggle-on` and `--color-toggle-on-edge` already map the
tokens, so `bg-toggle-on`/`border-toggle-on-edge` exist and the class-conflict registration check
already knows them.
