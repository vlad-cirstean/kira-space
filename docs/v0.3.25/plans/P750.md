# P750: Details panel and proofs: auto-update on disk changes

SPEC row: Details panel, and the proofs inside it, do not refresh when files change on disk. Trace the
watch and invalidation path (file watcher, bridge event, TanStack Query), fix the broken link. Flow
test asserts the event, UI spec asserts the refresh.

## Path traced

Disk save to Details refresh has four hops:

1. Watcher. `ade/taskwatch.go` `taskWatch` watches `notes/`, `handovers/`, `proofs/<slug>/` of one task
   folder (`newTaskWatch`, `taskwatch.go:112-126`), debounced 300 ms / max 2 s.
2. Apply plus push. One live caller: `run` calls `SyncTaskFiles` (`taskwatch.go:337-348`), which ends
   in `SubmitFiles`, then `notifyBoardNow(taskChanged(taskID))` (`detailssubmit.go:237`). Zero or
   several callers, or a Rescan: `notifyBoardNow(taskChanged(id))` only (`taskwatch.go:276`, `:342`).
3. Bridge. `OnBoard` goes to `bridge.AdeTaskBoardChanged`, which emits `adewire.ChannelBoard`
   (`kira:adetask:board`, `bridge/adetask.go:65-67`).
4. Frontend. `control.onAdeTaskBoard` normalizes the payload (`bridge/index.ts:853-856`).
   - `installAdeReadSignals` refetches the board (`v2/readSignals.ts:33-37`).
   - `installAdeSignals` invalidates `handoversPrefix`, `artifactsPrefix`, `diskPrefix` and
     `issuePrefix` per task (`ade/queries.ts:84-89`).
   - Details reads `useHandovers`, `useTaskProofs`, `useTaskArtifacts` (`AdeTaskChain.vue:45-47`) and
     `useDiskChanges` (`AdeDetailsDiskBanner.vue:25`).
   - Inline proof diagrams read `useProofStep(proofId, rev, ordinal)`
     (`AdeProofDiagramStep.vue:12-16`), key `['proof','step',id,rev,ordinal]`
     (`studio/proof/queries.ts:22`).

## Broken links

### Link 1 (backend): no watcher unless an agent holds a Space grant

- `newTaskWatch` runs only from `watchTask`, only from `registerSpaceGrant` (`taskwatch.go:70-81`).
  `unwatchTask` stops it with the last grant (`taskwatch.go:128-168`).
- With no live agent, nothing watches the task folder. A save from an editor, script or shell raises
  no event, so no board push, so `diskPrefix` never invalidates.
- The banner refreshes only on open, window focus or the Refresh button (`useDetailsDisk.ts:12-23`).
  The code says so outright: "a user's edits show on the next trigger" (`useDetailsDisk.ts:9-10`).
  `ARCHITECTURE.md:4172` agrees: "With no live grant no watcher exists".
- Covers notes, handovers, `links.yaml` and proof files the user edits while no agent runs: the
  Details panel shows nothing until focus.

### Link 2 (frontend): a board push never invalidates the task's proofs

- `useTaskProofs` key `['adetask','proofs',taskId]` (`v2/queries.ts:577-582`) invalidates only on
  `studioControl.onProofChanged` (`ade/queries.ts:91-93`) and on delete (`v2/queries.ts:596`).
- `kira:proof:changed` fires only from `proof.Service.emit` (`proof/service.go:82-86`). Callers:
  `AcceptEdit`, `RejectEdit`, `Delete`, `RaiseReady` (new proof, via `NotifyProofReady`),
  `RaiseReview` / `WithdrawReview` (pending edit).
- An agent's edit of the task's newest proof is a silent accept: `approvalCause` returns no cause for
  `Latest` and `Decide` gives `Accept` with `NotifyNone` (`taskfiles/decide.go:146-151`).
  `unitApply` raises a review only when the pending flag changes (`proofunit.go:309-315`).
- So the only push for that accepted edit is the board push (`detailssubmit.go:237`). The frontend
  board handler skips `proofsPrefix` (`ade/queries.ts:84-89`).
- Result: steps, name, summary and `rev` stay stale. `AdeProofDiagramStep` keeps the old `rev` key, so
  diagrams stay stale too. `TestDetailsWatchLatestProof` (`detailswatch_test.go:233-294`) proves the
  backend applies the edit; nothing refreshes the panel.

## Changes

### Backend: board-wide idle watcher of the task files root

New file `apps/kira-space/internal/ade/idlewatch.go`. One `fswatch` watcher for the whole files root
(`detailsFiles.root`). It does not apply edits: it only pushes the board for a task with no agent
watcher, so the Details panel refetches. Agent-pass semantics stay as they are. Per-task
`taskWatch` remains the only applier.

```go
// idleWatch watches every task folder under the files root. A save in a task no agent watcher covers
// pushes the board for that task, so the Details panel restats; nothing is applied.
type idleWatch struct {
	b     *TaskBoard
	root  string
	nroot string // root, Clean and NFC: the spelling fswatch reports paths in
	w     *fileservice.Watcher
	deb   *fileservice.Debouncer

	mu      sync.Mutex
	tasks   map[string]struct{} // task ids with a save since the last push
	rescan  bool
	stopped bool
	done    chan struct{}
}
```

- Constant `idleWatchDepth = taskWatchDepth + 1` (3): `<root>/<task>/proofs/<slug>`.
- `skipDir(p)`: slash rel to `nroot`. Rules:
  - `""` (root itself): false.
  - One segment (task folder): skip only a hidden name.
  - Deeper: skip unless `watchedTopDirs[segs[1]]` and `!hasHiddenSegment(rel)`.
  - Reuse `watchedTopDirs` and `hasHiddenSegment` from `taskwatch.go`.
- `handle(ev)`:
  - `ev.Rescan`: set `rescan`, `deb.Schedule()`.
  - `ev.Op == fileservice.Meta`: return.
  - Else split rel into `seg` plus in-task rest. Drop the event when rest is `""` or
    `keepTaskFile(rest) == ""` (Kira-owned `README.md`, `task.yaml`, `state.yaml`, ignored kinds).
  - A Create/Rename of a dir under a watched top dir (`ev.Dir`, or `Lstat` says dir) counts too. Queue
    the task; no walk needed, since the push restats the whole folder.
  - Task id: `seg`. Folders are `pathSegment(taskID)` (`details.go:130`). Task ids have no `/` or `\`,
    so the folder name is the id. Pushing an unknown id is harmless.
- `fire()`:
  - Swap out `tasks` and `rescan`.
  - Under `b.watchMu`, drop every id with a live `b.watches[id]`. That task's own watcher already
    pushes after its pass. A second, earlier push would flash the agent's unapplied save as a banner
    row.
  - Rescan: `b.notifyBoardNow(adewire.BoardChangedEvent{})` (all tasks, `refs` false; merge treats an
    empty `TaskIDs` as all, `boardcache.go:65-71`).
  - Otherwise, when ids remain: `b.notifyBoardNow(taskChanged(ids...))`.
- Start: `func (b *TaskBoard) startIdleWatch()`, called as the last step of `startDetails`
  (`detailsmigrate.go:161`, already under `goTracked`). Start after migration and mirror so their
  writes are done.
  - Under `b.watchMu`: return when `b.ctx.Err() != nil` or `b.idle != nil`.
  - `fileservice.Host().MkdirAll(df.root)`.
  - `fileservice.Host().Watch(fileservice.WatchOptions{Names: []string{root}, MaxDepth:
    idleWatchDepth, SkipDir: iw.skipDir})`.
  - `NewDebouncer(taskWatchQuiet, taskWatchMaxWait, iw.fire)`, `go iw.loop()`.
  - A watch error logs `slog.Warn` with `taskWatchEvents` and leaves the board as before (banner on
    focus/Refresh).
  - Log `fileservice.WatchBackend()` once at start, like other watch consumers.
- Stop: `stop()` sets `stopped`, `deb.Stop()` (waits for an in-flight push), `w.Close()`, `<-done`.
  `stopTaskWatches` (`taskwatch.go:171-180`) takes `b.idle` under `watchMu`, sets it nil and stops it
  before `watchWG.Wait()`. `Close` already calls `stopTaskWatches` (`board.go:370`). Holding
  `watchMu` for the start check, with `b.ctx` cancelled first in `Close` (`board.go:350`), means a
  start racing `Close` either sees the cancel or is stopped by it.
- New field on `TaskBoard` beside `watches` (`board.go:214-218`): `idle *idleWatch // board-wide
  watcher of task folders no agent watches (idlewatch.go)`.
- `queue` after `stopped`: drop, as in `taskWatch.queue`.

Kira's own writes need no special case. `mirrorTask` and the state writer run on submits and state
changes, not on a board push, so a push cannot feed back into a save. A Kira write under `notes/` or
`proofs/` costs one extra push plus a restat that shows no diff. The debounce bounds it.

Cost: on Linux `fsnotify` adds one inotify watch per watched dir. That is about `1 + 3 + proofs`
per task folder, archived included: a few thousand for a large board, far below the default limit.
On macOS FSEvents uses one stream for the root.

### Frontend: a board push refetches the task's proofs

`apps/kira-space/frontend/src/ade/queries.ts:84-89`: add
`invalidateTaskFamily(queryClient, proofsPrefix, change);` to the existing board handler. A refetched
`TaskProof` carries the new `rev`, so `AdeProofDiagramStep`'s key changes and diagram steps re-read.
Keep `onProofChanged` (`:91-93`): proof-service events carry no task id.

Comment upkeep, same commit:
- `frontend/src/ade/v2/queries.ts:576`: "a proof push refetches it" becomes "a proof or board push
  refetches it".
- `frontend/src/ade/v2/details/useDetailsDisk.ts:9-10`: drop "a user's edits show on the next
  trigger". New text: Kira watches every task folder, so any save pushes the board and the banner
  restats.

No change to `AdeProofEntry.vue`, `AdeProofDiagramStep.vue` or any other proof component: P748 owns
those.

## Out of scope

- Proof window (`studio/proof/queries.ts:139`) listens only to `kira:proof:changed`. A silent
  accepted edit of the newest proof does not refresh an open proof window. The SPEC row names the
  Details panel only. If wanted, it becomes its own phase (emit `proof.Changed` on a silent accept).
