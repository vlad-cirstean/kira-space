## 2. Rules: when a line stays

Separate by tone step first (chrome < bg < elevated < field), then spacing (existing gap/padding), then type (weight, `text-muted-foreground`/`text-subtle`, uppercase panel labels). Draw a line only when one of these holds:

1. **Input edge stays**: Input, Textarea, NativeSelect `bordered`, InputGroup, PickerTrigger, Checkbox, Radio, Switch, segmented ToggleGroup `outline`, and dialog buttons (`dialog`, `dialog-primary`, `dialog-danger`). Read-only Input goes bare (`read-only:border-transparent`).
2. **Floating-surface edge stays**: popover, menu, sub-menu, dialog, command dialog, tooltip, autocomplete, git-ui drawer. Use one recipe: `ring-1 ring-border-strong` plus the existing `shadow-kira`/`shadow-kira-dialog`. `ring-fg/10` goes.
3. **Focus, selection and state stay**: `focus-ring`, `:focus-visible`, ADE card selected (`border-focus ring-1 ring-focus`), ripple outline, drop-target `outline-focus`, `aria-invalid:border-error`, tone borders (`border-tone-*`, `border-error`, `border-warn`, …), ADE task-colour left edge, parked swatch `border-2`, timeline rail `border-r-2` and dots.
4. **Data-grid cell lines stay**: SlickGrid, `StreamRowsTable`, `KeyValueRowsTable`, the `AppearancePane` grid preview, and `Table` `columns` mode. Cells keep `border-border` (now `#2b2b30`). The header row loses `border-border-strong` and is set apart by `bg-elevated` plus a hairline `border-b border-border`.
5. **Resize handle line stays**: `resizableHandle` `line` inset shadow. It is the grab affordance, and http/grpc/cell-editor specs assert it.
6. **Menu and command separators stay**: DropdownMenuSeparator, CommandSeparator, Monaco `menu.separatorBackground`. They group items inside one floating list.
7. **Authored-content rules stay** (markdown in `base.css`): blockquote `border-l-4`, `hr`, markdown table cells, callout `border-l-4` tones.

Everything else goes:

- Pane, panel and dock frames: drop `border border-border`. Keep `rounded-kira` and `bg-bg` on `bg-chrome`.
- Card `inset`: drop the border and keep the `bg-field` fill. `section`: drop the border and keep `bg-elevated`. `list`: drop the border and add `bg-elevated`. CardHeader/CardFooter section dividers go.
- Toolbar, view head, panel head, panel bar, tab strip, dialog header/footer, section header and list-row dividers (`border-b`/`border-t` between rows, `divide-y`, `last:border-b-0` pairs) go. Hover (`bg-hover`) and spacing carry rows.
- Table head (non-grid) is `bg-elevated` only, and table row lines go.
- `ToolbarSeparator`, TabStrip's pinned divider span and similar vertical delimiters become transparent spacers of the same box. Keep the element and its testid.
- Alert loses its border and keeps its `/10` tint.
- Active tab is `bg-elevated text-fg border-transparent`. Toolbar `aria-pressed` loses `border-border-strong`.
- Kbd loses its border and keeps the `bg-field` fill.
- Day-band and section rules in ADE: ordinary-day `border-t` goes `border-t-transparent`. Monday/Later/Today keep a hairline `border-t-border` (down from strong): a calendar landmark, rule 3.

Mechanics: delete a removed border's colour class together with its width class (`border-b border-border` -> nothing). Where a state variant elsewhere in the same string still sets a border colour, keep the width and use `border-transparent` at rest. `check-class-conflicts.ts` must stay green.
