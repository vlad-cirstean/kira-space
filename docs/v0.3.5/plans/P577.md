# P577 Terminal-less run logs and sessions: scroll, select, copy

Base: `chapter/v0.3.5` after P576 (`8347fe26b`). One sequential Sonnet implementer. Renderer only,
shared workbench and ADE components: no streams.

## Findings (from code)

### Which view shows an AI-started run

- MCP `run_script` runs headless (`internal/scriptruns/mcprun.go:56-77` `StartMCP`,
  `startHeadless`); no terminal tab. Its log lives in `script_run_logs`, read by
  `ScriptRunsService.ReadLog`.
- The run opens as a `script-run` tab: Runs section row click (`RunsSection.vue:76`), Operations
  menu "Open run", agent reveal (`apps/kira-space/frontend/src/state/agentNotify.ts:76`
  `placeRunTab`). Same tab for a smart script run (headless `claude -p`).
- Tab component: `apps/kira-space/frontend/src/workbench/tabViews.ts:32` `'script-run':
  ScriptRunView` (`packages/workbench/src/automations/runs/ScriptRunView.vue`). Log:
  `RunLog.vue` (`useRunLog`, TanStack Query) into `packages/workbench/src/components/LogLines.vue`
  (`max-height="none"`).
- Non-interactive Claude session in ADE: `AdeSessionsTab.vue:100` mounts
  `apps/kira-space/frontend/src/ade/v2/sessions/AdeHeadlessPane.vue`, which renders
  `AdeRunLog.vue` (`useLog`) into the same `LogLines`. Inline logs (session rows, run outcome, needs
  rows, worktree setup) use `AdeRunLog` too.
- No canvas, no xterm: every one of these is DOM text from `LogLines` (virtualized rows,
  `useVirtualRows`, ANSI spans).

### (a) Why the run log tab does not scroll

- Shell chain: `packages/workbench/src/components/WorkbenchShell.vue:99`
  `<div class="flex-1 min-h-0" data-testid="main-view">` is a flex item with a definite height but
  is not itself a flex container. `apps/kira-space/frontend/src/workbench/WorkbenchShell.vue:67`
  wraps `MainView` in `class="contents"`; `MainView.vue:46-59` renders the tab component directly.
- Every other tab view fills that box with `h-full` (e.g. `StreamView.vue:74` `h-full flex flex-col
  min-h-0`).
- `ScriptRunView.vue:69` root is `flex min-h-0 flex-1 flex-col gap-2 p-3`: `flex-1` is inert (parent
  not flex), so the root takes content height. `RunLog.vue:14` `flex-1` and `LogLines.vue:80`
  `flex-1 overflow-auto` with `max-height: none` then grow to the full virtual height
  (`totalSize`). The scroll element never overflows; `main-view`'s `overflow-hidden` ancestor
  (`WorkbenchShell.vue:86`) clips the rest. Wheel does nothing, lines below the fold are
  unreachable.

### (b), (c) Why nothing selects

- `packages/theme/src/base.css:37` body is `select-none`; only `input`, `textarea`,
  `[contenteditable]`, `.cm-editor` opt back (`:40-45`). Data surfaces opt in with `select-text`
  (`OpLogDetail.vue:49`, `OpLogCodeBlock.vue:39`, `ConsoleResultGrid.vue:562`, `ReviewThread.vue:167`).
- `LogLines.vue:77-83` never opts in, so every log (run tab, ADE headless pane, inline ADE logs,
  Docker and Kubernetes logs) inherits `user-select: none`. Same for `CodeBlock.vue:13` (run command,
  smart prompt) and `RunOutcomeBlock.vue:68-81` (last error, output tail).
- Copy itself works once text selects: both app menus carry the native Edit roles
  (`internal/shell/menu.go:109-117`, `application.Copy`), so Cmd+C copies a selection.
- Virtualization limit: rows outside the window are unmounted, so a drag selection only holds
  mounted rows. A whole-log copy needs its own action: Copy log button, built on the loaded query
  data, not the DOM.

### Library rules

- Clipboard: `useCopy` (`packages/workbench/src/behaviour/clipboard.ts:113-130`). VueUse
  `useClipboard` declined there already, named requirement: it swallows the `writeText` rejection
  that `useCopy` surfaces and announces (`clipboard.ts:25-29`). Reuse, no new code.
- Button: shadcn-vue `Button` (`variant="toolbar" size="kira"`, text swap on `copied`, same as
  `AdeRunOutcome.vue:145-147`, `ConfigFileBar.vue:59-66`).
- Server state: log pages already come through TanStack Query (`useRunLog`, `useLog`); the copy
  button reads the same cache. No Pinia state (no shared client state).
- Styling: Tailwind utilities only. ANSI stripping: `anser` already in use (`lib/ansi.ts:1`),
  `Anser.ansiToText`.

## Tasks (in order, one commit each)

Shared spec helper, used by tasks 1-3 (local to each spec file, not exported):

```ts
const longLog = (n: number) =>
  Array.from({ length: n }, (_, i) => ({
    seq: i + 1,
    at: 1_000 + i,
    stream: 'stdout',
    text: `${i === 0 ? '\u001b[32mfirst\u001b[0m' : `line ${i + 1}`} of the log\n`,
  }));
```

300 lines at 18 px is ~5400 px, far above the 960 px default viewport
(`packages/workbench/src/testing/ui/fixtures.ts:97`).

### 3. `feat(workbench): Copy log on the run log tab and the headless session`

## Out of scope

- Opening the run tab automatically when an agent starts a run (scratchpad
  `mcp-script-terminal-plan.md` section 4): not needed for the root cause.
- Running MCP runs in a terminal tab: headless by design (stored masked log, timeout, no stdin).
- Copy buttons on inline ADE logs (session rows, run outcome, needs rows, worktree setup) and Docker
  or Kubernetes logs: they gain selection through LogLines; their callers already offer Copy for
  agent or their own toolbars.
- Cross-row selection beyond mounted virtual rows (selection-aware copy handler): Copy log covers the
  whole-log case.
