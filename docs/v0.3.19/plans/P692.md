## Decisions (open questions 1-4)

1. Colored actions: every step action, by its own `tone` (the v0.3.11 set). Start (`session`,
   `run`, `resume`, `nextPass`) agent; Finish and Next stage green; Approve amber; Take over and
   Retry red; Archive purple. Reason: tone is already computed per action. Coloring Start and Finish
   only would need a kind filter on top of tone, a second rule for one button. Red drops the
   `dialog-danger` tint: Take over and Retry are not destructive, and the tint signals a
   destructive commit (U137). Listed as a visible change.
2. Icon card button: border and glyph both take the tone. Same class set as the text button (one
   cva entry for both looks). 1px border alone on a `size-control` button reads weak; red already
   colors glyph and border today. The other card header icons stay neutral `toolbar`. U150 does not
   fire (glyph inherits `currentColor`, no class on `CodiconIcon`); ARCHITECTURE gets the exception
   sentence.
3. Mechanism: new cva axis `outline` on theme `buttonVariants` (`agent|green|amber|red|purple`, empty
   base strings) plus five `compoundVariants` keyed on `variant: 'dialog'`. Hosts bind
   `variant="dialog" :outline="action.tone"`; no map, no ternary. vue-tsc fails if `TaskAction.tone`
   gains a value the axis lacks. Classes: border, text, `focus-visible:outline-*` in the tone, no
   fill, hover stays `dialog`'s `hover:bg-field`.
   Guards:
   - U210 (next free number at implementation time, see step 3): a `Button` or
     `TooltipIconButton` carrying the `ade-task-action-` testid without `:outline="action.tone"`,
     without literal `variant="dialog"`, with a bound `:class`, or with a color class.
   - U211: `outline` on any `Button`/`TooltipIconButton`/`SplitButton` outside
     `AdeTaskActionButton.vue` and `TooltipIconButton.vue` (the pass-through). Enforces "step action
     alone".
   UI spec `ade-v2-action-tone.spec.ts`: computed `border-top-color` and `color` of
   `ade-task-action-session` and `ade-task-action-finish` in card, panel header and workflow block,
   plus focus outline color in the panel. Expected values resolve from live tokens (`--kira-agent`,
   `--kira-status-green`) through a probe element, never a hex literal.
   "Both themes": only one theme exists. The spec runs in it. Since expectations come from the live
   tokens, a future light `:root` passes with no spec edit; add a theme loop when a theme switch
   exists. Recorded in Result, not faked.
4. U125: drop the dead `ACTION_CLASS` name from its regex (keeps no dead names: a name nobody can
   define guards nothing). Message and exempt list unchanged. Also remove the dead
   `ACTION_CLASS` loop and its docstring mention in `scripts/uiaudit/classes.ts`.
