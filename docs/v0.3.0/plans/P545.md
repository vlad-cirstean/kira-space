## Decisions

### D1 Merged-list item model

- One list, one model: `details/taskChain.ts` stays the merged-list model (P543 D1 reserved this). Its input becomes
  one object, so a later source adds a field, not a positional argument:

  ```ts
  export interface ChainSources {
    handovers: readonly Handover[];
    proofs: readonly TaskProof[];
    events: readonly TimelineEvent[]; // [] while the toggle is off
  }
  export type ChainLayer = 'chain' | 'timeline';
  export type ChainEntry =
    | { kind: 'handover'; layer: 'chain'; key: string; at: number; handover: Handover }
    | { kind: 'proof'; layer: 'chain'; key: string; at: number; proof: TaskProof }
    | { kind: 'event'; layer: 'timeline'; key: string; at: number; event: TimelineEvent };
  export function taskChain(sources: ChainSources): ChainEntry[];
  ```

- `layer` names which toggle governs an entry. `chain` entries always show; `timeline` entries show only while the
  toggle is on. The component gates by passing `events: []` when off, so `taskChain` stays merge and sort only; a
  later kind with its own layer filters the same way (D6).
- `details/taskTimeline.ts` shrinks to the event builder:
  `timelineEvents(task, branches, artifacts): TimelineEvent[]`, unsorted.
  `TimelineEvent = { key; type: 'created' | 'branch' | 'artifact'; at; label; url; sessionId }`. The `draft` field
  and the handover branch go: handovers and drafts are already chain cards with stage names (`entryTitle`,
  `noteStage`), time, author and origin session. Showing them twice in one list is the duplicate this phase removes.
  Detected artifacts (empty `id`, no real time) stay skipped. `TimelineBranch` stays exported here (callers
  `AdeDetailsTab`, `AdeTaskPanel`, `AdeArchivedPanel` keep their imports).
- Event keys keep their prefixes (`created`, `branch:<id>`, `artifact:<id>`); chain keys stay `handover:<id>`,
  `proof:<id>`. No collision.

### D2 Sort direction and ties

- Newest first for every entry, the P542 and P543 rule. The old timeline was oldest first; it now follows the notes.
- Time per entry: handover `updatedAt` for a draft, else `createdAt` (unchanged); proof `closedAt` (unchanged);
  event `at` (task `createdAt`, branch `addedAt`, artifact `createdAt`).
- Same millisecond: rank proof with diagram 0, handover 1, other proof 2, event 3, the `created` event 4, then
  `compareNatural(key)`. `created` ranks last so a branch made in the same millisecond as its task sits above it;
  creation stays the bottom row.

### D3 Toggle UX

- The `Collapsible`, its chevron trigger and the "Timeline (n)" header go. `AdeTaskTimeline.vue` is deleted.
- The toggle sits in the chain header row of `AdeTaskChain.vue`, after the title and before the add and attach
  buttons: shadcn-vue `Toggle` (`@theme/components/ui/toggle`, `size="kira"`, as `LogsView.vue` uses it) with a
  `history` codicon and the text "Timeline", wrapped in the existing tooltip pattern ("Show task events in the
  list"). `v-model` binds the store value (D4). Testid stays `ade-details-timeline-toggle`; reka-ui gives it
  `aria-pressed` and `data-state="on|off"`.
- The toggle shows for archived (read-only) tasks too: it changes the view, not the task.
- Event rows render through a new `details/AdeTimelineEntry.vue` (`<script setup lang="ts">`, Tailwind only): one
  `AdeRow` (`as="div"`), lead slot a codicon per type (`add` created, `git-branch` branch, `link` artifact), label
  `formatRelative(at)`, body the label (an `<a>` opening `control.openExternal` when `url` is set, as today), actions
  slot `AdeOriginSession`. Attributes: `data-testid="ade-details-timeline-entry"`, `data-kind="event"`,
  `data-event="<type>"`. Rows sit in the same `flex flex-col gap-2` list as the cards, in time order between them;
  slimmer than a card on purpose, so events read as context around notes and proof.
- Empty state (`ade-notes-empty`) shows when no `chain`-layer entry exists and the composer is closed, whatever the
  toggle; with the toggle on, event rows follow it (the `created` row always exists).
- Title `space.ade.proof.chain.title` ("Notes and proof") stays.

### D4 Default and persistence

- Default off: the list opens as notes and proof only, as the Details tab looks today with the timeline closed.
- One preference for all tasks, persisted per device: `usePersistedState('kira.ade.details.timeline', false)`
  (`@workbench/behaviour/persisted`, the repo's localStorage wrapper the review agent panel uses for
  `kira.ade.review.agentPanel`; it adds key naming, schema check and cross-window sync over raw VueUse
  `useLocalStorage`). A toggle is a view preference; per-task, in-memory state reset on every start reads as a
  collapsible, which the SPEC row removes.
- Owner: new Pinia store `state/adeDetailsList.ts`, `useAdeDetailsListStore` (`showTimeline` ref,
  `setShowTimeline`). One concern: how the Details list renders. `adePanelTabs` stays the panel-tab store and loses
  `timelines`, `timelineOpen`, `setTimelineOpen` and the `timelines` line in `prune`; its comment drops the timeline
  clause. No settings key, no backend change: the PARALLEL B5 condition holds.

### D5 Data flow

- `AdeTaskChain.vue` props become `{ task: Task; branches: readonly TimelineBranch[]; readonly?: boolean }`
  (`task.id` replaces `taskId` inside). It calls `useHandovers`, `useTaskProofs` (unchanged) and `useTaskArtifacts`
  (same key as `AdeLinkGroups`, so TanStack Query serves one cached fetch to both; no new request). `events` is
  `computed(() => store.showTimeline ? timelineEvents(task, branches, artifacts) : [])`.
- `AdeDetailsTab.vue` renders `AdeLinkGroups` then `AdeTaskChain` only; comment updated.
- No bridge, wire, Go or migration change.

### D6 Extension points for P546 and P547

- P547 (audit trail): adds `kind: 'audit'` to `ChainEntry`, an `audit` field to `ChainSources`, a rank, and an
  `AdeAuditEntry.vue` branch in the `v-for`. It picks the layer: `timeline` (shown with the toggle) or a third layer
  with its own toggle in the same header row (a second `Toggle` and a second persisted key in
  `adeDetailsList`). P545 decides neither; the store and header row take either without a rewrite.
- P546 (forward edits): edits live in entry components (`AdeNoteEntry` save, `AdeProofEntry` unlink,
  `AdeProofAttachMenu`, `AdeLinkGroups`), not in the list. Event rows are read-only, so P546 never offers a forward
  on `kind: 'event'`. The list adds no edit surface P546 must handle.
- Both read `entry.kind` and `entry.layer`; neither needs `taskTimeline.ts`.
