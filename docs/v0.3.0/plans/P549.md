## Decisions

### D1 Encoder: sharp, lossless WebP, in-process at capture

- Playwright `screenshot()` emits only `png` or `jpeg`. PNG is lossless, so the PNG buffer is the in-memory
  capture result. `captureShot` encodes it to WebP before the first write. No PNG file ever touches disk. That
  is WebP generated at capture, not a post-conversion step over files.
- Library: `sharp` (Apache-2.0) over prebuilt libvips (`@img/sharp-libvips-*`, LGPL-3.0-or-later). Both fully
  open source; no gated tier. Already in the toolchain: `site/package.json` pins `sharp` `0.35.5` (Astro's
  image service). Add `"sharp": "0.35.5"` to `packages/workbench/package.json` `devDependencies` (same exact
  version, so bun keeps one copy). Explicit dependency instead of resolving through the site workspace like the
  fonts do: the encoder is the capture module's own runtime need.
- Rejected `cwebp`: a system binary, not installed in the sandbox or CI image, not version-pinned by the
  lockfile, so byte-identical reruns across machines are not guaranteed. A hand-rolled encoder is out of question.
- Settings: `sharp(png).webp({ lossless: true, effort: 6 })`. Measured on the 12 committed PNGs in this
  sandbox (sharp 0.35.5): PNG 1,589,192 B, lossless WebP 469,386 B (29.5 %), lossy q90 611,332 B (larger
  than lossless). Every file decodes to RGBA identical to its PNG source, alpha included. Two encodes of each
  file are byte-identical (deterministic, so `git status --porcelain screenshots/` stays clean on rerun).
  Encode time 50 to 420 ms per file. Lossy gains nothing on UI pixels and loses text detail, so lossless.
- One encoder function: `encodeWebp(png: Buffer): Promise<Buffer>` in `capture.ts`, exported (P550 reuses it,
  see Contract).

### D2 Output paths and names

- `screenshots/<id>-detail.webp` and `screenshots/framed/<id>.webp`. Same stems as today, only the extension
  changes, so `site/tests/*.spec.ts` `-detail` checks keep working.
- One writer: `saveShot(name: string, png: Buffer): Promise<string>` encodes with `encodeWebp` and writes
  `screenshots/<name>.webp` (creating parent dirs), returns the path. `name` may hold one `/` subdir
  (`framed/<id>`); reject an absolute path, `..` or an extension in `name` (throw). `captureShot` uses it for
  both files.
- Readiness steps (mouse to 0,0, hide Monaco scrollbars, `document.fonts.ready`, Inter loaded, no console
  errors) move from `captureShot` into exported `prepareCapture(page, consoleErrors)`. `captureShot` calls it
  first. P550's element crops need the same readiness, so this split is the only crop-ready hook P549 adds.
  Crop mechanism, padding, crop names and crop shadow stay P550's.

### D5 macOS 26 frame

Reference: none verifiable. No macOS in the sandbox. A web search found no Apple point values for macOS 26
(Tahoe) window radius, traffic-light size, spacing or shadow; only forum commentary (a larger window radius
than Sequoia, several radii across Apple apps, traffic lights at the same edge distance as Sequoia in one
measured comparison). Per the SPEC row, the user supplies the reference. **Question for the user:** a macOS 26
screenshot at 2x of a dark window with a full-size content view and hidden title bar (Kira Space itself on
macOS 26 is ideal), uncropped so the corners, traffic lights and shadow show.

Until it arrives the implementer builds the frame with the provisional values below, all in one exported
`FRAME` constant in `capture.ts` (CSS px, rendered at `SCALE`), so the reference changes numbers only:

| Part | Provisional value | Today |
|---|---|---|
| Window corner radius | 16 | 10 |
| Traffic lights | 3 circles, 12 diameter, centres 20 apart, first centre at 20,17 (unchanged position) | same geometry |
| Light colours | flat fills `#FF5F57`, `#FEBC2E`, `#28C840`; 0.5 px inner rim `rgb(0 0 0 / 0.12)`; no darker stroke | fills plus darker 0.5 px stroke |
| Rim | inset 1 px `rgb(255 255 255 / 0.1)` plus outer 0.5 px `rgb(0 0 0 / 0.5)` hairline | inset rim only |
| Shadow | `0 18px 48px rgb(0 0 0 / 0.45)`, baked into the image | none (site adds CSS shadow) |
| Canvas margin | top 32, left 56, right 56, bottom 80; transparent | none |

- Traffic-light colours and rim live in `screenshots/assets/traffic-lights.svg` (rewrite it); geometry and
  window values live in `FRAME`. The SVG stays the one source for the button art.
- `frame()` change: outer `#canvas` div with `FRAME.margin` padding and transparent background holds `#frame`
  (window, radius, rims, shadow, lights). Screenshot `#canvas`, not `#frame`: a locator screenshot clips to the
  element box and would drop the shadow. Framed size becomes (1024 + 112) x (640 + 112) CSS px = 2272 x 1504
  px at scale 2 with provisional margins.
- Raw full-window capture still never contains window buttons; detail crops stay unframed.
- Frame is final only once the user reference is applied: measure radius, light diameter, pitch, offset,
  colours and shadow extent from it, set `FRAME` and the SVG, regenerate the 3 Space shots, state the reference
  file in the commit message and in `docs/ARCHITECTURE.md`. P549 stays open until then; the orchestrator asks
  the user now so it does not block the implementer.

## Contract for P550

P550 reads this; P549 owns and lands it first.

- Format: lossless WebP (`encodeWebp`: sharp `webp({ lossless: true, effort: 6 })`), scale 2. No PNG in
  `screenshots/` or `site/` (N15 fails the lint).
- Paths, relative to repo root:
  - `screenshots/<id>-detail.webp`: 880 x 660 px, opaque, unframed phone crop.
  - `screenshots/framed/<id>.webp`: full window 1024 x 640 CSS px inside the macOS 26 frame, RGBA,
    transparent margin with baked shadow. Size comes from `FRAME`; read width and height from the image
    metadata (`framedWidth`, `framedHeight`), never hardcode.
  - `screenshots/assets/`: frame source assets, not output; never glob it as shots.
  - New P550 outputs (crops) go under `screenshots/` through `saveShot(name, png)`; P550 picks the names and
    any subdir (for example `crop/<id>`), keeping `<id>-detail` and `framed/` meanings unchanged.
- Exports from `@workbench/testing/screenshots/capture`: `WINDOW`, `SCALE`, `FRAME`, `CAPTURE_LAUNCH`,
  `CAPTURE_NOW`, `installCaptureFonts`, `prepareCapture(page, consoleErrors)`, `encodeWebp(png)`,
  `saveShot(name, png)`, `captureShot(page, { id, detail, consoleErrors })`. Frame applies to full-window shots
  only; P550's crop shadow is its own code in its own file.
- Site: `site/src/lib/shots.ts` `ResolvedShot` = `ShotDef` plus `framed`, `framedWidth`, `framedHeight`,
  `detail`, `detailWidth`, `detailHeight`, `social`. P550 may reshape the manifest and add crop fields; it
  rebases onto P549's edits of `lib/shots.ts` and `Shot.astro`.
- Shared-file additions to `PARALLEL.md` B7 table (beyond what it lists): `site/src/lib/shots.ts`,
  `site/src/components/Shot.astro`, `site/src/layouts/Landing.astro`, `README.md`, `site/tests/{site,docs}.spec.ts`
  (P549: WebP and frame consumption; P550: manifest and crop entries). Additive, rebase cleanly.
- Generated, uncommitted shots in CI (P550) use the same paths; whether a path is committed or CI-only is P550's
  call.
