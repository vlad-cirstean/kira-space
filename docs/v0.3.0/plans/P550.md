## Decisions

### D1 Images are not committed; CI generates every product shot

- No product shot is committed, PNG or WebP. `screenshots/` keeps only `assets/` in git. `.gitignore` gains
  `/screenshots/*` and `!/screenshots/assets/`. The implementer `git rm`s every tracked image under `screenshots/`
  (P549's 12 WebP, C6). P549's `screenshots/**/*.png` ignore line folds into the new rule.
- Which shots generate in CI: all of them (the 6 window shots plus the 2 crops of D4). Which stay committed: none
  today. Rule for later (P551): an image no shot spec can produce (a hand-made diagram, an external logo) is
  committed as WebP under `site/src/assets/`; anything a shot spec can produce is generated, never committed.
- README: the 6 images point at stable published URLs `https://vlad-cirstean.github.io/kira-studio/shots/<id>.webp`
  (D7). They update with each Pages deploy, that is each chapter merge.
- Why not commit WebP only: the user asked for a build step in the publishing Action and no image churn in the repo.
  Committed copies would drift from the UI between manual runs, which is the problem this phase removes.

### D2 Crop kinds

Three kinds, one per capture spec:

- `window`: full window, P549 frame, plus the phone `detail` crop. Only for overview, hero, layout and module
  switching shots. All 6 existing shots stay `window`: each shows a whole module as hero or highlight.
- `floating`: a dialog, popover or menu. Element screenshot of the matched element, composited onto a transparent
  canvas with `padding` (default 24 CSS px) and one light shadow (lighter than the window frame's), corners clipped to the element's computed
  `border-radius`, so backdrop and page content never show. No window frame.
- `region`: a panel or toolbar inside the window. Viewport screenshot clipped to the element's bounding box grown by
  `padding` (default 12 CSS px), clamped to the viewport, so the real neighbouring UI shows at the edges. No frame,
  no shadow; the site gives it the same rounded ring as a window shot.
- All kinds capture at scale 2 (`SCALE`) in the 1024 x 640 window (`CAPTURE_LAUNCH`), WebKit, as today.
- Mechanism: Playwright, no new library. `floating` composites exactly like P549's `frame()` does: a fresh context at
  scale 2, `setContent` with the element PNG as a data URL, `locator('#wrap').screenshot({ omitBackground: true })`.
  Shadow: `0 1px 2px rgb(0 0 0 / 0.12), 0 8px 24px rgb(0 0 0 / 0.16)`; padding leaves room for it. Output goes
  through `saveShot` (lossless WebP keeps alpha).
- Crops are applied at capture, not in a later build step: the element's box is known only in the live page, and a
  post-hoc crop of a full screenshot would need coordinates that drift with the UI.

### D3 Crop spec manifest: `site/src/data/shotCapture.ts`

- New file, zero imports, so both the site (Astro) and the shot specs (`tsconfig.tests.json`) can load it.
  `site/src/data/shots.ts` cannot be that file: it imports `IconName` from `icons.ts`, whose `?raw` SVG imports
  only resolve under Astro.
- Shape:

```ts
export type ShotCapture =
  | { readonly kind: 'window'; readonly detail: { readonly x: number; readonly y: number } }
  | { readonly kind: 'floating'; readonly selector: string; readonly padding?: number }
  | { readonly kind: 'region'; readonly selector: string; readonly padding?: number };

export const SHOT_CAPTURE = {
  'studio-data-grid': { kind: 'window', detail: { x: 265, y: 130 } },
  // ... the other 5 window shots with today's detail coordinates ...
  'studio-grid-row-menu': { kind: 'floating', selector: '[data-testid="context-menu"]' },
  'space-commit-detail': { kind: 'region', selector: '[data-testid="detail-region"]' },
} as const satisfies Record<string, ShotCapture>;

export type ShotId = keyof typeof SHOT_CAPTURE;

/** Files under screenshots/ that one shot writes; the single source for site, fill script and cache. */
export function shotFiles(id: ShotId): { main: string; phone?: string };
```

- `shotFiles`: `window` gives `framed/<id>.webp` and `<id>-detail.webp` (C2); `floating` and `region` give
  `crop/<id>.webp`. `screenshots/crop/` is P550's own new output folder; P549's folders are not touched.
- `site/src/data/shots.ts` keeps the site copy (title, alt, caption, icon, label). `ShotDef.id` becomes `ShotId`
  (type-only import), so a typo fails `astro check`. Its file comment points at `shotCapture.ts`.
  `resolveAllShots` throws when a `SHOT_CAPTURE` id has no `SHOTS` entry or the reverse.
- Naming: `<app>-<subject>` kebab case, as today (`studio-`, `space-`). No kind in the name.

### D5 Astro consumption, no optimisation

- `site/src/lib/shots.ts` reshaped on top of P549's version (C5):
  - Globs `../../../screenshots/**/*.webp` once (`import.meta.glob`, eager, `ImageMetadata`), excluding
    `assets/`. Looks up `shotFiles(id)`.
  - Shot files are served as is (no re-encoding), as P549 set up. The one `getImage` call stays: P549's `social`
    PNG for `og:image`, window shots only.
  - `ResolvedShot` = `ShotDef` plus `kind`, `placeholder: boolean`, and: `window` keeps P549's `framed*`,
    `detail*`, `social`; crop kinds get `crop`, `cropWidth`, `cropHeight`. A discriminated union on `kind`.
  - Missing file: build fails with P549's `Missing screenshot <file>` error unless placeholder mode is on (D8).
    Placeholder mode returns `site/src/assets/shot-placeholder.svg` (committed, neutral, 2048 x 1280 viewBox, no
    text) for every field and logs one warning per missing id; `social` falls back to the SVG URL.
- `Shot.astro` by kind:
  - `window`: P549's markup unchanged.
  - `floating` and `region`: one `<img src={crop}>` with `width` and `height` set to half the pixel size (CSS px at
    scale 2), classes `mx-auto block h-auto max-w-full`. Never upscaled: a narrow menu sits centred in the column at
    its natural size, so text stays the same size as in window shots. `region` adds `rounded-xl ring-1
    ring-border-strong overflow-hidden`; `floating` adds nothing (shadow is in the image). Same source on phone and
    desktop. Link to full size points at `crop`.
  - Caption block unchanged, so captions align the same for every kind.
- `Landing.astro`: hero and highlights must be `window` shots; throw at build otherwise (`hero.social` needs it).

### D8 Flake rule, fill script, local dev

- `site/scripts/shots-fill.ts`, run by root script `site:shots:fill`. For every `SHOT_CAPTURE` id it checks the
  `shotFiles` paths under `screenshots/`:
  - Default (no flag): strict. Any missing file prints the list and exits 1. Local verification after
    `bun run screenshots`; proves every manifest id has a capture call.
  - `--fallback <dir>` (CI): a missing file is copied from `<dir>` when present, with a `::warning::` naming the shot.
    Still missing: `::warning::` plus `KIRA_SITE_SHOTS=placeholder` appended to `$GITHUB_ENV`. Writes
    `complete=true|false` to `$GITHUB_OUTPUT` (true only when nothing was filled) and a short list to
    `$GITHUB_STEP_SUMMARY`. Exits 0, so one bad shot never blocks the deploy.
  - Manifest error (unknown kind, duplicate output path): exit 1 in both modes.
- Fallback order per shot: fresh capture, then last-good cached copy, then placeholder. A placeholder deploy is
  visible as a workflow warning, never silent.
- Placeholder mode (`lib/shots.ts`): on when `KIRA_SITE_SHOTS=placeholder` or under `astro dev`
  (`import.meta.env.DEV`). `site:build` without it stays strict.
- Local dev with no images: `bun run site:dev` works at once with placeholders and warns
  `Missing screenshot ... Run: bun run screenshots`. Real images: `bun run screenshots`, then `site:dev` or
  `site:build`. No separate generate command: `bun run screenshots` is it.
