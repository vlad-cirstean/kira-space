## Decisions

### D1 Library: `mermaid` 12.2.0 plus `dompurify` 3.4.17, both exact, in `frontend/package.json`

- `mermaid` is MIT at package level. Every feature used (parse, render, `base` theme, dagre layout) is in the
  MIT package. No paid tier gates anything (Mermaid Chart is a separate hosted product, not used).
- Runtime deps, checked with `npm view mermaid@12.2.0 dependencies`: d3, dagre-d3-es, cytoscape, khroma,
  marked, stylis, roughjs, dayjs, katex, `@mermaid-js/parser`, `@braintree/sanitize-url`, es-toolkit
  (MIT/ISC/Apache-2.0); `dompurify` (MPL-2.0 OR Apache-2.0); `chevrotain` (Apache-2.0); `elkjs`
  (EPL-2.0 OR GPL-3.0-or-later). All OSI open source, no community/commercial split. ELK is not used (D3 sets
  `layout: 'dagre'`), so its chunk is never loaded.
- Version: 12.3.0 is 3 days old (published 2026-11-03), under the two-week rule; 12.2.0 (2026-10-13) is the
  newest that qualifies. `dompurify` 3.4.17 (2026-10-12) sits inside mermaid's `^3.4.12` range, so one copy.
- `dompurify` is a direct dependency because D3 sanitizes mermaid's SVG output again with a private instance.
- Hand-rolled renderer declined: Mermaid syntax has dozens of diagram grammars; no requirement here justifies
  a parser. ECharts (already in) draws charts, not graphs from text.
- `frontend/package.json` (beside `modern-screenshot`), not root: only the proof window uses it.
- Load lazily: `diagramRender.ts` does `await import('mermaid')` and `await import('dompurify')`. Nothing
  imports either statically, so the main window entry and every non-diagram step stay unchanged.

### D3 Render safety (layered; no layer trusts the one before it)

1. Go input rules (D4) refuse what changes config or reaches out: front matter, `%%{...}%%` directives,
   `click` lines, CSS `url(` and `@import`, control characters. Caps bound render cost.
2. Mermaid config, set by `diagramRender.ts` on every render (one serial queue, since `initialize` is
   global): `startOnLoad: false`, `securityLevel: 'strict'` (labels HTML-encoded, click and links disabled),
   `htmlLabels: false` (pure SVG text, no `foreignObject`, so nothing HTML-shaped and a clean canvas for the
   screenshot), `maxTextSize: 20000`, `maxEdges: 500`, `layout: 'dagre'`, `theme: 'base'` with
   `themeVariables` from tokens (D6), `secure` = mermaid's default list plus `theme`, `themeVariables`,
   `htmlLabels`, `layout`, `fontFamily`.
3. Second sanitize: a private `DOMPurify(window)` instance (never the default one; mermaid uses the default
   internally and a global hook would change its label handling). Profile `svg` plus `svgFilters`;
   `FORBID_TAGS` `script`, `foreignObject`, `image`, `a`, `iframe`; a `uponSanitizeAttribute` hook drops any
   `href` or `xlink:href` not starting with `#`. Keep mermaid's `<style>` (add it with `ADD_TAGS` only if
   the svg profile drops it; check once). Output over 2 MiB is not mounted: error state "too large".
4. Window CSP (`frontend/index.html`, unchanged): `default-src 'self'; script-src 'self'; img-src 'self'
   data:`. No inline script runs, no remote image, font or fetch loads, including during mermaid's own
   measuring pass in its temporary off-screen node. Mermaid 12.2.0's `dist/chunks/mermaid.core` holds no
   `eval(` or `new Function(`, so `script-src 'self'` needs no widening.
- Mount: `v-html` of the sanitized string, with a one-line comment naming steps 2 and 3 (repo precedent:
  `MobileQr.vue`, `LocalFileView.vue`).
- `securityLevel: 'sandbox'` declined: it renders into an iframe loaded from a `data:` URL, which the CSP's
  `default-src 'self'` blocks (no `frame-src`), and the screenshot cannot clone an iframe's content.
- `<img src="data:image/svg+xml,...">` declined: an image cannot use the app's web font, so text measured in
  the DOM would overflow inside the image.

### D4 Go validation and what the agent is told

New file `internal/proof/diagram.go`, `checkDiagram(data json.RawMessage) (any, error)`, called from the
`StepInput.validate` switch (`case ViewDiagram`). Every refusal is an `InvalidError`, so the agent gets it as a
tool error naming the field and limit (existing `proofResult` path). Rules in order:

1. `data.source` required, valid UTF-8, 1 to 20000 bytes after normalization, at most 1000 lines.
2. No control characters except `\n` and `\t`.
3. First line not blank and not a `%%` comment: must not be `---` ("front matter is not allowed; put the
   title in description"); its first token must be one of `flowchart`, `graph`, `sequenceDiagram`,
   `classDiagram`, `stateDiagram`, `stateDiagram-v2`, `erDiagram`, `gantt`, `journey`, `gitGraph`, `mindmap`,
   `timeline`. Message lists them.
4. Anywhere: no `%%{` ("directives are not allowed"); no line whose trimmed text starts with `click `
   ("click lines are not allowed"); no `url(` or `@import`, case-insensitive ("CSS url() and @import are not
   allowed").

Excluded diagram types and why: `pie`, `xychart`, `quadrantChart`, `sankey`, `radar`, `treemap` plot numbers,
which the `chart` view already validates value by value; `architecture` loads icon packs; `C4`, `block`,
`packet`, `kanban`, `requirement` are beta or niche; `zenuml` is an external plugin. Before landing, confirm
each allowed keyword against mermaid 12.2.0's detectors (`dist/diagram-api`, diagram definitions) and drop any
renamed one from both lists.

Syntax is not checked in Go: no maintained Go Mermaid parser exists, and running the JS parser in the backend
means a JS runtime in the app for one check. A partial Go grammar check would refuse valid text. So a
header-valid diagram with a syntax error is stored; the window shows the parser message plus the source
(D5), so the proof still reads. The tool text says so and gives the one tip that prevents most parse errors
(quote labels with punctuation). Gap recorded in `docs/ARCHITECTURE.md` Known open items: the agent hears of a
parse error only if the user tells it.

### D5 Frontend viewer

- `frontend/src/studio/proof/diagramRender.ts`: `renderDiagram(source, theme, id): Promise<string>`. Serial
  promise chain; lazy imports (D1); `initialize` (D3.2), `await mermaid.parse(source)`, `mermaid.render(id,
  source)`, sanitize (D3.3), size check. Throws `Error` with mermaid's message (first 500 characters) on
  failure. Ids: `proof-diagram-<n>` from a module counter, so compare view and tab remounts never collide.
- `frontend/src/studio/proof/ProofDiagram.vue`, `<script setup lang="ts">`, Tailwind utilities only, no
  scoped style. Props `payload: ProofDiagramPayload`, `description: string`, `seed: {top: number; left:
  number}`. Emits `update:scroll [top, left]`, `ready`.
  - Render via VueUse `computedAsync` (keyed on `payload.source` plus the theme), error captured by its
    `onError`. Theme from `useChartTheme()` (`charts/theme.ts`, VueUse mutation observer), so a theme
    switch re-renders. Not TanStack Query: rendering is local computation; the step itself already comes
    from `useProofStep`. No Pinia store: no state outlives the component.
  - Success: `<figure data-testid="proof-diagram" :data-diagram-type="payload.type" :aria-label>` with an
    `overflow-auto size-full` scroller holding the svg. After the first mount, restore `seed` scroll on
    `nextTick`, then emit `ready`. Scroll changes go out through VueUse `useScroll` on the scroller
    (`update:scroll`); `useStepViewState` already throttles and debounces.
  - Error: `data-testid="proof-diagram-error"`: existing `EmptyState` (icon `warning`, title "Diagram does not
    parse", description = error text as text interpolation, never HTML), and below it the source in a
    read-only `MonacoHost` (language `plain`, `data-testid="proof-diagram-source"`). Emit `ready` too: a
    capture shows the error state.
  - No shadcn-vue primitive is needed (no button, dialog or menu); `EmptyState` and `MonacoHost` are the
    existing app components the chart and grid paths use.
- `ProofStepView.vue`: parse `data.data` with `proofDiagramPayloadSchema` in the existing watch branch
  (`diagramPayload` shallowRef beside `chartPayload`; a ZodError lands in `pageError` as today). Render
  `ProofDiagram` in a new `v-else-if` with `:seed="{ top: seed.resultScrollTop, left: seed.resultScrollLeft
  }"`, `@update:scroll="view.setDiagramScroll"`, `@ready="resultReady = true"`.
- `useStepViewState.ts`: add `setDiagramScroll: (top, left) => update({ resultScrollTop: top,
  resultScrollLeft: left })`.
- `pages.ts`: `buildProofPage` view type becomes `Exclude<ProofView, 'chart' | 'diagram'>`.
- `viewIcon.ts`: `diagram: 'type-hierarchy-sub'` (codicon present in `@vscode/codicons`).
- `packages/shared/domain/proof.ts`: `proofViewSchema` gains `'diagram'`; new `proofDiagramPayloadSchema`
  `{ type: z.enum([...D4 list]), source: z.string() }` and its type.
- i18n (`packages/theme/src/i18n/en.json`, under `studio.proof`): `diagram.region.aria` ("Diagram: {description}"),
  `diagram.invalid.title` ("Diagram does not parse"), `diagram.tooLarge.body`, `diagram.source.label`. Wording
