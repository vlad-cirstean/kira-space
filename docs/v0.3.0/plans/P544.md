## Collisions and renames

Go identifiers colliding between `storage/{model,repos}` and `studiostorage/{model,repos}` (measured with a
type/func grep): `AdvancedPatch AdvancedSettings DefaultSettings IsJSONObject IsRenderableTabKind
RenderableTabKinds Settings SettingsPatch TabRecord WindowBounds WindowModes WindowRecord
validateAdvancedSection`; repos: `New Repos SettingsRepo TabsRepo WindowsRepo isUniqueViolation nullInt queryer
rowScanner settingsSelectAllSQL tabsSelectAllSQL upsertAdvancedSection`.

  persists it. `RenderableTabKinds` is the union. Studio `WindowsRepo`, `TabsRepo`, `WindowRecord`,

  `DbAdvancedPatch`, `DefaultDbSettings`, `DbSettingsRepo` (field `Repos.DbSettings`), over the same `settings`

  confirms `DbSettingsRepo.Set` writes only the leaves in its patch (no default write-back); otherwise filter to
  Studio-owned prefixes. Part 2 deletes the family.
- Op log (interim, Part 1 only): Studio `OpRecord` becomes `DbOpRecord`, `OpsRepo` becomes `DbOpsRepo`

## Data migration (package `apps/kira-space/internal/dbfold`)

Replaces `appmerge` and the DB half of `homefold.Runs` wiring in `main.go`. Shape copies `configfold`: marker
JSON in Space `settings`, backup dir, `Step`/`Now` test seams.

- Marker key `dbfold.p544`, value `{"state":"importing"|"done","fresh":bool,"backup":"<dir>"}`.
- Source: `config.ModuleDbPathAt(home)` (`<space>/studio.db`, already moved there by P539's `homefold.Files`).
  `ModuleDbPathAt` survives only for `dbfold`; its comment says so.
- Flow, `Run(o Options) error`, `Options{Home string; Space *sql.DB; Step func(string) error; Now func() time.Time}`:
  1. Marker `done`: return.
  2. No `studio.db`: write `{done, fresh:true}`, return. Covers Space-only users and fresh installs.
  3. Marker absent: write `{importing, backup}` first. Backup dir `<home>/backups/p544-<UTC 20060102T150405Z>`
     (P540 pattern). On resume (`importing`), reuse the recorded dir.
  4. Backup, before any write to either DB: `VACUUM INTO` `space.db` and `studio.db` (unmigrated) in the backup
     dir, each through a `.tmp` then rename; skip a file already present (resume). Step `backup`.
  5. Open `studio.db` with `appstorage.OpenAt(path, legacy.All())`: lifts `0064`/`0065` to `0066`. A
     `SchemaTooNewError` aborts boot as today. Step `upgrade`.
  6. `homefold.Runs` with the legacy handle (P539: copies runs rows, deletes Studio script rows and the
     script-param `secret_values` scope). Step `runs`.
  7. Import on one pinned `*sql.Conn` of the Space pool: `ATTACH` studio, `BEGIN IMMEDIATE`, then:
     - module tables (every 0078 table): insert by column intersection from `PRAGMA table_info` on both sides
       (legacy columns ride along when present). `op_log` goes to `db_op_log`.
     - `proof_task_links`: only rows whose `task_id` exists in `ade_tasks` (FK on); count dropped rows, `slog`.
     - `settings`: Studio-owned keys only: `data.%`, `cache.%`, `api.%`, `dbMcp.%`,
       `advanced.opLogRetentionDays`, `advanced.expensiveQueryRows`, `config.migrated.connections`,
       `config.migrated.api`, `INSERT OR IGNORE`. Never `config.migrated.runs` (homefold forces re-export). When
       Space settings were fresh (no `appearance.%` row before the fold), also apply `appmerge`'s
       `settingRenames` (`appearance.*`, `agent.provider`, `agent.hermetic`, `advanced.notifyPrompts`,
       `advanced.logLevel` to `advanced.gitLogLevel`), moved verbatim into `dbfold`.
     - `config_last_valid`, `secret_values` (connection and api scopes): `INSERT OR IGNORE`, Space wins.
     - `ui_layout`: `modes.{studio,api,docker,kubernetes}.%` and `panel.cellEditor.height`, `INSERT OR IGNORE`
       (P538 M1 asked for the latter).
     - `tabs`: `appmerge.rekeyTabs` logic moved in: orphan window keys go to the Space primary window; an id
       already present gets a fresh id.
     - marker to `{importing, imported:true}` in the same tx. `COMMIT`, `DETACH`. Step `import`.
  8. When `config.migrated.connections` was copied, call `connfiles.DropLegacy(db)` (export the private
     `dropLegacy`; it already uses `hasColumn`, so a second run no-ops). Otherwise `connfiles` exports on its
     first `MigrateOnce` and drops then, as today.
  9. Close legacy handle; remove `studio.db`, `-wal`, `-shm`. Step `remove`.
  10. Marker `{done, fresh:false, backup}`. Step `done`.
- Idempotent: every step resumes. Rerun after `import` sees `imported` and skips to 8. Rerun after `remove`
  with no file and marker `importing` writes `done`.
- `main.go`: `storage.Open`, `repos.New`, `foldConfig`, `foldLegacyHome`, then `foldStudioDB` (replaces
  `studiostorage.Open`, `studiorepos.New`, `carryOverStudio`, `foldLegacyRuns`), then `appwire.Build`. Failure
  is a startup error through `startupfail` like the other folds.
- `appmerge` deleted (package and test). `homefold.Runs` stays (dbfold calls it); `homefold.backupSpaceDB` is
  not called for this path (dbfold's backup covers it).

## Single writer

- `kira.db` keeps `SetMaxOpenConns(1)` and WAL. Studio's writers (op log append and finish, response and gRPC
  history, `metadata_cache` blobs, connection files) now queue behind ADE writes on one connection. No
  `SQLITE_BUSY`; cost is queueing.
- Rule for Part 1: no tx held across network or process I/O. Check every `Begin`/`BeginTx` in the moved
  repos and their callers with `codegraph_explore`; restructure any that waits on an adapter call. Today's
  Studio repos were written to the same rule, so expect none.
- `dbfold` holds the pinned conn for the whole import, at boot, before any service starts: no contention.
- WAL: one file, checkpointed by SQLite's default autocheckpoint. Studio's `Reclaim` (P23 D5 freelist) now
  runs on `kira.db`; harmless (no-op while `auto_vacuum` is NONE or freelist small).
- No measurement planned: the question would only change if a long tx exists, and the grep answers that.
