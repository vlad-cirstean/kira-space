# P537 Merge Kira Space and Kira Studio into one app named Kira Space

Umbrella plan: decisions both Parts depend on, the cut, and why it is cut this way. Step plans:
`P537-part1.md` (enabling, sequential) and `P537-part2.md` (three parallel streams). Base: `aa8a899b`.

Discovery ran through `codegraph_explore` (appwire `Build`/`wire*`, both `main.go`, both `config`,
both `appcore.Deps`, `appupdate.App`, `dbmcp` token and server naming, `secrets` keychain, mode
registries, `WorkbenchShell`/`createWorkbenchHost`, tabs stores), plus shell counts for config and
docs files the index does not cover.

## Why Parts, not a straight 3-way split

The user's suggested cut (A Go, B frontend, C build/tests/docs) has three real couplings at base:

1. B's typecheck and build need `@bindings/*`, generated from the merged Go bridge. Before A lands,
   no merged bridge exists, so B cannot verify. Simulated bindings would pass B and fail on landing.
2. Every Studio path moves (`apps/kira-studio/**`). Root `package.json`, every `tsconfig*.json`,
   `scripts/setup.sh`, `scripts/prepare-worktree.sh`, `scripts/hook-scope.sh`, `biome.json` and
   `knip.json` name those paths. All three streams would edit them. Zero overlap is impossible.
3. The pre-commit hook typechecks per target from `hook-scope.sh` and `package.json`. A stream
   that renames a target breaks the hook in the other streams' worktrees.

So: **P537 Part 1** relocates every Studio file to its final path, rewires every path reference,
and merges the Go bridge to its final bound surface (one binary, one bindings tree). Sequential,
one implementer. **P537 Part 2** then runs three parallel streams that edit content only, against
a frozen bindings surface and frozen paths. No Part 2 stream moves a top-level directory or edits a
file another stream owns.

## Target layout

- One app dir: `apps/kira-space`. `apps/kira-studio` is deleted at the end of Part 1.
- Go module path stays `github.com/kirathecat/kira-studio`. It names the repo, not the app.
- Studio Go packages with no Space twin move as-is: `apps/kira-studio/internal/X` to
  `apps/kira-space/internal/X` (adapterhost, adapters, agentapi, apifiles, apivars, connections,
  connfiles, datagrip, dbmcp, enginecache, grpcclient, httpclient, ipcfixture, kubernetes,
  localauth, mask, maskreview, maskrules, mcpauth, page, postman, preconnect, proof, queryplan,
  tableref, tree). `apps/kira-studio/cmd/g1measure` to `apps/kira-space/cmd/g1measure`.
- Studio frontend: `frontend/src` to `apps/kira-space/frontend/src/studio/`; `frontend/proto` to
  `apps/kira-space/frontend/proto/`; `vite.proto.config.ts`, `tsconfig.proto.json` beside them.
- Studio tests: suites with a Space twin go to `apps/kira-space/tests/<suite>/studio/` (contract,
  e2e-real, fixtures, perf, screenshots, ui, unit, visual). `ipc`, `proto`, `support` have no twin
  and go to `apps/kira-space/tests/<suite>/`.

## Bridge surface (frozen at end of Part 1)

18 service names exist in both bridges. Rule: a service over a process-wide singleton becomes one
service; a service over per-home or per-DB state stays twin until P539 to P541, Studio side renamed
`Studio<Name>`.

| Service | Verdict |
|---|---|
| Agent, Approvals, Prompts | One (code identical). One `approvals.Queue`, one prompt router process-wide. |
| Files | One. Union of methods (Studio's set is larger); name collisions resolved in Part 1. |
| KeepAwake | One controller, one `caffeinate` child. Union of features. |
| Layout | One, over Space's layout table. Studio rows imported once (Stream A). |
| Lifecycle, Link, Windows, Update, Terminal | One each. One window registry, one PTY registry, one updater (`appupdate.Space`). |
| LlmPrompts | One, over Space's `llm-prompts.json`. Studio overrides merged in once (Stream A). |
| Tabs | One. Routes Studio tab kinds to Studio DB `tabs` (keeps `connection_id` and its FK), the rest to Space DB. List merges both. |
| CustomScripts, ScriptRuns | One bound service each, routing in Go over both homes' stacks (list is the union, a call routes by script id, create goes to Space home). Router deleted by P539 when `runs/` folders merge. |
| ConfigFiles | Twin: `StudioConfigFilesService` (per-home folders until P540). |
| Ops | Twin: `StudioOpsService` (two op logs). |
| Settings | Twin: `StudioSettingsService` (two models until P541). |

Other colliding top-level identifiers (`Events`, `Dialogs`, `Browser`, `Flusher`, arg/result types)
follow their service: one copy for merged services, `Studio` prefix for twins. Event channel strings
that collide with different payloads (for example settings changed) get a `studio:` prefix on the
Studio side. Part 1 writes the final rename table (services, types, channels) into its Result in
`P537-part1.md` before Part 2 starts. That table is the contract Part 2 builds on.

Settings split for app-wide keys: Space settings own `Appearance`, `Agent` (provider, hermetic),
`Advanced.NotifyPrompts` and the process log level. Studio settings keep `Data`, `Cache`, `Api`,
`DbMcp`, `Advanced.OpLogRetentionDays`, `Advanced.ExpensiveQueryRows`. Studio's copies of the
app-wide keys stay in its model, unread, until P541.

## Existing installs

P537 moves no user data. P539 to P541 do the folds.

- Bundle: `Kira Space.app`, `com.kirathecat.kira-space`. Space users update in place through the
  existing updater. Space WebKit storage and windows carry over.
- Studio home `~/.kira-studio` and its `kira.db` stay where they are and are opened in place.
- Studio-only users: `scripts/install.sh --app=studio` installs Kira Space, verifies it, then moves
  `/Applications/Kira Studio.app` to the Trash. The old Studio updater fetches `install.sh` from
  `main` at run time, so its next update takes this path. Releases ship only
  `kira-space-macos-arm64.dmg`.
- Keychain: service `Kira Studio Secrets` (repo-root `internal/secrets`) stays. It is already shared
  by both apps. A Studio-only user sees one macOS access prompt from the new bundle.
- First launch, once, with a marker and a `VACUUM INTO` backup of both DBs to
  `<space home>/backups/p537-<timestamp>/` first (Stream A): re-key Studio tabs to Space's primary
  window; import Studio layout rows for Studio modes; when Space DB is fresh, copy Studio's
  app-wide settings (table above); merge Studio `llm-prompts.json` overrides for ids Space has not
  overridden. Studio windows table is ignored (bounds only, no loss).
- A running old `Kira Studio.app` would write the same Studio DB and config folders. At startup the
  merged app checks for a process from that bundle and shows a startup alert asking to quit it.
- WebKit storage of the old Studio bundle is lost. It holds no data (grep: no `localStorage` use).

## `internal/dbmcp` and `kira-db`

- `dbmcp` moves as-is to `apps/kira-space/internal/dbmcp`. It runs inside Kira Space.
- MCP server name stays `kira-db`, token file names stay. Every user's agent config registers it
  under that name. A rename orphans each registration and its helper script path. P548 builds on
  this name; it may still revisit naming.
- User-facing copy saying "Kira Studio" becomes "Kira Space" (Go: `startupfail` info, About text,
  llmprompts texts; frontend: catalog). Studio module labels ("Studio", "API") stay.
- Token and helper script stay under Studio home until P539 moves them and re-registers.
