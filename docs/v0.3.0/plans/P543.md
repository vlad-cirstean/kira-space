## Decisions

### D1 Data model: one chain, `ade_task_handovers` holds user notes as state `note`

- A user note is a row with `state = 'note'`, `source = 'user'`, `from_step_id`/`from_step_name` = the task's
  current stage when written (snapshot; '' when the task has no stage), `to_step_*` = '', `session_id` = ''.
  Drafts and handed rows keep their rules unchanged (`LatestHandover`, `BoardHandovers`, `HandoverDraft`,
  `FinishedDrafts` filter on `draft`/`handed`, so notes never become a stage's handover or raise the prompt).
- Table name stays: P544 folds both DBs next and renames once if it wants to; a rename here costs every query for
  no behaviour.
- `ade_tasks.notes` is dropped. One store remains.
- `Handovers(taskID)` order stays (draft by `updated_at`, others by `created_at`, newest first). The UI renders
  server order as is: one list, sorted by time, newest first. The drafts-first split in the list goes.
- Wire `Task.notes` stays as a derived, read-only projection: the task's user notes, newest first, bodies
  joined by a blank line. It is exactly the `Notes` input the launch prompts get before `capNotes`, so
  `compose.ts`, the shelf row meta and the mobile Later shelf keep working unchanged. No column backs it.
  Board reads build it in bulk: `BoardHandovers` gains a third query (`state = 'note'`, `created_at DESC, rowid
  DESC`) into `BoardHandover.Notes`; `wireTask` and the archived-task path (find it with `codegraph_explore
  toWireTask BoardHandovers ListArchived`) join it.
- Limits by row kind: a `note` row up to 1 MiB (today's `adeMaxNotesBytes`, key `backend.space.ade.notesTooLong.body`);
  drafts and handed rows keep 16 KiB (`agentmcp.MaxHandoverBytes`). Prompts stay bounded by `capNotes`.

### D2 Migration `internal/storage/migrations/0077_p543_unified_notes.sql`

Register `{Version: 77, Name: "p543_unified_notes", File: "0077_p543_unified_notes.sql"}` in `embed.go`. P543
owns `storage/migrations` in B2 (P539 needs none, P541 owns `studiostorage/migrations`). Steps, in one file, 0067
rebuild pattern:

1. `CREATE TABLE ade_task_handovers_new` = 0057 columns plus `session_id TEXT NOT NULL DEFAULT ''` (0066), with
   `state CHECK (state IN ('draft', 'handed', 'note'))`. Copy every row (all columns). Drop, rename, recreate
   `ade_task_handovers_draft` (partial unique, `WHERE state = 'draft'`) and `ade_task_handovers_task`.
2. Copy notes: `INSERT ... SELECT lower(hex(randomblob(16))), id, '', '', '', '', notes, 'user', 'note', 0, 0, 0,
   created_at, created_at, '' FROM ade_tasks WHERE trim(notes) <> ''` (archived tasks included; body verbatim,
   not trimmed). Time = the task's `created_at`: no edit time exists, and the two creation paths (Add popover,
   capture) write notes at creation, so the chain stays a truthful history. Id shape follows 0023.
3. `ALTER TABLE ade_tasks DROP COLUMN notes`. Before writing it, dump `SELECT sql FROM sqlite_master WHERE
   name = 'ade_tasks'` on a DB migrated to 76 and confirm no CHECK, index, view or trigger names `notes` (0015's
   comment: DROP COLUMN fails under a CHECK naming the column). If one does, rebuild `ade_tasks` in the same
   file instead, preserving every column, index and FK (children reference it with `ON DELETE CASCADE`; the
   migration runner's FK handling decides whether a rebuild is safe: read `sqlitex` migrate code first).
- Rebase rule: if the rebase finds a `0077` already in `storage/migrations` (P539 added one against its plan),
  renumber to the next free version (file name, `embed.go` entry, migration test, this plan, ARCHITECTURE text)
  in the rebase commit.

### D3 Author marker

- Derived, no new column: author `user` when `source = 'user'`, else `agent` (`agent` and `run` are both agent
  output; `run` is a finished run's summary). Frontend helper `noteAuthor(h)` in `notes/noteChain.ts`.
- Each entry shows an `AdeChip` with codicon `account` plus "You" (`common.picker.you.label`) or `hubot` plus
  "Agent" (`memory.common.origin.agent.label`); `data-author="user|agent"` on the entry. A run row adds the
  existing grey "Run" chip as detail. Draft, Finished, Edited chips stay for drafts and handed rows; `note` rows
  show no Edited chip (the user edits their own text).
- Entry title: draft and handed keep `draftFrom`/`fromTo`; a note shows "Note" plus "during {stage}" when
  `fromStepName` is set (new keys, D9).

### D4 Editor instances replaced (one editor: `AdeNotesEditor`)

`AdeNotesEditor.vue` becomes the one rich text editor for adding and editing any note. New API:
props `modelValue: string`, `readonly?: boolean`, `hardBreaks?: boolean`, `label?: string` (aria and toolbar
caption; default `space.common.notes.label`), `compact?: boolean` (smaller min height for popovers and
dialogs), `autofocus?: boolean`; emits `update:modelValue` (debounced `TIMING.autosave`, and on blur) and
`submit` (primary modifier + Enter, through `isPrimaryModifier`). `itemId` and the item-switch watcher go;
callers key instances (`:key`). Emit only after a user edit: a `dirty` flag set in `onUpdate`, cleared on
emit; `setContent` keeps `emitUpdate: false`. Reason: Markdown parse and serialize normalizes text, so a
blur with no edit must not emit a changed string (the stage dialog sends notes only when they differ from the
prefill; `ade-v2-handover.spec.ts` "Move with the draft untouched sends no notes" guards it).

`notesExtensions(opts?: { hardBreaks?: boolean })`: `hardBreaks` sets `Markdown.configure({ markedOptions:
{ gfm: true, breaks: true } })` (`@tiptap/markdown` 3.32.2 exposes `markedOptions`). Agent text is plain text with
single newlines; without it, rendering as Markdown joins its lines. Every agent-authored entry (display and
edit) and the stage dialog when its prefill draft is agent-written pass `hardBreaks`.

Instances:

1. `details/AdeDetailsTab.vue`: the top `AdeNotesEditor` and `saveNotes` go; `notes/AdeNotesChain.vue` takes
   its place (top), then `AdeLinkGroups`, then `AdeTaskTimeline`. The separate `AdeHandoverList` slot goes.
2. `notes/AdeHandoverList.vue` is replaced by `notes/AdeNotesChain.vue` (rename, one term: notes chain). Entry
   body: `AdeNotesEditor` read-only (no toolbar). Edit: the same entry swaps to an editable `AdeNotesEditor`
   seeded with the body, Save (`UpdateHandover`) and Cancel; empty body deletes (existing rule). The plain
   `Textarea` goes. Draft keeps Move on.
3. Composer in `AdeNotesChain.vue`: hidden by default; an "Add note" button (`TooltipIconButton` icon `add` in
   the chain header, plus a text `Button` in the empty state) reveals an `AdeNotesEditor` with Save and Cancel.
   Save (or `submit`) calls `AddNote`, clears the draft and hides the composer. Archived: no button.
4. `stage/AdeStageDialog.vue`: notes `Textarea` becomes `AdeNotesEditor v-model="store.notes" compact`;
   `hardBreaks` when the prefill draft's source is not user. `FieldDescription` hint stays.
5. `AdeAddPopover.vue`: notes `Textarea` becomes `AdeNotesEditor v-model="notes" compact`. Create sends
   `CreateTaskArgs.notes` as today; the engine turns it into the first note row (D6).
- Mobile (`frontend/mobile`): `PlanTaskCard.vue` step-move notes keep their plain `Textarea`; `LaterShelf.vue`
  reads the derived `Task.notes`. Reason: the mobile app has no Wails bridge (`AdeNotesEditor` opens links
  through `control.openExternal`) and no TipTap in its entry; the SPEC row names the desktop `notes/` files.
  Flagged in the Result for the user to confirm or ask as a follow-up; not silently dropped.
