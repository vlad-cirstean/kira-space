## Decisions

### D1 Chain model and ordering key

- Details tab, top to bottom: links of interest (`AdeLinkGroups`, unchanged: Main and Related groups), then the
  task chain, then the timeline (P545 merges it into the chain).
- Task chain = one list of entries, kinds `handover` (P542 rows: user notes, drafts, handed rows) and `proof` (one
  entry per proof session attached to the task). No link entries: links stay grouped on top.
- Ordering key: entry time, newest first, the P542 rule. Handover row: `updatedAt` for a draft, else `createdAt`
  (server order today). Proof entry: the session's `closedAt` (when the agent produced it; an attached old session
  lands at its true place in history, not at link time).
- Tie (same millisecond): rank proof with a diagram step 0, handover 1, other proof 2, then key. This keeps the
  SPEC example (diagram, then handover, then other proof) wherever time cannot decide.
- Reading of the SPEC example: the order work happens in a stage (agent draws a diagram, hands over, the next stage
  adds proof), shown in time order. A fixed kind rank was declined: it splits one stage's work across the list and
  contradicts P545, which merges the timeline into this list by time, newest first.
- Model: `details/taskChain.ts`, `taskChain(handovers, proofs): ChainEntry[]` with
  `ChainEntry = { kind: 'handover'; key; at; handover: Handover } | { kind: 'proof'; key; at; proof: TaskProof }`.
  P545 adds its timeline kind here. No logic beyond merge and sort.

### D2 Proof-to-task link: Studio DB table, written through the task board

- New table in the Studio DB (where `proof_sessions` lives), migration
  `internal/studiostorage/migrations/0066_p543_proof_task_links.sql`, register
  `{Version: 66, Name: "p543_proof_task_links", File: "0066_p543_proof_task_links.sql"}` in `migrations/embed.go`:

  ```sql
  CREATE TABLE proof_task_links (
    session_id TEXT PRIMARY KEY REFERENCES proof_sessions(id) ON DELETE CASCADE,
    task_id TEXT NOT NULL,
    source TEXT NOT NULL CHECK (source IN ('agent', 'user')),
    kira_session_id TEXT NOT NULL DEFAULT '',
    step_id TEXT NOT NULL DEFAULT '',
    step_name TEXT NOT NULL DEFAULT '',
    linked_at INTEGER NOT NULL
  );
  CREATE INDEX proof_task_links_task ON proof_task_links(task_id);
  ```

- One task per proof session (primary key); a task holds any number. A separate table, not columns on
  `proof_sessions`: deleting a session cascades the link, and no rebuild of a table 0065 just rebuilt.
- Cross-DB rule (Studio DB until P544): `task_id` names a Space DB `ade_tasks` row with no foreign key. The board
  checks the task exists and is not archived before every link write (D4). Tasks are never deleted (no
  `DELETE FROM ade_tasks` anywhere; archive keeps the row), so a link cannot dangle today. P544 moves the table into
  the merged DB and adds `REFERENCES ade_tasks(id) ON DELETE CASCADE`; note it in the P544 hand-off (Docs).
- Space DB: no migration. P543 owns only `studiostorage/migrations` in B3; P540's move is filesystem only.
- Rebase rule: a `0066` already in `studiostorage/migrations` at rebase means renumber to the next free version
  (file, embed entry, this plan, ARCHITECTURE text) in the rebase commit.

### D3 Retention

- `pruneClosed` keeps the newest `ProofKeepClosed` (30) unattached closed sessions and never prunes an attached one:
  `WHERE state = 'closed' AND id NOT IN (SELECT session_id FROM proof_task_links)`. Unlinking makes a session
  eligible again at the next close.
- User delete in the proof window (`ProofService.Delete`) still deletes; the link cascades and the chain drops the
  entry on the `kira:proof:changed` push.
- `dbmcp.tool.proof_list_sessions` text says so (D6).

### D4 How links are made

1. Agent, going forward: new agent MCP tool `attach_proof` (args `{name}`), granted with the Space tools (task
   sessions and runs). The agent calls it after `proof_close_session`. Handler in `internal/agentmcp/space.go`
   (`addAttachProofTool`, registered in `addSpaceTools`): `spaceTask(req)` for the call, `name` trimmed and
   required (1 to 80 runes, `proof.NormalizeName` rules), then `s.space.AttachProof(ctx, call, name)`.
   `SpaceTools` gains `AttachProof(ctx, call SpaceCall, name string) (AttachProofResult, error)`;
   `AttachProofResult{Name string; Steps int; Status string}` with status `attached`. Every `SpaceTools` fake
   in tests gains the method (grep `func (.*) ReportArtifacts(`).
2. User: "Attach proof" menu in the chain header lists closed, unattached sessions, newest first; choosing one links
   it (source `user`). "Remove from task" on a proof entry unlinks it. Archived tasks show neither.
- Engine (`internal/ade/proof.go`, new): `ProofLinks` interface, implemented by `*proof.Service`:

  ```go
  type ProofLinks interface {
  	AttachByName(name string, l proof.TaskLink) (proof.TaskProof, error)
  	AttachByID(id string, l proof.TaskLink) (proof.TaskProof, error)
  	Detach(id, taskID string) error
  	TaskProofs(taskID string) ([]proof.TaskProof, error)
  	Unattached() ([]proof.Summary, error)
  }
  ```

  `TaskBoard.SetProofs(p ProofLinks)` (atomic pointer; the board is built before the Studio stage, so appwire binds
  it after `buildStudio`, one hunk). Board methods: `AttachProof` (SpaceTools), `LinkProof(ctx, taskID, proofID)`,
  `UnlinkProof(ctx, taskID, proofID)`, `TaskProofs(ctx, taskID)` (archived tasks work), `ProofChoices(ctx)`. Writes
  take `taskMu`, `loadTaskCtx` (refuses archived), snapshot stage `currentStepID`/`stepName` (as `AddNote`).
  `AttachProof` turns refusals into `agentmcp.ToolError` (archived task, proofs not bound: "Proof is not available
  in this session.", proof user errors verbatim). Proofs nil on a user call: `invalid`.
- Proof service (`internal/proof/tasklink.go`, new): `TaskLink{TaskID, Source, KiraSessionID, StepID, StepName}`,
  `TaskProof{ID, Name, Summary, ClosedAt, LinkedAt, Source, KiraSessionID, StepID, StepName, Rev, Pending, Steps
  []StepMeta}`; the five methods above. Each write calls `s.emit(id)` (`kira:proof:changed`).
- Repo (`studiostorage/repos/proof.go`): `LinkTask(id string, byKey bool, l ProofTaskLink, now) (ProofSessionRow,
  error)` in one transaction: session by id or `name_key`; unknown is `ProofNotFound` ("no proof session with that
  name; call proof_list_sessions"); not closed is `ProofBadState` ("close it with proof_close_session first");
  linked to the same task is a no-op success; linked to another task is `ProofBadState` ("proof session %q belongs
  to another task"). `UnlinkTask(id, taskID)` (`ProofNotFound` when no such link). `TaskSessions(taskID)`: one
  query for sessions joined to links (current rev, pending flag), one for their current-rev step metas, grouped in
  Go (no N+1). `Unattached()`: closed sessions with no link, newest first.

### D5 How existing proof records migrate into the chain

- Migration 0066 creates the table empty. Every existing session stays unattached, keeps showing in the proof window
  and becomes attachable from the "Attach proof" menu.
- No automatic attribution: no stored record ties a past proof session to a task or agent session (DB MCP calls carry
  no session identity), and a time-window guess would attach proofs a terminal session or another task wrote.
- `Unattached` lists every closed unattached session (at most 30 survive pruning), so the user can file the old ones.
