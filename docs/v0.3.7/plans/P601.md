## 2. Design

### 2.1 Lead slot (agent indicator first)

Card head line and shelf row start with a lead slot replacing the square:
`<span class="inline-flex min-w-4.5 shrink-0 justify-center" data-testid="ade-row-lead">`
holding `<AdeTaskSessions>` when `card.sessions`, else empty. Slot always renders so status text
lines up across rows. `AdeTaskSessions.vue` itself unchanged.

### 2.2 Status as small text with dropdown

New `plan/AdeTaskStatusMenu.vue` (`<script setup lang="ts">`, Tailwind only):

- Prop `card: CardModel`. Statuses from `usePlanModel().model.value?.board.statuses`.
- shadcn-vue `DropdownMenu` / `DropdownMenuTrigger as-child` / `DropdownMenuContent align="start"`
  / `DropdownMenuLabel` (`common.field.status.label`) / `DropdownMenuRadioGroup`
  (`:model-value="card.status.id"`) / `DropdownMenuRadioItem` per status, content `AdeChip
  :label :color`. Radio group gives checked state, arrow keys, Enter, Escape for free.
- Trigger: theme `Button variant="toolbar" size="inline"`, class `h-4.5 max-w-24 shrink-0
  truncate rounded-kira-sm border-0 px-1 text-kira-sm font-normal` plus
  `STATUS_TEXT_CLASS[card.status.color]` (status colour moves from glyph to text; plan colour rule
  in ARCHITECTURE already allows status colour). Text `card.status.name`. `aria-label`
  `space.ade.plan.card.status.aria` ("Status: {status}. Change status"). Wrapped in `AdeTip` with
  `space.ade.plan.card.status.tooltip` ("Change status").
- Trigger gets `@click.stop`: head and shelf row select on click. Keydown needs no stop: their
  Enter/Space handlers use `.self`. Same pattern as the card's Change base dropdown. Drag: Sortable
  `fallbackTolerance: 4` means a click never drags, same as existing head buttons.
- `@update:model-value` (or item `@select`) with an id different from current: `useUpdateTask`
  `mutateAsync({ taskId, patch: taskPatch({ statusId }) })`. On error: `ui.select(taskId)`,
  `ui.actionError[taskId] = errorText(err)` (task menu's behaviour; panel shows
  `ade-panel-action-error`). Same id: no write.
- Test ids: trigger `ade-row-status` (`data-status-id`), content `ade-row-status-menu`, items
  `ade-row-status-option-<id>`.
- Rendered for every non-review card, parked included (task menu allows a status on any non-review
  task). Review cards have no head.

No Pinia store (no new shared state); server state stays in the existing TanStack Query mutation.
No VueUse need. `AdeStatusPicker.vue` unchanged (panel keeps arrows plus picker).

### 2.3 Row changes

`plan/AdeTaskCard.vue` head line, new order: lead slot, `AdeTaskStatusMenu`, tag glyph (only when
not the stored status, see below), orchestrator badge, workflow segments, step label, bar,
attention, automation chip, updates dot, parent chip, meta, change base, review, action.

- Delete square span `ade-card-dot`.
- Move `<AdeTaskSessions>` from line 169 into the lead slot.
- Tag glyph: `const tagGlyph = computed(() => card.tag && !(card.tag.kind === 'status' &&
  card.tag.color) ? card.tag : null)` with a one-line comment (stored status shows as text; "Pass
  done" has no colour and keeps its glyph). Blocked, merged, not merging, pass done keep their
  glyph after the status text. No edit to `board/actions.ts` (P598 owns it this batch).
- Left edge `border-l-3` with task colour stays.

`later/AdeShelfRow.vue`:

- Delete square `ade-shelf-dot`; lead slot with `<AdeTaskSessions>` first; remove the mid-row
  `<AdeTaskSessions>`.
- After title: `AdeTaskStatusMenu`.
- Colour: add `box-border border-l-3` and `:style="{ borderLeftColor: card.color }"` (the card's
  edge; no shadow, Plan surfaces stay flat). Parked title gets `text-muted-foreground` (replaces the
  outlined-square cue).

`plan/AdeDayBand.vue` span rows: delete the `size-2` square; add `border-l-3` and
`borderLeftColor: s.color` to the existing `border border-border` row. No indicator or status:
span is a pointer to the card, which shows both.
