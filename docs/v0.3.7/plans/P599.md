Stream A of batch 4 (P599, P600, P601). Worktree `/home/user/ws-p599`, branch `stream/p599`. P597 and
P598 (batch 3) may still be landing; shared files listed in §9.

Ask (user): "The review changes button should show not only for commits but also uncommitted changes
too".

Paths below are under `apps/kira-space/` unless noted. `en.json` is
`packages/theme/src/i18n/en.json`. `git-ui` is `packages/git-ui/src/`. Key prefix `rc.` means

## 1. Findings

The button is "Review code" (`space.ade.board.taskMenu.reviewCode.label`, icon `git-compare`). Every
control goes through one rule, `frontend/src/ade/v2/board/reviewCode.ts` `reviewChoice` (P240):

- task panel header `ade-panel-review` (`panel/AdeTaskPanel.vue`), card head icon `ade-card-review`
  (`plan/AdeTaskCard.vue`), branch row icon `ade-branch-review` and its menu item `ade-review-code`
  (`plan/AdeBranchRow.vue`), branch panel header action `ade-panel-action-review`
  (`panel/AdeBranchPanel.vue` + `panel/headerActions.ts`), task menu entry (`board/menu.ts`
  `reviewEntry`, `plan/useTaskMenu.ts`), shortcut `ade.reviewCode` (`shell/AdeShell.vue`), picker
  for several branches (`review/useReviewCode.ts` `openTask`).
- Not gated by `reviewChoice`: step block "Review" (`ade-run-review`, review step waiting) and Needs
  page "Review" action. They open the window whatever the facts.

`reviewChoice` today, in order: parked hidden; unnamed disabled (`rc.createFirst`); `baseMissing`
disabled; `ahead === 0 && dirty.length > 0` disabled (`rc.uncommitted.hint` "Only uncommitted
changes on {branch}. Commit them to review against {base}."); `ahead === 0` disabled
(`rc.noCommits.tooltip`); else enabled (`rc.review.tooltip`, plus `rc.working.tooltip` while an agent
runs). So the button **shows** but is **disabled** for uncommitted-only work. That gate is the whole
ask on the button side.

`Branch.dirty` (`internal/ade/board_facts.go`, `toDirtyEntries`): porcelain status of the row's
worktree minus ignored entries (staged, unstaged, untracked, unmerged). Empty when the row has no
worktree. Same file set `ReviewWorking` lists (`gitsession.WorktreeChanges`: diff vs worktree HEAD
plus untracked).

Backend refuses nothing here: `TaskBoard.OpenReviewWindow` (`internal/ade/review.go:161`) checks
only `reviewableBranch` (archived, kind, unnamed), never `ahead`. `crreview.go` (`internal/gitsession`)
is host change-request review state (P581 era), unrelated to this gate.

Uncommitted review already exists end to end (P418, P465, removed section):

- What the reviewer gets: `AdeTaskService.ReviewWorking` lists staged, unstaged and untracked files
  against the worktree HEAD (path from the branch row, never the client), with review state and
  content hashes. `ReviewWorkingDiff` gives HEAD blob vs file on disk. The window feeds them into
  git-ui's Files pane as the Uncommitted section (`AdeReviewFiles.vue` `pushWorking`).
- Results to files and lines: marks in `review_working_file`/`review_working_range`, ranges in the
  coordinates of a stored sha256-hashed snapshot, projected onto current content on read. Comments
  carry `origin = working` and `anchor_content`; agent prompts flag them `Uncommitted`
  (`commentVars`), Comments pane badges them.
- Mixed commits + uncommitted: already the normal case (Committed section plus Uncommitted section,
  one comment list, stepping over both).
- Staleness: a mark or comment echoes the content hash it was built on; a changed file refuses with
  `E_CONFLICT` and the list reloads (`ade-review-files-mark-refused`). A file edited after its
  review reads `changed`. Freshness: board push, window focus, agent PostToolUse/Stop in the
  worktree, stat-stamp poll. Commit: `PromoteWorkingReview` moves landed marks and comments onto the
  committed review; `refsChanged` plus locked-window auto-apply re-resolves the range.

The real gap besides the button: the review window with **zero commits**. git-ui
`ReviewSessionState.#applyResolution` sets phase `empty` for range kind `empty`, and
`ReviewView.vue` then renders only `review-empty` ("“{branch}” adds no commits to “{base}”."). The
pane toolbar, Files pane (with its Uncommitted section) and Comments pane render only in phase
`listing`. Enabling the button alone would open a window that hides the very changes it was opened
for.

## 2. Decisions

1. Rule (`reviewChoice`), order kept: parked hidden; unnamed disabled; `baseMissing` disabled;
   `ahead === 0 && dirty.length === 0` disabled; otherwise enabled. Enabled tip by case:
   - `ahead > 0`, clean: `rc.review.tooltip` (unchanged).
   - `ahead > 0`, dirty: new `rc.reviewMixed.tooltip`.
   - `ahead === 0`, dirty: new `rc.reviewUncommitted.tooltip`.
   - `rc.working.tooltip` still appended while an agent runs on the branch.
2. Label stays "Review code" everywhere. User's "review changes button" names this control; a
   relabel would touch five surfaces, P601's task row, and visual baselines for no gain in the ask.
   Open question 1.
3. No backend API change. `OpenReviewWindow`, `ReviewWindowTarget`, `ReviewWorking*` already serve
   an uncommitted-only branch. No new wire field, no error code, no migration, no git-ipc contract
   bump.
4. Review window, zero commits with uncommitted files ("working-only"): git-ui shows the pane bar
   with Files and Comments (no Commits tab), the Files pane without the Committed header, tree and
   diff-mode control, a one-line note `git.review.empty.body` above the Uncommitted section, and the
   Comments pane. Defaults to Files (the window already opens on `pane: 'files'`). Zero commits and
   a clean worktree keep today's `review-empty` text.
5. Working-only is a view over phase `empty`, not a new `ReviewPhase` member. `ReviewPhase` is public
   API of git-ui (`index.ts` export) and the phase stays true: the range is empty. Transitions need
   nothing new: first commit fires `refsChanged`, locked auto-apply moves to `listing`, promotion
   moves landed marks; a worktree that goes clean drops back to the plain empty text.
6. Git sidebar Review tab (`repo/RepoReviewView.vue`, git-ui "Review branch changes") unchanged. It
   passes no `workingChanges`: it reviews a branch by name, with no worktree binding (a branch can
   be checked out in any worktree or none), and its menu entry is never gated on commits. Working
   review there needs a non-task working review API keyed by worktree path: a separate feature.
   Open question 2.
7. Review agent first message (`ade.review.message`) unchanged. The agent works in the worktree and
   reads files on disk, so it sees uncommitted edits; forwarded and round comments already flag
   uncommitted ones. A prompt change would also force a real `claude` test run (token cost) for no
   concrete gap. Open question 3.
8. Unit tests: none. `reviewChoice` is a short ordered rule; the UI spec covers each branch.

## 3. Frontend: button rule

`frontend/src/ade/v2/board/reviewCode.ts` `reviewChoice`: replace the two `ahead === 0` branches:

```ts
const dirty = b.dirty.length;
if (b.ahead === 0 && dirty === 0) {
  return choice(true, branchParts('space.ade.board.reviewChoice.nothing.tooltip', vars));
}
const tip =
  b.ahead === 0
    ? branchParts('space.ade.board.reviewChoice.reviewUncommitted.tooltip', vars, { count: dirty })
    : dirty > 0
      ? branchParts('space.ade.board.reviewChoice.reviewMixed.tooltip', vars, { count: dirty })
      : branchParts('space.ade.board.reviewChoice.review.tooltip', vars);
```

Implementer may flatten the nested ternary into `if`s if Biome's style rules or readability ask.
`count` goes through `text` (number), so `t` picks the plural branch. No caller changes: every
control reads `choice.disabled` and `choice.tip`.

## 4. git-ui: working-only review

All in `packages/git-ui/src/components/review/`. Tailwind utilities only; no new component.

`ReviewView.vue`:

- `const workingOnly = computed(() => review.value?.phase.value === 'empty' &&
  (props.workingChanges?.files.length ?? 0) > 0);`
- `const pane = computed(() => workingOnly.value && review.value?.pane.value === 'commits' ? 'files'
  : review.value?.pane.value);` Template uses it for the Files and Comments branches.
- `review-empty` branch: `v-else-if="review.phase.value === 'empty' && !workingOnly"`.
- Files pane branch: `(phase === 'listing' && pane === 'files') || (workingOnly && pane ===
  'files')`, pass new prop `:committed="!workingOnly"`.
- Comments pane branch: same widening (`listing` or `workingOnly`, `pane === 'comments'`).
- Comments target watch (line ~321): set target for phase `listing` **or** `empty` (session key is
  repo + branch, no base). Files target watch stays `listing` only (no committed range).
- `usePanelHeaderSearch` `searchable` and `useReviewStepping` `shortcuts`: `listing || workingOnly`.
- Pass `:working-only="workingOnly"` to `ReviewToolbars`.

`ReviewToolbars.vue`:

- New prop `workingOnly?: boolean`. Pane toolbar `v-if="review.phase.value === 'listing' ||
  workingOnly"`. `panelItems` drops the `commits` option when `workingOnly`. Model value of
  `SecondaryTabs`: the effective pane (`commits` reads as `files` when working-only), so no tab
  shows unselected.

`ReviewFilesPane.vue`:

- New prop `committed?: boolean` (default `true`, `withDefaults`). When `false`: hide the diff-mode
  `SecondaryTabs` (committed-only: full range vs since review), `deltaStatusText`, the
  `review-committed-header` row and `review-files-tree`; show a muted line above the Uncommitted
  section: `<p class="px-2 py-1 text-graph-sm text-muted-foreground" data-testid="review-empty">`
  with `git.review.empty.body` (`branch`, `base`). Pass branch and base as props (`emptyBranch`,
  `emptyBase`) or a single `emptyNote: string` computed in `ReviewView`; pick `emptyNote` (one prop,
  pane stays ignorant of resolution). Keep prev/next unreviewed buttons: stepping covers the working
  section (`useReviewStepping`).
- The Uncommitted block sizes `flex-auto` when the committed tree is hidden, so it fills the pane.

No change to `state/review.ts`, `ReviewPhase`, git-ipc, or `AdeReviewFiles.vue` (it already pushes
`workingChanges` whatever the phase). Git sidebar passes no `workingChanges`, so `workingOnly` is
always false there: behavior unchanged.
