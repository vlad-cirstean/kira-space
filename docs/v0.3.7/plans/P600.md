Ask (user): "In the task details group the top links by category. And have issue cr and misc types. Also
make it more space efficient and nicer." Paths below are under `apps/kira-space/` unless noted.

## 1. Today

- `frontend/src/ade/v2/details/AdeDetailsTab.vue` renders `AdeLinkGroups` then `AdeTaskChain`.
- `details/AdeLinkGroups.vue`: header row "Links" (`AdeRow` label), gap alerts, then two groups from
  `linkGroups()` (`details/linkGroups.ts:51-95`):
  - Main: Jira slot (`task.jira`, origin `jira`), host slot (`task.hostUrl`, kind from
    `task.hostLink.kind`, origin `host`), detected change requests (`source === 'host'`, `id === ''`).
  - Related: every other artifact minus detected branches, minus URLs Main holds, minus the tracker's
    own row for the task's Jira key.
  - Each group: its own header row, an "No links yet." row when empty, then rows. Related ends with
    `AdeLinkAddLine` (always-present paste/type input; backend classifies via `AddLink`).
  - Under the Jira row: `panel/AdeTaskIssueLine.vue` (P592), up to three more rows: title + status +
    view button, PR count, gap text.
- `details/AdeDetailsLink.vue`: one `AdeRow` (`li`). Label column (`w-24`) holds the kind: a
  `AdeLinkKindMenu` chip menu for stored rows, a plain `AdeChip wide` otherwise. Body: title link
  (change request opens in-app via `useOpenChangeRequest`, P594; else `control.openExternal`) and
  status chip. Actions always visible: open external, origin session (slot), edit, remove.
- Model: `Artifact.kind` is `changeRequest | issue | branch | deployment | doc | link`
  (`wire.ts:520`); `HostLink.kind` is `changeRequest | issue`. Add: `AddLink` (text only, backend
  picks the kind). Edit: `EditLink` (text, or new kind for a stored row). Remove: slot clear via
  `UpdateTask` or `RemoveArtifact`.
- Vertical cost, example task (Jira with tracker info, host CR, 1 detected CR, 3 stored misc links):
  Links header 1 + Main header 1 + Jira 1 + issue title 1 + PR count 1 + 2 CR + Related header 1 +
  3 links + add line 1 = 12 rows, plus `gap-2` between blocks. Empty groups cost a header and an
  empty row each.

## 2. Design

Pure frontend regrouping. Link model, wire and backend unchanged: no flow test (SPEC row: flow test
only if the model changes).

### 2.1 Categories

Three categories, fixed order, from the link's kind:

- `issue`: kind `issue` (Jira slot, GitHub/GitLab issue host link, stored and tracker issues).
- `changeRequest`: kind `changeRequest` (host CR link, detected CRs, stored CRs).
- `misc`: `branch`, `deployment`, `doc`, `link`.

`linkGroups.ts`:

- Add `export type LinkCategory = 'issue' | 'changeRequest' | 'misc'` and
  `export function linkCategory(kind: Artifact['kind']): LinkCategory`.
- `linkGroups(task, artifacts)` returns `{ id: LinkCategory; items: LinkItem[] }[]` in order
  `issue`, `changeRequest`, `misc`, every group present (caller hides empty ones). Build the current
  `main` then `related` list exactly as today (same dedup, same tracker-row skip, same detected-branch
  skip), concatenate `main` then `related`, then bucket by `linkCategory(item.kind)` keeping order.
  Result: Jira first in Issues, host link first in its category, detected CRs before stored CRs.
- Update the doc comment. No unit test: bucketing a list by a three-way map is not complex logic.

## 7. Decisions and open questions (defaults taken)

- "Misc" label: user's word kept. "Other" is the alternative if the user prefers plain copy.
- Six stored kinds stay; the user's three "types" are the display groups. Collapsing the model to
  three kinds would drop doc/deployment/branch meaning and need a migration; not asked.
- One add line for all groups, not one per group: `AddLink` classifies from text, a per-group add
  would need a kind argument on the wire (model change) for no gain; the kind menu re-files.
- Actions hover-revealed; the title link stays always clickable.
- Empty state keeps one hint row also when editable (copy rule, existing test), still saves a row
  against today's two.
