# P597 Proof: screenshot button saves all to a Desktop folder, location customizable

Stream: `stream/p597` (worktree `/home/user/ws-p597`), batch 3 (`batches.md`). Runs beside P595
(API rules default, migration 0096, settings) and P596 (Privacy tab). Base: `6877b37db`.

## Ask

User, verbatim:

1. "the export all screenshots should create a folder by default and save on Desktop. The save
   location can be customised from that window"
2. "The proof tool screenshot button should be the save all to folder."

Reading: the proof window's screenshot button saves every tab of the proof into a new folder under
the Desktop, with no picker. The parent location is changeable from the proof window, persists, is
shown, and resets to Desktop. Single-tab JPEG save and the separate "save all" menu item go away.

- Go, `internal/bridge/proofshots.go`: `ChooseShotFolder` (dialog, then `mkFreshDir(parent,
  safeBaseName(session))`, `-2`..`-99` on collision), `SaveJpegTo` (opaque `shot_` id, never a path

## Decisions

1. **One button.** `proof-shot` primary click = save all tabs to a new folder (no picker). Label
   "Save screenshots", camera icon kept. Tooltip names the target location.
2. **Menu (`proof-shot-more`)** keeps the split button:
   - "Copy current tab" (`proof-shot-copy`): the existing clipboard PNG copy. Kept: it is not a save
     and the user asked for nothing about it; dropping it would lose a working feature.
   - Separator, then a `DropdownMenuLabel` showing "Save to" plus the location path
     (`proof-shot-location`), "default" marker when it is the Desktop default, warn text when the
     folder no longer exists.
   - "Change location…" (`proof-shot-location-choose`): native folder picker, persisted.
   - "Reset to Desktop" (`proof-shot-location-reset`): shown only while a custom location is set.
   - Removed: `proof-shot-save` (single-tab JPEG) and `proof-shot-save-all` (now the primary).
3. **Remove single-tab save end to end**: `ProofService.SaveJpeg`, `ProofSaveJpegArgs`,
   `ProofSaveJpegResult`, `proofSaveJpegResultSchema`, `control.proofSaveJpeg`, mocks, specs.
   `downloadsDir` stays (used by `files.go`).
4. **Default parent = Desktop**, resolved fresh per call by `desktopDir()`:
   - `XDG_DESKTOP_DIR` env when absolute and a directory (Linux dev convenience; cheap).
   - else `<home>/Desktop` when it is a directory (macOS fixed location; Windows default).
   - else `<home>` (fallback, never create `~/Desktop`).
   - `os.UserHomeDir` failure: error `shotLocationMissing` with empty path text replaced by "home".
   No library: macOS, the only shipped OS, fixes `~/Desktop`; `adrg/xdg` caches dirs at package
   init (fights the flow harness's per-test `HOME`) and adds a dependency for one path. Requirement
   named: per-call resolution against the current `HOME`.
5. **Custom location** persisted as settings leaf `proof.shotLocation` (string, absolute, `""` =
   default). Read and written only through `ProofService`, never through `SettingsPatch`: the
   renderer never sends a path (existing proofshots design) and P595 is editing `model.Settings`,
   `SettingsPatch` and `repos/settings.go` in parallel. New repo methods live in a new file.
6. **Choose validates**: picker result must be absolute, exist, be a directory and be writable
   (create and remove a probe dir `os.MkdirTemp(path, ".kira-shot-*")`). Failure keeps the old
   value and returns a localized error. Cancel changes nothing.
7. **Save-time errors are explicit, never a silent fallback**:
   - custom location gone or not a dir: `shotLocationMissing` ("The save location {path} no longer
     exists. Change the location or reset it to the Desktop.").
   - `fs.ErrPermission` (or `EROFS`) on `Mkdir`: `shotLocationUnwritable` ("Kira Space can't write to
     {path}. Change the location.").
   - 99 collisions: `shotFolderTaken` (existing).
   - no tabs: frontend refuses before any IPC (`studio.proof.shot.none.error`), button already
     disabled when `tabs.length === 0`; the guard covers a race.
8. **Folder name** unchanged: `safeBaseName(sessionName)`, unique via `-2`..`-99`.
9. **Close, not forget**: `ForgetShotFolder` becomes `CloseShotFolder`. It refuses further
   `SaveJpegTo` for the id, removes the folder when still empty (`os.Remove`, error ignored except
   logged at debug: nothing was written, so no empty folder is left on the Desktop after a failure),
   and keeps the id resolvable for reveal until the cap-8 eviction.
10. **Reveal**: `RevealShotFolder({folderId})` reveals the saved folder in Finder through the
    existing `FileOpener.RevealFile`. Closed ids allowed; an evicted or unknown id returns
    `shotFolderGone`; a removed (empty) folder returns `shotFolderGone`.
11. **Visible feedback**: new `ProofShotStatus.vue`, an `Alert` strip (`strip` variant) between
    header and panes (`proof-shot-status`), `role="status"`:
    - success (`info`): "Saved {count} screenshots to {path}" plus "Reveal" button
      (`proof-shot-reveal`, `common.action.reveal.label`) and dismiss (`proof-shot-status-dismiss`,
      `common.action.dismiss.label`). Auto-hides after 10 s (`useTimeoutFn`, VueUse).
    - partial or error (`error`): message, dismiss; no auto-hide. Next save replaces it.
    - `announceApp` kept for screen readers.
    Result lives in `useProofWindowStore` (`shotResult`, `clearShotResult`): header menu and strip are
    siblings, and the state is proof-window UI state, the store's own concern.
12. **Location server state** through TanStack Query: `proofKey.shotLocation`, `useShotLocation`,
    `useChooseShotLocation`, `useResetShotLocation` (mutations `setQueryData` with the returned
    location). `useProofSync`'s blanket invalidation re-reads it too; harmless.
