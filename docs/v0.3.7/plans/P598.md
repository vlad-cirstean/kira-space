# P598 Task work start: require a repo choice before an agent opens

Stream of batch 3 (P596, P597, P598). Worktree `/home/user/ws-p598`, branch `stream/p598`, off
`chapter/v0.3.7` at `054402278`.

Ask (user): "When starting work in a task first ask me to at least select a repo. As right now if i
forget the agent is opened in a random run folder. This applies from inside a task when starting
working in a workflow." Acceptance (SPEC): a task with no repo cannot start work without choosing at
least one repo in a prompt; no start path falls back to a run folder.

Paths below are under `apps/kira-space/` unless noted. Line numbers are at the base commit.

## 1. Current behavior

The "random run folder" is the task folder `<home>/ade/tasks/<taskId>` (`TaskBoard.taskDir`,
`internal/ade/taskdir.go:12`). P467 made a task with no repo start and run there on purpose
(ARCHITECTURE "Repo-less tasks (P467)", lines 2482-2489, and line 2354). P510 added `outside_repo`
steps that use the same folder even when the task has repos.

  non-review, non-`only` step when the task has no mine branch. `TaskBoard.plan`
  (`internal/ade/runs.go:191-227`) gives an outside-repo automatic step `[taskTarget]` (line 209-210)
  and pins `taskTarget` on any step that already has a `""` run in the pass (lines 221-223).
- Run creation. `queueRun` (`runs.go:474-529`) turns `taskTarget` into `taskDir` (lines 479-486). Every
  automatic start goes through it:
  - `StartRun` (Run button, Run dialog, phone) `runs.go:322-377` via `startStep` (`runs.go:458-471`);
  - `advanceLocked` auto start of the next step and `chainRerun` reruns (`runs.go:1278-1322`);
  - `Approve` (`runs.go:1371-1396`) via `startStep`;
  - `RetryRun` (`runs.go:1399-1441`, line 1439) and `ResumeRun` via `queueResumeLocked`
    (`runs.go:1449-1500`, line 1500);
  - loop reruns from `decideRoute`/`decideLoop` (`internal/ade/route.go`).

- Take over / Resume of a session. `takeOverLocked` (`launches.go:152-203`) reuses the recorded cwd

- Not folder paths:

## 2. Decisions

1. Backend guard plus frontend prompt, both. The engine refuses a start on a task with no repo with a
   new sentinel `ade.ErrTaskNoRepo`, wire code `E_TASK_NO_REPO`. The guard sits at the two choke points
   (`queueRun`, `LaunchStep`) so no path, current or future, desktop or phone, can fall back to the task
   folder even if a client skips the prompt. The desktop asks before calling (board state says the
   task has no repo) and also catches `E_TASK_NO_REPO` from a stale board, then asks and retries once.
2. Still repo-less by design, kept working:
   - `outside_repo: true` steps (agent, script, session manual). P510 made them task-folder steps on
     purpose; they never get the prompt and keep running in the task folder, with or without repos.
     This is also how a workflow keeps the P467 "first stage picks repos" pattern: mark that stage
     `outside_repo`; `declare_repos` and `request_branches` still work from it.
   - Orchestrator tasks (kind `orchestrator`, P571). They spawn child tasks and edit no code; they are
     created without repos (`TestOrchestratorSpawn`). Asking them for a repo would block their only
     job. Default chosen: exempt; listed as open question 1.
3. What counts as "has a repo": automatic steps need a mine branch (`tc.mine`, as targets do today);
   a manual session needs any branch row (as `launchDirs` does today). A draft row from `AddTaskRepo`
   satisfies both. Mirrored in the frontend.
4. Prompt UI: one dialog for every start kind, `AdeRepoGateDialog.vue`, driven by one Pinia store
   `useAdeRepoGateStore` (one concern: the pending repo choice before a start). It reuses the existing
   `ProjectPicker` + `useProjectOptions` + `useAddTaskRepo` flow of the Main tab. The user may pick one
   or more repos; Continue is disabled until one is chosen. Continue adds each with `AddTaskRepo`
   (`base: null`), then the original start continues. Cancel (or Esc / close) aborts the start and calls
   nothing. If an `AddTaskRepo` call fails, the dialog stays open with the error; repos already added
   stay (they are ordinary task repos, visible in the Main tab).
5. Legacy task-folder runs. A pass that started before this phase can hold a `""` run on a repo-aware
   step (pin, `runs.go:221-223`). Keep the pin, so in-flight tasks keep their route and history. A
   retry, resume or loop of such a run is refused: with no mine branch `ErrTaskNoRepo`; with repos now
   on the task an `invalid(...)` refusal "step %q worked in the task folder before repos were required:
   move the task back to this step to run it on a repo" (`SetTaskStep` resets the pass, which drops the
   pin). No legacy fallback survives.
6. Auto-advance into a repo-aware step on a repo-less task (after an outside-repo step, or after
   `StepDone`): `advanceLocked` cannot start it (target error, logged today and still logged). Today
   `StartRun` would then refuse ("does not wait for Run", `nextAction` says `actStart`) and the task
   is stuck. Fix: `StartRun` also accepts the current step when `nextAction` is `actStart` for that
   step (the engine owed the start but did not make it). Frontend shows Run on such a step.
7. Take over and Resume of an existing session keep the recorded cwd (conversation resume pins it).
   They continue work, not start it, and only exist for outside-repo, orchestrator or pre-P598 sessions.
   No change.
8. `only <nick>` and review steps keep their target errors and their "Needs a repository" text with no
   Run (a random repo would not satisfy them). The review agent's `errNoRepo` now maps to
   `E_TASK_NO_REPO` (same sentinel); the review panel shows the catalog text, no prompt (it needs a
   branch with commits, not a draft).
9. Prompt templates (`internal/llmprompts/registry.go:1144, 1177-1178`, `ade.step.prompt`,
   `ade.manual.message`) keep their "No repo yet" branch. It is now unreachable from the engine, but the
   templates are user-editable and a text change needs golden, budget and real-claude churn for no
   behavior gain. Default chosen; open question 2. No real `claude` test run needed (no prompt change).
10. Phone (`frontend/mobile`, `internal/mobileweb`): no picker there. `StartRun`/`LaunchStep` from the
    phone get `E_TASK_NO_REPO`, mapped to HTTP 409 with the catalog text. Choosing the repo happens on
    the desktop.
