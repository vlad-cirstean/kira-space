## 2. Decisions

### 2.1 Model

`McpSettings` becomes:

```go
type McpSettings struct {
	Description string `json:"description"`
	Enabled     bool   `json:"enabled"`
	// Approval is "prompt" (each read asks the user) or "allow" (reads run at once).
	Approval string `json:"approval"`
}
```

Field named `approval`, the word `list_scripts` already shows agents for the same choice. Approval
is stored while off too (scripts keep `run` the same way), so turning a cluster back on restores its
choice.

New cluster rows default `enabled = false`, `approval = 'prompt'`, description empty. A new
kubeconfig context is invisible to agents until the user turns it on.

### 2.2 Four per-group modes: removed

User asked for one mode. Lost granularity, stated in docs and Result:

- No mixed approval per operation: e.g. discover and list without asking while describe and logs ask.
  Now every `kube_*` read on a cluster asks, or none does.
- No deny per operation: a cluster cannot be exposed for listing while describe (manifests,
  events) or pod logs stay refused. Exposure is all five tools or none.

Kept: the approval card still names the operation (discover, list, describe, logs) per call, so a
prompt cluster lets the user refuse a describe or log read call by call.

### 2.3 Migration 0097: never widens

`internal/storage/migrations/0097_p603_kube_mcp_access.sql`, registered in `embed.go`
(`{Version: 97, Name: "p603_kube_mcp_access", File: "0097_p603_kube_mcp_access.sql"}`):

```sql
-- P603: one MCP switch and one approval mode per cluster, like scripts. Never widens access:
-- a cluster turns on only if some operation was prompt or allow; it runs without asking only if every
-- operation was allow. Any other stored word counts as deny.
ALTER TABLE kube_clusters ADD COLUMN mcp_enabled INTEGER NOT NULL DEFAULT 0 CHECK (mcp_enabled IN (0, 1));
ALTER TABLE kube_clusters ADD COLUMN mcp_approval TEXT NOT NULL DEFAULT 'prompt' CHECK (mcp_approval IN ('prompt', 'allow'));
UPDATE kube_clusters SET
  mcp_enabled = CASE WHEN mcp_discover_mode IN ('prompt', 'allow') OR mcp_list_mode IN ('prompt', 'allow')
    OR mcp_describe_mode IN ('prompt', 'allow') OR mcp_logs_mode IN ('prompt', 'allow') THEN 1 ELSE 0 END,
  mcp_approval = CASE WHEN mcp_discover_mode = 'allow' AND mcp_list_mode = 'allow'
    AND mcp_describe_mode = 'allow' AND mcp_logs_mode = 'allow' THEN 'allow' ELSE 'prompt' END;
ALTER TABLE kube_clusters DROP COLUMN mcp_discover_mode;
ALTER TABLE kube_clusters DROP COLUMN mcp_list_mode;
ALTER TABLE kube_clusters DROP COLUMN mcp_describe_mode;
ALTER TABLE kube_clusters DROP COLUMN mcp_logs_mode;
```

(modernc sqlite v1.61 supports `DROP COLUMN`; the four columns carry no index or CHECK.)

Mapping:

| Old four modes | enabled | approval |
| --- | --- | --- |
| all deny (or unknown words) | off | prompt |
| all allow | on | allow |
| no deny, some prompt | on | prompt |
| some deny, some allow or prompt | on | prompt |

Deviation from the brief's formula ("prompt unless every non-deny group was allow"): that formula
turns `list allow, logs deny` into `allow` for all five tools, so logs would run without asking.
Here `allow` needs all four allow. The last row is the one residual change: an operation that was
deny on an otherwise exposed cluster now asks each call (never runs unasked). Alternative, stricter:
turn such clusters off (loses the reads the user had allowed). Default chosen: on + prompt (open
question Q1).

Untouched rows (all four still the old default `prompt`) migrate to on + prompt: same access as
today. Only rows created after the migration start off (open question Q2).

Unknown words count as deny: old `kubeRun` refused an unknown group mode, so it never ran a read.

### 2.4 Gate

`kube_tools.go`:

- `kubeExposed(m)` returns `m.Enabled`. Delete `modeOfGroup` and `kubeDeniedText`.
- The operation constants stay (`kubeDiscover`... ); comment becomes "Operation names, shown on the
  approval card". `kubeRun(ctx, clusterID, op, namespace, statement, read)`:
  1. `resolveCluster`; not found (unknown, gone from kubeconfig, or off) gives `noClusterResult`
     (unchanged text `no cluster %q exposed to MCP`, identical for every case and every tool).
  2. `c.Mcp.Approval == "allow"` runs. Anything else asks (fail closed): same `ApprovalRequest`
     as today (`Kind: "kubernetes"`, `Cluster.Operation: op`). Not approved:
     `approvalOutcomeError` unchanged.
  3. After approval re-resolve; turned off or gone during the wait gives `noClusterResult`. No
     other re-check: switching prompt to allow during the wait changes nothing for an approved call.
- `kubeListClusters`: skip `!c.Mcp.Enabled`; view replaces `Permissions kubePermissions` with
  `Approval string json:"approval"`. Delete `kubePermissions`.

Prompt per call stays as today: one approval per tool call; `kube_discover` is one call, one
approval for namespaces and kinds.
