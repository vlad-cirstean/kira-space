# P532 Table allow list per connection for DB MCP

Ask (SPEC row P532): table allow list on the connection. A statement touching an unlisted table is refused over MCP,
whatever the mode (read, write, ddl, later P535 browse). Select-all checkbox sets or clears the whole list. Table
extraction per statement; parser approach decided here; fail closed: unparsable statement under a non-all list is
refused. Cover views, CTEs, subqueries, schema-qualified names, `list_connections` reporting. Existing connections
default to all allowed. UI in `ConnectionMcpTab.vue` with search and select-all.

## 1. Decisions

### 1.1 Parser: maintained libraries, one per dialect, pure Go

Repo has no SQL AST parser in Go. `adapters.ClassifySQL` reads the leading keyword only; `queryplan.Explainable` is a
prefix check; sqlite's `firstTopLevelSemicolon` is a scanner. None names tables. Hand-rolling a multi-dialect
parser is the "non-trivial infrastructure" CLAUDE.md forbids. Libraries (licenses checked at package level, every
feature used is in the open package; versions and dates from `go list -m` on 2026-11-05):

| Kinds | Module | License | Notes |
|---|---|---|---|
| postgres | `github.com/wasilibs/go-pgquery` subpackage `parser` only (`ParseToJSON`) | MIT; embeds libpg_query (BSD-3) and PostgreSQL source (PostgreSQL License); runtime `github.com/tetratelabs/wazero` (Apache-2.0) | Real Postgres grammar (libpg_query) compiled to wasm, run by wazero, no cgo. 2.5 MB wasm. |
| mysql, mariadb | `github.com/pingcap/tidb/pkg/parser` | Apache-2.0 | MySQL grammar, pure Go, maintained (commit 2026-11-05). Needs `_ ".../parser/test_driver"` for value exprs. |
| clickhouse | `github.com/AfterShip/clickhouse-sql-parser` v0.5.6 | MIT | Pure Go, no runtime deps. |
| sqlite | `github.com/rqlite/sql` | MIT | Pure Go SQLite parser (rqlite), no deps. |
| mongodb | existing `mongo.parseStatement` / `parseTarget` | own | Console grammar already parsed by the adapter. |
| kibana | existing `model.KibanaDiscoverRequest` JSON decode | own | One Discover request; data view id. |

Declined, with the requirement each misses:
- `github.com/pganalyze/pg_query_go/v6` (BSD-3): cgo. Wails builds on Windows and Linux CI stay cgo-free for this
  path; libpg_query C also slows every build.
- Root package of `go-pgquery` and any import of `pg_query_go`'s root package: `pg_query.go` there is `//go:build
  cgo` and imports the cgo `parser`. Only `github.com/wasilibs/go-pgquery/parser` is imported; walk its JSON
  output generically (section 3.2). Guard: implementer runs `go list -deps ./apps/kira-studio/... | grep
  pganalyze` and expects no package (module requirement in go.mod is fine).
- `github.com/cockroachdb/cockroachdb-parser`: CockroachDB dialect, not Postgres; last release 2025-06.
- `vitess.io/vitess` sqlparser: whole vitess module for one package; MySQL only, same coverage as TiDB's.
- One multi-dialect library: none maintained in Go with these five grammars.

MariaDB through a MySQL grammar: MariaDB-only syntax fails to parse, so it is refused under a list (fail closed).
Stated in the refusal text and the MCP tab note. TiDB-only extensions it accepts are harmless: the server rejects
them.

`NOTICES.md`: add libpg_query (BSD-3) plus PostgreSQL License copyright notice (both require the notice in copies,
binary included), and any `NOTICE` file shipped by go-pgquery (`NOTICE.txt`), wazero and TiDB parser (Apache-2.0
§4(d)). Implementer reads each module's root for `NOTICE*` and copies what exists.

### 1.2 Non-SQL engines

- **mongodb**: collections are tables. List applies. Extraction from the console grammar (section 3.6).
- **kibana**: data views are its tables (the run_query `dataView` is the data view id from `list_children`). List
  applies; entry is the data view id.
- **redis**: no tables. Keys are created on the fly, unbounded, and a key's position in a command varies per command
  (`COMMAND GETKEYS` needs the server). A key-pattern allow list is a different feature. List does not apply: modes
  alone govern redis. MCP tab shows a note instead of the list. A `mcp.tables` key on a redis file is a validation
  error.
- **kafka, s3, sqs**: no console, `run_query` already fails. List does not apply, same validation error, same note.
  `list_children` on them is not filtered.

Applicability lives in one Go function (`tableref.Applies(kind)`) and its TS mirror (section 4.2).

### 1.3 Storage and select-all

- File key `mcp.tables`: absent = all tables, including tables created later. Present = exactly those entries;
  `tables: []` = none. Existing files have no key, so nothing changes (no file migration).
- Header checkbox: checked only when the key is absent. Check sets all (removes the key). Uncheck from all writes
  `[]`. Indeterminate while an explicit list exists, even one naming every current table: "every current table"
  and "all, including future tables" differ, and the UI shows which one is stored.
- New tables under an explicit list stay refused until listed. Fail closed.
- Entry string per kind, `.`-separated, a segment wrapped in `"` (with `""` escape) when it holds `.`, `"`, or
  leading/trailing space:
  - postgres: `database.schema.name`
  - mysql, mariadb, clickhouse, mongodb: `database.name`
  - sqlite, kibana: `name`
- Go model `McpTables []string`: nil = all, non-nil (maybe empty) = list. Wire JSON `mcpTables: string[] | null`.
  File struct `Tables *[]string` so `[]` survives `omitempty`.
- DB column `mcp_tables_json TEXT` (NULL = all), projection only; the file stays the source.
- Entry matching: exact for postgres (parser already folds unquoted identifiers), mysql/mariadb, clickhouse,
  mongodb, kibana. ASCII case-insensitive for sqlite (SQLite identifiers are). MySQL with
  `lower_case_table_names=1` may accept a case the list does not; that is a false refusal, never a bypass.

### 1.4 What counts as touching a table

- Every base table, view, materialized view or collection named anywhere in the statement: FROM, JOIN, subqueries
  (WHERE, SELECT list, LATERAL, EXISTS, IN), CTE bodies, set operations, INSERT/UPDATE/DELETE/MERGE targets and
  sources, `RETURNING` subqueries, DDL targets (CREATE/ALTER/DROP/TRUNCATE/RENAME, both sides of a rename, `LIKE`,
  `INHERITS`, `PARTITION OF`, a view's defining query), index targets, `EXPLAIN` inner statement.
- **Views**: a listed view is checked by its own name only. Underlying tables are not expanded. Same model as SQL
  `GRANT` on a view: listing a view is a deliberate grant of what it shows. MCP tab note says so. Writing through an
  updatable view needs the view listed.
- **CTEs**: names declared in `WITH` are not tables inside their scope. Precise scoping (a wrong scope is a bypass,
  e.g. `WITH secret AS (SELECT * FROM secret) SELECT * FROM secret`):
  - non-recursive `WITH`: CTE i's body sees CTEs 0..i-1; the main body sees all.
  - `WITH RECURSIVE`: every CTE body and the main body see all CTEs of that `WITH`.
  - Nested `WITH` pushes a new scope; inner shadows outer.
  - A CTE named like a real table shadows it inside scope, as the engine does.
- **Schema-qualified names**: qualified parts win. Missing parts:
  - postgres: database = call's `path` database (required by run_query today); unqualified relation names resolve
    by the server's `search_path` through the catalog probe (section 3.2), never a guessed `public`. A
    `catalogname` other than the path database is refused.
  - mysql/mariadb: database = path database, else connection's database; none known is refused.
  - clickhouse: database = path database, else connection's configured database, else `default`.
  - sqlite: `main.` is stripped; any other qualifier (`temp.`, attached) is refused.
  - mongodb: database from path; `$lookup.db` style qualifiers use their own db.
- **Functions and procedures**: user code can read any table, invisible to the parser. Under a list:
  - `CALL`, `DO`, `EXECUTE`, `PREPARE`, anonymous blocks: refused.
  - A call to a user-defined function (postgres, mysql/mariadb, clickhouse SQL/executable UDF): refused, naming it.
    Built-in versus user is decided live by a catalog probe (section 3.2), never by a cached or embedded name list
    (a cache misses a function created a second ago, which is a bypass).
  - Built-ins that run SQL text or read a relation by name are refused by name: postgres `query_to_xml`,
    `query_to_xmlschema`, `query_to_xml_and_xmlschema`, `cursor_to_xml`, `cursor_to_xmlschema`, `table_to_xml`,
    `table_to_xmlschema`, `table_to_xml_and_xmlschema`, `schema_to_xml*`, `database_to_xml*`, `ts_stat`,
    `ts_rewrite`, `set_config`; clickhouse `dictGet*`, `dictHas`, `dictGetHierarchy`, `dictIsIn`,
    `dictGetChildren`, `dictGetDescendants`, `joinGet*`; sqlite `pragma_*` table-valued functions,
    `load_extension`.
  - ClickHouse table functions: allowed only `numbers`, `numbers_mt`, `zeros`, `zeros_mt`, `generateRandom`,
    `values`, `null`, `generate_series`; others (`remote`, `cluster`, `merge`, `file`, `url`, `s3`, `mysql`,
    `postgresql`, `view`, `dictionary`, `input`, ...) refused, including `INSERT INTO FUNCTION`.
- **Engines that reference other tables** in CREATE TABLE: clickhouse engines outside MergeTree family, `Memory`,
  `Log`, `TinyLog`, `StripeLog`, `Null`, `Set` are refused (Merge, Distributed, Buffer, Dictionary, MySQL, URL,
  ...); mysql `ENGINE=MERGE|FEDERATED|CONNECT` refused; postgres `CREATE FOREIGN TABLE`, `IMPORT FOREIGN SCHEMA`
  refused (not on the whitelist).
- **Statement whitelist** (fail closed, per dialect in section 3). Allowed: SELECT/WITH/VALUES/`TABLE t`,
  INSERT/REPLACE/UPDATE/DELETE/MERGE, EXPLAIN of an allowed statement, transaction control (BEGIN, START, COMMIT,
  ROLLBACK, SAVEPOINT, RELEASE), CREATE/ALTER/DROP/TRUNCATE/RENAME of TABLE/VIEW/MATERIALIZED VIEW, CREATE INDEX,
  postgres COMMENT ON TABLE/VIEW/MATVIEW/COLUMN, GRANT/REVOKE on tables (postgres only), REFRESH MATERIALIZED VIEW,
  ANALYZE/VACUUM/OPTIMIZE naming tables, LOCK naming tables. Everything else refused: SET/RESET/USE/ATTACH/DETACH/
  PRAGMA (they change name resolution or reach outside), SHOW/DESCRIBE (use the MCP metadata tools), COPY, LOAD
  DATA, `SELECT ... INTO OUTFILE|DUMPFILE`, CREATE FUNCTION/PROCEDURE/TRIGGER/RULE/EVENT/POLICY/DICTIONARY,
  CREATE DATABASE/SCHEMA, LISTEN/NOTIFY, postgres `DROP INDEX` (index name does not name its table without a
  catalog lookup).
- **Multi-statement input**: every statement parsed and checked; one refusal refuses the call.
- **Executable comments**: MySQL `/*! ... */` is code. TiDB's lexer treats it as code; a test pins it.
- **Unparsable**: refused under a non-all list. Refusal names the parser error and suggests plainer SQL or asking
  the user for all tables.

### 1.5 Tools gated

- `run_query`: full check (sections 2, 3).
- `explain_query`: same check on its `sql` (EXPLAIN reveals estimates and structure of the tables).
- `describe_table`: path's relation must be listed; a non-relation path (function, sequence) under a list is
  refused; a path below a relation (column) needs its relation listed.
- `describe_schema`: relations not listed are dropped from the result.
- `list_children`: nodes of kind table, view, matview, collection whose relation is not listed are dropped; a path
  below an unlisted relation is refused.
- `list_connections`: new `tables` field; `maskedColumns` drops rules whose `TableName` is neither `*` nor the
  name part of a listed entry (it names tables otherwise).
- Not gated: `run_script` (user-authored, user-exposed script; SQL fixed by the user, like a view), ops, kube,
  proof, api tools (no DB tables). P535 browse uses the same allow list directly (section 7).

### 1.6 Not an exemptable limit

The allow list is not a P528 `Limit`: its refusal never names `exemption`, no exemption id is minted, and the gate
runs before `claimExemption`, so a refused call spends no id and no EXPLAIN.

## 2. Gate order and the one hook

Stream A owns `runQuery`'s body (`claimExemption`, `checkLimits`, `awaitExemption`, exec limits). P532 does not
touch `runQuery`. Its run_query hook is the **last gate inside `resolveVerdict`**, after `tightenByClass`, just
before `return rv, nil, nil, nil, false`. Stream A leaves `resolveVerdict` unchanged, so the rebase is clean.

Resulting `run_query` order: resolve, path check, check mode, gate mode, clamp maxRows, read threshold, connect,
classify, tighten, **table allow list (P532)**, claim exemption (P528), pre-limits (P528/P530), maybeExplain,
approval or exemption dialog, exec limits plus execute (P528/P529), render, review.

Why there: after connect (the probe needs a live adapter) and after tighten (a wrong mode gets its more useful
refusal first); before any approval, exemption claim or EXPLAIN (no prompt, id or plan spent on a refused call).

Hunk in `tools.go` `resolveVerdict`:

```go
	if msg := tightenByClass(rv.summary, rv.mode, class); msg != "" {

	// P532: table allow list, before any exemption, limit, EXPLAIN or approval.

		return rv, res, out, err, true
	}

```

Other `tools.go` hunks, each a few lines: `explainQuery` right after its `state.Status != "connected"` check;
`listChildren`, `describeTable`, `describeSchema` after `resolveReadGated` (use its summary, today discarded with

## 3. Go design

### 3.1 `apps/kira-studio/internal/tableref` (new package)

Pure. Shared by connfiles (validation), adapters (output type), dbmcp (matching) and the bridge.

```go
// Ref is one table, view or collection, fully qualified for its kind. Unused levels are "".
type Ref struct{ Database, Schema, Name string }

// Levels is how many parts an entry has for kind: 3 postgres; 2 mysql, mariadb, clickhouse, mongodb;
// 1 sqlite, kibana; 0 when the list does not apply.
func Levels(kind string) int
func Applies(kind string) bool { return Levels(kind) > 0 }
// Parse reads one entry. Quoted segments may hold '.', '"' (doubled) and spaces.
func Parse(kind, entry string) (Ref, error)
// Format writes the canonical entry: quotes only where Parse needs them.
func Format(kind string, r Ref) string
// Key is the match key: Format, ASCII-lowercased for sqlite.
func Key(kind string, r Ref) string
// Set is a parsed list. A nil *Set means all.
type Set struct{ kind string; keys map[string]bool; names map[string]bool }
func NewSet(kind string, entries []string) (*Set, error) // nil entries -> nil, nil
func (s *Set) Allows(r Ref) bool                          // nil s -> true
func (s *Set) AllowsName(name string) bool                // name part only, for maskedColumns
// FromPath maps a tree path to the relation it is or sits under. ok false when the path names no relation.
func FromPath(kind string, segs []model.PathSegment) (r Ref, ok bool)
```

`FromPath` per kind: postgres `database/schema/(table|view|matview)`; mysql/mariadb/clickhouse
`database/(table|view|matview)`; sqlite `(table|view)` (implementer confirms sqlite's root shape via
`sqlite.Adapter.Children`); mongodb `database/collection`; kibana `collection` (data view id). Unit-tested
(quoting rules interact: section 6.1).

### 3.2 Adapter seam: `apps/kira-studio/internal/adapters/tablerefs.go` (new)

Two phases, so a pure parse never costs an op or a throttle slot; only a statement needing the catalog runs a probe
op.

```go
// FuncRef is a routine call the catalog decides (built-in or user).
type FuncRef struct{ Schema, Name string }

// TableParse is what statements name before any catalog lookup.
type TableParse struct {
	Refs        []tableref.Ref // qualified by the text or the path
	Unqualified []string       // postgres only: relation names search_path resolves
	Funcs       []FuncRef      // calls whose origin the catalog decides
	Refusal     string         // non-empty: refused under a list (unparsable, CALL, SET, denied built-in, ...)
}

func (p TableParse) NeedsProbe() bool { return len(p.Unqualified) > 0 || len(p.Funcs) > 0 }

// TableReferencer names the tables a statement touches (P532). Kinds with tables implement it.
type TableReferencer interface {
	ParseTables(statement string, path model.NodePath) TableParse
	// ResolveTables runs the catalog probe for p (called only when p.NeedsProbe()). refusal non-empty refuses
	// (a user function); err fails the call closed.
	ResolveTables(ctx context.Context, p TableParse, path model.NodePath, op *OpCtx) (refs []tableref.Ref, refusal string, err error)
}
```

Refusal constructs carry short agent text, e.g. `CALL`, `SET`, `function public.audit_rows`, `table function
remote`, `statement CREATE TRIGGER`, `parse error: <parser message>`.

Each adapter keeps a pure function (`parseTablesPostgres(sql, database string) TableParse`, etc.) that
`ParseTables` wraps with its defaults; unit tests call the pure function.

**Postgres** (`adapters/postgres/tablerefs.go`): `parser.ParseToJSON` (go-pgquery `parser` subpackage), decode into
`any`, walk generically:
- Top level `stmts[].stmt`: whitelist keys `SelectStmt`, `InsertStmt`, `UpdateStmt`, `DeleteStmt`, `MergeStmt`,
  `ExplainStmt`, `TransactionStmt`, `CreateStmt`, `CreateTableAsStmt`, `ViewStmt`, `AlterTableStmt`, `RenameStmt`
  (renameType TABLE/VIEW/MATVIEW/COLUMN/TABCONSTRAINT), `IndexStmt`, `DropStmt` (removeType TABLE/VIEW/MATVIEW),
  `TruncateStmt`, `CommentStmt` (objtype TABLE/VIEW/MATVIEW/COLUMN), `GrantStmt` (objtype TABLE, target object),
  `RefreshMatViewStmt`, `VacuumStmt` (non-empty rels), `LockStmt`. Other keys refuse `statement <Key>`.
- `RangeVar` anywhere: ref (`catalogname`, `schemaname`, `relname`), CTE scope applied (section 1.4). No schema:
  `Unqualified`.
- `DropStmt.objects` and `CommentStmt.object` hold `String` lists, not `RangeVar`: read those explicitly.
- `FuncCall.funcname` and `RangeFunction`: qualified with `pg_catalog`: denied-name check only; other qualifier:
  refuse `function s.f` (user schema); unqualified: denied-name check, then `Funcs` for the probe.
- `WithClause` scoping: when a node holds `withClause`, push its `ctes[].CommonTableExpr.ctename` with the
  recursive flag, walk each CTE body with its visible set, then the rest.
- Probe (`ResolveTables`), one statement on the path database, via the adapter's client for that database, with
  `op.SetCommand(probe)`:
  - unqualified relations: schema of `to_regclass(name)`; NULL (does not exist yet, e.g. CREATE TABLE) resolves to
    `current_schema()`.
  - functions: names present in `pg_proc` under `pg_catalog`. Any `Funcs` name absent there is user or extension
    code: refusal `function <name>` (unqualified names always resolve pg_catalog first, so a pg_catalog hit is the
    built-in).
  - Literals: dollar-quote each name with a tag absent from the name (independent of
    `standard_conforming_strings`). Never string concatenation of raw names.
  - Residual, written in ARCHITECTURE: a `SET search_path` the user ran in their own console session is not seen.
    MCP cannot run SET under a list.
- First `ParseToJSON` call compiles the wasm module (lazy, once per process). If that first call measures over
  1 s, warm it in a goroutine when the DB MCP server starts; record the measured value in the Result.

**MySQL/MariaDB** (`adapters/mysqlfamily/tablerefs.go`): `parser.New().ParseSQL`; `ast.Visitor`.
- Whitelist: `SelectStmt` (refuse non-nil `SelectIntoOpt`), `SetOprStmt`, `InsertStmt`, `UpdateStmt`,
  `DeleteStmt`, `ExplainStmt`, `BeginStmt`, `CommitStmt`, `RollbackStmt`, `SavepointStmt`, `ReleaseSavepointStmt`,
  `CreateTableStmt` (refuse ENGINE MERGE/FEDERATED/CONNECT), `CreateViewStmt`, `AlterTableStmt`,
  `RenameTableStmt`, `DropTableStmt`, `TruncateTableStmt`, `CreateIndexStmt`, `DropIndexStmt`,
  `AnalyzeTableStmt`, `LockTablesStmt`, `UnlockTablesStmt`.
- `*ast.TableName`: ref; CTE scope from `*ast.WithClause` (`CTEs`, `IsRecursive`) on select/setopr/update/delete.
- `*ast.FuncCallExpr`: keyword-typed builtins skipped; generic (`Tp` generic or `Schema` set) go to `Funcs`.
  Aggregates and window functions are separate node types, skipped.
- Probe: `information_schema.ROUTINES` where `ROUTINE_TYPE = 'FUNCTION'` and (schema, name) match; unqualified use
  the default database. Literals as hex (`CONVERT(0x… USING utf8mb4)`), safe under `NO_BACKSLASH_ESCAPES`.
  A hit refuses `function db.f`. Loadable UDFs (`mysql.func`, admin-installed native code) are out of scope: say so
  in ARCHITECTURE.

**ClickHouse** (`adapters/clickhouse/tablerefs.go`): `clickhouse-sql-parser` `NewParser(sql).ParseStmts()`; walk
the AST (library's visitor or `Walk`, whichever v0.5.6 exports).
- Whitelist: SELECT (incl. `WITH`), INSERT (refuse `INSERT INTO FUNCTION`), ALTER TABLE (incl. UPDATE/DELETE
  mutations), CREATE TABLE (engine rule), CREATE VIEW / MATERIALIZED VIEW (`TO t` is a target), DROP TABLE/VIEW,
  TRUNCATE, RENAME TABLE, EXCHANGE TABLES, OPTIMIZE TABLE, EXPLAIN of an allowed statement, DELETE FROM
  (lightweight delete). Refuse SET, USE, SYSTEM, KILL, ATTACH, DETACH, SHOW, DESCRIBE, CREATE FUNCTION/DICTIONARY.
- Table identifiers: ref; table functions: section 1.4 allow set; `WITH name AS (subquery)` is a CTE scope;
  `WITH expr AS alias` is a scalar alias, not a table.
- Function calls: denied names refused; others to `Funcs`; probe `system.functions` for names whose `origin` is not
  `System` (literals via `unhex('…')`). If the server lacks the `origin` column (implementer checks the minimum
  supported version in `MIN_SERVER_VERSION`), the probe errors and the call fails closed.

**SQLite** (`adapters/sqlite/tablerefs.go`): `rqlite/sql` `NewParser(strings.NewReader(sql))`, loop
`ParseStatement` to EOF; `sql.Walk`.
- Whitelist: SELECT, INSERT, UPDATE, DELETE, EXPLAIN [QUERY PLAN] of an allowed statement, BEGIN, COMMIT,
  ROLLBACK, SAVEPOINT, RELEASE, CREATE TABLE/VIEW/INDEX, ALTER TABLE, DROP TABLE/VIEW, ANALYZE t. Refuse ATTACH,
  DETACH, PRAGMA, VACUUM (incl. INTO), REINDEX, CREATE TRIGGER, DROP INDEX.
- Table names via `sql.QualifiedTableName` and friends; CTE scope; `pragma_*` and `load_extension` refused.
- No probe: SQLite has no SQL-defined functions. Implementer greps for app-registered functions
  (`RegisterScalarFunction`, `RegisterDeterministicScalarFunction`, `sqlite.Register*`); none expected. If any
  exist, refuse calls to them by name.

**MongoDB** (`adapters/mongo/tablerefs.go`): reuse `parseStatement`; target collection from `parseTarget`. For
`aggregate`, walk the pipeline: `$lookup.from` (and nested `pipeline`), `$graphLookup.from`, `$unionWith`
(string or `{coll, pipeline}`), `$out` (string or `{db, coll}`), `$merge.into` (string or `{db, coll}`), `$facet`
sub-pipelines. A stage value of an unexpected shape for those keys refuses (fail closed). Parse error refuses. No
probe.

**Kibana** (`adapters/kibana/tablerefs.go`): decode the statement exactly as `Execute` does
(`DisallowUnknownFields`); data view = `dr.DataView`, else path segment; ref `{Name: id}`. Decode error refuses.
No probe.

Redis, kafka, s3, sqs: do not implement `TableReferencer`.

### 3.4 dbmcp: `apps/kira-studio/internal/dbmcp/tables_gate.go` (new)

```go
// statementTabler is the optional QueryRunner half that names a statement's tables (*adapterhost.Router).
type statementTabler interface {
	StatementTables(ctx context.Context, connectionID, path, statement string) (adapterhost.TablesResult, error)
}

// allowListOf parses summary.McpTables. nil set = all. A stored entry that fails to parse (file validation
// should have stopped it) returns an error: callers refuse, never fall back to all.
func allowListOf(summary model.ConnectionSummary) (*tableref.Set, error)

// checkStatementTables refuses a statement under a non-all list when it touches an unlisted table, cannot be
// parsed, or uses a refused construct. A nil res and err means pass.
```
