## 2. Decisions

### 2.1 Permission: `masked`, file key `mcp.masked`, UI "Read masked data"

```yaml
mcp:
  read: deny
  masked: allow      # inherit (absent) | deny | allow | prompt
```

- Name: mode word `masked` everywhere (file key, model, `list_connections`, approval payload `mode`, P536's
  `mcp.review.masked`). UI label `Read masked data`.
- Values `inherit | deny | allow | prompt`. **Absent = `inherit` = same as read's value.** Why: browse reaches a
  subset of what read reaches, with masking stricter, so following read changes nothing for any existing connection:
  read deny stays deny for browse, read allow gives browse nothing read did not already give. A plain `allow` default
  would silently open row reads on a connection whose read is `deny`. A plain `deny` default would make the "browse
  first" tool refuse on every existing connection.
- Independent: any explicit value wins over read. The main use is `read: deny` (or prompt) with `masked: allow`.
- Not touched by `read_only` or write console (it is a read). Kinds without structured browse (2.9): access
  `{allowed: false, reason: "no structured browse"}` whatever the value.
- New connections: absent (inherit). File written only when not `inherit` (same rule as other modes' defaults).
- Relation to read/write/ddl: `masked` gates only `browse_table`. It never lets `run_query`, `explain_query` or the
  schema tools run. `read` does not imply `masked` once `masked` is set explicitly; `masked: deny` with `read: allow`
  is valid (agent must use `run_query`). Schema tools (`list_children`, `describe_table`, `describe_schema`) are
  allowed when read **or** masked is not deny (the agent needs columns to build a spec); today they need read.

### 2.3 Real query: `run_query` stays the distinct fallback tool, no new field

- `browse_table` is a new tool. `run_query` is already a separate tool, with `mode` declared; that is the explicit
  opt-in to a real query. No extra field: a field such as `custom: true` on `run_query` adds no guard (the agent sets
  it as easily as it calls the tool) and costs prompt budget.
- Steering is by text (2.11) plus refusals: `run_query` with mode read on a connection whose read verdict is deny and
  masked is allowed refuses with `... Allowed: <summary>. Rows can still be read with browse_table (masked).`
- No refusal of `run_query` statements that browse could serve: not asked, and classification of "browsable" from SQL
  text is the heuristic this phase exists to avoid.

### 2.4 Tool `browse_table`: structured spec

```json
{
  "connectionId": "c_…",
  "path": "<encoded table path from list_children>",
  "columns": ["id", "email", "created_at"],
  "filters": [{"column": "status", "op": "eq", "value": "open"},
              {"column": "id", "op": "in", "values": [1, 2, 3]},
              {"column": "email", "op": "isNull"}],
  "order": [{"column": "created_at", "direction": "desc"}],
  "limit": 50,
  "offset": 0
}
```

- `path`: one relation (tableref.FromPath ok, depth `containerDepth+1`), else refuse `browse_table needs a table path
  from list_children`.
- `columns`: optional, 1 to 200 distinct exact catalog names; omitted = every column. Never an expression.
- `filters`: optional, at most 20, ANDed (no OR, like one grid WHERE of ANDed comparisons). `op`: `eq ne lt lte gt gte
  in like isNull notNull`. `value` (scalar: string, number, boolean) for the comparison ops and `like`; `values` (1 to
  50 scalars) for `in`; neither for `isNull`/`notNull`. Strings at most 1000 runes. `like`: the agent's pattern, `%`
  and `_` are wildcards, case sensitivity is the engine's.
- `order`: optional, at most 5 terms, `asc|desc`.
- `limit`: 1 to 100, default 50 (schema `maximum` 100; the SDK rejects more before the handler).
- `offset`: 0 to 100000, default 0. Offset paging only: a keyset token carries display text of key columns, which
  could carry a masked or withheld value.
- Column names match exactly (case-sensitive), as the grid does. An unknown name refuses, listing the table's columns
  (names are schema, already in `describe_table`).
- Result: the run_query tabular shape (`renderTabularPage`) plus `offset`, `hasMore`, `nextOffset` (when hasMore),
  `withheldColumns`/`withheldNote` when any were left out. No `plan`.

### 2.5 Statement: built by the adapter's own grid read path, values bound as parameters

Reuse the grid browse builder (`adapter.Read` → `PlanRelationalPage`/`BuildPageSQL`, ClickHouse `readPage`), extended
with a structured condition list. No SQL text from the agent reaches any adapter.

- `adapters.ReadRequest` and `adapters.ReadReq` gain:
  ```go
  // Conditions are ANDed after Filter. Values bind as parameters, never as SQL text.
  Conditions []model.Condition
  // StatementTimeout bounds the read on engines with a session mechanism; zero means none (P529 semantics).
  StatementTimeout time.Duration
  ```
  `model.Condition{Column, Op string; Values []any}` in `storage/model/queries.go`; each value `string` or `bool`
  (numbers arrive as their exact JSON text, `json.Number`). Ops as 2.4.
- `adapters/conditions.go` (new): `BuildConditionsSQL(conds []model.Condition, columns map[string]model.ColumnMeta,
  quote func(string) string, placeholder func(idx int, col model.ColumnMeta) string, addParam func(any) int,
  isBinary func(string) bool) (string, error)`:
  - unknown column → `CodeNotFound` (a contract error from dbmcp's view: dbmcp validated first);
  - `col = ph`, `<>`, `<`, `<=`, `>`, `>=`, `col IN (ph, …)`, `col LIKE ph`, `col IS NULL`, `col IS NOT NULL`;
  - binary column values decoded from `0x…` like keyset; bool binds as Go `bool`;
  - returns `(c1) AND (c2) …`; caller ANDs it with `WhereClause(Filter)` and the keyset predicate.
  `placeholder` takes the column so ClickHouse can emit `{p1:<DataType>}`; the others ignore it.
- Postgres, mysqlfamily, sqlite `readPage`: after `WhereClause`, AND the conditions (one helper
  `adapters.AppendWhere(whereSQL, extra string) string`). Params order: conditions, keyset, LIMIT, OFFSET (left to
  right for `?` dialects). `RelationalFingerprint` gains `Conditions`.
- ClickHouse `readPage`: same helper; params passed to `StreamQuery`'s query-param argument (today `nil`) through
  the `param_` convention; placeholder `{pN:<column DataType>}`.
- Statement timeout in `Read`: postgres, mysqlfamily, clickhouse reuse their console helper for the read path
  (re-read `postgres/console.go` ~328-385, `mysqlfamily/console.go` ~256-330, `clickhouse/console.go` ~159); timeout
  errors map to `adapters.StatementTimeout` as in the console. SQLite: none (host timer only), matching
  `timeoutEnforcementOf(kind, "read")`.
- Mongo, redis, kafka, s3, sqs, kibana `Read`: non-empty `Conditions` → `adapters.Unsupported(kind, "structured
  conditions")`. Never reached through dbmcp (2.9); guards the contract.
- `assertReadOnlyFilterSortSafe` unchanged (conditions carry no SQL text).
- Why extend Read rather than build SELECT text in dbmcp and run it through `ExecuteRead`: the adapters already own
  identifier quoting, projection resolution, sort validation and parameter binding per dialect; a dbmcp-side builder
  would need its own literal escaping per engine (backslash rules differ between MySQL, Postgres
  `standard_conforming_strings` and ClickHouse), and one escaping slip in a filter value would reopen exactly the
  masking bypass this tool closes. No library builds statements for these five engines with this codebase's
  quoting, page planning and ClickHouse typed parameters; the existing builder is the one to reuse.

### 2.6 Execution path: `Router.Browse`, read lane, no page cache

`adapterhost/browse.go` (new):

```go
// BrowseRequest is browse_table's read: one page through adapter.Read on the read lane, never cached.
type BrowseRequest struct {
	OpID             string
	ConnectionID     string
	Path             string
	Projection       []string
	Conditions       []model.Condition
	Sort             *model.SortSpec // structured only
	PageSize         int
	Offset           int
	StatementTimeout time.Duration
	TimeoutByEngine  bool
}

func (r *Router) Browse(ctx context.Context, req BrowseRequest) (page.Page, error)
```

- Lane: same checkout as `ExecuteRead` (`acquireLane`, release on return); kinds outside `laneKinds` refuse (never
  reached: 2.9 kinds are all lane kinds). The engine's read-only session backs the guarantee that nothing writes, even
  if a builder bug slipped.
- Op: `runOp` kind `read`, `OpSpec.Timeout = StatementTimeout` (+ the P529 grace when `TimeoutByEngine`), so the P531
  per-connection gate admits it and the op log and Operations panel show it with the adapter's command text.
- No `enginecache`: conditions are not in the page cache key, and an MCP read must not be served from a grid page.
- Validates `PageSize` 1..100 and `Sort.Kind == "structured"`; else contract error.
- dbmcp `QueryRunner` gains `Browse(ctx, adapterhost.BrowseRequest) (page.Page, error)`; flow fakes and
  `flowharness` wiring updated.

### 2.7 Gate order for `browse_table`

1. resolve connection (`resolveEnabled`);
2. kind has structured browse (2.9), else refuse;
3. masked verdict (`modeVerdict(summary, modeMasked)`): deny → `connection "x" does not allow masked reads over MCP.
   Allowed: <summary>` (+ ` Use run_query (mode read).` when read is not deny);
4. spec shape (2.4): counts, ops, values, path is a relation;
5. table allow list (P532): `allowedPath(summary, set, path, true)`; bad list → `badListResult`;
6. connect (`connectForQuery`, state connected);
7. describe (`Tree.Describe(ctx, id, path, false, nil)`, L1 cached, throttled op only on miss): columns, relation kind;
8. mask state (P534 `maskStateFor`): incomplete → refuse (not exemptable);
9. relation kind: `view`/`matview` on a masked connection (rules or withheld non-empty) → refuse (2.8);
10. column rules (2.8): resolve projection, filter and order columns against the described columns, masked and
    withheld names;
11. approval (verdict prompt): one `db.query` item, `Mode: "masked"`, `Class: read`, `Statement`: display preview
    (2.10), `Enforcement: enforcementOf(kind)`, `OfferReview: true` (P536); approve → re-check exposure, masked
    verdict, allow list (stored summary refreshed, like `recheckAfterApproval`);
12. execute: re-read `maskStateFor` and redo step 10 on the fresh state (a column withheld or masked during a 10 min
    wait is caught); `Router.Browse` with the P529 timeout (`applyStatementTimeout` semantics, mode read);
13. render (2.8), masked driver errors value-free (`maskedConnection`), timeout → refusal (2.7 note);
14. P536 result review: `reviewForMode(summary, "masked")` or the approver's request → `reviewResponse`.

Not applied, on purpose:
- **No classifier, no tighten**: the statement is app-built SELECT on the read lane.
- **No P530 EXPLAIN / expensive_query**: no statement text exists in dbmcp; `planFor` explains agent SQL text and a
  parameterized plan needs a new plan path per engine. Bound instead by construction: at most 100 rows, offset at most
  100000, the statement timeout, the throttle. Known limit (section 12); user decision (section 14).
- **No P528 exemption**: browse has no `exemption` field. A timeout refusal reads `browse_table on "x" stopped at the
  connection's <n> s statement timeout. Narrow the filters, or use run_query with an exemption if read is allowed.`
  The `run_query` hint is shown only when read is not deny.

`list_children`, `describe_table`, `describe_schema`, `explain_query` gate change: `resolveReadGated` passes when read
**or** masked is not deny (masked inherit counts as read). `explain_query` keeps read only (it runs agent SQL).

### 2.8 Masking rules on the browse path; filters on masked columns

Masked name = a rule name from `maskset.Set` (P534 fold: lowercased column name, table ignored). Withheld name = P534
`maskset.withheld`. Matching is case-insensitive against the exact catalog name, like render.

- Projection: requested (or all) columns minus withheld names; the left-out ones go to `withheldColumns` with P534's
  `withheldNote`. Every requested column withheld → refuse `every requested column on "x" is withheld until the user
  reviews masking`. Masked columns stay in the projection and render masked (`renderTabularPage` with `mk`).
- **Filters on a masked column: only `isNull` and `notNull`.** Any comparison, `in` or `like` refuses:
  `column email on "x" is masked; browse_table only filters it with isNull or notNull. A comparison would let rows
  chosen by value reveal it.` Why: equality confirms a guessed value, ranges allow binary search, `like` allows
  prefix enumeration; with masked output the filter is the only remaining channel. Null-ness is one bit per row the
  user chose not to protect by masking (no masking kind preserves null-ness differently from a cell being absent),
  and "rows without an email" is a common legitimate ask.
- **Order on a masked column: refused** (`... cannot be sorted on; order reveals its values' order`). Order plus
  offset is a binary search over values.
- **Withheld columns: no filter, no order** (P534 text via `newColumnUnreviewedRefusedError(name, false)`).
- Correlation-tag kinds (`Correlate`) follow the same rule: masked is masked.
- Table-scoped rules: the P534 name fold stays (a `customers.email` rule also masks `orders.email`, safe direction).
  Not loosened to table-exact on this path: the over-mask is the user's existing configuration.
- Views: on a masked connection, `view`/`matview` refuse (`browse_table reads base tables only on a connection with
  masking: a view can rename a masked column`). A view defined as `SELECT email AS e` would otherwise return `e`
  clear: masking is by result name. Unmasked connections browse views.
- Render: `renderBrowsePage(pg page.TabularPage, limit int, mk *maskset) (browseResult, error)` in `render.go`: calls
  `renderTabularPage` directly. None of the statement-text guards run (no statement), including
  `riskyResultTypeClasses`: a JSON column here is a stored column, not an expression carrying a masked one. A
  non-tabular page → internal error (never produced by 2.9 kinds).
- What this closes for this path (masking leaks 2 and 3 in P534 section 1): no alias, expression or set-op can rename
  a masked column (projection is exact catalog names), and no value predicate touches a masked column. Leak 1
  (name-only rules) and leak 5 (scripts) stay, and are stated in the tab and docs.

### 2.9 Engines without structured browse

`browseKinds`: postgres, mysql, mariadb, sqlite, clickhouse (the shared relational builder plus ClickHouse's). Mirror
`BROWSE_KINDS` in `packages/shared/domain/dbmcp.ts`.

- mongodb: document pages; masking already refuses document results; a structured find builder is separate work.

no structured browse; use run_query (mode read) where read is allowed`, the MCP tab row is disabled with a note.
`mcp.masked` on those kinds is not a validation error (the value is kept for a later phase).

## 12. Known limits (to ARCHITECTURE and the tab)

- Masking stays name-based for rules (leak 1); browse closes alias/expression renames and value predicates only.
- Browse skips the expensive-query EXPLAIN; worst case is one timed-out read per call.
- Views refused on masked connections (a view can rename a masked column).
- Offset paging only, offset at most 100000; deep offsets cost a scan up to the timeout.
- `like` case sensitivity follows the engine and collation.
- MongoDB, Redis, Kafka, S3, SQS, Kibana: no browse.
- Null-ness of masked columns is observable through `isNull`/`notNull`.

## 13. Decisions for the user

- **Masked columns accept only isNull/notNull filters and no sort.** Alternative: equality allowed (enables
  guess-confirmation) or no filter at all on masked columns.
- **Browse skips P530's EXPLAIN check.** Alternative: a parameterized EXPLAIN path per engine (separate phase).
- **Absent `mcp.masked` follows read.** Alternative: default `allow` everywhere (silently opens masked reads where read
  is denied) or `deny` (browse refuses until set).
- **Views refused only on masked connections.** Alternative: base tables only everywhere.
