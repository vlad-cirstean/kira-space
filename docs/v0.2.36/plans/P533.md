## Which entries change

Change (table-bearing query path):

- `dbmcp.instructions`: the one place every client reads on connect.
- `dbmcp.tool.describe_schema`, `dbmcp.tool.describe_table`: say when to call them.
- `dbmcp.tool.run_query`: point of use.
- `dbmcp.tool.explain_query`: also takes a written statement.

No change, with reason:

- `list_connections`: about permissions/access; instructions already say start there. Adding schema advice dilutes it.
- `list_children`: a walk step, not a query step; describe_* text already says where `path` comes from.
- `proof_*`, `list_operations`, `cancel_operation`, scripts, `api_*`, `kube_*`: no tables queried.
- `run_query` arguments: unchanged (P528 adds argument entries there; avoid overlap).

## Exact new text

Wording uses imperative per CLAUDE.md style; nothing in code checks it, which is what "suggestion only" means. Implementer copies these strings exactly.

1. `dbmcp.instructions` — replace this sentence only:
   - old: ``` `describe_schema` returns every relation's columns in one call, cheaper than one `describe_table` per table.```
   - new: ```Before writing a query, inspect the schema of the tables it touches: `describe_schema` returns every relation's columns in one call, cheaper than one `describe_table` per table.```
   - Size 2082 to 2151 (+69).
2. `dbmcp.tool.describe_table` — append ` Call it before querying that table.` Size 106 to 142.
3. `dbmcp.tool.describe_schema` — append ` Call it before querying those tables.` Size 127 to 165.
4. `dbmcp.tool.run_query` — append at the end of the Default (after the kibana sentence): ` On engines with tables, inspect the tables a statement touches with describe_schema or describe_table before writing it.` Size 854 to 975.
5. `dbmcp.tool.explain_query` — append ` Inspect the tables with describe_schema or describe_table first.` Size 365 to 430.
