# P531 Ops throttle covers every op from every session, with explanation

Stream B. Base `chapter/v0.2.36` at `32484107d`. Runs beside P528 (Stream A); file ownership below keeps off `internal/dbmcp/*`, approvals and `internal/llmprompts`.

## 1. Current semantics (read from source)

- Limiter: `internal/adapterhost/throttle.go`. One `golang.org/x/time/rate.Limiter` per connection id in `throttleRegistry`, burst `max(1, min(10, round(perSec)))`.
- Gate: `Host.RunOp` (`host.go:266-279`). Op registers, then `limiter.Wait` bounded by `throttleMaxWait` (30 s), then `op:start`, then the adapter call.
- **Not serial.** The gate only paces admission. Admitted ops run concurrently, any number at once. So "ops run one at a time" is false today: a slow query does not delay later ops, it only shares the token bucket.
- **Per connection, app-wide already.** One `Router`/`Host` per process (`appwire/wire.go:86`), single instance (startup `StepInstanceLock`). All windows, tabs, MCP sessions and the P527 read lane key the same registry by connection id. No per-window or per-session limiter exists.
- Gated kinds are an allow-list (`throttledKinds`): read, count, mutate, execute, transfer, children, describe, definition, schemaColumns, keyTypes. Any new kind with a connection id is ungated by default (fail open; P108 Part 6 F3 already hit this once).
- Bypass: `Router.ClassifyStatement` (`router.go:471`) calls the adapter outside `RunOp`. Redis's classifier issues `COMMAND` and `COMMAND INFO` on cache miss (`adapters/redis/client.go:268`), real server work with no throttle. dbmcp calls it on every `run_query` and for each composed EXPLAIN statement.
- Live edit (`connections/service.go:404` `ConfigChanged`) calls `set`, which replaces the limiter: the bucket resets, queued waiters keep the old limiter.
- Timeout text is hard-coded English (`host.go:275`), not a catalog key.
- Set before Connect, cleared in `Router.Disconnect` (`router.go:326`).

## 2. Change

One gate per connection id, shared by every caller, serial plus paced, when `throttle_per_sec > 0`. At 0 nothing changes (concurrent, unpaced).

### 2.1 `throttle.go`

```go
type connGate struct {
	limiter *rate.Limiter
	slot    *semaphore.Weighted // weight 1; FIFO; ctx-aware Acquire
}
```

- `throttleRegistry.byID map[string]*connGate`.
- `set(id, perSec)`: `perSec <= 0` deletes. Existing entry: `limiter.SetLimit` + `SetBurst` in place, slot kept. New entry: fresh limiter + `semaphore.NewWeighted(1)`. Burst formula unchanged.
- `gateFor(id) *connGate` replaces `limiterFor`.
- Replace `throttledKinds` with `throttleExemptKinds = {connect, disconnect, test, preconnect}`. Gate rule: `spec.ConnectionID != nil && !throttleExemptKinds[spec.Kind]`. Fails closed for future kinds. Kinds without a connection id (http, grpc, kubernetes) stay ungated.
- Cleared entry while ops queue on it: holders capture the `*connGate` once; queued ops drain through the old slot. New ops see no gate. Bounded by the wait limit; no extra code.

### 2.2 `Host.admit`

`func (h *Host) admit(ctx context.Context, connectionID string) (release func(), err error)` in `host.go`:

1. `gateFor` nil: return no-op.
2. Reentrancy: if ctx carries a held-slot marker for this connection id, skip the slot (still take a token). Prevents a future nested call deadlocking. Today no `RunOp` fn calls back into a gated path; implementer confirms by grep.
3. `waitCtx := context.WithTimeout(ctx, h.throttleWait)`. One bound covers both waits.
4. `slot.Acquire(waitCtx, 1)`, then `limiter.Wait(waitCtx)`. Order matters: slot first, so tokens are spent only by the op about to run, and admitted rate holds.
5. On error release whatever was taken. Classify: `ctx.Err() == context.Canceled` gives `E_CANCELLED` (`backend.studio.adapter.cancelledWaitingForRateLimit.body`, text updated). Else `E_TIMEOUT`: slot wait gives `throttleBusyTimeout`, token wait gives `throttleRateTimeout` (§4). `rate.Limiter.Wait` fails early when the deadline cannot be met; same classification as today.
6. Return `slot.Release` (sync.Once guarded) and a ctx with the held-slot marker.

- `Host.throttleWait time.Duration` field, default `throttleMaxWait`, same pattern as `earlyTTL`. Unit tests shorten it.
- `RunOp`: replace the block at `host.go:266-279` with `admit`. Gate stays after registration, before `op:start` (DurationMs excludes queue time; queued op stays cancellable; no events for an op that never ran). Release right after `safeRun` returns, before `op:end` emit.

### 2.3 Bypass fix: classify

- New optional interface in `adapters/classify.go`: `RemoteClassifier { ClassifiesRemotely() bool }`. Redis implements it (`adapters/redis/console.go`), true. Pure-parse classifiers (postgres, mysql family, sqlite, clickhouse, mongo, kibana) do not, so they cost no token and no slot.
- `Router.ClassifyStatement`: when the adapter is a `RemoteClassifier` reporting true, wrap the call in `r.host.admit(ctx, connectionID)`. No op events (unchanged: classify is not an op-log row). Update its doc comment: the old "issues no server work" claim is wrong.
- dbmcp calls classify outside any `RunOp`, so no deadlock. Reentrancy guard covers the rest.

### 2.4 Read lane (P527)

Lane ops reach `executeOn` with `ConnectionID` = the connection id and `Adapter` = lane. Gate keys by connection id, so the lane shares slot and bucket with the main adapter. An MCP read waits behind a slow user query on the same connection and the reverse. That is the ask. Lane open (`connect`) and teardown (`disconnect`) stay exempt.

### 2.5 Cancel

`stopOp` calls `adapter.Cancel` directly, outside `RunOp`. Keep exempt: a cancel must reach an op holding the slot, else serial mode deadlocks Stop. Covers tab Stop (`CancelOp`), Operations panel and P518 `CancelRunning`, MCP `cancel_operation`, `CancelOpsForConnection`, `CancelOpsOnAdapter`. A queued op cancelled by any of these leaves the slot wait with `E_CANCELLED`, no slot leak.
