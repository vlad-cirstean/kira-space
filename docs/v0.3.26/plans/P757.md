# P757: false "merged into main"

Source: `SPEC.md` row P757, `plans/audit-merged.md`. Audit file:line checked against tree at
`17f78dba5`; current lines below.

## Definition (target)

A `mine`/`review`/`parked` branch row is merged into main iff:

1. it has own commits: `had_commits` latched when `Ahead > 0` against its **resolved base**
   (`resolveBase`), never against main; and its tip is reachable from main; or
2. a recorded merge holds at **exactly the current tip**: `merged_at` set and `merged_tip == tip`.
   Recorded by the ancestor rule (tip) or by a merged PR whose `HeadSha` equals the tip or descends
   from it.

No own commits: never merged by ancestry. Tip moved past a recorded merge: not merged, and the
record is cleared. Accepted, unchanged: reverted commits still read merged.

## Design decisions

- **Own-commit count: resolved base, not stored start tip.** `hadCommits := sb.HadCommits ||
  wb.Ahead > 0`. `wb.Ahead` is already computed against `base.tip` (`board_facts.go:359-366`); 0
  when `!base.ok`. Stored start tip declined: Kira does not see external rebases, so start..tip
  overcounts after any rebase not run by Kira, and adopted branches (`AddExistingBranch`) have no
  start. Write-once latch stays: it keeps a develop-based branch merged into develop (Ahead 0
  afterwards) counting once develop reaches main.
- **`merged_tip` column**, `TEXT NOT NULL DEFAULT ''`. Ancestor path stores `row.Tip`. PR path
  stores the **local tip it verified** (`wb.Tip`), not `HeadSha`: the read rule is plain equality,
  no git call per build. Pulling a PR head that is ahead of the local tip makes the row read not
  merged until the next Refresh re-checks (then `HeadSha == tip`, recorded again).
- **Clear on move.** A build that finds `merged_at` set but `merged_tip != tip` and not merged by
  ancestry writes a clear, guarded on the stale `merged_tip` (compare-and-clear). Stored-row readers
  (rebase stack, archive risk, history, quick artifacts) converge without each needing git.
- **Merged write overwrites a stale record**: `WHERE id = ? AND (merged_at IS NULL OR merged_tip <>
  ?)`. Old `IS NULL` guard blocked re-recording after a follow-up commit was merged.
- **PR check**: only rows with own commits; first change request must be `merged`, `HeadSha != ""`
  and `HeadSha == wb.Tip` or `IsAncestor(wb.Tip, HeadSha)`. Missing `HeadSha` object locally
  (`IsAncestor` error) reads not merged, logged at debug. "PR updated after `AddedAt`" declined: the
  head check already rejects a reused name's old PR (its head is not this branch's tip or a
  descendant), and `UpdatedAt` moves on any comment.
- **`newlyMerged` (`integration.go:368`): no change.** It reads `Integration` rows, which count own
  commits as `baseTip..tip` (`contains`, `integration.go:40-61`, `total == 0` reads not merged) and
  target only non-main integration branches (`withoutMain`). Stacked zero-commit and develop-based
  zero-commit rows give `total == 0`. The main-merge notice is `updates/diff.go:107`
  (`!a.Merged && b.Merged` from `wb.MergedIntoMain`), fixed by the producer fix.
- **No wire change.** `merged_tip` stays internal; `adewire.Branch.MergedIntoMain` and `MergedAt`
  keep shape. `wb.MergedAt` is set only while merged.

## Migration `0109_p757_merged_tip.sql`

Next free after `0108_p751_drop_issue_tracker.sql`. Patch release: migrations allowed (CLAUDE.md
minor-bump rule drops legacy only at a minor bump). Add `{Version: 109, Name: "p757_merged_tip",

```sql
-- P757: a merge into main is recorded at one branch tip and holds only at that tip.
ALTER TABLE ade_task_branches ADD COLUMN merged_tip TEXT NOT NULL DEFAULT '';

-- Live merges recorded before P757 have no tip. Forget them: the next board build re-records
-- ancestor merges, the next Refresh re-records PR merges.
UPDATE ade_task_branches SET merged_at = NULL
WHERE archived_at IS NULL AND merged_at IS NOT NULL;

-- had_commits of a stacked or non-main-based row was counted against main and may hold its base's
-- commits. Recount from the resolved base on the next build. Main is stored as base ''.
UPDATE ade_task_branches SET had_commits = 0
WHERE archived_at IS NULL AND had_commits = 1 AND (base_branch_id <> '' OR base <> '');
```

Main-based rows keep `had_commits`: their old count was against main, which is their base. Archived
rows untouched (history keeps its record).

## Risks

- Migration drops `had_commits` of stacked and non-main-based live rows. A develop-based or stacked
  row whose own commits already reached main before the upgrade cannot recount (Ahead against its
  base is 0) and reads not merged from then on. Accepted: false negatives on finished work beat the
  owner's false positives; such tasks are archivable.
- Squash-merged live rows read not merged from upgrade until the next Refresh re-checks the PR.
- PR path records the local tip; pulling a PR head ahead of it reads not merged until the next
  Refresh.
- Clear-on-move lands with the build's async write (`writeBoardMarks`); an archive inside that
  window keeps a stale `merged_at` in history. `branchRisk` checks the tip itself, so the archive
  dialog stays correct.
- `checkPrMerges` adds one `IsAncestor` spawn per merged PR whose head differs from the tip, only on
  Refresh. Negligible.
- P758 touches `artifacts.go` after this phase; it builds on this tree.
