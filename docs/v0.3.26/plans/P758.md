## Fixes chosen

All six, in priority order. a, b and c share one rewrite of the UI repo source.

### a. Host lookups never block Artifacts

- UI path (`Quick` false) answers each branch's change request from
  `RepoEntry.CachedBranchChangeRequest` (changerequests.go:598, no host call, any age), else the
  row's stored one, exactly as `quickRepoArtifacts` (artifacts.go:298-335) does. Branch web page
  from `entry.BranchURL` (:671, local compose, no network).
- Host gap: served from the last host kind known for the repo, not from a live lookup. New state
  `artifactHost` (new file `ade/artifacthost.go`): `mu`, `kind map[codeRepoID]string`,
  `refresh singleflight.Group`. One field on `TaskBoard` (`board.go:192` struct). Written by the
  background refresh below and by `ChangeRequests` (board.go:826-866, which already computes each
  repo's kind). A gap shows when the last kind is `unavailable`.
- Background confirm: after answering, the UI path starts one tracked job per task
  (`b.goTracked`, board.go:336; `refresh.DoChan` keyed by task id; a running job means skip). Under
  `context.WithTimeout(b.ctx, artifactHostRefreshTimeout)` (30 s) it runs `resolveRepoHost` per
  repo (blocking is fine here), records each repo's kind, rebuilds the repo share with the resolved
  change requests and URLs, and compares with what the call served. On any difference it pushes
  `notifyBoardWith(adewire.BoardChangedEvent{Refs: true, TaskIDs: []string{taskID}})`: refs true so
  the PR facts query refetches too. No difference, no push, so a refetch never loops.
- Stale entries: parity with today. `ResolveBranchChangeRequest` already served stale data and
  refreshed in the background without a push; the new path does the same. Only the miss case was
  blocking; the confirm job covers it.
- Archived tasks take the same path (their stored PR stays the fallback).

### b. Branch facts from the board snapshot

- New `boardCache` read `boardLatest() (board adewire.Board, current, ok bool)` in `boardcache.go`:
  the kept `snap` of any gen, `current` when its gen equals `c.gen.Load()`, `ok` false when none
  exists. Read-only, no build, no 2 s rule (that rule is for unannounced git moves; the next push
  refetches artifacts anyway).
- UI path, live task: facts by branch id from `boardLatest().Branches`. When `ok` is false (no board
  built yet), wait on `b.Board(ctx)` once, as today's cost. When the snapshot is not `current`, the
  background confirm job (a) also awaits `b.Board(b.ctx)` (joins the flight the frontend's board
  refetch starts on the same push), rebuilds the share and pushes on difference.
- `repoSource.Artifacts` drops the `BranchesLive` and `SetupByBranch` reads (artifacts.go:257-268)
  and `repoArtifacts` drops the `repoFacts` call (:385-388). `repoFacts` stays for its other
  callers (`board_writes.go`, `taskbranches.go`, `board.go`).
- Status rule with facts present: facts decide, `merged` iff `wb.MergedIntoMain`, else `pushed` iff
  `wb.Upstream != ""`, else `local`. Row `MergedAt` decides only without facts (archived, quick
  path, branch missing from the board). Today's code ORs `r.MergedAt` in first (:407-409), so a
  stale `merged_at` would outlive P757's fix. If P757 already rewrote these lines, keep its row rule
  for the no-facts case and apply the facts-decide rule on top.
- Refactor: split `repoArtifacts` into input gathering and one pure builder
  `repoShare(sc, nick, named, crs map[id]ChangeRequest, urls map[id]string, facts map[id]adewire.Branch, hostGap bool) ([]Artifact, []ArtifactGap)`.
  The served answer and the confirm job both call it, so the comparison is like for like
  (`slices.EqualFunc` or `reflect.DeepEqual` on the sorted output). The snapshot is shared
  read-only: never mutate `wb.Deployments`.

### c. Stored, task and notes links never wait on the repo source

- Delivered by a and b: the UI repo source now reads only caches, the store and the kept snapshot.
  It has no host or git wait left, so the errgroup answers as fast as the store reads, and stored,
  task and notes links arrive together with the cached repo share.
- Declined: a second bridge call (local list first, full list second). After a and b it would only
  double every refetch and add an IPC method, bindings, mocks and contracts for no remaining wait.
  The one remaining wait is the first board build of an app start, and the panel cannot open before
  the board has loaded.
- Frontend: the links skeleton waits `SPINNER_DELAY` like `QueryState`'s own placeholders
  (`packages/workbench/src/components/QueryState.vue`; reuse the helper it uses, else VueUse
  `useTimeout`), so a fast first answer never flashes it. Skeleton stays a trailing line under the
  task's slot pills (already the case).

### d. Details stays mounted

- `AdeTaskPanel.vue:199-201`: Details mounts on first visit and then stays mounted under `v-show`
  while the panel shows that task. Main and Sessions keep `v-if`. A local `ref` per panel
  instance tracks the first visit (panel-local, not shared state, so no Pinia store).
- `AdeDetailsTab` gets an `active` prop. `AdeDetailsDiskBanner` passes it as `useDiskChanges`'s
  existing `enabled` argument: no restat while hidden; re-enabling refetches the stale query, which
  keeps "stats on open" (ARCHITECTURE disk banner rule).
- Declined: `placeholderData: keepPreviousData` on `useTaskArtifacts`. Its key holds the task id, so
  on a task switch it would show the previous task's links under the new task. A same-key refetch
  already keeps data.

### e. Scoped pushes

- Backend: replace bare `notifyBoard()` with `notifyBoardWith(taskChanged(id))` where the write
  touches only the task's own rows: `artifacts.go:520`, `:587`, `foundlinks.go:134`,
  `handover.go:247`, `:306`, `links.go:156`, `:174`, `:285`. `handover.go:138` and `:148`: read
  `MirrorFinish` and `RecordRunHandover`; if they write the parent task's rows, pass both ids
  (`taskChanged(child, parent)`); keep the bare notify only if the parent id is not at hand. Before
  each change confirm the write touches no branch row, ref or change request (`taskChanged` doc,
  boardcache.go:93); a site that does keeps `notifyBoard()`.
- idlewatch Rescan (`idlewatch.go:202-205`): push `taskChanged` of every live task with no agent
  watcher and no grant (same rule `fire` applies at :206-213). On a store read failure keep
  `BoardChangedEvent{}`.
- Frontend: no artifacts-only filter. Declined because `BoardChangedEvent` carries no change kind
  and task-folder pushes (agent watcher passes) do change stored artifacts, so filtering would drop
  real updates. Scoping on the backend plus a and b make the remaining refetches cheap.

### f. DiskChanges does not wait on task ops

- `detailssubmit.go:431`: `mu.TryLock()`. On failure return the task's last result if one is cached
  (`detailsFiles` field `lastDisk map[taskID][]adewire.DiskChange` under its own mutex); with none
  cached, block as today (the first answer must be real). Store the result on every computed call.
- Drop `lastDisk[taskID]` in every path that changes what DiskChanges reports: Accept and Discard
  (`detailssubmit.go:505` area), `SyncTaskFiles`, `mirrorTask` (`details.go:258`). A cached answer
  is then never older than the last Kira write, and the op's own push restats once the lock frees.
- No wire flag for staleness: nothing would read it (the banner restats on the next push).

## Risks

- Confirm-job push loop: a push only on a real difference, and the refetch serves the refreshed
  caches, so the second confirm finds none. Deployment `CheckedAt` changes only with a new facts
  build, which is a real difference once. Verify with step 3 of the flow test.
- Stale facts window: an older-gen snapshot serves until the confirm job lands (one board build).
  Same window as the board view itself.
- Host gap after restart shows only after the first confirm (kind map is in memory).
- Background jobs must run through `goTracked` so `Close` waits for them; ctx is `b.ctx`, never the
  request ctx.
- Scoped push sites: a site that also writes a branch row or parent task must keep a wide push;
  missing one leaves another task's Details stale until the next push.
- f: a cached disk answer can omit a hand edit made during a long op until that op's push restats.
- d: a hidden mounted Details keeps its artifacts observer, so pushes still refetch it in the
  background; cheap after a and b.
- Owner-machine latency stays unmeasured until the slow-call log shows in a real run.
