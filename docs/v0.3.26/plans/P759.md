# P759 plan: remove the proof ready dialog

Goal: a new proof never pops a dialog. Delete `ProofReadyPrompt` and every symbol only it uses, end
to end (frontend, routed prompt kind, backend notify chain, seen tracking, DB column, i18n, specs,
docs). Keep every quiet signal that already tells the user a proof exists.

Discovery: CodeGraph (`ProofReadyPrompt proofReady NotifyProofReady`, `proof.Service RaiseReady
RaiseReview ...`, `detailsEvents Accepted RaiseUnreviewed MarkSeen`, `unitApply ProofChanged`) plus
grep for strings, specs and docs.

## How the popup works today

1. Agent saves `proofs/<slug>/proof.md`. `unitTx.create` (`taskfiles/proofunit.go:409`) calls
   `Decide(..., OpCreate)` only to copy `d.Notify` (`NotifyProofReady`) into `FileResult.Notify`.
2. `submitRun.finish` (`taskfiles/submit.go:300-306`) calls `Events.Accepted` for every accepted
   result with a notify.
3. `detailsEvents.Accepted` (`ade/detailssubmit.go:35-41`) calls `TaskBoard.proofReady`
   (`ade/proof.go:135-147`), which calls `ProofLinks.RaiseReady`.
4. `proof.Service.RaiseReady` (`proof/service.go:499-505`) opens a routed prompt
   (`prompts.KindProof`, id `proof:<session>`, title `backend.prompt.proof.title`) and emits
   `kira:proof:changed`.
5. The prompt router routes it to a window and posts the per-kind OS notification
   (`backend.prompt.count.proof.title` when several wait). `App.vue` maps kind `proof` to
   `ProofReadyPrompt.vue`, which reads `ProofService.Session` (for `taskTitle`) and offers Open.
6. Opening the proof window calls `markOpened` (`bridge/proof.go:340-349`), so
   `Service.MarkSeen` stamps `proof_sessions.seen_at` and withdraws the prompt. At boot
   `RaiseUnreviewed` re-raises prompts for sessions with `seen_at IS NULL` or a pending edit.

## Quiet signals that stay

- **Details task chain.** `SubmitFiles` (`ade/detailssubmit.go:238`) always ends with
  `notifyBoardNow(taskChanged(taskID))`; `ade/queries.ts:83-88` invalidates `proofsPrefix` on a board
  push, so the new proof appears as `AdeProofEntry` in the task's Details. No change.
- **`kira:proof:changed` for a new proof.** Today it comes only from `RaiseReady`'s `s.emit(id)`.
  `TestProofStaleSignal` (`flows/proofflow/stale_test.go:48`) waits for it, `ade/queries.ts:90`
  refetches on it, and ARCHITECTURE "Stale proof window" promises it. Keep it: move the emit into the
  normal `unitApply` path (set `a.changed` in `create`), see Step 1.
- **Pending edit review.** `RaiseReview`/`WithdrawReview`, `putReview`, the `proof.review` approvals
  item, `ProofOpenWindow.vue` approval body and `AcceptEdit`/`RejectEdit` stay. This is an approval of
  another agent's edit, not the ready popup. The boot re-raise stays for pending edits only (the
  approvals queue is in memory, `internal/approvals/queue.go:100`).
- **Proof window open path.** `ProofService.OpenWindow`, `AdeProofEntry` name click, the approvals
  body button stay. Only the seen stamp inside `OpenWindow` goes.
- **Agent notifications.** `agentnotify` finished/needs-input notifications are untouched; the
  agent writes a proof inside a run, so its finish note still reaches the user.
- **No task row badge exists.** No board row reads proof state (grep of `ade/v2` outside `details/`).
  Nothing to keep there; adding one is out of scope.

The router's OS notification for kind `proof` dies with the prompt: a router note exists only for an
open prompt, and a prompt with no dialog would sit in the routed list forever. Keeping that note
would need a new notification path; not in this row.

## Risks

- **Migration number clash with P757.** Both phases add a migration; P759 runs after P757 in table
  order. Take the next free number at implementation time.
- **Lost `kira:proof:changed` on a new proof** if Step 1's `a.changed` is missed: the chain still
  refreshes via the board push, but `TestProofStaleSignal` fails and ARCHITECTURE goes false. Step 1
  lands it in the same commit as the `RaiseReady` removal.
- **OS notification for a new proof goes away** with the prompt. Agent finish notifications remain.
  If the owner wants a desktop note without the popup, that is a new phase.
- **Pending-edit review still pops** (kind `approval`, approvals queue). Out of this row; the owner
  named only the ready dialog.
- **P758 overlap.** P758 touches Details opening (`AdeTask.Artifacts`, queries). P759 touches
  `ade/v2` only in `ade-v2-proof-chain.spec.ts`; `ade/detailssubmit.go` and `ade/proof.go` hunks are
  disjoint from P758's findings list. Rebase conflicts unlikely; resolve additively if any.
- **Contract writes merge.** Stale `taskTitle` keys stay in fixtures unless deleted by hand.
