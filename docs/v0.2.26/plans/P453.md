## 3. Decisions

### 3.1 Files and format

- One file `~/.kira-space/agent/settings.yaml`, YAML, cap 256 KiB, beside P452's `context.md`. One file,
  not separate `mcp.yaml`/`hooks.yaml`: one schema, one save and conflict domain, one resulting-config
  view, and `<provider>.skip_hooks` cross-references stay inside one document. `AGENTS.md` has a section
  per top-level key.
- Absent or empty file means no app settings: launches unchanged. Invalid with last good: last good in
  use. Invalid with no last good: no app settings (nothing was ever applied), the editor shows the problem.
- Shape (example, also the `AGENTS.md` example):

```yaml
env:
  JIRA_TOKEN: "${secret:jira}"
permissions:
  allow: ["Bash(git status)"]
  deny: ["Read(.env)"]
mcp_servers:
  github:
    url: https://api.githubcopilot.com/mcp/
    headers:
      Authorization: "Bearer ${secret:github-token}"
  notes:
    command: npx
    args: ["-y", "@modelcontextprotocol/server-filesystem", "${HOME}/notes"]
    env: { API_KEY: "${secret:notes-key}" }
    enabled: false
hooks:
  format:
    event: tool_end
    matcher: "Edit|Write"
    command: 'prettier --write "$FILE"'
    timeout: 30
claude:
  model: sonnet
  permission_mode: acceptEdits
  status_line: { command: "~/bin/statusline.sh", padding: 0 }
  hooks:
    compact-note: { event: PreCompact, command: "echo compacting" }
  skip_hooks: [format]
opencode:            # step 9
  model: anthropic/claude-sonnet-4-5
  plugins: ["file:///Users/me/.kira-plugins/notify.js"]
```

### 3.2 Reference syntax

- P450's `${NAME}` and `${secret:name}` (`$${` literal), in fields marked `x-kira-ref`: `env` values,
  `mcp_servers.*.{command,args[],url,headers.*,env.*}`. Never in hook commands or `status_line.command`
  (the shell expands `$VAR`; `AGENTS.md` says: put the secret in `env`, read `$NAME` in the command).
- Not `apivars` `{{name}}`: P450 fixed one syntax for every config file and kept `{{name}}` as the API
  module's own. `{{…}}` in YAML needs quoting or reads as a flow mapping; `${VAR}` is Claude's own MCP
  config expansion, so P454 exports env references unchanged. The two-stage shape is kept: stage 1 (load)
  checks syntax and keeps references verbatim in the decoded value and the projection; stage 2 (launch)
  resolves (`configfs.Resolver`) and returns `[]Used` for masking, the `apivars.UsedSecret` pattern.

### 3.3 Secret values: one shared sealed store

- Values must be readable by both apps (Space TUI and steps, Studio Continue in terminal). Per-app
  `secret_values` cannot share. New file `~/.kira-space/agent-secrets.db` (sibling of the agent folder,
  never inside it, so a synced or committed folder carries no ciphertext). Opened by both processes with
  `sqlitex.OpenImmediate` (two writers; `memory.db` precedent), its own embedded migration
  `internal/agentcfg/migrations/0001_secret_values.sql` (P447 DDL verbatim) through `sqlitex.Migrate`.
- `secrets.NewStore(db, cipher)` on it, new scope `ScopeAgentCredential Scope = "agent-credential"`
  (added to `valid()` and the frozen-string test), owner `"agent"` (one shared definition). No new
  `secrets.Store` method: `Put`, `Prune(… keep)` for delete, `Names`, `Open`.
- `configfs.SecretSourceFunc` over `Store.Open(ScopeAgentCredential, "agent")`: absent name wraps
  `configfs.ErrSecretMissing`; unreadable value is an error naming the reference; keychain unavailable
  passes through. Resolver namespace `"agent"` (fixed in code, never in the file).
- Resolver path `kirapaths.SharedAgentSecrets()` = `filepath.Join(Home("KIRA_SPACE_HOME", ".kira-space"),
  "agent-secrets.db")`; Space passes its own home explicitly (P452 rule).
- Write-only. No reveal (P447 answer kept). Delete is explicit only: removing a reference from the file
  never prunes, because a broken or half-saved edit would destroy values.
- Store unavailable (keychain or file): Set fails with `E_SECRET_STORE` (P447 code and key); a launch that
  references a secret fails with the resolver error naming it.

### 3.4 Env source

- `${NAME}` resolves from the user's login shell, then the process env (a Finder-launched app lacks the
  shell's variables; every agent launch already runs through the login shell).
- New `loginshell.ProbeEnv(ctx, names []string) (map[string]string, error)`: one `-l -i -c` run printing
  each name NUL-separated after a marker (kubernetes `probeShellEnv` pattern), 5 s timeout. `agentcfg`
  caches the result per process and probes again only for a name not yet probed. Probe failure: Warn
  once, process env only. Kubernetes keeps its own probe (not refactored here).
- Flow tests inject `Env` (process env) through `agentcfg.Options.Env`.

### 3.5 Schema and validation

- Common schema `internal/agentcfg/settings.schema.json` (2020-12, `additionalProperties: false`
  everywhere). Provider sections come from the providers: new optional role (3.7) `SettingsSchema()
  []byte`; `agentcfg.New` assembles `properties.<provider id>` for each registered `SettingsHost`, so a
  provider's section is validated by that provider's own schema, and an unregistered key is refused.
- Rules (`configfs.Rule`, each with its `AGENTS.md` doc):
  - `server-transport`: an MCP server has `command` or `url`, not both; `args`/`env` only with `command`,
    `headers` only with `url`.
  - `kira-names`: an MCP server name never starts with `kira` (Kira's own `kira-ade`, `kira-memory`); an
    env name never starts with `KIRA_` (Kira's launch variables).
  - `hook-matcher`: `matcher` only on `tool_start`/`tool_end`.
  - `skip-hooks`: every `<provider>.skip_hooks` entry names a common hook.
- Schema patterns: server names `^[a-z0-9][a-z0-9_-]{0,63}$`, hook names the same, env names
  `^[A-Za-z_][A-Za-z0-9_]*$`, `timeout` 1-600 s. Neutral hook `event` enum: `session_start session_end
  prompt tool_start tool_end notification turn_end` (maps to `harness.EventKind`).
- `Settings` (Go) implements `UnmarshalJSON`: known keys to fields, provider ids to `Sections
  map[string]json.RawMessage` (the schema already refused anything else).

### 3.6 Hooks

- Common `hooks` (name -> event, matcher, command, timeout) apply to every provider unless its section
  lists the name in `skip_hooks`. A provider section may add native hooks (`claude.hooks`, events from
  C3). Removing is editing the file; per provider override is `skip_hooks` plus native additions.
- Kira's hooks are added at launch by the listener, never read from or written to `settings.yaml`, never
  shown as user hooks, never skippable: `skip_hooks` names only common hooks, the schema has no key for
  Kira's. User hooks run after Kira's for the same event (Kira's entry first in each event array).
- OpenCode (step 9): common hooks are not mapped. The view lists each as "Not applied: OpenCode runs
  plugins, not hook commands. Add a plugin under `opencode.plugins`." Reason: OpenCode's plugin events
  and blocking semantics are unverified (U12) and differ from Claude's exit-code contract; a generated
  runner plugin would be a guess.
- Isolated runs (smart scripts, ADE smart steps, rebase runs) take nothing from agent settings (3.9),
  hooks included.

### 3.7 Harness seam (`internal/harness/settings.go`)

```go
// SettingsHost is a provider that takes the app's agent settings. Optional role.
type SettingsHost interface {
	// SettingsSchema is the JSON Schema (2020-12) of the provider's section in settings.yaml.
	SettingsSchema() []byte
	// RenderSettings renders s natively for one launch kind. It writes nothing.
	RenderSettings(s AgentSettings, kind LaunchKind) (NativeConfig, error)
}
type LaunchKind int // LaunchInteractive, LaunchHeadless
type AgentSettings struct {
	Env     map[string]string // values resolved (or verbatim references for the view)
	MCP     []MCPServer       // enabled servers, existing type
	Allow   []string          // Kira tool vocabulary
	Deny    []string
	Hooks   []Hook            // common, minus the provider's skip_hooks
	Section json.RawMessage   // the provider's own section, refs resolved the same way
}
type Hook struct {
	Name, Matcher, Command string
	Event                  EventKind
	TimeoutSec             int
}
type NativeConfig struct {
	Files []NativeFile
	Env   []string // KEY=value; may carry secrets
	Notes []string // settings not applied, for the view
}
// NativeFile is one provider document. Role is the provider's own key ("mcp", "settings"); Inline
// means the provider wants the bytes (env-carried), so Kira writes no file for it.
type NativeFile struct {
	Role, Name string
	Data       []byte
	Inline     bool
}
// AppConfig is NativeConfig after Kira wrote its files (0600). Env and Inline may carry secrets:
// never returned from a bound method, never logged.
type AppConfig struct {
	Files  map[string]string // role -> absolute path
	Inline map[string][]byte // role -> bytes
	Env    []string
}
```

- `InteractiveSpec.App *AppConfig`, `HeadlessSpec.App *AppConfig` (nil = none). Only the provider maps
  them.
- `Launch.ConfigFile string`: the Kira-written provider config file a hook listener extends in place; ""
  none.
- Optional listener role `harness.ConfigMerger{ ComposeInto(terminalID, cwd, command, configFile string)
  (string, []string, error) }`. `Hooks.Compose(provider, terminalID, cwd, command, configFile string)
  (string, []string, error)`: a merger listener with a non-empty `configFile` gets `ComposeInto`; else
  today's `Compose` (OpenCode's P449 listener unchanged).
- `KIRA_*` names and every env entry Kira itself adds come after `App.Env`, so Kira's value wins
  (exec keeps the last duplicate).

### 3.8 Claude mapping (`internal/harness/claude/settings.go`, `settings.schema.json`)

- Section schema: `model` (string, pattern `^[A-Za-z0-9._:/\[\]-]{1,100}$`), `permission_mode` (enum C5),
  `status_line` (`command` required, `padding` 0-10, `refresh_interval` 1-3600), `hooks` (name ->
  `event` from C3, `matcher`, `command`, `timeout`), `skip_hooks` (names). No `env` or `mcp_servers` here:
  defined once, common.
- `RenderSettings`:
  - `mcp` file (`Name: "mcp.json"`): `p.MCPConfig(s.MCP)` (existing renderer; map literals keep G5's
    `json:"headers"` rule satisfied). Omitted when no server.
  - `settings` file (`Name: "settings.json"`): `{"model", "permissions":{"allow","deny","defaultMode"},
    "hooks":{<Claude event>:[{"matcher"?, "hooks":[{"type":"command","command","timeout"}]}]},
    "statusLine"}` through `encoding/json` over Go structs (the `hooksDocument` types). Neutral event to
    Claude name: `EventKind` wire strings (already Claude's). Headless omits `defaultMode` and
    `statusLine` (an unattended run must not enter `plan` or ask; `claude -p` never runs a statusline).
    Omitted when empty.
  - `Env`: `s.Env` as `KEY=value`, sorted.
  - No secret can reach `settings.json`: no ref field renders into it (3.2).
- `InteractiveCommand`: `App.Files["mcp"]` joins `--mcp-config` after the grant (with no grant, as
  Continue in terminal has, `--mcp-config <app>` alone; `--allowedTools` still only with a grant).
  `App.Files["settings"]` -> `--settings '<path>'`, and `Launch.ConfigFile` = that path. `App.Env`
  appended to `Launch.Env`.
- `Script` (headless, non-isolated only): app mcp file appended to the `--mcp-config` words, `--settings
  '<path>'` after `--setting-sources`. `Script` with `Isolated` and `App != nil` is a programming error:
  `RunHeadless` refuses it. `App.Env` is in `spec.Env` already (the caller inserts it, 3.10).
- Hooks listener (`claude/hooks`): `Server.ComposeInto` reads the Kira-written file, prepends Kira's entry
  to every `hookEvents` event, and when `statusLine()` is on wraps the file's `statusLine` (its command
  becomes `KIRA_USER_STATUSLINE`, padding and refresh kept; the wrapper alone when none), writes it back
  0600 with `renameio`, returns the command unchanged plus the hook env. A read or write error fails the
  launch (Kira's hooks are always on, so never a silent drop).
- `userStatusLine` is deleted. Without an app settings file, `Compose` writes the wrapper with no user
  statusline (the per-terminal file stays as today). A user statusline now comes only from
  `claude.status_line` (P454 imports it). Project `.claude/settings*.json` statuslines are no longer
  chained: Kira's flag settings outrank them (C6), as before; listed in ARCHITECTURE.
- P444 `disableAllHooks`: isolated runs that tick a user CLI server still load the user settings source,
  so `userMCPSettings` keeps `disableAllHooks` until P455 drops that source. P453 supersedes it for every
  run that takes app settings: their hooks come from the app list, rendered in the same `--settings`
  document, and no app run sets `disableAllHooks`. Stated in ARCHITECTURE and Known open items.

### 3.9 Which launches get settings

- Interactive: every Space TUI (`prepareWithGrant`), Continue in terminal (both apps). Kind
  `LaunchInteractive`.
- Headless: non-isolated ADE agent steps and review rounds (`superviseAgent` with `spec.Isolated` false).
  Kind `LaunchHeadless`. A step's own `allowed_tools` and Kira's grant tools stay on `--allowedTools`; the
  app `deny` list joins through settings (deny wins).
- Not: isolated runs (smart scripts both apps, ADE smart steps, rebase runs). Their tool and MCP policy is
  explicit by design; ambient app config would break that. Structured calls (memory) as P452.
- `model` in a provider section applies where the launch names none (TUI always; headless steps have no
  model field).

### 3.10 Launch-time preparation (`internal/agentcfg/prepare.go`)

```go
type Launch struct {
	Provider harness.Provider
	Kind     harness.LaunchKind
	Dir      string // Kira's own 0700 run dir (ADE agent dir, automations-mcp)
	Stem     string // file name stem: the run id (headless), "tui-<uuid>" otherwise
}
type Prepared struct {
	App     *harness.AppConfig // nil when there is nothing to apply
	Secrets []string           // resolved secret values, for a Masker
	Release func()             // removes the files; idempotent
}
func (s *Store) Prepare(ctx context.Context, l Launch) (Prepared, error)
func (s *Store) Close() error              // removes every file not released yet
func (s *Store) Sweep(dirs ...string) error // at start: removes leftover *-app.*.json (a crash)
```

- Steps: last good `Settings` (`Folder.Get`), skip the provider's `skip_hooks`, drop disabled servers,
  resolve every ref field (`configfs.Resolver`: login-shell env, shared secret source), build
  `AgentSettings`, `RenderSettings`, write each non-inline file as `<Dir>/<Stem>-app.<role>.json`
  (`configfs.WriteAtomic`, 0600; dir 0700), register for `Close`. A provider that is not a
  `SettingsHost` gets `Prepared{}` plus a Warn once per provider when the file is non-empty.
- Any resolve or write error is returned; the caller fails the launch with it (message names the
  reference, never a value). Never a launch with a silently missing secret.
- Release paths:
  - TUI: `prepareWithGrant` combines `Prepared.Release` with the grant release passed to `bindTUI`, so
    stop, intent expiry, Abort and rebind remove both; a failed `Prepare` releases at once.
  - Headless: after `RunHeadless`, next to the grant `release()`.
  - Continue in terminal: `newAgentLaunch` stores the release with the token. `BeginAgent(token, command,
    terminalID)` binds it to the terminal; `Exited(terminalID, …)` runs it. Token expiry (`LaunchTTL`
    sweep) and `Service.Close` run unconsumed ones. `terminal/bound.go` calls `Scripts.Exited` for
    agent-token terminals too (today only script runs); `scriptruns.Exited` ignores unknown terminals
    after releasing.
  - Quit: `agentcfg.Store.Close` in both appwire shutdowns. Crash: `Sweep` at start over the ADE agent
    dir and `automations-mcp`.
- Secrets reach only: the bound `SetSecret` args, `Store.Put`, `Store.Open`, the resolver, the 0600 run
  files, the child env (`Launch.Env`, `spec.Env`, token env). Never `slog`, `op_log` (`SetCommand` holds
  paths only), the projection, tab state, contracts, bound reads.
