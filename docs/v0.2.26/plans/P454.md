## 3. Decisions

### 3.1 Scope

- Providers: `claude`, `opencode`. `fake` and any provider without a porter show no buttons.
- Files, user level only. Paths resolve with the login-shell env (`loginshell.ProbeEnv`, P453 cache) for
  `CLAUDE_CONFIG_DIR` and `XDG_CONFIG_HOME`, then the process env:

| Provider | Role | Path | Import | Export writer |
|---|---|---|---|---|
| claude | settings | `$CLAUDE_CONFIG_DIR/settings.json`, else `~/.claude/settings.json` | yes | Kira, merge |
| claude | context | `$CLAUDE_CONFIG_DIR/CLAUDE.md`, else `~/.claude/CLAUDE.md` | yes | Kira, whole file |
| claude | mcp | `$CLAUDE_CONFIG_DIR/.claude.json`, else `~/.claude.json`, key `mcpServers` only | yes | `claude mcp` CLI |
| opencode | config | `$XDG_CONFIG_HOME/opencode/opencode.json`, else `~/.config/opencode/opencode.json` (`.jsonc` per Q-P454-OC1) | yes | Kira, merge |
| opencode | context | same dir, `AGENTS.md` | yes | Kira, whole file |

- Never: project files, `.mcp.json`, `projects.*` in `~/.claude.json`, `~/.claude/.credentials.json`,
  OpenCode data dir and `auth.json`, managed settings.
- Dropped as redundant (row allows): state sync, live conflict tracking. Kept: per-item conflicts in the
  import preview, a content-hash staleness check at apply (§3.8).
- Export adds or replaces; it never deletes a user item absent from Kira's files.

### 3.2 Package layout and the G5 line

- New `internal/agentport` (repo root, Space-only caller): file I/O, provider porters (`claude.go`,
  `opencode.go`), classifier, YAML edit, backups, preview sessions, service. It is the one package that
  opens user-level agent config, only from an Import or Export call.
- Provider packages keep G5 unchanged: `internal/harness/claude` gets no `.claude.json` literal and no
  `json:"headers"` tag; `internal/harness/opencode` no `opencode.json` literal and no file read. They
  contribute pure helpers only:
  - `claude/mcpinstall`: `InstallJSON(ctx, name string, server json.RawMessage) harness.InstallResult`
    over the existing `register` (remove then add-json). Optional `harness.JSONInstaller` interface in
    `internal/harness/mcp.go`.
  - `opencode/port.go`: `PermissionDoc(allow, deny []string) (json.RawMessage, []string, error)` (over
    `translateRules`; untranslatable entries return as notes), `KiraPermissions(raw json.RawMessage)
    (allow, deny []string, skipped []string)` (inverse, §3.5), `EnvRef(name) string`, `ParseEnvRefs`.
    The `{env:NAME}` syntax and file-name facts go in `facts.go` with probe ids (P449 isolation rule).
- G5 grows an `internal/agentport` scope: fails on the literals `.credentials.json`, `auth.json`,
  `.local/share/opencode`, `OPENCODE_AUTH_CONTENT`, `apiKeyHelper` used as a command, an `auth` or
  `providers` argv, `claude mcp get` argv, `Header.Set`/`Header.Add`. ARCHITECTURE "CLI credentials"

- Why not porters inside provider packages: G5 forbids exactly these reads there, by design; one
  exception package is easier to audit than exemptions in two.

### 3.3 Neutral item model (`internal/agentport/item.go`)

```go
type Item struct {
	ID       string   // "mcp/gh", "env/JIRA_TOKEN", "allow/Bash(git status)", "deny/…", "hook/<name>",
	                  // "claude/model", "claude/permission_mode", "claude/status_line", "claude.hook/<name>",
	                  // "opencode/model", "opencode/plugin/<url>", "context"
	Kind     string   // context|env|mcp|allow|deny|hook|native_hook|model|permission_mode|status_line|plugin
	Source   string   // display path, "~/.claude.json"
	State    string   // new|same|conflict|skipped
	Reason   string   // i18n text for skipped and conflict
	Modes    []string // context conflict only: "replace", "append"
	Text     string   // YAML snippet as it will be written: secrets as ${secret:name}
	Current  string   // conflict only: the current snippet
	Secrets  []SecretSlot
	value    any      // decoded value with literals, server side only
}
type SecretSlot struct {
	Name  string `json:"name"`  // generated secret name
	Field string `json:"field"` // "mcp_servers.gh.headers.Authorization"
	Reuse bool   `json:"reuse"` // an equal value is already saved under Name
}
```

- Selection default: `new` selected; `conflict` unselected (selecting means replace, or the chosen
  mode); `same` and `skipped` not selectable.
- Conflict rules: `mcp/*`, `env/*`, scalar items differ from the current value; `allow`/`deny` union
  (present means `same`); hooks dedupe by event, matcher and command (an equal hook under any name is
  `same`; names generated unique, `<event>-<n>`); plugins union; context differs from a non-empty
  `context.md`.

### 3.4 Credentials: classifier and secrets (`classify.go`)

- A string in a ref field (`env` values, MCP `url`, `headers.*`, `command`, `args[]`, `env.*`) is a
  credential when any rule holds:
  - MCP header, unless its name is in a safe list (`Accept`, `Content-Type`, `User-Agent`, `MCP-Protocol-Version`);
  - env name (settings or MCP env), case-insensitive, contains one of `token`, `secret`, `passw`,
    `pwd`, `apikey`, `api_key`, `auth`, `credential`, `bearer`, `private`, `cookie`, or ends in `_pat`
    or `_key` (one table in code);
  - value pattern: known prefixes (`sk-`, `ghp_`, `gho_`, `github_pat_`, `glpat-`, `xox[abp]-`, `AKIA`,
    `AIza`, JWT `eyJ…\.…\.…`), or 32+ chars of base64url/hex with mixed classes;
  - an arg after a flag whose name matches the env rule (`--api-key X`), or `--flag=value` likewise;
  - a URL with userinfo or a query parameter matching the env rule.
- Scheme prefixes stay literal: `Bearer `, `Basic `, `token ` before the secret part
  (`Authorization: "Bearer ${secret:gh-authorization}"`).
- A flagged value always becomes a secret: no "keep as text" toggle (row: credentials rule kept). An
  unflagged literal stays text; the user can move it later (Agents > Settings).
- Secret names: `<server>-<field>` or `env-<name>`, lowercased, non-`[a-z0-9_.-]` to `-`, cut to 64.
  An existing saved name with an equal value (compared server side through `SecretStore.Store.Open`) is
  reused (`Reuse`); a different value takes `-2`, `-3`.
- Values already a reference in the source keep their meaning: Claude `${VAR}` is Kira `${VAR}`;
  OpenCode `{env:VAR}` becomes `${VAR}`; `${KIRA_SECRET_<X>}` / `{env:KIRA_SECRET_<X>}` maps back to
  `${secret:<x>}` when a saved secret derives that env name (round trip, §3.6). Forms Kira cannot
  express (`${VAR:-default}`, `{file:…}`) skip the item with a reason. A literal `${` in an OpenCode
  value is written as `$${`.
- Classifier library: none adopted. gitleaks (MIT) is a text-scanning rule engine with a large
  dependency tree (viper, etc.); the requirement here is field-location plus name rules over a few
  dozen known fields, which it does not model.
- Unit test `classify_test.go`: one table (several interacting rules: location, name, value, flag
  adjacency, scheme split). The only unit test of the phase.

### 3.6 Export mapping

- Source: the effective settings (`Store.Settings()`) and context. A settings or context file with a
  problem blocks export ("Fix settings.yaml first"), as it blocks import.
- References: `${NAME}` stays `${NAME}` for Claude (C-P4), becomes `{env:NAME}` for OpenCode.
  `${secret:x}` becomes env name `KIRA_SECRET_<X>` (`x` upper-cased, non-alnum to `_`); two secrets
  deriving one name fail the export naming both. `$${` in a value: the item is skipped (no escape in
  either CLI). The preview lists every env name the user must set in their shell (names only).
- A literal the classifier flags in Kira's own file blocks that item: "Move this value to a secret
  first" (never plaintext out).
- Claude `settings.json`: merge into the existing document with `hujson` (comments, order, unmanaged keys
  kept byte for byte). Managed keys: `model`, `permissions.defaultMode` (scalars, replaced),
  `permissions.allow`/`deny` (union, appended), `hooks.<Event>` (entries appended unless an equal
  matcher plus command exists), `statusLine` (replaced), `env` (keys set; only literal values: a
  reference is skipped with "settings.json env has no expansion: set NAME in your shell"). Hooks come from
  `RenderSettings(LaunchInteractive)` (common minus `claude.skip_hooks`, plus `claude.hooks`). Kira's own
  hooks and status line wrapper are never in `settings.yaml`, so never exported.
- Claude MCP: each enabled server through `JSONInstaller.InstallJSON` (stdio gets `"type":"stdio"`).
  Preview per server: `add` or `replace` (name in `claude mcp list` user output, already parsed by
  `UserMCPServers`, run with cwd = the agent folder so no project scope shows). No text diff: Kira never
  holds this file's text in the UI. Claude CLI not found: the servers part is blocked with the install
  hint, files still export. The CLI gets `CLAUDE_CONFIG_DIR` when resolved, so it writes the file Kira
  backed up.
- OpenCode `opencode.json`: `hujson` merge: `model` replaced, `mcp.<name>` replaced per name,
  `permission` from `PermissionDoc` merged per key (Kira's patterns appended after existing ones, deny
  after allow), `plugin` union. Common hooks: not exported (note, as P453). Env: not exported (OpenCode has
  no config env; note lists the names to set in the shell). If Q-P454-OC7 shows the global `AGENTS.md` is
  not loaded, export also adds its absolute path to `instructions` (union) — orchestrator's call.
- Context: `CLAUDE.md` / `AGENTS.md` replaced whole by `context.md`; empty or absent `context.md` skips
  the file (never blanks the user's file).
- Per-file selection (checkbox per target, default all changed files); no per-item selection on export.

### 3.7 Writes and backups

- Before writing a file that exists and changes: copy it to `<file>.kira-backup-<UTC
  20061102T150405Z>` beside the original, mode kept (at least 0600 for JSON). Before the first Claude CLI
  call: the same for the resolved `.claude.json`. Backups are never pruned (Q4). Listed in the result.
- A symlinked target (dotfile managers) is resolved with `filepath.EvalSymlinks`; the link target is
  written, the link kept.
- Write with `configfs.WriteAtomic` (renameio), mode kept, parent dirs 0700 when created.
- Order per apply: hash check every selected file (§3.8), backups, file writes, then CLI servers one by
  one. First failure stops; the result lists done, not done, and backups. No automatic rollback: the
  backups are the undo.

### 3.8 Preview sessions and staleness

- Preview returns a `token` (128-bit random). The server keeps the decoded items with literal values
  (import) or the computed output bytes and current hashes (export), 10 min TTL, single use, dropped on
  Cancel, apply and `Service.Close`. Literal values never cross the bridge; the UI sees `••••` and slot
  names.
- Import apply: secrets `Put` first (orphans are harmless, "Not referenced"), then `settings.yaml` through
  YAML node edit (§3.9) and `Store.Save(text, baseHash)`; context through `agentctx.Store.Save`. A
  changed `settings.yaml`/`context.md` since preview is `ErrConflict`: "Preview again".
- Export apply: re-hash every selected target; a change since preview is a conflict; write the bytes
  computed at preview.

### 3.9 Writing settings.yaml

- Absent file: marshal a fresh document (`yaml.v3`, indent 2), keys in schema order.
- Existing file: edit the `yaml.Node` tree (`go.yaml.in/yaml/v3`, already used by configfs): set or
  replace `mcp_servers.<n>`, `env.<K>`, section scalars; append to `permissions.*`, `hooks`,
  `<provider>.hooks`, `opencode.plugins`. Untouched nodes keep comments; the encoder normalizes indent.
- New `agentcfg.Store.Check(text []byte) *configfs.Problem` (decode without saving): the edited text must
  pass before `Save`; a failure is an internal error (a porter bug), nothing written.
