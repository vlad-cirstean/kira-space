## Spec corrections

- Continue in terminal and Take over always continue a stored conversation, so they keep the stored
  provider (row rule "No cross-provider resume" wins over the row's list). The step override reaches
  only launches that start a new conversation: manual step session, ADE Start (`StartBranch`), a new
  review agent (also the reset-conversation path), headless agent steps and new review rounds.
- Studio has no Agent pane and no ADE. Studio gets the provider registered (Runs smart scripts follow
  its `agent.provider`), no picker. P453 shares agent settings between apps.
- Rebase runs have no step: they use the default provider.
- P448 user Q2 (headless late id) lands here: OpenCode needs it.
- P448 user Q4 (step `allowed_tools`, rebase built-ins): kept in Kira's vocabulary (Claude names);
  OpenCode translates them through `toolTable`; an entry with no translation fails the run with its
  name (fail closed).

## Design

### Provider `internal/harness/opencode`

Files: `opencode.go` (ID `opencode`, Label `OpenCode`, ProductLabel `OpenCode`, Command `opencode`,
HeadlessLabel `opencode run`), `facts.go` (every UNVERIFIED constant/table, nothing else),
`locate.go`, `interactive.go`, `session.go`, `mcp.go`, `usermcp.go`, `install.go`, `sandbox.go`,
`headless.go`, `stream.go`, `tools.go`, `env.go`, `hooks/` (step 4), `parse_test.go`.

- Roles: `Locator`, `Interactive`, `Sandboxed`, `MCPHost`, `SessionLocator`, `Headless`, `HookHost`,
  `harness.CostCapper` (new, below). No `Structured` (no JSON-schema call: memory falls back to
  claude, P448). No `UsageReporter`. No stage settings.
- Models: `Catalog{Aliases: ["default"], Default: "default"}`; `default` omits `-m`, so the user's
  own OpenCode model applies. `ModelLabel("default")` = "OpenCode default model". Reason: ids are
  `provider/model` and depend on the user's logins; `opencode models` is user-specific and the catalog
  is static (validation runs without a CLI). P453 adds a per-provider model setting.
- Locate (step 1 hoist): `harness.ResolveCLI(ctx, CLISpec{Name, Candidates, Product}, deps)` in new
  `internal/harness/locate.go`, the body of today's `claude.Resolve`/`Require`/`Missing` with the name
  as a parameter. Claude calls it (`claude.Resolve` stays as a thin wrapper, same probe order, same
  error text). OpenCode passes `candidates` (U15) and a `SetSystemPaths` seam like claude's.
- Interactive: `opencode` + ` -s '<id>'` on resume (V1) + ` -m '<model>'` never (TUI uses user
  default). `Launch.Env = ["OPENCODE_CONFIG=<s.MCPConfig>"]` when set (V5: the file holds
  `MCPHost.MCPConfig`'s OpenCode-shaped document). AddDirs, and AllowedTools only when
  `interactiveNeedsPermission` is true (U9), go in `OPENCODE_PERMISSION=<json>` (U19):
  `{"external_directory":{"<dir>/**":"allow"}}` (U18) plus `allow` entries. `OPENCODE_CONFIG_CONTENT`
  stays free for hooks. `Launch.SessionID`: `""` new, `s.SessionID` resume.
  `WithPrompt`: `command + " --prompt " + Quote(prompt)` (V1).
- SessionLocator: run `opencode session list --format json -n 20` with `cmd.Dir = q.Cwd`,
  `ScrubEnv`ed env, 10 s timeout; `parseSessionList` (U2) keeps items whose directory equals `q.Cwd`
  (after `filepath.Clean`) and created >= `q.Since`, returns the newest valid id. Unparsable output:
  `("", nil)` plus one `slog.Warn` with the byte length only.
- MCPHost: `MCPConfig` renders `{"mcp":{name:{type:"remote",url,headers,enabled:true}|{type:"local",
  command:[cmd,args...],environment:env,enabled:true}}}` (V6, U6). `MCPToolName` U7. `ToolArgs` maps
  a `ToolPolicy` through `tools.go` into the same Kira-vocabulary shape claude returns (tools, allowed),
  so callers stay neutral; the translation to OpenCode permission happens in `RunHeadless`.
  `UserMCPServers`: `opencode mcp list` through the CLI, `parseMCPList` (U10) keeps name, transport,
  target host or command base name, status; unknown output -> `errMCPList`. Never opens a config file.
  `MCPInstaller`: `Status` locates the CLI; `Install`/`InstallStdio` return `OutcomeInstallFailed` with
  Detail i18n `backend.core.agent.opencode.manualInstall.body` while `mcpAddArgv` is nil (U11);
  `Command`/`StdioCommand` return the JSON snippet for the user's `mcp` block (copy text, never written).
- Sandboxed: `ConfigDirs` = the four V4 home dirs (config first); `ProtectFiles` `opencode.json`,
  `opencode.jsonc`, `AGENTS.md`; `ProtectDirs` `plugin`, `plugins`, `agent`, `command`, `mode`;
  `InstallPrefix` from the resolved bin after `filepath.EvalSymlinks` (npm launcher), two levels up when
  the parent is `bin`; `QuietEnv` U14. `SandboxDenies` returns Kira vocabulary (same entries as claude's;
  shared helper not allowed across provider packages, so a 15-line copy in `sandbox.go` with a comment
  naming the claude twin). `APIHosts`: exact hosts of `OPENCODE_*BASE_URL`-style vars are unknown, so
  suffixes only (U16).
- G5: extend `internal/conventiontest` to `internal/harness/opencode`: forbid `auth.json`,
  `opencode.json` and `.local/share/opencode` literals, `OPENCODE_AUTH_CONTENT`, argv `"auth"` and
  `"providers"`, `Header.Set`/`Header.Add`, `RoundTrip` methods, `os.ReadFile`/`os.Open` of any path
  under the config or data dir. Exempt `sandbox.go` (names dirs, never opens). Kira's own generated
  config files are named `kira-agent-config.json` (no `opencode.json` substring).

### Headless (`run --format json`)

- Argv via login shell like claude's `Script`: optional sandbox wrapper, then `opencode run --format json`,
  `-s '<resume>'` when resuming, `-m '<model>'` unless `default`/empty, `--dir '<Dir>'`. Prompt on stdin
  when `promptOnStdin` (U4), else `-- '<prompt>'`.
- Env: `OPENCODE_CONFIG=<MCPConfigs[0]>`; extra `MCPConfigs` merged into one per-run 0600 temp config
  under the run's scratch dir (removed on return). `OPENCODE_CONFIG_CONTENT` = `permissionDoc(spec)`:
  `tools` off for built-ins outside `spec.Tools` (when non-nil), `allow` for `AllowedTools`, `deny` for
  `DisallowedTools` (deny wins), every other built-in `deny` when `Isolated` so nothing can prompt.
  `Bash(<pattern>)`/`Bash(<p>:*)` -> `bash` pattern map. `Edit(/dir/**)` -> `edit` pattern map only if
  U8 holds for patterns, else error. Untranslatable entry -> `RunHeadless` returns a
  `*harness.Error{Kind: ErrUnsupported}` naming it before start. Never `--auto`.
- `Isolated`/`Config`: `ConfigNone` or `Isolated` without `UserMCP` -> `XDG_CONFIG_HOME` points at a
  per-run dir holding a symlink to every entry of the real config home except `opencode` (git and other
  tools keep their config; V5). `Isolated` with `UserMCP`: no redirect; the content document adds
  `mcp.<n>.enabled=false` for every user server (from `UserMCPServers`) not in `UserMCP`/`GrantMCP`.
  `ConfigUser`/`ConfigAll`: no redirect. P455 reuses the redirect helper.
- Stream: `parseEvent` (U3) per stdout line. Text -> `StreamStdout` line; tool start -> `StreamEvent`
  line `tool: <name>`; error -> `StreamStderr`; unknown JSON -> skipped; non-JSON -> stdout line as is.
  `OnResult` once: from an error event (`EndError`) or at exit (`EndDone` on code 0, else `EndError`),
  cost when seen. Text bounded like claude's.
- Late headless id: new `harness.Handler.OnSessionID func(id string)`. OpenCode calls it on the first
  valid event id, else after exit via `FindSession{Dir, start}`. Claude never calls it.
  `HeadlessSpec.SessionID` doc: "proposed id; a SessionLocator provider reports its own through
  `OnSessionID`". Callers: `ade.superviseAgent` -> `Sessions.SetAgentSessionID(sessionID, id)`;
  `scriptruns` smart run -> runs repo `SetSessionID(runID, id)` (add if missing). Headless rows of a
  `SessionLocator` provider insert `AgentSessionID: ""`; `model.AdeSession.Validate` allows `""` for
  headless too. Every resume source built from a stored headless id (`runs.go` retry 1237, restart 1303,
  `reviewstep.go` 513/516/861, `ResumeCommand`) refuses an empty id with the existing
  `backend.space.ade.sessionIdUnknown.body` (Space) / new `backend.core.scriptRun.sessionIdUnknown.body`
  (scriptruns); a retry with `""` never silently starts a fresh conversation.
- `ResumeLost`: prefixes U5. `ScrubEnv`: U13.
- Cost: new optional `harness.CostCapper{ CapsCost() bool }`, `harness.CapsCost(p)` true unless p says
  false. `scriptruns.plan`: `MaxBudgetUSD > 0` on a provider that cannot cap -> `Preview.Blocker`
  (`backend.core.agent.noCostCap.body`). Same plan: a set `smart.Model` not in `agent.Models()` ->
  blocker (`backend.core.agent.modelUnknown.body`); the registry union now holds `default`, so a Claude
  script with `default` must not reach `claude --model default`. `RunHeadless` refuses either case too
  (defence in depth, `ErrUnsupported`).

### Hooks (HookHost through a Kira plugin)

- `internal/harness/opencode/hooks`: `Server` on `internal/localsock` (0700 dir, 0600 socket, 32-byte
  token), its own `POST /hook` handler (bounded body, bearer token, same limits as claude's), writes
  `plugin.js` (embedded, `//go:embed`) into the dir. `Compose(terminalID, cwd, command)` returns
  command unchanged and env `KIRA_TERMINAL_ID`, `KIRA_AGENT_HOOK_SOCKET`, `KIRA_AGENT_HOOK_TOKEN`,
  `OPENCODE_CONFIG_CONTENT={"plugin":["file://<dir>/plugin.js"]}`. On interactive launches
  `OPENCODE_CONFIG_CONTENT` belongs to hooks alone; the launch's own config rides `OPENCODE_CONFIG`
  and `OPENCODE_PERMISSION` (see Interactive), so they never collide.
- `plugin.js` (U12): every handler wrapped in try/catch, never throws, never blocks the agent (fire and
  forget `fetch("http://kira/hook", {unix, method:"POST", headers:{authorization}, body})`, 2 s abort).
  Posts `{type, sessionID, tool, message}` only. No-op when the env vars are missing.
- Go maps `type` through `hookEvents` (facts.go) to `harness.EventKind`: `session.created` ->
  `EventSessionStart` (fills the late id through the existing `Tracker.HandleEvent` rule),
  `session.idle` -> `EventTurnEnd`, `session.deleted` -> `EventSessionEnd`, `tool.execute.before` ->
  `EventToolStart`, `tool.execute.after` -> `EventToolEnd`, `permission.updated` -> `EventNotification`
  with `NeedsInput`, user `message.updated` -> `EventPrompt`. Unknown types dropped (200). `Wakes`
  never set.
- Never `--pure` on Kira launches (V1: it drops plugins).
