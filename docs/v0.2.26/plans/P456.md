## 1. Rules every step follows

- Site pages (`site/src/content/docs/**`) pass `bun site/scripts/check-docs.ts` (rules in
  `site/scripts/docsRules.ts`). Pre-commit runs it for any staged `.md`/`.mdx`; root `lint` and
  `site:build` run it too. Rules:
  - D1: max 25 words per sentence (off inside `:::caution`/`:::danger` asides; headings exempt).
  - D2 filler, case-insensitive whole words: just, really, basically, actually, simply, very, quite,
    rather, somewhat, fairly, pretty much, easily, obviously, clearly, of course, certainly, sure (except
    "make sure"), happy to, feel free, please, note that, in order to, it is worth, keep in mind, as you can
    see, a lot of, lots of, various.
  - D3 invented abbreviations: cfg, conf, impl, req(s), res, resp, fn, func, msg(s), ctx, tmp, btn, approx,
    w/, w/o, b/c.
  - D4 no arrows in prose (`->`, `=>`, `<-`, `→`); inside inline code is fine.
  - D5 no emoji. D8 no TODO/TBD/FIXME/XXX.
  - D6 a table needs at least 3 columns and 3 body rows, no empty cell (header row included), else a list.
  - D7 terms: `repository` not repo, `folder` not dir/directory, `Settings` not preferences, `cancelled`,
    no `e.g.`/`i.e.`/`etc.`, `GitHub`, `macOS`, `PostgreSQL`, `colour` not color.
  - D9 frontmatter: `title`, one-sentence `description` (prose rules apply), non-empty `sources:` of
    repo-relative paths (globs allowed) that exist.
  - Inline code is one opaque word: put paths, keys, env names, flags in backticks.
- Site claims come from code and `packages/theme/src/i18n/en.json`, never README wording
  (ARCHITECTURE "Presentation site"). A bold UI label is the exact catalog string with placeholders
  filled (`{agent}` is the provider label: `Claude Code` or `OpenCode`; `Label()` is `Claude`/`OpenCode`,
  `ProductLabel()` is `Claude Code`/`OpenCode`). Keys are given below per label.
- i18n/catalog: this phase adds, edits or removes no catalog key. A UI string that reads wrong goes to
  section 10 for P457, not into `en.json` (the catalog rules C1 to C10 and `--unused` run in `lint:rules`).
- `README.md` (root) is normal prose, outward-facing. Every other markdown file here (`apps/kira-space/
  README.md`, ARCHITECTURE, DEV_ENVIRONMENT, this plan) follows the CLAUDE.md terse style. Do not restyle

## 2. Facts sheet (verified in source at `cbabafaf5`)

Providers and picker:
- Two providers: `claude` (`Claude Code`, headless `claude -p`) and `opencode` (`OpenCode`, headless
  `opencode run`), `internal/harness/providers/providers.go`. CLI found on PATH, then the login shell, then
  candidate paths (`harness.ResolveCLI`).
- OpenCode roles: no Structured (memory calls use Claude Code), no UsageReporter (no usage item), no cost
  cap (`capsCost = false`, `opencode/facts.go`). Hooks through a Kira plugin; no wake events.
- Smart scripts never run on OpenCode: every smart script has a budget of 0.05 to 25 USD
  (`internal/scripts/smart.go` `MinBudgetUSD`, `MaxBudgetUSD`; 0 becomes the default 1.0), and
  `agentBlocker` (`internal/scriptruns/preview.go:246`) refuses any budget on a provider without a cost cap
  (`backend.core.agent.noCostCap.body` "{agent} can’t cap a run’s cost. Remove the budget from the script.").
  Applies to smart scripts and ADE smart steps. Plain agent steps run.
- Settings section label is the active provider's `ProductLabel()` (`SettingsDialog.vue` `Agent:
  agentInfo.value.productLabel`): the nav shows `Claude Code` or `OpenCode`. Field label "Agent"
  (`memory.common.origin.agent.label`), select `settings-agent-provider`; a missing CLI shows
  "{agent} (not found)" (`space.settings.agent.provider.notFound.label`), disabled; description
  `space.settings.agent.provider.description` "Runs new sessions and background steps. Sessions already
  started keep their agent."
- Usage switch shows only for a provider with usage (Claude Code). Finished/needs-input switches show
  for a provider with hooks (both).
- Launch menu on a task: button tooltip "New terminal or agent session"
  (`space.ade.taskLaunch.trigger.tooltip`). With two or more installed providers it lists one entry per
  provider, "{agent} session" (`space.ade.taskLaunch.agent.label`, `AdeTaskLaunchMenu.vue`). One provider:
  the menu stays as before.
- Workflow step key `agent` (agent steps, review steps, manual steps with `session: true`): a provider id;
  empty uses the setting. Step editor Advanced section: select "Agent", first option "Default provider"
  (`space.ade.workflows.stepInspector.agentDefault.label`, `AdeStepAdvanced.vue`).
- Order for a new conversation: the launch menu pick, then the step `agent`, then the setting. Resume,
  Take over, Restart and Continue in terminal keep the stored provider. No cross-provider resume. A gone
  provider: "The agent that ran this conversation is no longer available." (`backend.core.agent.providerGone.body`).
- Studio has no picker and no Agent section; it runs the provider in its own `agent.provider` (default
  `claude`).
- OpenCode interactive gets no `-m`; `opencode.model` in `settings.yaml` reaches it inside
  `OPENCODE_CONFIG_CONTENT`. Session id is learned after launch (`opencode session list --format json`).
  Before it is known, resume refuses: "The agent hasn’t reported its session ID yet. Retry once it has
  started." (`backend.space.ade.sessionIdUnknown.body`).
- OpenCode MCP install for Kira's own servers is a copy snippet: "OpenCode can’t add MCP servers from here.
  Copy the snippet into the mcp block of your OpenCode config." (`backend.core.agent.opencode.manualInstall.body`).

Context (`internal/agentctx`, ARCHITECTURE "Agent context (P452)"):
- File `~/.kira-space/agent/context.md` (`kirapaths.SharedAgentDir()`, honours `KIRA_SPACE_HOME`), Markdown,
  cap 32 KiB. Blank or missing: no context. Invalid (over cap, bad UTF-8): agents get the last good text.
- Agents > Context tab (`space.ade.context.tab.label` "Context"): textarea, Save, Discard, Refresh, file
  bar. Hints: `space.ade.context.applies.hint`, `space.ade.context.resume.hint` "A resumed {label}
  conversation keeps the context it started with until it compacts." (Claude only: `ContextKeeper`).
- Every launch gets it: interactive, Take over, resume, headless steps, smart scripts (both apps), Continue
  in terminal. Not memory calls. Claude: `--append-system-prompt-file`; OpenCode: `instructions`.
- A running agent never sees an edit (immutable snapshot). OpenCode re-reads on resume.

Settings (`internal/agentcfg`, schemas `internal/agentcfg/settings.schema.json`,
`internal/harness/{claude,opencode}/settings.schema.json`):
- File `~/.kira-space/agent/settings.yaml`, cap 256 KiB. Unknown keys refused with a line.
- Common keys: `env`; `permissions.allow`, `permissions.deny` (Kira tool vocabulary = Claude tool names; deny
  beats allow); `mcp_servers.<name>` stdio `command`, `args`, `env` or http `url`, `headers`, plus `enabled`
  (default true); `hooks.<name>` `event` (`session_start`, `session_end`, `prompt`, `tool_start`, `tool_end`,
  `notification`, `turn_end`), `matcher` (tool events only), `command`, `timeout` (1 to 600 s, default 60).
- `claude`: `model`, `permission_mode` (`acceptEdits`, `auto`, `bypassPermissions`, `manual`, `dontAsk`,
  `plan`; terminal sessions only), `status_line` (`command`, `padding`, `refresh_interval`), `hooks` (Claude
  event names), `skip_hooks`.
- `opencode`: `model` (`provider/model`), `plugins` (`file:///abs` URLs), `skip_hooks`. OpenCode applies no
  common hook: view note "OpenCode doesn’t run hook {hook}. It is not applied."
- Rules: a server has a command or a url, never both; names starting `kira` and env starting `KIRA_` are
  reserved.
- References: `${NAME}` (login-shell env, then process env), `${secret:name}`, `$${` literal. Only `env`
  values and MCP `command`, `args`, `url`, `headers`, `env`. Hook and status line commands take none: put
  the secret in `env` and read `$NAME`. Missing var or secret fails the launch naming it. OpenCode refuses a
  value holding `{env:` or `{file:` (`backend.core.agentSettings.opencode.refSyntax.body`).
- Secrets: section "Secrets" (`space.ade.settings.secrets.title`), "Set value", write-only ("The value is
  sent once and never shown again."). Hint "Write {ref} in the file. Values stay sealed on this computer."
  Stored sealed in `~/.kira-space/agent-secrets.db`, shared by both apps. Delete warns: "Settings that
  reference this secret fail to launch until you set it again." Name rule
  `backend.core.agentSettings.secretName.body`.
- Result panel ("Result", `space.ade.settings.result.title`) per provider: exact native config, references
  verbatim, notes, "Kira adds at launch". OpenCode note: "OpenCode receives this through
  OPENCODE_CONFIG_CONTENT. No file is written."
- Which launches: every Space terminal session, Continue in terminal (both apps), headless agent steps and
  review rounds. Smart scripts, smart steps and rebase runs take no settings, but with hermetic on their MCP
  tick list comes from `mcp_servers` here.
- Resolved values: 0600 per-run files or env, removed at exit. Headless step output masks them; a live
  terminal does not.

Import and Export (`internal/agentport`):
- Links under each provider in Agents > Settings: "Import from {agent}", "Export to {agent}"
  (`space.ade.port.importButton.label`, `.exportButton.label`).
- User-level files only. Claude: `~/.claude/settings.json`, `~/.claude/CLAUDE.md`, `mcpServers` of
  `~/.claude.json`. OpenCode: `opencode.json`, `opencode.jsonc` or `config.json` (jsonc wins over json) and
  `AGENTS.md` under `$XDG_CONFIG_HOME/opencode`, else `~/.config/opencode`. Over 4 MB not read.
- Import preview: states "To add", "Same", "Differs" (conflict, unchecked by default), skipped keys by name.
  Context mode "Replace" or "Append". A literal credential becomes `${secret:<server>-<field>}` and a
  sealed secret at apply. Login keys never listed (`apiKeyHelper` and others). Dialog hint
  `space.ade.port.importDialog.hint`.
- Export: merges by key, keeps other keys and JSONC comments; diff with masked credentials; confirm; backup
  `<file>.kira-backup-<UTC 20060102T150405Z>` beside each changed file. Refs: Claude `${KIRA_SECRET_<X>}`,
  OpenCode `{env:NAME}`; "Environment variables" list with "Copy export lines" (no values). Claude MCP
  servers go through `claude mcp remove` and `claude mcp add-json -s user`. Hooks export to Claude only.
  A preview lives 10 min, single use; a file changed since the preview aborts with nothing written.

Hermetic (`agent.hermetic`, `internal/appsettings/agent.go`, ARCHITECTURE "Hermetic launches (P455)"):
- Default on. Space switch "Hermetic agent launches" (`space.settings.agent.hermetic.label`, description
  `space.settings.agent.hermetic.description`) in the agent's Settings section. Studio: no switch, on.
- Every launch: interactive, Take over, resume, workflow steps, headless, smart scripts.
- Claude: `--setting-sources project,local`, `ENABLE_CLAUDEAI_MCP_SERVERS=false`,
  `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`, `claudeMdExcludes` for `~/.claude/CLAUDE.md`. Drops user settings,
  hooks, permissions, MCP servers, skills, commands, agents, plugins, `CLAUDE.md`, claude.ai connectors,
  auto memory. Keeps project `CLAUDE.md`, `.claude/`, `.mcp.json`, local-scope servers, login.
- OpenCode: `XDG_CONFIG_HOME` to a per-launch folder linking every `~/.config` entry except `opencode`, plus
  `OPENCODE_DISABLE_CLAUDE_CODE_PROMPT=1`. Drops user `opencode.json`, global `AGENTS.md`,
  `~/.claude/CLAUDE.md`. Keeps project `opencode.json`, project `AGENTS.md`, login (data folder). Also drops
  project `CLAUDE.md`. Still loads `~/.opencode` and user skills in `~/.claude/skills`, `~/.agents/skills`.
- Smart scripts: hermetic MCP list is Kira's own (`automations.smart.mcpHintApp.hint` "Servers from Kira’s
  own agent settings, not your CLI config."); a ticked name missing from `settings.yaml` blocks the run.
  Off: the CLI's list (`automations.smart.mcpHint.hint`) and user settings load, hooks off.
- Cannot isolate: managed settings and policy; shell profile exports; sign-in kept in user config (use
  the same env in `settings.yaml` or turn hermetic off).

Config files (`internal/configfs`):
- Folders `~/.kira-space/workflows/` and `~/.kira-space/agent/`. Each gets a generated `AGENTS.md`
  (rewritten at Space start; an edit is overwritten) that lists every option for an AI agent.
- File bar on Workflows, Context and Settings pages: path, status ("Line N: message"), Open, Reveal, Copy
  path, "About these files" (`common.config.about.label`) opens that folder's `AGENTS.md`.
- Edit in any editor; the app watches; a broken edit keeps the last good version. Files never hold a secret.

Runs secret params (`internal/scripts`, `internal/scriptruns`, `internal/secrets`):
- A secret param can keep a saved value: field placeholder "Saved, type to replace"
  (`automations.params.secretValue.saved.placeholder`), status "Value saved". Write-only.
- Run dialog: "Saved, type to use another value" (`automations.run.secretSaved.placeholder`). A typed
  value wins. Still env only (`KIRA_PARAM_<NAME>`), never in the prompt
  ("A secret can’t be used in the prompt.").
- Stored log, run outcome and terminal tail show the mask; the live terminal tab and the phone ring do not.
- Resume uses the saved value. "Run without asking" needs a saved value for each required secret param;
  else the hint "Needs your answer each time. A required secret parameter has no saved value."
  (`automations.schedule.askLocked.hint`). Schedule params never hold a secret.
- Delete of a script, collection or param (or rename, or un-secret) deletes the value. Duplicate and export
  never copy it.
- Keychain unavailable: "The keychain is unavailable, so a secret can’t be saved. Each run asks for it."
  (`automations.params.secretValue.storageOff.description`). Saved value unreadable at run:
  `backend.core.scriptRun.savedSecretUnreadable.body`.
- Both apps seal with one keychain-held key (shared `internal/secrets`).
