## 2. Claude CLI facts (2.1.316, `claude --help` plus binary inspection, no model call)

- C1 `--append-system-prompt <prompt>`: listed. Appends to the default system prompt.
- C2 `--append-system-prompt-file <file>`: present, hidden (commander `.hideHelp()`), help string "Read
  system prompt from a file and append to the default system prompt". `--bare` help names it
  (`--append-system-prompt[-file]`). Read in the main command action next to `--system-prompt-file`: a
  missing file exits with "Error: Append system prompt file not found: <path>"; with both C1 and C2 the
  texts are merged. The file is read once at startup.
- C3 `--system-prompt-snapshot <on|off>`: on by default (except `--bare` outside cloud/background). The
  prompt is rendered on the conversation's first request, `--append-system-prompt` included, recorded,
  and every later request and resume sends the record as is, "even when a later launch passes different
  text, until the conversation is compacted".
- C4 `--add-dir <directories...>`: grants tool access; `CLAUDE.md` loading from added dirs needs the env
  variable.

Mapping chosen: `ContextFile` -> `--append-system-prompt-file <path>`, interactive and headless.

- C1 inline rejected: the text would ride the interactive `Command` over the bridge, into the op log and
  tab state, and against the 64 KiB command cap.
- `--add-dir` plus `CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1` rejected: the variable applies to every
  `--add-dir`, so headless steps would start loading `CLAUDE.md` from stack worktrees, read folders and the
  sandbox scratch dir; the dir becomes tool-writable scope; tool children inherit the variable, which
  `claude/env.go` treats as session-tying; its interplay with `--setting-sources ""` (isolated runs) and
  P455 hermetic mode is unknown.
- Risk: C2 is hidden. A CLI that drops it fails the launch loudly ("unknown option"), never silently. The
  real-claude test (step 7) guards it; ARCHITECTURE Known open items records it.

Which launches see an edit (Claude):

- A new conversation sees the text saved before its launch: ADE Start, "+", review agent new
  conversation, headless step first attempt, review rounds, rebase runs, new smart run.
- A resumed conversation (Take over, Resume, Continue in terminal, headless retry and restart, smart run
  resume) gets the current file too, but C3 keeps the recorded prompt until the conversation compacts.
  Kira never passes `--system-prompt-snapshot off` (it would re-render the prompt each request).
- A running session never sees an edit.

## 3. Decisions

### 3.1 File, folder, cap

- File `~/.kira-space/agent/context.md`, Markdown. Singleton, fixed name. Absent, empty or whitespace
  only means no context: no flag, no snapshot.
- Cap `agentctx.MaxBytes` = 32 KiB (Q1), checked by `configfs.Text(MaxBytes)`. Over the cap or not UTF-8
  is a `Problem`; the last good text stays in use.
- Text passes verbatim. No `${...}` interpolation (P450 refs are for schema fields marked `x-kira-ref`).
  `AGENTS.md` says the file must hold no secrets: every agent reads it.
- Resolver `kirapaths.SharedAgentDir()` = `filepath.Join(Home("KIRA_SPACE_HOME", ".kira-space"),
  "agent")`. Space passes `filepath.Join(<its home>, "agent")` explicitly so flow tests with an explicit
  home stay hermetic; Studio calls the resolver.

### 3.2 Config versus state

- `agent/context.md`: config.
- `config_last_valid` row (`folder='agent'`, `file='context.md'`): derived projection, one per app DB. It
  exists for last good across restart while the file is broken. Nothing else in SQLite.
- Snapshot `<own home>/agent-context/<hash16>/AGENTS.md`: derived, per app, pruned.
- `agent/AGENTS.md`: derived docs, written by Space only.

### 3.3 Projection table (both apps)

- New generic table, reusable by P453 for `settings.yaml`:
  `config_last_valid(folder TEXT NOT NULL, file TEXT NOT NULL, value_json TEXT NOT NULL,
  recorded_at INTEGER NOT NULL, PRIMARY KEY (folder, file))`. Migrations Studio
  `0053_p452_config_last_valid.sql`, Space `0063_p452_config_last_valid.sql`.
- `configfs.TableProjection{DB *sql.DB; Folder string}` (`internal/configfs/table.go`) implements
  `Projection` (Snapshot, Record upsert, Forget). One implementation over both DBs, like
  `secrets.Store`.
- Workflows keep `ade_workflow_last_valid` (no migration of existing projections).

### 3.4 Store `internal/agentctx` (repo root, both apps)

```go
const File = "context.md"
const MaxBytes = 32 << 10
type Options struct {
	Dir         string               // shared agent folder
	SnapshotDir string               // <own home>/agent-context
	Projection  configfs.Projection
	App         string               // "Space" | "Studio", AGENTS.md header
}
type Store struct{ /* folder *configfs.Folder[string]; snapshot dir; prune once */ }
func New(o Options) *Store
func (s *Store) View() View                                  // file text, hash, problem, last good flag
func (s *Store) Save(text, baseHash string) (View, error)    // configfs.ErrConflict on stale baseHash
func (s *Store) ContextFile() (string, error)                // snapshot path of the text in effect; "" none
func (s *Store) Watch(onChange func()) (stop func(), err error)
func (s *Store) WriteDocs() error
```

- Folder: `configfs.Folder[string]{Dir, Ext: ".md", Name: ^context\.md$, Decode: configfs.Text(MaxBytes),
  Projection}`. Only `Get(File)` is used, never `List`: other `.md` files in the folder are not config.
- `ContextFile`: `Get(File)`; no file, nil value (invalid, no last good) or blank text gives `""`.
  Else path `<SnapshotDir>/<TextHash(text)[:16]>/AGENTS.md`: written with `configfs.WriteAtomic` (0600,
  dirs 0700) when missing, else `os.Chtimes` to now (marks in use). After a new write, and once per
  process, prune hash dirs with mtime older than 30 days, except the current one. Any write error is
  returned: the caller fails the launch, never launches silently without context.
- The name `AGENTS.md` is the cross-tool convention and keeps step 9's primary OpenCode route possible
  (a config dir holding `AGENTS.md`). Claude reads only the path it is given.
- `Save`: `MkdirAll(Dir, 0755)`, then `Folder.Save(File, baseHash, text)`. `baseHash` is always sent; for a
  missing file it is `TextHash(nil)`, which `Folder.Save` matches against a missing file, so a concurrent
  create is a conflict, not an overwrite.
- `View` (wire type, JSON tags camelCase): `{folder:"agent", file:"context.md", path, exists, text, hash,
  editable, problem: {line, message} | null, lastGood: bool, maxBytes, keepsOnResume: []string}`.
  `editable` is false when the file is not valid UTF-8 or over 1 MiB (text would be lost in JSON); the
  page then offers Open only. `keepsOnResume` lists `Label()` of every registered provider for which
  `harness.KeepsContextOnResume(p)` is true (3.5).
- `WriteDocs`: `Folder.WriteDocs` with a `DocModel{App: "Space", Title: "Kira agent folder", Intro:
  agents_intro.md (embedded), Pattern: "context.md", Format: "Markdown", Singleton: true, MaxBytes}`.
  Called by Space at start, non-fatal (P451 pattern). Studio never writes it: two app headers would
  rewrite the file at each start. P453 extends the same doc for its files.
- `configfs.DocModel` gains `Singleton bool` (Files section says "A single file" instead of "One item per
  file…") and `MaxBytes int` (0 = 1 MiB). `TestAgentsDocCoversSchema` stays green.
