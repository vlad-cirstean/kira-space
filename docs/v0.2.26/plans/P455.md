## 3. Decisions

### 3.1 What hermetic means

Hermetic: an app-launched agent loads none of the user's own agent config. Kira supplies settings
(`agent/settings.yaml`, P453), MCP (grant plus app servers), context (`agent/context.md`, P452), Kira's
hooks. Project files and managed policy still load. Login stays where the CLI keeps it.

| Item | Claude, hermetic | OpenCode, hermetic |
|---|---|---|
| User settings, hooks, permissions, env, statusline, model | `--setting-sources project,local` (C1, C4) | `XDG_CONFIG_HOME` redirect |
| User MCP servers | same (C3) | same |
| Account MCP (claude.ai connectors) | `ENABLE_CLAUDEAI_MCP_SERVERS=false` (C5) | none known |
| User instructions | same (C2) | redirect (global `AGENTS.md`); `~/.claude/CLAUDE.md` by H-OC4 env |
| User skills, commands, agents, plugins | same (C4) | redirect; `~/.claude/skills`, `~/.agents/skills` by H-OC3 env |
| Auto memory | `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1` (C6, Q3) | none known |
| Project config, project MCP, project and local `CLAUDE.md`/`AGENTS.md` | kept (`project,local`) | kept (no `--pure`, no `OPENCODE_DISABLE_PROJECT_CONFIG`) |
| Local-scope MCP (`~/.claude.json` `projects[cwd]`) | kept with `local` (Q4) | n/a |
| Login | kept (C7) | kept (data dir untouched) |
| Managed policy | applies (cannot isolate) | applies (cannot isolate) |

### 3.3 Harness seam

```go
// internal/harness/interactive.go, InteractiveSpec
	// Hermetic loads none of the user's own agent config; only the provider maps it.
	Hermetic bool
	// IsolationDir is a Kira-owned 0700 dir an Isolator prepared for this launch; "" none.
	IsolationDir string

// internal/harness/headless.go, HeadlessSpec
	// Hermetic loads none of the user's own agent config; Isolated runs load none already, Hermetic
	// still sets the provider's hermetic env. Only the provider maps it.
	Hermetic bool

// internal/harness/hermetic.go
// Isolator is a provider whose hermetic TUI launch needs files on disk. Optional role.
type Isolator interface {
	// Isolate fills dir (empty, Kira-owned) for one hermetic launch; environ is the launch's base env.
	Isolate(dir string, environ []string) error
}
// PrepareIsolation makes <parent>/<stem>-iso (0700) and has p fill it; dir "" and a no-op release
// when p is no Isolator. Release removes the dir; safe twice.
func PrepareIsolation(p Provider, parent, stem string, environ []string) (dir string, release func(), err error)
// IsolationGlob is the leftover pattern a start-up sweep removes.
const IsolationGlob = "*-iso"
```

- `InteractiveCommand` stays pure: it only names `IsolationDir`. Headless providers build their own
  scratch (OpenCode `runEnv` already does).
- Every env value a hermetic launch needs that the user's profile could override goes on `/usr/bin/env`
  words inside the command, after the login profile (sandbox wrapper precedent). Paths and flags only:
  never a secret.

### 3.6 Isolated runs and ticked MCP servers

Hermetic on (default): ticked servers come from Kira's agent settings `mcp_servers`, rendered per run,
never from the user's CLI config. No user settings source loads, so no `disableAllHooks`.

- `internal/agentcfg/servers.go`:

```go
// ServerSource is where an isolated run's ticked MCP servers come from: the app's settings when
// hermetic, else the agent CLI's own list.
type ServerSource struct {
	Store    *Store      // nil: CLI only
	Hermetic func() bool // nil: true
}
type ServerList struct {
	Source  string               `json:"source"` // "app" | "agent"
	Servers []harness.UserServer `json:"servers"`
}
func (s ServerSource) List(ctx context.Context, p harness.Provider, dir string) (ServerList, error)
// Missing is the first ticked name absent from the source ("" none); known false means not checked.
func (s ServerSource) Missing(ctx context.Context, p harness.Provider, dir string, names []string, wait bool) (missing string, known bool, err error)
// Wire returns what a run passes: an app MCP file (hermetic) or the names for UserMCP (CLI).
func (s ServerSource) Wire(ctx context.Context, l Launch, names []string) (Ticked, error)
type Ticked struct {
	MCPConfig string   // <Dir>/<Stem>-app.mcp.json, 0600; "" none
	UserMCP   []string // CLI mode only
	Secrets   []string // for the run's Masker
	Release   func()
}
```

- App `List`: every server in the last good settings, `enabled` ignored (a tick is explicit; `enabled`
  governs ambient launches only). `Transport` `http`/`stdio`, `Target` URL host or command base name,
  `Status` `""` (Kira never health-checks).
- `Wire` (app): resolve refs as `Prepare` (same resolver, same `Used` collection), render with
  `p.MCPConfig` (existing `MCPHost`), write `<Stem>-app.mcp.json` through `writeFiles`, track for `Close`;
  `Sweep` already matches. A missing name: `harness.ErrServerGone{Name, Agent: "Kira agent settings"}`.
  Sandbox profile already allows `<RunID>-app\.[a-z]+\.json` (P453).
- Callers: `scriptruns` `McpServers` (bound return becomes `ServerList`), `smartBlocker`, `launchSmart`
  (`MCPConfigs: [grant, app]`, `UserMCP` from `Ticked`, masker gains `Ticked.Secrets`, release with the
  grant), `Preview` text unchanged; ADE `checkMCP` and `superviseAgent` smart branch (`sink.setMask`
  joins). `HeadlessSpec.Hermetic` set from the same read.
- Hermetic off: CLI list and P444 path unchanged, `disableAllHooks` kept: an isolated run never runs user
  hooks, and loading the user source is the only way the CLI finds its own server. A design fact, not an
  open item (ARCHITECTURE).
- Wire change: `ScriptRunsService.McpServers` returns `{source, servers}` in both apps
  (`packages/shared/domain/scripts.ts` `scriptMcpServerListSchema`, `module.ts`, both bridges, mocks,
  regenerated bindings). Picker hint by source: `automations.smart.mcpHint.hint` (agent) and new
  `automations.smart.mcpHintApp.hint` "Servers from Kira's agent settings. Add one in Agents > Settings."
  Status hidden when `""`. Blocker copy from `ErrServerGone` ("MCP server X is no longer in your Kira
  agent settings config" via existing text; implementer adjusts `ErrServerGone.Error` wording only if it
  reads wrong).

## 10. Spec issues

  commands, subagents, plugins and output styles (C4). One flag, so hermetic drops them too. OpenCode's
  redirect drops the same set from `~/.config/opencode`.
- "Reject any control that breaks login": `--setting-sources` keeps OAuth, keychain and
  `.credentials.json` login, but not sign-in a user put in `~/.claude/settings.json` (`apiKeyHelper`,
  provider `env`). Same for an OpenCode provider defined in the user's `opencode.json`. No control keeps
  one and drops the rest without Kira reading the file (G5). Plan: documented in the setting description,
  env workaround through `settings.yaml` `env`, else hermetic off (Q1).
- "Toggle in Settings Agent": Studio has no Agent pane; Studio launches stay hermetic with no switch (Q2).
- Hermetic on by default turns existing smart scripts and smart steps that tick CLI servers into
  blocked runs until the servers are in `settings.yaml` (P454 imports them) or hermetic is off (Q5).
- "Each provider maps hermetic mode in its own package": done for flags and env; the OpenCode TUI needs a
  dir on disk, so the seam adds one optional role (`Isolator`) and one helper, both in `internal/harness`.
- Auto memory (C6) and claude.ai connectors (C5) are user-level context and MCP the spec does not name;
  plan turns both off (Q3).
- "OpenCode controls: `OPENCODE_DISABLE_CLAUDE_CODE`": the full switch also drops project `.claude/`
  compatibility, so the plan uses `_PROMPT` (and the H-OC3 skills name) instead, keeping project files.
