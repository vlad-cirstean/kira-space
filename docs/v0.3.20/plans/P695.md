# P695: Task files: watch on disk, submit narrowed, errors in state, no human diff for latest AI edits

Spec (user): watch task files on disk. `submit` only triggers a Kira action, or merges into step finish.
On a validation error Kira writes the error into state (agent's state file section). AI is told to check
that file and section regularly. While AI edits latest note, handover or proof, no human diff is shown.

Runs after P694 (verdict in "Overlap with P694"). Line numbers are from `a7dd84a4f`; find symbols by name
once P694 has landed, and rebase prompt text onto P694's final wording.

## Findings (codegraph, verified against worktree)

- Pipeline: `taskfiles.Service.Submit` (`apps/kira-space/internal/taskfiles/submit.go`) walks the folder
  (or named `Paths`), `Classify`, parse, diff against cache, `Decide` per change, then applies, restores,
  rejects or marks pending. Results: `FileResult{Path, Status, Message, Line, Notify, Proof}` with status
  accepted, pending, rejected, invalid, restored, unchanged, ignored. `one()` returns unchanged when the
  file hash equals the row's `AcceptedSHA256`.
- Kira writes (`Service.Write`): put intent in `task_file_intents`, `WriteAtomic`, then one transaction
  stores the accepted hash and deletes the intent. So a Kira write re-read by Submit is unchanged.
- Only entry points today: agent MCP `submit` (`internal/agentmcp/submit.go`, `SubmitArgs{Paths, Reason}`,
  both `omitempty`, so both optional) into `Board.Submit` (`ade/detailsmcp.go`) into `SubmitFiles`
  (`ade/detailssubmit.go`); and the implicit whole-folder flush in `FinishSession`/`SubmitForFinish`
  (`SubmitFiles(nil, "")`). No watcher exists: `useDetailsDisk.ts` and `AdeDetailsDiskBanner.vue` comments
  say "no watcher"; the user's external edits show only via `DiskChanges` on focus or Refresh.
- `SubmitFiles` holds `taskMu`, calls `svc.Submit`, mirrors cache back to disk (`mirrorTask`), bumps
  `df.lastSync[session.key]`, `notifyBoardNow`.
- Session: `submitSession(call)` maps `agentmcp.SpaceCall` to `detailsSession{key, run, role}`. Grants are
  registered by `b.agent.Register(agentmcp.Grant{TaskID, RunID, StepID, SessionID, Space, ...})` at
  `ade/launches.go:447` (TUI/manual) and `ade/runs.go:1009` (headless); release runs on process end.
- fsnotify v1.10.1 is already a dependency. Pattern to copy: `ade/folderwatch.go` (fsnotify, `addDirs`,
  `time.AfterFunc` debounce 500ms, stop waits for in-flight work). Also `internal/configfs/watch.go`.
- `state.yaml` (`ade/statefile.go`): `stateDoc{Rev, Task, Repos, Registered, Leases, Operations, Runs,
  Chain, Pending, Answers}`; one writer goroutine per task, 150ms coalesce, `markStateDirty`, writes only
  on body change via accepted-hash path. `writeArchivedState` builds empty slices.
- Decide matrix (`taskfiles/decide.go` `approvalCause`): note edit/create always `CauseNote`; handed
  handover `CauseHandover`; draft of current step free; links free when own or new; proofs free until
  accepted, then `CauseProof` (edit) or `CauseProofDelete`. `Collision` forces ask-first.
  `ReasonError` text: `%s: needs reason (%s). Call submit again with {"reason": %q}.`
- Diff ownership: `detailshandlers.go` `Diff` sets `Own` for creates and own rows. `detailsOwner.Answer`
  adopts an approved agent change as `RoleUser` (Source user), so author fields cannot tell an approved
  agent note from a user note.
- Collision: `collisionOf` in submit.go flags when `row.AcceptedBy` is another writer and
  `row.AcceptedAt > LastSync`.
- Claude hooks drop `tool_input` on decode (privacy rule, ARCHITECTURE ~1632): hooks cannot attribute a
  write to a session. Declined as watcher source.
- Server build (`-tags server`) differs only in `main`; `ade` is identical, so watcher works the same.

## Interpretation (decided)

### (a) Watch on disk

Watcher runs per task while at least one agent Space grant for that task is live. Its passes run
`SubmitFiles` as the one live agent caller with reason `""`, over the event paths only. Event paths only
(not a full walk), so a user's earlier external edit stays on the disk banner instead of being swept in
as the agent's.

- One live caller: pass runs as that caller (role, key, run, step).
- Zero or several live callers (orchestrator plus manual session on one task): no pass, clear the path
  set, `notifyBoardNow` so the disk banner refetches. Edits wait for that caller's explicit `submit` or
  finish flush, as today. Attribution needs one writer; guessing would misfile ask-first edits.
- User edits while no agent runs: no watcher, banner as today, plus board push now refetches the banner
  query (frontend change below).

### (b) Submit narrowed, rest merged into finish

- `submit` stays (tool name, allow lists, `SpaceToolIDs` unchanged) as the ask-first trigger: `paths`
  and `reason` both required. It is the one Kira action that needs an agent decision (send to user).
- Every other edit applies on save via watcher. `state step.finish` keeps its implicit whole-folder
  flush (`SubmitForFinish`/`FinishSession` unchanged): that is the "merged into finish" part, covering
  multi-caller tasks and edits in the last debounce window.
- Rejected alternative: fold reason into finish only. It delays approvals until step end and mixes
  finish's own failure reason with file reasons.

### (c) Errors in state

`state.yaml` gets a `fileErrors` section, right after `task`. Entry: `path`, `line` (omit when 0),
`error`. Recorded from agent-role results of status invalid or rejected; cleared when a later result for
that path has another non-empty status. In-memory only, no migration. Prompts and README tell the agent
to read `state.yaml` `fileErrors` after each edit.

### (d) No human diff for latest AI edits

"Latest" = newest of its type in the task, any author (literal reading; author fields cannot tell an
approved agent note from a user note, see Findings). Types: notes, handed handovers, proofs.

- Agent `OpEdit` of latest note or latest handed handover: free (accepted, no approval, no diff).
- Agent edit of any file of the latest proof (proof.md, data, image; create of a new file inside it
  too): free, even when accepted. Delete keeps `CauseProofDelete`.
- Older ones: unchanged rules (ask-first with reason).
- Note create stays ask-first (`CauseNote`): spec scopes freedom to editing latest. Draft is already
  free.
- Collision still forces ask-first.
- Disk banner hides paths with a live `fileErrors` entry: agent is mid-fix, no human diff for them.

## Changes

### 1. Watcher (`apps/kira-space/internal/ade/taskwatch.go`, new)

Types:

```go
const taskWatchQuiet = 300 * time.Millisecond

type taskWatch struct {
	b      *Board
	taskID string
	root   string
	w      *fsnotify.Watcher
	mu     sync.Mutex
	callers map[string]agentmcp.SpaceCall // key: SpaceCall session key (SessionID, else RunID)
	paths  map[string]struct{}            // rel slash paths since last pass
	timer  *time.Timer
	done   chan struct{}
	wg     sync.WaitGroup
}
```

`Board` gets `watches map[string]*taskWatch` guarded by its own `watchMu sync.Mutex` (not `taskMu`: a
pass takes `taskMu` inside `SubmitFiles`).

- `b.registerSpaceGrant(g agentmcp.Grant) (release func())`: calls `b.agent.Register(g)`. When
  `g.Space && g.TaskID != "" && b.files != nil`, builds the `SpaceCall` the MCP server would hand
  `Board.Submit` for that grant (same fields: TaskID, RunID, StepID, SessionID, Orchestrator), calls
  `b.watchTask(call)` and returns a release that first calls `b.unwatchTask(call)` then the original
  release. Replace both direct `Register` calls (`launches.go:447`, `runs.go:1009`) with it. Check the
  exact return shape of `Register` and keep it (wrap, do not change signature callers rely on).
- `watchTask(call)`: get or create the task's watcher (`fsnotify.NewWatcher`, root from
  `b.files.root`/task folder helper used by `mirrorTask`), add caller. Watch errors (fd limit, missing
  folder) log at warn and leave the task unwatched: finish flush still covers it. No pass at start.
- Dirs: root, `notes/`, `handovers/`, `proofs/`, each `proofs/<slug>/` (depth at most 2 under root).
  Walk with `filepath.WalkDir`; skip symlinked dirs (`d.Type()&fs.ModeSymlink`) and hidden names. On a
  `Create` event for a dir at allowed depth: add it, walk it, queue each file found (files written before
  the watch was added).
- Event filter: `rel, err := filepath.Rel(root, ev.Name)`; drop on error, `..` prefix or absolute. Slash
  it (`filepath.ToSlash`). Drop hidden segments, `README.md`, `task.yaml`, `state.yaml` (Kira-owned:
  stops the state.yaml rewrite loop; finish still restores tampering). Drop `Classify(rel).Kind ==
  KindIgnored` unless `ProofFolderHint(rel) != ""` (bad proof folder names surface as errors). Chmod-only
  events dropped.
- Queue: add rel to `paths`, `timer.Reset(taskWatchQuiet)` (`time.AfterFunc` on first). Timer fires
  `pass()` in a goroutine tracked by `wg`.
- `pass()`: swap out `paths`; if `len(callers) != 1`, `b.notifyBoardNow(taskID)` and return. Else
  `b.SyncTaskFiles(ctx, call, rels)` with `context.Background()` plus the Board's shutdown context if one
  exists (check `Board` for a lifecycle ctx; use it).
- `unwatchTask(call)`: remove caller. When none left: stop timer; if paths pending, run one final
  `pass()` synchronously while the last caller is still known (capture it before delete); close
  watcher; wait `wg`; delete from map; `b.files.clearFileErrors(taskID)`.
- Board shutdown: stop every watcher (find where folderwatch is stopped and do the same).

`SyncTaskFiles` (`ade/detailssubmit.go`, exported for tests):

```go
// SyncTaskFiles applies agent edits the watcher saw; reason "" so ask-first files report fileErrors.
func (b *Board) SyncTaskFiles(ctx context.Context, call agentmcp.SpaceCall, rels []string) error
```

Keeps rels that exist on disk or have an index row (deletes), sorted, deduplicated; none left returns
nil. Builds session via `submitSession(call)`, calls `SubmitFiles(ctx, taskID, s, rels, "", watchPass)`
where a new `syncMode` arg tells `SubmitFiles` not to bump `lastSync` (see section 2). Explicit submit
and finish pass `explicitPass`.

Race guard (`taskfiles/submit.go`): load open intents for the task once per `Submit`
(`task_file_intents` query exists for recovery; reuse it). In `one()` and proof `unit()`, a file whose
current SHA256 equals an open intent's hash for that rel returns `FileResult{}` (empty Path: nothing to
report). Kira is mid-write; the transaction after `WriteAtomic` makes it accepted.

Partial writes: debounce plus the last event always schedules a pass. A half-written file gives a
transient `fileErrors` entry, cleared by the next pass.

### 2. Errors in state (`ade/details.go`, `ade/detailssubmit.go`, `ade/statefile.go`)

- `detailsFiles` gets `fileErrs map[string]map[string]fileError` (taskID, rel) under `df.mu`;
  `type fileError struct{ line int; msg string }`.
- In `SubmitFiles`, after `svc.Submit`, for agent roles only (`s.role.Agent()`), per result with
  non-empty `Path`:

  - status restored: skip (Kira-owned, restored already);

  `row.AcceptedBy == "kira"` (Kira mirrors are not another author's change).
- `clearFileErrors(taskID)` deletes the task's map and marks state dirty; called from `unwatchTask` and
  `writeArchivedState`.
- `stateDoc`: add `FileErrors []stateFileError \`yaml:"fileErrors"\`` right after `Task`;
  `stateFileError{Path string \`yaml:"path"\`; Line int \`yaml:"line,omitempty"\`; Error string \`yaml:"error"\`}`.
  Build sorted by path, always non-nil (`[]` when empty), in the writer and in `writeArchivedState`.
- `DiskChanges`: drop paths that have a live `fileErrors` entry.
