# P697: Required services: repo scripts that must be running for a task

Name kept: "Required services". Repo file key `services`, Go `RequiredServices`, UI "Required services".

Line numbers are from worktree head `425b198dc`; find symbols by name if they moved.

## Findings (codegraph, verified against worktree)

- Run scripts live in `internal/scripts` (`CustomScript`, global, Automations module). A run is a
  `script_runs` row (`internal/scriptruns/run.go` `Run`): `State` `running` while live, `TaskID`/
  `BranchID` set when started for an ADE task. A normal script runs in a terminal tab: `Service.Begin`
  inserts the running row, `Service.Exited` finishes it (`FinishByTerminal`). `Service.Recover`
  (boot) fails every row the last process left `running`, so `state = running` is trustworthy for
  Kira-started runs. That is the whole detection seam: no process, port or health probe.
- `scriptruns.Repo` already has `Running(scriptID, taskID, branchID)` (exact task and branch) and
  `Active(scriptID, exceptID)` (running or waiting). No "running run of a script, any task" query.
- Repo files (`apps/kira-space/internal/repocfg`) already reference Run scripts by name:
  `worktree.prepare_run`, `environments[].deployed_sha_run`, each a `model.ScriptRef`
  (`{script, params}`), validated by `scriptRefsRule`, resolved at run time by
  `ade.resolveScriptRef` (`ade/scriptref.go`). `resolveScriptRef` also checks params and calls
  `scripts.PrepareDir` (side effect): a status read must not call it.
- Shared repo files (`repocfg/shared.go` `SharedFile`) carry the team-safe keys, `prepare_run`
  included; `configsync/repos.go` merges them key by key (`collect`/`applyRepoEntries`).
- Repo form: `frontend/src/repo/RepoConfigForm.vue` over one draft; `state/repoFields.ts`
  (`REPO_FIELDS`, `REPO_FORM_POINTERS`); `RunScriptRefPicker.vue` picks a normal script plus params
  (Pinia `useCustomScriptsStore`). `RepoEnvRow.vue` is the list-row precedent.
- Work start gate precedent: P598 repo gate. `useRepoGate.ts` (`ensureRepo`, `opAfterRepo`),
  Pinia `adeRepoGate.ts` (`ask(taskId): Promise<boolean>`), `AdeRepoGateDialog.vue` mounted async in
  `AdeShell.vue`. Called from `useTaskAction.ts` (run, approve, session, startNew),
  `useNeedsAction.ts` (approve), `AdeRunDialog.vue`, `adeDialogs.ts`.
- Other user work starts: `adeDialogs.start(branchId)` (branch Start), `adeDialogs.session(taskId)`
  (new session dialog), `adeTakeOver.request(sessionId)` (Take over, Resume of a TUI session),
  retry and resume of runs (`useTaskAction`, `useNeedsAction`), ad hoc session
  (`sessions/AdeTaskLaunchMenu.vue`, `StartAdHoc`), review agent (`AdeReviewAgentPanel.vue` `start`).
- Starting a script for a task from ADE: `useScriptRunDialogStore().open({scriptId, taskId,
  branchId, prefill, from: 'ade'})` (`packages/workbench/src/automations/run/runDialog.ts`), the same
  path `useRunAutomation.start` uses. The run dialog previews, starts and opens the terminal tab.
- `ade` already imports `internal/scriptruns` (`ade/automation.go`), so the board may hold the runs
  repo. `appwire/wire.go` `wireAdeTask` has `runs *scriptruns.Service` (`runs.Runs` is the repo).
- Push channels: `control.onScriptRunsChanged` (`kira:scriptRuns:changed`, every run change) and
  `control.onRepoConfigChanged` exist in `frontend/src/bridge/index.ts`.

## Decisions (planner defaults; user may override, see report)

1. Declaration: top-level repo file key `services`, a list of `ScriptRef` (`{script, params}`), max
   10, normal scripts only, unique script names. No inline shell form: an inline command has no run
   record, so Kira could never see it running. Also allowed in shared files and synced by config
   sync, like `prepare_run`.
2. Detection (user decided): only Kira-started runs. A service whose script runs in its own folder
   (`UseAdeDir` off) counts as running when any `running` run of that script exists, whatever task
   started it (one dev DB serves every task). A service whose script has "Run in ADE worktree" on is
   per branch: one entry per mine branch of the task in that repo, running when a `running` run of
   that script exists for that task and branch. Params are not compared; they only prefill a start.
3. States per entry: `running`, `stopped`, `noWorktree` (worktree service on a branch with no
   worktree yet: it cannot run, never asks), `invalid` (ref does not resolve: missing, smart,
   duplicate name; carries the reason).
4. Trigger: frontend gate before every user action that starts an agent or a step on the task: Run
   (agent step opens the Run dialog only after the gate; other steps start directly), Approve, Retry,
   Resume (runs), new session dialog, branch Start, Take over (and TUI Resume through it), ad hoc
   session, review agent. Engine-driven starts (auto advance, scheduled scripts, MCP, review rounds,
   restart resume) never ask: work already started. Phone writes (`mobileweb`) do not ask: no dialog
   surface there. The server build runs the same frontend, so it asks too.
5. Ask: dialog lists entries with state `stopped` or `invalid` (and the others for context). It opens
   only when at least one entry is `stopped` or `invalid`.
6. Memory: Continue with a service still not running remembers a skip for that task in memory (Pinia)
   until app restart; later starts of that task do not ask. Nothing persisted.
7. Ownership: Kira never stops services it started when the task finishes or archives.
8. Row Run: closes the gate (that start is not made) and opens the run dialog for the script with
   the task, branch (worktree services) and ref params as prefill. The user starts work again; the
   service now counts as running and the gate stays silent. Reason: two modal dialog roots at once
   (gate plus run dialog) fight over focus trap; duplicating the run dialog's preview, hash and
   terminal-launch logic in the gate is worse.

### `apps/kira-space/internal/ade`

- `scriptref.go`: extract the lookup half of `resolveScriptRef` (name match, kind, duplicate count,
  refusal reasons) into `findRefScript(all, use, name) (scripts.CustomScript, error)` returning a
  `refReason`; `resolveScriptRef` calls it. No behaviour change for prepare, env and smart steps.
- New `services.go`:
  - `TaskBoardDeps.RepoServices func(repoID string) []model.ScriptRef` and
    `TaskBoardDeps.ScriptRuns *scriptruns.Repo` (board.go deps struct, doc comments).
  - `func (b *TaskBoard) RequiredServices(ctx context.Context, taskID string) (adewire.RequiredServices, error)`:
    1. `loadTaskCtx`; unknown or archived task returns the usual not-found error.
    2. Distinct code repos of the task's branch rows (any kind), branch order. Per repo
       `b.deps.CodeRepos.Get` then `b.deps.RepoServices(rec.RepoID)`. No deps (nil) or no refs:
       empty `Items` (never nil).
    3. `b.listScripts()` once. Per ref `findRefScript(all, repoFileUse, ref.Script)`; failure: one
       `invalid` entry with `Problem` = reason.
    4. `UseAdeDir` off: one entry, `ScriptRuns.RunningScript(id)`; state `running` (with `RunID`) or
       `stopped`. Dedupe by script id across repos (first repo keeps the entry).
    5. `UseAdeDir` on: per mine branch of the task in that repo: `newAttachCache().worktree(ctx, sb)`
       (one cache per call); `attached == ""` gives `noWorktree`, else
       `ScriptRuns.Running(id, taskID, sb.ID)`. Dedupe by (script id, branch id).
    6. `Params` = `ref.Values()` (non-secret only: secret params are refused in repo files already).
  - Read-only: no task mutex, no `PrepareDir`, no op row.
- No `RepoConfigChanged` change: status is computed per call.
