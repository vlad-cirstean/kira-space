# P696: Dialogs: remove redundant buttons (audit every dialog)

User request: "Lots of dialogs have useless buttons like a cancel next to a no while all dialogs also
have the x button. But check all dialogs for such things."

Frontend only. No IPC, Go or bridge change, so the IPC-split test rule has no backend half: no flow test.
The UI specs below are the whole proof. Line numbers are from worktree head `a7dd84a4f`; find symbols by
name if they moved.

## Findings (codegraph, verified against worktree)

- Every `DialogContent` dialog renders its header through `DialogHeader`
  (`packages/theme/src/components/ui/dialog/DialogHeader.vue`). `closable` defaults to `true`, so the X
  is on every dialog except `CommandDialog` (palette, `:closable="false"`, sr-only header, no buttons) and
  `UpdateDialog` while `state === 'installing'`.
- The X calls `requestClose` (`DialogContent.vue` 92-108): asks the discard confirm when `dirty`, then
  `rootContext.onOpenChange(false)`, which fires the dialog's `@update:open` handler. Esc goes the same
  way (blocked for `prompt` dialogs, whose hide chord `prompt.hide` also calls `requestClose`, 121-128).
- Footer Cancel/Close buttons call the same handler as `@update:open` in every dialog listed as redundant
  below (checked per file: same function, or `DialogClose`, or `open = false` on a `v-model:open`). The
  only difference: a footer Cancel skips the dirty discard confirm (`DialogContent.vue` 91 comment,
  `docs/ARCHITECTURE.md` 1423). After this phase the X and Esc are the only dismiss paths and both ask.
- Destructive dialogs (`DialogContent destructive`, `ConfirmDialogView tone="danger"`) open focused on
  `[data-dialog-dismiss]` (`DialogContent.vue` `onOpenAutoFocus` 68-85). Today that attribute sits on
  the footer Cancel. With the Cancel gone, the X must carry it, or a destructive confirm opens with no
  safe focus target.
- `ConfirmDialogView` (`packages/workbench/src/components/ConfirmDialogView.vue`) is the one confirm
  look: store host `ConfirmDialog.vue` plus 8 direct hosts. Its footer always shows Cancel, plus an
  optional secondary button. The only `choose()` caller (`apps/kira-space/frontend/src/studio/api/state/tabClose.ts`
  112) renders Cancel + Discard + Save: the "Cancel next to No" case. Cancel there resolves `'cancel'`,
  the same as the X (`@update:open` emits `cancel`).
- `TextPromptDialog.vue` (`packages/workbench/src/prompt/`) is a hand-rolled `role="dialog"` (U3
  exempt) with no X: its Cancel is the only click dismiss. Keeps it.
- Popovers with Cancel (`packages/git-ui/src/App.vue` force-delete popover, `StreamComposeMessage.vue`)
  are not dialogs and have no X: out of scope, unchanged.
- Inventory search: `git grep -l -E "<DialogContent\b|<AlertDialog|<ConfirmDialogView\b|<SheetContent\b|<DrawerContent\b|<CommandDialog\b|<DialogFooter\b|<DialogHeader\b|<Dialog\b|role=\"dialog\"" -- '*.vue'`
  minus `components/ui/`: 68 files. No `AlertDialog`, `Sheet` or `Drawer` exists. Wrappers resolved:
  `ConfigFileDialog` (hosts `ApiVariablesDialog`, `ConnectionFileDialog`, `RunFileDialog`),
  `TextPromptDialog` (5 hosts), `RestoreDialog` (hosts docker `RestoreDialog`, `RunsRestoreDialog`),
  `PairingRequestDialog` (host `MobilePairingDialog`), `ScheduleConfirmDialog` (host
  `ScheduleConfirmPrompt`), `SettingsShell` (host `SettingsDialog`), `AdeStageDialog` (hosts `AdeShell`,
  `AdeHandoverPrompt`), `ConfirmDialogView` (hosts below).

## Rule applied

- R1 (dismiss duplicate): a footer button whose only outcome is closing the dialog (Cancel, Close, Later,
  Not now wired to the same handler as `@update:open`, `DialogClose`, `open = false`) duplicates the X.
  Remove it.
- R2 (same outcome side by side): Cancel beside No/Discard/Not now in a confirm. Covered by R1 because
  the X is that Cancel.
- Keep every button with its own outcome: commit (Save, Create, Run, Delete...), alternate (Discard,
  Stash and check out, Choose another, Copy, Stop, Retry, Cancel restack), and a negative answer that
  sends something the X does not (Deny, Not now that declines or withdraws, Dismiss that clears a restore
  offer, Cancel that answers a credential prompt with null).
- A dialog that hides the X keeps its dismiss button (`UpdateDialog` installing Cancel, `TextPromptDialog`).
- Destructive confirms keep an explicit negative path: the X, focused on open (moved
  `data-dialog-dismiss`), plus Esc. No dialog is left without a way to dismiss: every dialog below keeps
  its X, and Esc keeps working where it did (prompt dialogs keep the hide chord).
- A footer left with no button is removed (or gated with `v-if` for the states that still have one).
