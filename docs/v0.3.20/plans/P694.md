# P694: Agent prompts: when to write proofs, where the task Details live

User-mandated exact wording, very short: finish line `Write a proof for any checkable result before finishing.`
and files line `This task's Details files live in {{.Folder}}; see README.md there.`

Two prompt fixes, user-approved. User constraint: one short model-facing sentence per fix, no examples
list, no rationale. Wording below is final; implementer copies it byte for byte.

Line numbers are from worktree head `1d42b47ac`; find symbols by name if they moved.

## Findings (codegraph, verified against worktree)

- Proof guidance today is format only: `proofExample` in `apps/kira-space/internal/taskfiles/readme.go`,
  the `Proofs:` index lines of `HeadlessSpaceFiles` (`internal/llmprompts/registry.go`). Nothing says when.
- `HeadlessFinishStepSuffix` (`headless.finishStep.suffix`) ends every agent step prompt
  (`ade.step.prompt` lists it in `RequiredFragments`) and every resumed step message
  (`composeResumePrompt`, `apps/kira-space/internal/ade/vars.go`). `.Plain` is true only for runs with
  no Space grant (review rounds, `PlainFinishInstruction`): those have no `submit`, so no proofs.
- Workflow YAML: no workflow or step ships as a default (`adeflow` embeds only `agents_intro.md`,
  `steps_intro.md`); neither mentions proofs. Silent, not contradicting: no change.
- `submit` tool (`HeadlessToolSubmit`): description is neutral on proofs. Its `reason` arg lists the
  ask-first files but omits accepted proofs, which `proofunit.go` (`Decide(... OpEdit, ProofAccepted:
  true, Reason ...)`) and the README "Ask first" line both gate on reason. Contradiction: align it.
- Details path: `HeadlessSpaceFiles` already carries the folder (`Task folder: {{.Folder}}. See
  README.md there.`). `FilesVars` from `filesVars` (`ade/detailsprompt.go`) reaches every Space prompt:
  step prompt (`AdeStepPrompt`), manual session first message (`AdeManualMessage`, interactive TUI),
  branch Start session (`AdeStartMessage`), review agent (`AdeReviewMessage`), smart step, and resumed
  step runs (`composeResumePrompt` from `startRun`, `runs.go` ~745, after `restartHeadless` or a
  send-back). So the fix is wording, not a new injection point. `context.md` (`internal/agentctx`) stays
  untouched: user-edited and shared.
- `RunResumeLine` needs nothing: a resumed headless step gets `line + headless.space.files + finish`
  via `composeResumePrompt`. A resumed interactive TUI conversation keeps its first message, which
  already holds the line. Smart-script resume (`scriptruns/resume.go`) has no task folder.
- Interactive Start and manual sessions carry no finish instruction (user finishes them), so they get
  the proof sentence through the README line only. Accepted: README is listed in their files line.

## Changes

### 1. Proof sentence in the finish instruction

`internal/llmprompts/registry.go`, `HeadlessFinishStepSuffix.Default`: append at the very end, after the
closing `{{end}}` of the Implicit/declared branch:

```
{{if not .Plain}} Write a proof for any checkable result before finishing.{{end}}
```

End placement keeps the rendered text starting with `When this step ...`, so the `copy-coverage.spec.ts`
exemption regex (`/^(?:Kira tools: |When this step is done, call state)/`) still matches; recency also
helps the model. Gated on `not .Plain`: review rounds have no `submit`.

### 2. README mirror line

`apps/kira-space/internal/taskfiles/readme.go`, `Readme`: add one line to the fixed block, right after
the `Ask first ...` line, before `proofExample`:

```
Write a proof for any checkable result before finishing.
```

Fixed lines go 13 to 14; `MaxReadmeLines` (35) stays, child room drops by one. Fix
`TestReadmeCapHoldsForAnyTask` only if it hard-codes room.

### 3. Details path sentence

`HeadlessSpaceFiles.Default`: replace the first two sentences `Task folder: {{.Folder}}. See README.md
there.` with:

```
This task's Details files live in {{.Folder}}; see README.md there.
```

Rest of the template unchanged.

### 4. submit `reason` arg alignment

`registry.go`, `arg(HeadlessToolSubmit.id, "reason", ...)` text becomes:

```
One line: why you changed a handed handover, a note, an accepted proof or another author's link. Required for those; the user reads it.
```

### 5. Registry metadata

No new entry: prompt count stays 169 (`flows/llmpromptsflow/llmprompts_test.go`), catalog counts
unchanged. `packages/theme/src/i18n/en.json` (only locale file):

- `llmPrompts.entry.headlessFinishStepSuffix.description`: `Tells an agent step how to report its result with the finish_step tool, using the results the step declares, and asks for a proof of any checkable result when Kira Space tools are on.`
- `llmPrompts.entry.headlessSpaceFiles.description`: replace `Names the task folder, points at the readme there,` with `Names the task's Details folder, points at the readme there,`.
- `llmPrompts.entry.headlessSpaceFiles.usedBy.body`: `Follows the Kira Space tools line in every ADE step prompt and session message, and in every resumed step message.`

`scripts/copy/` has no guard on these Go defaults; run `check-copy`/`check-catalog` anyway (i18n changed).

### 6. Edited prompts

An override stores the user's full text (`Prompt.Text`: valid override, else default). A user who edited
`headless.finishStep.suffix` or `headless.space.files` keeps their text and gets neither new sentence;
the Settings editor shows their text against the new default (`PromptDetail.vue` diff), so they can
merge. Edits of `ade.step.prompt` cannot drop the finish instruction (`RequiredFragments`), so the proof
sentence survives them. `composeResumePrompt` calls `HeadlessSpaceFiles` directly, so resumed runs keep
the Details sentence even when a message entry was edited. `TestRunUsesEditedFinishInstruction` stays
as is (override replaces default, proof sentence included).
