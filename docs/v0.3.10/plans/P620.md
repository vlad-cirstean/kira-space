# P620 Resource leases: named queues, push wake-up

Plan by Opus. One sequential Sonnet implementer, no streams. Base: `chapter/v0.3.10` after P617 to P619.

## Findings (verified with codegraph_explore)

### Session end on hard kill

- PTY child dies, so `terminal.Session` readLoop ends. `unregister` calls `Registry.remove`, which fires `OnChange`.
- `OnChange` reaches `ade.Tracker.Reconcile`. Once spawn grace passes, Reconcile stops the record and calls `OnStopped(recordID)`. That is `TaskBoard.OnTUIStopped` (launches.go), which already releases the agentmcp grant.
- Same path for exit, crash and kill: no hook is needed, and `SessionEnd` never fires on SIGKILL.
- Headless run end releases its grant through `joinRelease` (dbmcp.go) or the run's release func (runs.go ~932).
- Conclusion: session-end release hangs off these two points. Lease key is `Grant.SessionID`, which is the ade_sessions record id: `cmpNonEmpty(pa.Resume, pa.RecordID)` for TUI, `l.sessionID` for headless.

### Idle detection

- No busy/idle state is stored today. It derives safely from hook events `Tracker.HandleEvent` already sees, per record:
  - busy: after `EventPrompt` (UserPromptSubmit), `EventToolStart` or `EventToolEnd`.
  - idle: after a main-agent `EventTurnEnd` (Stop) with `AgentID == ""`, `Background == 0` and no wake armed (`Tracker.wake`).
  - input: after `EventNotification` with `NeedsInput`, i.e. a permission or question prompt. Typing would answer it, so never inject here.
  - unknown: spawn until first event. Treated as not idle.
- Residual risk: the user typing into the terminal is invisible. `Tracker.Send` (review forward, mobile reply) already accepts this.
- Decision: idle detection is safe enough, so keep injection. Inject only into a record whose state is `idle`, checked under the tracker lock in the same critical section as the write.

### Hook fallback

- The Claude hook server cannot answer today:
  - `handleHook` (internal/harness/claude/hooks/http.go) writes a bodiless 200.
  - The shim (shim.go:67-75) runs curl with `--output /dev/null`.
- Fallback needs a reply path:
  - The shim prints the body to stdout.
  - On Stop, the server returns `{"decision":"block","reason":"..."}`, so the agent continues with the message.
  - On UserPromptSubmit, the server returns `{"hookSpecificOutput":{"hookEventName":"UserPromptSubmit","additionalContext":"..."}}`.
- The OpenCode hook server cannot reply, so OpenCode gets injection only.
- Headless runs have no terminal and no hooks. They learn of a grant by calling `acquire_lease` or `lease_status` again, and the tool text tells them to.

### MCP caller identity and heartbeat

- `agentmcp.Grant` carries `SessionID`, `TaskID` and `RunID`, and `spaceTask(req)` yields `SpaceCall{TaskID, RunID, StepID, SessionID}`.
- `recordCalls` (optools.go) reports every tools/call to `Options.OnToolCall` as `ToolCall{Tool, RunID, TaskID, Args}`. It lacks `SessionID`; add it there for the heartbeat.

### Task order

Requirement: grant order equals task list order exactly. How the UI computes the task list (verified with codegraph):

- **Plan list:** `buildTimeline(...).seq` (`frontend/src/ade/v2/board/timeline.ts:421`).
  - `buildMineEntries` (:153):
    - Covers every task, but skips a review item without a plan day.
    - `day` = `isoToOffset(today, plan.day[id])`, or `LATER` (9999) if undated.
    - `est` = `parseEst(t.est, workdayHours, spanDayShare)` (`calendar.ts:20`); null for review items.
    - `span` = 1 if undated, else `est?.days ?? 1`.
    - `days` = `spanDays(cal, day, span)`, which walks `nextWork` past weekends and `offDays` unless the day is in `workWeekendDays`.
    - `end` = the last of `days`.
    - `pos` = index in `plan.order`, or 999.
    - Sort by `(end, day, pos)`.
  - Filter to `shelfOf(board, id) === 'plan'` (`shelf.ts:9`).
  - `placeReviews` (:194): for each mine entry in order, put an undated review item right above the first task that has a branch with that review's first branch as an ancestor or a conflict partner. Reviews never placed go last.
  - Ancestors and conflicts come from `buildBranchGraph` (`branchGraph.ts:56`):
    - parent = `plan.queuedAfter[b]`, else a `baseBranchId` that is a board branch;
    - conflicts = same-repo review branch, not an ancestor, of a live non-draft mine branch, with non-empty `pairs[].conflicts`.
- **Later tab:** `shelfIds(board, 'later')`, then `shelfIds(board, 'backlog')`. That is plan order, with tasks missing from `plan.order` appended in board order.
- **Display only:** the repo filter and the first-10 cap hide rows but never reorder them.
- **Full task list order** = seq ids, then Later ids, then Backlog ids.
- **Inputs all exist in Go:**
  - board fields: `adewire.Board` `Tasks`, `Branches` (`BaseBranchID`, `MergedIntoMain`, `Kind`, `CodeRepoID`, `Name`), `Plan` (`Day`, `Order`, `Backlog`, `QueuedAfter`), `Pairs`;
  - settings: `model.Settings.Ade` `WorkdayHours`, `SpanDayShare`, `OffDays`, `WorkWeekendDays`;
  - today: the local date, the same machine clock the UI reads.
- **Decision:** port the ordering to Go and pin it to the TS function with a shared golden fixture, so both compute the same list.
  - Rejected: the frontend publishing its order. It goes stale when the UI is closed or the day rolls over, and grants need it then.
  - Rejected: moving the timeline to the backend. That is a large UI refactor outside this phase.
  - No concrete requirement blocks an exact match.

## Design

### Core package `apps/kira-space/internal/leases` (new, no app imports)

`leases.go`:

- `type Key string` holds the session record id; `"run:" + RunID` when `Grant.SessionID` is empty.
- `type Entry struct{ Key Key; TaskID string; Seq uint64; Since, Seen time.Time; ReleaseAsked bool }`.
- `type Queue struct{ Name string; Holder *Entry; Waiters []Entry }`.
- `type Book struct`:
  - fields: `mu sync.Mutex`, `queues map[string]*queue`, `names []string`, `seq uint64`, `now func() time.Time`, `ttl time.Duration`, `order func() []string`, `onGrant func(Grant)`, `onChange func()`.
  - `order` returns the task list order (see "Task list order in Go"), called once per promote and per snapshot.
  - A waiter's rank is its task's index in that list. Tasks not in the list (archived, run without a task) rank after all listed ones. Ties go by `Seq`.
- Methods, all non-blocking:
  - `SetQueues(names []string) error`: set the names in the given order and trim spaces. Reject an empty name, a duplicate, a name over 64 characters, or a name outside `[A-Za-z0-9 ._-]`. A removed queue drops its holder and waiters; each dropped holder gets `onGrant` with `Revoked: true`.
  - `Acquire(key, taskID, queue) (Status, error)`:
    - An unknown queue returns `ErrUnknownQueue` listing the names.
    - Holder re-call: touch `Seen`, return `held`.
    - Waiter re-call: keep `Seq`, return its current position.
    - A free queue is granted at once (`Status{State:"held"}`).
    - Otherwise append with a new `Seq` and return `queued` with a 1-based position, computed after sorting by rank and then `Seq`.
  - `Release(key, queue) []string`:
    - `queue == ""` releases every hold and every wait of key.
    - It returns the released names and grants the next waiter of each freed queue.
  - `ReleaseSession(key)`: the same as `Release(key, "")`, used at session end.
  - `ForceRelease(queue) (Key, error)`: drop the holder, grant the next waiter, and fire `onGrant` with `Revoked: true` for the old holder.
  - `RequestRelease(queue) (Key, error)`: set `ReleaseAsked` and return the holder key. No state change otherwise.
  - `Touch(key)`: extend `Seen` on every hold of key.
  - `Sweep(alive func(Key) bool)`: release each holder with `now - Seen > ttl` unless `alive(key)`. alive is true while the holder's record is mid-turn (busy), so a long Bash run never expires.
  - `Snapshot() []Queue`: queues in name order, waiters sorted by the same rank used to grant.
- Grant step, private `promote(q)`:
  - Sort waiters by index in `order()` and then `Seq` at grant time. This re-evaluates priority on each grant.
  - Pop the first waiter into `Holder` with `Since = Seen = now` and fire `onGrant(Grant{Queue, Key, TaskID})` after unlocking.
  - Never touches a present holder: no preemption.
- `Status` carries `Queue`, `State` (`held` or `queued`), `Position`, `HolderTask` and `TTLSeconds`.
- `const DefaultTTL = 10 * time.Minute`.
- Callbacks run outside `mu`. Collect them in a slice under the lock and call them after unlock.

`leases_test.go` is the only unit test, for logic that is genuinely hard to get right:

- ordering by list index, unlisted tasks, `Seq` ties, and re-ranking between grants when `order()` changes;
- a waiter re-call keeping its position;
- no preemption by a higher-ranked arrival;
- TTL expiry versus `alive`;
- session release freeing several queues and promoting each;
- a concurrent Acquire/Release/ForceRelease race under `-race` (N goroutines). Assert one holder per queue and no lost or duplicated key.

Go side: new `apps/kira-space/internal/ade/taskorder.go`.

- `func TaskListOrder(b adewire.Board, s model.AdeSettings, today string) []string`, a line-for-line port. Name the settings type per `model/settings.go:68`, the struct holding `WorkdayHours`.
  - `parseEst`:
    - Regex `^(\d+(?:\.\d+)?)\s*(m|h|d|w)$` after lowercase and trim.
    - Match JS `trim` and `\s` exactly. JS whitespace includes U+FEFF and the Unicode Zs class, while Go `\s` is ASCII and `strings.TrimSpace` lacks U+FEFF. Use `strings.TrimFunc` with JS's set and the class `[\t\n\v\f\r \x{a0}\x{1680}\x{2000}-\x{200a}\x{2028}\x{2029}\x{202f}\x{205f}\x{3000}\x{feff}]`.
    - Use `strconv.ParseFloat`, `math.Ceil(n/workdayHours - 1e-9)` and cap 60. `\d` is ASCII in both.
  - Calendar:
    - `isoToDays` via `time.Date(y, m, d, 0, 0, 0, 0, time.UTC).Unix() / 86400`.
    - Day of week from the epoch Thursday (index 4).
    - Off days and work-weekend sets as offsets from today.
    - `nextWork` and `spanDays` exactly as in TS.
  - Branch graph: only `parentOf` and `ancestors` (cycle-safe walk), `conflicts` per `buildConflicts`, and a pairs map in both directions.
  - Entries:
    - sort with `sort.SliceStable` on `(end, day, pos)`. JS `Array.prototype.sort` is stable, so equal keys keep board task order.
    - `shelfOf`, `shelfIds` and `placeReviews` as in TS.
- `TaskBoard.taskListOrder()` builds the order from the board snapshot `Board()` already produces (`adewire.Board`), the current Ade settings and `time.Now().Local().Format("2006-01-02")`.
  - The UI's `today` is also the machine's local date; confirm its source via codegraph on the `today` input passed to `buildTimeline`. If the UI uses a settings or zone override, use the same one.
  - Wire it as `Book.order`.

### Tracker: turn state, safe send, hook reply (`apps/kira-space/internal/ade/tracker.go`)

- Add `turn map[string]turnState` keyed by record id, with `turnUnknown|turnBusy|turnIdle|turnInput`. Set it in `trackStatusLocked` per the Findings rules and delete it where `byRecord` entries are dropped.
- `func (t *Tracker) Busy(recordID string) bool` returns true for `turnBusy` and feeds `Sweep`'s `alive`.
- `func (t *Tracker) SendIfIdle(recordID, msg string) (bool, error)`:
  - Under the lock, require `turnIdle` and a live terminal.
  - Write the same bytes as `Send`: reuse `pasteBytes` and the enter write.
  - Set the state to `turnBusy` before unlocking, so two sends cannot both pass.
  - Returns false when not idle.
- `SetIdleHandler(func(recordID string))`, like `SetStoppedHandler`. It fires after the lock is released when a record moves into `turnIdle`, and is used for OpenCode, which cannot get a hook reply.
- `SetHookReplyHandler(func(recordID string, ev harness.AgentEvent) harness.HookReply)`. `func (t *Tracker) HookReply(ev harness.AgentEvent) harness.HookReply` maps `ev.TerminalID` to a record and calls the handler. It answers only for main-agent Stop (`AgentID == ""`) and UserPromptSubmit.

### Hook reply plumbing

- `internal/harness/hooks.go`:
  - Add `type HookReply struct{ Block string; Context string }` (empty means no output).
  - Add `HookOptions.Reply func(AgentEvent) HookReply`.
- `internal/harness/claude/hooks/http.go` `handleHook`:
  - Compute `Reply` first, then call `OnEvent`. Both stay synchronous; the shim's curl has `--max-time 2`.
  - A non-empty `Block` on Stop writes `{"decision":"block","reason":Block}`.
  - A non-empty `Context` on UserPromptSubmit writes `{"hookSpecificOutput":{"hookEventName":"UserPromptSubmit","additionalContext":Context}}`.
  - Otherwise keep writing an empty 200.
  - Reply runs before OnEvent so a Stop that carries the wake never also counts as idle.
- `internal/harness/claude/hooks/shim.go`: replace `--output /dev/null` with `--output -` and keep `exit 0`. An empty body prints nothing, so other events are unchanged. Keep `--fail` semantics as they are now: on a non-2xx status the shim prints nothing.
- OpenCode (`internal/harness/opencode/hooks/server.go`) ignores `Reply`.
- `appwire.wireTracker` sets `Reply: tracker.HookReply`.

### Board glue (`apps/kira-space/internal/ade/leases.go`, new)

- `TaskBoardDeps.LeaseQueues` takes a repo interface `{List; Save}`. `NewTaskBoard` builds a `leases.Book` with:
  - `order` = `b.taskListOrder` (see "Task list order in Go, pinned to TS");
  - `onGrant` = `b.onLeaseGrant`;
  - `onChange` = `deps.OnLeases`, emitting `kira:ade:leases`.
- The sweep runs every 30 s in `TaskBoard.Start`, stops with the board, and calls `Book.Sweep(b.tracker.Busy)`.
- Notices, `pending map[leases.Key][]string` under the board's lease mutex:
  - `onLeaseGrant(g)` builds a message:
    - grant: "Kira: you now hold lease `<q>`. Continue the work that waited for it. Call release_lease when done."
    - revoked: "Kira: the user revoked your lease `<q>`. Stop using the resource; call acquire_lease to queue again."
  - It then calls `deliver(key, msg)`.
  - `RequestRelease` calls `deliver(holder, "Kira: the user asks you to release lease `<q>`: finish the current step, then call release_lease.")`.
  - `deliver`:
    - Run-keyed or no live terminal: leave the message pending. Headless reads it on its next lease tool call, and every lease tool result appends and clears pending notices.
    - `tracker.SendIfIdle(key, msg)` true: done.
    - Otherwise append to `pending`.
  - `hookReply(recordID, ev)`:
    - Stop: join pending messages into `Block` and clear them.
    - UserPromptSubmit: put them into `Context` and clear them.
    - Deliver once.
  - `onIdle(recordID)`: if pending is still set (OpenCode path), `SendIfIdle` it and clear on success.
- Session end:
  - `OnTUIStopped(recordID)` adds `b.leases.ReleaseSession(Key(recordID))` and drops `pending`.
  - The headless run release func does the same with its run's key. Join it beside the grant release in runs.go (codegraph `joinRelease`, the run end path).
- Heartbeat: in `NewTaskBoard`'s `OnToolCall` wrapper (`mcpRecorder`, opsrecord.go) call `b.leases.Touch(keyOf(call))`. `ToolCall` gains `SessionID` (optools.go: `SessionID: g.SessionID`). Hook events from the holder also count: `HandleEvent`'s path calls a `Touch` through the idle and event handler. Simplest is a `SetEventHandler`, or reuse the idle handler call site in `trackStatusLocked` firing `onActivity(recordID)`.
- `keyOf` is used by every lease tool and by the heartbeat: `SessionID`, else `"run:"+RunID`.
- `LeaseQueues()`, `SaveLeaseQueues(names)`, `LeaseSnapshot() adewire.LeaseSnapshot`, `RequestLeaseRelease(q)` and `ForceLeaseRelease(q)` serve the bridge. `SaveLeaseQueues` writes the repo, then `Book.SetQueues`. `Recover`/`Start` load names from the repo into the Book.

### Flow test `apps/kira-space/internal/flows/adeflow/leases_test.go` (`TestLeases`, contract `ade-leases`)

Setup:

- `flowharness.New(t, WithTrackerGrace(time.Second))`.
- Three tasks: A dated today with est `1d`, B dated yesterday with est `3d` (span ends after A's), C on Later. Task list order is A, B, C, so a span decides A over B: plain plan-day order would put B first. Assert `TaskListOrder` gives A, B, C before acquiring.
- Save queue `push`.
- Three TUI sessions with the fake agent. Each `Action` has an `MCP` call `acquire_lease {queue:"push"}`. Follow `sessionstatus_test.go` (`claude(app, ...)`, `WaitFile` flags).

Steps and assertions:

1. Queue: C acquires first and gets held. B, then A, get queued.
   - The snapshot lists waiters A, B: task list order beats arrival.
   - The `mcp-acquire_lease-*.json` results show `held` and `queued` with positions.
   - Contract `LeasesService.Snapshot#queued`.
2. Re-call: B's second acquire returns the same position.
3. Grant with idle injection:
   - Send A a Stop through `hook()` so it is idle.
   - C calls `release_lease`. A is granted and A's `.prompt` file contains the grant message (`pfPrompts`-style read).
   - Contract `#granted`.
4. Hook fallback:
   - B is busy (UserPromptSubmit hook sent).
   - `ForceRelease("push")` from `app.W.Leases` revokes A and grants B.
   - `hook()` for B's Stop returns stdout with `"decision":"block"` and the grant text. A second Stop returns empty.
