## Part B: opening a GitHub PR in the app

### Root cause (reproduced)

The in-app PR view (`HostViewService.Open` -> host view window -> `HostViewService.ChangeRequest`
-> `github.Provider.ChangeRequestDetail`) sends `detailQuery`
(`apps/kira-space/internal/githost/github/detail.go:20`). That query is invalid GraphQL, so GitHub
rejects the whole request with `errors[]` and no `data`. `Client.graphqlWithin`
(`graphql.go:72-80`) turns that into `KindForbidden` with the first message, and
`ChangeRequestView.vue` shows it as the failure reason. The PR never loads. `useOpenChangeRequest`
does not fall back to the browser because `Open` itself succeeded.

Validated offline against GitHub's published schema (`https://docs.github.com/public/fpt/schema.docs.graphql`)
with both graphql-js and `github.com/vektah/gqlparser/v2`. Four errors:

- `Fields "comments" conflict because they have differing arguments`: `syncPRFields` selects
  `comments{totalCount}`, `detailQuery` adds `comments(last:100){…}`.
- Same for `reviews` (`reviews{totalCount}` vs `reviews(last:50)`).
- Same for `assignees` (`assignees(first:10)` vs `assignees(first:50)`).
- `Fields "name" conflict because they return conflicting types "String" and "String!"`:
  `requestedReviewer{… on User{login name} … on Team{slug name} …}` (`User.name: String`,
  `Team.name: String!`).

`syncPageQuery`, `syncChecksQuery` and `replyThreadMutation` validate clean (sync works, which is
why PR badges show while the view fails). With the four aliases below the query validates with 0
errors (checked).

Why tests missed it: `TestChangeRequestDetail` (unit, fake runner) and flow `TestHostViewGitHub`
feed a hand-written `testdata/pr_detail.json` for any command matching `latestOpinionatedReviews`;
nothing checks the query text. P594 fixed link parsing only, so the view still failed against real
GitHub. Live repro with `gh` is impossible in this sandbox (proxy blocks GitHub GraphQL); the schema
check is the reproduction.

Out of scope (unchanged, already recorded by P594): GHES PR links classify as plain links
(`Provider.ParseLink` hardcodes `github.com`).

     above the const: aliases avoid field-merge conflicts with `syncPRFields`.
