## Background (facts the implementer needs)

- Each task branch row reserves own folder `<home>/kira-space-wts/<repo>/<wt_id>`
  (`BE/ade/worktreedir.go` `ownWorktreePath`). `resolveAttachment` reads which branch git says
  holds what.
- Agent running `git switch Y` inside own folder: row's branch X no longer checked out anywhere.
  `fillAttach` (`BE/ade/board_facts.go:475`) then sets `Branch.Worktree = ""` and
  `Branch.Detached = {Worktree: own, Holder}`. Nothing says the folder now holds Y. Agent's
  `branch_info` tells it "No worktree. Call request_branches…", a wrong hint.
- `porcelain.InventoryRef.WorktreePath` (`%(worktreepath)` of for-each-ref) already in `sc.inv`.
  That is the source for "what does own folder hold".
- `SetTaskBranch` (`BE/ade/taskbranches.go`, UI change-branch) replaces row id and removes old
  worktree via `detachRow`. Unusable for a running agent: deletes its cwd, unbinds its sessions.
  New MCP tool therefore keeps row id and folder.
- Approval-gated tool pattern: `BE/ade/branchrename.go` (`RenameBranch`, `planRename`,
  `renameRefusal`, `applyRename`) plus `awaitBranchRequest` (`BE/ade/branchrequest.go`). Approval
  dialog renders `BranchRequestItem`s through `FE/request/BranchRequestBody.vue`. Reuse unchanged
  except one new item kind tag.

## Section C: MCP `change_branch` tool

Semantics: re-point the task row `from` to existing local branch `to`, switching the row's own
folder when needed. Row id, folder, sessions stay. No new branch, no remote DWIM
(`SwitchWorktree` uses `git switch --no-guess`); new branches stay on `request_branches`.

Backend, `BE/ade/branchchange.go` (new), shaped after `branchrename.go`:

1. `func (b *Board) ChangeBranch(ctx, call agentmcp.SpaceCall, args agentmcp.ChangeBranchArgs)
   (agentmcp.ChangeBranchResult, error)`.
2. `planChange` under task lock:
   - resolve row via `taskRepoRows` / `renameTarget`-style lookup on `args.Repo` + `args.From`;
   - refusals (text result, no prompt, `Outcome: "refused"` matching rename's refusal style):
     row not on task or not `mine`; `to` reserved (`reservedExistingText`); `to` not a local branch
     in `sc.inv`; `to` on another live task row; row has no own folder; `to` checked out in a folder
     other than own (`classifyHolder`); switch needed and folder dirty or mid-operation
     (`holderBlock`); setup, rebase or sandbox bound to row (extract shared
     `rowBusyRefusal(...)` from `renameRefusal`, call from both);
   - draft request via `requestDraftOf` with one `BranchRequestItem{Kind: "switch", Branch: to,
     From: from}`.
3. `awaitBranchRequest`; decision switch copied from `RenameBranch`: abandoned, timeout, denied or
   `!dec.approved[itemID]`.
4. `applyChange` re-checks every refusal under task lock and repo mutex, then:
   - `SwitchWorktree(ctx, own, to)` unless `headIn(...) == to`;
   - `snapshotChangeRequests` for old name (same as rename);
   - store `ChangeBranch`;
   - `notifyBoard`.
   On store error after switch: switch folder back to `from` if it held `from` before, return
   `failed` with error text.
5. `BE/ade/branchrequest.go`: add kind const `branchItemSwitch = "switch"`; `planItem` and
   `createApproved` ignore it (handled by `ChangeBranch` only, like rename).
6. `BE/storage/repos/adetask.go`: `ChangeBranch(ctx, id, from, to string) error`, beside
   `RenameBranch` (line ~1236): update `name = to`, `merged_at = NULL`, `had_commits = 0` where id
   and name match; unique violation returns `ErrBranchNameTaken`; zero rows returns
   `ErrBranchMissing`. Rows using it as `BaseBranchID` keep the id link, no repoint needed (unlike
   rename, which repoints name-based stacking: confirm in `RenameBranch` body and mirror any
   name-based repoint).
7. `internal/agentmcp/space.go`:
   - `ChangeBranchArgs{Repo, From, To string}`, `ChangeBranchResult{Repo, From, To, Outcome,
     Worktree, Next string}`; outcome const `BranchChanged = "changed"`, reuse denied, failed,
