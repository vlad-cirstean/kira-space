# P552 plan: tighten SQLite types and constraints, reorganise schema

Spec row: `docs/v0.3.1/SPEC.md` P552. Base: `chapter/v0.3.1` at `625a4c982`. Runs in batch with P551 and P554 (`plans/PARALLEL.md`); P553 starts after this lands.

## 0. Facts found (measured, not assumed)

- Driver: `modernc.org/sqlite v1.61.1`. `SELECT sqlite_version()` on a fresh `storage.OpenAt` DB returns **3.54.1**. STRICT needs 3.37, `unixepoch(x,'subsec')` 3.42, `ALTER TABLE DROP COLUMN` 3.35. All available.
- `PRAGMA foreign_keys` reads 1 (DSN `_foreign_keys=1`, `internal/sqlitex.BuildDSN`; modernc parses `_foreign_keys`).
- Fresh schema after migration 0082: 67 tables including `schema_version`, 52 explicit indexes. Zero STRICT tables. Snapshot taken by opening `storage.OpenAt(t.TempDir())` and dumping `sqlite_master`.
- Runner: `sqlitex.Migrate` runs every step inside one `db.Begin()` transaction. `PRAGMA foreign_keys` is a no-op inside a transaction. With FKs on, `DROP TABLE parent` runs an implicit `DELETE` that fires `ON DELETE CASCADE` on every child. 0078's header already flags this. Any parent rebuild today would wipe child rows. Precedent workaround: `internal/memory/migrations/0005_p274_ingest.sql` copies children to TEMP tables first. That does not scale to 67 tables; this plan changes the runner instead (section 4.1).
- Schema is not static after migrations. Two runtime exporters drop legacy shape once their config files exist:
  - `connfiles.DropLegacy`: drops `connections.password`, `connections.uri`, tables `connection_tree_filters`, `connection_ddl`. Marker: settings key `config.migrated.connections`.
  - `repocfg.dropLegacy`: drops `git_repo_settings`, `ade_repo_integration`, `ade_repo_envs`, column `ade_repo_config.nickname`. Marker: `configfs.MigrateOnce` key `config.migrated.repos` (confirm `repocfg.Folder` value).
  - Both run after `storage.Open`. A P552 migration can meet either shape. Static SQL cannot reference a column that may be gone.
- Boot order: `storage.Open` (migrations) then `configfold`, `homefold.Files`, `dbfold.Run`. `dbfold.importRows` copies Studio rows into the already-migrated schema by column-name intersection with `INSERT OR IGNORE`. `homefold.Runs` does the same for script tables. Both must survive STRICT, renames and TEXT-to-INTEGER timestamps.
- Out-of-process writer: `kira-space memory-mcp` writes `op_log` in `kira.db` (`appwire/memoryops.go`). An older running copy can outlive an app upgrade. `op_log` column names stay unchanged for that reason.
- `internal/secrets` store code serves both `kira.db` `secret_values` and `agent-secrets.db`. `secret_values` column names stay unchanged.
- Convention N7 (`scripts/check-conventions.ts` `migrationHits`) rejects `*_at TEXT` in any new migration. Every rebuilt table with a TEXT instant must convert it to INTEGER ms.
- TEXT instants are written by `kiratime.NowISO()`: fixed-width `2006-01-02T15:04:05.000Z`. `CAST(unixepoch(x,'subsec')*1000 AS INTEGER)` converts losslessly (0080 precedent). `kiratime.FormatISO(time.UnixMilli(ms))` converts back byte-identically. Precedent for converting at the repo boundary: `repos/oplog.go`, `internal/scripts/repo.go`.
- No triggers or views in `kira.db`.
- Rowid is load-bearing: `filter_history`, `metadata_cache`, `api_response_history`, `grpc_call_history`, `ade_db_audit` order by `rowid` as tiebreak; `apifiles` legacy read orders `api_variables` by rowid; `oplog.WatchForeign` cursors `op_log` by rowid.

## 1. Conventions every rebuilt table follows

- C1 `STRICT`. Types only `INTEGER`, `REAL`, `TEXT`, `BLOB`.
- C2 Instants: INTEGER unix ms, `CHECK (x >= 0)`. Name `*_at`. Existing `*_ms` instant names (`op_log.started_ms`, `ade_db_audit.started_ms/ended_ms`, `secret_values.updated_ms`) stay: external-writer and shared-store contracts. No new `*_ms` instant. Unit audit: implementer greps each `*_at INTEGER` writer; any seconds-based writer (none found by `\.Unix()` grep in storage, ade, scripts, scriptruns) converts ×1000 in the migration and in its writer.
- C3 Booleans: `INTEGER NOT NULL DEFAULT 0|1 CHECK (x IN (0,1))`.
- C4 JSON TEXT: `CHECK (json_valid(x))`; with `''` sentinel `CHECK (x = '' OR json_valid(x))`; nullable `CHECK (x IS NULL OR json_valid(x))`. Skipped on bulk payloads (write cost of parsing MB-size text on every insert): `api_response_history.snapshot_json`, `api_grpc_history.snapshot_json`, `connection_metadata_cache.payload_json`.
- C5 Counts, bytes, positions, `sort_order`, `attempt`: `CHECK (x >= 0)` (`attempt >= 1` kept).
- C6 TEXT primary keys: `CHECK (id <> '')`.
- C7 Every FK states `ON DELETE`. Every FK child column set is the leftmost prefix of a non-partial index (a partial index cannot serve the cascade lookup).
- C8 Enum `CHECK` only on state the app owns and validates on write. No enum `CHECK` on open sets (adapter kinds, window modes, tab kinds read with drop-on-read tolerance), external data (GitHub states, docker, kube), or history/log rows (folded legacy values exist).
- C9 Column order: narrow hot columns first, wide TEXT/JSON/BLOB last (overflow pages; P4 D2 precedent).
- C10 Copy preserves `rowid` for every rowid table (`INSERT INTO t__new (rowid, ...) SELECT rowid, ...`).
- C11 Soft references with `''` sentinel stay soft (no FK) when they point at history that must outlive its parent, at ids outside `kira.db` (agent session ids), or at rows deleted by retention. Listed per table. Converting `''` to NULL would change every scan and wire field for no integrity gain on history rows.
- `schema_version` stays as `sqlitex` creates it (shared runner across four databases; one row).

## 4. Migration strategy

### 4.1 Runner change (`internal/sqlitex`)

- `Migration` gains `ForeignKeysOff bool` and `Func func(*sql.Tx) error`. Both default zero: agentcfg, memory and gitreview migrations behave as today.
- `LoadMigrations` sets `ForeignKeysOff` when the file's first line is exactly `-- kira:foreign-keys off`. The property travels with the SQL file.
- `Migrate` for a `ForeignKeysOff` step: pin one `*sql.Conn`; `PRAGMA foreign_keys = OFF`; `BEGIN`; exec SQL; run `Func` if set; `PRAGMA foreign_key_check`; any row aborts with `ROLLBACK` and an error naming table, rowid and parent; record version; `COMMIT`; `PRAGMA foreign_keys = ON` in a `defer` (runs on every path). The pool has one connection (`SetMaxOpenConns(1)`), but pinning makes the pragma scope explicit.
- Rebuild order per table inside a step follows SQLite's documented 12-step procedure: `CREATE TABLE t__new ... STRICT`, quarantine and copy, `DROP TABLE t`, `ALTER TABLE t__new RENAME TO t`, recreate indexes. Renamed tables create the final name directly and drop the old one.
- Go `Func` exists for exactly two rebuilds whose source shape varies at runtime: `connections` and `ade_repo_config` (legacy carry columns, section 0). It reads `pragma_table_info` and the settings marker, then builds the column list. The DDL text stays in Go constants beside it, one place. Everything else is static SQL in `.sql` files (P553 keeps migrations as SQL).
- Why not a library: golang-migrate and goose are runners (this repo has one). Atlas declarative apply gates parts behind its Pro tier and does no row-level repair or quarantine. The requirement no library meets: data-preserving rebuild with per-column repair and quarantine inside the existing `schema_version` runner.

### 4.3 Backup

- `storage.OpenAt` opens with `sqlitex.Open`, reads `schema_version`. ## 5. Violating rows

Never fail startup on row data. Fail only on a structural error, with a message naming table and rowid; the backup exists.

- Repair, no information lost: boolean column holding non-0/1 integer becomes `x <> 0`; numeric TEXT in an INTEGER column becomes `CAST`; ISO TEXT instant becomes INTEGER ms.
- Repair and record (`action = 'repaired'`, original row as `json_object(...)`): invalid JSON in a column with a documented default (`'[]'`, `'{}'`, `''`) takes the default; unparsable TEXT instant in a nullable column becomes NULL; out-of-range count becomes 0.
- Remove and record (`action = 'removed'`): enum value outside the new CHECK set; orphan child under a new FK (`ade_sessions`, `ade_tracked_items`, `script_run_logs`, deferred status FKs: a task or default naming a missing status is repaired to the `new` default slot's status instead, recorded `repaired`); NULL in a new NOT NULL column with no default; unparsable instant in a NOT NULL column.
- Mechanics in SQL: `INSERT INTO schema_quarantine (...) SELECT 't', json_object(<all cols>), '<reason>', '<action>', <version>, <now ms> FROM t WHERE NOT (<predicate>)` before the copy; the copy uses repair expressions and `WHERE <keep predicate>`. One predicate per rule, written once per table.
- `dbfold` import (Studio rows after P552): `copyModuleTables` gains a per-destination-column expression map (instants `CAST(unixepoch(c,'subsec')*1000 AS INTEGER)`, booleans `c <> 0`) and a source-to-destination table and column rename map (`moduleTable{src,dst}` already exists; `copyTabs` writes `sort_order`). After each table it compares source count to rows inserted and warns with the gap, as it already does for `proof_task_links`. `homefold.Runs` gets the same rename map for `custom_scripts`/`custom_script_collections` and the same instant transform where the Studio source column is TEXT (legacy `0024` `custom_scripts.created_at TEXT`).
