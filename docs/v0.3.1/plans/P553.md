## 1. Library decision

Requirements:

- R1 pure Go, no cgo (modernc). R2 runtime dialect choice: one repo implementation serves a later Postgres backend. R3 upsert, `RETURNING`, placeholders, quoting per dialect. R4 sustained maintenance record. R5 fully open source, package-level license. R6 builds SQL only; repos keep `database/sql` scanning (boundary conversions from P552 stay where they are). R7 no ORM owning schema or migrations.

Candidates, checked at package level (`go mod download`, LICENSE, go.mod, release history on proxy.golang.org):

- **`github.com/huandu/go-sqlbuilder` v1.44.1 (MIT). Chosen.** Runtime flavors `sqlbuilder.SQLite` and `sqlbuilder.PostgreSQL` (`?` vs `$n`, double-quote `Flavor.Quote`). `Returning` on insert, update, delete for both flavors. `InsertIgnoreInto` per flavor (SQLite `INSERT OR IGNORE`, Postgres `ON CONFLICT DO NOTHING`). `Cond.In` with zero values renders `0 = 1`. `IsNotDistinctFrom` portable. CTE, joins, `Struct` mapper (unused). Deps: `huandu/go-clone` (MIT), `huandu/xstrings` (MIT), no driver imports. Releases roughly monthly through 2026 (v1.40.1 2026-04 to v1.44.1 2026-10-23). Gap: no `ON CONFLICT ... DO UPDATE` clause; filled by one helper over `InsertBuilder.SQL` (section 2.2), whose text is identical in SQLite and Postgres.
- `github.com/go-jet/jet/v2` v2.16.1 (Apache-2.0, steady releases). Type-safe, generator works on modernc via `generator/sqlite.GenerateDB`. Ruled out by R2: statements come from dialect packages (`jet/v2/sqlite`, `jet/v2/postgres`); generated table types import one of them and type columns per dialect (INTEGER bool vs `boolean`). A Postgres backend means a second repo copy or build-tag swaps plus edits at every bool and JSON expression.
- `github.com/stephenafamo/bob` v0.50.0 (MIT). Ruled out by R2 (per-dialect `dialect/sqlite`, `dialect/psql` packages) and R4 (pre-1.0, breaking changes across minors). `bobgen-sqlite` imports `mattn/go-sqlite3` (cgo) beside modernc.
- `github.com/doug-martin/goqu/v9` v9.25.0 (MIT). Meets R1-R3 well (runtime dialects, `OnConflict(DoUpdate)`). Ruled out by R4: v9.19.0 (2023-11) then v9.20.0 to v9.25.0 all inside 2026-11-03..05. Three years dormant, then six releases in 72 hours, newest one day old. No sustained record to adopt across 475 call sites.
- `github.com/Masterminds/squirrel` v1.5.4 (MIT, 2023-03, declared feature-complete). Ruled out by R4; no dialect upsert.
- `github.com/sqlc-dev/sqlc` v1.31.1 (MIT). Not a builder: generates code from static per-engine SQL files. Ruled out by R2 (Postgres duplicates every query file) and dynamic filters (IN lists, optional clauses).
- `entgo.io/ent` v0.14.6 (Apache-2.0). Ruled out by R7: schema-as-code with Atlas migrations; P552's SQL schema and SQL migrations stay the source.

Pin exactly `github.com/huandu/go-sqlbuilder v1.44.1` in `go.mod`. Never call `Interpolate` / `Flavor.Interpolate` (values always bind as args).

## 2. Design

### 2.1 Generated schema identifiers and drift check

- Package `internal/kiraschema` (root `internal/`, so root packages can import it). One generated file `kiraschema_gen.go`, header `// Code generated by TestKiraSchemaGenerated; DO NOT EDIT.` (golangci-lint skips it).
- Per table one exported var, table name to CamelCase (`op_log` to `OpLog`), with `Table string` and one `string` field per column in table order, Go initialisms applied (`id` to `ID`, `steps_json` to `StepsJSON`, `repo_id` to `RepoID`, `mcp_*` to `MCP*`). Values are the bare SQL names. Example: `kiraschema.OpLog.Table == "op_log"`, `kiraschema.OpLog.StartedMs == "started_ms"`.
- No row structs. Repos keep domain types and explicit scans: every scan converts (ms to ISO, 0/1 to bool, JSON decode, drop-on-read), so a generated row struct would add a mapping layer without removing one.
- Source: a fresh `storage.OpenAt(t.TempDir())`, `sqlite_master` tables in name order, `pragma_table_xinfo` columns. Skip `schema_version`, `schema_quarantine` (migration-only) and `sqlite_*`. Legacy carry tables and columns do not exist on a fresh DB (P552), so they never get identifiers; their readers are fold code (section 3.2).
- Generator and drift test: `apps/kira-space/internal/storage/kiraschema_test.go` (package `storage_test`, beside `schema_test.go`, reuses `openFresh` and the `-update` flag). `TestKiraSchemaGenerated` renders with `text/template` + `go/format` and compares to `internal/kiraschema/kiraschema_gen.go`; `-update` rewrites it. Fails with "run go test ./apps/kira-space/internal/storage -run TestKiraSchemaGenerated -update".
- `internal/kiraschema/doc.go` holds `//go:generate go test ../../apps/kira-space/internal/storage -run 'TestKiraSchema|TestSchemaSnapshot' -update`.
- CI drift check: the test runs in the existing Go CI job (`go test ./...`). No workflow edit. A schema change without regeneration fails the test; a column removed from the schema and regenerated breaks the build at every repo using it. Keyword column names: P552 removed them (`sort_order`, `trigger_`); identifiers emit bare.

### 2.2 `internal/sqlb`

Thin layer over go-sqlbuilder. Holds dialect choice, run helpers and every dialect-variant fragment. Builds no SQL syntax itself except the upsert tail and the offset-only form.

- `type Dialect struct{ flavor sqlbuilder.Flavor }`; zero value is SQLite. `sqlb.SQLite` exported. Methods `Select(cols ...string)`, `InsertInto(table)`, `InsertIgnoreInto(table)`, `Update(table)`, `DeleteFrom(table)`, `With(...)` return go-sqlbuilder builders created from the flavor. Postgres stays unregistered (out of scope); adding it is one exported value.
- `sqlb.Querier` (`Exec`, `Query`, `QueryRow`, satisfied by `*sql.DB` and `*sql.Tx`). `sqlb.Exec(q, b)`, `sqlb.Query(q, b)`, `sqlb.QueryRow(q, b)` call `b.Build()` then the driver. Builders whose clause list ends up empty (e.g. `Set()` with no assignment) return an error, never run.
- `sqlb.Upsert(ib, conflictCols []string, updateCols []string, where string)` appends `ON CONFLICT (c...) DO UPDATE SET x = excluded.x ... [WHERE ...]` via `ib.SQL`, before `Returning`. Also `UpsertSet` for assignments that are not plain `excluded.x` (`repeat_count`, `rounds + 1`). Same text in SQLite and Postgres.
- `sqlite.go` holds every SQLite-only fragment, each with its Postgres counterpart in a comment:
  - `RowID` (`"rowid"`). Postgres needs a real ordering column (P552 section 9).
  - `OffsetOnly(sb, n)`: SQLite renders `LIMIT -1 OFFSET ?`; Postgres `OFFSET $n`. go-sqlbuilder drops `OFFSET` without `LIMIT` on SQLite: a bare `Offset(n)` in a prune subquery would select every row and delete the whole category. Every offset-only site (`oplog.go` x2, `proof.go`) uses this helper.
  - `instr(id, '.') = 0` becomes portable `id NOT LIKE '%.%'` (same truth table; `.` is not a LIKE wildcard). No helper needed.
  - `IS ?` null-safe compare becomes `Cond.IsNotDistinctFrom` (SQLite 3.39+).
- Sort-order and keyed-replace helpers move here on the builder: `NextSortOrder(q, d, table string, where ...string)`, `ReindexSortOrder`, `ReorderSortOrder`, `ReplaceKeyed`, `UpsertLeafList`, `UpdateLeaves`, `QueryLeaves`. Same semantics as the `sqlitex`/`appstorage` versions. The old versions are deleted in stage 3, once no caller remains.
- Binding rules (STRICT, P552): bind Go `bool` (driver stores 0/1; Postgres gets `boolean`); scan bool columns into `bool` in converted code (`database/sql` converts 0/1). Bind JSON as `string`, never `[]byte`/`json.RawMessage` (modernc binds `[]byte` as BLOB; STRICT TEXT rejects). Instants stay `int64` ms; never `time.Time`.

### 2.3 Repo interface boundary

- Boundary stays the concrete repo types built by `repos.New(db)`; consumers keep their own narrow interfaces. No new interface layer: a Postgres backend reuses the same repo code with another `sqlb.Dialect`, so no second implementation needs one.
- Each repo struct in scope (all `storage/repos` types, `scripts.Repo`, `scriptruns.Repo`, `secrets` store, `configfs.TableProjection`, `connfiles`/`apifiles` stores) gets field `Dialect sqlb.Dialect`. Zero value is SQLite, so every existing `&repos.X{DB: db}` construction (tests, `flowharness`, `appwire`) keeps working unchanged. `repos.New` signature unchanged.
- Statements build per call with the repo's dialect. Exception: the 3 prepared statements in `repos.New` build once there. Section 6 decides whether any other hot statement moves to build-once.
- Column lists: existing `const xColumns = "a, b, ..."` become `[]string{t.A, t.B, ...}` in the same order, so every `Scan` stays as is.

### 2.4 Raw SQL that stays, isolated

- Migrations `storage/migrations/*.sql` and the runner `internal/sqlitex` (SQLite runner; a Postgres runner is a sibling later).
- `storage/db.go`: open, backup (`VACUUM INTO`), `schema_version`, quarantine count.
- `repos/maintenance.go` (`PRAGMA auto_vacuum`, `freelist_count`, `page_size`, `incremental_vacuum`) and the `PRAGMA data_version` read in `repos/oplogforeign.go`: SQLite maintenance with no Postgres analogue.
- One-shot fold and legacy-export code: `dbfold`, `homefold`, `configfold`, `repocfg/migrate.go`, `connfiles/migrate.go`, `apifiles/migrate.go`, `configfs/migrate.go`. They introspect pre-P552 or Studio shapes (`pragma_table_info`, column intersection), run once per install, and have no Postgres counterpart (a Postgres install never folds a legacy SQLite file).
- Separate databases (not `kira.db`'s app schema): `internal/memory`, `internal/agentcfg`, `gitreview` `review.db`, DB adapters. Out of scope. `internal/secrets` store converts: same code serves `kira.db` and `agent-secrets.db`, both SQLite, same table shape.

## 9. Postgres readiness (design only, nothing built)

- Dialect: `sqlb.Dialect` wraps the flavor; add `sqlb.Postgres` and pass it to repos. Placeholders, quoting, `RETURNING`, insert-ignore, null-safe compare, empty IN come from go-sqlbuilder per flavor.
- Upsert: `sqlb.Upsert` text is valid in both.
- Types: INTEGER ms to `BIGINT`; 0/1 to `boolean` (repos bind and scan Go `bool`); JSON TEXT to `jsonb` (bind string); BLOB to `bytea`.
- Still SQLite-only, all named in `internal/sqlb/sqlite.go` or section 2.4: `rowid` ordering (needs a real column), `LIMIT -1`, pragmas, `VACUUM INTO`, `WITHOUT ROWID`, VIRTUAL generated `scope_key` (Postgres `STORED`), `COLLATE NOCASE`, expression index on `lower(...)`, FK-off rebuild runner.
- Concurrency: today's correctness leans on one connection and `_txlock=immediate` (read-modify-write such as `NextSortOrder` then insert, "no query meanwhile" in transactions). A Postgres pool needs row locks (`SELECT ... FOR UPDATE`, go-sqlbuilder `ForUpdate`) or serializable transactions at those sites.
- Migrations: a per-dialect migration set and runner; `internal/sqlitex` stays SQLite's.
- Full text: none used.
