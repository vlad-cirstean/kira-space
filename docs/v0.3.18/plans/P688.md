## Decision

Join policy (ARCHITECTURE copy section, W2):

1. Fragment joins are one message. A unit, a label prefix, a parenthetical, an arrow, a separator
   between a fixed pair, or punctuation added between parts goes into the catalog: an existing pair
   message (`common.dotPair`, `common.withDetail`, `common.commaPair`, `common.dashPair`) or a site
   message with placeholders.
2. Whole sentences join through `joinSentences(...parts)` from `@theme/i18n`. Each part is a
   complete sentence (catalog message or backend error text) with its own end punctuation. Reason
   for a helper over `.join(' ')`: the sentence separator is locale-dependent (no space in CJK), so
   it needs one owner, not 25 call sites.
3. A variable-length list of self-contained facts joins with `' · '`; lines join with `'\n'`
   (tooltips, copied text). Both glyphs are locale-neutral.
4. Whitespace-only padding around one `t(` call (`` `  ${t(k)}` ``, `` `${t(k)} ` ``,
   `` `\n${t(k)}` ``) is layout, allowed.
5. UI-visible English never sits outside the catalog, packages included: tables hold message keys,
   `t(` runs at call time (`packages/shared` and `packages/api-core` already import `t`:
   `shared/domain/connection.ts`, `api-core/src/http/url.ts:134`).

Library: vue-i18n named placeholders (the existing runtime) carry every fragment join; no new
dependency. `joinSentences` is a 3-line filter-and-join, not infrastructure. `Intl.ListFormat`
declined: it builds "a, b and c" lists, not sentence sequences or " · " fact lines.

Guard (W2): extend U69 (same rule, composed translations) and add U208 (prose literal outside the
catalog). Details under Guard.
