# P675: JS engine for the API MCP

Planner: Opus. Implementer: one sequential Sonnet subagent. No streams: one new package, one
`go.mod` change, order-dependent.

Spec row: embedded JavaScript engine in Go for the API MCP (P676 to P679) and DB MCP (P680), never
UI-facing. Hard CPU limit and interrupt, memory ceiling, output cap, no filesystem, network,
process, timers or `require`, deterministic globals, big-integer handling documented, structured
errors with line and column, one package with a narrow interface. Not in scope: jq or gojq.

## Discovery (codegraph)

- No JS engine or script sandbox exists. `internal/scripts` and `internal/scriptruns` run shell
  processes; `internal/agentsandbox` renders a macOS Seatbelt profile for agent CLIs. Nothing to
  reuse or replace.
- `go.mod` has no JS engine. `modernc.org/sqlite` v1.61.1 already links `modernc.org/libc` v1.79.1,
  `modernc.org/memory`, `mathutil`, `go-humanize`, `google/uuid`, `bigfft`.
- `dbmcp/api_tools.go`: `apiRequest` plans, approves (`approveAPI`), then `Send` returns a masked,
  capped `agentapi.Result` as JSON. P676 inserts the engine between `Send` and `jsonResult`; P675
  touches neither.
- Approval-binding precedent: `scriptruns.PlanMCP` returns `Preview.Hash`; `StartMCP` refuses a
  changed script (`checkStart`). The engine's source hash follows that shape.
- `dbmcp/browse.go` and `oplog/redact.go` decode JSON with `UseNumber`: the repo already treats
  numbers as exact text where it matters. `internal/jsonx` keeps object key order.
- Packaging (`docs/PACKAGING.md`): macOS arm64 only, built with `CGO_ENABLED=1` (Wails). Dev and
  CI run linux/amd64. `docs/DEV_ENVIRONMENT.md`: `GOOS=darwin` cross-builds here only with
  `CGO_ENABLED=0`, so a cgo engine could not be built or vetted for the shipped target here.

## Package

`apps/kira-space/internal/jsengine` (every consumer, `dbmcp` and `agentapi`, lives under
`apps/kira-space/internal`). No app imports beyond stdlib and `modernc.org/quickjs`; never imports
`bridge`, `dbmcp`, `agentapi`, `secrets`. P675 ships the package and its tests only; P676 wires the
first caller. An exported package without a production caller is by design for this phase.

Files:

- `engine.go`: `Engine`, `New`, `Exec`, run goroutine, deadline and cancel handling.
- `limits.go`: `Limits`, defaults, ceilings, `normalize`.
- `source.go`: `SourceHash`, `Check`, source validation, wrapper.
- `json.go`: big-integer marker rewrite (Go side, token stream), output marker restore, depth cap.
- `bindings.go`: `Binding`, `HostFunc`, name rules, host-call trampoline with panic recovery.
- `errors.go`: `Error`, `Kind`, mapping from `*quickjs.Error`, frame parse and scrub.
- `prelude.js` (`//go:embed`): hardening, clock, PRNG, JSON helpers, freeze. All prelude function
  names start `__kira_` so frame scrubbing can drop them.

### Interface

```go
// Engine runs scripts. Safe for concurrent use; each Exec gets a fresh VM.
type Engine struct{ /* sem chan struct{} */ }

func New() *Engine // MaxConcurrent slots

type Run struct {
	Source   string
	Bindings []Binding
	Limits   Limits    // zero fields take defaults
	Now      time.Time // Date.now() and new Date() for the whole run; zero = time.Now() at Exec start
	Seed     uint64    // Math.random seed; 0 = derived from SourceHash
}

type Binding struct {
	Name  string              // global identifier the script reads
	Value json.RawMessage     // eager JSON value; or
	Funcs map[string]HostFunc // an object of host methods (Value nil)
}

// HostFunc gets the JS call's arguments as one JSON array (lossless big integers) and returns one
// JSON value. A returned error throws Error(err.Error()) in the script; a panic is recovered.
type HostFunc func(ctx context.Context, args json.RawMessage) (json.RawMessage, error)

type Result struct {
	JSON    json.RawMessage // compact, key order kept, big integers exact; "null" for undefined
	Type    string          // undefined | null | boolean | number | bigint | string | array | object
	Elapsed time.Duration
}

func (e *Engine) Exec(ctx context.Context, r Run) (Result, error) // error is *Error, or an internal fault
func SourceHash(source string) string                             // hex sha256 of the exact bytes
func Check(source string) *Error                                  // validation + compile only, never runs
```

Nothing else exported except `Kind` constants, `Error`, `Frame`, `Limits` and the limit constants.
P676 to P680 extend through `Bindings` and `Limits`, never new engine entry points, unless a later
plan proves the need.

### Script shape

- Source is a function body. Engine evaluates `(function () {"use strict";\n` + source + `\n})`
  and calls it with `this` undefined. The script ends with `return <value>`. Lines report as
  line − 1; columns unchanged (the prefix sits on its own line). `Check` uses the same wrapper, so a
  syntax error reads the same in `Check` and `Exec`.
- Breaking out of the wrapper (`}); ...; (function(){`) only runs more code in the same sandbox;
  accepted. A test pins that it gains nothing.
- Bindings are read-only globals (`Object.defineProperty(globalThis, name, {value, writable:
  false, configurable: false, enumerable: false})`). Name rule `^[a-z][A-Za-z0-9_]{0,31}$`, not a
  reserved word, not an existing global, not `kira`, unique per run. Binding values are not frozen
  (per-run, mutation harmless).
- Built-in helper object `kira` (frozen): `kira.parseJSON(text)`, lossless (below). Only helper in
  P675; later phases add theirs as `Bindings`, not in the prelude.
- Returning a Promise or thenable: `KindOutput`, "script returned a Promise; return a plain value".
  Pending jobs are never run (`ExecutePendingJobs` never called). `await` at the top level is a
  syntax error in a non-async function body.

### Limits

| Field | Default | Ceiling | Enforced by |
|---|---|---|---|
| `Timeout` (wall clock, whole run) | 2 s | 10 s | per-call `SetEvalTimeout(remaining)` + `context.AfterFunc` interrupt + hard return at timeout + 1 s grace |
| `MemoryBytes` | 64 MiB | 256 MiB | `SetMemoryLimit` (QuickJS allocator, outside the Go heap) |
| `InputBytes` (sum of binding JSON) | 4 MiB | 32 MiB | Go side before VM creation; also per host-call args and return |
| `OutputBytes` | 1 MiB | 8 MiB | in VM on the encoded string length, then Go side on bytes |
| Source | 64 KiB | fixed | `Check`/`Exec` validation |
| JSON nesting depth (input, host calls, output) | 256 | fixed | Go token rewriter |
| Host calls per run | 10,000 | fixed | trampoline counter |
| Stack | libquickjs `MaxStackSlots` default | fixed | `SetMaxStackSize(0)` keeps the default |
| Concurrent runs | 4 | fixed | `Engine` semaphore |

- Zero field: default. Above ceiling: `Exec` returns an internal error (programming error, not a
  script error). No silent clamp.
- "CPU limit": Go has no per-goroutine CPU clock; the wall-clock deadline is an upper bound on CPU
  for a single-threaded VM, so it satisfies the row. Say so in ARCHITECTURE.
- Worst-case engine memory: 4 × 256 MiB at ceilings, 256 MiB at defaults, plus Go-side copies of
  input and output.

### Deadline, interrupt, cancel

- modernc `enter()` clears a pending `Interrupt` at each top-level Go-to-JS call, and
  `SetEvalTimeout` restarts per call. So one deadline is computed at Exec start and, before every
  Go-to-JS call (prelude, binding install, compile, call, encode), the engine checks ctx and
  deadline and sets `SetEvalTimeout(deadline − now)`. `context.AfterFunc(ctx, vm.Interrupt)` covers
  cancel mid-call. After an `interrupted` error: `ctx.Err() != nil` gives `KindCanceled`, else
  `KindTimeout`.
- The VM runs in its own goroutine (created, used and closed there). `Exec` returns at
  min(done, deadline + 1 s grace, ctx done + 1 s grace). A native built-in that does not poll the
  interrupt (example: `TypedArray.prototype.sort` without comparator) can outrun the deadline; Exec
  still returns `KindTimeout`/`KindCanceled` on time, and the goroutine closes the VM when it ends.
  The semaphore slot is released only when the goroutine ends, so runaway VMs never exceed 4.
  Semaphore acquire honours ctx (`KindCanceled`).
- Any panic inside the goroutine is recovered: `KindInternal`, one `slog.Error` with static message
  and `err` only (no source, no data). modernc leaks a VM abandoned by a panic; accepted, logged.

### Sandbox: globals

Created by `quickjs.NewVM()` (QuickJS `JS_NewContext`); never call `StdAddHelpers`,
`SetDefaultModuleLoader` or `SetModuleLoader`. `SetCanBlock(false)`. Prelude, in order:

1. Delete: `eval`, `WeakRef`, `FinalizationRegistry` (GC-timing nondeterminism), `Atomics`,
   `SharedArrayBuffer`. Keep the rest of the probe list: Error types, `Array`, `Object`,
   `Function` (replaced below), `Iterator`, number/string/URI functions, `Number`, `Boolean`,
   `String`, `Math`, `Reflect`, `Symbol`, `globalThis`, `BigInt`, `Date`, `RegExp`, `JSON`, `Proxy`,
   `Map`, `Set`, `WeakMap`, `WeakSet`, `ArrayBuffer`, typed arrays, `DataView`, `Promise`.
2. Dynamic code off: replace `Function` and the `constructor` of `Function.prototype`, and of the
   prototypes of async, generator and async generator functions, with a thrower
   (`EvalError: dynamic code is disabled`) that keeps `.prototype` so `instanceof Function` works.
   Why: the approval card shows the script; code built from data at run time (for example from an
   API response carrying injected text) would run logic the user never saw. `import()` has no
   loader and its promise never settles a job; test pins no effect.
3. Clock: `Date` replaced by a subclass whose no-argument construction and `Date.now()` return
   `Run.Now` (ms, fixed for the whole run); `Date()` called as a function returns that instant's
   string; `Date.parse`, `Date.UTC` kept. Local-time methods (`getHours`, `getDate`, `setHours`,
   ..., `getTimezoneOffset` returning 0, `toString`, `toDateString`, `toTimeString`, `toLocale*String`) map
   to UTC. Why: output must not depend on the host time zone, and the user's zone must not leak to
   the AI.
4. `Math.random`: seeded 32-bit PRNG (mulberry32 or splitmix32) from `Run.Seed`; default seed is the
   first 8 bytes of `SourceHash(source)` folded to 32 bits. Same script, same sequence.
5. `BigInt.prototype.toJSON` set to a prelude closure: it returns `marker + digits` while the
   engine's output encoder runs (closure flag `encoding`), else plain `this.toString()`. So
   `JSON.stringify` inside a script gives a digit string, not a TypeError, and the encoder still
   sees every bigint. A replacer cannot do this: `JSON.stringify` calls `toJSON` before the
   replacer (ECMA-262 SerializeJSONProperty), so the replacer would only see the string.
6. Capture `JSON.parse`, `JSON.stringify`, `Object.defineProperty` and friends into prelude
   closures, define `kira`, then deep-freeze: every global intrinsic, its `prototype`, their own
   property values that are objects or functions (cycle-safe walk with a `Set`), then
   `Object.freeze(globalThis)` after bindings are installed. Strict mode makes writes throw.
   Bindings install before the `globalThis` freeze, through a captured
   `__kira_bind(name, jsonText)`.
7. Remove the host trampoline globals from `globalThis` after capture (`delete` before freeze).

Estimated prelude cost: under 1 ms per run (small, interpreted once). If the test suite shows it
above 5 ms, compile the prelude once per process with `VM.Compile` and run `EvalBytecode` per VM;
not before.

### JSON and big integers

- Input bindings, host-call args and returns, `kira.parseJSON` all pass JSON text. Go side rewrites
  with `json.Decoder` + `UseNumber` in token mode (order kept, compact out): an integer literal (no
  `.`, `e`, `E`) outside ±(2^53 − 1) becomes the string `marker + digits`. In the VM, captured
  `JSON.parse(text, reviver)` turns marker strings into `BigInt(digits)`.
- Marker: 16 random bytes hex, per run, prefixed with `\u0000`. If any input text contains the
  marker, draw a new one (bounded retries, then `KindInternal`). Real strings never collide.
- Script view: integers within ±(2^53 − 1) are `number`; larger integers are `bigint`
  (`typeof x === 'bigint'`, `x > 5` works, `x + 1` throws TypeError, use `x + 1n` or `String(x)`).
  Decimals and exponents stay `number` (float64; `1e400` becomes `Infinity`, which encodes as
  `null`). Big decimals as exact values are not supported; P680 decides how SQL `numeric` arrives.
- Output: in-VM encoder sets the `encoding` flag (prelude item 5), calls captured
  `JSON.stringify(value)`, clears the flag in `finally`; a cycle or a throwing `toJSON` becomes
  `KindOutput`. A bigint at the top level encodes the same way. Length check in VM, then Go side
  rewrites marker strings back to bare integer literals (token mode, order kept). So big integers
  from the input reach the AI as exact JSON numbers, never strings, unless the script stringifies them.
- `kira.parseJSON(text)`: same lossless path, through a host call (counts against host-call and
  input caps). Script-side `JSON.parse` stays standard and lossy above 2^53; ARCHITECTURE says to
  use `kira.parseJSON` for nested JSON text.
- Strings: invalid UTF-8 into the VM and lone surrogates out become U+FFFD (modernc default, WTF-8
  off). Output bytes are valid UTF-8.

### Source integrity and hash

- `SourceHash(source)`: lowercase hex SHA-256 of the exact bytes, no normalisation (CRLF stays):
  the approval card shows verbatim source and P676 binds approval to this hash the way
  `scriptruns` binds `Preview.Hash`.
- Validation in `Check` and `Exec`, `KindSource`: empty or blank; over 64 KiB; invalid UTF-8 (modernc
  would run a replaced character the user never saw); NUL; bidirectional control characters
  U+202A to U+202E and U+2066 to U+2069 anywhere (Trojan Source: the card would show different
  logic than runs). Error names the line and column of the first offending character.
- `Check`: validation, then `VM.Compile(wrapped, EvalGlobal)` in a fresh VM with 16 MiB and 1 s, no
  prelude, no bindings, never executes. Uses the semaphore. Returns nil or `*Error` (`KindSyntax`
  with line and column, or `KindSource`).

### Errors

```go
type Kind string // syntax, runtime, timeout, canceled, memory, stack, source, input, output, internal

type Error struct {
	Kind    Kind    `json:"kind"`
	Message string  `json:"message"`          // capped at 2 KiB, "TypeError: ..." form for runtime
	Line    int     `json:"line,omitempty"`   // 1-based in the user's source; 0 when unknown
	Column  int     `json:"column,omitempty"` // 1-based
	Stack   []Frame `json:"stack,omitempty"`  // user frames only, at most 10
}
type Frame struct {
	Function string `json:"function,omitempty"`
	Line     int    `json:"line"`
	Column   int    `json:"column"`
}
func (e *Error) Error() string // "script <kind> error at line L, column C: <message>"
```

- Mapping: compile failure `SyntaxError` uses `LineNumber − 1`, `ColumnNumber`; a position past
  the source (unterminated block) clamps to the last line. Runtime errors carry no line in
  `*quickjs.Error`; parse `Stack` lines `    at <fn> (<eval>:L:C)`, drop frames named `__kira_*`
  and the anonymous wrapper frame, subtract 1 from the line of user frames; `Line`/`Column` are the
  top user frame. `interrupted`: timeout or canceled (above). `InternalError: out of memory`:
  `KindMemory`. `InternalError: stack overflow`: `KindStack`. Exception value `null` with no name:
  QuickJS throws `null` when it cannot allocate the error object at the limit (probe: push loop);
  map to `KindMemory` with message "out of memory (memory limit reached), or the script threw
  null". modernc v0.27.0 exposes no memory-usage call to tell them apart; this is a Known open item.
- A caught out-of-memory (`try { ... } catch {}`) lets the script go on near the limit; memory
  stays bounded and time still runs. Documented, tested for boundedness only.
- Scrub: file name is always `<eval>` (modernc fixed `evalFN`), so no host path can appear. Go
  errors from host funcs reach the script as their `err.Error()`; callers own its text. Panic text
  never reaches the script or the agent ("internal error").
- Messages may echo data the script handled. The engine knows no secrets; P676 and P679 mask error
  text like any agent-bound text. Write that into ARCHITECTURE.
- The engine logs nothing about scripts or data; internal faults only, per `sloglint` rules
  (static message, `err` key, `scope: "jsengine"`).

## Tests

Package tests only, `apps/kira-space/internal/jsengine/*_test.go`, standard `testing`, table-driven,
`t.Parallel()` where the semaphore allows. No flow test and no UI spec in P675: the engine has no
IPC surface. The split flow test plus UI spec belongs to P676 (first feature). Each file below
guards something hard to get right (limits and interrupt timing, sandbox escape, token rewriter
with several interacting rules, frame mapping); no CRUD or trivial-wrapper tests, no test of
`SourceHash` alone.

1. `limits_test.go`: infinite loop gives `KindTimeout` within timeout + grace; ctx cancel mid-run
   gives `KindCanceled`; `repeat(2**28)`, push loop, `Array(2**31).fill` give `KindMemory` and the
   process heap (`runtime.ReadMemStats` HeapAlloc delta) stays far below the allocation tried;
   swallowed OOM still returns within the deadline; recursion gives `KindStack`; output over cap
   gives `KindOutput`; input over cap gives `KindInput` before VM creation; hard-grace path: a
   test binding whose `HostFunc` blocks on a channel makes Exec return `KindTimeout` at timeout +
   grace while the VM is still busy, and the fifth concurrent Exec waits until that goroutine ends
   (close the channel, assert release); semaphore wait honours ctx; deadline spans several
   top-level calls (big input parse plus loop exceed the budget only together).
2. `sandbox_test.go`: `typeof` is `undefined` for `require`, `process`, `std`, `os`, `print`,
   `console`, `setTimeout`, `setInterval`, `fetch`, `XMLHttpRequest`, `WebAssembly`,
   `performance`, `WeakRef`, `FinalizationRegistry`, `Atomics`, `SharedArrayBuffer`, `eval`;
   `Function('x')`, `(function(){}).constructor('x')`, async, generator and async generator
   constructors, `Reflect.construct(Function, ['x'])` throw `EvalError`; `import('os')` has no
   effect and the run returns; `Object.prototype.x = 1`, `Math.random = ...`, `JSON.parse = ...`,
   `globalThis.y = 1`, redefining a binding all throw; a second run on the same `Engine` sees no
   leftover; wrapper break-out gains nothing; `Date.now()` and `new Date()` equal `Run.Now`;
   `new Date(0).getTimezoneOffset() === 0` and `getHours() === getUTCHours()` with
   `t.Setenv("TZ", "America/New_York")` (not parallel); `Math.random` sequence equal across two runs
   with the same seed, different with another; Promise return gives `KindOutput`.
3. `json_test.go`: table over inputs 2^53 − 1 (number), 2^53 + 1, −2^63, 2^64, a 40-digit integer
   (bigint, exact out), `1.5`, `1e3`, `1e400`, negative zero, nested arrays and objects, key order
   with numeric-looking keys (JS orders integer keys first: test pins actual output), duplicate
   keys, depth 256 passes and 257 fails `KindInput`; output depth cap; host-call round trip of a big
   integer through `HostFunc`; `kira.parseJSON` lossless; script `JSON.stringify(2n**64n)` gives a
   string; a string equal to `"\u0000"` plus 32 hex chars that is not the run's marker stays a
   string; cycle in output gives `KindOutput`; host func error text reaches the script as an
   `Error` it can catch; host func panic gives "internal error" and the run continues; 10,001st
   host call throws.
4. `errors_test.go`: syntax error on line 1, a middle line and the last line (unterminated brace)
   with exact line and column, same from `Check` and `Exec`; runtime error inside a nested user
   function gives user frames only with mapped lines, no `__kira_` frame, after an error inside
   `kira.parseJSON` the top frame is the user call site; message cap 2 KiB; `Check` refuses NUL,
   invalid UTF-8, U+202E and U+2067 with position, over 64 KiB, blank; `Check` never executes
   (a script whose body would loop forever passes `Check` instantly); `Error()` string shape;

## Risks

- Transpiled C: a modernc bug or a panic abandons a VM and leaks its memory. Mitigation: recover,
  log, fresh VM per run, bounded concurrency. Same supplier as the app's SQLite driver.
- Single primary maintainer upstream. Fallback if it stalls: QuickJS on wazero (wazero already in
  the graph) behind the same `jsengine` interface; nothing outside the package names QuickJS.
- QuickJS is slower than V8-class engines; transforms of up to a few MiB are well inside 2 s
  (`NewVM` 0.15 ms measured; script throughput not measured, no decision depends on it).
- Wall clock, not CPU: a loaded machine gives a script less work per second. Acceptable; limits are
  safety rails, not quotas.
- Prelude hardening is JS-level. A missed intrinsic constructor path would re-open dynamic code;
  sandbox tests enumerate the known paths. Dynamic code still runs only inside the same sandbox,
  so a miss breaks the "user saw the code" rule, not isolation.
- Date subclass and local-to-UTC mapping can surprise a script expecting local time. Documented in
  the tool text by P676.
- `libc` v1.79.0 vs v1.79.1 skew (above); tests decide.
