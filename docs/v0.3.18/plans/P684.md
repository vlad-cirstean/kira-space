## Decision

One model: filter lines (kube's). Docker logs move to it; kube keeps its behaviour and its
hand-written filter moves into one shared composable.

Why filter, and the requirement `FindBar` cannot meet for logs:
- A log is a live stream capped by `appendCapped`: every batch past 20 000 lines drops the head.
  Find-in-place keeps a cursor into an index list (`current` into `matchLines`); a head drop shifts
  every index, so the "current" match silently moves to another line, and `revealCurrent` turns off
  follow on each step. A filter has no cursor to drift. Requirement: a stable result over a
  head-trimmed stream. `FindBar` stays for documents and pages (response body, grid, stream search).
- Filtered lines are the copy source: `CopyLogButton` over `shown` gives grep-then-copy (kube
  F-C8 contract), which find-in-place cannot offer.
- Marks already come from `LogLines` `needle`; filter needs no extra state (no open flag, no
  cursor, no prev/next, no reveal).
- Same model as kube `DescribeView` filter in the same module.

Library check: `SearchField` (theme, shadcn-vue `InputGroup`) is the field; `CopyLogButton` and
`useCopy` the copy; `useKeptState` (Pinia view-state store) holds the query. No debounce: the
composable caches each line's lower-cased plain text in a `WeakMap`, so a keystroke costs one
`includes` per line (20 000 max); VueUse `refDebounced` declined, it would only delay marks with no
measured cost to save. No new dependency.

Docker toolbar actions: Copy log added (part of the model: copy the shown lines). Clear stays on
docker (not part of find; dropping it removes a feature nobody asked to drop). Kube gains no Clear
and docker keeps Jump to latest: outside the find model, out of scope.

## Shared API

### `packages/workbench/src/behaviour/logFilter.ts` (new)

```ts
import { t } from '@theme/i18n';
import { computed, type MaybeRefOrGetter } from 'vue';
import { plainText } from '../lib/logTail';
import { useKeptState } from './viewState';

/** The one log find model: a kept filter that hides lines without the text. Trimmed,
 *  case-insensitive substring, ANSI ignored. `shown` feeds LogLines and CopyLogButton;
 *  `needle` marks matches in LogLines; `status` reads "N of M lines" while filtering, else ''. */
export function useLogFilter<T extends { text: string }>(
  lines: () => readonly T[],
  key: MaybeRefOrGetter<string>,
) {
  const filter = useKeptState(key, '');
  const needle = computed(() => filter.value.trim().toLowerCase());
  // Lower-cased plain text once per line object; lines are appended, never mutated.
  const lower = new WeakMap<T, string>();
  const textOf = (l: T): string => {
    let s = lower.get(l);
    if (s === undefined) {
      s = plainText(l.text).toLowerCase();
      lower.set(l, s);
    }
    return s;
  };
  const shown = computed(() => {
    const n = needle.value;
    return n === '' ? lines() : lines().filter((l) => textOf(l).includes(n));
  });
  const status = computed(() =>
    needle.value === ''
      ? ''
      : t('common.logs.matches.status', { shown: shown.value.length, total: lines().length }),
  );
  return { filter, needle, shown, status };
}
```

Semantics equal `matchesQuery` (trim, lower, `includes`). Lives in `/behaviour/` beside
`viewState.ts`; `clipboard.ts` already imports `t` there.
