### Mobile evidence

- Phone transport is real HTTP: `mobile/api/http.ts` `request` maps a fetch failure to `E_NETWORK`.
  Real browser `offline` means no network interface, so no fetch to the desktop can succeed.
- Raw writes (`mobile/state/useAdeWrites.ts`) carry an idempotency key per intent and
  `retry: count < 2 && code === 'E_NETWORK'`: a replay after reconnect runs once on the server.
- Remote profile already has `retry: 1`, `refetchOnReconnect: true`, `refetchOnWindowFocus: true`.
- `AppShell.vue` shows connection state (`useOnline`, SSE `connection` dot), so a paused write is
  explained on screen.
- `QueryState.vue` renders `isPending` (paused with no data) as loading; with data it keeps data.

## Decision

Desktop (`remote: false`), queries and mutations: `networkMode: 'always'`. Every call is a Wails
bridge call to the local Go process; Go owns network failures and reports them as coded errors. The
webview's network state says nothing about it. Also `refetchOnReconnect: false`: mirrors
`refetchOnWindowFocus: false`; the only queries it would touch are `staleTime: 0` or short-stale
ones (polls, previews, Kibana data view list), which refetch by interval or on mount already. Retry
stays `false` (queries) and TanStack default 0 (mutations).

Phone (`remote: true`), queries and mutations: `networkMode: 'online'`, set explicitly (equals the
default; written out so the profile states its choice). Pausing is right there: offline means the
request cannot reach the desktop; a paused query resumes on `online` and `refetchOnReconnect` covers
stale ones; a paused write runs on reconnect with its idempotency key; `retry: 1` and the writes'
`E_NETWORK` retry pause between attempts instead of burning them. Failing fast instead would show
"unreachable" errors for a state the shell already shows.

Phone must run on its own profile. Today `approvalsQueries.ts` and `agentInfo.ts` pin the desktop
singleton, so on the phone they would silently switch to `always` with this phase. Fix in-phase:
both use `useQueryClient()` (every app installs `VueQueryPlugin` since P682; every caller already
calls `inject` in the same function, so it is setup context). `AppShell.vue` drops the
`approvalsClient` import and invalidates `['approvals']` on its own `queryClient`.

`useAsyncAction`: drop its per-call `networkMode: 'always'` and its comment. On desktop the default
now gives `always`. On the phone every `useAsyncAction`/`useTaskAction` thunk wraps a raw
`useAdeWrites` mutation that pauses anyway (`LaterScreen` capture, `NeedsScreen` take over and
launch), so the visible result is the same; the client default becomes the one owner of network
mode. Unit-tested stores passing `{ queryClient }` pass the singleton (`collections.ts:122`,
`variables.ts:51`, `datagripImport.ts:60-61`) and inherit it.

   ```ts
   export function createQueryClient({ remote }: { remote: boolean }): QueryClient {
     const networkMode = remote ? 'online' : 'always';
     return new QueryClient({
       defaultOptions: {
         queries: remote
           ? { networkMode, retry: 1, refetchOnWindowFocus: true, refetchOnReconnect: true, staleTime: Number.POSITIVE_INFINITY }
           : { networkMode, retry: false, refetchOnWindowFocus: false, refetchOnReconnect: false, staleTime: Number.POSITIVE_INFINITY },

       },
   ```
