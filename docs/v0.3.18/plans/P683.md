## Decision

Extend the existing shared pieces; no new library, no new Pinia store. Each view kind keeps its own
store (one concern: that view kind's per-tab runtime). Shared bodies are plain factories and
functions called inside each store's setup, the pattern `createRuntimeStore` and
`createPageNavigation` already set.

- TanStack Query: declined for the view runtime and page cache. Requirements it cannot meet: (1)
  supersession by op id with a backend `opsCancel` of the superseded read (keyvalue `stopOp`,
  `runPagedLoad`'s `rt.opId !== opId`), (2) a decode cache pruned to the visible row window
  (`setVisibleWindow`), not a key-based gc, (3) per-tab keyed status/error written by load, count,
  stop and mutations and outliving the component (P682 "keyed store surfaces"). Request views stay
  on their op runtime for the same reason (streaming events matched by `lastCallId`).
- Pinia: no new store. `staleData` gains one method (same concern: staleness).
- VueUse: nothing applies (no DOM or browser composable involved). Watchers stay Vue `watch`.
- `stream/search.ts`: stays its own store. Requirement: one case-insensitive substring match over
  five fixed columns, no regex or whole-word toggles, no chunked rAF scan, no `SearchToolbar`
  binding (its own comment, `stream/search.ts:9-16`). Merging it into `createPageSearch` would add
  a scan model it does not use.
- `selectRow` (documents, stream; one line each), `setFilterDraft` (fields differ per kind),
  `reload`/`poll` (3 lines, tails differ: grid cursor, stream batch drop): stay per kind.

## Behaviour changes

No visible change. Internal only:

- Console `documentRow`/`documentId`/`keyValueRow` gain the row-bound guard (out-of-range row
  returns `null`; callers already fall back with `?? ''`). Console `keyValueRow` gains
  `isTruncated` (unused there).
- Grid `load()` apply: strategy check moves before `setPage`/`applyPagePosition`. Today it throws
  after `rt.opId = null`, so `applyLoadFailure` drops it and the tab sits idle on a page it called
  invalid; now the throw reaches the error state. Unreachable path for current adapters.
- Tab-close cleanup order: grid's `clearCellFocus` now runs before the record delete (was after);
  nothing reads both.
- Documents setters keep `void` returns (`void restart(...)`).

Eyeball list for chapter-end visual re-record: none (no template or class change).
