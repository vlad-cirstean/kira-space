## Decision

### P687: one core, `useGuardedDraft`

New `packages/workbench/src/behaviour/guardedDraft.ts`. One composable owns draft, base hash, dirty,
the save action (`useAsyncAction`, so TanStack mutation state owns pending and error, P682), the
`conflict` computed, follow-while-clean, Discard, Reload and Overwrite. Text and structured drafts
alike (generic `T`). A store that must own the draft value (D4, D5: the inspector, nodes and
`useStepRemoval` edit it) passes its refs as `state`; the save state stays in the component that
saves. `useConfigFormDraft` keeps its form layer (decode chain, `applyModel`, `errorFor`,
`unmatched`) and delegates the guarded part to the core.

Adopted: D1, D2, D3, D4, D5, D6 (through D1's `secrets` option), D10 (unchanged caller of D1).
`isConflict(err)` in `codedError.ts` replaces every hand predicate, draft or not (12 sites).

Declined, each with the requirement the core cannot meet:
- D7 `useFileEdit`/`fileEdit`: the draft lives in a cached Monaco model that survives tab switches
  (no value ref; a text ref would copy the whole buffer per keystroke), dirty is a Monaco alternative
  version id compare, and conflict is three-state (`changed`, `gone`) raised eagerly by a focus-time
  disk check, with a `gone` path that leaves edit mode. Takes `isConflict` only.
- D8 `llmPromptDrafts`: N drafts, each with its own base hash, sent as one batch under
  `SettingsShell`'s single Save (`extra`); no per-draft Reload/Overwrite surface exists. Not a
  single guarded draft. No change.
- D9 `dockerEdit`: a conflict is resolved by a three-way merge rebase that keeps the user's fields
  (`merge3`, `rebaseOnce` after its own apply), not Reload/Overwrite of a whole value. Takes
  `isConflict` only.

Libraries: TanStack Query already backs the save (through `useAsyncAction`); a `useQuery` cannot
hold an unsaved draft. VueUse: `useDebounceFn` stays in `useConfigFormDraft`; nothing else applies.
Pinia: no new store; `adeWorkflowDraft` shrinks (loses `error`, `conflict`, `push`, `discard`,
`rebase`, `saved`).

### P685: one shell, `ConfigFileDialog.vue`

New `packages/workbench/src/config/ConfigFileDialog.vue` (workbench, since `RunFileDialog` lives
there). It composes the shadcn-vue `Dialog*` primitives, `ViewToolbar` + `SecondaryTabs`,
`QueryState`, `ConfigFileProblem`, `ConfigFormProblemAlert`, `CodeTextEditor`, `SaveConflictAlert`
and the footer. Hosts keep their query, mutations, field tables, per-kind tab bodies, title and
footer start actions. No new library: every primitive exists. A plain composable for the shell was
declined: the repeated part is template (head, toolbar, body frame, footer), which only a component
removes.

One behaviour per piece (majority of the three, or the existing shared rule):
- Footer: Discard (resets the draft, stays open, disabled when clean) + Save. Run loses its
  `DialogClose` Close/Discard; closing is the header X or Esc, guarded by `DialogContent :dirty`.
- Size: `2xl fixed-height`, YAML editor `h-72` (run was `lg`, `h-64`).
- Top problem alert: `draft.unmatched(all section pointers)`, so a problem a field or tab badge
  already shows is not repeated (run used `draft.problem`).
- Tab badges on every dialog: count from the section's pointers (`draft.errorFor`) plus an optional
  host count (run's client-side checks). API gains badges from `VARIABLES_SECTION_POINTERS`.
- Load failure: `QueryState` (inline error with Retry, testid `<prefix>-error`) in every dialog.
- Secret errors: the typed-secret flush is one write with the file (`useConfigFormDraft` `secrets`
  option, P687 W1), so the shell shows one save error. Connection's lifecycle error (Duplicate,
  Delete) passes as `actionError` and shows in the same alert, as today.

### `packages/workbench/src/behaviour/guardedDraft.ts` (new, W1)

```ts
export interface DraftSource<T> { value: T; hash: string }

/** Draft value, base hash and dirty flag; a store that owns them passes them as `state`. */
export interface GuardedDraftState<T> { draft: Ref<T>; baseHash: Ref<string>; dirty: Ref<boolean> }
export function guardedDraftState<T>(initial: T): GuardedDraftState<T>;

export interface GuardedDraftOptions<T> {
  /** The saved value as the query or prop holds it; undefined while loading. Followed while clean. */
  source: MaybeRefOrGetter<DraftSource<T> | undefined>;
  /** Fresh read for Reload and Overwrite. Default: `toValue(source)`. */
  refetch?: () => Promise<DraftSource<T> | undefined>;
  /** Writes `value` built on `baseHash`; resolves the new hash. */
  write: (value: T, baseHash: string) => Promise<{ hash: string }>;
  /** Initial draft when no `state` is passed. */
  initial?: T;
  state?: GuardedDraftState<T>;
  /** Copy taken from the source (default: identity; workflows: `cloneWorkflow`). */
  clone?: (v: T) => T;
  /** Compare key for "unchanged while the write ran" (default: the value; workflows: JSON). */
  key?: (v: T) => unknown;
  /** Discard and Reload: replaces the default state writes (store `open` resets its selection). */
  adopt?: (src: DraftSource<T> | undefined) => void;
  /** Runs before a save; false stops it (config: apply the form, refuse on a problem). */
  beforeSave?: () => Promise<boolean>;
  /** Writes riding the same Save after the file (typed secrets). Save runs when either is pending. */
  side?: { pending: () => boolean; flush: () => Promise<void> };
  /** After a successful file write (store clears its fresh-step set). */
  onSaved?: () => void;
  /** After follow and after resetTo wrote the state (config: decode the new text). */
  afterLoad?: () => void;
  /** Only a unit spec without an app. */
  queryClient?: QueryClient;
}

export function useGuardedDraft<T>(opts: GuardedDraftOptions<T>): GuardedDraftState<T> & {
  saving: ComputedRef<boolean>;
  saveError: ComputedRef<string | null>;
  conflict: ComputedRef<boolean>; // isConflict(cause)
  canSave: ComputedRef<boolean>;  // (dirty || side.pending()) && !saving
  edit: (next: T) => void;        // draft = next, dirty = true
  save: () => Promise<boolean>;   // no-op false when saving, refused by beforeSave, or nothing pending
  resetTo: (src: DraftSource<T> | undefined) => void;
  discard: () => void;            // resetTo(toValue(source))
  reload: () => Promise<void>;    // resetTo(await refetch())
  overwrite: () => Promise<void>; // fresh = await refetch(); none: return; baseHash = fresh.hash; dirty = true; save()
  clearError: () => void;
};
```

Rules the implementer keeps exact:
- Follow: `watch(() => toValue(source), immediate)`: when present and `!dirty`, `draft = clone(value)`,
  `baseHash = hash`. Never calls `adopt` (a push after one's own save must keep the graph selection).
- Save action body: snapshot `sent = key(draft)`; if dirty, `next = await write(draft, baseHash)`,
  `baseHash = next.hash`, `dirty = false` only when `key(draft) === sent`, `onSaved?.()`; then
  `await side?.flush()`. One `useAsyncAction`, so one pending, one error, latest-wins (P682).
- `resetTo`: `action.reset()`, then `adopt(src)` when given, else `draft = clone(src.value)` (or
  `initial` when `src` is undefined), `baseHash = src?.hash ?? ''`, `dirty = false`.
- A component never wraps one mutation call in `useAsyncAction` (P682): `write` plus bookkeeping
  plus `side` is more than one call, as in today's D1-D3.

### `packages/workbench/src/config/useConfigFormDraft.ts` (W1)

Same return names as today (callers unchanged apart from the option), built on `useGuardedDraft<string>`:
`draft`, `baseHash`, `dirty` come from the core; `saving`, `conflict`, `discard`, `reload` from the
core; `saveError` = `core.saveError ?? ''`; `overwrite` = `core.overwrite` (its `beforeSave` applies
the form); `saveNow` = `core.save`; `afterLoad: () => void decode()` keeps today's "load, then decode" on

passes through as the core's `side`. `canSave` = `!saving && ((dirty && !(tab === 'form' && problem))
|| secrets.pending())` (today's dialog `draft.canSave || hasTyped`).
