# P678: API MCP: kept variables and chained requests

Planner: Opus. Implementers: two Parts, one sequential Sonnet subagent each, Part 1 then Part 2. No
streams inside a Part: store, request resolution, tool, bridge and card are one order-dependent
chain.

Spec row: a script stores a result in a named variable held by Kira; the value never returns to
the AI; later requests and scripts refer to it by name. The approval card lists every variable a
request or script reads (name, value, source request, age, expiry) and highlights each use site. A
view lists live variables (value, source, remaining time) and clears them. Retention short (default
1 h), memory only, wiped on exit, never refreshed silently. Agent sees names only. Store is
MCP-agnostic (P680 reuses it): one package, entries tagged with source MCP and request. Plan
decides package, caps, naming, agent-facing text.

## Parts (SPEC rows)

Orchestrator renames the row `P678 Part 1: kept variable store, request references, card and view`
and adds `P678 Part 2: kept variables in scripts` right after it.

- Part 1 needs no JS engine. It ships the store, its Go API, retention, sweeper, the
  `{{kept.<name>}}` request syntax resolved after approval, the approval-card panel with use-site
  highlights, the `list_kept_variables` tool, the bridge service and the Settings view. Tests use a
  fake producer: flow tests `Put` entries straight into the store (the store is the producer seam).
- Part 2 needs P675 (engine), P676 (scripts in `api_request`) and P677 (result review) landed. It
  adds the `kept` script binding (`kept.get`, `kept.set`), script-site highlights, staged writes
  committed after the result is final, and the "will keep" lines in the P677 review card.

Why split: Part 1 is the larger half and its contract (entry shape, payload, syntax) is what P676,
P679 and P680 read; it can be verified alone. Part 2 is small but depends on P676/P677 code that
does not exist at planning time; its implementer plans against the tree those phases leave.

## Decisions

### Package and entry shape

`apps/kira-space/internal/keptvars`. Imports stdlib only. Never imports `dbmcp`, `agentapi`,
`bridge`, `jsengine`, `secrets`. P680 and P679 use it unchanged.

```go
type SourceKind string // "script" (P678), "user" (P679)

type Source struct {
	Kind    SourceKind `json:"kind"`
	MCP     string     `json:"mcp"`     // "api" (P678), "db" (P680)
	Tool    string     `json:"tool"`    // "api_request"
	Request string     `json:"request"` // display text: "GET https://host/path?x" as the op log shows it
	                                     // (secrets {{name}}); SQL masked by the producer
	Client  string     `json:"client"`  // ApprovalOrigin.Client
	TaskID  string     `json:"taskId,omitempty"`
	SessionID string   `json:"sessionId,omitempty"`
}

type Meta struct {
	ID        string    `json:"id"`        // "kv_" + 16 hex, crypto/rand; new on every Put
	Scope     string    `json:"scope"`     // "external" or "session:<SessionID>"
	Name      string    `json:"name"`
	Type      string    `json:"type"`      // null|boolean|number|string|array|object
	Bytes     int       `json:"bytes"`     // compact JSON length
	Items     int       `json:"items"`     // array length or object key count; 0 otherwise
	Secret    bool      `json:"secret"`
	Source    Source    `json:"source"`
	CreatedAt time.Time `json:"createdAt"`
	ExpiresAt time.Time `json:"expiresAt"`
}

type Entry struct {
	Meta
	Value json.RawMessage // compact JSON; Get returns a copy
}
```

- `Secret` and `SourceKind user` exist now so P679 adds a producer and a reveal path only. P678
  already honours `Secret` everywhere a value could leave: list and payload previews are empty,
  `Value(id)` refuses, `agentapi` adds secret values used by a request to the response mask
  (below). No P678 producer sets it; flow tests use the fake producer with `Secret: true`.
- Scope: `session:<id>` for a session-server call, `external` for the external server (one scope:
  stateless transport, no client identity). A scope sees only its own entries. `ClearScope` runs on
  session release. Cross-MCP use inside one scope is allowed (P680 reads API-made ids); `Source.MCP`
  is informational.
- Names: `^[A-Za-z][A-Za-z0-9_]{0,39}$`, case-sensitive, unique per scope. Fits a JS identifier and
  a `{{kept.<name>}}` span. Error text names the rule.
- Replace: a `Put` with an existing name in the scope removes the old entry (watchers get reason
  `replaced`) and inserts a new one with a new `ID` and a fresh expiry. A `Put` never replaces an
  entry of another `SourceKind` (`ErrNameTaken`): a script cannot overwrite a P679 user value.
- Values: any JSON. Compacted with `json.Compact`, validated, depth ≤ 64 (Go token scan), size
  checked after compaction.

### Store API

```go
type Options struct {
	Now       func() time.Time         // nil = time.Now
	Retention func() time.Duration     // read per Put; nil or error path = 1 h
	OnChange  func(revision uint64)    // after every mutation batch, outside the lock
}
func New(o Options) *Store

type Put struct {
	Scope, Name string
	Value       json.RawMessage
	Secret      bool
	Source      Source
	TTL         time.Duration // 0 = Retention(); never above MaxTTL
}
func (s *Store) Put(p Put) (Meta, error)
func (s *Store) Get(scope, name string) (Entry, bool) // live only: now < ExpiresAt
func (s *Store) ByID(id string) (Entry, bool)          // live only
func (s *Store) List(scope string) []Meta              // "" = every scope (UI); sorted by CreatedAt desc
func (s *Store) Clear(ids ...string) int               // reason cleared
func (s *Store) ClearScope(scope string) int           // reason ended
func (s *Store) ClearAll() int                         // reason cleared
func (s *Store) OnRemove(ids []string, fn func(Removal)) (stop func()) // fires once, first removal
func (s *Store) Close()                                // stop sweeper, ClearAll (reason quit)
func ValidName(name string) error

type Removal struct{ ID, Name string; Reason Reason } // expired|cleared|replaced|ended|quit
```

Errors: `ErrName`, `ErrTooLarge`, `ErrScopeFull`, `ErrStoreFull`, `ErrNameTaken`, `ErrClosed`, each
with fixed text and no value.

### Caps, memory, eviction

| Limit | Value | Why |
|---|---|---|
| Per value (compact JSON) | 1 MiB | equals jsengine `OutputBytes` default; a list of 100k ids fits |
| Entries per scope | 64 | a chain needs a handful; bounds a looping agent |
| Entries in store | 512 | |
| Bytes in store | 32 MiB | worst case 32 MiB plus small per-entry overhead; app RAM untouched otherwise |
| Kept names per request | 16 distinct | card stays readable |
| TTL | retention setting 5 to 240 min, default 60; `MaxTTL` 240 min | spec: short |
| Preview in payload and list | 2 KiB compact JSON, rune boundary, `previewTruncated` | queue snapshot fans out to every window: at most 50 items x 16 x 2 KiB |

- Eviction: expiry only. No LRU of live entries: dropping a value the user saw and approved would
  silently break a chain. At a cap, `Put` refuses with text naming the cap and the Kept variables
  view. Replacing a name frees the old size first; expired entries are swept before a cap check.
- Expiry is fixed at `Put`. Nothing extends it: no read, no use, no retention change (a changed
  setting applies to new entries; the pane says so). A new value under the same name is an explicit
  new entry with its own age.
- Clearing zeroes the stored `Value` bytes (best effort; matters for P679). `Get` and `ByID` hand
  out copies, so zeroing never races a reader.

### Locking and concurrency

- One `sync.Mutex` guards maps (`byID`, `byScope[scope][name]`), totals, the expiry min-heap
  (`container/heap` on `ExpiresAt`), watchers (`map[id][]*watcher`) and `revision`.
- Every mutation collects removals under the lock, bumps `revision` once, unlocks, then runs
  watcher callbacks (each at most once, `sync.Once` per watcher) and `OnChange(revision)`. No
  callback runs under the lock, so a callback may call back into the store.
- `Get`/`ByID` treat `now >= ExpiresAt` as absent even before the sweep: expiry is exact for reads.
- Sweeper: one goroutine, a `time.Timer` reset to the heap minimum; `Put` with an earlier expiry
  pokes a buffered channel (size 1) to reset it. One sweep removes every due entry as one batch:
  one revision, one push. `Close` stops it (done channel) and waits.
- `OnRemove(ids)`: registers a watcher per id under the lock; an id already absent fires at once
  (after unlock) with reason `expired` or `cleared` as known, else `expired`. `stop` deregisters.
- Ordering guarantee: a removal is visible to `Get` before its watchers run. `OnChange` revisions
  are monotonic; the renderer only refetches, so a push arriving late is harmless.
- Unit test `store_test.go` (qualifies: expiry and eviction under concurrency). Covered below.

### Request syntax: `{{kept.<name>}}`

- Agent writes `{{kept.ids}}` in `url`, a header name or value, a query name or value, `body`, a
  form name or value, `contentType`. Same braces as env variables, reserved `kept.` prefix, so the
  user reads one template language and the card highlights one token shape.
- `kept.` names never resolve as env variables on the agent path: `checkNames`, `resolvePlain` and
  `variablesUsed` skip them. An env variable literally named `kept.x` is unreachable for agents;
  the user's own HTTP console is untouched.
- Refused at plan (agent-facing text in quotes, never a value):
  - unknown or expired in the scope: "no kept variable \"ids\" (it may have expired or been
    cleared); call list_kept_variables";
  - a pipeline (`{{kept.ids | base64}}`): "kept variables take no transforms; write
    {{kept.ids}}";
  - inside the URL's scheme, host or port (authority: from `://` to the first `/`, `?` or `#`):
    "a kept variable cannot be part of the URL's scheme, host or port". The approved host and the
    access-rule verdict stay decided by text the user saw;
  - array or object in `url`, header, query, form or `contentType`: "kept variable \"ids\" is a
    list; only text, number or boolean values fit in a URL, header, query or form field. Use it in
    a JSON body, or keep a joined string";
  - a string with CR or LF in a header: "kept variable \"x\" contains a line break; it cannot go in
    a header";
  - JSON body (content type contains `json`, case-insensitive): a reference inside a JSON string
    literal: "in a JSON body write {{kept.ids}} without quotes; Kira inserts the value as JSON";
    body not valid JSON with every reference replaced by `null`: "body is not valid JSON once kept
    variables are inserted";
  - more than 16 names: "a request can use at most 16 kept variables".
- No host check per entry in P678; P679 decides host rules for user values.
- Insertion at send, by position:
  - `url` before `?`: scalar text through `url.PathEscape`; after `?`: `url.QueryEscape`;
  - `query` pairs and form fields: scalar text (the existing encoders escape);
  - header: scalar text;
  - JSON body: the value's compact JSON text (any type): `{"ids": {{kept.ids}}, "n": {{kept.n}}}`;
  - other body: string as raw text, number and boolean as JSON literal, array and object as compact
    JSON;
  - scalar text: string as is, number as its JSON literal (big integers exact), boolean
    `true`/`false`, null as empty.
- No rescan: `buildRequest` splits each field at kept spans first; literal segments go through the
  secret resolver; kept values are inserted after and never scanned again. A response-derived
  value holding `{{token}}` is sent literally and never pulls a secret in. `sameTarget` runs after.
- Planned keeps the template (`{{kept.ids}}` verbatim), like secrets. Op log command, audit and
  every agent-visible text show the template only.

### Plan, approval, send: what binds to what

- `agentapi.Input.Scope` (set by dbmcp from `originFrom`). `agentapi.Service.Kept` is a
  consumer-declared interface `KeptReader { Get(scope, name string) (keptvars.Entry, bool) }`;
  nil means no kept variables (any `{{kept.*}}` refused as unknown).
- `Planned.Kept []KeptUse`:

```go
type KeptUse struct {
	keptvars.Meta              // snapshot at plan: id, type, source, created, expiry
	Preview          string    // 2 KiB cap; "" when Secret
	PreviewTruncated bool
	Sites            []KeptSite
}
type KeptSite struct {
	Field string // "url" | "header" | "query" | "form" | "body" | "contentType" | "script" (Part 2)
	Index int    // pair index for header/query/form; 0 otherwise
	Part  string // "name" | "value" for pairs; "" otherwise
	From, To int // UTF-16 code units in the payload's text for that field (renderer indices)
}
```

  Sites are computed on the Planned display fields that the payload carries, so offsets match what
  the card renders. Body sites past the 64 KiB display cap are dropped (the card's truncation risk
  already shows).
- `approveAPI`, when `plan.Kept` is non-empty: `ctx2, cancel := context.WithCancelCause(ctx)`;
  `stop := Kept.OnRemove(ids, func(r) { cancel(&keptGoneError{r}) })`; request on `ctx2`; `defer
  stop()`. The broker drops the item on ctx end. If `context.Cause(ctx2)` is a `keptGoneError`, the
  agent gets "kept variable \"ids\" <reason> while waiting for approval; nothing was sent. Produce
  it again, then repeat the request." Reason words: expired, was cleared by the user, was replaced,
  ended with the session. So a card never offers Send for a value that is gone.
- `Send`: after `sameRequest`, every `approved.Kept[i].ID` must equal the ID `Kept.Get(scope,
  name)` returns now (same lookup takes the value copy). Mismatch or absence: same text with
  "changed" or the reason (race between Approve and expiry). An unapproved send (allow rule,
  `never`, auto-approved read) re-plans and uses the IDs of its own plan.
- A value is used when it is live at the moment `Send` reads it, which is after approval. After
  that read, expiry no longer matters for the request in flight.
- Approval decision is unchanged by kept use: allow rules, `apiApproval: never` and
  `agentAutoApproveReads` still skip the card. Reason: those are explicit user trust settings; a
  forced prompt would make every chain step noisy and contradict P595. The op log command names
  the variables (template), so a skipped card still leaves a trace.
- Masking: values of `Secret` entries a request used join the request's mask (`newMask` gets extra
  values), so a response echoing a P679 value is masked. Non-secret kept values are not masked in
  responses: a server echoing ids is server data, and masking ids would break normal results.

### Logging

Op log command is the template (`{{kept.ids}}`). Bridge logs internal faults only (static message,
`err` key, `scope: "keptvars"`).

### Script hook (the contract P676 leaves room for)

P676's planner should keep two things so Part 2 adds no restructuring: `jsengine.Run.Bindings`
built as a slice the caller can append to, and one point where the agent-bound result is final
(after the P677 review approves, or right after the transform when review is off).

```go
type keptStage int // keptBeforeSend (read only), keptAfterResponse (read and set)

type keptRun struct {
	scope  string
	reads  map[string]keptvars.Entry // snapshot at plan, by name
	sets   map[string]bool           // names the source declares
	staged map[string]json.RawMessage
	secret [][]byte                  // secret values read, for the output mask
}

func (s *Server) keptRunFor(scope, source string, stage keptStage) (*keptRun, error) // plan time
func (k *keptRun) Bindings() []jsengine.Binding                                       // one: "kept"
func (k *keptRun) Commit(src keptvars.Source) ([]keptSummary, error)                  // Put staged
func (k *keptRun) Uses() []agentapi.KeptUse                                           // card, Field "script"
```

- Binding `kept` with `Funcs{"get", "set"}` (`set` only at `keptAfterResponse`). `get(name)`:
  name must be in `reads` (declared by a literal `kept.get("name")`) and the entry still live with
  the planned ID, else the script gets `Error("kept variable \"x\" is not listed in this script")`
  or the expiry text. `set(name, value)`: name declared by a literal `kept.set("name", ...)`,
  `ValidName`, value ≤ 1 MiB, at most 16 per run; staged only.
- Aliasing (`const k = kept; k.get(n)`) or computed names reach only declared names, because the
  host function checks the declared set. So the card's "may read" and "will keep" lists are
  complete.
- Card: script sites highlighted (`Field "script"`); reads appear in `KeptVariablesPanel` like
  request uses; declared sets listed as "This script may keep: summary".
- Commit: after the final point; a denied P677 review, a script error, a send failure or a cancel
  drops the staged values (user rejected or nothing completed). The agent result gains `kept:
  [{name, type, items, expiresInSeconds}]`. P677's review card shows staged values under "Will
  keep" with `KeptValueView` (preview only, from the held staged bytes).
- Output masking: secret values the script read join the transform output mask (P679 path).
  Non-secret reads returned by the script on purpose are visible in the card (the `kept.get` site
  is highlighted and the panel shows the value); the card adds a neutral note "This script reads
  kept variables; its output goes to the agent".
- Expiry during the approval wait: reads join the `OnRemove` set of `approveAPI` (same cancel and
  texts as request uses).
- DB MCP (P680): same `keptRun` from the `dbmcp` package, same panel; P680 binds kept values into
  SQL as parameters (its own decision).

## Risks

- Offsets drift between Go sites and the rendered text (URL slicing, pretty-printed JSON). Mitigation:
  sites in UTF-16 units on the exact payload strings; the pretty body re-scans with the shared
  regex; UI spec asserts every highlighted mark text equals `{{kept.<name>}}`.
- An agent loops `Put` to fill memory: caps refuse, never evict.
- Value expiring during the 10 min approval window cancels the item: the agent must redo the
  producing call. Accepted (spec: short retention, no silent refresh); the "expires before you
  answer" tag warns the user early.
- External clients share one scope (stateless transport). Two external agents can read each
  other's names and use each other's values. Accepted and stated in ARCHITECTURE; session-server
  agents are isolated.
