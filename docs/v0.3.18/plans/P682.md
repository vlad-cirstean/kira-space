## Decision

TanStack mutation state owns every write's pending and error. `useAsyncAction` stays the one
adapter, rebuilt on `useMutation`; local refs are retired.

- Local ref: declined. It is a hand copy of `useMutation`'s state machine (`isPending`, `error`,
  `reset`), which CLAUDE.md forbids. No requirement it meets that a mutation cannot.
- `useAsyncAction` as a ref composable: declined as an implementation, kept as the API. Today it is
  a second state machine beside TanStack's; rebuilt on `useMutation` it is the shared errorText
  mapping over the library's state, not a hand equivalent. It also fixes overlap: today the first
  of two overlapping runs clears `pending` and an older failure overwrites a newer run's state;
  `MutationObserver` follows the latest run only.
- Raw `useMutation` state in a component: kept for pending (`m.isPending` on a button) and for
  error read as `errorText(m.error)` at display (already one owner, see "Conforming"). A component
  never wraps `m.mutateAsync` in its own try/catch ref and never wraps a single mutation call in
  `useAsyncAction` (two observers for one write).

Rule (goes to ARCHITECTURE.md): a write's pending and error come from its TanStack mutation:
`useMutationAction(m)` for a mutation from a queries file, `useAsyncAction(fn)` for any other
awaited call, `useTaskAction()` for one error surface fed by several writes; `describe` maps or
hides the text, `cause` gives the coded error for branching; never a hand ref.

## Shared API

File `packages/workbench/src/behaviour/asyncAction.ts` (U39-U63 never scan `/behaviour/`).

```ts
export interface AsyncAction<Args extends unknown[]> {
  run: (...args: Args) => Promise<boolean>; // false after a failure; never throws
  pending: ComputedRef<boolean>;
  error: ComputedRef<string | null>;        // describe(cause); null when none or hidden
  cause: ComputedRef<CodedError | null>;    // toCodedError of the failure, for code branches
  reset: () => void;
}
export interface AsyncActionOptions {
  describe?: (err: unknown) => string | null; // default errorText; null hides (a cancel)
  queryClient?: QueryClient; // only a Pinia store unit-tested without an app
}
export function useAsyncAction<Args extends unknown[]>(
  action: (...args: Args) => Promise<unknown>, opts?: AsyncActionOptions,
): AsyncAction<Args> & { fail: (err: unknown) => void };
export function useTaskAction(opts?: AsyncActionOptions):
  AsyncAction<[task: () => Promise<unknown>]> & { fail: (err: unknown) => void };
export function useMutationAction<TData, TVars>(
  mutation: UseMutationReturnType<TData, unknown, TVars, unknown>,
  opts?: Pick<AsyncActionOptions, 'describe'>,
): AsyncAction<[vars: TVars]>;
```

Implementation:

- `useAsyncAction`: one `useMutation<unknown, unknown, () => Promise<unknown>>({ mutationFn:
  (task) => task(), networkMode: 'always', gcTime: 0 }, opts.queryClient)`. `run(...args)` =
  `mutateAsync(() => action(...args))` in try/catch returning a boolean. The variable is a thunk so
  typed values (secrets in `ConfigSecretsSection`, run file secrets) are not kept as plain mutation
  `variables`; `gcTime: 0` drops settled, unobserved mutations at once. `networkMode: 'always'`:
  TanStack's default `online` mode pauses a mutation while `navigator.onLine` is false, and these
  actions are local bridge calls (desktop) or paired-desktop calls (phone) that must fail, not hang.
- `fail(err)` = `mutate(() => Promise.reject(err))`: records an outside failure (a child's error,
  a `reviewCode.open` `onError`, a non-throw result) through the same owner. `mutate` swallows the
  rejection, so no empty catch (U61, U81).
- `useTaskAction(opts)` = `useAsyncAction((task) => task(), opts)`.
- `useMutationAction(m)`: `run(vars)` = `m.mutateAsync(vars)` in try/catch; `pending` =
  `m.isPending`; `cause`/`error` from `m.error`; `reset` = `m.reset`. Reads the mutation's own
  observer; adds none.
- Doc comment replaces the current one with the rule above.

Plain-ref writes become: `x.error.value = null` → `x.reset()`; a custom message set into the action
(`connectionLost`, `nothingToRun`) → `throw new Error(t(...))` inside the action; a non-throw
failure result → throw inside the task or `fail(text)`.

App roots: `provideShellServices(app, queryClient)` in `packages/workbench/src/bootstrapShell.ts`
also installs `VueQueryPlugin` with that client. Callers: `src/main.ts` (desktop `queryClient`,
drop its own `app.use(VueQueryPlugin)`), `mobile/main.ts` (its remote client, same), git-ui
`main.ts` (desktop `queryClient` from `@workbench/state/queryClient`; git-ui is desktop only),
`reviewDecorations.ts` (each `createApp` at :222, :280, :488, :508; desktop client).

`useInlineEdit` (`behaviour/inlineEdit.ts`): commit runs through `useAsyncAction(opts.commit)`;
`pending` = action pending; `error` = `computed(() => action.error.value ?? '')`; `onCancel` and a
successful commit call `reset()`. Keeps `pending || settled` double-commit guard and the `once`
rule.

Tests (unit-test bar: concurrency ordering only):
`packages/workbench/src/behaviour/asyncAction.spec.ts`, bun, inside `effectScope` with
`createQueryClient({ remote: false })` passed as `queryClient`:
1. Overlapping runs: run A (rejects late), run B (resolves); `pending` stays true until B settles,
   A's late rejection leaves `error` null.
2. Older run rejects first while newer still pending: `error` stays null, `pending` true.
Nothing else: `describe`, `fail`, `reset` and `useMutationAction` are thin pass-throughs.

Placement rule for every site:

- One mutation call, nothing after it that can throw: `useMutationAction(m)`.
- A handler with steps after the write (open, copy, reload) or a non-mutation call: `useAsyncAction`
  over the handler.
- Several handlers into one Alert or FieldError: `useTaskAction()`, each handler `surface.run(...)`.
  Per-button spinners keep `m.isPending`.
- Template: same element, same testid, text from `.error`; `v-if="x.error.value"` in script,
  `x.error` unwrapped in template.
- Dialog open/close watchers that cleared the ref call `reset()`.
- Enter-to-submit forms keep their `if (x.pending.value) return` guard.

## Behaviour changes

- Latest run wins: an older run's late failure no longer replaces a newer run's state, and
  `pending` stays true until the newest run settles (rows toggled concurrently in
  `ScriptsMcpSection`, `KubeMcpSection`, `StudioMcpKeptPane` show only the last row's failure).
- Error clears on retry as before (a new run starts with `error` null) and on `reset()`.
- Children that emitted error text (`AdeShelfSection`, `LaterShelf`, `DiscoverSavedControls`) emit
  `run` with the task; the parent runs it on its surface. Same element, text and timing.
- `AdeTaskBranchMenu`/`AdeMainBranches` keep emitting text (one parent writes a keyed store);
  `AdeMainTab` records it with `surface.fail`.
- `startScript` and `useRerun` (`automations/runScript.ts`) throw (a blocker as `new Error(blocker)`)
  instead of returning text; callers show it through their action. Same text.
- `ResponseDiffDialog` snapshots load through `useQuery` + `QueryState` (U54): loading becomes
  QueryState's InlineState loading (same component today), failure becomes QueryState's inline
  error with Retry (was a bare error Alert, no retry).
- No copy change, no new catalog keys.

Visible-change list for the chapter-end visual re-record: `http-diff-dialog` load failure (QueryState
error with Retry). Eyeball only (same pixels expected): `ade-capture-note`, `ade-port-error`,
`generate-data-error`, `boot-error` (git-ui), `config-sync-pane-error`, `comment-error`.
