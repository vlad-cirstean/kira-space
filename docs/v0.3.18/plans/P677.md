# P677: API MCP: result review with raw and transformed views

Planner: Opus. Implementer: one sequential Sonnet subagent. No streams: broker kind, review step in
`deliverAPI`, settings, pending-response wire, generic review component and kind body are one
order-dependent chain over shared payload types.

Starts only after P676 has landed on `chapter/v0.3.18` (`dbmcp/jsscript.go`, `api_script.go`,
`deliverAPI`, `apiOutcome`, `JsScriptBlock.vue`, `Result.Mask`). Written against `plans/P676.md`
and the tree at `7adccd575` (P675 landed; P676 and P678 Part 1 in flight). Where landed P676 code
differs from its plan, follow the code and note the binding in Result.

Spec row: the DB MCP has a review step for results. Check whether the API MCP has an equivalent; if
not, add it. Before anything returns to the AI the user sees the raw response (status, headers,
body) and the result after the JS transform, as two views of one review, plus the script that
produced it. The user approves or denies what the agent receives. Follows the shared approvals
surface (P520) and its item bodies. Settings: whether results are reviewed, mirroring the DB
connection option.

## Decisions

### Where the review sits

One point: the top of P676's `deliverAPI`, the single function that turns an outcome into the
agent's tool result. P677 routes every post-send path through it, including the no-transform path
P676 left as `jsonResult(raw)`:

```go
// apiRequest tail after P677:
raw, err := s.cfg.API.Send(ctx, in, &plan)
if err != nil {
	return errResult(err.Error()) // no response: not reviewed (below)
}
o := apiOutcome{Raw: raw}
if sc != nil && sc.Transform != "" {
	o = s.transformAPI(ctx, plan, sc, raw)
}
return s.deliverAPI(ctx, plan, sc, o, requested)

func (s *Server) deliverAPI(ctx context.Context, plan agentapi.Planned, sc *apiScripts, o apiOutcome, requested bool) (*mcp.CallToolResult, any, error) {
	res, out, err := apiAgentResult(sc, o) // P676 body: Failure -> errResult; transform -> {"result":…}; none -> jsonResult(o.Raw)
	// Read after the send: the user may change the setting while the request runs.
	if rv := s.apiReviewFor(plan, sc, requested); rv.On {
		if refusal := s.reviewAPI(ctx, plan, sc, o, rv, res, err); refusal != "" {
			return errResult(refusal)
		}
	}
	// Final point: the agent gets res. P678 Part 2 commits staged kept values here.
	return res, out, err
}
```

- Reviewed exits: every exit after a response arrived: plain response, transform result, transform
  failure (runtime, timeout, output cap, input too large). The transform failure text carries the
  HTTP status (P676 rule); the user sees it before the agent does.
- Not reviewed: `Send` errors (re-plan mismatch, blocked host or redirect, transport failure,
  timeout). They carry no response data, only app-authored or masked transport text, like the DB's
  "exits before Execute". Also not reviewed: every refusal before send (plan, approval, prepare
  script).
- Review is independent of the pre-send approval: it applies when the request needed no approval
  (allow rule, `apiApproval: never`, auto-approved read), as the DB reviews an `allow` verdict.
- Approved: `res` is returned untouched. The held `Text` is `resultText(res)` (or `err.Error()`
  for a bare Go error, the go-sdk rule `reviewResponse` already relies on), so Send returns exactly
  the bytes the user saw.

### When results are reviewed (settings, mirroring the DB connection option)

DB shape: app leaf plus per-connection per-mode `inherit|review|send`. API equivalent of a
connection is the environment (it already holds `agentAutoApproveReads`).

- App leaf `dbMcp.apiReviewResponses` (Go `APIReviewResponses bool`, patch pointer, default
  `false` in `DefaultSettings`, zod `z.boolean().default(false)` in every settings default block of
  `settingsDomain.ts`). Default off mirrors `previewResponses`. No migration (missing leaf reads the
  default). `bridge.apiSettings()` maps it to `dbmcp.APISettings.ReviewResponses`; its read-failure
  fallback sets `ReviewResponses: true` (fail closed, as `previewResponses`).
- Environment file key `agentReview: {read, write}`, each `inherit|review|send`, default inherit;
  an inherit value is left out of the file, and the object is left out when both are inherit
  (connection `mcp.review` rule). Go `apifiles.AgentReview{Read, Write string}` with
  `json:"read,omitempty"` etc., field `AgentReview *AgentReview \`json:"agentReview,omitempty"\``
  on `EnvironmentFile`; schema `environment.schema.json` object, `additionalProperties: false`,
  enum `["inherit","review","send"]`, descriptions as the connection schema ("Response review per
  request class. An unset class is inherit. inherit follows the app setting; review always holds
  responses for a look; send never holds them."). Collection files keep refusing agent keys (their
  schema has none). `agentapi.EnvInfo` gains `Review apifiles.AgentReview` (or its own two-string
  struct), copied in `envInfoOf`. A value outside the enum is a file problem (schema), and the last
  good file stays in force (existing `EnvironmentRef` rule).
- Class: read = `isReadMethod(method) && !plan.HasBody()` (the same rule as
  `agentAutoApproveReads`), else write. A GET with a body is write: stricter wins, as the DB's
  declared-mode-or-class rule.
- Resolution, `dbmcp/api_review.go`:

```go

// apiReviewSetting: the environment's value for the class, inherit reads the app leaf.
func (s *Server) apiReviewSetting(env agentapi.EnvInfo, read bool) bool
```

  A request with no environment uses the app leaf. Setting wins over requested for `Reason`
  (`setting` when both).

### Approvals kind and what is held server-side

- New kind `approvals.KindAPIResponse = "api.response"` in `internal/approvals/queue.go`, added to
  `newApprovalBrokerCaps`'s registered list. Item id `api.response:<requestId>`.
- `ApprovalRequest` for the review: `Subject: KindAPIResponse, Stage: ApprovalStageResponse, API:
  &plan, Response: &held, ConnectionName: plan.Host, Kind: "http", Class: ClassUnknown, Statement:
  plan.Method + " " + plan.URL, Reason: ApprovalReasonPermission, Origin: originFrom(ctx)`.
- `ApprovalResponse` gains two generic fields (P680 Part 2 reuses both names):

```go
type ApprovalResponse struct {
	Text      string // exact TextContent the agent receives on Send
	IsError   bool
	Bytes     int    // len(Text)+len(Raw)+len(Script.Source): what the caps count
	Requested bool
	// Raw is the response the script read, set only when a script produced Text.
	Raw string
	// Script is the script that produced Text from Raw; nil without one.
	Script *HeldScript
}

type HeldScript struct {
	Source string
	Hash   string // jsengine.SourceHash
}
```

- API values: `Text` = held agent text (above). `Raw` (only with a transform) = compact JSON of the
  masked `agentapi.Result` the transform read (P676: body up to `transformBodyBytes` 2 MiB, masked,
  `Result.Mask` applies). `Script` = transform source and hash from `apiScripts`. Without a
  transform `Raw` is empty and the card renders `Text` as the response (they are the same bytes).
  Prepare scripts are not held: the pre-send card showed them.
- Caps: the existing 8 MiB per result and 64 MiB total, counted on `Bytes`. API worst case is about
  2.2 MiB raw plus 512 KiB text plus 64 KiB script, so `ApprovalTooLarge` is reachable only through
  `SetHeldCaps` in tests; the text exists anyway. Bytes drop on every exit (existing broker rule).
  Memory only: never SQLite, op log, audit payload or slog.
- Snapshot payload `apiResponsePayload` (fans out to every Studio window, so no body, text, raw or
  script):

```json
{"method":"POST","url":"https://api.example.com/v1/users","host":"api.example.com",
 "environment":{"id":"…","name":"Staging","color":"amber"},
 "status":201,"statusText":"Created","isError":false,"scripted":true,
 "bytes":1234,"rawBytes":56789,"class":"write","reason":"setting"}
```

  `url` is the plan URL (secrets as `{{name}}`), `status`/`statusText` from the masked result,
  `isError` true for a transform failure, `class` read|write, `reason` setting|requested (P679
  extends the enum). zod `apiResponsePayloadSchema` in `packages/shared/domain/dbmcp.ts`.
- `itemOf` case `KindAPIResponse`: Reason `preview`, Target as `apiItemParts` (host, env colour and
  name), Operation `{Class: "request", Tone: methodTone(method)}`. `promptTitle` case:
  `backend.prompt.dbMcpAPIResponse.title` "Response from {host}: {method}" (new backend i18n key).
- Pending-response wire (one IPC method, no new binding): `DbMcpPendingResponse` gains `Raw string
  \`json:"raw"\`` and `Script *PendingScript \`json:"script"\`` (`{source, hash}`), filled from
  `ResponseFor`. zod `dbMcpPendingResponseSchema` gains `raw: z.string().default('')` and `script:
  z.object({source: z.string(), hash: z.string()}).nullable().default(null)`. Regenerate Wails
  bindings per DEV_ENVIRONMENT. P680 Part 2 uses `hash`, not its plan's `sha256` (its plan says to
  reuse P677's names). P678 Part 2 adds `willKeep` here.

### Deny, timeout and the agent-facing texts

`apiHeldRefusal(outcome ApprovalOutcome, plan agentapi.Planned, read bool, size int) string` in
`api_review.go`. App-authored, never response data: no status, header or body (the status the
user withheld is response data). `<req>` = `<METHOD> <host>`.

| Outcome | Text |
|---|---|
| Denied | `the user withheld the response to <req>; the request was sent, but you get no response. Do not resend it to get the response another way.` |
| TooLarge | `the <req> request was sent, but its response is N.N MB, over the 8 MB review limit, so it was withheld unseen.` read: ` Ask for less: narrow the request or reduce the response with a transform script.` |
| HeldFull | `the <req> request was sent, but too many results are waiting for the user's review, so its response was withheld. Do not resend it.` |
| TimedOut | `the <req> request was sent, but its response got no review within 10m0s and was withheld.` (`approvalWindow()`) |
| Abandoned | `the Studio MCP server stopped before the response to <req> was reviewed; the request was sent and its response was withheld.` |
| QueueFull | `the <req> request was sent, but too many requests are waiting for approval, so its response was withheld. Do not resend it.` |
| Turned off during review | `the <req> request was sent, but API requests were turned off in Kira Space's Studio MCP settings while its response was in review, so it was withheld.` |
| other | `the <req> request was sent, but its response was not approved.` |

- `apiSentSuffix(msg, read)`: write class appends ` Its effects stay.` and ` Do not resend it.`
  unless the text already says "not resend" (`ranSuffix` rule). Read class gets neither.
- Recheck on approve (`recheckAPIHeld`): `s.apiEnabled()` must still hold, else the "turned off"
  text. No mask re-check: the held text was masked by the request's own masker at send time, and
  unlike DB mask rules no user setting can change what that masker covers mid-review without the
  user also seeing the response. Stated in ARCHITECTURE.
- Client cancel or disconnect: broker abandons through ctx (existing), the agent is gone.
- Timeout is the broker's `ApprovalTimeout` (10 min), as every approvals kind.

### Interaction with P678 Part 2 (held writes) and P679 (forced review)

- P678 Part 2 commits staged kept values at the "final point" comment in `deliverAPI`, only when the
  agent gets `res`. Every review refusal returns before it, so withhold, timeout, abandon,
  too-large, held-full and turned-off drop staged values. Its agent `kept` summary (names, types,
  items, no values) must be built into `res` inside `apiAgentResult`, before the review, so the
  reviewed `Text` stays the exact bytes sent; only the commit waits. Its "Will keep" block (staged
  previews) rides in `ApprovalResponse` and `DbMcpPendingResponse.willKeep` (counted in `Bytes`) and
  renders in `ResultReview`'s `after` slot. P677 leaves the slot and the comment; it adds no kept
  code.
- P679: `apiReviewFor` gains the forced case (a script that read a user value) with `Reason:
  "userValue"`; the pre-send card then shows `reviewResult: true` (tick checked and disabled) when
  the read is known at plan time; `apiResponsePayload.reason` zod enum gains `userValue`; P679's warn
  risk tag goes in `apiResponseRisks`. Held `Raw`, `Text` and error text already pass the request
  mask P679 extends (`Result.Mask`, `maskResult`), so the review payload needs no extra hook.
- The review never changes what was sent or the approval class; it only gates delivery.
