# P679: API MCP: user-supplied values the agent never sees

Planner: Opus. Implementer: one sequential Sonnet subagent. No streams: tool argument, plan
checks, broker transport, store write, masking and card are one order-dependent chain.

Spec row: agent declares an input (name, label); user types the value in the approval UI; agent
never sees it; value is reusable by name afterwards through the P678 store and retention, marked
user-supplied and secret (masked by default, reveal on demand); request and script reference it
like any kept variable. Never logged, never in op log or history, never in prompts; redaction
applies to responses that echo it. Plan covers entry UI, reuse within retention, clearing, what the
agent is told (an input exists, never its content).

Runs after P676, P677 and P678 Parts 1 and 2 (table order). Their code is the base. P678 Part 1 is
planned in `plans/P678.md` and was mid-implementation at planning time (stream
`stream/v0.3.18-p678`: store, agentapi kept resolution, `list_kept_variables`, `KeptVarsService`
landed there); P676/P677 had no plan yet. Where this plan names a P676/P677 seam, implementer
binds it to what those phases left and records the binding in Result.

## Decisions

### Tool shape: `inputs` argument on `api_request`

```json
{"method": "GET", "url": "https://api.example.com/me",
 "headers": [{"name": "Authorization", "value": "Bearer {{kept.token}}"}],
 "inputs": [{"name": "token", "label": "Personal access token"}]}
```

- `apiRequestArgs.Inputs []apiInput{Name, Label}`; `agentapi.Input.Inputs []InputDecl`.
- Rejected: separate tool (`request_user_input`). It would collect a value with no request in
  view, its own approval kind, and no host to bind to. Spec puts entry in the request's approval UI.
- Rules, checked at plan (error text in quotes, never a value):
  - at most 4: "a request can declare at most 4 inputs";
  - name `keptvars.ValidName`, unique in the list;
  - label: 1 to 80 runes after trim, no control characters: "input \"token\" needs a label of 1 to
    80 characters on one line";
  - each declared name used at least once as `{{kept.<name>}}` in the request, or read by a literal
    `kept.get("<name>")` in the request's script (P678 Part 2 `ScanScript`): "input \"token\" is
    declared but not used; write {{kept.token}} where the value goes";
  - a live entry of the same name in the scope that is not `SourceUser`: "\"token\" is already a
    kept variable made by a script; choose another input name";
  - a live user entry of the same name bound to another origin: "the value kept as \"token\" was
    supplied for https://a.example; choose another input name for https://b.example";
  - positions follow P678 (`{{kept.*}}` never in scheme, host or port; no pipeline). A pending input
    is checked as a one-line string: allowed in path, query, header, form, body; in a JSON body
    unquoted (Kira inserts a JSON string);
  - room: live entries in scope plus missing inputs over the P678 per-scope cap: P678 cap text.
- Undeclared `{{kept.token}}` naming a live user entry works like any kept use (reuse), host check
  included. Undeclared and absent: P678 "no kept variable" text, now ending "...; to ask the user for
  it, declare it in inputs".

### Input states and the approval

Per declared input at plan, `agentapi.InputUse{Name, Label, State, KeptID}`:

| Live entry in scope | State | Card | On approve |
|---|---|---|---|
| none | `needed` | value field, required | `Put` new user entry |
| user, same origin | `stored` | masked row, "Enter a new value" disclosure | reuse; replace if a new value was typed |
| user, other origin | refused at plan | none | none |
| other source kind | refused at plan | none | none |

- Approval decision: any `needed` input forces the card, whatever allow rules, `apiApproval:
  never` or `agentAutoApproveReads` say: the card is the only entry point. `needsAPIApproval(st, p)
  || p.MissingInputs() > 0`. With every input `stored`, P678 rules apply unchanged (allow rule or
  `never` sends without a card; op log shows the template).
- User types empty or only whitespace: Approve stays disabled with reason "Enter {label} to send".
  Go also refuses (below); item stays pending with the error tag. Value is trimmed at both ends
  (pasted tokens carry newlines); inner control characters refused ("a value must be one line of
  text"); max 8 KiB ("a value can be at most 8 KiB"); valid UTF-8.
- Deny: renderer sends no inputs; Go discards any it gets on deny. Agent text: existing "request was
  denied by the user" plus "; no value was kept for \"token\"" (names of `needed` inputs). Stored
  values stay.
- Timeout, client cancel, server stop, item abandon: nothing stored; existing outcome texts plus the
  same suffix.
- Stored value expires, is cleared or replaced while the card waits: P678 `watchKept` cancels the
  item. P679 adds to that text for a user entry: "Repeat the request with the same inputs; the user
  will be asked again."
- Put fails after approval (cap race, store closed): nothing sent, value wiped, agent gets "the value
  for \"token\" could not be kept (<fixed store error text>); nothing was sent".
- Replace: a typed value for a `stored` input `Put`s under the same name (same kind, so allowed):
  new ID, fresh expiry, old entry fires `replaced` (other pending items using it cancel with P678
  text). `watchKept` of this item is stopped before the `Put`.

### Transport: values ride the approve answer, nowhere else

- Renderer: Pinia `state/approvals.ts` gains `inputs: Record<itemId, Record<name, string>>`,
  `setInput(id, name, value)`, cleared in `done`, `prune` and after a successful answer; kept on
  `fail` so the user can correct. `useApprovalActions.answer` merges `{inputs}` into an item's
  options only when `approve` is true. Generic: any future kind with typed secrets uses it.
- `useAnswerApprovals`: `gcTime: 0`; `answer` calls `mutation.reset()` after settle, so variables
  holding a value leave the mutation cache and observer.
- Go: `brokerOwner.Answer` decodes approve options into `answerOptions{ApprovalChoice fields...,
  Inputs map[string]string}` (unknown fields still refused). `ApprovalChoice` stays comparable;
  inputs travel as `approvalResolution.inputs SuppliedInputs` (`map[string][]byte`).
- `ApprovalRequest.Inputs []ApprovalInput{Name, Label, Needed bool}` (declared, for validation).
  `answer` checks under `mu` with the entry: every `Needed` name present and non-empty after trim;
  every given name declared (a `stored` name may be given: replace); size, UTF-8, control chars.
  Failure: `ipcerr.Contract` with fixed text naming the label, item pending. Inputs on a kind without
  declared inputs: "this approval takes no inputs".
- `RequestInputs(ctx, req) (ApprovalOutcome, ApprovalChoice, SuppliedInputs)`; `RequestChoice`
  wraps it and wipes inputs. Every non-approve path wipes. `SuppliedInputs.Take(name) []byte`,
  `Wipe()` zeroes bytes Kira owns. Best effort: Go strings from JSON decoding are not wiped; stated
  in ARCHITECTURE.
- Observer and audit see `ApprovalRequest` only (labels, never values). `dbaudit` stores subject,
  reason, stage: unchanged.

### Store: reuse P678 `keptvars`, additive only

- `Meta.Origin string \`json:"origin,omitempty"\``: `scheme://host[:port]` of the request a user
  value was supplied for, normalised the way `agentapi.sameTarget` compares hosts (lowercase host,
  default port dropped). Set only for `SourceUser`.
- Entry: `Put{Scope, Name, Value: json string, Secret: true, Source{Kind: user, MCP: "api", Tool:
  "api_request", Request: template display text, Client, TaskID, SessionID}, Origin}`. Retention,
  caps, sweeper, scopes, `ClearScope` on session release, `Close` on quit: P678 unchanged.
- `Store.Secrets() []Entry`: live secret entries of every scope, copies (mask building).
- `keptvars/forms.go` (stdlib only): `SecretReplacer(entries []Entry) *strings.Replacer` maps each
  value's forms to `{{kept.<name>}}`, longest first. Forms: raw, JSON-escaped; for values of 8 bytes
  or more also `url.QueryEscape`, `url.PathEscape`, base64 std and raw-URL. `SecretRaw(entries)
  []string` raw values for the fallback `secrets.Masker`. P680 builds its result mask from the same
  two functions: no fork.
- Scripts: P678 Part 2 already refuses `kept.set` over a user entry (`ErrNameTaken`).

### Host binding

- A user value goes only to its origin. Plan refuses another origin (text above). `redirectGuard`
  treats a request using a user value like one holding a credential bound to the origin host: a hop
  off that scheme, host and port is blocked (the first hop reaches the server only). Header values
  are already stripped cross-host by httpclient; the guard covers query, path and body.
- Why: an allow rule or `never` sends a reuse without a card; without the binding an agent could
  send a token anywhere a rule allows.

### Masking and where the value may never appear

`agentapi.mask` gains the kept replacer over `Store.Secrets()` (all scopes, not only values the
request used) and the raw values join the `secrets.Masker` fallback. `mask.repl` becomes one
`*strings.Replacer` built from the combined pattern list (env secret forms from
`apivars.UsedSecret` plus kept forms), so `WireMask` stays one replacer. Applied to:

| Surface | How |
|---|---|
| `api_request` result (status text, headers, final URL, redirects, body) | `maskResult`; truncated body tail cut uses max length over both sets |
| Send and op errors | `m.text` (existing) |
| Op log command and error | template URL through `m.text` (existing) |
| httpclient wire capture | `WireMask` |
| P676 script output and script errors to the agent | same mask on the agent-bound text |
| P676 prepared request shown in the card or op log | template forms only; any script-derived text passes the mask before a payload |
| P677 review payload (raw and transformed views) | same mask: the queue snapshot fans out to every window |
| Approval item payload | template only; `inputs` carry name, label, state, entry meta |
| `list_kept_variables`, kept tool texts | names, `source.kind`, `secret`, expiry; never value or length |
| slog | never; Wails binding log redacted (below) |
| dbaudit, history, prompts, ADE transcripts | never reach them: inputs live only in broker resolution and store; agent text is masked |

Result scripts (P676) that read a user value with `kept.get`: allowed (spec: scripts reference it
like any variable), host function returns the value. A transform can defeat a mask (reverse, hash,
re-encode), so such a call always goes through the P677 review (forced like `ReviewOn`), and the
review card shows a warn tag "Script reads a value you supplied: check the output before sending".
Request-prep scripts that read one run after approval or show only template forms in the card,
whichever P676 left; implementer binds and states it in Result.

### Reveal and clearing

- `KeptVarsService.Reveal(args{id, confirmed}) (KeptReveal, error)`: `localauth.Gated` over the app's
  one `*localauth.Authorizer` (5 min grace shared with connection and variable reveals), reason "show
  a value you supplied to an agent request"; outcome strings as `apivars.RevealResult`; fetch is
  `Store.ByID` (live, secret, any kind). `Value` keeps refusing secrets. Gone entry:
  `ipcerr.NotFoundNamed("kept variable")`.
- Renderer: plaintext never enters TanStack Query or Pinia. Declined: a `useQuery` for reveal,
  requirement: plaintext lives only in the component showing it and dies with it; the query cache
  outlives components until `gcTime`. `useKeptReveal(id)` composable calls the bridge through
  `runReveal` (reuse `studio/api/reveal.ts`; if the module boundary lint refuses the import, move
  `runReveal` to a shared Studio location in the same commit), holds the value in a local `ref`,
  hides it after 60 s (VueUse `useTimeoutFn`) or on unmount. Copy (VueUse `useClipboard`) only
  while revealed.
- Clearing: P678 `Clear`, `ClearAll`, session end, quit, expiry. Clearing zeroes value bytes (P678).
  No new clear path.

  requests to the same host (default 1 hour). A request with a value still missing always waits for

## Risks

- Agent-chosen label can phish ("enter your bank password"). Mitigation: description names the
  agent as asker, the kept name and the only origin it goes to; host binding limits damage.
- Masking misses transformed forms. Mitigation: response forms above; scripts reading a value force
  review; open item recorded.
- Value in renderer memory between typing and answer (Pinia, mutation variables). Mitigation:
  approve-only send, `gcTime: 0`, `reset()`, store cleared on done and prune.
- P676/P677 seams unknown at planning: implementer binds them and states the binding in Result.

## User decisions

1. Result scripts may read a user value, and such a call is always reviewed (alternative: refuse
   `kept.get` on user values entirely). Plan picks review to honour "script references it like any
   variable".
2. User values are bound to the origin they were supplied for; reuse elsewhere is refused (new name
   needed). Alternative: no host binding.
3. A missing input forces the card even under allow rules or `apiApproval: never`.
