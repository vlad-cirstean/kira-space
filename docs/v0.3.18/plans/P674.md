# P674: Full-app UI uniformity audit

Planner: Opus. Master plan: defines Parts, discovery method, triage, guards, iteration gate and
final scan. Part 1 is implementable from this file alone. Every later Part gets its own Opus file
(`P674-iter1.md`, `P674-iter2.md`, optional `P674-iter3.md`, `P674-final.md`) written against the
tree as it stands then.

Spec row: same method as v0.3.17 P672, whole app, no subject list. Find reimplementations and
variation a subject list cannot name. Each finding names its shared home. Fresh scan per
iteration, final all-subject scan last, carry-forward items listed.

User goal: uniform, centralised UI with one design pattern per job. Accessibility is not a goal:
no finding exists only for a11y; existing a11y wiring (aria, sr-only, live region) stays as is.

## Part 1: audit tool

Discovery only, never wired into `lint` or hooks (heuristic, noisy by design). Enforcement stays in
guards. Bun TS under `scripts/uiaudit/`, run as `bun run audit:ui [--channel <id>] [--out <file>]`
(add script to root `package.json`). Stateless: no ledger, allowlist or baseline read at runtime.
Output: one markdown report to `--out` (default stdout), sections per channel, each cluster with a
stable key (sha1 of normalised signature, 10 hex), size, file:line sites, module set. Clusters
sort by module spread, then site count.

Scan set: `DIRS` of `check-ui-primitives.sh` plus `CORE_DIRS`, excluding
`packages/theme/src/components/ui/`, `/testing/`, specs, `.d.ts`, generated `wire`/`bindings`.
Module of a file = first path segment that names an area (`studio/api`, `studio/kubernetes`,
`studio/docker`, `studio/views/<view>`, `ade/v2/<area>`, `repo`, `hostview`, `mobile`, package
name, ...); table in `modules.ts`.

Channels (each its own file, one `run.ts` dispatcher):

- C1 template subtrees (`templates.ts`). Parse each `<template>` with `@vue/compiler-sfc`. Normalise
  each element node to `tag + sorted static class tokens (via theme cn) + sorted prop and directive
  names`; drop text, interpolations and bound values. Hash every subtree of at least 4 element
  nodes. Report hashes seen in 2+ files, and near clusters: same tag skeleton (tags only) with class
  Jaccard >= 0.7 across 2+ modules.
- C2 class strings (`classes.ts`). Every static `class`, string literals in `:class`, `cva`/`cn`
  arguments and `*_CLASS` constants in `.ts`. Normalise through `cn`, sort tokens. Report exact
  sets used 3+ times in 2+ files, and near sets (Jaccard >= 0.8, 4+ tokens) across 2+ modules.
  Flag sets that equal or contain a shared constant's tokens (`rowVariants` outputs, `frames.ts`,
  `rowMeta`, `ACTION_CLASS`) without importing it.
- C3 script duplicates (`scripts.ts`). Run `jscpd` programmatically on the scan set, min 40 tokens,
  vue and ts; keep clones whose two sides sit in different files. Plus composable shape: `ref` +
  `watch`/`computed` + bridge call groups repeated in 2+ components (state logic for a composable,
  Pinia store or TanStack query).
- C4 shared-piece near-miss (`nearmiss.ts`). For every component in the shared homes, take root
  element signature, prop names and emitted events. Report module components whose signature
  matches at C1 near threshold or whose props overlap >= 60%, and which do not import the shared
  piece. Also report basename collisions: one `.vue` or composable basename in 2+ dirs.
- C5 display drift (`display.ts`, TS AST over scripts and template expressions). Calls to
  `Intl.*`, `toLocale*String`, `toFixed`, `padStart`, `Date#get*`, byte math (`/ 1024`), unit
  suffix template literals, `.slice(0, 7|8|12)` on ids, path `split('/')` for display, shortcut
  glyph strings, em dash or `-` placeholders, outside the formatter homes (`theme/format.ts`,
  `i18n/number.ts`, `workbench/behaviour/format.ts`, `shortcuts`, `Identifier`). Each hit tagged
  with the data kind (date, size, duration, count, id, path, shortcut, missing).
- C6 vocabulary (`vocabulary.ts`). Pairs of icon name and the concept next to it (catalog key or
  label of the same element, `ICON` map entry): report one concept with 2+ icons, one icon with
  2+ unrelated concepts, literal icon names bypassing `ICON` where `ICON` has the concept. Catalog
  (`packages/theme/src/i18n/en.json`): identical or case-folded-equal English under 2+ keys outside
  `common.*`, and one action key family rendered with different verbs (Remove, Delete, Discard,
  Clear) for the same IPC call or store action.
- C7 library near-miss (`libraries.ts`). Hand `addEventListener`/`removeEventListener`, `new
  ResizeObserver|IntersectionObserver|MutationObserver`, `setTimeout`/`setInterval` debounce or
  poll, `localStorage`, module-level `reactive`/`ref` shared across components, `loading`/`error`
  refs wrapped around a bridge call, raw `<select>`, `<input type="checkbox|radio">`, `<dialog>`,
  `role="menu|dialog|listbox|tab"` on plain elements, absolutely positioned popups. Known library
  exceptions documented in code comments (for example `copyText` over VueUse `useClipboard`) are
  listed with the comment so triage sees the reason.

Spec: one `scripts/uiaudit/cluster.spec.ts` for the normaliser and near-cluster thresholds (token
order, `cn` conflict folding, Jaccard boundary at 0.7 and 0.8, subtree size floor). Nothing else
gets a test. Knip already covers `scripts/**/*.ts`; keep it clean.

Done when: `bun run audit:ui` runs over the tree in under 2 minutes, every channel reports, the
spec passes, `lint` and `typecheck` pass. Commit per channel group. Document the command in one
line in `docs/DEV_ENVIRONMENT.md` (tooling section).

## Iteration Parts (Part 2, Part 3, optional iter3)

Each iteration: Opus auditor, then Sonnet waves. Fresh scan on the current tree; never reuse an
earlier report's clusters as the input list.

### Auditor (Opus, writes `P674-iter<N>.md`, commits before any fixer starts)

Prompt restates: call `codegraph_explore` (ToolSearch "codegraph"; `projectPath`
`/home/user/kira-space` or the worktree's own index once synced) before Read/Grep for every
symbol, blast-radius or caller question. Orchestrator greps its log.

1. Run `bun run audit:ui --out` to scratchpad (report is not committed; rerunnable).
2. Triage every cluster with module spread >= 2 and every C4, C5, C6, C7 hit (rules below).
3. Module sweep by hand, every area, each against the spec's open look-for list and against the
   same surface kind elsewhere: Studio (project tree, connections, grid, document, key-value,
   stream, console and kibana, charts, proof, query builder), Studio API (collections, HTTP, gRPC,
   variables, cURL), Studio Kubernetes, Studio Docker host glue and `packages/docker-ui`,
   approvals (`studio/approvals`, workbench approvals), Space repo and `packages/git-ui`, ADE
   (`ade/v2/*` every area), hostview (issues, change requests), capture, configsync, settings
   (`src/workbench/settings`, workbench settings shell), memory, automations, agents, terminal,
   op log and status bar, mobile, site tokens. Compare like with like: side panel vs side panel,
   detail pane vs detail pane, settings pane vs settings pane, list row vs list row, toolbar vs
   toolbar, empty and error vs same. Sweep findings carry channel `S`.
4. Cross-check v0.3.17 rules (`docs/ARCHITECTURE.md` "UI uniformity rules (P672)" and "UI leftover
   conventions (P267)"): an offender a guard misses is a GUARD-GAP finding (extend the guard).
5. Write the ledger, wave plan, stream table and guard list (formats below). Commit.

### Triage rules

A finding is one of:

- DUP: 2+ sites do one job with different code, markup or look.
- NEAR: 1+ site hand-builds what a shared piece, shadcn-vue, VueUse, Pinia or TanStack Query
  already provides.
- DRIFT: one concept shown, named or iconed 2+ ways (data format, label, icon, copy for one action).
- GUARD-GAP: an existing rule's offender the guard does not catch.

Not a finding (DISMISS, reason in ledger): different job that looks alike; real requirement the
shared piece cannot meet (name it); engine hosts (Monaco, xterm, SlickGrid internals); D1 board
pastels; D3 toasts; a v0.3.17 PERMANENT exemption whose reason still holds; a11y-only gaps; pure
markup similarity under 3 sites in one module with no visible divergence.

Verdict per finding:

- MIGRATE to an existing shared piece (extend its props only when 2+ sites need the option).
- EXTRACT a new shared piece. Needs 2+ consumer sites. Home by layer: `packages/theme`
  (presentational, no store or bridge import), `packages/workbench` (behaviour, stores, app
  services), module `shared/` dir when every consumer sits in one module. Library first per
  CLAUDE.md Frontend: new UI styles with Tailwind utilities, primitives from shadcn-vue, DOM
  composables from VueUse, shared client state in a single-concern Pinia store, server state
  through TanStack Query; decline only against a named requirement.
- MERGE two shared pieces doing one job into one; callers move, the loser is deleted.
- PARK: needs a design decision or work outside UI (backend contract, new feature). Becomes a
  named follow-up phase in SPEC (next free number, P682 up), never a Result line.

Every MIGRATE, EXTRACT, MERGE and GUARD-GAP gets a guard at zero offenders, or the ledger states
why no pattern exists (purely semantic). A semantic finding then gets an ARCHITECTURE rule line.
Never manufacture a finding; an iteration with nothing real says so.

### Ledger format (`P674-iter<N>.md`)

Base commit; tool report summary (clusters per channel, triaged, dismissed); then one entry per
finding:

`F<N>.<k> [DUP|NEAR|DRIFT|GUARD-GAP] <verdict>` / sites (file:line, all of them) / shared home /
change (props, API, deletions) / guard (id, kind, exempt column, regex, or reason none) / visible
change yes or no (yes feeds the chapter-end visual re-record list) / specs to run (testids or
files) / wave and stream.

Dismissed clusters: key plus one-line reason, so the next iteration's auditor can tell new from
seen.

### Guards

- Default home `scripts/check-ui-primitives.sh`: new `U<id>@@kind@@exempt@@message@@regex` lines,
  header line `# Guards U<a>-U<b>: docs/HISTORY.md (v0.3.18).`. Ids continue from U162 in ledger
  order; streams never pick ids, the ledger does.
- Cross-file checks grep cannot express (basename collisions, one component per job) go in the same
  script as a scripted block after the regex loop, one U id each, exemptions as PERMANENT lines
  with reason.
- Catalog wording guards (one verb per action family, duplicate English) go in
  `scripts/copy/check-catalog.ts`, same U id sequence.
- Zero offenders on landing. No TEMPORARY baselines (mechanism removed in v0.3.17). PERMANENT only
  with a reason naming the requirement.
- Update `docs/ARCHITECTURE.md` "UI uniformity rules (P672)": rename section to cover P674, add one
  rule line per new rule, update the guard range line (`U83-U<last>`) and the PERMANENT count.

### Waves and streams

Extract-then-migrate is order dependent, so each iteration runs in waves:

- Wave 1, one sequential Sonnet: every EXTRACT and MERGE (new or merged shared pieces in theme,
  workbench or module `shared/`), shared-piece prop extensions, `icons.ts`, `format.ts`, catalog
  key consolidation, ARCHITECTURE rules; migrates sites inside `packages/theme` and
  `packages/workbench`. No guard lines yet.
- Wave 2, module migrations. One sequential Sonnet by default. Up to 3 streams only when the
  ledger's wave-2 sites exceed about 40 and split by the ownership table below with no ordering
  dependency; each stream its own worktree off the wave-1 commit. Each stream runs every listed
  guard regex by hand (`grep -Pzl`) over its own dirs and reaches zero before handing back.
- Wave 3, one Sonnet after rebase: adds all guard lines, runs `bun run lint:rules`, fixes any
  leftover offender, commits. Remove worktrees, push.

Default stream ownership (the auditor may rebalance; it restates the table it uses):

| Stream | Owns |
|--------|------|
| A Studio | `apps/kira-space/frontend/src/studio/**` (views, api, kubernetes, docker glue, approvals, proof, charts, project, editor) |
| B Space and ADE | `apps/kira-space/frontend/src/{ade,repo,hostview,views,capture,configsync,openedfiles,components}/**`, `packages/git-ui/src/**` |
| C Shell and shared modules | `apps/kira-space/frontend/src/workbench/**`, `apps/kira-space/frontend/mobile/**`, `packages/docker-ui/src/**`, `packages/workbench/src/{memory,automations,agent,approvals,settings,terminal}/**`, `site/src/**` |

Shared files (additive hunks only, each stream's edit listed in the ledger):
`packages/theme/src/i18n/en.json` (key removals of distinct keys, no new keys in wave 2),
specs under `apps/kira-space/tests/ui/` owned by the stream owning the surface (a spec touching two
streams' surfaces stays with wave 1 or wave 3). `scripts/check-ui-primitives.sh`,
`docs/ARCHITECTURE.md`, `packages/theme/src/**` and `packages/workbench/src/{components,behaviour,lib,state}/**`
are wave 1 or wave 3 only, never touched by a wave-2 stream. A conflict outside the listed shared
files means the ownership table was wrong: stop and report.

### Iteration gate

After Part 3 (iteration 2) the orchestrator counts iteration 2's MIGRATE, EXTRACT, MERGE and
GUARD-GAP findings:

- 5 or more, or any finding in a category (DUP, NEAR or DRIFT kind plus subject) iteration 1 never
  had: insert Part 4 iteration 3; final scan becomes Part 5.
- Otherwise go to the final scan.
- Iteration 3 never triggers an iteration 4: what remains goes to the final scan.

## Final scan Part (`P674-final.md`)

Opus auditor, fresh tree, all channels C1-C7 plus sweep, plus an all-subject pass: every v0.3.17
family (forms and labels, buttons and dialogs, menus, popovers, tooltips, headings, key-value,
cards, status and tones, tabs and choice, states, icons, type, spacing, radii, frames) checked
against ARCHITECTURE rules, plus every look-for item of the spec row (reimplemented near a
primitive, two components one job, module wrappers duplicating theme or workbench, per-module
copies of layout, row, list, header, empty or error, hand-built library widgets, data shown
differently (dates, sizes, durations, counts, identifiers, paths, shortcuts), one concept with
several names or icons, duplicated state logic, inconsistent copy for one action).

Same triage, ledger, waves and guards. Exit criteria: every real finding fixed with its guard at
zero, or PARKed as a named SPEC follow-up phase. Ledger ends with a carry-forward list (PARK items
with their phase numbers; "none" if none). The Part's Result in SPEC states totals per iteration
(findings, dismissed, guards added, PERMANENT added), the visible-change list for the chapter-end
re-record, and the carry-forward list.

## Tests

- Migrations and merges are behaviour-preserving refactors: no new spec. Implementer runs the
  existing UI specs covering each touched surface (ledger lists them; find by testid grep under
  `apps/kira-space/tests/ui/`, `tests/mobile/`), plus `bun run typecheck`, `bun run lint`.
- A new shared piece with behaviour (reactive state, keyboard, timing) gets one targeted UI spec
  on a real host surface. Renderer-only: no flow half; say so in Result.
- A DRIFT fix that changes a value crossing IPC (Go formats or labels it) splits at the IPC
  boundary: flow test asserts the wire value, UI spec asserts the same rendered text.
- Spec failures from locator drift get fixed in the spec; real regressions in code.
- Visual and screenshot specs: failures expected, not re-recorded here (chapter end re-records once).
- Pre-existing failures in touched areas get fixed on the spot per working agreement.

## Out of scope

- Accessibility as a goal (a11y-only findings).
- Go backend, except display text that reaches a UI surface (DRIFT across IPC).
- Site Astro components and layout; site is in scope only where it redefines what `tokens.css`
  owns.
- Engine internals (Monaco, xterm, SlickGrid, ECharts options beyond shared tokens).
- D1 board pastels, D3 toasts, the 48 v0.3.17 PERMANENT exemptions while their reasons hold.
- New features, behaviour changes beyond unifying one job, copy rewrites beyond one wording per
  action.
- P676-P680 approval and variable UI (built later on these rules).
- Visual baseline re-record (chapter end).

## Risks

- Tool noise: thresholds start as above; the auditor may tune them per run (flags, not code edits)
  and states the values used in the ledger.
- Ledger size: an iteration may exceed one Sonnet's context. Wave 1 and wave 2 implementers commit
  per finding group and record progress by ticking ledger entries (`done <sha>`) so a restart
  resumes from disk.
- Guard regex false positives: test each new regex against its fixed sites (zero) and one planted
  offender in a scratch copy before committing.
