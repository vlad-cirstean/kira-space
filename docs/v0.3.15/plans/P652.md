## 2. Code fixes

### 2.1 `fix/cart-flaky` line 2 clip (ask 1)

Root cause: board line 2 (`plan/AdeBranchRow.vue:582-591`, `ade-branch-line2`) is `flex
overflow-hidden whitespace-nowrap gap-1.5`. Every child refuses to shrink: `AdeBranchProg` root is
`inline-flex shrink-0` with the label `max-w-28 truncate` (a `max-w`, not a shrink), the spacer is
`flex-1`, and every `AdeBranchChips` span is `shrink-0`. `b_cart` (fixture `tests/fixtures/ade-v2/board.json`)
carries progress `Release · failed` plus `dev ✓`, divider, `▲staging ✓`, `▲prod ✓`: 263px content in
a 255px box. Nothing can give, so `overflow-hidden` cuts the last chip by 8px. Any row with a long
step label plus three or more targets clips the same way.

Fix, no information hidden (full label and every chip stay in `AdeBranchTip`, which wraps line 2):

- `plan/AdeBranchProg.vue`: root `inline-flex shrink-0 items-center gap-1` to `inline-flex min-w-0
  shrink items-center gap-1`; segment wrapper `inline-flex gap-0.5` gets `shrink-0`; label keeps
  `max-w-28 truncate`, adds `min-w-0`. The label is the one text that yields; segments never shrink.
  Panel caller (`AdeBranchRow.vue:358`, inside an `overflow-hidden` flex with `truncate` context)
  gains the same yield rule; harmless there.
- `plan/AdeBranchRow.vue` board line 2: wrap `<AdeBranchChips :chips="row.chips" />` in
  `<span class="flex shrink-0 items-center gap-1">`. Tighter chip spacing (4px, as the line-1 state
  group, P648 iter2 4.1 point 2) saves 2px per gap; target chips are the fact the row exists for,
  so they never truncate.

Result at 400px: chips keep full width, label truncates to `Release · fai…` only when needed; tooltip
on line 2 shows `Release · failed` in its Progress row. Not chosen: wrapping line 2 (changes row
height under the drag geometry), spanning line 2 across the repo column (breaks the iter2 rule that
detail hangs under the name).

Regression spec: section 3.4 item 9.

### 2.2 Drag ghost covers the target card's last row (known defect): fix

Root cause: `plan/AdeDayBand.vue:50-73` places the ghost 16px right of the pointer and vertically
centred (`y: ev.clientY - r.top - GHOST_HALF_H`). With the midpoint rule, the pointer sits on the
lower half of the card the slot goes after; a ghost centred on the pointer covers that card's last
row (22px above the pointer).

Fix: ghost top-left corner GHOST_GAP right of and below the pointer.

- `GHOST_HALF_H` goes; `fallbackOffset` becomes `{ x: ev.clientX - r.left + GHOST_GAP, y:
  ev.clientY - r.top + GHOST_GAP }`. Comment: `Ghost's top-left sits GHOST_GAP right of and below the
  pointer: rows at and above the pointer, and the slot's left part, stay visible.`
- Everything above the pointer (the card the slot follows) stays visible; the dashed slot opens at
  the pointer and spans the card width, so its left part is never covered; the 0.6-opacity ghost
  overlaps only the slot's right part. Slot resolution reads the pointer, unaffected.
- Verify in the real-data run (4.3 step D2) with a screenshot mid-drag.
