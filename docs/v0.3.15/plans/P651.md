## 1. Ask

User (verbatim): "It's very annoying as I have file paths, open file etc. everywhere that points to
the YAML files. Drop them. Also editing a connection etc says to edit the config file and is very
annoying and confusing. In all places of the app, not just the examples I provided."

SPEC row: remove file paths and "open file" affordances pointing to YAML files. Remove "edit the
config file" copy. App-wide.

Two asks:

1. A. No YAML config file path, file name, Open file, Reveal file, Copy path or "About these files"
   affordance anywhere in UI.
2. B. No copy telling user to edit a config file / file. User edits through app UI (form or in-app
   YAML tab).

## 2. Decisions

- In-app YAML tabs stay (Form | YAML editors, "Fix it in YAML", "Show in YAML", "Copy YAML"). They
  edit through app UI, not on disk. Labels say "YAML", never "file".
- Config modules on disk stay: configfs, watcher, AGENTS.md per folder (`internal/configfs/docs.go`),
  config sync. Agents and sync need them. Internal only; nothing in UI points to them.
- `ConfigFilesService` (`internal/configfs/configsvc`) only opens/reveals config files for UI.
  Remove whole package and binding.
- `FileOpener` stays: proof screenshot reveal (`internal/bridge/proofshots.go`) and proof
  OpenFolder/RevealFolder need it. Retype `appwire.Options.FileOpener` to `bridge.ProofRevealer`.
- ADE task-folder Open/Reveal (task.yaml, state.yaml dir) removed, Go and UI. `DetailsFolder` stays
  (tests, agents, change list).
- Wire `path`/`dir` fields stay as internal data, no longer rendered: agentctx `View.Path`, agentcfg
  `FileView.Path`, connfiles `View.Dir` and `FileDetail.Path`, apifiles `Dir`/`Path`, scripts
  `FileView.Path`, repocfg `filePath`, workflows `dir`/`stepsDir`. Dropping them churns Go,
  bindings and flow tests for no user-visible gain. Implementer drops a frontend-only use that
  becomes dead (knip decides).
- Where a file name served as an item identifier (broken rows, dialog title fallback), show the name
  without extension via new helper `configName()`. Display name wins where one exists.
- task.yaml / state.yaml mirrors: agent-facing, internal. Mirrors, their writer and the agents' docs
  stay unchanged. UI keeps only what identifies an agent edit (change list in
  `AdeDetailsDiskBanner`), with no path to open. Task-detail edit prompt text
  (`DetailsEditBody`) is P649 territory; untouched here.
- Out of scope (not YAML config, or a real user-chosen file): proof window and proof entry folder
  (proof.md + images; `ProofHeader.vue`, `AdeProofEntry.vue`), config sync screens (Git file sync),
  agent port native agent files (Claude `settings.json` etc.) on export/backup, workflow "Import
  YAML" (external file the user picks), export collection to file, repo source file viewer
  (`space.repo.file.*`), memory import, HTTP body files, SQLite path, kubeconfig, git executable
  path, proof screenshot save folder, update folder, docker compose, `automations.run.isolated.body`,
  `space.ade.stepBlock.taskFolder.label`, `studio.proof.delete.body`, llmPrompts descriptions, site
  `how-it-works.md:19` (data-location fact).
- Backend messages reworded only where user-facing. Contract/validation errors kept (section 8).
