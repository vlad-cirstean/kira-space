## 2. Root cause: product bug (P643, v0.3.14)

An ADE smart step can never finish ok when a later stage follows it.

- `SubmitForFinish` (`apps/kira-space/internal/ade/detailsmcp.go:108`) refuses an ok `step.finish`
  with no draft unless `noStageRun` (rebase, review, check: `run.Purpose != ""`) or the route ends
  (`routeContinues`, `route.go:249`). A smart step run has `Purpose ""` and here routes on to `work`,
  so it is refused: "write handovers/draft-one.md, then call state step.finish".
- The smart step cannot write that file. `smartStep.spec` (`smartstep.go:134`) sets `--tools` to the
  script's own built-ins (`Read`; `scripts.DefaultTools` is `Read, Grep, Glob`, no write tool).
  `withTaskFolder` adds `Edit(<folder>/**)`/`Write(<folder>/**)` to `--allowedTools`, but a tool not in
  `--tools` does not exist. So a default smart script deadlocks on its own finish.
- The prompt says the opposite of what the run can do: `planSmartStep` (`smartstep.go:58`) renders
  `headless.space.files` with `Draft` set (`filesVars`, `detailsprompt.go:31`), so the agent is told to
  write a draft it has no tool for. Haiku reads that, fails honestly with a reason.
- Design intent says smart runs carry no draft: `finishRun` (`internal/agentmcp/mcp.go:411`) "a run
  with no draft (smart script, rebase): the reason is its one-line result", and ARCHITECTURE "Prompts"
  (line 4074) "a run with no draft (smart script, rebase, review round) takes an ok finish's `reason`
  as its one-line summary". A standalone smart script run already gets this (its run id is no ADE run,
  so `noStageRun` is true). The ADE smart step falls through: the bug.
- Flow tests hid it: `fakeagent.callTool` writes the draft a refusal names (`writeDraftAsked`)
  whatever `--tools` says, and `TestAutomationStep` smart steps have no later stage.
- Ruled out: MCP `state` nested `{action,args}` contract (haiku called it fine), model choice, budget
  (0.002 USD of 0.05), timeouts (12 to 15 s of 2 m), hermetic settings (settings check never reached).
  The test's command names `finish_step`, which a Space grant no longer has; haiku found `state`
  anyway. Stale text, secondary, fixed in §3.3.

## 3. Fix

### 3.1 Product: a smart step run needs no draft

Rule: an ADE smart step run hands over by its ok finish's `reason`, never by draft. A draft it does
write (script ticks `Write`) is still accepted and still wins as summary (`draft != ""` path,
unchanged). Sessions are unchanged: a session opened at a smart stage keeps its draft clause (it has
write tools).

Rejected alternatives:
- Add `Write`/`Edit` to every smart step's `--tools`: widens the script's explicit isolated tool
  policy ("Smart scripts always run isolated ... their tool and MCP policy is explicit"), and costs
  the run extra turns on a tight script budget.
- Exempt only smart steps whose script lacks a write tool: needs the script re-resolved at finish
  time (it may be edited mid-run), two sources of truth for one rule. Pre-P643 smart steps handed
  over through `finish_step`'s summary, which the reason now replaces: same behaviour as before.
- Change `routeContinues` itself (planner's prototype, §5): also drops the draft clause from sessions
  at a smart stage. Narrower change below.

Edits:

1. `apps/kira-space/internal/ade/smartstep.go`
   - Add, next to `planSmartStep`:
     ```go
     // smartStepOf reports whether the workflow's step stepID runs a smart script. Its runs hand over
     // by the ok finish's reason: the script's tools are its own, often without a write tool.
     func smartStepOf(tc *taskCtx, stepID string) bool
     ```
     Body mirrors `stepAgentOf` (`stagesettings.go:46`): nil `tc.wf` is false; match `s.ID == stepID`,
     return `s.SmartScript != ""`.
   - In `planSmartStep` (line 58): take `v := b.filesVarsFor(...)`, set `v.Draft = ""` before the
     `v.Folder != ""` check renders `HeadlessSpaceFiles`. Comment: a smart step needs no draft (see
     `smartStepOf`).
2. `apps/kira-space/internal/ade/detailsmcp.go` `SubmitForFinish` line 127: add
   `|| smartStepOf(tc, cur)` to the pass-through condition (before `routeContinues`, cheaper: no
   `plan`). Update its doc comment: "without one the finish is refused, unless its route ends the task
   or the step is a smart step."
3. `apps/kira-space/internal/ade/runs.go` resume branch (line 741): build the files vars once,
   `files := b.filesVars(tc, def.ID, agent, ...)`; `if smart != nil { files.Draft = "" }`; pass
   `files` to `composeResumePrompt`. Keeps a resumed smart step from being told to write a draft.
4. `internal/agentmcp/space.go:201` interface comment: "an ok finish with no draft is refused while
   its result's route continues, except for a smart step." `internal/agentmcp/mcp.go:411` comment:
   "(smart script or smart step, rebase)".

No change to `routeContinues`, `filesVars`, `noStageRun`, `README.md` generation. The task README
still lists `handovers/draft-<step>.md` as writable; it is per task, not per run, and planner runs
passed with it unchanged.
