## 2. What counts as an agent

An agent is a process Kira launches to run an agent CLI. Its whole descendant tree counts. Roots:

| Launch | Spawn site | Root pid |
|---|---|---|
| ADE step / rebase / review runs, any headless run (Claude) | `internal/harness/claude/headless.go` `RunHeadless`, after `cmd.Start()` (~L233) | login shell that `exec`s claude (same pid) |
| Same, OpenCode | `internal/harness/opencode/headless.go` `RunHeadless`, after `cmd.Start()` (~L317) | same |
| Structured calls (memory import, LLM prompts) | `internal/harness/claude/structured.go` `RunStructured` (L112, `toolexec.RunIO`) | claude |
| Agent terminals (ADE sessions, take-over, mobile-started launches, any `LaunchKindAgent` open) | `internal/terminal/session.go` `Registry.Open` when `p.Agent` | PTY shell (`Session.PID`) |

Not agents, stay out of both figures (unchanged): plain user terminals (user's own workload),
script terminals, git/tool children (`toolexec.Run*` without tracking, `claude mcp add` installs,
version probes). Agent MCP calls served in-process by Kira count as App, since that CPU is Kira's.

Why a registry, not name matching: the terminal package already forbids inferring agent-ness from
a command (`OpenParams.Agent` comment, P85 OQ-3 "no heuristic" rule). Native claude installs run
an executable named after its version, node installs run `node`, sandbox wrappers sit in front.
Spawn sites know for certain.

## 3. Backend

### 3.1 Root registry: new `internal/agentproc/agentproc.go`

```go
// Package agentproc records the root pid of every live agent process tree this process launched.
// Process-wide by nature (pids are), so one package-level set; internal/metrics reads it.
func Track(pid int) (untrack func())   // ref-counted per pid; untrack idempotent (sync.Once)
func Roots() []int32                    // snapshot, any order
```

`sync.Mutex` + `map[int32]int`. Package-level state justified: spawn sites sit deep in providers
and the terminal package with no shared deps struct; the set is a fact about this OS process.

### 3.2 Spawn sites

- `claude/headless.go`, `opencode/headless.go`: right after successful `cmd.Start()`:
  `defer agentproc.Track(cmd.Process.Pid)()`. Untracks on return, after `Wait` and any group kill.
- `internal/toolexec/exec.go`: add
  `RunIOTracked(ctx, path, args, dir, env, stdin, onStart func(pid int) (done func())) ([]byte, error)`.
  `spec` gains `onStart`; `spawn` uses `cmd.Start()` + `done := onStart(pid)` + `cmd.Wait()` +
  `done()` when set, else `cmd.Run()` as today. Same error/escalation handling on both paths.
  `RunIO` unchanged (10 callers).
- `claude/structured.go:112`: `toolexec.RunIOTracked(..., agentproc.Track)`.
- `internal/terminal/session.go` `Registry.Open` (L459-513): after the session is registered
  (non-doomed path, where `sess.unregister` is set), when `p.Agent`:
  `untrack := agentproc.Track(sess.PID())`, and `sess.unregister` calls `r.remove(...)` then
  `untrack()`. `unregister` runs exactly once from the reader goroutine on any exit.

Root reaped but not yet untracked (microseconds between `Wait` and untrack): pid could only be
reused in that window; a reused pid absent from Kira's tree would count as agent for at most one
tick. Accept; note in code comment.

### 3.3 Process table with parent pids

`procEntry` gains `ppid int32`.

- `processlist_darwin.go`: per pid, also `proc_pidinfo(pid, PROC_PIDTBSDINFO, 0, &info,
  PROC_PIDTBSDINFO_SIZE)` and read `pbi_ppid`. Keep an entry when either `proc_pidpath` or
  `proc_pidinfo` succeeds; drop only when both fail. One extra syscall per pid (~500 pids, well
  under 1 ms at a 5 s interval).
- `processlist_other.go`: `p.Ppid()` (gopsutil, `/proc/<pid>/stat` on Linux). Stop skipping a
  process whose `Exe()` fails: keep it with `exe: ""` so a parent chain never breaks.
  `AppProcessSet` already skips empty exe when matching.

Library check: gopsutil v4.26.10 (BSD-3, already a dependency) supplies the probes and `Ppid`.
Its `Process.Children()` is not used: on darwin and Linux it rescans the whole process table per
call (`process_darwin.go:249`, `process_linux.go:341`), so a tree walk would cost O(table × nodes)
per tick. Walking descendants over the one table already listed is a map plus a queue, not
non-trivial infrastructure; no library offers it over a caller-supplied table.

### 3.4 Grouping: `sampler.go`

```go
// ProcessSet is one tick's process groups. A pid is in at most one.
type ProcessSet struct{ App, Agents []int32 }

// ProcessSets lists the process table once and splits it.
func ProcessSets(anchorNeedles, helperNeedles []string, agentRoots []int32) (ProcessSet, error)
```

- `listProcesses()` once. Pure helper `groupProcesses(entries []procEntry, anchors, helpers
  []string, roots []int32, tracked bool, responsible func(int32) int32) ProcessSet`:
  1. Agents: roots present in the table, plus every descendant at any depth (children index by
     ppid, BFS, visited set so a ppid cycle from a pid-reuse race terminates). Roots missing from
     the table are ignored (already exited).
  2. App: today's anchor/helper rule (`includeHelper`), minus any pid already in Agents. Agents
     win: fixes the Linux `bwrap` agent sandbox double count.
- `AppProcessSet` stays as a thin wrapper (`ProcessSets(..., nil)` → `.App`) for
  `apps/kira-space/cmd/g1measure` (unchanged).
- `CachedPIDs.resolve` becomes `func() (ProcessSet, error)`; it stores `createTimes` plus an
  `agent map[int32]bool` from each rescan; `revalidate` drops from both. `PIDs()` returns
  `(ProcessSet, map[int32]procSample, error)`. `Sampler.pids`, `NewSampler`, `NewTicker` take that
  signature.
- `NewAppTicker(appName string, agentRoots func() []int32)`; resolve =
  `ProcessSets([]string{appName}, HelperNeedles, agentRoots())`. `appwire.go:590` passes
  `agentproc.Roots`. metrics never imports agentproc.

### 3.5 Sample: `sampler.go`

```go
type Usage struct {
	CPUPercent   float64 `json:"cpuPercent"`
	MemoryBytes  uint64  `json:"memoryBytes"`
	ProcessCount int     `json:"processCount"`
}
type Sample struct {
	CPUPercent   float64 `json:"cpuPercent"`   // App + Agents, clamped 0..100
	MemoryBytes  uint64  `json:"memoryBytes"`  // App + Agents
	LogicalCPUs  int     `json:"logicalCPUs"`
	ProcessCount int     `json:"processCount"` // App + Agents
	App          Usage   `json:"app"`
	Agents       Usage   `json:"agents"`
}
```

`Sample()`: probe each pid as today (fresh map first), accumulate memory/count per group, build
`appNow`/`agentNow` cpuState maps. `prevCPU` stays one union map (store `appNow ∪ agentNow`).
`App.CPUPercent = cpuDeltaPercent(prev, appNow, …)`, `Agents.CPUPercent = cpuDeltaPercent(prev,
agentNow, …)`: same createTime guard, new pid contributes from its second tick, each clamped.
Totals = sums; total CPU clamped to 100. Headline shows totals: the ask is that the widget includes
agents, and a total is what a user compares against Activity Monitor.

Agent exits between samples: its pids vanish from the table, contribute nothing that tick; CPU it
burned in its last partial interval is not counted (cumulative time unreadable after reap). Agent
starts: memory counts from the next tick, CPU from the one after (existing new-pid rule).

Memory: probe unchanged. darwin footprint already excludes shared pages, so summing agent trees
does not double count shared libraries. Linux RSS over-counts shared pages across processes;
Linux is the dev sandbox, not a shipped target; accept and keep the existing doc comment saying so.

Update comments that now lie: package doc ("not a pid-tree walk" → app by path match, agents by
tree from tracked roots), `Sample`, `NewSampler`, `Ticker`.
