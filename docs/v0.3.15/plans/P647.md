## 3. Drag and drop (ask 2)

### 3.1 Current implementation

- `plan/AdeDayBand.vue:49`: `useDraggable` (vue-draggable-plus 0.6.1 over SortableJS 1.15.7) on each
  band's drop list `[data-testid="ade-band-drop"]`; `draggable: '[data-ade-task]'`, `sort: false`,
  no put/pull, `forceFallback`, `fallbackOnBody`, `fallbackTolerance: 4`, `ghostClass`
  (`opacity-50`, `SORTABLE_GHOST_CLASS`). Sortable never moves Vue DOM; it only drives the drag
  lifecycle, floating clone and auto-scroll.
- `plan/usePlanDrag.ts`: while dragging, `useElementByPoint` (rAF) over `useMouse`; `resolveTarget`
  maps element under pointer: inside `[data-testid="ade-card"]` gives `{kind:'card', taskId}`
  (insert before that card), else inside `[data-ade-band]` gives `{kind:'band', day}` (append to
  day), else `null`.
- `plan/AdePlanView.vue:214`: on end, `dropVerdict` (`board/dropPlan.ts`) gives `move` (one
  `useSetPlan` write) or `refuse`. `dragOverDay` outlines a whole band only for band targets.

### 3.2 Root causes of finicky feel

1. Dead zones append to day end. Cards sit 16px apart (`gap-2` on list plus `mt-2` on every card
   after the first). Pointer in a gap, on the band heading or the list's top padding hits the band,
   so a card aimed "between A and B" lands at the end of the day.
2. Card hit always means "before". Lower half of a card cannot mean "after". Only way to land
   after the last card is the 8px `pb-2` strip.
3. Pointer over plan padding (`px-4`), the 1px band seams or the sticky header resolves `null`:
   release there silently refuses.
4. No feedback. Card targets show nothing; band targets outline the whole band; refused targets
   look the same as accepted ones. User cannot tell where the card goes.
5. Auto-scroll: SortableJS default `scrollSensitivity: 30`, `scrollSpeed: 10`, measured from the
   scroll container top, which the sticky header covers. Scroll zone sits mostly under the header
   and moves slowly.
6. Press on a nested `<button>` (status menu, icon buttons, current title button) starts a drag
   after 4px jitter and swallows its click.

### 3.3 Library decision

Keep vue-draggable-plus + SortableJS (both MIT, already in repo, used by `useSortableReorder`) for
drag lifecycle, fallback clone and auto-scroll. Keep VueUse (`useMouse`, `useRafFn`) for pointer
tracking. No new dependency.

Declined: Sortable native cross-list sorting (shared group, `sort: true`), whose moved ghost would
be a free placeholder. Requirement it cannot meet: each band list also holds non-draggable history,
overdue, overflow and span rows, and plan placement is not DOM index (auto-placed review items count
as band drops, past/day-off bands refuse, display order sorts by merge day). Sortable would move
Vue-rendered DOM across lists and its index would still need mapping back through `dropVerdict`.
`@dnd-kit` is React-only. `@atlaskit/pragmatic-drag-and-drop` (Apache-2.0) adds a dependency with
no placeholder built in; no gain over current lifecycle.

### 3.4 New target resolution (geometry, not element-under-pointer)

Rewrite `plan/usePlanDrag.ts`. Signature:
`usePlanDrag(root: Ref<HTMLElement | null>, onDrop: (taskId, target: DropTarget | null) => void)`.
`DropTarget` and `dropVerdict` stay unchanged (unit-tested; no edit to `board/dropPlan.ts`).

- Pointer: keep `useMouse({ type: 'client' })`. Replace `useElementByPoint` with
  `useRafFn(tick, { immediate: false })`; `begin` resumes, `end` pauses.
- `tick` computes `resolveSlot(root, x, y, draggedId)` and assigns `target` only when its key
  changes (`card:<id>`, `band:<day>`, `none`), so props change only on a real move, not per frame.
- `resolveSlot`:
  1. Pointer outside `root` rect horizontally or vertically: `null` (release over the panel
     cancels).
  2. Band: among `root.querySelectorAll('[data-ade-band]')`, the one whose rect contains `y`;
     else nearest by vertical distance (closes seams and padding).
  3. Cards: `band.querySelectorAll('[data-ade-task]')`, skipping the dragged one
     (`dataset.taskId === draggedId`). First card whose rect mid-Y is below `y` gives
     `{ kind: 'card', taskId }`; none gives `{ kind: 'band', day }`. Band heading and top padding
     resolve to "before first card"; gaps resolve to the nearer slot.
  4. No-op: slot before the card that directly follows the dragged card in the same band, or band
     end when the dragged card is already that band's last card: `null` (no placeholder, no write).
- Live rects every frame, so auto-scroll under a still pointer re-resolves. Midpoint rule plus an
  in-flow placeholder is stable: inserting the slot pushes the neighbour card away from the pointer,
  so the same side stays chosen (no oscillation).

`AdePlanView.vue`: pass `scrollEl` as `root`. `onDrop` unchanged.

### 3.5 Snap placeholder

- `AdePlanView.vue`: replace `dragOverDay` with `dropSlot` computed:
  draggedId and target set, `dropVerdict` says `move`, then
  - card target, entry not `auto`: `{ day: <band of that card>, before: taskId }`;
  - card target, entry `auto`: `{ day: entry.day, before: null }`;
  - band target: `{ day, before: null }`;
  - else `null`.
  Band of a card: `m.view.entries.get(taskId)?.day`; implementer confirms it equals the band key
  the card renders in (`band.taskIds`); if not, carry the band day from `resolveSlot` in drag state.
- Same `dropVerdict` drives placeholder and write, so placeholder never shows where the drop is
  refused, and always shows where it lands.
- `AdeDayBand.vue`: drop `dragOver` prop, `accepts`, `highlight` and the band outline class. Add
  prop `dropBefore?: string | null` (`undefined` = no slot in this band, `null` = after last card,
  id = before that card). AdePlanView passes
  `dropSlot?.day === band.key ? dropSlot.before : undefined`.
- Render inside the cards `v-for`, before the matching card, and once after the loop for `null`
  (after cards, before span rows):
  `<div class="h-9 shrink-0 rounded-kira border border-dashed border-focus bg-focus/10" data-testid="ade-drop-slot" aria-hidden="true" />`.
  Tailwind utilities only; check-theme-classes and check-tokens must accept the classes (use an
  existing token if `bg-focus/10` is refused, e.g. `bg-select`).
- Dragged original keeps `ghostClass` (`opacity-50`) in place; floating clone follows pointer.
- `cursor-grab` already on the card (`AdeTaskCard.vue` `boxClass`); no change.

### 3.6 Sortable options (`AdeDayBand.vue` `useDraggable`)

Add:

- `filter: 'button, a, input, textarea, [role="menuitem"]'`, `preventOnFilter: false`: nested
  controls keep their clicks and never start a drag. Card head, branch rows (`div role="button"`)
  and title (span after section 5) still drag.
- `scrollSensitivity: 56`, `scrollSpeed: 14`, `bubbleScroll: false`: scroll zone reaches past the
