# P649 Prompt dialogs

Plan by Opus. Stream A of 3 (P649, P650, P651), own worktree `stream/p649`. One Sonnet implementer,
sequential. Base: `07246566`.

Backend changes allowed. User wants minimal test churn this chapter: section 9 lists every test

## 1. Asks

1. Approve dialog shows nothing for an AI explain, for a simple create task and for other prompts;
   buttons missing too. Explain "probably explains the explain".
2. Create-task wait still 30 min. All such limits 10 min.
3. Typing in Kira makes prompts disappear or approve/deny them. Every prompt keyboard shortcut needs
   2 keys. While user types: no dialog, toast only; open after a short pause that lets user finish
   the sentence.
4. Proof update notification "forward to agent": show a prompt like the others or nothing.

## 2. Root causes

### 2.1 Blank task.create card (ask 1)

`apps/kira-space/internal/ade/taskcreate.go`: `taskCreateRepo.Base` is tagged
`json:"base,omitempty"`. `frontend/src/ade/v2/request/payload.ts` requires `base: z.string()`. Repo
with no base fails zod parse. Parse runs in `TaskCreateBody`, `TaskCreateDetails` and the
`requester` of `taskCreateKind` (`kindDefs.ts`), which `ApprovalItemActions` calls. All three throw,
so body and footer render empty: no text, no Approve.

### 2.2 Blank explain card (ask 1)

`apps/kira-space/internal/dbmcp/tools.go` `awaitExplainApproval` (~line 773) builds
`ApprovalRequest` without `Mode`. Payload goes out with `mode:""`.
`packages/shared/domain/dbmcp.ts` `dbMcpPayloadModeSchema = z.enum(['read','write','ddl','masked'])`
rejects it. `dbQueryPayloadSchema.parse` throws in `DbQueryBody`, in `operation` of
`studioApprovalKinds['db.query']` and in `queryRisks`. Card blank.

"Explains the explain": no real loop. `explain.go` `planFor` returns nil unless
`queryplan.Explainable(sql)` (SELECT/WITH only), and `explainPreflight` refuses anything else, so an
EXPLAIN is never wrapped again. Perception comes from `Statement: strings.Join(statements, "\n")`:
the card would show the composed `EXPLAIN (FORMAT JSON …) SELECT …`, not the agent's SQL, under a
generic "Run query" label. Fix shows agent SQL labelled "Explain".

Other `Approvals.Request` sites (`tools.go` ~398, ~656, `limits_gate.go` ~144) set `Mode`. Other
kind schemas checked against Go payloads, all match: branch.request, details.edit, proof.review,
script.run, kube.read, db.exemption, db.response.

### 2.3 Any future mismatch blanks a card (ask 1, "other prompts")

Card and actions call kind defs (`operation`, `where`, `risks`, `requester`, `labels`, body/details
components) with no guard. One throw empties the card. Section 4 adds a guard so a mismatch shows an
error risk and Deny, never a blank card.

### 2.4 Typing approves/denies/hides (ask 3)

- Dialog opens mid-typing and steals focus (reka `FocusScope`).
- `ApprovalItemActions.vue` line 41 puts `data-dialog-initial` on Deny; `ProofReadyPrompt.vue`
  line 56 and `MaskingReviewPrompt.vue` line 53 put it on a button too. Next typed Space or Enter
  presses it. Specs `studio/dbmcp-approval.spec.ts:50–62` and `dbmcp-approval-script.spec.ts:48–58`
  assert exactly that ("Deny is focused first", Enter denies).
- Without `data-dialog-initial`, reka focuses first tabbable (X button, body checkbox): Space
  toggles or closes.
- Bare Escape minimises approvals and hides routed prompts: "disappear".
- `GitCredentialDialog.vue` lines 67, 75: bare Enter submits.

### 2.5 Create task 30 min (ask 2)

`taskcreate.go` line 26 `defaultTaskRequestWait = 30 * time.Minute`, used by `taskRequestWait()`
when `deps.TaskRequestWait` is 0 (always in prod).

### 2.6 Proof forward notification (ask 4)

`apps/kira-space/internal/ade/proof.go` `proofReady` (lines 126–141) does two things:

1. `links.RaiseReady` raises `prompts.KindProof` (`ProofReadyPrompt`, Open / Later). That already is
   "a prompt like the other stuff".
2. `b.recordPanelEdit(taskID, "proof:"+id, panelItemKindProof, "proof", "", proofText(...))` queues a
   panel-forward item. User sees it in the panel-forward notification ("forward to agent").

`recordPanelEdit` doc: records "a user edit". Forward message (`llmprompts`
`AdePanelForwardMessage`): "The user changed the task panel". A proof never comes from the user: it
comes from the agent's own submission (`detailssubmit.go` Accepted, `NotifyProofReady`). Forwarding
echoes the agent's own proof back to it. Purpose dead.

Decision: remove the forward (option "nothing"). The prompt from point 1 stays and covers "show a
prompt like the other stuff".

## 5. Two-key chords (ask 3)

### 5.1 Chords

`packages/shared/domain/shortcuts.ts`:

- `ShortcutScope` gains `'prompt'`.
- `'prompt.deny': { scope: 'prompt', chord: { key: 'Backspace', cmdOrCtrl: true } }`
  (Mod+Backspace).
- `'prompt.hide': { scope: 'prompt', chord: { key: 'Escape', shift: true } }` (Shift+Escape).

### 5.2 `DialogContent` prompt mode

`packages/theme/src/components/ui/dialog/DialogContent.vue`: new prop `prompt?: boolean`.

- `onOpenAutoFocus`: if `prompt` and no `[data-dialog-initial]` inside, `preventDefault()` and focus
  content root (`tabindex="-1"`, not actionable). Enter/Space hit nothing.
- `onEscapeKeyDown`: if `prompt`, always `preventDefault()`.
- `keydown` on root: if `prompt` and `shortcutKeydown(['prompt.hide'])` matches, run the existing
  close path (through `requestClose` when `dirty`).

Dialogs with a text field that should own focus keep `data-dialog-initial` / `useFocusOnMount` on
that field (GitCredential input). Only buttons lose it.

## 6. Typing gate (ask 3)

### 6.1 Definition

User is typing when both hold:

1. a keydown landed on a typing target within the last `PROMPT_QUIET_MS`;
2. focus is still on a typing target.

Typing target: `isEditableTarget(el)` (`packages/workbench/src/behaviour/dom.ts`: INPUT, TEXTAREA,
SELECT, contenteditable) or `el.closest('.monaco-editor, .xterm')` (Monaco 0.57 uses EditContext on
Chromium, not an input; xterm uses a helper textarea already covered, class check is belt and braces).

`PROMPT_QUIET_MS = 4000`. Why: pauses between words stay under 1 s, mid-sentence thinking pauses
around 1–3 s; 4 s ends a sentence without feeling stuck. Cost against a 10 min expiry is nil.

### 6.2 Store and composable

New `packages/workbench/src/state/promptGate.ts`, Pinia setup store `usePromptGateStore` (one
concern: typing gate). VueUse only, nothing hand-rolled:

- `activeElement = useActiveElement()`;
- `recent = refAutoReset(false, PROMPT_QUIET_MS)`;
- `useEventListener(window, 'keydown', e => { if (isTypingTarget(e.target)) recent.value = true },
  { capture: true, passive: true })`; reassigning `true` restarts the timer;
- `typing = computed(() => recent.value && isTypingTarget(activeElement.value))`.

Exported `useGatedOpen(want: Ref<boolean>)` returns `{ ready, force }`:

- `want` false: `ready` false (reset latch).
- `want` true: `ready` turns true once `typing` is false; latched, so typing inside the open dialog
  never closes it.
- `force()`: `ready` true now.

### 6.3 Approvals

`ApprovalsSurface.vue`: dialog condition becomes `!store.minimised && !promptShown && gate.ready`;
toast shows otherwise. `ApprovalsToast.vue`: Show calls `store.open()` and `gate.force()`; while
deferred (not minimised, not ready) add hint `t('workbench.prompts.toast.typing.status')` ("Opens
when you pause typing").

### 6.4 Routed prompts

- `packages/workbench/src/prompts/PromptHost.vue`: wrap head prompt display in `useGatedOpen`,

  `usePromptVisibility`.
- `promptsQueries.ts` `usePromptVisibility`: add `deferred` (head entry or null) and `release()`
  (calls gate `force`).
- New `packages/workbench/src/prompts/PromptsToast.vue`: Tailwind classes, theme `Button`; shows
  entry title (Go already localizes it), `t('workbench.prompts.toast.more.status', { n })` when more

- `apps/kira-space/frontend/src/App.vue`: add `<PromptsToast />` inside `CornerStack` next to

New `en.json` keys: `workbench.prompts.toast.more.status`, `workbench.prompts.toast.typing.status`,
`workbench.approvals.risk.unreadable.status`, `studio.dbMcp.approval.op.explain.label`.
