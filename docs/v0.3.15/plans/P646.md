# P646 Task-list actions design mock

Plan by Opus. Deliverable: one static HTML mock for user approval. No app code changes. P651
implements the approved design; it gets its own plan after approval.

User ask: handle more from task row without opening task panel Main tab (example: edit branches).
Survey every Main-tab capability, propose split, show example. List stays narrow, fits MacBook Air.
Implementation waits for user agreement.

Term: "task list" = Plan view (`AdePlanView` > `AdeDayBand` > `AdeTaskCard` with `AdeBranchRow`
rows). Later tab rows (`AdeShelfRow`) follow same row design in P651; mock shows Plan only.

## 2. Proposed split

Principle: row does every single-field edit and every branch-level edit in place, via hover cluster
and popovers. Panel keeps long-form, per-run and multi-field content.

### 2.1 Moves to row

| # | Capability | Row affordance |
|---|-----------|----------------|
| R1 (M11) | Branch edit: change branch, add name to draft slot, change repo, remove branch, remove repo | Hover pencil on branch row opens Popover: segmented Branch / Repo, BranchPicker (search, existing branches, "Create `<typed>`"), footer Remove branch, Remove repo (discard guard confirm). Same `AdeTaskBranchForm` content. |
| R2 (M9) | Add repo, add branch | Hover `+` on card head opens Popover: repo list (ProjectPicker inline) and "Attach existing branch…" (`addUi.openAttach`). |
| R3 (M12) | PR state and checks | Always-on 13px PR glyph + checks glyph on branch row; click opens PR (marks seen). Tooltip: PR title, base. |
| R4 (M2) | Estimate | Line-2 chip `3h` (or faint `est` placeholder on hover); click opens Popover with number + h/d + clear. |
| R5 (M15) | Step pick | Step label becomes dropdown trigger: step list (skipped disabled), back/next items; opens stage dialog as today. |
| R6 (M8) | Updates mark seen | Updates dot click opens Popover listing updates, Mark seen per item, Mark all seen. |
| R7 (M3) | Branch request review | Attention-style chip "Branch request" on line 2; click opens approval. |
| R8 | Title rename | Double-click title (or F2 on focused row) swaps to inline Input; Enter commits, Esc cancels. |
| R9 (M14) | Workflow switch | Task menu submenu "Workflow ▸" (radio list), same E_CONFLICT confirm. Rare action, menu only. |
| R10 (M5, M6) | Not merging, orchestrator | Already in task menu. No change. |
| R11 (M1) | Status | Already on row (`AdeTaskStatusMenu`). No change. |

### 2.2 Stays in panel

M7 full children list (row keeps compact children), M13 force-push dialog (triggered from row
already), M14 Edit workflows link, M16 step blocks with run lines, logs, reports, Take over per
run, Approve/Retry/Resume per run (row keeps current-step action only), header alerts, forward bar,
automations block, Details and Sessions tabs. Main tab keeps all its rows too (row adds shortcuts,
removes nothing from panel) so panel stays complete.

### 2.3 Row interaction model

- Hover or `:focus-within` on a card head reveals head cluster: `+` (R2), Review code, `⋯` (task
  menu). Branch row hover/focus reveals: pencil (R1), first fix action, Review code, `⋯`.
- Cluster overlays the right end of its line on a solid row-hover background; content beneath
  truncates, never reflows. No layout shift on hover.
- Popovers anchor to their trigger, `align="end"`, width 320px max (fits inside 360px list).
- Step action icon stays always visible (primary action).
- Keyboard: Tab reaches cluster buttons; Enter opens; Esc closes and returns focus.

### 2.4 Frontend rules (P651)

- Primitives: shadcn-vue `Popover`, `DropdownMenu`, `Tooltip`, `Input`, `Button` (all in
  `@theme/components/ui/*`). Pickers: existing `BranchPicker`, `ProjectPicker` (Command-based).
- Styling: Tailwind utilities, `group-hover`/`group-focus-within` for clusters, `@container`
  queries for density steps (container already used in `AdeShell`). No scoped `<style>`.
- VueUse only if a measured width is needed beyond container queries (`useElementSize` already
  used in `AdePlanView`).
- State: popover open state local to component. No new Pinia store; reuse `useAdeBoardUiStore`,
  `useAdeOpsStore`, `useAdeAddUiStore`, `useAdeStageDialogStore`.
- Server state: existing TanStack mutations/queries only (`useSetTaskBranch`, `useUpdateTask`,
  `useCandidates`, `useChangeRequests`, `useMarkTrackedSeen`, `useSetTaskWorkflow`). Extract
  `AdeTaskBranchForm` content so row and panel share it.

## 3. Narrow-list spec

- Targets: MacBook Air 13" default 1440x900 (M1) / 1470x956 (M2+); "larger text" setting 1280x800.
  Design floor: 1280 window width.
- List default width 400px; panel takes rest (880px at 1280, 1040px at 1440). P651 changes
  `AdePanelPane` default from half to `rowWidth - 400` when no width stored; raises `MIN_PAGE` to
  360. Stored user width still wins.
- Row content must work from 360px to 520px; wider just adds meta text.
- Card head: 2 lines, 44px total (from 68px).
  - Line 1 (h-5, 20px): sessions lead, title (13px medium, single-line truncate, full title in
    tooltip), status text (`max-w-20`), step action icon.
  - Line 2 (h-4.5, 18px): step segments (`w-12`), step label dropdown (`max-w-28`), estimate chip,
    glyph strip (attention, automation, lease, updates, parent, orchestrator), meta
    (truncate, flex 1).
  - Progress bar + percent move into step segments tooltip (drop from row).
- Branch row: single line, `h-row` 28px (from 40px): indent, repo chip (`max-w-20`), branch name
  (truncate), PR glyph, checks glyph, tag icon, always-on fix action only when red/danger. Context,
  merged/deployed chips, base marker move to `AdeBranchTip` hover card (already exists).
- Container steps: below 400px hide meta text; below 380px hide lease/automation chips (they stay
  in tooltip of step label).
- Plan padding `px-4` to `px-3`. P650 changes also visible in mock (no Today group background, no
  repos header, refresh-all only, no title underline, panel without facts line).

## 4. Mock build instructions (Sonnet implementer)

### 4.2 Page layout

- Top control bar (outside frame): theme (System / Light / Dark), viewport (1280 / 1440 / 1470),

### 4.3 List content (scenarios)

Day groups Today and Tomorrow, then Later strip. Tasks:

1. Agent step running, 1 branch, PR open, checks passing, estimate 3h.
2. Two repos, three branches: one draft slot (no name, muted "add branch name"), one behind base
   with Rebase fix action, one with PR checks failing.
3. Orchestrator with two live children and "1 archived" line.
4. Failed step: red Retry action, attention mark.
5. Not merging (parked): muted, dashed dot.
6. Review task (another owner): no head, owner pill on branch row.
7. Updates dot (2 updates) plus pending branch request chip.
8. Long title and long branch names, to show truncation at 360px.

Use plausible fake repo, branch and task names; no real people or companies.

### 4.4 Interactions (all in-memory)

- Hover/focus card head: shows `+`, Review code, `⋯`. Hover/focus branch row: pencil, fix action,
  Review code, `⋯`. No layout shift.
- Pencil: branch popover. Segmented Branch / Repo. Branch mode: search input filtering ~10 fake
  branches with "Create `<typed>`" when no exact match; pick updates row name and shows toast
  "Branch changed". Repo mode: repo list; pick updates repo chip. Footer: Remove branch, Remove
  repo, each opens small confirm dialog naming discard risk, then removes row. Draft slot opens
  in Branch mode titled "Add branch".
- `+` on head: popover with repo list (adds draft branch row) and "Attach existing branch…" (toast).
- Estimate chip: popover with number input, h/d segmented, clear. Saves to chip.
- Status text: dropdown of statuses (Todo, In progress, In review, Blocked, Done) with colours.
- Step label: dropdown of steps, back/next items; pick shows toast "Opens stage dialog".
- Updates dot: popover list, Mark seen per item, Mark all seen; dot disappears when empty.
- Branch request chip: toast "Opens approval".
- PR glyph: toast "Opens PR #123"; tooltip shows title, base, checks.
- Title double-click: inline input; Enter commits, Esc reverts.
- `⋯` and right-click on card: context menu with full task menu (section 1.3 list) plus new items
  Rename, Estimate…, Add repo ▸, Workflow ▸. Branch `⋯`: fix items, Run automation ▸, See log, Edit
  branch…, Remove branch.
- Row click: selects task, highlights row, panel shows that task.
- Esc closes any popover/menu; click outside closes; focus returns to trigger.

### 4.5 Task panel content

Selected task's panel: header (dot, status chip, title, action, Review code, More; no facts line),
tabs Main / Details / Sessions (only Main rendered). Main shows all Main-tab rows (M1 to M16)
statically, with a small "also on row" marker next to rows reachable from the row, so user sees
nothing lost.

### 4.6 Current vs Proposed toggle

Current: render rows per section 1.3 (68px head, icon line then 2-line title, 40px two-line branch
rows, list at half width). Proposed: section 3 spec. Same data, so user compares density.
