## 2. Hover cluster mechanics (head and branch row)

User rule: pencil and cluster sit just after title / branch name, never right-anchored (that covered
status dropdown and PR glyph in a first try).

Line layout: `[lead][name: min-w-0 truncate, no flex-1][cluster][spacer flex-1][right items]`.

- Cluster: `<span class="hidden shrink-0 items-center gap-0.5 group-hover/<g>:flex
  group-focus-within/<g>:flex has-[[data-state=open]]:flex has-[[data-pinned]]:flex">`. `<g>` is
  `head` on the card head, `row` on the branch row (add `group/head` / `group/row` to those roots;
  keep the branch row's existing unnamed `group`, `rowActions` in `rowVariants.ts` uses it).
- In flow, right after the name. Short name: cluster takes spacer width, right items stay put.
  Long name: name truncates further while hovered. No right-side element ever moves or is covered.
  This replaces the mock's absolute overlay (app pattern: in-flow flex, as in `AdeSessionsRow`).
- Pin: a cluster stays shown while one of its menus or popovers is open. Reka triggers carry
  `data-state="open"` (DropdownMenuTrigger, PopoverTrigger). `AdeTaskBranchMenu`'s form popover hangs
  off a `PopoverAnchor`, so its trigger Button gets `:data-pinned="formOpen || undefined"`.
  TooltipTrigger states (`delayed-open`, `instant-open`) never match.
- Keyboard: head and row are focusable (`tabindex="0"`); focus shows the cluster, Tab reaches its
  buttons. Hidden buttons are not tabbable while the row has no focus (intended).
- Hover fill: head keeps `hover:bg-field` / `bg-select`. Board branch row adds `hover:bg-field` when
  not selected. Keep `bg-select` on both (U37 exemptions in `scripts/check-ui-primitives.sh` must keep
  matching, or the run fails).
