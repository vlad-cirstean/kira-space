## Decisions

D1. **Stepping rule** (one pure function, `internal/releaseline.NextStep`). Terms:

- `norm(v)` = `"v" + TrimPrefix(v, "v")`. Line of `v` = `semver.MajorMinor(norm(v))` (`v0.3`). Lines
  order by `semver.Compare` on the line string. Pre-1.0 needs no special case: `0.3.14` is line
  `v0.3`, minor is middle number; `v0.9` then `v1.0` are consecutive lines.
- Eligible release: not draft, not prerelease, tag valid semver with no prerelease or build suffix
  (`semver.Prerelease == "" && semver.Build == ""`), and an asset named exactly the platform asset
  (`kira-space-macos-arm64.dmg`) with `state == "uploaded"` and `size > 0`.
- Last patch of `X.Y` = highest eligible release in line `X.Y`. First of `X.Y` = lowest eligible
  release in line `X.Y` (`X.Y.0` when it is eligible, else the next eligible patch).
- `Newest` = highest eligible release overall ("" when none).
- `Target` for running version `C`:
  1. Highest eligible release in line(`C`) strictly greater than `C`, if any (last patch of `C`'s minor).
  2. Else the first eligible line strictly after line(`C`): its lowest eligible release (`X.(Y+1).0`,
     or its first eligible patch when `.0` is missing or has no asset). Empty minors are passed over:
     no release exists to stop at.
  3. Else "" (no update).
- `Target > C` holds by construction, so no downgrade is ever offered. `C` need not be published
  (`0.3.7` tag without release, unreleased local build) and may be a prerelease (`0.4.0-rc.1` steps to
  `0.4.0`). `C` newer than everything published offers nothing. Clean install is not the app's job:
  `install.sh` without `--tag` keeps installing `releases/latest`.
- `Stepped` = `Target != "" && Target != Newest`.

D2. **Package split.** New leaf package `internal/releaseline` (imports only stdlib and
`x/mod/semver`): types `Release`/`Asset`, `Lines(rels, eligible) []Line`, `NextStep(current, rels,
asset) Step`. Retention tool imports the same package, so "last patch" and "first of minor" have one
definition for updater and retention. Leaf keeps the retention job's `go run` small (no ipcerr,
i18n, procgroup).

D3. **Release listing.** Replace `releases/latest` GET with
`GET https://api.github.com/repos/vlad-cirstean/kira-space/releases?per_page=100&page=N`, N from 1.
Stop on a page shorter than `per_page` (no Link-header parsing needed; a full last page costs one
extra empty request). Bounds: `maxPages = 10` (1,000 releases; exceeding is an error, fail closed),
`maxPageBytes = 8 << 20` (release bodies carry notes). Decode only `tag_name`, `draft`, `prerelease`,
`assets[].{id,name,state,size}`; never `browser_download_url` (S10). Same headers as today
(`Accept`, `X-GitHub-Api-Version`, `User-Agent`), same proxy-aware `httpClient`, 10 s timeout per
request. Any page failing (non-200, decode, cap) fails the whole check and keeps the previous cached
`Result` (existing refresh semantics): a partial list could drop an old install's own minor and
cause a jump, so never decide from a partial list.

D4. **Rate limits.** Unauthenticated limit is 60 requests/hour/IP. Cadence unchanged: Go cache 6 h
after success, 30 min after failure, singleflight, renderer polls hourly (cache floor decides).
One page today, so about 4 requests/day. No ETag/conditional requests: budget is ample, and a 304
on page 1 would not prove later pages unchanged. 403 or 429 with `X-RateLimit-Remaining: 0` (429
always) returns a sentinel `errRateLimited`; `FailureCause` maps it to `rate limited`. A poll stays
silent; manual Check shows `Couldn’t check for updates (rate limited).`.

D5. **Install a given tag.** `install.sh` gains optional `--tag=vX.Y.Z` (both modes). With it,
step 5 resolves `GET .../releases/tags/$TAG` instead of `releases/latest`; tag validated against
the existing `v[0-9]+.[0-9]+.[0-9]+` check before it reaches the URL; die messages say "release
$TAG" instead of "latest release". Everything else (asset URL prefix check, size, sha256 digest,
bundle version equals tag, `staged $TAG` handshake) unchanged. Contract marker stays `2`: the flag
is additive, every pre-P653 app (contract 2) never passes it and keeps working; bumping the marker
would make every installed app refuse the script. Update the line 11 usage text and line 15-16
comment ("adding an optional flag needs no bump; removing or changing one does").
`Installer.Stage(ctx, tag)` passes `--tag=<tag>`, and `handleLine` accepts only `staged <tag>`
for the requested tag; any other line is `installerStopped` with cause
`installer staged <x>, want <tag>`. `UpdateService.InstallUpdate` passes `"v" + Status().TargetVersion`.

D6. **Versions on the wire carry no `v`.** `Result{UpdateAvailable, CurrentVersion, TargetVersion,
NewestVersion}`, both version fields trimmed of `v` (today `LatestVersion` leaks `v0.3.14` next to
`0.3.14`). Wire `UpdateStatus{updateAvailable, currentVersion, targetVersion, newestVersion,
installLogPath}`; `latestVersion` is removed everywhere (one term per concept: target = offered
step, newest = highest published).

D7. **UI.** Status-bar item label unchanged in form (`Update {version}`) with `version` = target.
Tooltip adds row `Newest version` = newest, only when stepped. Dialog idle body keeps
`update-dialog-versions` with target, and adds, only when stepped,
`<p data-testid="update-dialog-step-note">`:
`{newest} is the newest version. {app} updates one minor version at a time, so it offers the next update after this one.`
Installing body names target. All Tailwind utility classes on existing shadcn-vue `Dialog`; no new
primitive, no scoped style.

D8. **Persistence and prompts.** Prompt ref and `dismissedVersion` key on target (store keeps key
`kira.appUpdate.dismissedVersion`; value was a version string before too). Later silences that
target until a different target appears; a newer `newest` with the same target does not re-prompt.
After a step the app relaunches as a fresh process: Checker cache is empty, first `Status` fetches,
next target differs from the dismissed one, router raises the popup for it. So a multi-minor
catch-up is a chain of prompted, clicked steps, each one minor (two clicks per minor: last patch,
then next `.0`). Nothing installs without the click (unchanged).

D9. **Retention keep set** (`scripts/releaseretention`, Go, table-tested). Candidates: published,
non-prerelease releases whose tag is `vX.Y.Z` with no suffix. Drafts, prereleases and other tags are
skipped and logged, never touched. "Has assets" = at least one asset of any name. Keep every asset of
a candidate if any of:
- `x.y.0`: patch is 0;
- `first of minor`: lowest candidate with assets in its line (D1's "first"; covers missing `.0`,
  so the updater's step 2 target always has assets);
- `last patch of minor`: highest candidate with assets in its line (updater's step 1 target);
- `current minor, last 5`: current line = line of highest candidate; its 5 highest candidates;
- `releases/latest`: tag the API returns for `/releases/latest`.
Delete every asset of every other candidate. Stable under rerun: kept releases keep assets, so first
and last per line never move except when a newer release appears; rerun deletes nothing new.
Reason "first/last with assets" uses any asset while the updater uses the platform asset; with one
asset per release today they coincide, and a future second platform asset only widens retention.
Abort (exit 1, delete nothing) when: latest tag is not a candidate; plan would delete an asset of the
latest release; listing empty while latest exists.

D10. **Retention workflow** `.github/workflows/release-retention.yml`, separate from `release.yml`
so its failure never fails a release.
- Triggers: `workflow_run` of `Release`, `types: [completed]`; `workflow_dispatch` with input
  `dry_run` (boolean, default `true`); `schedule` daily `'43 5 * * *'` as fallback. Reason for the
  schedule: `release.yml` normally starts from `release-on-merge.yml`'s `GITHUB_TOKEN` dispatch, and
  if GitHub creates no `workflow_run` for that chain, retention would never run unattended. Plan is
  idempotent, so an extra run is harmless. Orchestrator may drop it if unwanted.
- Job `if`: dispatch, schedule, or `github.event.workflow_run.conclusion == 'success'`.
- Dry-run first: dispatch uses `inputs.dry_run`. Unattended runs (workflow_run, schedule) apply only
  when repository variable `RELEASE_RETENTION == 'apply'`, else dry run. User sets the variable after
  inspecting a dispatch dry run (PACKAGING repository-settings step 6).
- `permissions: {}` at top; job `permissions: contents: write` only. `concurrency: group:
  release-retention, cancel-in-progress: false`. `runs-on: ubuntu-24.04`, `timeout-minutes: 10`.
- Steps: `actions/checkout@v7` (`persist-credentials: false`); `actions/setup-go@v7`
  (`go-version-file: go.mod`, `cache: false`); fetch: `gh api --paginate --slurp
  "repos/$GH_REPO/releases?per_page=100" > releases.json` and `gh api "repos/$GH_REPO/releases/latest"
  --jq .tag_name` (empty on 404 = no release yet: exit 0 with a log line); plan: `go run
  ./scripts/releaseretention -releases releases.json -latest "$LATEST" -deletes deletes.tsv` (log to
  stdout, also appended to `$GITHUB_STEP_SUMMARY`); apply: when `DRY_RUN=true` print `dry run: would
  delete N assets` and stop; else per line `gh api -X DELETE
  "repos/$GH_REPO/releases/assets/$ID"`, treating `HTTP 404` as already deleted (idempotent, same
  stderr-grep pattern as `release-on-merge.sh` `tag_commit`), logging each.
- Only endpoint that deletes is `releases/assets/{id}`. Never `git/refs`, never `releases/{id}`.

D11. **Release smoke covers `--tag`.** `release.yml` `install-smoke` keeps `sh scripts/install.sh`
(clean install path) and then runs `sh scripts/install.sh --tag="$TAG"` over it (tag path plus the
replace-older-copy path), then same asserts. This is the only CI that can run the macOS script.
Not cleanup, so it belongs in `release.yml`. Needs `TAG: ${{ needs.tag.outputs.tag }}` in env.

D12. **Transition, pre-P653 installs.** Builds up to `0.3.14` read `releases/latest` and run
`install.sh` without `--tag`, so they jump to the newest release. While newest is still `0.3.x` that
lands on the stepping updater. One that updates after `0.4.0` ships skips `0.3.last`'s migrations.
Not fixable from the server without duplicating the rule in shell. Record in ARCHITECTURE "Known open
items"; report to user. CLAUDE.md rule facts are unchanged (still P653), so CLAUDE.md is not edited.

D13. **Asset name single source pair.** Go const `macAsset = "kira-space-macos-arm64.dmg"` in
`internal/appupdate` (darwin/arm64 is the only shipped platform; other GOOS/GOARCH have no asset
name, so no update is offered). Extend S11 in `verify-packaging.sh`: `install.sh`'s `ASSET="..."` equals that Go
constant (sed both, compare). `release.yml` names the file; its comment already points at install.sh.
