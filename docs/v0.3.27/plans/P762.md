# P762: branch actions of `state` cannot target a row when a repo has several branches

Spec row: `SPEC.md` P762. Stream A of `plans/batch.md`.

## What "branches MCP" is

Kira Space tool server `kira-space` (`internal/agentmcp`), tool `state`. Its branch-scoped actions:
`branch.rename`, `branch.change`, `worktree.remove` (all name a task row by `{repo, branch|from}`).
`branch.request` resolves against registered repos, so it is not affected. `git` (rebase runs) already
takes `worktree`; out of scope.

## Root cause

`apps/kira-space/internal/ade/agenttools.go:114-125` `taskCandidates` appends one `repoCandidate` per
task row (`tc.branches`), not per repo. A task with two rows in repo `api` (P517 allows several
branches per repo) yields `[{id:R,name:api}, {id:R,name:api}]`.

`resolveRepoRef` (`agenttools.go:56-93`) then counts 2 hits in the nickname or name tier
(`:71-81`) and returns ToolError `"api" matches several repos. Use a code repo id: R, R.` Retrying with
the id `R` hits the id tier twice: same error. No input resolves the repo, so the agent cannot name
either branch.

Paper repro: task T, rows A (`api`, `feat/one`, worktree `wt/api/wt_a`) and B (`api`, `feat/two`,
`wt/api/wt_b`). `state worktree.remove {repo:"api", branch:"feat/two"}`:
`state.go:425` `RemoveWorktree` -> `worktreeremove.go:36` `resolveRepoRef(args.Repo,
b.taskCandidates(...))` -> 2 hits -> ToolError -> `state.go:427` invalid item. Same path for
`branchrename.go:144` (`renameTarget`), `branchchange.go:112` (`changeTarget`), and
`agenttools.go:417` (`taskBranch`), whose caller `setupwait.go:26-29` returns silently: the second
branch of a `branch.request` burst never waits for its setup (answers `created` while setup runs).

Existing coverage misses it: `TestAgentWorktreeRemove`, `TestBranchRename*`, `TestBranchChange*` use
one row per repo; `TestAgentBranchCreateNoPrompt` makes two `api` rows but never calls a row action.

Second gap (owner's ask): even resolved, the agent can only name a row by branch name. `state.yaml`
`repos[].worktree` and every `branch.request` reply give the worktree path; the row's identity is its
own folder (`worktreedir.go:112-114`), so the agent should be able to pass that path.

## Fix

### 1. Backend: dedupe candidates (root cause)

`agenttools.go` `taskCandidates`: skip a `CodeRepoID` already added (seen set). One candidate per repo.
Fixes all four callers, including `setupwait` (no code change there).

### 2. Backend: worktree selector

New helper in `apps/kira-space/internal/ade/agenttools.go`, next to `taskBranch`:

```go
// taskRow resolves an agent's row selector: worktree when given, else repo and branch. repo and branch
// may be empty with worktree; when given they must agree with the row the worktree names.
func (b *TaskBoard) taskRow(ctx context.Context, tc *taskCtx, cfgs []model.AdeRepoConfig, repo, branch, worktree string) (named *model.AdeTaskBranch, codeRepoID string, err error)
```

- `worktree == ""`: `resolveRepoRef(repo, taskCandidates, "task")`, then `taskRepoRows(tc, id, branch)`;
  `named` may be nil (callers keep their own "Branch %q is not on this task in that repo." error).
- `worktree != ""`: `want := filepath.Clean(worktree)`; one `b.newAttachCache()`; for each
  `tc.branches[i]` with `Name != ""`, `at := cache.worktree(ctx, row)`; match when
  `filepath.Clean(at.own) == want` or `at.attached != "" && filepath.Clean(at.attached) == want`.
  Own folder wins over attached when both match different rows (cannot happen for live rows; check own
  first, then attached).
  - no match: `agentmcp.ToolError(fmt.Sprintf("Worktree %q is not a worktree of this task. Its worktrees: %s.", worktree, joinOrNone(paths)))`, paths = each named row's `at.attached` (else `at.own`), non-empty, task order.
  - `repo != ""`: `resolveRepoRef(repo, ...)` must equal the row's `CodeRepoID`, else
    `ToolError(fmt.Sprintf("Worktree %q belongs to %s, not %s.", worktree, tc.nick[row.CodeRepoID], repo))`.
  - `branch != ""` and `branch != row.Name`: `ToolError(fmt.Sprintf("Worktree %q holds branch %s, not %s.", worktree, row.Name, branch))`.
  - returns `&tc.branches[i]`, `row.CodeRepoID`.

Callers switch to `taskRow`:

- `worktreeremove.go:32-47`: replace `resolveRepoRef` + `taskRepoRows` with
  `named, id, err := b.taskRow(ctx, tc, cfgs, args.Repo, args.Branch, args.Worktree)`. After it,
  `args.Branch = named.Name` (when named), so every text and the op subject (`:84`) carry the real
  name when the agent sent only `worktree`. `nick := tc.nick[id]`. Keep `named == nil` error as is.
- `branchrename.go:132-153` `renameTarget` and `branchchange.go:100-118` `changeTarget`: same swap with
  `(args.Repo, args.From, args.Worktree)`. `renameTarget` takes `ctx` already via `planRename`; add a
  `ctx context.Context` param to `renameTarget` (callers `:97`, `:340` pass theirs).
- `branchrename.go:64,67` and `branchchange.go:53,56` (late answers): use `plan.nick + "/" + args.To`
  instead of `args.Repo + "/" + args.To`, so an answer keyed by a worktree-only call reads
  `api/feat-x`, not `/feat-x`.

`taskBranch` (`agenttools.go:408`) stays on repo and branch; the dedupe fixes it.

Handlers:

- `stateBranchMove` (`:394-416`): read `wt := d.str("worktree")`. Before the call:
  `repo == "" && wt == ""` -> `invalidItem(d.action, "Name the branch with repo, or with worktree.")`.
  Pass `Worktree: wt` in both arg structs. Item id: `res.Repo + "/" + to` when the backend answered
  with `res.Repo != ""`, else `cmpNonEmpty(repo, wt) + "/" + to` (errors).
- `stateWorktreeRemove` (`:419-430`): `wt == "" && (repo == "" || branch == "")` ->
  `invalidItem(d.action, "repo and branch, or worktree, are required.")`. Pass `Worktree: wt`. Item id
  `res.Repo + "/" + res.Branch` on success, else `cmpNonEmpty(repo, wt) + "/" + branch` trimmed of a
  trailing `/`.

Back compat: every old call (`repo` + `branch`/`from`) decodes and behaves as before. The existing
`mcp_test.go:376` "remove blank" case (repo "", branch "x", no worktree) stays invalid.

## Tests (split at IPC boundary)

Scenario `ade-agent-multi-worktree`: task with two agent rows in `api` (`feat/one`, `feat/two`); the
agent removes `feat/two`'s worktree naming only its worktree path; `feat/one` keeps its row and folder.

### Go flow test

New `apps/kira-space/internal/flows/adeflow/agentmultiworktree_test.go`, `TestAgentMultiWorktree`,
header comment naming the contract and the UI spec. Fixture: `newRemoveFixture(t,
[]fakeagent.Action{{Name: "done"}})`, `one := f.agentCreate(t, "api", "feat/one")`,
`two := f.agentCreate(t, "api", "feat/two")`. Subtests share nothing (fresh fixture each):

1. "repo and branch resolve with two branches in one repo" (regression of the root cause):
   `RemoveWorktree({Repo:"api", Branch:"feat/two"})` -> `BranchRemoved`; `gone(t, two.Worktree)`;
   `one.Worktree` still exists; board rows of the task = `[feat/one]`.
2. "worktree alone picks the row": before removal store
   `f.app.Contract(t, "ade-agent-multi-worktree", "AdeTaskService.Board#before", rows, rowMask)`
   (rows sorted by name). `RemoveWorktree({Worktree: two.Worktree})` -> `BranchRemoved`,
   `res.Repo == "api"`, `res.Branch == "feat/two"`, `res.Worktree == two.Worktree`. Store
   `"AdeTaskService.Board#afterRemove"` (remaining task rows, `rowMask`). Op `agentWorktreeRemove`
   ok with subject `api/feat/two`.
3. "worktree with a disagreeing branch or repo is an error": `{Worktree: one.Worktree, Branch:
   "feat/two"}` -> error holds `holds branch feat/one, not feat/two`; `{Repo:"web", Worktree:
   one.Worktree}` with `web` declared on the task first (`DeclareRepos`) -> error holds `belongs to api,
   not web`; `{Worktree: "/nowhere"}` -> error holds `is not a worktree of this task`. Both folders stay.
4. "rename and change resolve in a two-branch repo": `RenameBranch({Repo:"api", From:"feat/two",
   To:"main"})` and `RenameBranch({Worktree: two.Worktree, From:"feat/two", To:"main"})` -> outcome
   `BranchFailed` with the reserved-name refusal (resolution passed, refused before any prompt);
   `ChangeBranch({Worktree: two.Worktree, From:"feat/two", To:"no/such"})` -> `BranchFailed` with the
   missing-local-branch refusal. Neither text holds `matches several repos`. `f.noApproval(t)`.
5. "the tool path": one fakeagent run proves `state` decodes `worktree`:
   `stateCall("worktree.remove", map[string]any{"worktree": <path>})`. The path is unknown when the
   fixture registers actions, so register after creating rows: `claude(f.app, map[string][]fakeagent.Action{"*": {{MCP: []fakeagent.MCPCall{call}, Name: "done"}}})`
   (re-registering a scenario; confirm `app.Scenario` replaces it, else build the fixture by hand as in
   the "session open" subtest of `TestAgentWorktreeRemove`). `f.startRun`, `waitRun(... "done")`,
   `f.resultOf(t, "worktree.remove", 1)` holds `"status":"done"`. The run's cwd is the repo root, not
   the removed worktree.

Write the contract with `KIRA_CONTRACT=write` once, commit `tests/contract/ade-agent-multi-worktree.json`.

Extend `internal/agentmcp/mcp_test.go` (existing state routing test near `:329` and the invalid table
near `:376`; not a new unit test): `fakeSpace.RemoveWorktree` records `args.Worktree` too
(`remove|task|repo/branch|worktree`); add a call `{"worktree": "/w/x"}` -> done and recorded; add
