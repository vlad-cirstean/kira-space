## 2. What "host" means per link

One display string per link, `host` below. Computed in backend, one function, so recognition stays in
`linkclassify.go` territory.

| Link | Example URL | `host` |
|------|-------------|--------|
| Change request on a code host | `https://github.com/acme/api/pull/482` | `github.com/acme/api` |
| Branch tree link / detected branch with URL | `https://github.com/acme/api/tree/feat/retry` | `github.com/acme/api` |
| Issue on a code host | `https://github.com/acme/api/issues/77` | `github.com/acme/api` |
| GitLab-style nested group | `https://forge.test/acme/platform/api/-/merge_requests/9` | `forge.test/acme/platform/api` |
| Jira slot / Jira issue link | `https://acme.atlassian.net/browse/PAY-130` | `acme.atlassian.net` |
| Doc / wiki / plain link | `https://docs.google.com/document/d/abc/edit` | `docs.google.com` |
| Link found in notes or handovers | `https://grafana.acme.io/d/latency` | `grafana.acme.io` (same rules) |
| `www.` host | `https://www.postgresql.org/docs/16/` | `postgresql.org` |
| Non-default port, IP, localhost | `http://10.0.4.12:8080/health` | `10.0.4.12:8080` |
| IDN host | `https://xn--bcher-kva.example/` | `xn--bcher-kva.example` (ASCII kept) |
| No URL: Jira key only, local-only branch | `PAY-12`, branch `wip/spike` | `''` |
| Unparsable or non-http URL | `notes://x`, `ftp://…` | `''` |

Rules, first match wins:

1. Empty, unparsable or non-http(s) URL: `''`.
2. `Registry.ParseBranchLink` claims URL: `Repo.Host` lowercased + `/` + `Repo.Owner` + `/` +
   `Repo.Name`. Owner/name keep provider case.
3. Else hostname lowercased, leading `www.` dropped, port kept when not default for scheme.

IDN stays punycode on purpose. Host is the trust cue for "where does this click go". A Unicode
lookalike (`gіthub.com` with Cyrillic `і`) would defeat it.

Local-only branch (no URL, `Artifact.Repo` set): pill falls back to repo nickname in host slot, drawn
with a `repo` icon so it never reads as a hostname. No URL and no repo: no host segment, pill as today.

## 3. Design

### Common to both options

- Host text: `font-data` (LAW 08: value from data, matches card URL line), `text-kira-sm`,
  `text-subtle` (`--kira-fg-subtle`, 5.29:1 on bg). Label stays `font-ui text-fg`.
- Status dot stays last, after host. Status words stay `sr-only` as today.
- Label dedupe: when label starts with host's bare hostname (auto-titled links like
  `wiki.example/x`), label shows the remainder without leading `/` (`x`). Remainder empty: label is
  host, host segment hidden. Applied in `linkGroups.ts`, not in templates.
- Bare refs: today `artifactLabel` prefixes repo nickname to `#12` (`api#12`). Host now names the
  repo, but nickname still disambiguates two repos on one host. Keep as is (open question Q3).
- Truncation: label shrinks first, host second. Host caps at `max-w-40` (160px), end ellipsis. Full
  label, host and URL stay in the card. `TruncatedText` tooltips a truncated label already; host gets
  the same component.
- Card (`AdeLinkCard.vue`): meta row gains host before repo (`data-testid="ade-links-card-host"`).
  URL line unchanged. Hidden when host empty.
- Add popover (`AdeLinkTarget.vue`): passes `host: ''`. Popover already prints the repo beside the
  pill; repeating it adds noise.
- Favicon: **no**. Requirements it cannot meet:
  - CSP `img-src 'self' data:` blocks remote images. Loosening it for arbitrary hosts opens a
    tracking channel.
  - Fetching `https://<host>/favicon.ico` or a favicon service sends every linked host (intranet
    hosts included) to a third party or the network on render. That breaks the "no network for
    found links" rule in `foundArtifact` and works offline only from a cache we would have to build.
  - Codicon kind icon already carries meaning (PR, branch, issue, doc, link). A favicon would replace
    meaning with branding.

  Kind icon plus host text is the identity. Known code host providers could later get a codicon
  glyph (`github`, `azure-devops`) from `HostInfo`. Out of scope unless owner asks (Q5).
- Empty states unchanged: no links shows existing `ade-links-empty`.
- Colour: only existing utilities (`bg-field`, `text-fg`, `text-subtle`, `border-border`,
  `text-muted-foreground`, tone dots). No new token. App is dark-only today; the mockup's light
  palette is a stand-in so owner can judge contrast if a light theme ever ships (Q6). Tokens
  map 1:1, so a light theme would need no change here.

### Option A: pill with host segment (recommended)

Keep strip layout, categories, wrapping, roving model, card. Pill becomes two segments:

```
[icon] Fix retry backoff │ github.com/acme/api ●
```

- Segment divider: `border-l border-border pl-1.5 ml-0.5` inside the Badge, not a `·` glyph
  (reads cleaner at 11px, no extra character to screen readers).
- Pill max width `max-w-48` (192px) grows to `max-w-80` (320px).
- Kind icon shows on every pill, not only Misc: with host present, icon separates label from host at
  a glance. Category icon column stays.
- Found links: dashed outline and note icon unchanged; host segment same.
- Height unchanged (18px pill, 24px line). Strip grows only by extra wrapping.
- `aria-label` of pill: `"<label>, <host>"`, so screen readers hear host too.

Pros: smallest change; all keyboard, popover and collapse code untouched; dialogs (stage, run) stay
compact. Cons: hosts do not align, so scanning "which links go to Jira" needs reading each pill;
wider pills wrap sooner (8 links take 3-4 lines at Details width instead of 3).

### Option B: list rows with host column

Strip becomes a list. One 24px row per link:

```
⊙  PAY-130  Checkout times out on retry ............... acme.atlassian.net   ●
⎇  #482 Fix retry backoff ........................... github.com/acme/api   ●
```

- Grid per row: kind icon 16px, label `1fr` truncating, host right-aligned (`max-w-[40%]`), status
  dot 8px. Category icon on first row of each category only; group gap `gap-1.5`.
- Row hover `bg-field`, `rounded-kira-sm`; focus-visible ring as today.
- Roving orientation becomes vertical; Up/Down move rows, the line-jump branch in `onKeydown`
  (151-160) goes. Left/Right free.
- "+N more" becomes a last row of the category.
- New `AdeLinkRow.vue` for the strip; `AdeLinkPill.vue` stays for `AdeLinkTarget.vue` (Option A's
  host segment not needed there).

Pros: host column scans; long titles get full width; reads like a link list. Cons: height grows with
link count (8 links: ~8 rows, about 2.5x today) in all three mounts, which matters most in the stage
and run dialogs; larger blast radius (keyboard model, more UI specs, all three baselines change shape).

### Recommendation

Option A. Owner asked to add host, not to change how the strip behaves. A keeps keyboard model,
popover and dialog height, and touches the fewest specs. B is right if owner wants link list scanning
by host; it is a bigger redesign and could ship later on top of the same `host` field.

Rejected: grouping by host (one line per host). Categories already group, and two groupings fight.

## 4. Implementation plan (after sign-off)

One sequential Sonnet implementer. Backend first, then frontend, then tests.

### Backend

1. `internal/ade/linkhost.go` (new): `func (b *TaskBoard) linkHost(ctx context.Context, raw string) string`
   with rules from §2. Uses `b.hostRegistry()` and `httpURL` from `linkclassify.go`.
2. `internal/bridge/adewire/wire.go`: `Artifact.Host string \`json:"host"\`` ('' none) and
   `Jira.Host string \`json:"host"\``. Additive key: contract change per P143 rule 1; note it in the
   wire header comment's change list if that file keeps one.
3. Fill `Host`:
   - one pass at the end of `taskArtifacts` (`artifacts.go:79`) over merged rows, so every source
     (task, stored, host/git, notes) gets it without touching each builder;
   - `toWireTask` (`board.go:717`) for `Jira.Host`.
   - Cost: `ParseBranchLink` is pure string parsing per provider (`Claims` reads config); no network.
4. Host slot: backend already emits the host-slot artifact (`taskLinkSource`), so it carries `Host`.

### Frontend

5. `frontend/src/ade/v2/wire.ts`: `Artifact.host`, `Jira.host`.
6. `frontend/src/ade/v2/links/linkGroups.ts`: `LinkItem.host`; `fromArtifact` copies it; Jira slot
   uses `jira.host`; host slot takes `host` from the artifact with the same normalized URL (build
   the map before the dedupe at 148-163); label dedupe from §3.
7. Option A: `AdeLinkPill.vue` host segment (`data-testid="ade-links-pill-host"`, `data-host`),
   `max-w-80`, kind icon always (drop `showKind` prop or default true; `AdeLinkStrip.vue:255` and
   `AdeLinkTarget.vue:74` updated), `aria-label`. Option B instead: new `AdeLinkRow.vue`,
   `AdeLinkStrip.vue` list layout and vertical roving.
8. `AdeLinkCard.vue`: host in meta row.
9. `AdeLinkTarget.vue`: `host: ''`.
10. i18n: none for A (host is data). Pill `aria-label` pattern key
    `space.ade.links.pill.aria` if one is needed for `"{label}, {host}"`.

Frontend rules: Tailwind utilities only, no scoped style; Badge from shadcn-vue stays the pill
primitive; `TruncatedText`/`TextTooltip` existing theme components; host is server state from
`useTaskArtifacts` (TanStack Query), no Pinia store, no client-side host parsing. VueUse not needed.

### Tests, split at IPC boundary

  `Artifacts` returns `host` for the PR (`forge.test/acme/api`), branch tree link

  Up/Down row navigation to the same spec and drops the line-jump case.
- No unit test: dedupe is one prefix check; host rules are covered by the flow test.
- Existing UI specs that read `ade-links-pill-label` text keep passing (label testid unchanged);
  implementer greps `ade-links-pill` and fixes any text assertion that read the whole pill.
