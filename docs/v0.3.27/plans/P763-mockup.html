  • Tier rule (existing data, see plan section 3): main = Jira slot, host slot, every detected row (id empty, source not notes: change requests, issues, branches, deployments), and stored rows whose URL is one of the task's own change requests. Related = every other stored row (user paste, agent report) and every found link.
  • Main rows: text fg, host fg-subtle. Related rows: text fg-muted, host at 75%, kind icon subtle. Found rows keep the note icon; the dashed outline goes (detected rows are now main, so "dashed = detected" no longer holds).
  • Host column: code host github.com/acme/api (hostname gives way first when narrow); other links hostname, www. dropped, port kept, punycode kept; no URL: repo nickname with repo icon, or Jira for a key-only issue. Same host as the row above (same tier) dims.
  • Name: real title in UI font; else identifier in data font (PAY-130, #77, feat/retry-backoff); else URL rest after the host, muted; host-only URL shows /.
  • Secondary: ref beside a title (#482), URL rest beside a titled doc, short sha beside a deployment, local beside an unpushed branch. Truncation order: secondary, name (min 6ch), hostname part, repo part.
  • Kind order inside a tier: issue, change request, branch, deployment, doc, link; found links last in related. Main never collapses; related collapses above 3 rows.
