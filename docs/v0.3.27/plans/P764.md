# P764: Task colours as a faint background (design for review)

Owner request: "Redesign task colours using a fainted background. This implies the task details, and
review window use the same fainted color and design."

Iteration 2 owner feedback, applied here:

1. Remove the 3px colour line under the task details header and the review/files title bars. Only
   the tint carries the colour there.
2. Stronger tint, so tasks tell apart more easily. Adjust palette slots rather than lower the tint
   when a slot fails contrast.
3. Four options for the selected card, shown next to rest and hover. Recommend one.

Status: design for owner review. No product code. Mockup: [`P764-mockup.html`](P764-mockup.html)
(open locally; dark and light, toggle top right).

## 2. Design

### Principle

Hue lives in the ground. Text, borders, controls stay neutral tokens. Colour lines under headers go
(owner point 1); the tint alone marks the task in details, review and files windows.

### Tint formula

Opaque mix over chrome, so card, card head, details head and title bars share one value:

```css
--task-tint:       color-mix(in srgb, var(--task-color) var(--kira-task-tint), var(--kira-bg-chrome));
--task-tint-hover: color-mix(in srgb, var(--task-color) var(--kira-task-tint-hover), var(--kira-bg-chrome));
--task-edge:       color-mix(in srgb, var(--task-color) 40%, var(--kira-bg-chrome));
```

Percentages are theme tokens in `tokens.css`, so a future light `:root` can retune them.

### Intensity

| Option | Rest | Hover / selected ground | Palette |
|---|---|---|---|
| Strong (default, recommended) | 14% | 18% | adjusted, table below |
| Soft (alternative) | 10% | 14% | unchanged |

Iteration 1 used 8% / 14%. Strong is 1.75x at rest. Median pairwise OKLab distance between resting
tints: 0.0160 at 8%, 0.0256 at strong 14% (+60%). Soft keeps the palette untouched and is the
fallback if the owner rejects any palette shift. Neighbouring low-chroma slots (16 slate, 19 grey) stay
close at any tint (dE 0.0063); that pair needs the card title, not the tint, to tell apart.

### Palette adjustment (strong option)

Rule: at the 18% hover/selected ground every text grade keeps 4.5:1. For each failing slot, lower
OKLCH lightness only, until subtle text passes; hue and chroma held. Hue drift at most 1.1 deg
(slot 19, neutral grey: 4.3 deg, imperceptible at chroma 0.013). Full colour against chrome stays
5.02-5.67:1 (minimum is slot 8, unchanged).

### Contrast (WCAG 2.x, worst of 20 slots, dark theme, tint over chrome)

| Ground | fg | muted | subtle |
|---|---|---|---|
| today chrome | 12.56 | 7.24 | 5.71 |
| today selected `select` | 8.12 | 4.68 | 3.70 (fails) |
| original palette 14% | 9.90 | 5.71 | 4.51 |
| original palette 18% | 9.10 | 5.25 | 4.14 (fails: why the palette moves) |
| soft rest 10% (original palette) | 10.71 | 6.18 | 4.88 |
| strong rest 14% (new palette) | 10.53 | 6.07 | 4.79 |
| strong hover/selected 18% (new palette) | 9.90 | 5.71 | 4.51 |
| new palette 10% | 11.15 | 6.43 | 5.07 |

Every grade passes 4.5:1 on every resting, hover and selected ground in the strong option.

Light (preview only, no light theme ships; new palette, zinc light chrome `#f4f4f5`, fg `#18181b`,

### Placement

- Plan card: whole card on `--task-tint` (head and branch rows), 1px `--task-edge` border. Hover head
  or row: `--task-tint-hover`. Ripple: dashed `--task-edge`. Day band span rows: same as card head.
- Task details: head band (`DetailHeader` incl. forward bar, alerts) on `--task-tint`. No colour line.
  Tab row and tab body neutral.
- Review and files windows: title bar on `--task-tint`. No colour line. Gutter, tab strip, panes
  neutral.
- Branch panel: same band; a review card uses `--kira-info` as its `--task-color`.
- Lists (shelf, needs, sessions): keep the 16x3 mark (question 4).

### Selected card: four options

All four keep the 18% ground on hover. Text contrast is per option; none uses `select` grey any more,
so the 3.70:1 failure goes away in S1-S3.

| | Selected treatment | Text contrast (worst slot) | Cue contrast | Cost |
|---|---|---|---|---|
| S1 Neutral ring (recommended) | ground 18%; 2px inset ring `--kira-fg` | fg 9.90, muted 5.71, subtle 4.51 | ring 9.90:1 on tint, 12.56:1 on chrome | `taskGrid.ts` only |
| S2 Colour ring | ground 18%; 2px inset ring in full task colour | same as S1 | ring 4.02:1 on its tint, 5.02:1 on chrome | `taskGrid.ts` only |
| S3 Lifted | ground 18%; 1px `--kira-select-edge` border; `shadow-kira`; 1px inner top highlight | same as S1 | border 3.84:1 on chrome; shadow weak on dark | `taskGrid.ts`, card class |
| S4 Solid head | head on full task colour, all head text `--kira-bg-chrome`; rows stay 14% | head text 5.02:1 (slot 8); one grade only (dark secondary at 80% chrome fails, 3.90) | head is the cue | dark variants for status chip, step segments, action button, hover overlay |

- S1: highest contrast, colour-independent, so a selected card next to a same-hue neighbour (slots 3
  and 14) still stands out. Fits P710 (selection neutral). Risk: the keyboard focus ring is also
  neutral grey (`--kira-focus` `#a1a1aa`); keep focus as an outline offset 2px outside the card and
  selection as a flush inset ring, so both read apart when they coincide.
- S2: in-family with today's look (colour outline), but between same-hue neighbours the selected
  card differs only by ring presence, and ring on tint is only 4.02:1.
- S3: subtle on dark; elevation barely reads on chrome. Tinting over `elevated` instead was rejected:
  subtle drops to 4.31 at 10%.
- S4: loudest, but every control in the head needs an inverted variant, and secondary text loses
  its grade.

Recommendation: S1. Selected branch row inside a card follows the same rule: 18% ground plus a 1px
inset `--kira-fg` ring, replacing `GROUND_SELECTED` grey.

Details panel context: the band stays at the resting tint (14%) whatever the selection option, so
details and review stay identical. The selected card in the plan list carries the selection cue; the
mockup shows each option beside the open details panel.
