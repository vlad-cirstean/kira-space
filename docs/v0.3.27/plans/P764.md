# P764: Task colours as a faint background (design for review)

Owner request: "Redesign task colours using a fainted background. This implies the task details, and
review window use the same fainted color and design."

Decided so far:

- No colour line under the task details header or the review/files title bars. The tint alone marks
  the task there (round 1).
- Selected card: neutral ring (S1) (round 2).
- Target design: A+C, header-only tint on a calmer palette (round 4). Options A-D stay below as
  reference.

Status: design for owner review. No product code. Mockup: [`P764-mockup.html`](P764-mockup.html)
(open locally; Today, A, C and A+C side by side; dark and light toggle top right).

## 2. Design

### Principle

Hue lives in the header ground only. Card body, text, borders and controls stay neutral tokens. No
colour lines under headers.

### Formula

Opaque mix over chrome, so card head, details head and title bars share one value:

```css
--task-tint:       color-mix(in srgb, var(--task-color) var(--kira-task-tint), var(--kira-bg-chrome));
--task-tint-hover: color-mix(in srgb, var(--task-color) var(--kira-task-tint-hover), var(--kira-bg-chrome));
```

### Target: A+C (header-only tint, calm palette)

- Palette: A's calm palette (OKLCH chroma x0.75, lightness and hue held, hue drift at most 1.2 deg).
  Applies to every colour use (list marks, base marker, phone dot).
- Card head band: 8% at rest, 12% on hover and when selected. Branch rows neutral chrome; row hover
  `field`. Card border neutral 1px `--kira-border`.
- Details panel head and review/files title bar: the same 8% band. Bodies neutral.
- Selection: S1 ring (below).

Why 8% and 12%:

- Rest 8%: the header alone carries identity, so it needs more than A's whole-card 6% (median dE
  0.0121 vs 0.0092). Yet it stays well under C's 12% on the brighter original palette (0.0234), which
  the owner found too much.
- Hover and selected 12%: the step from rest is clear (per-slot dE median 0.0225, min 0.0201, about
  twice C's 12-to-14% step of 0.0112). Subtle text stays at 4.69, the same floor C had at rest. 14%
  would drop subtle to 4.51, which is too close to the 4.5 limit.

Cost of A+C: distinguishability at rest is about half of C (0.0121 vs 0.0234) and about 60% of Soft.
The same-hue neighbours 3 and 14 sit 0.0067 apart at rest, so in that pair the hue reads only side by
side. The title and key still separate them.

### Selected card: S1 neutral ring (decided)

- Head ground steps to 12%. A 2px `--kira-fg` ring sits inside the card edge (inset outline, painted
  above head and row grounds). Ring contrast: 10.30:1 on the selected head, 12.56:1 on chrome rows.
- Grey `select` is no longer used on cards, so the 3.70:1 subtle failure goes away.
- Selected branch row in a card: `field` ground (subtle 4.58) plus a 1px inset `--kira-fg` ring.
- Focus ring stays outside: card keyboard focus is an outline offset 2px outside the card; selection
  is flush inside. Both read apart when they coincide.

### Light theme (preview only, P138 open item)

A+C bands pass in the light preview (table above, subtle `#5f5f68`). Full palette colours on white
stay below 3:1 for several slots, so a shipped light theme would need light palette variants for
marks. Out of scope here.

### Shared design: `AdeTaskBand` + `task-tint` utilities

- `apps/kira-space/frontend/src/ade/v2/taskTint.css` (imported beside `tones.css`): Tailwind v4
  `@utility task-tint` (sets `--task-tint`, `--task-tint-hover` from `--task-color`, paints
  `background-color: var(--task-tint)`) and `@utility task-tint-vars` (variables only).
- `packages/theme/src/tokens.css`: `--kira-task-tint: 8%`, `--kira-task-tint-hover: 12%`.
- `apps/kira-space/frontend/src/ade/v2/AdeTaskBand.vue` (`<script setup lang="ts">`): prop
  `color: string`; root `task-tint` with inline `--task-color`; default slot. No `ColorLine`.
  `data-testid="ade-task-band"`.
- Users: card head (via `task-tint-vars`), `AdePanelFrame` head (task, branch, archived panels),
  `AdeReviewHeader`, `AdeTaskFilesWindow`, day band span rows.
