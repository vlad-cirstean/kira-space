# P764: Task colours as a faint background (design for review)

Owner request: "Redesign task colours using a fainted background. This implies the task details, and
review window use the same fainted color and design."

Decided so far:

- No colour line under the task details header or the review/files title bars. The tint alone marks
  the task there (round 1).
- Selected card: neutral ring (S1) (round 2).

Open in this round (round 2 feedback): the previous Strong tint is "a bit too much". Four calmer
options (A-D) below, each with contrast and a distinguishability figure, so the cost of calm shows.

Status: design for owner review. No product code. Mockup: [`P764-mockup.html`](P764-mockup.html)
(open locally; all options side by side; dark and light toggle top right).

## 2. Design

### Principle

Hue lives in the ground. Text, borders, controls stay neutral tokens. No colour lines under headers.

### Common formula

Opaque mix over chrome, so card, card head, details head and title bars share one value:

```css
--task-tint:       color-mix(in srgb, var(--task-color) var(--kira-task-tint), var(--kira-bg-chrome));
--task-tint-hover: color-mix(in srgb, var(--task-color) var(--kira-task-tint-hover), var(--kira-bg-chrome));
```

Percentages are theme tokens in `tokens.css`. Option B uses a precomputed ground table instead (below).

### Calm options

Distinguishability: median pairwise OKLab distance between the 20 slot grounds (higher tells tasks
apart more easily), and the closest pair. Contrast: WCAG 2.x, worst of 20 slots, dark theme.

- Cost: half the distinguishability of Soft (0.0092 vs 0.0197). Cards read as almost-grey with a hint.

#### B Muted hue

- Ground is OKLCH lightness 0.198 (chrome 0.188 plus the lift a 4% tint gives) at chroma 0.010 in the
  task hue; hover and selected: lightness 0.213, chroma 0.018. Same luminance for every slot, so
  yellow no longer glows brighter than blue.
- Precomputed per slot in `palette.ts` (`TASK_GROUND`, `TASK_GROUND_HOVER`); no CSS relative colour
  syntax, so no webview version risk. Dark rest grounds, slot 0-19: `#1a1412 #181511 #161611 #141612
  #121713 #111716 #111719 #13161a #14151a #161519 #181418 #191416 #1a1414 #191511 #151611 #111715
  #13161a #171419 #1a1414 #151516`.
- Cost: only hue differs, so near-hue slots collide. Slots 7 and 16 and slots 12 and 18 get the same
  ground (`#13161a`, `#1a1414`).

#### C Header-only tint (recommended)

- Card head band 12% (hover 14%, selected 14%). Branch rows neutral chrome; row hover `field`.
  Card border neutral 1px `--kira-border`.
- Details panel head and review/files title bar: same 12% band. Bodies neutral.
- Why recommended: total coloured area drops to the head strip (one 44px band per card instead of the
  whole card with its branch rows), so the board reads calmer, yet each band keeps the highest
  distinguishability of the four (0.0234, above Soft's 0.0197). The card head, details head and title
  bar become one visual element: "task colour lives in the header", which is the "same design" the
  owner asked for. No palette change.
- Cost: head band contrast is the lowest of the four (subtle 4.69 at rest, 4.51 on hover), still
  above 4.5:1.

#### D Tint on hover and selection only

- Rest: neutral chrome card with a 1px 40%-mix edge as the only colour cue. Hover and selected 10%.
- Details panel and review show the selected task, so their band is 10%.
- Cost: at rest nothing but the thin edge tells tasks apart (edge-to-edge dE 0.0679, but 1px only).
  Calmest board, weakest at-a-glance identity; tint appears and disappears with the pointer.

### Selected card: S1 neutral ring (decided)

- Ground steps to the option's hover/selected value (C: head 14%). 2px ring `--kira-fg` drawn inside
  the card edge (inset outline, paints above head and row grounds).
- Ring contrast against the selected ground: 9.90:1 (C), 10.71:1 (A, D), 11.82:1 (B); 12.56:1
  against chrome. Text on the selected ground: the hover column above. Grey `select` is no longer
  used on cards, so the 3.70:1 subtle failure goes away.
- Selected branch row in a card: `field` ground (subtle 4.58) plus a 1px inset `--kira-fg` ring.
- Focus ring stays outside: card keyboard focus is an outline offset 2px outside the card; selection
  is flush inside. Both read apart when they coincide.

### Light theme (preview only, P138 open item)

With light chrome `#f4f4f5`, fg `#18181b`, muted `#52525b`, subtle `#5f5f68`: C head 12% 14.25 /
6.22 / 5.08 (14%: 13.95 / 6.09 / 4.98); A 6% 15.18 / 6.62 / 5.41; B 15.46 / 6.74 / 5.51; D 10% 14.55 /
6.35 / 5.19. Full colours stay 1.86-3.76:1 on white: rings and edges need light palette variants.

### Shared design: `AdeTaskBand` + `task-tint` utilities

- `apps/kira-space/frontend/src/ade/v2/taskTint.css` (imported beside `tones.css`): Tailwind v4
  `@utility task-tint` (sets `--task-tint`, `--task-tint-hover` from `--task-color`, paints
  `background-color: var(--task-tint)`) and `@utility task-tint-vars` (variables only).
- `packages/theme/src/tokens.css`: `--kira-task-tint: 12%`, `--kira-task-tint-hover: 14%` (C).
- `apps/kira-space/frontend/src/ade/v2/AdeTaskBand.vue` (`<script setup lang="ts">`): prop
  `color: string`; root `task-tint` with inline `--task-color`; default slot. No `ColorLine`.
  `data-testid="ade-task-band"`.
- Users: card head (via `task-tint-vars`), `AdePanelFrame` head (task, branch, archived panels),
  `AdeReviewHeader`, `AdeTaskFilesWindow`, day band span rows.
