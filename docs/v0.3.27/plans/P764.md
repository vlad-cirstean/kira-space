# P764: Task colours as a faint background (design for review)

Owner request: "Redesign task colours using a fainted background. This implies the task details, and
review window use the same fainted color and design."

Decided so far:

- No colour line under the task details header or the review/files title bars (round 1).
- Selected card: neutral ring (S1) (round 2).
- Structure: header-only band, neutral card body (rounds 4-6).
- 10 colours; the round 6 "More saturated" direction (round 7).
- Calm, harmonious, clearly distinct named hues; no neon, no pastel mix (round 7).

Open: Pure-B or Pure-B+ band chroma (recommended Pure-B+).

Status: design for owner review. No product code. Mockup: [`P764-mockup.html`](P764-mockup.html)
(open locally; More set reference, Pure-A, Pure-B, Pure-B+ side by side; dark and light toggle top right).

## 2. Design

### Principle

Hue lives in the header band only. Card body, text, borders and controls stay neutral tokens. No
colour lines under headers. The band tells tasks apart through hue spacing at equal lightness, not
loudness.

### Diagnosis (round 7)

- Washed-out inks: the round 6 set mixed light pastels (lavender `#b3a6fe`, pink `#fe91b1`) with loud
  slots (citron `#a2a203`, cyan `#12cff6`). Ink lightness spread 0.10, chroma spread 0.026.
- The band shrank hue toward grey: an 8% sRGB `color-mix` over the dark chrome keeps only a few
  percent of each hue's chroma (band chroma 0.014-0.023). Band separation therefore depended on ink
  loudness. Proof: calm inks with the same `color-mix` band (Pure-A) separate worse than the loud set
  (band min 0.0077 vs 0.0136).
- Fix both: calm inks with one lightness and chroma, and a band defined directly in OKLCH at a fixed
  dark lightness with explicit chroma. Every slot then gets the same text contrast and far more hue
  separation.

### Inks: 10 named hues

- Hues are 36 deg apart in OKLCH, starting at red 20 deg. Lightness 0.68 for all; amber 0.76, because
  amber at 0.68 reads ochre. Chroma 0.13, clamped to the sRGB gamut (teal 0.115).
- Equal spacing is the optimum here. A search over hue offsets and per-slot nudges, maximising the
  minimum ink and band distance, returned an equal 36 deg grid. At equal chroma, OKLab already
  corrects the green/cyan compression of HSL hue. Moving hues onto "name" anchors (red 25, orange
  55, ...) lowered the minimum band distance by 16%.
- Slot order is farthest-first on the band, so the first live tasks and consecutive slots are
  maximally apart: red, teal, amber, violet, blue, orange, magenta, green, lime, sky.

### Bands

- Pure-A: pure inks, `color-mix(in srgb, ink 8%/12%, chrome)` as in round 6.
- Pure-B: OKLCH band, rest L 0.235 C 0.035, hover/selected L 0.250 C 0.045.
- Pure-B+: OKLCH band, rest L 0.235 C 0.045, hover/selected L 0.250 C 0.055.
- Every chroma is clamped to the sRGB gamut for its hue: cyan-teal tops out near 0.041 at L 0.235.
  That keeps band chroma spread at 0.006 (Pure-B+: 0.040-0.046).
- Text limit: on a neutral ground, subtle text hits 4.5:1 near L 0.27. L 0.235 and 0.250 keep every
  grade on every slot at or above 4.85:1.

- Against the More set: Pure-B+ band minimum 1.9x, median 2.6x; Pure-B 1.4x and 2.1x. Text contrast
  is higher in both, because every band sits at the same lightness.
- Closest band pair: Pure-B teal/sky; Pure-B+ teal/green.

  lightness lift.

- Inks drop from the More set's 0.118 to 0.077 minimum distance by design (calm, equal chroma). Inks
  appear only on small marks; the band carries identity on surfaces.
- Light preview: OKLCH bands at L 0.955 / 0.935: 15.38 / 6.71 / 5.48 rest, 14.40 / 6.28 / 5.13 hover.

### Recommendation: Pure-B+

- It is the most distinguishable option, with the highest minimum, median and adjacent distance. It
  keeps text contrast above today's 12% band.
- It stays calm: band chroma 0.045 at L 0.235 is a dark, faint tint, and every slot carries the same
  lightness and nearly the same chroma, so no slot glows. Ink chroma 0.13 with spread 0.016 and
  lightness spread 0.08 passes the circus check.
- Pure-B is the fallback if the owner wants the bands fainter still. It is still 1.4x the More set's
  minimum.

### CSS: tokens or precomputed hex

- The webview supports `oklch()`. Release notes require macOS 14 or later (`.github/workflows/release.yml:213`);
  `apps/kira-space/build/darwin/Info.plist:530` sets `LSMinimumSystemVersion` 26.0.0. Either way
  WKWebView is at least Safari 17-level, and `oklch` shipped in Safari 15.4.
  UI tests run in Playwright WebKit and e2e-real in Chromium; both support it. Tailwind 4.3.3 emits
  `oklch` in its own palette.
- Still precompute hex per slot (`TASK_BAND`, `TASK_BAND_HOVER` in `palette.ts`, inline
  `--task-band` / `--task-band-hover`). Three reasons:
  - Each slot needs its own gamut-clamped chroma, so a shared `--kira-task-band-c` token would need
    `min()` inside `oklch()` per slot.
  - WebKit and Chromium gamut-map out-of-range `oklch` differently, and UI specs compare computed
    colours across both.
  - The repo stores perceptual palettes as hex with their OKLCH recipe in a comment (`tokens.css:161`
    connection palette, `:177` status palette).
- The recipe lives as tokens: `--kira-task-band-l: 0.235`, `--kira-task-band-c: 0.045`,
  `--kira-task-band-l-hover: 0.250`, `--kira-task-band-c-hover: 0.055`. They document the values
  and drive the unit guard; no CSS reads them.

### Slot model: 20 to 10 (unchanged from round 6)

Stored `AdeTask.Color` is an int 0-19 (`internal/storage/model/adetask.go:56`). `pickColorSlot`
(`internal/storage/repos/adetask.go:388`) assigns the first slot no live task uses, else the least
used. `patchLeaves` (`:594-599`) rejects values outside `0..maxColorSlots-1`.

1. Migration `0112_p764_color_slots_10.sql`: `UPDATE ade_tasks SET color = color % 10 WHERE color >= 10;`.
2. `maxColorSlots = 10`; `pickColorSlot` and `patchLeaves` keep their logic.
3. `palette.ts`: 10 inks plus 10 rest and 10 hover band hex, indexed directly.

Effect: slots 0-9 keep their number and take the new colour; 10-19 become slot minus 10. Two live tasks
can share a colour (old 3 and old 13) until one is archived; new tasks avoid both.

### Selected card: S1 neutral ring (decided)

- Head band steps to the hover/selected value. A 2px `--kira-fg` ring sits inside the card edge
  (inset outline, painted above head and row grounds). Ring contrast: 10.65:1 on the selected head,
  12.56:1 on chrome rows.
- Grey `select` is no longer used on cards, so the 3.70:1 subtle failure goes away.
- Selected branch row in a card: `field` ground (subtle 4.58) plus a 1px inset `--kira-fg` ring.
- Focus ring stays outside: card keyboard focus is an outline offset 2px outside the card; selection
  is flush inside.

### Light theme (preview only, P138 open item)

Light bands pass (numbers above). Every ink is below 3:1 on white, so a shipped light theme needs light
ink variants for marks. Out of scope.

### Shared design: `AdeTaskBand`

- `apps/kira-space/frontend/src/ade/v2/AdeTaskBand.vue` (`<script setup lang="ts">`): prop `slot: number`
  (or the band pair), root `bg-(--task-band)` with inline `--task-band` / `--task-band-hover` from
  `taskBand(slot)`; default slot. No `ColorLine`. `data-testid="ade-task-band"`.
- Users: card head, `AdePanelFrame` head (task, branch, archived panels), `AdeReviewHeader`,
  `AdeTaskFilesWindow`, day band span rows.
