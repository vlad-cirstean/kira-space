# P764: Task colours as a faint background (design for review)

Owner request: "Redesign task colours using a fainted background. This implies the task details, and
review window use the same fainted color and design."

Decided so far:

- No colour line under the task details header or the review/files title bars (round 1).
- Selected card: neutral ring (S1) (round 2).
- Structure: header-only band, neutral card body, 8% rest and 12% hover/selected (rounds 4-6).
- 10 task colours, not 20, each clearly distinct (round 6). Open: less or more saturated set.

Status: design for owner review. No product code. Mockup: [`P764-mockup.html`](P764-mockup.html)
(open locally; Today, Less saturated and More saturated side by side; dark and light toggle top right).

## 2. Design

### Principle

Hue lives in the header ground only. Card body, text, borders and controls stay neutral tokens. No
colour lines under headers.

### Formula

Opaque mix over chrome, so card head, details head and title bars share one value:

```css
--task-tint:       color-mix(in srgb, var(--task-color) var(--kira-task-tint), var(--kira-bg-chrome));
--task-tint-hover: color-mix(in srgb, var(--task-color) var(--kira-task-tint-hover), var(--kira-bg-chrome));
```

`--kira-task-tint: 8%`, `--kira-task-tint-hover: 12%`. 12% is also the ceiling: both new palettes keep
every text grade at or above 4.5:1 up to 12% and fail subtle at 13%.

### Placement

- Card head band: 8% at rest, 12% on hover and when selected. Branch rows neutral chrome; row hover
  `field`. Card border neutral 1px `--kira-border`.
- Details panel head and review/files title bar: the same 8% band. Bodies neutral.
- Selection: S1 ring (below). Full colour (ink) stays only on small marks: list marks, base marker,
  phone dot.

### 10-colour palettes

Method: 10 hues spaced exactly 36 deg apart in OKLCH (no two slots share a hue family). Per slot,
lightness alternates within 0.69-0.79 where that raises the minimum distance. The search maximises the
minimum pairwise OKLab distance of the 8% header grounds, with the full-colour ink distance as a
secondary goal. Every candidate must keep fg, muted and subtle at or above 4.5:1 on both the 8% and
12% grounds. Slot order is farthest-first: each next slot is the one farthest from all earlier ones.
`pickColorSlot` hands out the lowest free slot, so the first few live tasks get the most distinct
colours and slots adjacent in assignment order are never close.

### Recommendation: More saturated

- It wins every distance figure at the same text contrast. Its closest header pair (0.0129) is above
  the median of the round 4 calm palette (0.0121). All 10 header colours read apart at a glance.
- On surfaces only the 8% band shows, so the saturation stays faint there. The muddiness came from
  low chroma and 20 crowded hues. Full chroma only appears on dots and marks, where saturation helps.
- Cost: as ink, citron `#a2a203` and cyan `#12cff6` are loud. If the owner finds the marks too bright,
  Less saturated keeps 2x today's minimum distance with softer ink.

### Slot model: 20 to 10

Stored `AdeTask.Color` is an int 0-19 (`internal/storage/model/adetask.go:56`). `pickColorSlot`
(`internal/storage/repos/adetask.go:388`) assigns the first slot no live task uses, else the least
used. `patchLeaves` (`:594-599`) rejects values outside `0..maxColorSlots-1`.

Plan:

1. Migration `0112_p764_color_slots_10.sql`: `UPDATE ade_tasks SET color = color % 10 WHERE color >= 10;`.
   One idempotent statement, no schema change.
2. `maxColorSlots = 10`. `pickColorSlot` and `patchLeaves` keep their logic, so new tasks and patches
   use 0-9.
3. `palette.ts`: `PALETTE` holds 10 hex values. `taskColor(slot)` indexes it directly (no fold, so no
   legacy code survives the next minor bump).

What existing tasks see:

- Slots 0-9 keep their slot number. Their colour changes to the new hex for that slot.
- Slots 10-19 become slot minus 10, so slot 13 gets the slot 3 colour. Two live tasks can then share a
  colour (for example old 3 and old 13) until one is archived. New tasks avoid both, because
  `pickColorSlot` reads the migrated values.
- No colour is ever unmapped, and archived tasks follow the same rule.
- Alternative with no migration: fold in code (`slot % 10` in `taskColor` and in `pickColorSlot`'s
  counts). Same colours on screen, but the fold is compatibility code that must stay. The migration is
  preferred.

### Selected card: S1 neutral ring (decided)

- Head ground steps to 12%. A 2px `--kira-fg` ring sits inside the card edge (inset outline, painted
  above head and row grounds). Ring contrast: 10.05:1 on the selected head, 12.56:1 on chrome rows.
- Grey `select` is no longer used on cards, so the 3.70:1 subtle failure goes away.
- Selected branch row in a card: `field` ground (subtle 4.58) plus a 1px inset `--kira-fg` ring.
- Focus ring stays outside: card keyboard focus is an outline offset 2px outside the card; selection
  is flush inside. Both read apart when they coincide.

### Light theme (preview only, P138 open item)

Bands pass in the light preview (numbers above). Every ink is below 3:1 on white (1.83-2.97), so a shipped
light theme would need light ink variants for marks. Out of scope here.
