- **A1-6 history off the board wire: excluded.** Removing `history` from `TaskBoard` changes contract

- **A2-2 part 2 (one taskCtx threaded through the completion chain): excluded.** Each step reloads
  after its own writes; a threaded ctx goes stale between them. After part 1 a reload is 3 indexed

- **A2-4 full async start with errors on the run row: excluded.** 36 flow-test files and

- **A2-5 stop `scheduleBoard` in `emitRuns`: excluded.** Board fields derive from runs (task sandbox

- **A2-10 `RunningRebaseOn` SQL filter: excluded.** Rows are bounded by concurrently running rebases;

- **A2-13 prune `taskMus`: excluded.** About 100 bytes per task ever touched. Safe deletion needs

- **Backend async with new oplog ops: excluded.** `oplog.Record` has no `BranchID`; adding one needs

## Feedback model

P618's `adeOps` store wraps the bridge promise (`run(op, fn)`). No backend event feeds it. So:

- User-initiated slow calls keep a synchronous bridge contract: the promise resolves when the work is
  done and rejects with its error. Stream C wraps each in `adeOps.run` with a new kind (table at end).
- Backend narrows lock scope and makes each call idempotent against double submission: a
  singleflight keyed `<kind>:<target>` (commit 14). A second identical call while the first runs
  joins it and gets the same result. No second worktree add, no second run row.
- Work that truly continues after return (refresh tail: PR merge checks, tracked updates pass,
  conflict checks; per-repo facts past their deadline; pair conflict checks) reports through state
  already on the board: `RepoState.updating`, `Pair.checking`, branch conflict `checking`, then a
  board push when it lands. Failures log and leave the previous value, as conflict checks do today.

## Board-changed payload (A owns)

Go, `internal/adewire/wire.go`:

```go
// BoardChangedEvent is ChannelBoard's payload. TaskIDs empty means any task may have changed.
type BoardChangedEvent struct {
	Refs    bool     `json:"refs"`    // git refs, branch facts or change requests may have changed
	TaskIDs []string `json:"taskIds"` // changed tasks; null means unknown, treat as all
}
```

TS (Stream C adds to `frontend/src/ade/v2/wire.ts`):

```ts
export interface BoardChangedEvent { refs: boolean; taskIds: string[] | null }
```

Rules:

- Bare `notifyBoard()` / `scheduleBoard()` mean `{refs: true, taskIds: null}`.
- Merge of two pending changes: `refs` OR; `taskIds` union, null if either side is null.
- Task-scoped calls pass `{refs: false, taskIds: [id]}`. Convert only in `runs.go`, `status.go`,
  `handover.go`, `reviewstep.go`, `panelforward.go` and `emitRuns`' `scheduleBoard`, and only where
  the call changes no branch row, ref or change request. When unsure, keep the bare call.
- `handleEmit("repo.changed")` stays `refs: true`, all tasks.
- Mobile SSE (`eventChannels[ChannelBoard]: nil`) passes the payload through unchanged. A phone
  client that ignores it keeps working.

## Risks

- **Stale snapshot read.** A caller expecting post-write state could read a pre-write board.
  Mitigation: every write path calls `notifyBoard`/`scheduleBoard`, which bump gen before return;
  builds keyed by gen. Race test plus full adeflow suite.
- **Shared snapshot mutated by a caller.** Corrupts later reads. Mitigation: audit callers in commit
  3; `-race` suite.
- **Push timing changes.** 30 ms coalescing shifts event order in flows. Mitigation:
  `notifyBoardNow` where order matters; handover flow test guards it.
- **Overlay shows facts for a renamed or rebased row.** Mitigation: `rowSig` keeps facts only for
  unchanged `Name/Base/BaseBranchID/Kind`.
- **Background tails outlive Close.** Mitigation: every new goroutine uses `goTracked` on `b.ctx`;
  `Close` waits.
- **Deferred marks lost on crash.** Next board build recomputes and writes them; marks are idempotent.
- **Pair `checking` hides a real conflict briefly.** Same model as branch conflict checks today; a
  push follows within one merge-tree run.
- **Singleflight joins calls with different intent.** Mitigation: key holds every outcome-changing
  input.
- **SendReview phase-2 recheck misses a change.** Mitigation: recheck run state, round count, branch
  name; race test.
- **Meta cache serves an outdated remote after an external `git remote` edit.** Bounded by 30 s TTL;
  `repo.changed` from the watcher covers ref changes, not config, so TTL is the bound. Stated in the
  ARCHITECTURE facts.
- **Flow tests relying on synchronous refresh tails.** Mitigation: commit 12 converts them to polls;
  never sleeps.
