## Op kinds: one place, one commit

All in `v2/state/adeOps.ts`, commit 1. Store shape after commit 1:

```ts
export type AdeOpKind = /* existing */ 'removeBranch' | 'removeRepo' | 'archive'
  /* client */ | 'forcePush' | 'setBranch' | 'attachBranch' | 'stopRuns' | 'startRun' | 'approve'
  | 'retry' | 'nextPass' | 'setStep' | 'launch' | 'sendReview' | 'finishReview' | 'rebase'
  | 'restartSession' | 'closeSession' | 'leaseRequest' | 'leaseRelease'
  /* backend mirror */ | 'agentBranches' | 'agentRename' | 'agentChange' | 'agentFinish'
  | 'agentWaitApproval';
export interface AdeOp {
  id: string; kind: AdeOpKind; name: string;
  taskId?: string; branchId?: string; sessionId?: string;
  source: 'client' | 'backend';
}
```

Toast policy per kind, `TOAST_POLICY: Record<AdeOpKind, 'always' | 'slow' | 'never'>`:

- `always`: P618 behavior, unchanged. Loading toast at once, success/error by id.
- `slow`: loading toast only once op passes `SLOW_MS = 2000`. Success toast only if loading toast
  showed. Error toast always.
- `never`: chip only.

| Kind | Source | Chip surface (`AdeOpStatus` prop) | Toast | Caller |
|---|---|---|---|---|
| removeBranch, removeRepo, archive | client | branch row / task card | always | unchanged |
| forcePush | client | branch row (`branchId`) | slow | `AdeForcePushDialog.vue` |
| setBranch | client | branch row | slow | `v2/panel/AdeTaskBranchForm.vue` `submitBranch` |
| attachBranch | client | task card | slow | callers of `useAddExistingBranch` |
| stopRuns | client | task card; session row when from session | slow | `useTaskMenu.ts` stopRuns, `AdeWorkflowReviewPanel.vue` stop, `AdeSessionActions.vue` onStop |
| startRun | client | task card | slow | `run/useTaskAction.ts`, `run/AdeRunDialog.vue` send |
| approve, retry | client | task card | slow | `run/useTaskAction.ts` |
| nextPass | client | task card | slow | `state/adeStageDialog.ts` pass submit (`useNextPass`) |
| setStep | client | task card | slow | callers of `useSetTaskStep` (step-change menu) |
| launch | client | task card | slow | `useTaskLaunch.ts` start agent |
| sendReview, finishReview | client | review panel header (`branchId`) | slow | `review/AdeWorkflowReviewPanel.vue` |
| rebase | client | branch row | slow | callers of `useRebase` |
| restartSession, closeSession | client | session strip tab + sessions row (`sessionId`) | slow | `sessions/useSessionMenu.ts` |
| leaseRequest, leaseRelease | client | lease row button pending (`ops.isRunning(id)`) | slow | `state/adeLeases.ts` |
| agentBranches, agentRename, agentChange, agentFinish | backend | task card | finish toast iff `durationMs >= 2000` (ok or error); no loading toast | mirror (commit 2) |
| agentWaitApproval | backend | task card | never | mirror (commit 2) |

Backend kinds skip the "error toast always" rule. A refused MCP call is an answer to the agent, not a
user failure; B1 itself asks for a threshold on both outcomes. Long ops include the approval wait,
so the user gets a toast after approving.

Not on adeOps (fast, existing surface suffices): retry setup (`isPending` on button, C1-F4), open
review window (pending via `useMutationState`), show/focus session, open proof window (pending +
`toast.error`), deny all (pending only), workflow/agent-file/note saves.

Backend mirror contract, `MIRROR_KINDS` in `v2/state/adeOpMirror.ts` (commit 2), the only mapping:

| Record match (`module === 'ade'`, `category === 'mcp'`, `taskId !== ''`) | AdeOpKind |
|---|---|
| `kind === 'request_branches'` | agentBranches, or agentWaitApproval while board shows an open branch request for the task |
| `kind === 'rename_branch'` | agentRename, same approval rule |
| `kind === 'change_branch'` | agentChange, same approval rule |
| `kind === 'finish_step'` | agentFinish |

These kinds exist today (`internal/agentmcp/space.go` tool names). B needs no new emit for C. If
P623 renames a tool or adds a post-approval op C should show, the change is one row here.

## Board-changed payload (additive)

Today payload-free: Go `AdeTaskBoardChanged` broadcasts with no data; `fe/bridge/index.ts:814`
`onAdeTaskBoard: (cb: () => void)`; `mobile/api/events.ts:47` drops data. A adds optional
`reason?: string` and changed task ids. C contract:

```ts
/** Optional facts Stream A may add to a board push; absent = unknown, treat as everything changed. */
export interface BoardChangedEvent { reason?: string; taskIds?: string[] }
```

Lives in `v2/readSignals.ts`. If P622 adds a Go struct to `adewire`, move it to `v2/wire.ts` at
landing to mirror it (wire.ts mirrors adewire). Field name for task ids follows P622 if it differs;
one-line rename.

Baseline, works with no payload: single-flight board refetch with dirty flag (commit 4). With
`taskIds` present and non-empty: per-task invalidations (panel forward, review step, handovers,
artifacts, issue) narrow to those task ids. Board itself always refetches whole. `reason` is
recorded only for narrowing decisions P622 documents; unknown values change nothing.
