# v0.3.11

Agents module performance: speed, latency and responsiveness, backend and frontend, including Kira Space MCP tools. Phases P622 to P624 run as parallel streams A, B, C (batch requested by user). Highest prior phase: P621. Two code review rounds after the full non-UI run.

Size survey (non-test): BE `ade` 24k lines/70 files, `bridge` 15k, `harness` 6.4k, `terminal` 1.4k, `leases` 0.5k; FE `ade/v2` 34k lines/290 files, approvals 0.6k.

|-------|-------|--------|

Each phase: several Opus auditors run in parallel (read-only, `codegraph_explore` mandatory), findings go into the phase plan, then one Sonnet implementer per stream fixes them.

Cross-cutting requirement (user): cover latency, not only throughput. Slow work (git, DB, MCP tools, agent steps) may move async, but every such operation shows feedback while running and when finished (running status where the user looks, completion and failure notice). Each auditor lists: slow operations with no feedback, blocking calls that should go async, feedback surface to use. Reuse `adeOps` store, `AdeOpStatus` chip and vue-sonner toasts from P618; extend, never build a parallel mechanism. Measure before and after only where a claim needs it.

## P622 Backend board, tasks, orchestrator, storage (Stream A)

- Scope: `apps/kira-space/internal/ade`, repos, bridge ADE services. Auditors: A1 board, tasks, branches; A2 orchestrator, steps, review, workflows, storage.
- Targets: query counts, git facts per call (`Board()` cost), lock hold times, event fan-out, DB writes on read paths, calls that block the UI and need async plus feedback.

Result: Done. Plan `plans/P622.md`, 16 planned commits plus two test fixes. Storage: migration 0100 index `ade_runs_latest` (plan shows a covering index), `AdeTaskRepo.CountReturns` replaces full run scans in `wireRun`, `AdeLogsRepo.Append` trims by scanning only the dropped prefix (review round 1 replaced a whole-tail window-function cutoff) and one delete (boundary test against a brute-force sum). Board: `Board()` serves a shared snapshot keyed by a gen (fresh 2 s) and joins one tracked build per gen; pushes coalesce per 30 ms into `adewire.BoardChangedEvent{refs, taskIds}` (bridge, appwire, mobile SSE pass it through; `notifyBoardNow` keeps handover's board-before-prompt order); lease order reads the snapshot stale-while-revalidate; one shared load of configs, code repos and live branches per build and a repo-config cache; task-scoped `loadTaskCtx` through `BranchesOfTask`; board marks written after assembly; ahead/behind, ancestry and `gitsession` entry-meta caches; per-repo 1 s facts deadline with last-good overlay (`RepoState.updating`, contract `ade-repo-updating`, flow `repoupdating_test.go`); pair conflict checks in the background (`Pair.checking`); workflow decode, history and per-task index memos plus `adeflow.Reader.Get` memo; change requests resolved in parallel per repo. Tasks: `Refresh` holds the repo lock for the fetch only and returns after branch facts (PR merge marks, conflict checks and tracked updates finish in a tracked goroutine, then push; `WaitRefreshTails` for flow tests); `queueRun` reads one setup; `ensureWorktree` seeds the attach cache with its inventory; worktrees prepare in parallel across repos; singleflight (`opdedupe.go`) joins identical in-flight `StartRun`, `Approve`, `RetryRun`, `ResumeRun`, `SetTaskBranch`, `AddExistingBranch`, `ForcePush`, `SendReview`, `FinishReview`; `SendReview` gathers outside the task lock, rechecks under it, retries once, then `ErrStale`. Benchmarks in `docs/PERF.md` section 2.16: `BenchmarkBoardWarm` 34.8 ms and 21 spawns/op at baseline, 9.1 ms and 7 spawns/op at head; `BenchmarkBoardHit` 0 spawns/op, about 70 ns.

Deviations: commit 6 invalidated the snapshot after a clean mark write without a push, against the plan's `notifyBoard()`; review round 1 restored the push, because a build inside the write window reads the old marks (target mark, `HadCommits`, a `mergedAt` from its own clock), so its board can differ from the stored one. Dedupe keys carry the full JSON args after the kind (plan: `<kind>:<target>`), because `StartRun`, `SetTaskBranch` and others take inputs beyond the target; `SendReview` and `FinishReview` key on the args (run id, route, target) not the task id. Lease order also rebuilds after 5 s without a board change, for settings that never announce one. Two tests relied on the old synchronous behavior and now poll: `board_test.go` conflict checks after `Refresh`, `integration_test.go` out-of-band git moves (invalidates like the repo watcher). Benchmark reports spawns only (harness hides its `*sql.DB`). Checks: `go test -race ./internal/ade/...`, storage, gitsession, adeflow reader, bridge, mobileweb, flows `adeflow` and `mobileflow` pass; hook clean per commit.

Left out, with reasons: SQLite read pool (shared `sqlitex` with Studio, read-after-write audit of every repo method, no tested rollback; Known open item added). History off the board wire (changes contract JSONs and Stream C readers: ordering dependency; the history build is memoized instead; follow-up phase: lazy history fetch, A and C together). Dropping `repoMutex` around `ForcePush` (preflight and push stay atomic under the lock against local branch moves; the call takes the remote slot first, so it waits for another remote op without the lock; only double-submit dedupe lands). One `taskCtx` threaded through the completion chain (goes stale between steps that write; a reload is now three indexed reads). Full async `StartRun` with errors on the run row (36 flow files and the agent `request_branches` path read its error synchronously). Stopping `scheduleBoard` in `emitRuns` (board fields derive from runs; `taskIds` narrows the refetch instead). `RunningRebaseOn` SQL filter (rows bounded by running rebases). Pruning `taskMus` (about 100 bytes per task; needs refcounting). New oplog ops for async user calls (`oplog.Record` has no `BranchID`; needs a migration; calls stay awaitable).

## P623 Kira Space MCP tools and agent runtime (Stream B)

- Scope: `agentmcp`, `llmprompts`, `harness`, hooks, `terminal`, `leases`, approvals backend. Auditors: B1 MCP tool handlers, B2 harness, hooks, terminal, session tracking.
- Targets: tool call latency, blocking waits, approval and prompt round trips, hook reply timing, tool calls that need async plus feedback.

Result: Done. Plan `plans/P623.md`, 14 plan commits plus one refactor. Hooks: `harness.Hooks` processes events on per-terminal lanes (queue 1024 per lane, ordered per terminal, a slow handler delays only its terminal), providers answer 200 at once, `Hooks.Flush` for tests, shutdown reordered so `Tracker.Close` flushes `lastActive` after the drain. `SendIfIdle` and `flushLease` write the PTY outside `Tracker.mu` and `lease.mu`, under a per-owner flush lock that also covers re-queues and notice reads; learning a stopped session's id is serialized per cwd on a fixed stripe of mutexes. `learnStopped` runs in the background, deduped, waited on by `Tracker.Close`. Terminal: `Registry.OnChange` dispatched off the `Open`/`remove` path (coalesced), `CloseWindow` closes sessions concurrently, `appevent.Coalescer` flushes outside its mutex, terminal `coalesceMaxBytes` 64KiB. Agent CLI path lookup runs fresh on every launch; only the login-shell probe result is cached (stat-checked, misses never cached). MCP: tool handlers that block run under `callCtx` (a call ends with its registration; `finish_step` and `reply_review_comment` are short and do not); `task_info` computes after the wait, wakes on setup end and sends MCP progress notifications; one `SetupByBranch` read per call, registered repos only without repos or with `includeRegistered` (prompt text updated); finish reply built from local artifact data. Feedback: new ops `agent`/`agentApproval`, `agentBranches`, `agentRename`, `agentChange` (`CategoryAgent`, `agentops.go`; contract for Stream C in the plan). Approved branch slots of different repos create in parallel (errgroup capped at `boardFanOut`, slots of one repo in order; slot grouping extracted by the last commit). `fetch_remote` and `push_branch` run the network step outside `repoMutex`; every ADE remote op (`runRemote`) queues on a per-repo remote slot taken before `repoMutex`, so a blocked push never holds the repo lock. ARCHITECTURE notes updated. Deviations: lease ranker uses `taskListOrder`, which Stream A made non-blocking itself (snapshot based, stale order returned while one background build refreshes), so landing step L1 needs no swap; there is no `BoardCached`, so landing step L2 is dropped; one extra commit (slot grouping refactor, timing tests hardened). Left out, with reason: quick artifact scope in the finish reply reads DB rows plus `RepoEntry.CachedBranchChangeRequest` (no cached board snapshot exists to read from, so it is not improved further); B1-2 dropping `taskMu` across git (needs a re-check design shared with rename and change, a design decision, follow-up); B1-8 duplicate structured and text tool result (MCP spec and go-sdk require both, no transcript evidence); B2-3 close and restart feedback (calls stay synchronous to protect the conversation file, Stream C wraps them in `adeOps`); B2-3 SIGTERM claim (wrong, SIGHUP already first); B2-8 lease order cache (Stream A); B2-9, B2-10, B1-7 (no user-visible gain); B1-2 `BranchInventory` pass-through and B1-4 `attachCache` reuse (Stream A files, listed in the plan). Tests: `go build` and `go vet` clean; `lint:go`, `lint`, `lint:claude` clean; `-race` on harness, terminal, appevent, agentmcp, llmprompts, oplog and `ade` (284 s) pass; adeflow (all 151 tests in three chunks), harnessflow, githostflow pass. Real claude (auth probe `ok`): whole module run in four chunks (ADE, hooks, hermetic, agent settings, smart script, DB and prompt-registry row via `test:claude:db`, memory) all pass except two model-behavior flakes unrelated to this diff: `TestDbMcpBrowsePreferredThroughClaude` (haiku sometimes calls `run_query`; also fails on the base commit `ec0f3fa6`, 2 of 4 runs pass there, 1 of 3 here) and `TestMemoryMcpFollowsDocs/files` (failed once, passed on two reruns); `TestMemoryIngestEval` skipped by design. The DB flake needs prompt tuning of Studio DB tool descriptions, a separate subsystem: follow-up.

- Targets: first paint and interaction latency, reactivity cost, list rendering, query refetch storms, lazy loading, dialog and prompt responsiveness, missing running and finished feedback for slow actions.

Result: Done. Plan `plans/P624.md`, 20 commits plus three follow-ups, landed on `chapter/v0.3.11-stream-c`. Reads: shallow board-family queries, single-flight board refetch with dirty flag (`refetchGate.ts`), board push payload `BoardChangedEvent{refs, taskIds}` per P622 (`taskIds` null, absent or empty means all, `refs: false` skips the change-request refetch, narrow per-task invalidations), selection and ripple moved out of the plan model, memoized plan layers (`planModelMemo.ts`), shared task writes, day band props memo, observer-driven history bar, `RepoState.updating` chip and `Pair.checking` marker.
