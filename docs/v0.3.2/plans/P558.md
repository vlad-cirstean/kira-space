Base: `chapter/v0.3.2` at `2643676ec`. Kira Space frontend only. Line numbers are from CodeGraph at base.

## Decisions

- **D1 Shape.** New ADE top-bar tab `repos`, label `common.module.repositories.label` ("Repositories"), testid `ade-tab-repos`. First item in the right `TabsList`, before Agent config and Workflows (the three config pages sit together). `adeBoardUi.view` gains `'repos'`.
- **D2 Page.** New `ade/v2/repos/AdeReposPage.vue`, built from `ReposDialog.vue`'s script and body, laid out like `AdeWorkflowsTab.vue`: list pane (`paneFrame`, fixed width `w-75`, `PanelHeader` "Repositories" with the Import action) beside a detail pane (`paneFrame`, `PanelHeader` naming the selected repo, "Scan folders" or "Other files"). The left pane keeps the virtualized list, keyboard navigation, problem dot, hidden mark and the Scan folders / Other files rows. The right pane keeps every body unchanged: repo head with hide/remove, `RepoIdentity`, `RepoFilePane`, Other files, Scan folders. No `Dialog*` primitives, no Close button, no sr-only dialog description. The footer note (`repos-dialog-note`, folder import count) moves into the Scan folders pane as a `FieldDescription` under its toolbar. Tailwind utilities only; shadcn primitives as today.
- **D3 Store.** `repo/state/reposDialog.ts` is deleted. New `ade/v2/state/adeReposUi.ts` `useAdeReposUiStore`, one concern (Repositories page state, in memory): `tab: 'repos'|'folders'|'files'`, `selectedRepoId`, `dirty`, `leave()`, `setTab(next)`, `pickRepo(id)`, `open({ repoId?, tab? })`. `leave()` copies `adeAgentsUi.leave` (confirm title `space.ade.workflowDiscardConfirm.title`, new body key, `common.action.discard.label`, tone danger).
- **D4 Leave guard.** The dialog stayed open while its owner switched repos, so edits were lost only on an explicit switch. As a tab, leaving the page unmounts `RepoFilePane` and drops a draft silently. So the page joins the existing guard, same as Workflows and Agents: `RepoFilePane` emits `dirty` (boolean) on change and resets to false `onBeforeUnmount`; the page writes it to `adeReposUi.dirty`. Picking another repo, switching Scan folders / Other files, picking another unclaimed file, and leaving the tab all await `leave()`. Mode switch away from ADE is not guarded, same as Workflows today.
- **D5 One view switch.** New `ade/v2/state/adeView.ts` exporting `switchAdeView(next): Promise<boolean>`: returns true at once when `next` equals the current view; otherwise awaits the leave guard of the current view (workflows, agents, repos), then sets `adeBoardUi.view`. `AdeShell.onView` calls it instead of its inline checks. `adeReposUi.open()` calls `useModeStore().setMode('ade')`, then `switchAdeView('repos')`; on true it applies `repoId`/`tab`. A plain function module, not a store: it composes three stores and holds no state. It avoids an import cycle (`adeWorkflowsUi` already imports `adeBoardUi`).
- **D6 ADE with no repos.** `AdeView.vue` renders `AdeShell` when `codeReposStore.records.length > 0` or `adeBoardUi.view === 'repos'`; else `ModuleStart`. The `ade-import` button calls `adeReposUi.open()`, so the first import happens on the page itself. Leaving the Repositories tab with zero repos returns to `ModuleStart`. Hint `space.ade.view.empty.hint` becomes "Import repositories to start planning agent work." (no longer points at the Git module).
- **D7 Git module entry points.** The Git module no longer mounts or owns any repositories UI. Defaults (see NEEDS USER DECISION 1):
  - Remove the Git panel header `manage-repos` button. The ADE tab replaces it.
  - `GitStart.vue` button (`git-start-import`) stays as a jump: calls `adeReposUi.open()`. Without it a fresh install's Git module has no way to import. Label stays `space.repo.manage.label`.
  - `RepoList.vue` row item `configure` stays as a jump: `adeReposUi.open({ repoId: repo.id })`.
  Git importing ADE state has precedent (`repo/state/reposQueries.ts:3`, `repo/RepoIdentity.vue:11` import `ade/v2/wire`).
- **D8 Files that move vs stay.** Only the dialog container and its store move into `ade/v2/`. `RepoFilePane`, `RepoIdentity`, `RepoConfigForm`, `RepoEnvRow`, `RepoScriptField`, `RunScriptRefPicker` and the `repo/state/repo*` query and form modules stay in `repo/`: they are repo-config building blocks, and ADE already imports `repo/state/reposQueries.ts` from 7 files (`AdeBranchPanel`, `AdeSetupProgress`, `AdeAddPopover`, `AdeBranchRow`, `usePlanModel`, `useReviewContext`, `useDialogCtx`). Moving them is churn with no behaviour change (see NEEDS USER DECISION 2).
- **D9 Testids.** The page is no longer a dialog, so the prefix changes: every `repos-dialog-*` testid becomes `ade-repos-*` (root `repos-dialog` becomes `ade-repos`). Removed: `repos-dialog-close`, `repos-dialog-footer-close`. One mechanical rename across source and specs.
- **D10 i18n.** `space.repo.dialog.*` moves to `space.ade.repos.*` (same leaf names, same English), in `packages/theme/src/i18n/en.json`. Removed: `space.repo.dialog.description` (sr-only dialog description, no longer rendered). Added: `space.ade.repos.discardConfirm.body` ("Your edits to this repository's settings file are not saved."). Changed: `space.ade.view.empty.hint` (D6). Kept: `space.repo.manage.label`, `space.repo.panel.configure.label`, `space.repo.settingsFile.*` (still used by `RepoFilePane` and the page). After the edit, grep every removed key: zero hits.
- **D11 Agent tool text.** `agenttools.go:92`: "Ask the user to import it from Agents > Repositories, then try again." (`mobile.shell.heading.title` is "Agents", the ADE mode label.) `agenttools_test.go:54` asserts `"Agents > Repositories"`.
- **D12 Tests.** No new backend behaviour: same bound calls, so no new flow test; `repoflow` flow tests already cover import, folders, hide and remove. UI specs move their opener to the ADE tab. No unit test (nothing complex added; `switchAdeView` is three guard calls).
- **D13 One implementer.** Store, view switch, page, shell, AdeView, Git entry points, i18n, testid rename and specs are one chain (the specs and the rename depend on the page). No stream split.
