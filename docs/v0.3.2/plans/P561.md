# P561 Review window file list follows the shown file

Ask (verbatim): "In the Review window. Go to next file also moves the left panel with the files."

Base: `chapter/v0.3.2` at `5df2439d8`. Frontend only (`packages/git-ui`, `apps/kira-space/frontend`). Line numbers from CodeGraph at base.

## Reading of the ask

Request, not bug report: when the centre diff moves to another file, the left Files panel must move with it. Today the list does not reliably follow:

- Cross-file "next/previous change" (`RepoDiffView.vue:107-126` `crossFile`) calls the registered navigator's `selectFile`. That sets `ReviewFilesState.selectedPath` (`packages/git-ui/src/state/reviewFiles.ts:175-180`), so the highlight index changes. But `FileTree.vue` never scrolls a row into view when `selectedFile` changes from outside: its watch (`FileTree.vue:195-208`) only moves `activeKey`. A file below the fold stays off screen. A file inside a collapsed folder is not in `visibleRows` at all, so it gets no highlight either. `orderedFilePaths` (`fileTreeModel.ts:225-235`) walks the tree with every folder expanded, so the next file can sit in a collapsed folder. A row past the 500-row render cap (`FILE_TREE_PAGE_SIZE`) is likewise missing.
- Same gap for the git-ui "Next/Previous file to review" buttons and Alt+F8 (`useReviewStepping.ts:53-65`), which go through the same `selectFile`.

Other navigation paths that change the centre file, with their own gap:

1. Clicking another centre tab (or closing one, or the Window menu next/previous tab): the list does not follow at all. Nothing feeds the active tab back to the list.
2. A comment jump to an uncommitted file (right panel `AdeWorkflowReviewPanel` `openFile`, `AdeReviewWindow.vue:174`, routed by `AdeReviewFiles.vue:37-42` straight to `openRepoWorkingReviewTab`; git-ui Comments pane `onSelectComment`, `ReviewView.vue:353-356`): opens the tab but never moves the list cursor, so no working row is highlighted.
3. Stepping from a committed file into the Uncommitted section: `cursor` moves to the working row, but the committed tree still highlights the old `selectedPath` (`ReviewFilesPane.vue:124-128` ignores `cursor`). Two rows look selected.

## Decisions

- **D1 One source of truth.** The active centre tab is the file being shown. The list cursor follows it. Every path above ends with a review diff tab becoming active, so one watcher on the active tab covers them all; no per-path hack. Inside git-ui the single list cursor stays `useReviewStepping`'s `cursor` (`{ section: 'committed' | 'working', path }`); both trees derive their highlight from it. `ReviewFilesState.selectedPath` stays the committed file whose metadata (delta status line, toggle-reviewed palette action) is loaded; it is set together with `cursor` for a committed file.
- **D2 Host to git-ui channel.** `ReviewApi` (`packages/git-ui/src/state/review.ts:514-523`) gains `revealFile(section: 'committed' | 'working', path: string): void`. It moves the cursor without opening anything (the tab is already active). Implemented in `ReviewView.vue` `onMounted` `onReviewApi` (`:364-372`):
  - `committed`: `reviewFiles.value?.followFile(path)` then `cursor.value = { section: 'committed', path }`.
  - `working`: `cursor.value = { section: 'working', path }`.
  - A path not in its list: no-op (no cursor change).
  New `ReviewFilesState.followFile(path)`: if `selectedPath !== path`, set it and `#loadDiff()`; never `#openInEditor`. `selectFile` stays as is (click and navigator path still open the tab).
- **D3 Watcher location.** `AdeReviewFiles.vue` (review window host of the list, already holds `api`). Active tab read the way `MainView.vue:21-24` reads it (`useWorkbenchHost()`, `tabs.activeIdByWorkspace[activeWorkspace]`), through a `computed`. Map with `asRepoDiffTab` (`state/tabDomain.ts:366`) and `repoIdOfTab`:
  - `state.working?.branchId === target.branchId` and repo is `target.codeRepoId`: `revealFile('working', tab.path)`.
  - `state.review` with `review.branch === target.branch` and repo is `target.codeRepoId`: `revealFile('committed', tab.path)`.
  - Anything else (no tab, a non-review tab, another branch): leave the list as is.
  Watch `[activeKey, api]` with `immediate: true` so a tab restored before the list mounted still syncs once `api` lands. No feedback loop: a list click opens the tab, the watcher then sets the same cursor (no-op).
  `RepoReviewView.vue` (Git module sidebar) gets no tab watcher (see NEEDS USER DECISION 1); it still gains D4 and D5, which live in git-ui.
- **D4 Committed highlight follows `cursor`.** `ReviewFilesPane.vue` `selectedIndex` (`:124-128`) returns -1 while `cursor?.section === 'working'`. Keep the `selectedPath` fallback while `cursor` is null. Fixes gap 3.
- **D5 FileTree reveals its selected row.** `FileTree.vue`, one new watch on the selected path (`files[selectedFile]?.path`, not the index, so a list refresh that only shifts indexes never re-expands a folder the user collapsed). On a change to a non-null path:
  1. Tree mode: delete from `collapsedDirs` every entry that is a folder prefix of the path (`path.startsWith(dir + '/')`). Prefix match also covers collapsed chains such as `src/main/java`.
  2. If the row sits past the render cap, call `showMore()` until it is inside `visibleRows`.
  3. `await nextTick()`, find the row element in `treeEl` (`[data-nav-key="file:<path>"]`, same selector `useListNavigation` uses) and call `revealElement(row)` from `@workbench/behaviour/focus` (`block: 'nearest'`; the same helper `TabStrip.vue` uses for its active tab). Never move focus: the diff editor keeps the keyboard.
  A path hidden by the filter stays hidden; the filter is never cleared (NEEDS USER DECISION 2). Applies to every FileTree caller; for a click or arrow move the row is already visible, so `nearest` does nothing. No library needed: `scrollIntoView` plus one existing helper.
- **D6 Navigator interface unchanged.** `state/reviewNavigation.ts` keeps `adjacentFile` and `selectFile`; the cross-file path already ends in an active tab, so D3 handles the rest.
- **D7 No backend, no i18n.** No bound method changes, so no flow test. No new copy, so `en.json` untouched. Primitives: no new UI; Tailwind and shadcn-vue unchanged. All touched components already `<script setup lang="ts">`.
- **D8 One implementer.** git-ui API, FileTree reveal, host watcher and specs are one chain. No streams.

## NEEDS USER DECISION

Defaults let the implementer start; the user overrides before implementation if wanted.

1. **Git module review sidebar.** Default: the tab-follow watcher (D3) is review-window only, as asked; the Git module review sidebar still gets the scroll, expand and single-highlight fixes (D4, D5), since they live in git-ui. Alternative: add the same watcher to `RepoReviewView.vue` so the sidebar also follows the main window's active tab.
2. **File hidden by the filter.** Default: the list does not clear a typed filter to reveal a file it hides; the highlight stays where it was. Next/previous file already respects the filter, so only a tab click or comment jump can reach a hidden file. Alternative: clear the filter when the followed file is hidden.
