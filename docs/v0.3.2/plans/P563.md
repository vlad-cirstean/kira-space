## Decisions

- **D1 Base.** `<userHome>/kira-space-wts`. In `ade`: `const WorktreesDir = "kira-space-wts"` and `func WorktreesBase(home string) string { return filepath.Join(home, WorktreesDir) }`, the one place the name lives. `HomeDir` stays the user home; tests keep overriding it. No env var, no setting. Visible folder by user choice; not under the Space home, so backups or a wipe of `~/.kira-space` never touch work.
- **D2 Callers.** `worktreeDirFor`, `requestedWorktreeDirs` and `Board` use `WorktreesBase(b.deps.HomeDir)`. Export `PathSegment` (today `safeSegment`, `setup.go:52`; rename and update its four callers) so `wtmove` derives the same folder.
- **D3 Per-repo base path unchanged.** It never applied to ADE and still does not; it pre-fills the Git module's New worktree dialog. New `space.repo.config.basePath.description`: "Pre-fills the path in the Git module's New worktree dialog. Task worktrees always go to ~/kira-space-wts." `git.settings.worktreeBasePath.description` already says dialog only: unchanged. Site `space/git.mdx:104` gets the same clarification. A global base setting is out of scope (not requested).
- **D4 Move unit.** One `git worktree move <old> <new>` per worktree, run in the repo root (`code_repos.root`). Never copy or `os.Rename`: git writes the admin `gitdir` file and the worktree's `.git` file both ways; `move` keeps the index, untracked and modified files as they are. Parent `<base>/<seg>` created `0o755` first (git does not create it).
- **D5 Scope of what moves.** Rows of `ade_task_branches` with `worktree_dir <> ''`, any kind, archived included, joined to `code_repos` for `name` and `root`. Old path `<home>/wt/<PathSegment(name)>/<worktree_dir>`, new `WorktreesBase(home)/<PathSegment(name)>/<worktree_dir>`. Nothing else under `~/wt` is touched, even a `wt_*` folder with no row.
- **D6 Per-worktree outcome.** Read `git worktree list` once per repo root; match records by cleaned path (`EvalSymlinks` both sides when they exist, so `/var` vs `/private/var` matches).
  - Old in list, folder exists, new path free: move. Locked: `git worktree unlock`, move, `git worktree lock --reason <same reason>` (no `--reason` when none was given); a failed relock is logged with the path (default; NEEDS USER DECISION 3). Move refused (git error): log git's message, leave, retry next boot.
  - New path exists (file, folder or symlink, `Lstat`): never overwrite or merge. Log "target exists", leave, retry next boot.
  - Old in list but folder missing (`Prunable`): leave, log "missing; run git worktree prune or restore the folder", retry next boot. Never prune: the folder may be on a drive that is not mounted.
  - Old folder exists but not in the list: leave, log "not a worktree of <repo>".
  - Old absent and not in the list: nothing to move (already moved or never created). Still run D7 for that pair, so a crash between move and rewrite heals.
- **D7 Rewrite stored paths.** After a successful move, and for every pair whose new path is in git's list, in one transaction, matching the old path exactly or with a `/` suffix (`col = ? OR substr(col,1,len+1) = ? || '/'`, never `LIKE`, since `_` is a wildcard):
  - `ade_sessions.cwd`.
  - `tabs.state_json` `$.cwd` for `kind = 'terminal'` (`json_set`).
  - `tabs.path` for `kind = 'local-file'`.
  - `script_runs.cwd`.
  Use `kiraschema` column names and `sqlb`; no new repo methods (one-time code). Logs carry counts, not paths of tab content.
- **D8 Claude transcripts.** After D7, `claude.MoveProjectDir(home, old, new)` in new `internal/harness/claude/projectdir.go`: `ProjectDirName(cwd)` = cwd with each non-`[A-Za-z0-9]` rune replaced by `-`; rename `<home>/.claude/projects/<enc(old)>` to `<enc(new)>` only when the source is a real folder and the target is absent; target present: log, leave. No transcript content read or edited. Not a credential (CLAUDE.md G5 stays satisfied). Default on (NEEDS USER DECISION 1). OpenCode: nothing; a resume there ends as resume-lost, the existing path. Encoding note in the doc comment: Claude Code's own scheme as of today; a mismatch only means resume falls to the lost path, never data loss.
- **D9 Cleanup and done.** After all rows: for each `<home>/wt/<seg>` a row named, `os.Remove` (empty only); then `os.Remove(<home>/wt)`. Never `RemoveAll`. No marker file: early exit when `<home>/wt` does not exist and no `ade_sessions.cwd` starts with `<home>/wt/`. Every pass is idempotent; a second boot changes nothing. One summary line: moved, left (with reason counts), rewritten rows.
- **D10 Placement.** New package `apps/kira-space/internal/wtmove` (`Run(Options{DB *sql.DB, Home string, GitPath string})`), its doc comment says the next chapter deletes it. `RunOneTimeMoves` gains `userHome` and `gitPath` and calls `wtmove.Run` first, independent of the secrets move result (separate data, so a failed secrets move does not block it). Git path: read `settings.Git.GitPath`; simplest is moving `RunOneTimeMoves` after `repos.New` in `main.go` and `harness.go` and passing `repositories.Settings` (check `repos.New` does not read the secrets move changes; if it does, read the setting with one direct query instead), then `gitclient` discovery to resolve "" to the found git. Git missing or too old: log and skip; retry next boot. Context timeout per git call 30 s. Fits `layering_test.go` (check its rules for a new internal package).
- **D11 Ordering safety.** Runs after the single-instance lock and before Build: no board, tracker, terminal registry, file watcher or run exists yet, so nothing holds a worktree as cwd. Flow harness keeps the same order.
- **D12 Tests.** One backend flow test (below). No UI spec: no bound method, payload shape or UI behaviour changes; the board path is server data the existing contracts regenerate. Fixture text moves to the new base (default; NEEDS USER DECISION 2) so mock data and screenshots match the product.
- **D13 One implementer.** Order-dependent chain (constant, callers, move, tests, docs). No stream split.
