## Decisions

- **D1 Content shape.** Each `INSTALL.macos.items` entry keeps `title` and `body`. Only the Keychain entry carries an `image: { file, alt, caption }` object. The folder entry has no image fields. `Install.astro` renders a `<figure>` only for an entry with `image`.
- **D2 Guard stays, gets stricter.** `installShot` throws on a missing file in every build, not only under `CI=true`. The local placeholder existed only because the images were not yet supplied. Now the one required image is committed, so a missing file is always a bug. Error message stays as is. Return type becomes `InstallShot` (never `undefined`). Remove the `warned` set, `console.warn` and the placeholder box (`data-install-pending`). Not weaker: CI still fails; local builds now fail too.
- **D3 Display size.** 868x372 is a 2x Retina capture of a roughly 434 pt dialog. Render at half intrinsic size (`width/2`, `height/2`), same convention as `Shot.astro:41-42` for crops. Keep the original file: no `getImage` transform, as now.
- **D4 No ring on the image.** The WebP has alpha (VP8X alpha flag set) and transparent rounded corners. `ring-1 ring-border-strong rounded-lg` would draw a square frame around the transparent corners. Drop both; use `drop-shadow-lg` (a filter, follows alpha) so the dialog lifts off the card.
- **D5 `site:shots:fill` unchanged.** `site/scripts/shots-fill.ts:1-89` reads only `SHOT_CAPTURE`/`shotFiles`; it never touches install images. Nothing to remove there.
- **D6 `docs/HISTORY.md:7766` stays.** It records v0.3.1 as shipped ("both WebP"). CLAUDE.md forbids editing HISTORY outside a chapter close. The v0.3.2 close entry records the change.
- **D7 Intro "Expect two prompts." stays.** Still two macOS prompts (Keychain, folders). It counts prompts, not images.

- **Retina guess (D3) wrong.** If the dialog reads too small at 434 px, render at intrinsic size. Decide from the recorded baseline PNG, not by guess.
- **Phone width.** 434 px exceeds the 375 px viewport minus padding; `max-w-full h-auto` scales it. Baseline step 4 shows it.
- **Shot capture flake.** A failing `bun run screenshots` blocks step 4. Rerun the one failing shot spec alone (DEV_ENVIRONMENT method). `KIRA_SITE_SHOTS=placeholder` baselines are wrong: placeholder sizes change the layout.
- **Fonts.** Site text uses bundled `@fontsource` Inter and JetBrains Mono, so no system font setup is needed. If the whole page diffs uniformly, stop and check before updating.
- **Concurrent P556.** P556 touches app code and app baselines only, no `site/` file. No overlap.
