## 2. Design

### 2a. Question first and default

`ReviewThread.vue`: `KIND_ITEMS` order `question`, `change`; `kind` defaults to `'question'`. Edit
mode still loads the comment's own kind. Backend default for an omitted kind stays `change`
(wire compatibility); every UI compose now sends `question` unless the user picks Change. Applies to
every review thread (repo view review and review window), since it is one component.

### 2b. PR line comment

**Where it shows.** A third compose tab `host` ("{short} comment", testid
`review-thread-kind-host`), compose mode only, only on a committed diff tab inside a review window
whose tab branch is the window's branch, and only while the window's `changeRequest.reviewState` is
`ok`. Working (uncommitted) tabs never show it: those lines are not on the host. Repo view review
tabs (no window) never show it. Picking `host` swaps the send button to "Post to {short}"
(`review-thread-send` testid kept) and shows a hint line `review-thread-host-hint`: "Posts to
{short} #{number}. Kira keeps no copy." A blocked target (merged, closed, local tip not the host
head) shows the reason in that hint line and disables the send button. On success the thread shows
`review-thread-posted` ("Posted to {short} #{number}") with a Close button; nothing is stored in the
local review session. Errors render inline (`review-thread-error`), no toast, as today.

**Head rule.** Host line numbers only mean anything at the host's head. The post carries the commit
the tab shows (`review.branchTip`) as `headSha`; the server reads the host head fresh and refuses
with result kind `headMoved` when they differ. The frontend gate (from the cached `reviewState`) is
a convenience; the server check is the authority.

**Go API (provider-agnostic).** `internal/githost/comment.go`, next to `ChangeRequestComments`:

```go
// LineComment is a new comment on lines of one file at a change request's head.
type LineComment struct {
	Path      string // repo-relative, forward slashes
	Start     int    // 1-based, inclusive; lines of the file at CommitSHA
	End       int
	EndColumn int    // 1-based UTF-16 column after End's last character (hosts that anchor by column)
	CommitSHA string // the host's current head
	Body      string // Markdown, 1..MaxHostCommentBytes
}

// ChangeRequestLineComments is optional: a provider that comments on file lines of a change
// request (right side). Failure is in Status, never an error.
type ChangeRequestLineComments interface {
	CommentOnLines(ctx context.Context, r Repo, number int, c LineComment) Status
}
```

A separate optional role, same pattern as `ChangeRequestComments`, so a future provider without it
reads as `disabled` instead of breaking `ChangeRequestReviews`.

- **GitHub** (`github/review.go`, `github/provider.go` or `github/comment.go` for the role
  assertion): `Client.CommentOnLines` posts `repos/{o}/{r}/pulls/{n}/comments` with `-f body`,
  `-f commit_id`, `-f path`, `-f side=RIGHT`, `-F line=<End>`, and when `Start < End` also
  `-F start_line=<Start>`, `-f start_side=RIGHT`. `line`/`start_line` must be JSON integers; `-f`
  sends strings and GitHub answers 422. Extend `field` with `typed bool` and have `writeArgv` emit
  `-F` only for typed fields; rewrite its comment: `-F` only for integers Kira formats with
  `strconv.Itoa`, never for user text. `callWithin(..., writeTimeout, true)` like the others.
  Lines outside the PR diff come back as a host refusal (422 reason), shown inline.
- **Azure** (`azure/review.go`): `CommentOnLines` posts `pullRequestThreads` with the same thread body
  as `Comment` plus `threadContext: {filePath: "/"+Path, rightFileStart: {line: Start, offset: 1},
  rightFileEnd: {line: End, offset: EndColumn}}`. Factor the shared thread map into one helper used
  by `Comment` and `CommentOnLines`. CommitSHA is not sent (threads attach to the latest iteration;
  the head check already pinned it).
- **fakehost.Forge**: implements the role; records `LineComments(number) []githost.LineComment`;
  rate limit and gone like `Comment`.
- G5: both adapters only build `gh`/`az` argv and read output. No token, header or credential.

**gitsession** (`crreview.go`):

```go
// ChangeRequestLinePost is a line comment post's result: ChangeRequestPost's kinds plus
// "headMoved" (the host head is not headSha; HeadSha then holds the host head).
type ChangeRequestLinePost struct {
	Kind    string
	Status  *githost.Status
	HeadSha string
}

func (e *RepoEntry) CommentOnChangeRequestLines(ctx context.Context, number int, headSha, path string, r gitreview.LineRange, body string) (ChangeRequestLinePost, error)
```

Order: `reviewHost` (not ok, or provider lacks `ChangeRequestLineComments` → `disabled`); breaker
armed → `unavailable`; `rv.ReviewTarget` (not OK → `unavailable`, arm breaker on rate limit);
`t.HeadSha != headSha` → `headMoved`; `readSnapshotSource(ctx, headSha, path)` (not text →
`ErrCommentNotText`; `End > lineCount` → `ErrCommentRangeOutOfFile`, both already mapped by
`gitrpc/detail.go:32-34`); compute `EndColumn` (UTF-16 length of line `End` without a trailing `\r`,
plus 1); post through the same success/rate-limit tail as `post` (factor it so both share it:
`SyncChangeRequests` on OK, `armBreaker` on rate limit).

**gitrpc**: new request `changeRequest.lineComment`.

```go
// ChangeRequestLineCommentParams is changeRequest.lineComment's own request.
type ChangeRequestLineCommentParams struct {
	RepoID  string              `json:"repoId"`
	Number  int                 `json:"number"`
	Path    string              `json:"path"`
	Range   gitreview.LineRange `json:"range"`
	HeadSha string              `json:"headSha"` // the commit the caller reads; must be the host head
	Body    string              `json:"body"`
}

// ChangeRequestLineCommentResult mirrors @kira/git-ipc's ChangeRequestLineCommentResult.
type ChangeRequestLineCommentResult struct {
	Kind    string      `json:"kind"`
	Status  *HostStatus `json:"status,omitempty"`
	HeadSha string      `json:"headSha,omitempty"`
}
```

Handler `handleChangeRequestLineComment` in `changerequests.go`, shaped like
`handleChangeRequestSubmitReview`: `repoId` and `path` non-empty, `number > 0`,
`1 <= start <= end`, `validObjectID("headSha")`, body through `normalizeCommentBody`, empty →
`commentEmpty`, over `githost.MaxHostCommentBytes` → `hostCommentTooLong`. Register in
`handlers.go`. Contract 57 → 58, additive, in `contract.go` and `validate.ts` with a `P464` history
line each.

**git-ipc TS** (`packages/git-ipc/src/contract.ts`, export from `index.ts` like its siblings):

```ts
/** changeRequest.lineComment's result. `headMoved`: the host head is not `headSha`; nothing posted. */
export type ChangeRequestLineCommentResult =
  | ChangeRequestPostResult
  | { readonly kind: 'headMoved'; readonly headSha: string };
// request map:
'changeRequest.lineComment': {
  params: { repoId: string; number: number; path: string; range: LineRange; headSha: string; body: string };
  result: ChangeRequestLineCommentResult;
};
```

No Wails-bound signature changes (the call rides the git stream), so `bun run setup` binding
regeneration is not needed. Run it only if a bound method changes after all.

### 2d. Resizable panes

`AdeReviewWindow.vue`: drop `LEFT_MAX`/`RIGHT_MAX`. Bounds come from the pane row's width:
`useElementSize` (VueUse) on the row `div` (template ref `row`). Constants `LEFT_MIN = 180`,
`RIGHT_MIN = 280`, `CENTRE_MIN = 320`, `CHROME` = the row's horizontal padding plus gaps plus
handle widths (derive from the classes in use, name it, no magic number). No cycle: the right pane
takes priority, the left pane fits around it.

```ts
const rightMax = computed(() => Math.max(RIGHT_MIN, rowWidth.value - LEFT_MIN - CENTRE_MIN - CHROME));
// right.size clamps storedRight to [RIGHT_MIN, rightMax]
const leftMax = computed(() =>
  Math.max(LEFT_MIN, rowWidth.value - CENTRE_MIN - CHROME - (store.agentPanelVisible ? right.size.value : 0)));
// left.size clamps storedLeft to [LEFT_MIN, leftMax]
```

While `rowWidth` is 0 (before first layout) clamp to the minimum only. The clamp never writes back:
a stored width survives a temporarily narrow window. `ResizeHandle :max` gets the computed maxima.
The centre (diffs) is whatever is left, never under `CENTRE_MIN` while the window is wide enough.
Sane minimums stay as they are.
