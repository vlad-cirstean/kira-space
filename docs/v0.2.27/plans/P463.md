# P463 Persist task tabs across task switches

Spec row: `docs/v0.2.27/SPEC.md` P463. App: Kira Space. User words: "When switching between tasks
the tabs in the task are not persisted. For example I leave a task in session and move to another
one to notes; the first one when back is on notes."

Discovery ran through `codegraph_explore` (`useAdeBoardUiStore`, `AdeTaskPanel`, `AdeBranchPanel`,
`AdeSessionsTab`, `AdePanelFrame`, `AdePanel`, `AdeShell`, shelf/board shapes), then Grep for every
reader and writer of the tab and session refs. Planned against the tree after P461 (`f6643fa`).
Frontend only; no backend, wire or i18n change.

## 1. Current mechanism

All three pieces of panel view state are single global refs in
`apps/kira-space/frontend/src/ade/v2/state/adeBoardUi.ts`:

- `:14` `taskTab = ref('task')`: active tab of the task panel, shared by every task.
- `:15` `branchTab = ref('details')`: active tab of the branch panel, shared by every branch.
- `:17` `sessionId = ref<string | null>(null)`: selected session in any Sessions tab.

`select()` (`:38`) changes `selectedTaskId` only, never the tab. So the next task inherits whatever
tab the last one showed. That is the user's bug, and the P461 observation (second task reopened on
Sessions) is the same global ref, not per-task memory.

Readers and writers:

- `taskTab`: v-model `panel/AdeTaskPanel.vue:131`, branches `:232`, `:233`, `:235`; writes
  `panel/AdeTaskTab.vue:182` (handover "see notes" link sets `'notes'`), `plan/useTaskMenu.ts:85-86`
  (`showSessions`), `adeBoardUi.ts:60` (`openSession`), `:69` (`openSessions`).
- `branchTab`: v-model `panel/AdeBranchPanel.vue:236`, branch `:358`; writes
  `needs/useNeedsAction.ts:30`, `:44`, `plan/AdeTaskCard.vue:69`, `adeBoardUi.ts:59`.
- `sessionId`: read `sessions/AdeSessionsTab.vue:44` (`current` falls back to `running[0]` when the
  id is not in this scope); writes `AdeSessionsTab.vue:82` (strip select),
  `sessions/AdeSessionsList.vue:52` (dropdown primary), `sessions/AdeTuiPane.vue:44` (Show),
  `sessions/useSessionMenu.ts:42` (Restart), `adeBoardUi.ts:61` (`openSession`).
- `revealSessionId` (`:19`) is a one-shot request consumed by `AdeSessionsTab.vue:50-65`. Not view
  memory; it stays as is.
- The archived panel (`panel/AdeArchivedPanel.vue:39`, `:44`) keeps its own local `tab` and resets
  it on task change. Archived tasks are read-only history; it stays out of scope.
- Mobile (`frontend/mobile/`) uses none of these refs.

## 2. Design

### Store

New setup store `apps/kira-space/frontend/src/ade/v2/state/adePanelTabs.ts`,
`useAdePanelTabsStore` (`defineStore('adePanelTabs', …)`). One concern: what each task and branch
panel last showed. It imports no other store.

```ts
// Last view of each task and branch panel: the tab, and the session picked in a task's Sessions
// tab. In memory only; entries of tasks and branches that left the board are pruned.
export const useAdePanelTabsStore = defineStore('adePanelTabs', () => {
  const taskTabs = ref<Record<string, string>>({});
  const branchTabs = ref<Record<string, string>>({});
  /** Per task: the session last picked in its task or branch Sessions tab. */
  const sessionIds = ref<Record<string, string>>({});

  const taskTab = (taskId: string): string => taskTabs.value[taskId] ?? 'task';
  const branchTab = (branchId: string): string => branchTabs.value[branchId] ?? 'details';
  const sessionOf = (taskId: string): string | null => sessionIds.value[taskId] ?? null;
  function setTaskTab(taskId: string, tab: string): void { taskTabs.value[taskId] = tab; }
  function setBranchTab(branchId: string, tab: string): void { branchTabs.value[branchId] = tab; }
  function selectSession(taskId: string, sessionId: string): void {
    sessionIds.value[taskId] = sessionId;
  }
  /** Drops entries of tasks and branches no longer on the board (archived, removed). */
  function prune(taskIds: ReadonlySet<string>, branchIds: ReadonlySet<string>): void { … }
  return { taskTabs, branchTabs, sessionIds, taskTab, branchTab, sessionOf,
           setTaskTab, setBranchTab, selectSession, prune };
});
```

`prune` deletes keys of `taskTabs` and `sessionIds` not in `taskIds`, and keys of `branchTabs` not in
`branchIds`. Use `delete` on the reactive record; touch nothing when every key survives. Tab values
stay `string`, matching `AdePanelFrame`'s `defineModel<string>` and today's `ref('task')`.

### What is kept

- Task panel tab (Task, Notes, Artifacts, Sessions), per task.
- Branch panel tab (Details, Sessions), per branch. Same global-ref bug, same panel family, reached
  from the task; a fix that left it global would leave the bug one click away.
- Selected session, per task. Writers all hold the session's `taskId`, not the panel scope, so the
  key is the task. The task panel and its branch panels share it: a branch panel whose strip lacks
  the picked session falls back to its first running one, as today.

Not kept: Sessions dropdown open state, scroll positions, notes editor caret. They are component
local, reset on remount today, and nothing in the ask names them.

### Lifetime: app session, in memory

Decision: in memory only, no `usePersistedState`/`useLocalStorage`. Reasons:

- Selection itself is in memory (`adeBoardUi.ts:8`), so after a restart no panel is open. A stored
  tab would only steer the first open of each task, where the Task tab is the expected landing.
- Stored session ids point at sessions that may not run after restart; `current` would fall back
  anyway.
- Persisting a per-task map needs pruning against a board that is not loaded at boot, else
  localStorage grows by one key per task ever opened.

So VueUse storage sync is not used; no requirement here needs it.

### Cleanup

`panel/AdePanel.vue` already reads the plan model and stays mounted while a task (live or archived)
is selected. Add:

```ts
const tabs = useAdePanelTabsStore();
watch(
  () => model.value?.board,
  (b) => {
    if (b) tabs.prune(new Set(b.tasks.map((t) => t.id)), new Set(b.branches.map((x) => x.id)));
  },
);
```

`board.tasks` holds every live task (plan, Later, Backlog: `board/shelf.ts:17-24`); an archived task
moves to `board.history`, so archiving drops its entries on the next board push. Removing a branch
drops it from `board.branches`. Restore brings a task back on its Task tab, which is fine. A task
can only get an entry after its card or an `openSession` event names it; both come from a board
that already lists it, so a prune cannot race a fresh entry in practice. Stale entries while no
panel is mounted are a few strings and go on the next prune.

### No refetch from the switch

The store is plain client state; switching reads a record, issues no query. Tab bodies already
mount on `v-if` and read TanStack caches with `staleTime: Infinity` (`packages/workbench/src/state/
queryClient.ts:27-32`), keyed per task, so returning to a task reuses its cache. No `:key` on the
panel, no `invalidateQueries`, no `refetch` gets added. The spec asserts board and sessions call
counts stay flat across the switches.
