# P467 Start a workflow without a repo

Spec row: `docs/v0.2.27/SPEC.md` P467. App: Kira Space. User ask: start a workflow, or an agent run,
on a task with no repo bound. Today both start paths require one. First stage decides repos and
branches; later stages that need a repo handle its absence.

Discovery ran through `codegraph_explore` (`stepTargets`, `plan`, `StartRun`, `prepareWorktrees`,
`queueRun`, `startRun`, `launch`, `advanceLocked`, `LaunchStep`, `launchDirs`, `launchReviewAgent`,
`sandboxInput`, `prepareSandbox`, `ArchiveTask`, `DeclareRepos`, `RequestBranches`,
`composeManualMessage`, `AdeStepPrompt`, `AdeManualMessage`, `TaskBoardDeps`, frontend
`buildSteps`, `automaticAction`, `stepStatusText`, `needsYou`, `runMessageVars`), then Read for line
detail. Planned against `3783fb1` (P466 result).

## 1. Current mechanism

Two guards block a repo-less task:

- Automatic step (`StartRun`, `advanceLocked`): `plan()` (`internal/ade/runs.go:166`) calls
  `stepTargets(def.RunsOn, tc.mine)` (`internal/ade/steps.go:83`). Empty `mine` returns
  "the task has no branch of its own to run on". `StartRun` (`runs.go:286`) refuses on
  `plan[cur].TargetErr`.
- Manual session step (`LaunchStep`, `internal/ade/launches.go:568`): `launchDirs` (`launches.go:629`)
  ends with `invalid("the task has no repo")` when no dir is found. `launchReviewAgent`
  (`review_agent.go:39`) shares `launchDirs`.

Below the guards everything is keyed by a branch:

- `queueRun` (`runs.go:429`) resolves `tc.branch(branchID)`, path via `worktreeOf`, setup gate.
- `startRun` (`runs.go:530`) loads `CodeRepos.Get(sb.CodeRepoID)` (nil gives "code repo not
  found"), fills `runVarsFor` (`Repo`, `Branch`, `Worktree`), inserts the headless session with
  `BranchID: sb.ID, Cwd: runPath`, and hands `*rec` to `superviseScript`.
- `sandboxInput` (`sandbox.go:57`) and `prepareSandbox` (`sandbox.go:138`, line 170) call
  `GetBranch(run.BranchID)`.

What already tolerates no branch:

- `ade_runs.branch_id` is `TEXT NOT NULL DEFAULT ''`. No migration needed.
- Sessions already exist at task level (`BranchID ""`). `LaunchStep` builds `PrepareArgs` with no
  branch.
- Board wire filter (`board.go:582`, `if r.BranchID != "" && !live[r.BranchID]`) passes `""` runs.
- `launch` (`runs.go:484`) calls `RunningRebaseOn("")` and `claimOn("")`; both are no-ops for `""`.
- `tc.branch("")` callers in `handover.go:181`, `agenttools.go:417`, `route.go:142`,
  `automation.go:246` read zero values and stay correct.
- `setupReady` treats no setup row plus non-empty path as open.
- Bridge `StartRun` (`bridge/adetask.go:854`) and `LaunchStep` (`adetask.go:1145`) carry no repo
  check. No bridge validation change.
- Agent Space MCP tools `declare_repos` (`agenttools.go:193`) and `request_branches`
  (`branchrequest.go:211`) let a running agent add repos and branches to its task. The
  `headless.space.suffix` prompt already explains them.

## 2. Design

### Task folder: where a repo-less run works

- Path: `<KiraSpaceHome>/ade/tasks/<taskId>`. Sits beside `ade/runs` (`AgentDir`).
- New dep `TaskBoardDeps.TasksDir string`. Set in `appwire/wire.go` next to `AgentDir`:
  `TasksDir: filepath.Join(config.KiraSpaceHome(), "ade", "tasks")`.
- New helper in a new file `internal/ade/taskdir.go`:
  `func (b *TaskBoard) taskDir(taskID string) (string, error)`. Errors when `TasksDir` is empty.
  Runs `os.MkdirAll(dir, 0o700)` and returns the path. Validate `taskID` with the existing
  `safeSegment` so it cannot escape the root.
- Created lazily on first use, never at task create. A task that never runs repo-less gets no
  folder.
- `ArchiveTask` (`archive.go:136`) removes it with `os.RemoveAll` after the archive commit.
  Best effort: log a failure, never fail the archive. Restore needs nothing; next use recreates it.
- Session cwd is this folder for every repo-less run and launch. Takeover (`takeOverCwd`,
  `launches.go:346`) already uses the stored `rec.Cwd` for a task-level session; it errors if the
  folder is gone, which only happens after archive.

### Task target: automatic steps

- Go: `const taskTarget = ""` in `steps.go`. A run on it has `BranchID ""`.
- `stepTargets(runsOn string, kind string, mine []mineBranch)`:
  - Empty `mine` and `kind == "review"`: error "the review step needs a branch to review".
  - Empty `mine` and `runsOn` is `only <nick>`: keep the existing `only` error (no branch in
    that repo).
  - Empty `mine` otherwise: return `[]string{taskTarget}`.
  - Non-empty `mine`: unchanged.
- Pin in `plan()`: when the current pass holds a run of the step with `BranchID ""`, the step's
  targets are `[taskTarget]` regardless of `mine`. Why: the first stage declares repos mid-run;
  without the pin its own targets jump to the new branch, its `""` run vanishes from `Runs`, and
  the step reads pending again. `plan()` already gathers in-pass runs with `Purpose == ""`; add
  the pin there.
- `queueRun`: for `branchID == taskTarget`, skip `tc.branch`, use zero `sb` (with `TaskID` set),
  path from `taskDir`, `open = true` (no setup gate).
- `startRun`:
  - Zero `sb.CodeRepoID`: skip `CodeRepos.Get`, use a zero `CodeRepo`.
  - `runVarsFor`: `Repo ""`, `Branch ""`, `Worktree` is the folder.
  - Headless session insert keeps `BranchID: sb.ID` (now `""`) and `Cwd` the folder.
  - `superviseScript` with zero `rec`: env gets `WorktreePath` the folder, `WorktreeBranch ""`,
    `RepoRoot ""`. A script step runs in the folder.
  - A review step never reaches here: `stepTargets` refuses it.
  - `planSmartStep(tc, sb, path, def)` must handle zero `sb`; read it, guard any repo-only branch
    with `sb.ID == ""`.
- Sandbox:
  - `sandboxInput`: skip `GetBranch` when `run.BranchID == ""`. Worktrees list is the folder.
    Skip `requestedWorktreeDirs`.
  - `prepareSandbox` line 170: skip the grant `GetBranch` and `sandboxTargets` for `""`.
  - Design choice: a task-level run cannot write into worktrees it requests mid-run (sandbox is
    fixed at start). Next stage runs on those branches. State this in ARCHITECTURE.md.

### Downstream stages

- `advanceLocked` (`runs.go:1175`) `actStart` today calls `startStep(ctx, tc, plan, step, nil)`.
  Change it to call `prepareWorktrees(ctx, tc, nil, agentStep)` first, same as `StartRun`, so
  branches the first stage requested get worktrees (or the repo root for an unnamed agent-step
  branch, `prepareWorktrees` existing rule). `tc` and `plan` must be reloaded after the first
  stage finished; `advanceLocked` already loads fresh.
- After the first stage:
  - Repos and branches present: later steps target them as today.
  - Still none: an agent or script step runs in the task folder again.
  - Review or `only <nick>` with no matching branch: `TargetErr`. Advance stops there, same as
    a target error today. The board shows "Needs a repo" and no Run action.
- Pinning applies per step, per pass. A later step starts fresh and sees the new `mine`.

### Manual session step

- `LaunchStep`: replace the `launchDirs` call with `taskLaunchDirs(ctx, tc)`. It calls
  `launchDirs`; on the no-repo case (match by a sentinel `errNoRepo`, not by string) it returns the
  task folder as `cwd`, no extra dirs, no repo lines.
- `launchReviewAgent` keeps calling `launchDirs` and keeps "the task has no repo".
- `StartAdHoc`/`startBranch` (`launches.go:683-734`) are per branch. Unchanged.

### Frontend mirror

  - No mine branch: `[]` for `review` or `only <nick>`, else `['']`.
  - `pinned` (a run of this step with `branchId ''` in the current pass): `['']`.
  - Else unchanged.
- `buildSteps` (line 262) computes `pinned` from the pass's runs and passes `kind`.
- `buildTaskProgress` barTip: `nick('')` falls back to the task-folder label.

- Mobile `useAgentsModel`/`useTaskActions` reuse `buildTaskProgress`; no own change.

  No new primitive; the hint uses the dialog's existing muted-text pattern.
