# P461 Task "+" new terminal or agent works; remove list-row terminal button

Spec row: `docs/v0.2.27/SPEC.md` P461. App: Kira Space. User words: "The new terminal or agent in a
task doesn't work. I press plus and nothing appears. Remove the new terminal button from the task
from the task list."

Discovery ran through `codegraph_explore` (click handler, `useTaskLaunch`, `adeBoardUi`,
`openRepoTerminalTab`, `useLaunchOpener`, Popper wiring), then Read/Grep on reka-ui's `dist` for
confirmation. Planned against the tree after P459; P459 touches none of the files below except
`docs/ARCHITECTURE.md` (different lines).

## 1. Findings

### Code path

- Plus: `apps/kira-space/frontend/src/ade/v2/sessions/AdeTaskLaunchMenu.vue`. Rendered in two
  places: card head `plan/AdeTaskCard.vue:259-263` (`size="card"`) and Sessions tab bar
  `sessions/AdeSessionsTab.vue:93` (`size="bar"`; task panel `AdeTaskPanel.vue:233`, branch panel
  `AdeBranchPanel.vue:490`).
- Items call `useTaskLaunch.ts`: `openTerminal` (`:29`, `openRepoTerminalTab`, Git module tab,
  switches mode to `git` via `state/workspace.ts:89`) and `startAgent` (`:39`, `StartAdHoc`
  mutation, `useLaunchOpener().open`, `ui.openSession` to the branch panel Sessions tab).
- Backend `StartAdHoc` and the terminal open path work: existing flow `adeflow TestAdHocSession`
  and spec `ade-v2-task-launch.spec.ts` both pass calls through. Cause is not backend.

### Root cause (frontend, menu never positioned)

- `AdeTaskLaunchMenu.vue:48-50`: `DropdownMenu > AdeTip > DropdownMenuTrigger as-child > Button`.
  `AdeTip.vue:10-11` is `Tooltip > TooltipTrigger as-child`, so a reka `Tooltip` root sits between
  the menu root and its trigger.
- reka-ui 2.11.0 has one unscoped popper context: `Popper/PopperRoot.js:5`
  `createContext("PopperRoot")`. `DropdownMenuTrigger` renders `MenuAnchor > PopperAnchor`
  (`Menu/MenuAnchor.js:24`); `PopperAnchor.js:26-28` injects the nearest `PopperRoot` and calls
  `onAnchorChange`. Nearest root is the Tooltip's, not the menu's.
- Menu's `PopperRoot` anchor stays unset. `PopperContent.js:207` reference is `undefined`, so
  `isPositioned` never turns true and `PopperContent.js:250` keeps
  `transform: translate(0, -200%)`: content mounts above the viewport. User sees nothing.
- Evidence in tests: `ade-v2-task-launch.spec.ts:15` "The menu floats off-screen in this runtime,
  so the item is picked with the keyboard." `toBeVisible` passes for an off-viewport element, so
  the spec hid the bug. Same workaround in `agent-provider.spec.ts:122` and
  `ade-v2-base-rebase.spec.ts:237-238`.
- Same bug, same pattern: card change-base menu `AdeTaskCard.vue:205-207`
  (`DropdownMenu > AdeTip > DropdownMenuTrigger`). Fixed here: same root cause, same file this
  phase already edits.
- Working precedents: `packages/workbench/src/memory/import/ImportMenu.vue:27-34`
  (`DropdownMenuTrigger as-child > TooltipIconButton`; Tooltip root sits below the menu anchor,
  `memory-import.spec.ts:145-146` clicks items by mouse) and `git-ui/RefsPopover.vue:415-418`
  (explicit `PopoverAnchor` outside the Tooltip).
- Repo-wide grep for a Tooltip wrapping a Dropdown/Popover trigger: only the two ADE sites above
  plus RefsPopover (safe through its explicit anchor).

### Repro via UI tier

Open plan, open task `T_cart`, Sessions tab, click `ade-task-launch`, then
`expect(page.locator('[data-testid="ade-task-launch-menu"]')).toBeInViewport()` fails today;
`page.locator('[data-testid="ade-task-launch-terminal-b_cart"]').click()` times out (not in
viewport). Both pass after the fix.

### Terminal destination

Terminal item opens a Git module tab and switches mode (ARCHITECTURE.md "Task plus menu", P410).
Kept as designed: once the menu shows, the tab appears there. Not in scope to move terminals into
the ADE Sessions tab.
