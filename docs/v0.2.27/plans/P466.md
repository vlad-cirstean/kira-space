## 2. Design

The shared component is shadcn-vue `Badge` with its existing `count` variant
(`packages/theme/src/components/ui/badge/variants.ts`):
`min-w-control-sm h-control-sm justify-center rounded-kira-pill px-1.5 bg-badge text-fg`.
`h` equals `min-w`, radius is a pill, `bg-badge` is `--kira-badge: #616161`: a grey circle for one
digit, a grey pill for more. It already marks the Needs you tab, so the Needs badge and every new
one look the same. No new variant, no wrapper component, no scoped style. Badge meets the ask in
full; nothing to decline.

1. `SecondaryTabs` gets an opt-in prop `countBadge?: boolean` (default `false`). When true, both
   item render branches (`:67` tooltip branch, `:86` plain branch) render
   `<Badge variant="count">{{ item.count }}</Badge>` instead of the muted span. Opt-in, so Studio
   and package callers keep plain counts; the row asks for ADE only. Changing every `SecondaryTabs`
   count app-wide is a separate decision for the user, not this phase.
2. Count leaves the label. Tab labels become plain nouns; the number moves to the item's `count`
   field. A label with a baked-in number cannot be badged without string splitting, which the copy
   guard (U69, composed translations) forbids anyway.
3. Visibility: the panel and All sessions tabs show their count today even at 0. Keep that: the
   badge renders whenever `count` is defined, 0 included. This is a styling change, not a behaviour
   change. The Needs you badge keeps its own hide-at-0.
4. `AdeSessionsMenu` trigger swaps its `rowMeta` span for the same `Badge variant="count"`, testid
   `ade-sessions-menu-count` kept on the Badge.

### i18n

Catalog rule C3 forbids two keys with identical text; C10 forbids unused keys.

- "Sessions": `space.ade.sessionList.trigger.label` already holds it. Promote to one shared key
  `space.common.sessions.label` = "Sessions" (beside `space.common.notes.label`), use it in all
  three panels and `AdeSessionsMenu.vue:41`, delete `space.ade.sessionList.trigger.label` and
  `space.ade.panel.sessionsTab` (whole group).
- "Running": reuse `common.state.running.status` (exists, same meaning, used for run state).
- "Stopped": reuse `space.ade.activity.stopped.status` (exists, same meaning: a stopped session).
- Keep `space.ade.allSessions.running.label` / `.stopped.label`: `AdeSessionsList.vue` headings
  still use them.

If `bun run lint` (check-catalog) still flags anything, fix it in the catalog, never with an
`ALLOWED_DUPLICATES` entry.
