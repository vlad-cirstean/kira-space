## 2. Keyboard model

- Enter: add to Later (top of Later).
- `CmdOrCtrl+Enter` (Cmd on mac, Ctrl elsewhere): add to Today (top of today's plan day).
- Esc: close. Blur: close, except while a confirm is pending.
- Shift+Enter, Alt+Enter, Ctrl+Enter on mac: nothing.
- Empty clipboard or a notice on screen (5.3): Enter, `CmdOrCtrl+Enter` and Esc all close.

Modifier choice: `CmdOrCtrl`.
- App already binds it: `packages/shared/domain/shortcuts.ts:57` `form.submit` =
  `{ key: 'Return', cmdOrCtrl: true }`. Reuse that id; no registry change, no conflict-spec change.
- Common "send/commit" chord (Slack, GitHub, Jira). No OS or webview binding inside a text input
  on WKWebView, WebView2 or WebKitGTK.
- Rejected: Shift+Enter (newline convention, easy to hit while typing capitals); Alt/Option+Enter
  (Option+Enter inserts a line break in some macOS fields; Alt on Windows arms the menu bar);
  plain Ctrl on mac (not the primary modifier there).

Detection: `shortcutFor(e, ['form.submit'])` from `packages/workbench/src/shortcuts/keys.ts:90`
(exact match: no shift/alt). Plain Enter: `e.key === 'Enter'` with no modifier. Keep the existing
VueUse `useEventListener(window, 'keydown', …)` wiring and the `isComposing` guard.

Hints in the dialog (footer, `Kbd` like today):
- `Enter` + `common.later.label` ("Later"), testid `capture-hint-later`.
- `formatShortcut('form.submit')` (`⌘⏎` / `Ctrl+Enter`) + `space.common.day.today.label`
  ("Today"), testid `capture-hint-today`.
- `Esc` + `common.action.close.label`.
- Notice state: only `Enter` + Close and `Esc` + Close.

Today's date: frontend `localIso(new Date())` (`frontend/src/ade/v2/localDay.ts:2`), the same local
day the Plan uses. Literal today, as asked; no work-day shift.

### 4.3 Capture service

`internal/bridge/capture.go`:

```go
type CaptureConfirmArgs struct {
	WindowKey string  `json:"windowKey"`
	ItemID    string  `json:"itemId"`
	Title     string  `json:"title"`
	// Day is the plan day (YYYY-MM-DD) the task lands on; nil lands at the top of Later.
	Day *string `json:"day"`
}

// CaptureResult is Confirm's result. Notice names what the added task lacks ("" when complete);
// with a notice the popup stays open to show it.
type CaptureResult struct {
	TaskID string `json:"taskId"`
	Notice string `json:"notice"`
}
```

`Confirm`:
1. Validate window key; look up entry; stale id refused (unchanged).
2. `Kind == CaptureKindEmpty`: `ipcerr.Contract("nothing to capture")`.
3. `Day != nil`: `validateAdeISODate(*args.Day)`.
4. `res, err := s.add(ctx, e, args.Title, args.Day)`. `err` means no task: return it; popup and
   entry stay (retry is safe).
5. `res.Notice == ""`: `closePopup`. Else drop only the entry (`delete(s.entries, key)` under
   `s.mu`; keep `s.key` so a new hotkey press refocuses and refills this window). A repeat Confirm
   is then refused as stale: no duplicate task.

`add` (renamed from `later`):
1. `s.Tasks.CaptureTask(ctx, {Title, Day})`; error returns.
2. Patch as today (notes, `hostUrl`, `jira`). Patch failure: return
   `CaptureResult{TaskID, Notice: i18n.T("backend.space.capture.partial.body", {title, error})}`,
   nil. Same key, now a notice, not an error. Skip step 3.
3. `Kind == CaptureKindChangeRequest`:
   `s.Tasks.Engine.AddReviewLink(adeUserCtx(ctx), adewire.HostLinkArgs{URL: e.item.Text, TaskID: task.ID})`.
   Error: `Notice = i18n.T("backend.space.capture.noBranch.body", {title, error: errText(adeTaskError(err))})`.
   Import `i18n` the way `bridge/hostview.go` does.

Failure cases, all one notice, task kept with its `hostUrl` (the user can attach later from the
task):
- Repo not imported: resolver text "No repo in your workspace has a remote for host/owner/name.
  Add the repo first." Cloning an unknown repo is out of scope (repo import is its own flow with
  folder choice); the notice says what to do.
- PR not found or not visible, merged, host CLI signed out (`gh auth login` text), fetch failure,
  main branch, branch already on a live task (`ErrBranchOnTask` catalog text).

Ordering rationale: create first so a capture never loses the user's input over a network or host
failure. Fetch runs inside `Confirm`; popup shows a pending line meanwhile (5.2).

Credential rule: host lookup goes through the provider (host CLI); fetch goes through
`RunRemote` with the existing askpass. No new credential path.
