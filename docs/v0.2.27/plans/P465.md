## 1. Current mechanism

### 1a. Staleness is already detected server-side

- Committed review (`review.files`, `gitsession/incremental.go` `rangeFilesRecords:545`): every file
  with a record gets `changedSinceReview = currentBlobOID != rec.BlobOID` (tip blob vs blob at mark
  time). `reviewFileStatus:71` keeps `kind` (`full`/`partial`) and sets the flag.
- Uncommitted review (`AdeTaskService.ReviewWorking`, `ade/review.go:249` →
  `gitsession.WorkingReviewStates` `working_review.go:210`): `changed = rec.ContentHash != cur.Hash`
  (sha256 of worktree text at mark time vs now; size identity for binary/tooLarge).
- Wire: `ReviewFileStatus { kind, changedSinceReview, reviewedAt, reviewedAtSha }`
  (`packages/git-ipc/src/contract.ts:1314`, Go mirror `incremental.go:33`).

So the change key is already chosen and stored: **blob oid for committed, content sha256 for
uncommitted**. No new key, no schema change. The record is kept on purpose: `sinceReview` diffs
(`reviewFiles.ts:217`) and range projection need its snapshot.

### 1b. The UI ignores the flag

- `FileTree.vue:415` `reviewCheckboxState`: `full` → checked, `partial` → indeterminate, regardless
  of `changedSinceReview`. A changed file keeps a ticked box. Only a small warn `StatusDot`
  (`:572`, tooltip `git.review.changedSince.hint`) says otherwise.
- `reviewToggleTitle:411`, `ReviewFilesPane.onToggleReviewed:122`,
  `onToggleWorkingReviewed:132`, `ReviewView.onUiAction toggleFileReviewed:277`: "reviewed" means
  `kind !== 'none'`, so clicking a changed file's box **unmarks** it instead of re-marking.
- Counts (`ReviewFilesPane:76-85`) count `kind === 'full'`, changed included.
- `folderReview.ts:22` folder tri-state uses `kind` only.

This is the user's "checkbox stays stale".

### 1c. Refresh of the lists

- Committed list (`ReviewFilesState`): reloads on git stream `repo.changed` `refsChanged`
  (`reviewFiles.ts:99`), on mark, and on window focus (`AdeReviewFiles.vue:43`). A commit of an
  edit reaches it.
- Uncommitted list (`useReviewWorkingSync`, `useReviewWorking.ts:74`): invalidates on the board's
  tip/dirty signature, window focus, and agent `PostToolUse`/`Stop` events whose `cwd` is inside the
  worktree. Comment: "There is no polling; an edit made elsewhere shows on refocus."
- The git `RepoWatcher` watches `.git` dirs only (`gitclient/watcher.go:66` classify): an edit to an
  already-dirty file changes neither refs, index nor the board's dirty codes. Edits by a tool that
  fires no hook (external editor, an agent whose hook `cwd` is not the worktree path) never refresh
  the list while the window keeps focus. The ADE `folderWatcher` only rescans repo imports.

### 1d. Navigation and shortcuts

- `ReviewApi` (`git-ui/src/state/review.ts:514`): `selectFile`, `adjacentFile` (committed list order,
  `ReviewView.vue:365`), `refresh`. Diff tabs use it through `useReviewNavigationStore` for
  cross-file "next change".
- Shortcut registry: `packages/shared/domain/shortcuts.ts` `SHORTCUTS` (id → chord + scope), local
  binding through `@workbench/shortcuts/useShortcut`, display through `formatShortcut`, conflict
  check `packages/workbench/src/shortcuts/shortcutsConflicts.spec.ts`. `TooltipIconButton` takes
  `kbd`.

## 2. Design

### 2a. Attention state (frontend, one helper)

New `packages/git-ui/src/lib/reviewAttention.ts`:

```ts
export type ReviewAttention = 'unreviewed' | 'partial' | 'reviewed' | 'changed';

/** What a file needs: a recorded review whose content moved since is `changed`, whatever its kind. */
export function reviewAttention(s: ReviewFileStatus | undefined): ReviewAttention {
  if (!s || s.kind === 'none') return 'unreviewed';
  if (s.changedSinceReview) return 'changed';
  return s.kind === 'full' ? 'reviewed' : 'partial';
}

/** The state a checkbox click sets: a reviewed or partial file unmarks, anything else marks. */
export function markOnToggle(a: ReviewAttention): boolean {
  return a === 'unreviewed' || a === 'changed';
}
```

Plus the navigation step (2c). Every site in 1b switches to it:

- `FileTree.vue`: `reviewCheckboxState` → `reviewed` true, `partial` `'indeterminate'`, else false.
  `reviewToggleTitle` → `changed`: new `git.review.markAgain.tooltip`; `unreviewed`:
  `common.markReviewed.tooltip`; else `common.markUnreviewed.tooltip`.
- `ReviewFilesPane.onToggleReviewed` / `onToggleWorkingReviewed` and `ReviewView` `toggleFileReviewed`:
  `mark(path, markOnToggle(attention))`. A changed committed file re-marks through `review.mark`
  (re-snapshots at tip, flag false). A changed working file re-marks through `ReviewWorkingMark` with
  the list's current hash (existing `E_CONFLICT` guard stays).
- `folderReview.ts`: a file counts as `full` only when `reviewed`, as `notNone` only when `reviewed`
  or `partial`. A changed file reads as unreviewed, so a folder holding one is not checked, and a
  folder click re-marks it.
- Counts: `reviewedCount`/`workingReviewedCount` count `reviewed` only. Each header gets a warn chip
  when any file is `changed`: `git.review.changedCount.label` "{count} changed since review",
  testids `review-committed-changed-count`, `review-working-changed-count`.

"Returns to unreviewed" therefore means: shown, counted, navigated and toggled as unreviewed, while
the record survives for the since-review diff. No backend status change.

### 2b. Visual indicators (FileTree review rows only, Tailwind)

Each file row with `reviewStates` set gets `data-review-state="unreviewed|partial|reviewed|changed"`.

- `unreviewed`: empty checkbox, normal name. Needs attention.
- `partial`: indeterminate checkbox (dash), normal name (unchanged today).
- `changed`: empty checkbox with `border-warn` (class on `Checkbox`), name `text-warn`, the existing
  warn `StatusDot` kept (tooltip `git.review.changedSince.hint`). Needs attention.
- `reviewed`: checked box, name `text-muted-foreground`. Done; recedes.

Applies to the repo view's review sidebar too (same component). Folder rows unchanged apart from 2a.

### 2c. Previous/next unreviewed

Buttons in `ReviewFilesPane`'s `ViewToolbar`, after the diff-mode toggle (the delta status keeps
`ml-auto`): two `TooltipIconButton`s, icons `arrow-up` / `arrow-down`, testids
`review-prev-unreviewed` / `review-next-unreviewed`, labels `git.review.files.prevUnreviewed.tooltip`
"Previous file to review" / `git.review.files.nextUnreviewed.tooltip` "Next file to review",
`kbd` = `formatShortcut(id)` only when shortcuts are bound (2d). Disabled when no listed file needs
attention (`unreviewed`, `partial` or `changed`).

Order: the committed list as shown (`orderedPaths`, filter and list mode applied), then the working
list as shown (`orderedFilePaths(workingFiles, filter, listMode)`). Pure step in
`reviewAttention.ts`:

```ts
export interface ReviewSlot { section: 'committed' | 'working'; path: string; attention: ReviewAttention }
/** The next (previous) slot needing attention after (before) the cursor, wrapping; the first (last)
 *  one when the cursor is null or not listed; null when none needs attention. */
export function stepUnreviewed(order: readonly ReviewSlot[], cursor: { section; path } | null, dir: 'next' | 'previous'): ReviewSlot | null
```

`ReviewView.vue` owns the cursor (`ref<{section, path} | null>`): set by a committed open
(`reviewFiles.selectFile` path, including `ReviewApi.selectFile` and cross-file arrivals), a working
open, and every step. Fallback when null: `reviewFiles.selectedPath` as a committed cursor. A step
opens the target: committed → `reviewFiles.selectFile(path)`; working →
`workingChanges.onOpen(path, false)`. `ReviewFilesPane` emits `step` (dir) and `openedWorking`
(path); its `workingSelected` highlight derives from the cursor prop instead of local state.
Stepping with nothing to review (shortcut path) announces `git.review.allReviewed.announce`
"Every file is reviewed" through ReviewView's live region.

No unit test for `stepUnreviewed`: one wrap over one list; the UI spec walks it end to end.

### 2d. Keyboard shortcuts

`SHORTCUTS` gains, scope `view`:

```ts
'review.nextUnreviewed': { scope: 'view', chord: { key: 'F8', alt: true } },
'review.previousUnreviewed': { scope: 'view', chord: { key: 'F8', alt: true, shift: true } },
```

No conflict in `view` or `global` (the conflict spec must stay green). F7/Shift+F7 is Monaco's diff
navigation, so not used. Monaco's own Alt+F8 (next marker) has nothing to act on in a review diff;
the binding runs in capture so it wins.

Binding: new `MountOptions.reviewShortcuts?: boolean` (`git-ui/src/main.ts`, review rootProps).
`ReviewView` with it set calls `useShortcut(window, [...ids], handler, { capture: true })` (no
`ignoreTextFields`: Monaco's input is a textarea, and focus normally sits there). The review window
(`AdeReviewFiles.vue`) passes `reviewShortcuts: true`; the repo view sidebar does not, so several
sidebar mounts in one window never react to one key. The buttons show the `kbd` only with the flag.
Menu accelerators (`internal/shell/accel.go`) are global-only: untouched.

### 2e. Live refresh: stat stamp poll

Gap 1c: an edit to an already listed file by a hook-less tool. Choice: a cheap stat stamp polled by
the review window, not a worktree fsnotify watcher. Reasons: a recursive worktree watch costs
inotify watches on `node_modules`-sized trees, and review windows have no reliable backend close hook
(rows only drop on archive and at boot, `ade/review.go:334`, `main.go purgeReviewWindows`), so a
watcher would leak. A stat of the listed files spawns no git and reads no content.

Backend:

- `adewire`: `ReviewWorkingStampArgs { BranchID string "branchId"; Paths []string "paths" }`,
  `ReviewWorkingStamp { Stamp string "stamp" }`.
- `ade/review_working.go`: `func (b *TaskBoard) ReviewWorkingStamp(ctx, branchID string, paths
  []string) (string, error)`: `reviewWorktree` (same branch checks as ReviewWorking); worktree `""`
  → stamp `""`. Per path: `codeworkspace.ValidateRelPath(worktree, p)` (bad path → `invalid`),
  `os.Lstat`; feed `path \x00 size \x00 mtime-unix-nano \x00 mode \n`, or `path \x00 absent \n`
  for `fs.ErrNotExist`, into sha256; return hex. Any other stat error returns as an error.
- Bridge `adetask_review_working.go`: `AdeTaskService.ReviewWorkingStamp(ctx, args)`:
  `validateAdeItemID(branchId)`, `len(paths) <= adeMaxStampPaths` (5000) else `adeTaskInvalid("too
  many paths")`, no empty path; `adeTaskError` on the engine error.
- Regenerate bindings (`wails3 task common:generate:bindings`, DEV_ENVIRONMENT "Regenerate bindings").

Frontend:

- `ade/v2/wire.ts`: the two interfaces. `bridge/index.ts`: `adeTaskReviewWorkingStamp(args)`.
- `TIMING.reviewStamp = 1500` (`packages/workbench/src/behaviour/timing.ts`, doc: "Stat poll of the
  files a review window lists").
- `useReviewWorking.ts`: `useReviewWorkingStamp(branchId, paths)`: `useQuery` key
  `['adetask', 'reviewStamp', branchId]` (outside `reviewWorkingPrefix`, so a list invalidation never
  refetches it), `queryFn` reads `toValue(paths)` capped at 5000, `refetchInterval:
  TIMING.reviewStamp`, `enabled` while the window's branch has a worktree. A watch on `data`: a
  change from a previous defined stamp calls `invalidateReviewWorking()`. Settles in one round: a
  refetched list with the same paths yields the same stamp.
- `ReviewApi` gains `committedPaths(): readonly string[]` (every committed list path, unfiltered,
  reactive). `AdeReviewFiles.vue` keeps `api` in a `shallowRef` and calls
  `useReviewWorkingStamp(() => target.branchId, () => [...committedPaths, ...workingPaths])`. A
  committed path is stat'ed in the worktree too: an edit to a clean committed file makes it dirty,
  and the stamp change pulls it into the working list.
- Update the `useReviewWorkingSync` doc comment: it no longer claims no polling.

Committed side needs no poll: committing is a ref change, already pushed.

## 4. Tests (same scenario both halves, contract `ade-review-rereview`)

### 4a. Backend flow test

`apps/kira-space/internal/flows/adeflow/review_rereview_test.go`, `TestReviewRereviewOnEdit`, built
like `TestReviewWorkingReview` (`doneFixture`, `writeIn`, `gitOut`, `OpenReviewWindow`,
`ReviewWindowTarget`, `app.Contract`, `OpenGitStream`). Scenario:

1. Commit `base.txt`; write uncommitted `work.txt`.
2. Working: `ReviewWorking` → mark `work.txt` whole with its list hash → `ReviewWorking` reports
   `full`, `changedSinceReview: false`. Contract `AdeTaskService.ReviewWorking#reviewed`.
3. Stamp: `ReviewWorkingStamp{paths: [base.txt, work.txt]}` twice equal. Contract
   `args:AdeTaskService.ReviewWorkingStamp`, `AdeTaskService.ReviewWorkingStamp#before`.
4. Edit `work.txt` (different size, so mtime granularity cannot hide it). Stamp differs
   (`#after`). `ReviewWorking` reports `full`, `changedSinceReview: true`. Contract
   `AdeTaskService.ReviewWorking#changed` (masks as the existing test: `head`, `reviewedAt`,
   `reviewedAtSha`, worktree replace).
5. Re-mark with the fresh hash → `changedSinceReview: false`.
6. Committed: `repo.open`, `review.mark` `base.txt` reviewed on the git stream; `review.files` →
   `full`, not changed. Commit an edit to `base.txt`; poll `review.files` (cached refs lag, as the
   existing test does) until `changedSinceReview: true`. Contract `review.files#changed` (mask shas,
   `reviewedAt`).
7. Refusals: stamp with `../x` → `E_BAD_REQUEST`; more than 5000 paths → `E_BAD_REQUEST`.

Write the contract with `KIRA_CONTRACT=write`, then rerun without it.

### 4b. UI spec

`apps/kira-space/tests/ui/ade-v2-review-rereview.spec.ts` (`reviewTest`, `reviewControl`, git stream
mock with the contract's `review.files#changed` plus one reviewed-unchanged and one unreviewed file
built from the same entry shape):

1. Indicators: rows carry `data-review-state` reviewed / unreviewed / changed; the changed row's
   checkbox is unchecked (`aria-checked="false"`) with the warn dot; committed count excludes it;
   `review-committed-changed-count` shows 1. Working list from `ReviewWorking#changed`: same for
   `work.txt`, `review-working-changed-count` 1.
2. Re-review: clicking the changed committed box sends `review.mark` with `reviewed: true`; clicking
   the changed working box sends `ReviewWorkingMark` with `reviewed: true` and the list hash.
3. Live refresh: list starts as `#reviewed`, stamp `#before`; the spec swaps the stamp answer to
   `#after` and the list answer to `#changed`; within the poll the row turns `changed`. If the
   control mock cannot swap an answer mid-test, add `respond(channel, response)` to
   `ControlMockHandle` (`packages/workbench/src/testing/ui/mockRuntime.ts`) and use it.
4. Navigation: from no selection, next opens the first file needing attention, then the changed
   committed file, then the working file (working diff tab opens), then wraps; previous goes back;
   Alt+F8 / Shift+Alt+F8 do the same with focus in the diff editor. With every file reviewed both
   buttons are disabled.

Test support: `ipcChannels.ts` (`adeTaskReviewWorkingStamp: 'kira:adetask:reviewWorkingStamp'`),
`mockRuntime.ts` FQN entry `AdeTaskService.ReviewWorkingStamp` and a wildcard default
`{ stamp: '' }` so other review specs poll a stable stamp.
