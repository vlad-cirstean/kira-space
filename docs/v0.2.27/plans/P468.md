# P468 Agent branch and worktree requests: nanoid worktree name, branch in task

Spec row: `docs/v0.2.27/SPEC.md` P468. App: Kira Space. User ask: an agent requesting a branch and
worktree gets a worktree folder named with a nanoid. The branch keeps the name the agent asked for.
The branch lands in the task's Branches section.

## 1. Current mechanism

- MCP tool `request_branches` (`internal/agentmcp/space.go:211`) takes `repos` only
  (`requestBranchesArgs`, line 113). The agent cannot name a branch: P406 removed that, and
  ARCHITECTURE.md line 2428 says "never an agent-chosen name".
- Engine `ade/branchrequest.go`:
  - `planBranchRequest` (line 252) resolves refs against `taskCandidates`, so a registered repo not on
    the task is refused with "Call declare_repos first" (`resolveRepoRef`, `agenttools.go:92`).
  - `planRepo` (line 305): no row or non-mine row fails; named row with worktree is `existing`; named
    row without worktree is a `worktree` item; unnamed row is a `branch` item with its base.
  - `finishBranchRequest` (line 405) then `createApproved` (line 460) then `createBranch`
    (`agenttools.go:288`) with `newBranchName{generated: true}`.
- `ensureWorktree` (`setup.go:137`): folder is `freePath(rec.Name, branch)` =
  `<home>/wt/<repo>/<branch last segment>`, `-2`, `-3` on clash. Both the named path (line 156) and
  the new-branch path (line 178).
- `claimBranchName` (`setup.go:204`): `wanted` mode refuses a name git already has and maps
  `ErrBranchNameTaken` to "already on a task". Generated mode is `kira/<shortid 10>`.
- `internal/shortid` already wraps `github.com/matoous/go-nanoid/v2` (in root `go.mod`), Crockford
  base32 lowercase alphabet. Reused here; no new dependency.
- Task Branches section (`panel/AdeTaskTab.vue` line 255) renders `card.rows`, one per `task.branchIds`
  row (`usePlanModel.buildRow`). A row named by a request already shows there. Gap: a repo that is not
  on the task never gets a row, because the request is refused.

## 2. Design

### Interpretation (stated, for the orchestrator to check against the ask)

- "Keep the requested branch name as is": the agent may now pass a branch name per repo. Kira uses it
  exactly. No `kira/` prefix, no slug, no suffix. A repo without a name keeps today's `kira/<nanoid>`.
  This reverses P406's "never an agent-chosen name" for `request_branches` only.
- "Nanoid worktree name": every worktree a `request_branches` approval creates lives at
  `<home>/wt/<repo>/<nanoid>`. Covers both item kinds (`branch` and `worktree`).
- "Branch in task": a registered repo not on the task may be requested. On approval the repo row is
  added (origin `agent`) and gets its branch, so it shows in Branches. Deny, timeout or abandon adds
  nothing.
- Other worktree paths (StartRun, launch gate, SetTaskBranch, RetrySetup, rebase, automation
  predictions) keep `freePath`. Out of scope.

### MCP tool shape (additive)

`internal/agentmcp/space.go`:

- New exported `type BranchAsk struct { Repo, Branch string }`. `Branch ""` = Kira names it.
- `SpaceTools.RequestBranches(ctx, call SpaceCall, asks []BranchAsk)`.
- `requestBranchesArgs` gains `Names []branchNameArg \`json:"names,omitempty"\`` with
  `branchNameArg{Repo string \`json:"repo"\`; Branch string \`json:"branch"\`}`. `repos` stays
  required and non-empty, so existing calls keep working.
- New `cleanAsks(repos []string, names []branchNameArg) ([]BranchAsk, string)` replaces the
  `cleanRepos` call in the handler (keep `cleanRepos` for the repos list itself). Refusals:
  - more than 20 names: "names takes at most 20 entries."
  - a name whose `repo`, trimmed, is not in `repos`: "names[].repo must be one of repos."
  - one repo named twice: "names holds repo X twice."
  - an empty branch after trim: "names[].branch must not be empty."
  Branch text is otherwise passed through untrimmed-inside; git rules run in the engine.
- `fakeSpace.RequestBranches` in `mcp_test.go` takes `[]BranchAsk`; adapt its body (`asks[0].Repo`).

### Engine

`ade/branchrequest.go`:

- `RequestBranches(ctx, call, asks []agentmcp.BranchAsk)`; `planBranchRequest` takes `asks`.
- Resolve each ask's repo with `resolveRepoRef(ref, cands, "registered")` over
  `registeredCandidates` (not `taskCandidates`). An unregistered repo keeps the registered-kind
  refusal. Dedup by code repo id; the same id with two different names is a ToolError
  ("Repo X is asked twice with different branch names.").
- `requestSlot` gains `wanted string` and `addRow bool`.
- `planRepo(ctx, tc, id, wanted)`:
  - No row on the task: plan as an unnamed mine row (draft `model.AdeTaskBranch{TaskID, CodeRepoID: id,
    Kind: mine}` for `newBranchBase`), set `addRow`. Nick from the registered config (nickname, else
    name), since `tc.nick` lacks it.
  - Non-mine row: unchanged failure.
  - Named row and `wanted` set and different: failed, "Repo X already has branch Y on this task. Use
    it, or ask the user to change it." Same name or no `wanted`: today's rules.
  - Unnamed row (or added row) with `wanted`: `checkFreshName(ctx, id, wanted)`; an `ErrInvalidInput`
    becomes a failed slot with the refusal text (`toolMessage`). Item kind `branch`, `Branch: wanted`,
    `Base` as today.
- `createApproved(ctx, tc, s)`:
  - Row missing and `s.addRow`: `Tasks.AddBranch` (mine, origin `agent`, `AddedAt` now), same fields as
    `DeclareRepos`; use the returned row. Row missing and not `addRow`: keep "no longer on this task".
  - Row now named differently from `s.wanted` (changed during the wait): failed with the conflict text.
  - Then `createBranch(ctx, sb, s.nick, s.wanted)`. A creation failure after `AddBranch` keeps the row
    (the user approved the repo); the result is `failed` with the reason.
- `finishBranchRequest` unchanged apart from passing through.

`ade/agenttools.go`:

- `createBranch(ctx, sb, nick, wanted string)`: naming is
  `newBranchName{wanted: wanted, generated: wanted == "", idFolder: true}`. Doc comment updated.
- No change to `DeclareRepos`; it stays the way to add a repo without a branch.

`ade/setup.go`:

- `newBranchName` gains `idFolder bool`: "the worktree folder is a nanoid, not the branch's last
  segment". Doc comment updated.
- New `func (b *TaskBoard) idPath(repoName string) (string, error)`:
  `<HomeDir>/wt/<safeSegment(repoName)>/<shortid.New(agentBranchIDLen)>`. Up to
  `maxGeneratedNameTries` draws while `os.Lstat` finds the path; then an error
  "ade: no free worktree folder after 5 tries".
- New `func (b *TaskBoard) worktreeDir(repoName, branch string, n newBranchName) (string, error)`:
  `idPath` when `n.idFolder`, else `freePath`. Both `ensureWorktree` paths (named line 156, new line
  178) call it. On the new-branch path an `idPath` error releases the claimed name, same as an
  `addWorktree` failure (`SetBranchName(sb.ID, "")`).
- A named row whose branch already has a worktree returns that path unchanged (line 153), so an
  existing worktree is never moved.

### Path length and filesystem safety

- Folder name: 10 characters from `0123456789abcdefghjkmnpqrstvwxyz`. Lowercase only, so no clash on
  case-insensitive file systems (macOS, Windows). No separator, dot, space or shell metacharacter. Never
  a Windows reserved device name (those are 3 or 4 letters, or 4 plus a digit).
- Full path `<home>/wt/<safeSegment(repo)>/<10>`: never longer than the branch-derived path it
  replaces for a branch name over 10 bytes, so no new length limit. Git's own failure still surfaces
  as `failed` through `addWorktree`. No extra guard.
- Git names the admin dir `.git/worktrees/<basename>`; a random basename avoids git's own `1`, `2`
  suffix on folder-name clashes across repos sharing a name.
- Collisions: 50 bits per draw plus the `Lstat` retry. `git worktree add` refuses an existing
  non-empty path anyway.
- Sandbox: `requestedWorktreeDirs` (`sandbox.go:111`) grants `<home>/wt/<repo>`, the parent of the new
  folder. No sandbox change.
- Archive: `filepath.Base(lb.path)` becomes the nanoid as the dirty-confirm token
  (`archive.go:279`); it is opaque, no change.

### Migration and compatibility

- No schema change. Branch rows store names, not paths; worktree paths come from git inventory.
- Existing worktrees stay where they are. `ensureWorktree` returns an existing checkout's path before
  any naming runs. No rename, no move.
- Agents calling `request_branches` with `repos` alone behave as today, except the folder name and
  the wider repo set.
