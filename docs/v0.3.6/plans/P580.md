## Decisions

### Rule shape

```json
{ "effect": "allow" | "deny", "hosts": ["127.0.0.1", "*.example.com", "*"], "methods": ["GET", "POST"] | ["*"] }
```

- `hosts`: 1-20 entries. Each is `*` (any host, any port) or a `HostRule` entry without the `http://`
  prefix (scheme is not part of an access rule; `checkTarget` already limits schemes). `*.example.com`
  matches `a.example.com` and `a.b.example.com`, never `example.com`: same meaning as `agentHosts`, one
  grammar for both. `host:port` pins the port; no port means any port.
- `methods`: exactly `["*"]`, or 1-7 distinct members of `GET HEAD OPTIONS POST PUT PATCH DELETE`
  (the `api_request` method enum, `api_tools.go:151`), uppercase.
- List leaf `dbMcp.apiRules`, at most 50 rules, default `[]`.

### Precedence and default

- Empty list: every host and method allowed (today's behavior; existing installs unchanged).
- Non-empty list: a request is refused when any `deny` rule matches; otherwise allowed only when an
  `allow` rule matches; otherwise refused. Deny always wins, so order never matters (no reorder UI).
- A rule matches when one of its hosts matches the URL host (and port) and its methods hold the method.
- Deny-only list refuses everything; UI warns.

### Error text (agent-facing, plain Go strings, never catalog)

- Deny: `DELETE https://admin.example.com is denied by the API access rule "deny DELETE on *"`.
- No allow: `POST http://127.0.0.1:1234 is not allowed by the API access rules in Kira Space's
  database MCP settings. Allowed: GET on 127.0.0.1; any method on *.example.com. Ask the user to add a rule`.
  Text names method plus `scheme://host[:port]` only, never path or query, so no secret can leak.
- Redirect hop: `redirect to localhost blocked: GET is not allowed there by the API access rules`.
- Unreadable stored rules: `the API access rules in Kira Space's database MCP settings could not be read;
  ask the user to replace them`.

### Where it is enforced

In `agentapi.Plan`, after `buildPlanned`, before `checkCredentials`. Consequences:

- Refused request never raises an approval item (Plan failure returns an error, `api_tools.go:101-104`).
- Rules edited while an item waits apply at send, because `Send` re-plans.
- Every redirect hop is checked with the request's method (`redirectGuard` grows a policy argument).
  A 303 that turns POST into GET is still checked as POST: conservative, documented.
- `apiApproval` unchanged: `never` only skips the question for requests the rules allow;
  `agentAutoApproveReads` unchanged. Rules are a hard gate in front of approval, never a substitute.
- `Service.Access` nil means no rules (tests constructing `Service` directly keep working).

### Fail closed on bad stored data

`appsettings.Leaf` silently keeps the default on a decode failure, which would be `[]` (allow all). So
`GetAll` reads the leaf with a dedicated reader: present but undecodable or failing `apiaccess.Compile`
sets `DbMcpSettings.APIRulesInvalid = true` and `APIRules = []`. The access reader then refuses every
request with the unreadable text; UI shows an error alert. A successful `Set` of `apiRules` overwrites the
leaf and clears the flag. `Set` always validates, so only a hand edit or a future grammar change hits this.

### Package placement

New leaf package `apps/kira-space/internal/apiaccess` (stdlib plus `golang.org/x/net/idna`, already a dep):

- `hostrule.go`: `HostRule`, `ParseHostRule` moved from `apifiles/agenthost.go` (`git mv`, no alias).
- `policy.go`: `Rule` (JSON wire struct), `Policy`, `Compile([]Rule) (Policy, error)`,
  `(Policy) Check(method string, u *url.URL) error`, `(Policy) Empty() bool`.

`model` imports `apiaccess` for validation and the field type; `apifiles` and `agentapi` import it for
`HostRule`. No cycle.

### Libraries

- Go: no glob library in `go.mod` (`moby/patternmatcher` is indirect, path-oriented). `path.Match`/glob
  semantics are wrong here: `*example.com` would match `badexample.com`, and none normalize IDNA, IPv6
  brackets or default ports. Reusing `HostRule` keeps one host grammar across agent hosts and access rules.
- Frontend: no picomatch/minimatch in deps; validation is a shape check only (below), not matching.

### Settings UI

- Frontend rules: Tailwind utilities, no scoped `<style>`; shadcn-vue `Dialog`, `Button`, `Badge`,
  `TagsInput` (precedent `studio/api/ApiAgentAccessForm.vue`), `ToggleGroup` (type multiple) for methods,
  `Checkbox` for "Any method", `NativeSelect` for effect, `Alert`. `<script setup lang="ts">` only.
- Pinia: rules are part of settings, already owned by `useSettingsStore` (`patchSettings`); no new store.
- TanStack Query: settings are not query-cached server state in this app (store + `settings:changed`
  event); no query added. VueUse: no DOM composable needed.
- Instant action like the rest of the pane (no draft/Save): each dialog Save or row Remove sends one
  `SettingsService.Set` with the whole new `apiRules` list. Errors via `useAsyncAction`, shown in the dialog
  (save) or under the list (remove).
- Zod: stored-settings schema stays lenient (`hosts: z.array(z.string())`, `methods: z.array(z.string())`)
  so a Go-accepted entry the TS check would reject (IDN unicode host) never fails hydrate. Strict host
  shape check runs only in the dialog (`isHostPattern`), Go stays authoritative.

### Commit 2 `feat: API access rule policy`

5. `apiaccess/policy.go`:
   - `type Rule struct { Effect string `json:"effect"`; Hosts []string `json:"hosts"`; Methods []string `json:"methods"` }`.
   - `Compile` validates: effect `allow`|`deny`; hosts 1-20, each `*` or `ParseHostRule` with `HTTP == false`
     (error `rule %d: host %q: not a host, host:port, *.domain or * entry`, 1-based); methods `["*"]` or
     distinct enum members; at most 50 rules. Error names rule index and offending value.
   - `Check(method, u)`: empty policy -> nil; deny match -> deny error; allow match -> nil; else no-allow
     error listing allow rules (`GET, POST on 127.0.0.1; any method on *.example.com`). Rule summary
     helper `String()` (`deny DELETE on *`). Error text uses `method + " " + u.Scheme + "://" + u.Host`,
     never path or query.
6. `apiaccess/policy_test.go`, table-driven. Justified under WORKING_AGREEMENT Testing: decision structure
   with interacting rules (deny precedence over allow, `*` host, wildcard suffix not matching apex,
   port pinning vs any port, IDNA and IPv6 normalization, method list vs `*`, empty-list allow-all,
   deny-only refuse-all) plus `Compile` rejections (http prefix, path, empty hosts, duplicate or lowercase
   method, `*` mixed with methods, over limits). One table each, no CRUD-style cases.
