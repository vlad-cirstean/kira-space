## Decisions

### D1. Deviations from the design (guards and copy rules win; flag in Result)

- Weight: op and target use `font-medium` (500), not 600. U11 bans `font-semibold` outside log data; a
  weight preference is no requirement a primitive cannot meet, so no exemption. Hierarchy stays: 500 vs
  400 plus size 13 vs 12/11. The design's "2 weights" become 400 and 500 (Button already 500).
- Spacing: line 1 `gap-x-2` (8px, design 10px), item `py-3` (12px, design 14px): U88 scale.
- Body padding: the design's `px-4` is the mockup's first misalignment (header title at 12px, items at
  16px, footer buttons at 12px). Keep `DialogBody`'s `px-3`, so item edges match header and footer (A1).
- Risk type: `risks?(item): ApprovalRisk[]` with `ApprovalRisk = { text: string; tone: 'warn' |
  'neutral' | 'error'; testid?: string; tooltip?: string }`, not `string[]`: the design's testid table
  puts testids on risk tags and "Read-only" is neutral.
- Font flags: `targetData?: boolean` and `whereData?: boolean` on the def (api host, script cwd) instead of
  styling inside `where()`.
- Copy keys get roles and live in the owning app namespace (risks are computed in app `kinds.ts`, not in
  workbench). Full list in D9. Lowercase-start tags in the mockup ("new · from main", "rev 3",
  "secret · saved", "checkout") start with a capital (C6). Reuse instead of new key where C3/C4 demand
  (Looks like, Read-only, Edit, Run script, Result, Headers, Params, Variables, Workflow, Repository,
  Worktree, Check out, Description). "Note" becomes "Description" (`common.field.description.label`;
  "Note" collides with a markdown alert title). task.create base keeps
  `space.ade.request.taskCreate.base.label` / `baseMain.label` ("Branches off {base}"): "From {base}"
  is a C4 near duplicate of `space.mobilePairing.from.label`.
- "Reason" (C4 near duplicate of `memory.start.reason.label` "Reason:"): add `common.field.reason.label`
  "Reason", repoint `packages/workbench/src/memory/MemoryStart.vue:87` to it, delete the memory key.
  "Result": repoint the one caller of `space.ade.settings.result.title`
  (`ade/v2/settings/AdeSettingsResult.vue:46`) to new `common.field.result.label` "Result", delete the old
  key; the op reuses it. "Run script": reuse `automations.dialog.run.untitled.title` (P580 precedent of
  cross-feature reuse), delete `studio.dbMcp.approval.script.operation.label`.
- Credential risk: one tag `api-approval-credential` with tooltip naming each credential and its hosts
  (reuse `studio.dbMcp.approval.api.credential.label` text as tooltip), not one element per credential.
- Result table footnote: truncation, truncated cells, Redis type, TTL and note (today the summary line)
  stay as one `text-kira-sm text-subtle` line under the table (`db-mcp-preview-summary`), only when any
  is present. Row counts move into "+N more rows". This keeps data the design's table did not place.
- `ReviewResultOption` when already on by connection settings: checked and disabled, its
  `reviewResultOn.body` sentence moves to a `Tooltip` on the label (no room in the footer).
- Open window keeps key `studio.proof.change.openWindow.label`; value becomes "Open window".
- Testids: one element, one testid. Where keeps `approval-target-kind`, so `api-approval-target` (design
  table) is dropped; `api-approval-credential-<name>` becomes `api-approval-credential`;
  `db-mcp-approval-kube-namespace`, `db-mcp-approval-detected`, `db-mcp-approval-enforcement`,
  `db-mcp-approval-mode-masked`, `db-mcp-exemption-lede`, `db-mcp-exemption-no-timeout`,
  `ade-task-create-parent`, `ade-task-create-title`, `db-mcp-approval-plan` go with their elements.

## Alignment rules (fix the mockup, enforce in code and spec)

Mockup misalignments found (`approval-dialog-proposal.html`, PNG at 1925 px wide):

1. Items start 4px right of the header title and end 4px left of the footer buttons (`.dlg-b` 16px vs
   `.dlg-h`/`.dlg-f` 12px).
2. Risk tags sit about 2px above the line-1 baseline (`.risk` is `inline-flex items-center` inside an
   `items-baseline` row, so its baseline comes from the SVG): "~48,210 rows", "Timeout 31 s / 30 s",
   "Credential sent".
3. The colour band uses `margin-top: -2px` to cancel the row gap: band spacing differs from other gaps.
4. Formatted/As sent tabs: 11px text with its own line box at `top: 0`, so its baseline is about 2px off
   the first code line; long first lines can run under the tabs.
5. Footer gaps differ: Deny/Approve 12px apart, dialog Deny all/Approve all 6px; Open window uses an
   extra `margin-right: 4px`.
6. Monaco in the real app (not the mockup) adds 10px line decorations and 8px top padding, so SQL would
   sit right of and below other content.
7. Table head cells and first column carry `px-2` in the real `Table`, so result columns would start 8px
   right of the content indent.
8. `AdeNotesEditor` readonly prose carries `px-3 py-2`, so the brief would start 12px right of the indent.

Rules (A1-A11, each is a check in the alignment spec):

- A1 Edges: item left edge = `DialogTitle` text left = dialog footer left padding (12px); in an item,
  countdown right edge = Approve right edge = band right edge.
- A2 One indent token: content and details start at item left + 12 (`pl-3` on the card's body wrapper
  only). First code glyph (Monaco `.view-line`, `CodeBlock`), first table column text, branch checkbox,
  proof ordinal, brief text and every `dt` share that x (±1px).
- A3 Details: label column fixed 72px; every `dt` x equal, every `dd` x = content x + 84 across all items
  of the dialog (fixed width, so cross-item equal). `items-baseline`: `dt` baseline = first `dd` line
  baseline. "+N more" inside `dd` starts at the `dd` x.
- A4 Line 1: one `items-baseline` row; op, target, where, risk text and countdown share one baseline
  (±1px). Risk tag `inline-flex items-baseline`, icon `self-center`, so the text sets the baseline.
  Wrapped line 1: countdown aligns with the first line (flex first baseline).
- A5 Band: block child of the item column, no negative margin; x and width = item; vertical gap above
  and below = the item gap (8px).
- A6 Footer: `items-center`; requester, option and button centers equal (±1px); Deny/Approve gap 6px
  (`gap-1.5`, same as `dialogFooterClass`); requester/option/button group gap 12px; no ad-hoc margins.
- A7 Countdown: `tabular-nums`, so width is stable per second; right-aligned at item right (A1).
- A8 Tabs: own grid column right of content (`grid-cols-[minmax(0,1fr)_auto] gap-x-3`), so code never
  runs under them; tab right edge = item right; tab vertical center = first content line center (±1px).
- A9 Collapsed lists: "+N more" x = start of the column it extends; gap above = row gap.
- A10 Branch rows: one grid for all groups; repo, branch and tag column x equal across rows (±1px);
  checkbox center = row text center.
- A11 Monaco flush: editor background computed transparent (shows `bg-dialog`); no gutter
  (`.margin` width 0 or absent); first line top = wrapper top.
