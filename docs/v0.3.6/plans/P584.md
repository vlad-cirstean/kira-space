## Reading of the ask

"File names look strange and do not reflect the step name": stems stuck at `new-step-N` after a rename.
"Step names are strange": the `stp_...` ids in workflow YAML (the user sees `id` as the step's name) and the
uniform "New step" default. Cheapest reading that satisfies: stems follow `name` on in-app save, step ids
derive from the name, default names say the kind, existing files are converted once.

## Decisions

### Naming scheme

- Stem = `slug(name)` (existing `slug`, fallback `step` / `workflow`), unique by `-2`, `-3` suffix,
  capped at 60 with the suffix (new `freeStem`, same shape as `apifiles.freeName`, `apifiles/slug.go:36-51`).
- A stem "matches" a name when it equals `slug(name)` or `slug(name)-<n>`. A matching stem never moves.
- Stem follows name on structured saves only: `SaveStep` (Form mode) and `SaveWorkflow` (graph mode).
  YAML-mode saves (`SaveStepYaml`, `SaveWorkflowYaml`), external editors and imports write as given;
  the stem-is-id validation stays unchanged.
- Rename changes the id (id = stem stays the rule). No separate stable id: the only state holding an
  ADE config id is `ade_tasks.workflow_id`, rewritten in the same operation.
- Shared files keep their stem: when `<home>/config/.sync/base/<module>/<file>` exists, the file came from the
  shared repo and a rename would turn later pulls into conflicts. Save then writes in place (today's
  behaviour). New `configsync.HasBase(home, module, file string) bool` (pure path check, new file).

### Library step rename (Form save, name changed, stem no longer matches)

1. Under `Reader.wmu` then `StepLibrary.wmu` (fixed order). Base hash check on the old file as today.
2. Referencing workflows: `StepUsers()[old]`. Each must parse as YAML, else refuse the whole save:
   `workflow %s has a YAML error on line %d; fix it before renaming step %q`.
3. New stem = `freeStem(slug(name,"step"), taken)`, taken = file exists in steps dir.
4. Journal `{kind:"step", old, new, oldHash, workflows:[...]}` to the journal path (atomic write).
5. Write `<new>.yaml`: old doc with the edit applied (existing `encodeStep` path, comments kept), `id: new`.
6. Each workflow: node rewrite `retargetLibrary(root, old, new)`: item `step: old` becomes `step: new`. An
   item without `id` had step id `old`; rename that step id to `new` inside the file (`renameStepID`:
   rewrites result `next`, `routes` values, `review.implementer`) unless `new` is already a step id in the
   file, then pin `id: old` on the item. `configfs.WriteAtomic`.
7. Remove old file only when its hash still equals `oldHash`, else keep it and `slog.Warn` (never lose an
   edit made meanwhile). Remove journal. Return the new entry (`FileName` = new).

### Workflow rename (graph save, name changed, stem no longer matches)

1. `Reader.wmu`, base hash check. Journal `{kind:"workflow", old, new, oldHash}`.
2. Write `<new>.yaml` (existing `encodeWorkflow` on the old doc, `id: new`).
3. `retarget(old, new)` callback: `AdeTaskRepo.RenameWorkflowID(old, new)` =
   `UPDATE ade_tasks SET workflow_id = ? WHERE workflow_id = ?` (archived rows too). Snapshots untouched.
4. Remove old file (hash check as above), remove journal, return the new entry.

### Journal and recovery

- Path `<home>/ade/rename.json` (state dir, outside `config/`, so neither a module watch nor sync sees it).

### One-time migration of existing files

- `Reader.MigrateNames(backupDir string, keep func(module, file string) bool, retarget)` in `TaskBoard.Start`,
  after `RecoverRename`, only when marker `<home>/ade/names-v1.done` is absent. Order:
  1. Inline ids: every workflow file that parses as YAML; each item whose explicit `id` matches
     `^stp_[0-9a-hjkmnp-tv-z]{12}$` gets `freeStem(slug(name,"step"), ids in file)` via `renameStepID`.
     One atomic write per file. Files that do not parse: Warn, skipped.
  2. Library stems: valid file whose stem does not match its name and `!keep("steps", file)`: library rename.
  3. Workflow stems: same with `keep("workflows", file)`: workflow rename.
  4. Write the marker. Each step is idempotent, so a crash before the marker re-runs safely.
- Before the first write to any file, copy it to `<home>/backups/readable-names-<UTC ts>/<module>/<file>`
  with `fsmove.CopyVerified` (configsync's pattern, `configsync/apply.go:126`). One `slog.Info` with counts.
- Deps: `ade.Deps` gains `NamesMarker`, `BackupDir` (paths) and `KeepStem func(module, file string) bool`;
  empty marker disables the migration (unit fixtures). Wired in `appwire/wire.go:~251`.
- Hand-named files are renamed too: the new rule is stem = slug(name); a shared or synced file is exempt.

### Config sync impact

- No change to merge logic. A rename shows in the user's shared repo as delete plus add (git sees a rename).
  Pulled files keep their stems (`HasBase`), so pulls keep merging. A teammate pulling a renamed file gets

  theirs absent). ARCHITECTURE "Config sync" gets one bullet.
- Validator gate unchanged (`adeflow.ValidateStepYaml` still checks id = stem).

- Existing `id must equal the file name without .yaml` stays for YAML-mode and hand edits.
- Recovery and migration failures: `slog.Warn` with file names only, never content; app keeps booting.

## Docs (ARCHITECTURE.md, additive)

- "Workflows" / "Step library": file stem is `slug(name)` unique by `-N` (max 60); structured saves rename the
  file when the name's slug changes, rewriting `step:` references (implicit step ids follow, routes
  retargeted, collision pins the old id) and `ade_tasks.workflow_id`; journal `<home>/ade/rename.json`,
  recovered at `Start`; YAML-mode and external edits never rename; files with a sync base keep their stem.

  One-time migration (`names-v1.done`, backups `backups/readable-names-<ts>`).
- "Config files": after "A rename is a delete plus a create": ADE renames rewrite their references in one
  journaled operation.
- "Config sync": a local rename reaches the shared repo as delete plus add; synced files keep their stem.
