Why selection fails:

- `packages/theme/src/base.css:37`: `body` is `select-none`. `base.css:40-45` opts back in only for `input`,
  `textarea`, `[contenteditable="true"]`, `.cm-editor`.
- TipTap with `editable: false` (`AdeNotesEditor.vue:69`) renders ProseMirror as `contenteditable="false"`,
  so the opt-in misses it. `EditorContent` (`AdeNotesEditor.vue:274-279`) carries no `select-text`. Same in
  edit mode works (`contenteditable="true"`), which is why only the view is broken.
- Run dialog cards (`AdeRunDialog.vue:219`, `:227`) inherit `select-none`.
- Not a cause: no row click, mousedown or drag handler on `AdeNoteEntry` Card or ancestors (grep over
  `ade/v2/panel`, `details`, `notes`: only `AdeEstimateField.vue:83` and the editor toolbar
  `AdeNotesEditor.vue:246,266`, not rendered read-only). `handleClick` (`AdeNotesEditor.vue:73-82`) acts
  only on primary-modifier link clicks, returns `false` otherwise.
- Already fine: stage dialog (editable TipTap), agent dialog (`Textarea`).

P577 precedent (`docs/history/06-v2.8.md:1223`): same root cause (body `select-none`, viewers never opting
in). Fix: `select-text` on `LogLines`, `CodeBlock`, outcome spans, plus `CopyLogButton` over `useCopy`.
`docs/ARCHITECTURE.md:1364` records the rule: text a person reads as data opts back in with `select-text`.

Copy helper: `packages/workbench/src/behaviour/clipboard.ts:113` `useCopy()` (`copy`, `copied`, `error`),
built on VueUse `useTimeoutFn`. Its doc (`:110-111`) declines VueUse `useClipboard`: it swallows the
`writeText` rejection that `copyText` surfaces. Icon pattern: `packages/workbench/src/components/Identifier.vue:27-32`
(`TooltipIconButton :icon="copied ? 'check' : 'copy'"`).

## Decisions

1. Read-only notes editor selects. `AdeNotesEditor.vue` `EditorContent` gains `select-text cursor-text`
   when `readonly`. Fix lives in the shared component, so every chain entry kind (live and archived) is
   covered, and any later read-only use too. Native ProseMirror copy (Cmd+C on a drag selection) then
   works; its text serializer keeps hard breaks as newlines.
2. Run dialog handover and task notes cards get `select-text` (`AdeRunDialog.vue:219`, `:227`).
3. Copy button per chain entry. `AdeNoteEntry.vue` header row gets a `TooltipIconButton` before the edit
   button: icon `copy`, `check` while `copied`; `tone="error"` while `error`; label
   `space.ade.handover.copy.tooltip`; testid `ade-handover-copy`. Copies `handover.body` verbatim (the
   Markdown/plain source an agent or user wrote, fit for pasting into a prompt). Shown when not editing and
   `handover.body.trim()` is non-empty; shown read-only too (archived). Announcement: `useCopy` default
   (`common.copy.copied.announce`, failure `common.copy.failed.error`).
   - Library: `useCopy` from `@workbench/behaviour/clipboard`, not VueUse `useClipboard`. Requirement it
     cannot meet: surfacing the `writeText` rejection (swallowed by `useClipboard`); repo-wide rule since
     `useCopy` exists. Primitive: `TooltipIconButton` (shadcn-vue Button plus Tooltip). Tailwind only, no
     scoped style. No new store or query: copy feedback is component-local.
4. No copy button in the Run dialog: it is a launch confirmation; selection covers it. Stage and agent
   dialogs unchanged (already selectable).
5. Selection scope is the body only, not entry headers or chips (data, not chrome; ARCHITECTURE rule).
   Proof and audit entries in the same chain are not handovers: out of scope.
6. Row behaviour unchanged: edit button, child link, origin session link, Move on stay as they are.
7. No backend half: no IPC, wire or Go change. Copy writes `navigator.clipboard` in the renderer.
8. No unit test: two class bindings and one button, nothing complex.
