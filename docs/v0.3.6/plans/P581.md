# P581 Review tool: diff against target branch like a source control app, fetch buttons

Stream B of `batch-P580-P582.md`. Worktree `/home/user/kira-wt-p581`, branch `stream/p581`.

SPEC row: review window shows diff to target branch like a source control app; base gets the same "latest version" treatment the branch has; easy buttons fetch the right branches when the local branch or base is not latest.

"Review tool" here is the ADE review window (`AdeReviewWindow.vue`, opened by `OpenReviewWindow`). The Git sidebar review (`RepoReviewView.vue`) keeps its base picker and the repo toolbar's own Fetch; out of scope.

## 1. Current behavior (evidence)

Paths relative to `apps/kira-space/` unless they start with `packages/`.

### 1.1 How the window gets its refs

- `internal/ade/review.go:64-82` `reviewTarget` builds `ReviewWindowTarget{Branch, Base}` from `reviewSpellings` (`review.go:37-62`). Computed when the window boots (`frontend/src/main.ts:185-192`, `reviewTargetKey` query, `store.target` set once) and never again in that window.
- Branch: `resolveQueuedRef` (`internal/ade/gitfacts.go:76-90`) = local `refs/heads/<b>` first, else `<defaultRemote>/<b>`. Spelling via `refSpelling` (`review.go:29-34`): `feat/x` or `origin/feat/x`.
- Base: `boardCtx.resolveBase` (`internal/ade/board_facts.go:97-124`), the one base rule (P241):
  - main (`sb.Base == ""` or main's short name): `MainRef` (`internal/gitsession/queuefacts.go:80-111`): `origin/HEAD` target, else per candidate `<remote>/<c>` before local `<c>`. So normally `origin/main`.
  - named non-planner base: `resolveBaseRow` (`gitfacts.go:133-145`): default remote's branch first, else local.
  - planner parent (by id or name): `plannerRef` (`board_facts.go:127-137`) via `resolveQueuedRef`: **local first**.
  - base missing: `reviewSpellings` falls back to the stored name (`review.go:56-57`).
- Default remote: `DefaultRemote` = `pickAutoFetchRemote` (`internal/gitsession/autofetch.go:294-314`): `origin`, else the sole remote.

### 1.2 Diff semantics (already source-control shaped)

- File list: `rangeFilesRecords` (`internal/gitsession/incremental.go:545-611`): `branchTip` (`incremental.go:151-161`, cached refs snapshot) then `mergeBase(base, branch)` (`incremental.go:120-142`) then `NameStatusArgs(&mb, tip)`. Three-dot: merge-base of base and branch, to branch tip.
- File diff: `ReviewFileDiff` (`incremental.go:660-717`) via `handleReviewFileDiff` (`internal/gitrpc/incremental.go:113-150`); `mode: "range"` body is `rangeFileDiffBody(mb, tip, path)` (`incremental.go:518-532`), same merge-base. `sinceReview` diffs against the stored snapshot.
- Refs are names, resolved live: `branchTip` reads the refs snapshot; merge-base cache keyed by ref names, dropped on `refsChanged` (`internal/gitsession/cache.go:119-146`).
- git-ui follows ref moves: locked mount (`frontend/src/ade/v2/review/AdeReviewFiles.vue:180-200`, `lockTarget: true`) auto-applies a changed resolution (`packages/git-ui/src/state/review.ts:117-126,464`), and `ReviewFilesState` reloads on `refsChanged` (`packages/git-ui/src/state/reviewFiles.ts:100`).
- GitHub PR "Files changed" is the same three-dot diff (merge-base of head and latest base, to head). IDEs (VS Code, JetBrains) compare against local refs as of the last fetch.

Conclusion: diff semantics already match a source control app. What differs is ref freshness.

### 1.3 When fetches happen

- Never on review window open, focus or diff load. No fetch path in `review.go`, `incremental.go`, `useChangeRequestReview.ts`.
- Auto-fetch timer (`autofetch.go:178-207`): whole default remote, `Prune: true`, credential-free (`conn == nil`), only when the user set an interval and a non-quiet acquirer exists.
- ADE board repo chip ↻ (`frontend/src/ade/v2/plan/AdeRepoChip.vue:80-89`) calls `TaskBoard.Refresh` (`internal/ade/board.go:745-767`) then `refreshRepo` (`board.go:774-862`): whole default remote fetch with prune plus env scripts, merge marks, conflict checks.
- Explicit fetch path: `RunRemote` (`internal/gitsession/remote.go:300-430`) then `runFetch` (`remote.go:436-472`); askpass interposed through `withAskpass` (`remote.go:136-147`); `invalidateAfterWrite` on every exit (`remote.go:390`).
- `lastFetchAt` = mtime of the worktree's `FETCH_HEAD` (`internal/ade/board.go:964-972`), shown on the repo chip.

### 1.4 What the review window shows for staleness today

- Branch: head badge `ade-review-head` (`frontend/src/ade/v2/review/AdeReviewHeader.vue:75-100`, `useReviewHead.ts:11-31`): local branch tip vs the change request's host head (`internal/gitsession/crreview.go:73-125`, `LocalHeadSha`). `stale` / `current`, refreshed on `refsChanged`. Only with an open change request. No action button.
- Base: plain text `Base {base}` (`AdeReviewHeader.vue:58-60`). No staleness, no fetch age, no action.
- Local branch behind its remote: the board computes it (`fillUpstream`, `board_facts.go:373-390`: tracked upstream counts, else `AheadBehind` against `<remote>/<b>`) but the review window never shows it.

So the branch side has a freshness indicator (head badge); the base side has none, and neither side has a button.

### 1.5 Concrete stale cases

1. `origin/main` (or `origin/<named base>`) behind the real remote: no fetch since teammates merged. Diff shows their commits as if in the branch when the branch was rebased on the newer main by someone who had fetched (agent fetch through `FetchRemote`, other clone). Fix: fetch.
2. Planner parent base local and behind `origin/<parent>` (parent pushed from elsewhere). Fix: fast-forward local parent.
3. Local base fallback (no remote twin seen yet), later visible after a fetch. Fix: fast-forward local.
4. Local branch behind `origin/<b>` (review branch someone pushed to, or a teammate pushed to a shared branch). Review shows the old version. Fix: fast-forward local branch.

## 2. Decisions

D1. Diff semantics: keep three-dot (merge-base of base and branch, to branch tip). No change to `rangeFilesRecords`, `ReviewFileDiff`, `handleReviewFileDiff`. Matches GitHub PR.

D2. Ref spellings stay as resolved (P241 one base rule untouched). Reasons: review sessions are keyed by branch spelling (`review_session` repo_id+branch); switching `feat/x` to `origin/feat/x` would orphan marks; the board, rebase and conflict checks share `resolveBase`; a remote base spelling already tracks the remote after any fetch through `refsChanged` auto-apply. "Latest version" comes from two actions instead: Fetch updates remote-tracking refs; Update fast-forwards a local ref to its remote twin.

D3. Staleness detection, no network: per ref (branch, base) compute against local refs.
- Local spelling: twin = tracked upstream row, else `<defaultRemote>/<short>` row (same rule as `fillUpstream`). Counts: upstream track counts from the inventory, else `AheadBehind(localTip, twinTip)`. State: `current` (0/0), `behind` (ahead 0, behind > 0), `ahead` (ahead > 0, behind 0), `diverged` (both > 0), `noRemote` (no twin or upstream gone).
- Remote spelling: state `remote`; freshness = `lastFetchAt`.
- Plus `remote` name and `lastFetchAt` (shared `lastFetchAt` helper).
- No `git ls-remote` probe: a network read on open or focus would prompt for credentials or need a credential-free path; a fetch of the default remote costs about the same and leaves refs updated. IDEs base sync indicators on the last fetch too.
- No auto-fetch on window open: the user's auto-fetch interval setting owns background fetching.

D4. Fetch action `ReviewFetch(branchId)`: fetch every remote the review depends on: the default remote plus the remote of the branch twin and of the base twin (inventory `Remote` field, never parsed from a refname), deduped, sequential, `Kind: "fetch", Prune: true` (same as the repo chip and auto-fetch). Through `entry.RunRemote(ctx, b.conn, ..., RemoteDeps{Askpass: b.deps.Askpass})` under `b.repoMutex`. git owns credentials; Kira only interposes its askpass prompt (CLAUDE.md CLI credentials; ADE is outside G5's dirs but follows the rule). Whole-remote fetch, not refspecs: a refspec for a branch absent on the remote fails the whole fetch, and a deleted remote branch should prune. No env scripts, no conflict-check wait (unlike `Refresh`). `notifyBoard()` after.

D5. Update action `ReviewUpdateLocal(branchId, side)`, side `branch` | `base`: fast-forward only.
- Recompute facts server-side; refuse (`invalid`) unless the side's spelling is local, a twin exists, and local tip is a strict ancestor of the twin tip (`entry.IsAncestor`, `queuefacts.go:217`). Diverged and ahead never write.
- Ref checked out in a worktree (`InventoryRef.WorktreePath != ""`): refuse when an operation is in progress there (`WorktreeInProgress`); refuse unless that worktree's HEAD is the ref (`WorktreeHead`); run `git merge --ff-only <twinRef>` in that worktree (`gitops.MergeFFOnlyArgs`, `internal/gitops/pull.go:6`). git itself refuses when local changes would be overwritten; its message returns as the error.
- Not checked out: `git update-ref refs/heads/<b> <twinTip> <localTip>` (old-value check, atomic against a concurrent move).
- Under `b.repoMutex`; `invalidateAfterWrite`; `notifyBoard()`.
- The base checked out in the main checkout (local `main`) is updated there; tooltip names the path.

D6. Change request base hint (PR-style target check), frontend only: when the board's change request for the branch (`useChangeRequests`, `frontend/src/ade/v2/readQueries.ts:30`, `branches[branchId]`) is open and `baseRef` is set and differs from the review base's short name, show a warn badge with a hint to change the base on the board. No auto retarget: the base rule stays one rule (D2), and a locked git-ui mount has no retarget seam.

D7. UI: new `AdeReviewSync.vue` in the title bar right after `ade-review-base`, before the uncommitted badge. shadcn-vue `Button`, `Badge`, `Tooltip`; `TooltipIconButton`; Tailwind classes only; `<script setup lang="ts">`.
- Fetch: icon button (`codicon` `refresh`, as the repo chip) always shown when `remote !== ''`; tooltip `Fetch {remote}` plus last fetched age (`useRelativeTime`) or never fetched. Pending: button `pending`, label `common.fetching.loading`. testid `ade-review-sync-fetch`.
- Branch `behind`: labelled button `Update branch · {count} behind` (variant `title`, size `title-labelled`), tooltip names local ref, twin and worktree path when set. testid `ade-review-sync-update-branch`.
- Base `behind` (local base only): `Update base · {count} behind`, testid `ade-review-sync-update-base`.
- `ahead`: info badge `{count} not pushed` (branch side only; base ahead is rare and harmless). `diverged`: warn badge `Diverged` with tooltip naming both refs and saying the review does not change them. testids `ade-review-sync-branch-state`, `ade-review-sync-base-state` carrying `data-state`.
- Remote base: no badge; base label tooltip says it compares with `{base}` as of the last fetch.
- PR base mismatch (D6): warn badge `{short} targets {prBase}`, testid `ade-review-sync-pr-base`.
- Error: one inline `span` (`text-tone-red`, truncate, testid `ade-review-sync-error`) with the `RemoteOpError.message` or thrown error text; cleared on the next success or action start.

D8. Frontend state: server state only, so TanStack Query, no Pinia store (nothing shared client-side beyond the query). `useReviewSync(target)` in `frontend/src/ade/v2/review/useReviewSync.ts`:

## 3. Wire shape

Go `internal/bridge/adewire/wire.go` (next to `ReviewWorkingStamp`, around line 1247) and TS `frontend/src/ade/v2/wire.ts` (next to `ReviewWorkingStamp`, around line 928):

```go
// RefSync is one ref of a review against its remote twin. Counts are local refs as of the last fetch.
type RefSync struct {
	Name       string `json:"name"`       // spelling the review uses: feat/x or origin/feat/x
	Short      string `json:"short"`      // branch name without remote
	Local      bool   `json:"local"`
	Twin       string `json:"twin"`       // twin spelling, "" when none
	Ahead      int    `json:"ahead"`
	Behind     int    `json:"behind"`
	State      string `json:"state"`      // current | behind | ahead | diverged | remote | noRemote
	Worktree   string `json:"worktree"`   // where Name is checked out, "" when nowhere
}

type ReviewSync struct {
	Remote      string  `json:"remote"`      // default remote, "" when none
	LastFetchAt *int64  `json:"lastFetchAt"`
	Branch      RefSync `json:"branch"`
	Base        RefSync `json:"base"`
}

type ReviewUpdateLocalArgs struct {
	BranchID string `json:"branchId"`
	Side     string `json:"side"` // branch | base
}

// ReviewFetchResult carries a failed fetch's error; nil on success.
type ReviewFetchResult struct {
	Error *RemoteOpError `json:"error"`
}
```

`ReviewSync` args reuse `BranchArgs`; `ReviewFetch` takes `BranchArgs`; `ReviewUpdateLocal` returns `ReviewSync` (fresh facts).

## 8. Out of scope

- Git sidebar review (`RepoReviewView.vue`) base resolution.
- Updating a branch onto its base (GitHub "Update branch"); ADE rebase actions own that.
- Fork change-request branches with no upstream: twin none, state `noRemote`, no Update.
- Retargeting a locked git-ui mount to another base spelling.
