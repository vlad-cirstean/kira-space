## Decisions

1. Shared file layout. `repos/<name>.yaml` in the shared repo, file name free (readable, suggested
   `<host>-<owner>-<repo>.yaml`). Binding key is the `origin` key, normalized; same keyed-by pattern as
   local `path`. Not a stem derived from the URL: a normalized key with `/` and dots maps lossily to a
   file name and two spellings of one URL would split. Two shared files with one normalized origin: the
   first by name applies; each later one is a blocked row (`gate.duplicateOrigin`).

   ```yaml
   origin: https://github.com/acme/app.git
   worktree:
     prepare_script: bun install
     prepare_timeout: 15m
   integration_branches: [develop]
   environments:
     - name: staging
       deployed_sha_script: curl -fsS https://staging.example.com/version
   review:
     base_candidates: [main, develop]
   ```

   Allowed keys: `origin` (required), `worktree.prepare_script`, `worktree.prepare_run`,
   `worktree.prepare_timeout`, `integration_branches`, `environments` (`name`, `deployed_sha_script`,
   `deployed_sha_run`), `review.base_candidates`. Any other key (`path`, `nickname`, `worktree.base_path`,
   `graph`, `stash`, `pull`, `git_host`, `checkout`, unknown) blocks the file. Key set exactly as the SPEC
   narrows it; no change.

2. Origin normalization: reuse, do not write a second one. Move `memory.NormalizeRemote` and its test to
   new package `internal/gitremote` as `Key(raw string) (string, bool)`; `memory.DetectProject` calls it.
   configsync and repocfg import `gitremote`, not `memory` (memory pulls the embedding stack; layering).
   Check `internal/layeringtest` for a rule list that needs the new package.

3. Local repo identity. Targets are registered code repos (`code_repos`, hidden included), keyed by
   `RepoID` (= repocfg `path` key). Origin read by configsync itself: `git -C <RepoID> remote get-url --all
   origin` through `gitclient.Run` (same runner, `GitPath`, `ReadOnly`). Exit non-zero: no origin. Every
   listed URL must give the same `gitremote.Key`:
   - no remote `origin`, or its single URL does not normalize (local path, file URL): no origin, never a
     target;
   - several URLs with different keys, or any URL that does not normalize next to others: several
     origins, never a target. When one of its keys matches a shared file, list one blocked row for it
     (`gate.repoOrigins`) so the user sees why it does not sync.
   - Other remote names (`upstream` in a fork setup) are ignored: identity is `origin` only. Rationale:
     forks keep `origin` plus `upstream`; refusing every repo with two remotes would make the feature
     useless.
   - Raw URLs never leave configsync: rows, errors and logs carry the normalized key only (a URL can
     hold a token in its userinfo). No read of git credential config (G5).
   A local repo file whose path matches no registered repo is never a target. A registered repo with no
   file becomes one on its first take (file name from repocfg, decision 8).

4. Merge mode: entry-level `combined` only. Modes for `repos`: `local`, `combined`; default `combined`.
   No file-level `shared`: the local file carries local keys and a different file name, so a whole-file
   take is impossible. Entries (id: value):
   - `worktree/prepare`: `{prepare_script?, prepare_run?}` as one unit, absent when neither. One unit
     because the two keys are exclusive (`prepareExclusiveRule`); separate units could merge into both.
   - `worktree/prepare_timeout`
   - `integration_branches` (whole list)
   - `environments/<name>` per environment (names are unique and slash-free per schema pattern)
   - `review/base_candidates` (whole list)
   Local side reads the same ids from the local file and ignores every local key. Three-way `decide`
   unchanged.

5. Many and late targets. One shared file maps to every target with its origin (two clones: two
   targets). Each target is planned and merged on its own. The merge base is per target, not per shared
   file, so a repo registered later has no base and gets `add` rows on the next refresh (a shared value
   equal to a local value is no change; a different local value is a conflict). Base layout under
   `.sync/base/repos/`:
   - `<sharedfile>/origin`: the normalized key (text), written while the shared file exists. A shared
     file deleted upstream finds its targets through it, since its content is gone.
   - `<sharedfile>/<sha256(RepoID)[:16]>.entries.json`: the entry map as last pulled for that target.
     Hash of the path, not the local file name: survives a file rename and exists before the file does.
   - Stage drops target bases whose repo is gone or no longer matches the origin, and the shared dir when
     it holds no target base and the shared file is gone.
   A target with an invalid local file: one blocked row per target (`gate.localInvalid`, existing key),
   base untouched.

6. Refresh triggers. A plan is built on fetch, settings change, apply and Preview (all existing). New:
   repo import refreshes too. `Service.RefreshAsync()` runs `refreshLocked` under `opMu` in a goroutine,
   then `emit`; called from both `OnReposChanged` closures in appwire. A `git remote set-url` is seen at the
   next refresh (Known open item).

7. Rows and ids.
   - Row gains `Target string json:"target,omitempty"` (local file name, the created name for a new file),
     `Repo string json:"repo,omitempty"` (target RepoID) and `Origin string json:"origin,omitempty"`
     (normalized key). `omitempty` keeps the existing `config-sync.json` contract byte-identical.
   - `Row.File` stays the shared file name, so `unitKey(row)` and `SetDeactivated(module, file#entry)`
     work unchanged.
   - Id: `repos/<shared>#<entry>@<target>`; a file-level blocked row `repos/<shared>` (gate failure,
     duplicate origin) or `repos/<shared>@<target>` (local invalid, several origins).
   - New kind `unmatched`: a valid shared file whose origin matches no target. One row, `Origin` set, not
     actionable, shown in the review (muted badge "No local repo"). Counted as a unit.
   - `FileDiff.File` is the target file name for repos; the review matches the diff by
     `row.target ?? row.file`.

8. Gate and trust.
   - Shared file gate before any entry split: YAML parse, `Options.Repos.CheckShared(data)` (decision
     9), `credentialProblem` (existing: catches `ghp_...`, URI passwords, `token:` keys anywhere,
     including inside scripts). Failure: one blocked row, never offered.
   - Per entry: `gateEntries` (existing) on top.
   - Merged local text validated with the full local decoder `Options.Repos.CheckLocal(file, text)`
     through `mergedProblem` (max 10 environments after merge, exclusive prepare keys).
   - Runs-commands badge: `entryRunsCommands` true for `repos` `worktree/prepare` and
     `environments/*` (inline script or Run script reference both start a process). Same review and
     default as runs, steps, workflows: nothing applies without Pull in the review; conflict default is
     Keep mine.
   - Sizes: shared file `configfs.MaxFileBytes` (existing `readTree` cap); schema limits from repocfg
     (64 KiB prepare, 4 KiB env script, 10 branches, 10 environments, script ref name).
   - `origin` must normalize and hold no userinfo password (`originRule`, repocfg). A token-as-username
     URL is caught by the credential scan.
   - Unset secrets: repo files hold no `${secret:}` reference (secret params come from the script's
     saved values only); `SecretUnset` stays agent-only.
   - `patchTouchesRestrictedField` unchanged: the dialog still cannot set the prepare script.

9. `Validate` seam through repocfg. New `configsync.RepoFiles` interface in `Options.Repos`, implemented by
   an appwire adapter over `*repocfg.Store` (configsync never imports repocfg; adapter keeps the package
   graph one-way):

   ```go
   type RepoFiles interface {
       Targets() []RepoTarget                          // registered repos: RepoID, local File ("" none), LocalProblem bool
       CheckShared(data []byte) string                 // "" clean
       CheckLocal(file string, data []byte) string     // full local decode of a merged file
       NewFile(repoID string, taken map[string]bool) (file string, text []byte, err error)
       Reload()                                        // synchronous, after apply
   }
   ```

   repocfg side (new `repocfg/shared.go`):
   - `SharedFile` struct (`Origin`, `IntegrationBranches`, `Environments`, `Worktree *SharedWorktree`
     {`PrepareScript`, `PrepareRun`, `PrepareTimeout`}, `Review *Review`).
   - `assembleSharedSchema(hosts)` derived from the assembled base schema in `schema.go`: drop `path`,
     `nickname`, `graph`, `stash`, `pull`, `git_host`, `checkout`, `worktree.base_path`; add required
     `origin` string (max 2048). No second hand-written schema, so limits cannot drift.
   - Decoder `configfs.YAMLSchema[SharedFile](sharedSchema, sharedRules()...)`: `originRule` plus the
     existing integration, environments, prepare-exclusive, script-ref and timeout rules run on
     `sf.file()` (a `File` holding the shared leaves). Built once in `New`, stored on `Store`.
   - `Store.CheckShared(data)`, `Store.CheckLocal(file, data)` (`s.folder.Decode`), `Store.NewFile(repoID,
     taken)` (`freeName` that skips `taken`, plus `RenderYAML(File{Path}, header)`), `Store.SharedText(repoID,
     origin)` (decision 11).
   - Two new targets with one slug in one plan get distinct names through `taken`.

10. Apply. Repos file plans reuse the journaled commit: `fp.file` is the target file, so backup, journal,
   rollback, `takeSession` hash check and `Options.Write` work as is. Entry edits through
   `configfs.EditYAML` on the local text (comments, key order and local keys stay):
   - `worktree/prepare`: set `prepare_script` or `prepare_run`, unset the other; both unset when absent.
   - `prepare_timeout`, `integration_branches`, `review/base_candidates`: set or unset (empty parent
     pruned by `unsetNode`).
   - `environments/<name>`: rebuild the list from local order, replace by name, append new ones in shared
     order, drop removed; set the whole list, unset when empty. Comments inside the list are lost (list
     replaced whole, same as the P514 form rule; Known open item).
   - New file: start from `NewFile` text, then the edits.
   - `takeSession` also re-reads targets (`Targets()` plus origins) and compares a fingerprint
     (`RepoID`, file, key) stored in the plan: mismatch is `E_CONFLICT`, nothing written.
   - After `commit` succeeds and before `refreshLocked`: `Options.Repos.Reload()` when any repos file was
     written. That runs `Store.Reload`, whose `OnChange` already calls `TaskBoard.RepoConfigChanged` (prepare
     script, environments, integration targets) and the git router, and `OnReload` broadcasts
     `kira:repoConfig:changed`. Synchronous, so the board sees the new config before Apply returns; the
     later watcher reload is a no-op.

11. Producing a shared file. Pull-only sync means the author writes the shared file. New
   `ConfigSyncService.RepoSharedText({path})` returns YAML: `origin: https://<key>` (normalized key as
   https URL: carries no userinfo, and `gitremote.Key` maps it back to the same key) plus the repo's shared
   keys from its local file (no local key). Repo with no or several origins: `E_BAD_REQUEST`
   (`repoSync.noOrigin`). UI: repo settings pane button "Copy for shared config" (TanStack `useMutation`
   over the call, `useCopy` for the clipboard).

12. Deactivation per shared unit: `<shared>.yaml#<entry>` (existing `SetDeactivated`, no change). It holds
   for every target of that origin. No per-target deactivation (Known open item). Settings table counts
   repos units like other modules.

13. Settings and docs. `syncModules` gains `repos` (last). `sync.schema.json` enums gain `repos`. Settings
   rule doc: "Only agent, prompts and repos may be combined; repos is never shared whole-file." Manifest
   refusal and its catalog key removed. `repos_intro.md` gains a bullet: a shared config repository can
   set the shared keys by origin after review in Shared config; nothing is read from inside a code
   repository.
