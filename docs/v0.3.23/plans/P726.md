## Reading

User, on the P719 API card shots: "that's a variable length string before the input making each
input miss aligned. Also add a small separator between what is about the request and the variables
section so that's easier on the eye. And i want the same separation with pre after scripts too. I
see it as the current box that's inside the dialog but like 3 or 4 of them".

  `rounded-kira-sm border border-border p-3 flex flex-col gap-2`, testid `approval-body`. It wraps
  `def.content` for every kind (Studio, Space, phone). Comment in `registry.ts`: "`content` in a
  framed box".

  - `DbQueryBody.vue` (`db.query`), `DbExemptionBody.vue` (`db.exemption`): `KeptVariablesPanel`,

  - `KubeReadBody.vue` (`kube.read`, P718): `KeptVariablesPanel`, `KubeRequestLine` or plain

  - Result reviews `ApiResponseBody.vue`, `DbResponseBody.vue`, `KubeResponseBody.vue`
    (`api.response`, `db.response`, `kube.response`): `QueryState` then shared `ResultReview.vue`
    (tabs `TabbedContent`, then slots `script`, `mask`, `after`). Slot `script` holds a
    `JsScriptBlock`, `after` a `StagedKeepList` (Will keep). `DbResponseBody` without a script
    renders `PendingResponse` alone. `KubeResponseBody` has a `FieldError` path for a failed read.

  `SecretInput min-w-48 flex-1`, `SecondaryTabs variant="choice"`. Label width varies, so field x
  varies; choice width varies with `keepMinutes` ("Keep 5 min" vs "Keep 60 min"), so field right edge

  is field + choice with no label (field `aria-label`). Input states are only `needed` and `stored`
  (`apiInputSchema`).
- `Disclosure.vue` = shadcn `Collapsible` root (takes `class`) with direct children
  `[data-slot=collapsible-trigger]` and `[data-slot=collapsible-content]`.
- Tailwind 4.3.3: `grid-cols-subgrid` available; Electron Chromium supports subgrid.

Chosen reading (stated, not asked):

1. Value rows align on one grid: label column as wide as the longest label (capped at `max-w-48`,
   12rem; longer labels wrap), field column, choice column. Field left and right edges and choice
   left edges line up for 1 to 4 rows, any label lengths, mixed keep minutes. An opened stored row
   puts its field and choice in the same columns, label cell empty (trigger above names it).
2. Card body becomes several stacked boxes, each today's box style, `gap-2` (8px) apart. Order:
   - API request: kept, request (line, body, headers, variables), values, prepare, transform.
     Values move up from last to right after the request (user's order: request, then variables,
     then pre and after scripts).
   - DB query and exemption: kept, statement (statement + Parameters), result script.
   - Kube read: kept, request (kubectl line or plain statement), prepare, transform.
   - Result reviews: result (tabs + masking/footnote notes), script, Will keep. Loading and error
     state of the held-result query sits in one box. Notes move from between script and Will keep
     into the result box, under the views (they describe the result).
   - A box renders only when its section has content (the section's existing `v-if` moves to the box).
3. Titles: existing headings stay as each box's first line. Request, values and result boxes stay
   untitled. No new copy, no catalog keys.
4. Verdict row, warnings list (`approval-signals`), Details expander, footer stay outside boxes.
5. One shared component `ApprovalBox`; the card's own frame becomes it. Opt-in per kind via registry
   flag `sections`, so unopted kinds (script run, proof review, Space, phone) render byte-identical.

Gap default 8px (`gap-2`): matches the box's inner `gap-2`, smaller than the card's `gap-3` between
target, verdict and body, so boxes read as one group.

## Design

### `packages/workbench/src/approvals/ApprovalBox.vue` (new)

```vue
<script setup lang="ts">
// One framed section of an approval card. The card frames a whole body in one; a kind with
// `sections` frames each of its sections in its own.
withDefaults(defineProps<{ testid?: string }>(), { testid: undefined });
</script>

<template>
  <section
    class="flex min-w-0 flex-col gap-2 rounded-kira-sm border border-border p-3"
    data-approval-box
    :data-testid="testid"
  >
    <slot />
  </section>
</template>
```

Classes copied verbatim from the card's current box, so the unopted path renders the same pixels.
`<section>` vs today's `<div>`: no layout difference; if a visual or a11y spec objects, use `div`.

### `registry.ts`

- `ApprovalKindDef.sections?: boolean`: "content draws its own `ApprovalBox` per section; the card
  adds no frame". Update the interface doc comment ("`content` in a framed box, or in its own boxes
  with `sections`").

### `ApprovalItemCard.vue`

Replace the body `div`:

```vue
<template v-if="def">
  <ApprovalBox v-if="bodyFailed || !def.sections" testid="approval-body">
    <p v-if="bodyFailed" …>…</p>
    <component :is="def.content" v-else … />
  </ApprovalBox>
  <div v-else class="flex min-w-0 flex-col gap-2" data-testid="approval-body" data-sections>
    <component :is="def.content" :item="item" @options="…" />
  </div>
</template>
```

`approval-body` keeps its testid and full width in both paths (`dbmcp-approval.spec.ts:115` measures
its right edge). A body that throws while sectioned falls back to one box with the unreadable line.

### `UserInputsPanel.vue`: aligned rows

- Root `section` (testid `api-approval-inputs`, `v-if` unchanged):
  `grid grid-cols-[minmax(0,max-content)_minmax(12rem,1fr)_max-content] items-center gap-x-2 gap-y-2`.
- Needed row `div` (testid `api-approval-input-<name>`): `col-span-full grid grid-cols-subgrid
  items-center`. A real box, so row locators and `toBeVisible` keep working (no `display: contents`).
  Children: `FieldLabel class="max-w-48 break-words"`, `SecretInput class="min-w-0"` (drop
  `min-w-48 flex-1`; the track sets width), `SecondaryTabs`.
- Stored row: `Disclosure` with a `const STORED_ROW` class string in the script, commented ("trigger
  spans the row; content joins the panel grid so its field lines up"):
  `col-span-full grid grid-cols-subgrid [&>[data-slot=collapsible-trigger]]:col-span-full
  [&>[data-slot=collapsible-content]]:col-span-full [&>[data-slot=collapsible-content]]:grid
  [&>[data-slot=collapsible-content]]:grid-cols-subgrid
  [&>[data-slot=collapsible-content]]:items-center`. Content children: `<span aria-hidden="true" />`
  (label cell), `SecretInput` (keeps `aria-label`), `SecondaryTabs`. Drop the inner flex `div`.
  The descendant selector outranks `CollapsibleContent`'s own `flex` class (specificity 0,2,0 vs
  0,1,0); verify computed `display: grid` in the spec, not by eye.
- Declined: a fixed-width label column. It would waste space with short labels and still leave
  field right edges ragged when keep minutes differ. Declined: extending `Disclosure` with
  `contentClass`/`triggerClass` props for one caller; the scoped arbitrary variants stay local.
- Update top comment: rows share one grid so fields line up.
