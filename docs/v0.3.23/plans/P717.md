## Audit: the flow today

1. Agent declares. `api_request` takes `inputs: [{name, label}]`, at most 4
   (`dbmcp/api_tools.go:75`, `agentapi/inputs.go:15-25`). Each name must appear as `{{kept.<name>}}`
   in the request or be read by a script's literal `kept.get` (`agentapi/kept.go:152-177`).
2. Plan. `checkKept` looks each name up in the kept store (`kept.go:180`). No live entry: state
   `needed`, a stand-in entry (`pendingEntry`, `inputs.go:155`). A live user entry of the same
   origin: state `stored`, reused. A script entry or another origin refuses (`judgeInput`,
   `inputs.go:117`). `checkRoom` refuses when the needed inputs would overflow the scope's 64 entries.
3. Prompt. A needed input forces the card whatever rules say (`api_tools.go:159-160`). Payload
   `inputs: [{name, label, state, origin, keptId}]`, never a value (`api_inputs.go:47-62`). Card:
   `UserInputsPanel.vue` (a `SecretInput` per needed input; a stored one behind "Enter a new
   value"). Typed text lives in Pinia `approvals.inputs` only (`workbench/state/approvals.ts:15-44`),
   rides the approve answer `options[id].inputs` (`approvalsQueries.ts:54-68`), is dropped on settle.
4. Answer. `checkAnswer` trims, caps 8 KiB, one line, required ones present (`approval.go:446-490`)
   into `SuppliedInputs` (byte slices, `Wipe` zeroes them).
5. Storage. `settleInputs` calls `keepInputs` (`api_inputs.go:112-145`): every typed value is
   `Store.Put` as `{Secret: true, Source.Kind: user, Origin: request origin}`. TTL fixed at Put:
   `dbMcp.keptRetentionMinutes` (default 60, range 5 to 240, `MaxTTL` 240,
   `bridge/keptvars.go:26-36`, `keptvars/store.go:176-185`). Never refreshed by reuse. Then re-plan
   so the plan binds the new entry ids; scripts `rebind` (`api_tools.go:207-232`).
6. Where. Memory only: `keptvars.Store` is an in-process map with an expiry heap; nothing on disk,
   gone on app exit (`keptvars/entry.go:1-4`). The DB holds only the retention setting.
7. Reuse. Later requests in the same kept scope (per Studio session; one shared scope for all
   external clients, `kept_tools.go:33-38`) naming the same input get `stored` and send without
   typing, to the same origin only, until expiry or a clear in Settings, Studio MCP variables.
   A transform can read it (`kept.get`); anything that run keeps is secret, bound to the same origin,
   and expires no later than the source (`kept_script.go:331-358`).
8. Send. `Send` re-plans from the store and inserts values (`agentapi/send.go:37-74`). Mask: every
   live secret kept entry plus this request's values in all spellings (`newMask`,
   `secretKeptTexts`, `kept.go:468`).
9. What the agent sees. Never a value. Result carries `inputs: [{name, status: supplied | replaced |
   reused, expiresInSeconds}]` (`agentapi/types.go:149-162`, `api_script.go:362-389`). An echo shows
   `{{kept.<name>}}`. `list_kept_variables` lists the entry (name, type, source, expiry).
10. Logs and records. Audit row: agent args JSON (no values; values never pass through the agent)
    and refusal text, which never quotes a value (`dbmcp/audit.go`, `dbaudit/recorder.go:168-236`).
    Approval rows are raised before the user types. Op log command is the template URL. Wails binding
    log drops args and results (`logging.WailsLogger`). The "Kept by" source of the stored entry:
    `api_request`, template `METHOD URL`, caller (`kept_script.go:446-453`). Transcripts hold the tool
    result, which is masked.

What one-time changes: step 5 skips `Put`, so steps 6-7 vanish for that value (no entry, no
`list_kept_variables` row, no Settings row, no "Kept by" record, no reuse, next request asks again);
step 8 still masks it; step 9 reports status `once` with no expiry; step 7's derived keep is refused.
The value lives in process memory from the answer until the send and transform end, then its bytes
are zeroed.

## Recommendation

Per typed value, the user picks in the card: "Use once" or "Keep N min". Default "Use once" unless the
agent declares the input with `reuse: true` (it plans more requests with the same value), which
preselects Keep. The user always decides; the agent only suggests.

Why default once: every input is a secret (`Secret: true` today, no exception); the user's ask is
not to hold a value longer than needed; a needed input already forces the card, so the cost of a
wrong default is one more prompt, never a leak or a broken request. Why the agent hint: a chain of
several calls with the same API key would otherwise prompt on every call; the agent knows that plan,
the user does not see it from one card. Why not agent only: the user owns the value's lifetime.

## Design: backend

One-time is guaranteed by construction: the value never enters the store, so no store reader (list,
reveal, Settings, later plans, other cards, `watchKept`) can see it.

1. Answer. `answerOptions` gains `inputModes: {name: "once" | "keep"}` (`approval.go:139-143`,
   `DisallowUnknownFields` stays). `checkAnswer` validates: a mode only for an input the item asks
   for and that has a typed value; unknown mode is a contract error. Absent mode is `once` (safe
   side; the card always sends one). `SuppliedInputs` becomes `map[string]Supplied{Value []byte;
   Once bool}`; `Take` and `Wipe` keep their contracts.
2. Overlay. `agentapi.Input` gains `Once map[string]keptvars.Entry` (`json:"-"`), built by
   `keepInputs` for each once value: `{Name, Type "string", Secret true, Source.Kind user, Origin
   plan.Origin, ID "once_"+ids.NewID(), Value json string}`, `ExpiresAt` zero. `Service.lookupKept`
   reads `in.Once` before the store. `judgeInput` turns an overlay entry into new state
   `InputOnce` ("once") with `KeptID` the overlay id. `MissingInputs` counts only `needed`, so
   `Send` (which re-plans with the same `in`) passes; `checkKeptCurrent` compares the overlay id,
   stable for the call. `apply` puts the value into `keptValues` (secret), so the resolver inserts it
   and `secretKeptTexts` masks it in every spelling. `checkRoom` skips once values after the answer
   (it runs at plan time before the choice, so it stays conservative there).
3. Keep path. `keepInputs` Puts only `keep` values (unchanged code path). A stored input replaced
   with a once value: the held entry is cleared (`Store.Clear(id)`), then the overlay is used
   (open question 2). Statuses: `once` with `expiresInSeconds` 0; `fillReused` skips it.
4. Scripts. `keptRun` gets the overlay on `rebind`; `addUse` and `get` read it before the store.
   Reading it notes secret forms (mask) and sets `onceRead`. `readsSecret` is true for it, so the
   response review is forced as for any user value. `commit`: when `onceRead`, every staged value
   fails with `errDerivedOnce` ("the script read a value the user gave for this request only, so
   nothing derived from it can be kept") and is reported in `keptNotSaved`. `stagedViews` marks
   them (`HeldKeep.Blocked`) so the review card's "Will keep" block says they will not be kept.
   Prepare already refuses secret reads (`kept_script.go:204-207`), unchanged.
5. Wipe. `apiRequest` zeroes the overlay bytes right after the send and the transform return
   (before any response review wait) and on every earlier exit (`defer`). `keptValues` share the
   same slices, so they zero too. Go strings made for masking, header building and JSON decoding
   cannot be zeroed: same documented bound as today (process memory, not logs).
6. What the agent sees: `inputs: [{name, status: "once", expiresInSeconds: 0}]`; no
   `list_kept_variables` row. Prompt text (`internal/llmprompts/registry.go:897,933-935`): inputs
   may be one-time by the user's choice; a later request that needs it declares it again and the
   user is asked again; `reuse: true` asks the card to suggest keeping. New arg doc `inputs.reuse`.
7. Not recorded anywhere: approval payload (built at raise, before the answer, `apiItemParts`),
   audit rows, op log (template text), "Kept by" source (no entry), Settings list, transcripts (masked
   result), Wails log (args dropped). Each asserted in the flow test.
8. Payload. `apiInputPayload` gains `mode` (the suggested choice: `keep` when the declaration says
   `reuse`, else `once`) and `keepMinutes` (current retention, read from the store's retention func;
   new `keptvars.Store.Retention()` returning `ttlFor(Put{})`). Zod `apiInputSchema` mirrors both.

Settings: no new setting. "Keep" uses the existing `dbMcp.keptRetentionMinutes`; the card names it
("Keep 60 min"). Open question 3 asks whether the default choice needs a setting.

## Open questions (defaults in bold)

1. Who picks: user per input in the card, agent only suggests via `reuse`. **Both, user decides,
   default once without the hint.**
2. Replacing a stored value with a once value: clear the held one, or leave it for later requests?
   **Clear it**: "Enter a new value" means the held one is stale; leaving it would send the old value
   on the next request without asking.
3. A setting for the default choice (Settings, Studio MCP variables: "Typed values: use once / keep")?
   **No setting**; the agent hint covers chains. Add one later if the extra prompts annoy.
4. Remember the user's last choice per input name for the session? **No**: the card's default stays
   predictable.
5. "Variables in the api mcp": does it also mean the API module's `{{name}}` environment variables?
   From code: those are values the user saved in collection and environment files
   (`apifiles`, secrets in the OS secret store), read by name, persisted until edited, never typed
   in the prompt and with no 30 or 60 min lifetime. The only prompt-typed, time-limited values are
   `inputs` (kept for `keptRetentionMinutes`). **Only `inputs`**; environment variable editing is P718.
6. Should the agent learn the choice? It sees status `once` (so it knows to declare the input again).
   **Yes, status only**, as today's `supplied`/`reused`.
