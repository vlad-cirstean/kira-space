# P717: result review for every MCP tool that returns data

Design phase. Base: `chapter/v0.3.23` at `3f309d409` (P719, P723, P724 landed). P716 model A chosen
(`plans/P716-design.md` on `stream/p716`): no chain UI, kept variables plain or secret, agent makes
the follow-up request. Paths relative to `apps/kira-space/` unless rooted.

Discovery: `codegraph_explore` (index in `/home/user/kira-space` is stale), every fact below re-read
in worktree `/home/user/kira-space-v0.3.23-p717`.

## Recommendation

1. Review fits every tool that returns data from a user's system: `run_query`, `browse_table`,
   `api_request` (have it today), `kube_list_resources`, `kube_describe`, `kube_pod_logs` (new).
2. Metadata and app-state tools stay unreviewed (audit below argues each).
3. Kube gets the same three levers as DB and API: app default, per-cluster setting, per-call
   "Review result" tick on the `kube.read` card.
4. One held-result path in Go (`held.go`): one hold function, one refusal template, same caps and
   wait. DB and API texts stay byte-identical, so no contract churn.
5. One review component: `ResultReview.vue` hosts every view tab; the P715 data-review table moves
   into `ReviewTable.vue` so kube list rows reuse it.

## Design

### Which tools hold

`kube_list_resources`, `kube_describe`, `kube_pod_logs` join `run_query`, `browse_table`,
`api_request`. Everything else in the audit stays as is.

### Settings and defaults

Same shape as DB and API: app default, per-target override, per-call tick. Defaults off, as today.

- App: new `dbMcp.kubeReviewResponses` (bool, default false) in `DbMcpSettings` and `DbMcpPatch`.
  No migration: settings JSON decodes a missing field as false.
- Cluster: `McpSettings.Review` `inherit | review | send`, default `inherit`. One value covers list,
  describe and logs (open question 4). Migration `0105_p717_kube_mcp_review.sql`:
  `ALTER TABLE kube_clusters ADD COLUMN mcp_review TEXT NOT NULL DEFAULT 'inherit'`. New column only;
  no legacy path (CLAUDE.md minor bump rule).
- Per call: `kube.read` item gets `OfferReview` and `ReviewOn`; card footer shows "Review result".
  Under approval `allow` there is no card, so only settings hold (same as DB `allow`).
- `kube_list_clusters` reports `reviewResults: bool` per cluster, like DB and API listings.

Studio settings read:

- Settings, Studio MCP, Server pane: one "Review results before the AI gets them" `FieldSet` with two
  switches, Databases (existing `previewResponses`, moved under the set) and Kubernetes (new). API's
  switch stays in the API pane beside environment overrides.
- Cluster MCP dialog (`ClusterMcpDialog.vue`): "Review results" field below Approval, reusing
  `studio/components/ReviewChoiceField.vue` (inherit shows the app value, as connections do).

### Backend: one held-result path

New `internal/dbmcp/held.go`:

```go
// heldCall names a call whose result is held, for the one refusal template.
type heldCall struct {
	call   string // `this query on "shop"`, `GET api.shop`, `list pods in "prod-eu"`
	result string // "result" | "response"
	ran    string // "it ran" | "the request was sent"
	none   string // "no rows" | "no response" | "no data"
	redo   string // "rerun" | "resend"
	read   bool   // reads get no "stays" suffix
	narrow string // too-large hint for reads
}
func (s *Server) holdResult(ctx context.Context, req ApprovalRequest, held ApprovalResponse, c heldCall, recheck func() string) string
func heldRefusalText(o ApprovalOutcome, c heldCall, size int) string
```

- `holdResult` sets `Stage: ApprovalStageResponse`, calls `Approvals.Request`, runs `recheck` on
  approve, else returns `heldRefusalText`. Text never logged, as today.
- DB `holdResponse` (`tools.go`) and API `reviewAPI` (`api_review.go`) build `heldCall` and call it.
  Delete `heldRefusal` and `apiHeldRefusal`; `ranSuffix`/`apiSentSuffix` fold into one suffix
  helper driven by `read`, `redo`. Proof of byte-identical texts: existing dbmcp unit tests and the
  `dbmcp-review-*`, `e2e-held-writes-*` contracts pass unchanged.
- Kube: `kubeRun` (`kube_tools.go:118`) switches to `RequestChoice` with `OfferReview: true`,
  `ReviewOn: s.kubeReviewFor(c)`; after `read`, when `kubeReviewFor(c) || choice.ReviewResult` and
  the op is list, describe or logs, marshal the result once (same bytes `jsonResult` sends) into
  `ApprovalResponse` and `holdResult` with `Cluster` set. Recheck: `resolveCluster` still finds it
  exposed. `kubeReviewFor` reuses `reviewResolver` with the kube app leaf (resolver takes the leaf
  func instead of hard-wiring `PreviewResponses`).
- Kind: `approvals.KindKubeResponse = "kube.response"` (`internal/approvals/queue.go`);
  `ApprovalRequest.subject` maps Cluster plus response stage to it (`approval.go:351`); add to the
  kind list (`approval.go:406`); `itemOf` case with `kubeResponsePayload{context, server,
  namespace, operation, statement, isError, bytes, requested}` (`approval_item.go:168`);
  `promptTitle` kube response title (`backend.prompt.dbMcpKubeResponse.title`).
- Bridge: `PendingResponse` is already generic; no change.
- Config: `dbmcp.Config.KubeReviewResponses func() bool` (`server.go:159` next to
  `PreviewResponses`), wired in `internal/bridge/dbmcp.go:150`.
- Kube store: `types.go` `Review`, `store.go`/`bound.go`/`service.go` validate the enum in `SetMcp`,
  `storage/repos/kube_clusters.go` column, `internal/kiraschema/kiraschema_gen.go` regenerated by
  `TestKiraSchemaGenerated`.
- Agent text (`internal/llmprompts/registry.go`): kube list, describe and logs descriptions say the
  user may review the result; a withheld result carries no data, never retry for it.
  `kube_list_clusters` names `reviewResults`. Budgets `testdata/budget.tsv`, goldens.

Transform script (scope 3): DB and API already show "Agent gets" plus raw (`api-review-raw`,
`db-review-view-raw`). Kube has no script until P718; P718 fills the same `ResultReview` slots, no
kube-only path. P717 lays the slots so P718 only adds data.

### Frontend: one review UX

- `ResultReview.vue` becomes the one review frame: prop `views: { value, label, testid }[]`; one
  `TabbedContent`; slot `view-<value>` per tab; scripted adds "Agent gets" first, raw views after;
  `#script`, `#after` (kept rows), new `#mask` (masking note). DB and API bodies move onto it. DB's
  inner Table / Raw tabs (`PendingResponse.vue`) become `views` of the frame: same `TabbedContent`,
  same look.
- `ReviewTable.vue` (new): the P715 grid lifted out of `PendingResponse.vue` (all rows, click
  expand, `ResizeHandle`, cell popover with Copy, `useVirtualRows`, `useResizeObserver`). Props
  `columns`, `rows`, `footnote`, `testid`. `PendingResponse.vue` keeps DB parsing and mask lock icons
  and renders `ReviewTable`. Test ids stay (`db-mcp-preview-*` passed as prefix).
- `ReviewLog.vue` (new): monospace lines, timestamp column when present, virtualized through
  `useVirtualRows`, Tailwind only.
- `KubeResponseBody.vue` (new), views by operation:
  - list: Table (`ReviewTable`, columns from result) / JSON (`FlushEditor`).
  - describe: Manifest (`FlushEditor` yaml) / JSON. `#mask` note "Secret values are redacted by Kira"
    when `description.kind === 'Secret'`; none otherwise.
  - logs: Log (`ReviewLog`) / JSON. Footnote "truncated" when `truncated`.
  Bytes come from `usePendingResponse` (TanStack Query), never the payload.
- `kinds.ts`: `kube.read` gets `footerAction: ReviewResultOption`; new `kube.response` kind
  (content `KubeResponseBody`, `operation` "Result", `where` as `kube.read`, verdict
  `resultVerdict(true, …)`, labels Send to AI / Withhold). Footer, `ColorLine`, tint-free
  `dialog-approve`/`dialog-deny` Buttons with `shortcut` (`form.submit`, `prompt.deny`) come from
  `ApprovalItemActions.vue` unchanged.
- `ReviewResultOption.vue`: tooltip and test id per family (`kube-approval-review-result`, text
  "On by this cluster's settings").
- `packages/shared/domain/dbmcp.ts`: `kubeReadPayloadSchema` adds `reviewOffered`, `reviewResult`;
  new `kubeResponsePayloadSchema`. `frontend/src/studio/kubernetes/wire.ts`: `KubeMcpSettings.review`.
  `frontend/src/state/settingsDomain.ts`: `kubeReviewResponses`.
- `AdeAuditEntry.vue:63`: `kube.response` subject label.
- No new store: approval state stays in `useApprovalsStore`; settings in the settings store.

### Masking info, uniform

One `#mask` row under the views, `text-kira-sm text-subtle`, only when something is masked:

- DB: existing lock icon per masked column, plus row "Masked columns: a, b".
- API: "Secrets masked: <names>". The held text is masked today, but `api.response` carries no
  names: `apiResponsePayloadOf` (`approval_item.go`) adds `masked: string[]`, the credential and
  secret variable names the plan used, never values.
- Kube: Secret redaction note above.

### P716 model A and P719 one-time values

- No chain UI. Review is per call, like any other queue item (counter, Deny all).
- Kept values a script stages show in `#after` (`StagedKeepList`) with P716 Part 2's Secret/Plain
  badges and staged reveal behind `localauth.Gated` (`RevealStaged`). P717 does not edit those files.
- A script reading a secret kept or one-time value forces review: `readsSecret` (`kept_script.go:170`)
  counts the one-time overlay (entries are secret). One-time values never show in review: the held
  text is masked by the request masker; a derived keep shows "Not kept" (`HeldKeep.Blocked`).
- Kube kept (P718) uses the same `#after` slot.
