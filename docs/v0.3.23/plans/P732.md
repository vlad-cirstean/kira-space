## Decisions (stated, not asked; open ones listed at the end)

1. Script API hard cut, API, SQL, kube alike: globals `plain` and `secret`; no `kira.storeValue`,
   `kira.storeSecret`, `kira.getValue` (they become unknown methods). `kira.parseJSON` stays.
2. Injection: `plain` holds the current plain values of the names the script mentions literally
   (`plain.x`, `plain["x"]`, `plain['x']`, comments and strings included: over-listing is the safe
   side). Unmentioned names are absent, so the card's "Uses" list stays complete, the invariant P678
   kept. `secret` starts empty. Both objects have a null prototype. Values are checked against
   their plan-time entry IDs before the run; a changed or expired one refuses the stage with today's
   text.
3. Diff after a successful run, per stage: plain key new or changed (compact JSON compare) = write;
   plain key deleted = delete of the saved value at commit (only if its entry ID is still the planned
   one, else `notSaved` "changed since the script read it"); every `secret` key = secret write.
   A script cannot delete a secret. Same value rewritten is no write (TTL not refreshed).
4. Refusals (stage fails like a thrown error, through the stage's own failure wording, "Nothing was
   sent/ran/read" as today; for transform the request already went):
   - both kinds: `"x" is written as both plain.x and secret.x; use one.`
   - kind clash with the store: `"x" is saved as a secret; write secret.x or use another name` and the
     plain counterpart (also covers user values, `ErrNameTaken` stays).
   - invalid name: `plain["a-b"] is not a valid name: start with a letter, then letters, digits or _, at most 40.`
   - non-text value: `plain.x is a function; save text, a number, true/false, null, a list or an object.`
     (types: function, symbol, undefined, accessor property).
   - name not in the source: `plain.x is not written literally in the script; write plain.x = … so the user sees it.`
   - local declaration of `plain` or `secret` (any `var/let/const/function/class/param/catch`
     binding, patterns included): engine `KindInput` before the run: `the script declares its own
     "plain"; remove it: plain is Kira's global for saved values.`
   - reading a secret name: before the run, API `"x" is secret; scripts cannot read secrets. Write
     {{secret.x}} in the request.`; SQL/kube `"x" is secret; secrets are used only in api_request, as {{secret.x}}.`
   - more than 16 writes: existing cap text.
5. Prepare writes are allowed (API and kube). They stage in the same `keptRun`, are listed on the
   card, and commit with the transform's writes after the final response; deny drops them. API: a
   staged value is what `{{plain.x}}`/`{{secret.x}}` in this request interpolates (the "same plain and
   secret" decision). Kube args take no templates: kube prepare writes are only saved.
6. Display of prepare writes: `PreparedList` adds one row per write, key `plain.ts` / `secret.sig`,
   value preview, or a masked `••••` with a `Secret` badge for a secret (no reveal on the prompt).
   Request tokens `{{plain.ts}}` that a prepare wrote carry `data-prepared="plain.ts"` and
   `PREPARED_MARK` on top of the saved-variable mark, like changed fields.
7. Templates `{{plain.x}}` and `{{secret.x}}`; the kind must match the entry (`"x" is secret; write
   {{secret.x}}` and vice versa). Typed inputs are secret, so they are written `{{secret.x}}`.
8. Inputs: `inputs` becomes an array of names (`["apiKey"]`), no label; card label = exact name in
   `font-data`. A declared input must appear as `{{secret.name}}` in the request (script reads gone).
9. "Kept" wording retired in every user- and agent-facing text: UI strings, MCP tool name
   `list_kept_variables` -> `list_saved_variables`, tool and arg descriptions, refusal texts, agent
   result fields (`kept` -> `saved`, `keptNotSaved` -> `notSaved`, new `deleted`), docs, op log
   param labels. UI noun: "saved variables"; "Kept for N min" -> "Saved for N min"; review "Will
   keep" -> "Will save". Internal identifiers stay (Go package `keptvars`, `keptRun`, TS
   `studio/kept/*`, i18n key paths, payload JSON field names, contract file names, setting key
   `dbMcp.keptRetentionMinutes`): renaming them is churn no reader sees and the setting needs a
   migration. Open item 1.
10. Formatter: `prettier` (MIT) `standalone` + `plugins/babel` + `plugins/estree`, exact current 3.x
    pin, lazy `import()` memoised like `loadMonaco`. Biome declined: runtime use needs its WASM build
    (multi-MB) for one display feature; Monaco declined: needs the TS worker the one-worker guard
    forbids. Display only: the executed and hashed text is untouched.
11. "Script might keep" line and the reads hint go. The script itself highlights every `plain.x` and
    `secret.x` token, derived client-side from the shown (formatted) text; the "Keeps:" chip stays.
12. Review order: result, script, Will save, Request, then card Details. Request header =
    `SectionHeading flush collapsible` (chevron, uppercase like other section headings) inside its
    `ApprovalBox`; content gap like other boxes.
13. Approvals grouped by agent session: key `origin.session`, else `task:<origin.task>`, else
    `client:<client>|<cwd>`. Groups ordered by their oldest item; items by age inside. One
    `SecondaryTabs` row under the header when there are 2+ groups (label = requester text plus
    count). Counter `1/3` counts the current group, on the header row. "Deny all (N)" =
    `Button variant="outline" size="sm"`, denies the current group's ids only, shown when that group
    has 2+ items.
14. Op log `jsPrepare`/`jsTransform` history rows and `script.run` shell commands are not JS prompt
    scripts: not formatted.

## Open decisions (defaults above; user may veto)

1. "Retired in code": default renames user/agent-facing names only (tool `list_saved_variables`,
   result fields, texts); Go package `keptvars`, TS `studio/kept`, i18n key paths, payload field
   names, contract file names and setting `dbMcp.keptRetentionMinutes` stay.
2. "Non-text values": read as non-JSON values (function, symbol, undefined, accessor). Lists and
   objects stay allowed because SQL `params` bind lists (`registry.go:841`). Strict text-only would
   break list params.
3. `plain` holds only the names the script mentions, not every saved value, so the card lists every
   read.
4. Deleting `plain.x` deletes the saved value; prepare writes are saved too, not only interpolated.
5. Typed inputs stay secret; `{{plain.x}}` on an input is refused.
