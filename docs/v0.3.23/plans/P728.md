## Decisions (defaults taken; stated, not asked)

1. Rename is a hard cut: `kira.storeValue`, `kira.storeSecret`, `kira.getValue`; `kept.*` calls
   now fail like any unknown global (no binding named `kept`). Internal op names in `ScriptSite.Op`
   become `getValue`, `storeValue`, `storeSecret` so code, payload sites and docs use one vocabulary.
   `{{kept.x}}` templates, `list_kept_variables`, "kept variables" wording unchanged.
2. One-time removal is full-stack: no answer field, no overlay, no `once` status, no `reuse` arg.
   `answerOptions` keeps `DisallowUnknownFields`, so a stale `inputModes` is a contract error.
   Payload drops `mode`, keeps `keepMinutes` (drives "Kept for N min").
3. × on a card's kept row calls `KeptVarsService.Clear([id])`; the request then ends through the
   existing `watchKept` path. Tooltip says so; no confirm dialog (the card itself is the confirmation
   surface, and the effect is visible at once). × on a review "Will keep" row needs a new call:
   `KeptVarsService.DropStaged({requestId, name})` behind `ApprovalBroker.DropStaged`, which removes the
   name from the held run's staged set; the agent's result then lists it in `keptNotSaved` with
   `"the user chose not to keep it"`. Spec cites `Clear`; staged values are outside the store, so this
   is the minimal real mechanism. User may veto; then the review row gets no ×.
4. Chips: verdict facts only for variables: "Uses: a, b" (kept reads, tooltip lines "a, kept by …"),
   "Keeps: token (secret), pod" (transform may-keep), API "Sends: …" stays. "Runs N scripts" fact goes
   from DB, API and kube. The two kept risk lines go; "Expires before you answer" stays a risk line.
5. Header: registry `where` becomes `where?: (item) => ApprovalWherePart[]` with
   `{ text: string; label?: string; chip?: boolean; data?: boolean; color?: string }`; `whereData`
   removed. Card draws parts with `gap-x-1.5`, no " · " text; a `chip` part is a shadcn `Badge`
   `variant="chip"`. Kube: server (data, muted) + namespace chip (`default`, or "All namespaces"),
   both from payload `server`/`namespace` (no backend change). API: environment chip with its colour
   dot (`payload.environment.color`) or "No environment" muted. DB: host (data) + database/path chip;
   backend adds `host` and `path` (string, " / " joined) to db query, exemption and response payloads
   so the frontend never splits `location`. `script.run`: folder part (data). `proof.review`: rev part.
6. Details: approvals variant `density="approval"` on `KeyValueList` (key column 6rem, `gap-y-1.5`,
   `text-kira-md`, dt `text-kira-sm text-muted-foreground`, dd `text-fg`). `ApprovalDetails` and
   `ApprovalPairs` (when given `approval`) use it; other `KeyValueList` callers untouched.
7. Kube prepared values all visible: `maxRows` renders as a trailing meta comment `# up to N rows`
   (kubectl has no row-cap flag; the comment is honest display); a changed boolean set `false` renders
   `--previous=false` / `--timestamps=false` (valid kubectl syntax); a changed empty string renders the
   flag with `""`.
8. Review tabs: scripted views "After" (was Agent gets) then the raw views; API raw "Response" and DB
   raw "Raw result" become "Before". Kube raw views keep their format names (Table, Manifest, Logs,
   JSON): those are the format toggles the spec keeps; each gets tooltip "Before the script" when
   scripted. Unscripted reviews unchanged apart from wording.
9. Review Request section: collapsed `Collapsible` (shadcn-vue, `@theme/components/ui/collapsible`) in
   its own `ApprovalBox` above the result box, trigger "Request". Content reuses the prompt's request
   components read-only (no ×, no inputs, no scripts): API `RequestLine` + body + headers; DB
   `ApprovalStatement` + `DbParamsList`; kube `KubeRequestLine` (or plain statement for discover).
   Backend adds the data the review lacks (step 6).
