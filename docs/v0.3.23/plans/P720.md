## 2. Pain points

Each verified in code and in a before shot.

1. Edit is three hops from anywhere. Read-only tab, then Edit, then a dialog with tabs
   (`VariableSetView.vue:127-135`, `VariablesOverviewPanel.vue:84-93`; b03, b04).
2. Five surfaces for one concept (table above). The Environments tab alone has four buttons per
   row: "Edit variables" opens the read-only tab, "Edit environment" opens the dialog on its
   Environment tab, not Variables (`EnvironmentsView.vue:225-240`; b02, b08).
3. No side-by-side view. Each environment is edited alone, so a variable missing in Production, or
   a Staging URL pasted into Production, is invisible (b03).
4. Copy across environments is manual retyping; a secret cannot be copied at all.
5. Marking a row secret throws its value away: `setSecret` sets `value: undefined`
   (`ApiVariablesTable.vue:44-54`, line 48). The user must retype the value.
6. Secrets shown twice under two names. Dialog shows "Saved, type to replace"; the Environments tab
   lists `prod.token` with Set value and Delete (`ApiSecrets.vue`; b02, b04). The internal name is
   an implementation detail the user never chose.
7. Duplicate shares secrets. A copy of Staging edited into Production overwrites `staging.token`
   when the user types the Production token (`lifecycle.go:561-563`).
8. New environment gets a placeholder name and needs a dialog to rename (`EnvironmentsView.vue:87-89`).
9. Shadowing hidden. Collection versus environment precedence shows only as a scope badge in the
   overview; the shadowed collection row is not dimmed (b11).
10. Overview popover lists everything, not the request's variables; names truncate to
    `{{base_u…` (b11). No unresolved row: `tenant` is absent from it.
11. Unresolved badge is passive. Tooltip text "tenant", anchored on the tab strip (b10). No fix
    action.
12. Dotenv mode breaks on an empty row: Add variable then "Edit as dotenv text" shows `=""` and
    "Line 9 has no key" (`variablesForm.ts:91-99` keeps empty names; b05, b06).
13. Draft and Save in a dialog for a one-cell change, plus close; Save does not close (b04).
14. Agent access lives in two places: read-only overview in the Environments tab, editor in a dialog
    tab (b02, b07).
15. Import report gives a count only. Unset secrets after a Postman import are not named; no link to
    the variables (b13).
16. Design: table headers "Secret Description" run together (b04, b14); the read-only tab puts the
    reveal eye at the description column (b03); the tab icon is a gear while the head icon is the
    environment icon (b03); a stray RunState dash sits in every toolbar (b01, b02); the empty state
    explains nothing and offers no action (b01).

## 3. Design

### Model choice: one Variables tab, a matrix of names by scope

Rows are variable names. Columns are the collection default, then one column per environment in
saved order. A cell is that file's value for that name. This is the existing data model drawn
as-is: collection file = default column, environment file = override column. Nothing new is stored.

Why the matrix (users of Postman, Bruno, Insomnia know per-environment lists; Postman's
Environments page and Insomnia's environment JSON are both one environment at a time):

- The common failure is drift between environments (missing key, wrong host). A matrix shows it
  without opening anything; a per-env list never does.
- Copy across environments becomes copy a cell, paste a cell.
- Precedence is spatial: an empty environment cell shows the default dimmed (p03, `page_size`).
- Typical size fits: 3 to 6 environments, 5 to 40 names.

Rejected, close call: per-environment list with environment tabs (Bruno style). Better at many
environments and narrow widths, worse at every cross-environment task. The matrix keeps the list as
its narrow mode: under 760 px of tab width it shows one environment column picked in the toolbar
(p13, p14), the same layout Bruno users know.

### Variables tab (replaces Environments tab, variable-set tab, variables dialog form)

Layout (p03):

- Head: variables icon, "Variables". Toolbar: name filter, collection picker when there is more than
  one collection ("Defaults from: Orders API"), New environment, Add variable. RunState dash removed.
- Header row. Name. Collection default column with library icon and "default for every
  environment". One column per environment: 3 px colour line on top, active radio, name, `active`
  badge, column menu (Rename and colour, Agent access, Edit as .env, Open YAML file, Duplicate,
  Delete). Last header cell: `+` to add an environment inline (name input in the header, Enter
  creates it, no placeholder name).
- Active column: `bg-select` header, `bg-select/40` cells (N18 grey, no blue).
- Row: name (monospace), description note icon with tooltip, lock toggle (secret), row menu
  (Rename, Edit description, Copy `{{name}}`, Share with agents per environment, History, Delete).
- Cell states: value; inherited (default dimmed, italic, tooltip "From Orders API: type to override
  in Staging"); not set (amber warning, the row exists in another environment and there is no
  default); secret set (masked, reveal eye through the existing gate, replace pencil); secret not
  set (amber "Set value" button). Default cell overridden by every environment is dimmed with
  tooltip "Overridden in every environment" (p03 `base_url`).
- Last row: "Add variable…" input: type the name, Tab to the active column, type, Enter (p02, p03).
- Footer: counts, "N values missing" in amber, "Environment values override the collection
  default · saved to the file as you type".
- Empty state (p01): what a variable and an environment are, Add variable (primary) and New
  environment.

Editing (p04, p05): click or Enter on a cell opens an inline `Input`; Enter or blur commits, Escape
cancels, Tab moves right. Every commit writes the file at once (no draft, no Save, no dialog).
Undo is the existing per-variable history (row menu), which already records every value change.
A file with a YAML problem shows its column header in amber with "Fix in YAML"; its cells are
read-only until fixed (today's lastGood rule, kept).

Secret (p05): the row lock is the secret switch for every environment of that row. Locking moves
each plain value into sealed storage in the same call (fixes pain point 5). A secret cell edits
through a password `Input`; the value goes straight to the backend, never the file. Unlocking needs
the existing reveal confirmation, then writes values back as plain text (open question 3). The API
Secrets section goes away; a secret name nobody references is listed under "Unused secrets" in the
column menu's YAML dialog footer, with Delete.

### Request side

- Unresolved badge becomes a toolbar `Button` with warn tone: "tenant not defined · Fix" (p08).

- Request variables popover replaces `VariablesOverviewPanel` (p09, p11): "Used by this request",

- Environment picker stays as is (2 clicks, already always visible on request tabs). "Manage

### Import (p12)

button. A collection import names its unset secrets the same way.

### Agents

an "Agent access" dialog from the column menu: today's `ApiAgentAccessForm.vue` hosted in a
`ConfigFileDialog` with one section. Sharing a single variable: row menu "Share with agents" per
environment, and a small agent glyph in shared cells. The read-only overview section leaves the

## 4. Data and migration

File format: unchanged. Same keys, same `${secret:<name>}` references, same secret store. No file
migration.

Backend changes:

1. New `ApiConfigService.EditVariables(args ApiEditVariablesArgs) (apifiles.View, error)`
   (`internal/bridge/apiconfig.go`), backed by `apifiles.Store.EditVariables(edits []VariableEdit)`
   (new `internal/apifiles/variables_edit.go`). One edit:
   `{scope, ownerId, op, name, newName, value, secretValue, description, agent, agentHosts, before}`
   with `op` one of `set`, `unset`, `rename`, `lock`, `unlock`, `describe`, `share`, `move`.
   Applies to the YAML node tree (`parseDoc`/`encodeDoc`, comments kept, like `replaceRequest`),
   groups edits by file, seals secret values first, then writes each file through `saveLocked` and
   the projection, one `emitApiData` at the end. A broken file refuses with `BrokenError`. No base
   hash: edits are per name, last writer wins per cell, which matches inline editing. Justification:
   today a one-cell change costs Form plus SaveFile plus SetSecret round trips and a draft; the
   matrix also needs one call that touches several files (rename, delete row, lock row).
2. `lock` moves a plain value into a new secret named `<stem>.<slug>` (`freeName` on collision) in
   the same call. `unlock` needs `confirmed: true` after the reveal gate (`apivars` reveal rule).
3. `DuplicateEnvironment` copies each secret value under the new stem instead of sharing the name
   (open question 2). Existing shared names stay; the cell tooltip names the secret so sharing is
   visible.
4. `model.Variable` gains `secretSet bool` and `agent bool` (`internal/storage/model/variables.go`,
   filled in `VariablesRepo.List` from `secret_ref` and the secret names), so cells render set or
   not set without reading the config view. `packages/shared/domain/variables.ts` follows.
5. Import report: `environment.secretsUnset []string`, `collection.secretsUnset []string`
   (`internal/apifiles/import.go`, report types).

Tabs: the `variable-set` tab kind is removed. Persisted rows of that kind restore as the Variables
tab (one-line mapping in `state/tabKinds.ts` restore plus `internal/storage/model/tabs.go` kind
list). Legacy mapping lives only in this patch line; per CLAUDE.md the next minor bump (v0.4.0)
drops it. The `environments` tab kind stays, renamed in UI to Variables.

## 8. Open questions (defaults in bold)

1. Inline editing in the Variables tab vs a dialog. **Inline, autosave per cell; history is the
   undo.** YAML stays one menu item away.
2. Duplicate environment: share secrets (today) or copy them. **Copy under the new stem.**
3. Unlocking a secret row writes values back as plain text after the reveal confirmation, or leaves
   them empty. **Write back after confirmation.**
4. Where agent access lives. **Column menu Agent access dialog for environment settings; row menu
   Share with agents per environment; agent glyph in shared cells.**
5. More than one collection: one default column for the chosen collection (picker), or a column per
   collection. **One, picked; request popover and tree entry pre-select the request's collection.**
6. Rename variable: rename only in files where it exists, references in requests untouched.
   **Yes; a toast offers "Find usages" (request find) since requests are not rewritten.**
7. Narrow-mode breakpoint. **760 px tab width.**
8. Lock as a row property for every environment, even though the file allows mixed. **Row
   property; a mixed row (hand-edited YAML) shows a half lock and locking makes it uniform.**
