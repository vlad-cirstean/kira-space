# P725: column search in the Columns menu, scroll-to-column button

Spec row: `SPEC.md` P725. Branch `stream/p725` off `chapter/v0.3.23` (`7ddc5dbde`), worktree

## Reading

User: "The column search thing in sql data view have it as part of the column projection where i
have a searchbox too and an eye icon to scroll to the specific column".

Code facts:

- "Column search thing" is P658's column-name field at the right end of the filter toolbar
  (`FilterToolbar.vue:254-276`, `SearchField` testid `column-filter-input`, status
  `column-filter-status`, chip `data.filterColumns` ⇧⌘F). It does not find or scroll; it narrows the
  grid's rendered columns (`columnFilter.ts` `visibleColumnOrder`, runtime `DataViewRuntime.columnFilter`,
  `SlickGridHost.vue` `appliedColumnFilter` + `applyColumnFilterNow` + `watchDebounced`).
- "Column projection" is `ColumnsMenu.vue` (popover from `DataToolbar.vue` button `toolbar-columns`,
  icon `list-selection`). Rows: drag handle (`gripper`), visibility `Checkbox` (PK locked), name. No
  search box, no reveal.

Chosen reading: column search lives only in the Columns menu. Its search box filters the menu rows.
A per-row button scrolls the grid to that column. The toolbar field and the grid narrowing go away:
with search inside the menu, narrowing the grid while the menu is open is redundant with the
checkboxes (the persistent way to hide columns) and the reveal button. Keeping both would leave two
"hide columns" mechanisms with different persistence.

Icon: not `eye`. `DataToolbar.vue` mask-preview button already uses `eye-closed`; app-wide
eye/eye-closed mean show/hide (`RepoList.vue`, `GitPanel.vue`, `AdeReposPage.vue`). Beside a
visibility checkbox an eye reads as a second visibility toggle. Use codicon `target` (present in
`@vscode/codicons` dist). If the user prefers the eye at chapter end, swap the one icon name.

## Design

### ColumnsMenu.vue

- Top of `PopoverContent`, above `PopoverBar`: `SearchField` (theme, already shadcn `InputGroup`),
  `v-model="query"` (component-local `ref('')`, discarded on unmount), `size="kira"`,
  placeholder `studio.grid.columns.search.placeholder`, aria `studio.grid.columns.search.aria`,
  testid `columns-menu-search`, `ref="searchField"`. Wrap in a `div` with Tailwind padding
  (`px-1.5 pt-1.5`); no scoped style. No `shortcut` prop on it (the chord opened the menu; a chip
  inside it says nothing).
- Focus: `PopoverContent @open-auto-focus` handler: `e.preventDefault()`, `searchField.value?.focus()`.
  Opening by button or chord lands in the search box. Expose `focusSearch()` via `defineExpose`.
- `visibleNames = computed(() => filterColumnNames(order.value, query.value))`. `v-for` over
  `visibleNames`, not `order`.
- No match (query has terms, `visibleNames` empty, `meta` loaded): `InlineState kind="empty"` with
  `studio.grid.columns.noMatch.status`, testid `columns-menu-no-match`.
- All / None keep acting on every column, not only matches (unchanged semantics; simpler, and
  "None" keeps PK rule). State it in a comment only if not obvious.
- Drag reorder while filtered: pass `() => visibleNames.value` as `useSortableReorder`'s `ids`.
  `onMove` stays `order.value = moveId(order.value, from, to)`: `moveId` works by id, so a drop
  among filtered rows lands relative to the target in the full order. Add
  `filter: '[data-testid="columns-menu-reveal"]'` so pressing the button never starts a drag.
- Reveal button per row, after the name, pushed right (`ml-auto`): `TooltipIconButton`
  `icon="target"`, label `studio.grid.columns.reveal.tooltip`, aria-label
  `studio.grid.columns.reveal.aria` with `{column}`, testid `columns-menu-reveal`,
  `@click.stop.prevent="emit('revealColumn', name)"`. `.prevent` + `.stop`: the row is a `<Label>`;
  a click must not toggle the checkbox nor reach Sortable. Menu stays open.
- Disabled when the grid does not render the column: `rendered = computed(() => { void pageVersion.n;
  return new Set(getPage(props.tabId)?.columns.map((c) => c.name) ?? []); })` (page reflects the
  committed projection; adapters apply it, `setProjection` reloads). Disabled tooltip
  `studio.grid.columns.revealHidden.tooltip` (TooltipIconButton already wraps a disabled trigger;
  repo rule: name the condition, no silent disabled control). A column unticked in the menu but not
  yet committed is still rendered, so still revealable.
- `defineEmits<{ revealColumn: [name: string] }>()`.

### menu.ts

Add `filterColumnNames(names: readonly string[], query: string): string[]`: terms =
`query.toLowerCase().split(/[\s,]+/)` minus empties; no terms returns `names` as is; else names
where some term `matchesQuery(name, term)` (`@workbench/behaviour/match`). Moved from `columnFilter.ts`
(`columnQueryTerms`, `matchesColumnQuery`). No PK special case, no "no match shows all" fallback:
those existed to keep the grid non-empty.

### DataToolbar.vue

- `<ColumnsMenu ref="columnsMenu" ... @reveal-column="emit('revealColumn', $event)" />`.
- `defineEmits<{ revealColumn: [name: string] }>()`.
- `openColumnSearch()`: if `columnsOpen` already true, `columnsMenu.value?.focusSearch()`; else set
  `columnsOpen = true` (open-auto-focus does the focus). `defineExpose({ openColumnSearch })`.
- Columns `TooltipIconButton` gains `shortcut="data.filterColumns"` (chip in tooltip,
  `aria-keyshortcuts`).

### DataView.vue

- `dataToolbarRef = ref<{ openColumnSearch: () => void } | null>(null)`; `<DataToolbar
  ref="dataToolbarRef" :tab="tab" @reveal-column="onRevealColumn" />`.
- `useShortcut` handler: `data.filterColumns` calls `dataToolbarRef.value?.openColumnSearch()`.
- `onRevealColumn(name)`: `dataGridRef.value?.revealColumn(name)`.
- `dataGridRef` type: drop `applyColumnFilterNow`, add `revealColumn: (name: string) => boolean`.
- Delete `filterToolbarRef` and its `ref=` on `FilterToolbar`.
- `onGoToMatch`: only `dataGridRef.value?.revealPageCell(match.row, match.col)`; the
  clear-filter-then-reveal fallback goes (nothing hides a page column from the grid any more).

### SlickGridHost.vue

- `displayOrder(p)` returns `resolveColumnOrder(p, tab()?.state.columnOrder ?? null)`. Delete
  `appliedColumnFilter`, `applyColumnFilterNow`, the `watchDebounced` on `columnFilter`, the
  `visibleColumnOrder` import; drop `watchDebounced`/`TIMING` imports only if now unused
  (`TIMING.scrollPersist` still used at ~816).
- `applyPageAndOrder` comment: drop "and the column-filter apply"; keep the function (pageVersion
  watch still uses it). Re-grep this file for `column filter`, `filtered out`, `filter's debounce`
  comments and fix them (e.g. `currentOrder` comment at ~363, `revealPageCell` doc "False when that
  column is filtered out", `scrollCellIntoView` "live filter" wording if it refers to the column filter;
  leave row-filter wording).
- Expose `revealColumn(name: string): boolean`: `idx = currentOrder().indexOf(name)`; `-1` or no
  grid returns false; else `grid.scrollColumnIntoView(idx + 1)` (gutter is column 0, same `+ 1` as
  `revealPageCell`) and true. SlickGrid 5.20.2 `scrollColumnIntoView` uses the same
  `internalScrollColumnIntoView` as `scrollCellIntoView`, so the frozen gutter behaves as in
  `revealPageCell`. No hand-rolled scroll math.

## Tests

No backend half: search and reveal never touch the bridge. The UI spec asserts that (no extra
`data:read`, projection unchanged), as P658's did.

### `tests/ui/studio/data-view-column-search.spec.ts`

`git mv` from `data-view-column-filter.spec.ts`; keep its fixture (60-column `app.wide_table`,
`CONTROL`, `PORT`). Header comment: P725, search in the Columns menu, reveal per row, display-only.
One test, `contract: Columns menu search and scroll to column, display-only`:

1. Open wide_table. `column-filter-input` count 0 (old field gone).
2. Click `toolbar-columns`: `columns-menu-search` focused. Rows count = 60.
3. `fill('text_')`: rows equal the names matching `text_` in display order; `fill('bool uuid')`:
   OR-ed terms; `fill('zzz_none')`: 0 rows, `columns-menu-no-match` visible; clear.
4. Reveal: filter to the last column name (far right, off screen at 1200 px width). Its header cell
   (`headerCell(page, name)`) not in the grid viewport before; click its `columns-menu-reveal`;
   poll until the header cell's box lies inside `[data-testid="data-grid"]`'s box. Menu still open,
   that row's checkbox still checked.
5. Drag while filtered: filter to two names, drag one onto the other, close (Escape): grid header
   order has them swapped relative to each other (`headerNames`).
6. Hidden column: open menu, untick a non-PK column, close (projection reloads), reopen, search it:
   its reveal button disabled; hover shows `revealHidden` tooltip text. Tick it back, close.
7. Chord: click a grid cell, press `Meta+Shift+F` (spec env is macOS-chord like P658's step 8): menu
   open, search focused.
8. Backend: wide-table reads during steps 2 to 5 and 7 count no more than before step 2 (search and
   reveal send nothing); every read before step 6 has `projection: null`.
9. `consoleErrors` empty.
