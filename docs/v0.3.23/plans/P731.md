## 2. Decisions

### D1. Categories: "main" = every link today; "related" = found links only

- Backend: new detected source name `notes` (`artifactSrcNotes`). No new stored source value, no
  CHECK change on `ade_task_artifacts`.
- Frontend: new `LinkCategory` value `related`, rendered as its own line after Misc. A found link
  lands there whatever its kind (kind still drives its icon). Nothing else ever lands there.
- Main classes stay exactly as today: slots, stored `user` rows (manual, at creation via AddLink or
  later), stored `agent` rows (AI, through `links.yaml`), detected repo and tracker links.

### D2. Extraction runs on read, in the backend, as an `ArtifactSource`

Decision: derive found links on read in a new `notesSource` registered in `builtinArtifactSources`
(`artifacts.go:68-74`), not at write time. Justification:

- ARCHITECTURE "Task artifacts (P409)" rule: detected artifacts derive on read, never stored. Found
  links are detected artifacts of the task's own text.
- Write time needs hooks on about 8 writers (list in §1) plus file adopt, file remove and the P643
  migration; one missed writer leaves stale links. Read time has one code path.
- Edit and delete semantics come free and exact: a link vanishes the moment no note or handover
  holds it; manual and AI rows are never touched (they live in another table).
- No churn in `links.yaml`: stored found rows would mirror into the agent-edited file
  (`mirrorTask`), trigger edit approvals and eat the 200-row cap (`agentmcp.MaxArtifactsPerTask`).
- Cost estimate (plain read, no measurement needed): one `Handovers` query plus a linear regexp scan.
  Typical task: under 50 rows, under 100 KB, well under 1 ms. Worst case a few 1 MiB notes: about
  10 ms, inside the 5 s source timeout. The panel already pays a host and tracker fan-out per read.
- Runs in `Quick` mode too (local data only), so the agent's finish reply lists found links with
  `source: "notes"`.
- Archived tasks: listed read-only, as every source.

`notesSource.Artifacts(ctx, sc)`:

1. `rows := Tasks.Handovers(sc.Task.ID)`; keep the newest `maxFoundRows = 200` (input is newest
   first). Every state and source counts (notes, drafts, handed, child mirrors, pass rows): all are
   the task's notes and handovers.
2. `dismissed := Tasks.FoundLinkDismissals(taskID)` (set of normalized URLs).
3. Per row: `extractLinks(row.Body)` (D3), at most `maxFoundPerRow = 50`.
4. Per URL: normalize with `agentmcp.CleanArtifactAs(ArtifactInput{Kind: link, Title, URL},
   anyKind)` so the key equals a stored row's key (same normalization as AddLink and `links.yaml`).
   Drop on refusal (too long, not http/https). Drop when the key is in `dismissed`, or equals
   `sameLinkURL` of `task.HostURL` or `task.JiraURL`.
5. Group by key. One artifact per URL: `ID ""`, `Source "notes"`, `CreatedAt` = newest source row's
   `CreatedAt`, `Title` = first markdown link text seen, else `pastedArtifactTitle(url)`
   (`artifacts.go:527`), kind and ref from `foundKind` (below), `FoundIn` = up to
   `maxFoundSources = 5` provenance entries, newest first.
6. Stop at `maxFoundLinks = 100` distinct links.

`foundKind(task, u)`: pure subset of `classifyLink`, no ctx, no network: `Trackers.ParseRef` → issue
plus ref; Jira-host key rule (`linkclassify.go:143-150`) → issue; `hostLink` → its kind and ref;
`isDocURL(u, false)` → doc; else link. Skip `ParseBranchLink` and `Claims` (ctx-taking provider
calls). Extract the shared rules into one helper so `classifyLink` and `foundKind` cannot drift:
`classifyLink` calls `b.localLinkKind(task, u)` for the tracker, Jira-host and host-link rules, then
adds its ctx-bound branch and code-host rules.

### D3. URL extractor: pure function with a unit test (several interacting rules)

New `internal/ade/linkextract.go`: `extractLinks(body string) []foundURL` (`URL`, `Title`), plus
`linkextract_test.go` (table test). Rules interact (markdown vs bare scan, trailing punctuation vs
balanced parens, code skipping), so the unit-test bar holds. Rules, in order:

1. Skip fenced code blocks (```` ``` ```` and `~~~` fences) and inline code spans: URLs there are
   examples, commands, localhost.
2. Markdown links `[text](url)` and `[text](url "title")`: URL from the parens, title = trimmed text
   (empty text → no title). The span is consumed so the bare scan never counts it twice. Image links
   `![alt](url)` count the same (an attached screenshot URL is still a link).
3. Autolinks `<https://…>`: angle brackets stripped.
4. Bare scan: case-insensitive `https?://` then non-space run, cut at whitespace, `<`, `>`, `"`,
   backtick.
5. Trailing trim, repeated until stable: `.,;:!?'"*_` and `]`; a trailing `)` is dropped only while
   the URL's `)` count exceeds its `(` count (keeps `wiki/Foo_(bar)`, drops `(see https://x/y)`).
6. Accept only `http` and `https` (any case) with a host, through `url.Parse`. Everything else is
   ignored: `javascript:`, `data:`, `file:`, `ftp:`, `mailto:`, `vbscript:`, scheme-relative `//x`.
7. Drop URLs with userinfo (`https://user:pass@host`): credentials must never surface as a pill.
8. Drop loopback and unspecified hosts: `localhost`, `*.localhost`, `127.0.0.0/8`, `::1`, `0.0.0.0`,
   `[::]`. Private LAN addresses stay (a NAS or staging box is a real link).
9. Ports kept (`http://host:8080/x`); IPv6 literal hosts kept unless rule 8.
10. Length over `agentmcp.MaxArtifactURL` (2048) dropped. Dedup by exact string inside one body.

Table cases (each rule at least once, plus interactions): sentence-final period, comma list,
`(see https://a.b/c)`, `https://en.wikipedia.org/wiki/Foo_(bar).`, markdown with parens inside text,
markdown with title, `<https://a.b>`, `HTTPS://A.B/x`, port, IPv6, `javascript:alert(1)`,
`data:text/html,…`, `mailto:`, userinfo, localhost, `127.0.0.1:3000`, fenced block, inline code,
URL right before a closing `**`, over-long URL, same URL twice, markdown link also present bare.

### D4. Dedup and promotion rules

- A found link never overrides anything. `mergeArtifacts` (`artifacts.go:126-156`) gets a third
  pass: (1) detected non-`notes`, (2) stored, (3) `notes`; a `notes` artifact whose key already exists
  is dropped. The existing "detected beats stored" rule stays for pass 1 vs 2 only. Without this, a
  found URL (detected, `ID ""`) would replace a stored manual row and demote it.
- A URL already main stays main: covered by the third pass plus the HostURL/JiraURL check in D2.
- Same URL in several notes or handovers: one artifact, `FoundIn` lists the sources.
- Promotion is always an explicit add of the URL through an existing path; never automatic:
  - user: card action "Add to links" calls `AddLink` with `title url` (title kept when it differs
    from the URL; `parseLinkText` reads `title url`, `linkclassify.go:44-68`). Files like any paste:
    an empty Jira/host slot first, else a stored `user` row.
  - agent: lists the URL in `links.yaml`; Kira applies on save, row `source agent`
    (`detailshandlers.go:381-397`), no approval (a create is `Own`, `:71`). Single path, no new tool.
  - either way the stored row or slot wins pass 2 and the found copy disappears from Related.
- Reverse never happens: removing a manual or AI link whose URL is still in a note makes it reappear
  in Related (it is still found there), unless dismissed. Expected, documented in ARCHITECTURE.
- Note or handover edited or deleted: its links leave on the next read; links still found elsewhere
  stay with the remaining sources. Manual and AI rows are never touched (different table).

### D5. Dismissal: the only other manual action, user only

- New table `ade_task_found_link_dismissals`, migration `0106_p731_found_link_dismissals.sql`
  (highest today: `0105_p717_kube_mcp_review.sql`; P728 and P730 plans add none):

  -- P731: links found in notes and handovers that the user dismissed; read filters them out.
  CREATE TABLE ade_task_found_link_dismissals (
    task_id TEXT NOT NULL REFERENCES ade_tasks (id) ON DELETE CASCADE,
    url TEXT NOT NULL CHECK (url <> ''),
    created_at INTEGER NOT NULL CHECK (created_at >= 0),
    PRIMARY KEY (task_id, url)

  Additive within the 0.3 minor; nothing from older minors touched (CLAUDE.md minor-bump rule).

  (map[string]bool, error)`, `DismissFoundLink(taskID, url string, now int64) error` (upsert; then,

  `TestKiraSchemaGenerated` with its update flag) and the golden `internal/storage/testdata/schema.sql`
  (`go test ./internal/storage -run TestSchema -update`, flag at `schema_test.go:14`).
- Engine `TaskBoard.DismissFoundLink(ctx, args)` (`ade/foundlinks.go`, new file with `notesSource`):

## 9. Risks and open points

- Tooltip on a pill that is also a popover anchor and roving item: reka-ui `as-child` nesting must
  forward refs and events. If the trigger breaks keyboard or popover behaviour, put the tooltip on
  the note icon span instead (same text); do not drop the tooltip.
- Read cost on huge chains: bounded by D10; if a profile ever shows it, cache extraction per
  (row id, updated_at). Not built now (no measured need).
- Fragment loss: normalization drops `#fragment`, so two anchors of one page merge into one link
  (same as stored rows today).
- Dismissals stay when a URL leaves every note; harmless, capped at 500.
- Task folder export or import (if any) does not carry dismissals; acceptable as UI state.
- Migration number race with another stream: see §6.
- Not resolved: whether `TestDetailsBenchFrozenServes` fixtures embed README text; implementer checks
  and updates fixtures if they pin the old line.
