## Decisions (defaults taken; user may override)

1. Model A. No chain UI; no `ChainSteps` revival.
2. Scripts on the three data tools only: `kube_list_resources`, `kube_describe`, `kube_pod_logs`
   (same set P717 reviews). `kube_list_clusters` and `kube_discover` get none: app config and
   cluster metadata.
3. Argument `script {prepare, transform}`, object like `api_request`, no `script.input` (kube args are
   few and typed; kept values cover chaining). Empty object refused (`apiScriptEmpty`).
4. Prepare, yes. Runs before the card (as API); returns a subset of the tool's own args, through the
   same clamps and required checks. Card shows the final read with script-set fields marked. Allowed
   keys:
   - `kube_list_resources`: `kind`, `namespace`, `labelSelector`, `maxRows` (clamped 1-2000).
   - `kube_describe`: `kind`, `namespace`, `name`.
   - `kube_pod_logs`: `namespace`, `pod`, `container`, `previous`, `timestamps`, `tail` (clamped
     1-5000).
   - Never `clusterId`, the tool or the verb. Unknown key, wrong type, required arg emptied: refused,
     nothing read.
5. Transform: global `result` = the JSON the tool returns today, `request` = final args without
   `clusterId`. Input cap 8 MiB (`maxHeldResultBytes`), output 4 MiB (DB constants). Agent gets
   `{kind:"script", output, input:{operation, rowCount, truncated}, kept, keptNotSaved}`; `rowCount`
   is rows (list), lines (logs), 0 (describe).
6. Kept writes: `kept.set` (plain, preview) and `kept.setSecret` (secret, masked from output, reveal
   behind fingerprint in review) in transform; prepare cannot keep (`keptRunFor` refuses). Kube
   secrets bind no origin (as DB, `commit(src, "")`): usable through `{{kept.name}}` in
   `api_request`, never in SQL (`kept_params.go` rule unchanged).
7. Kept reads in kube scripts: plain values only. Secret or user-typed values refused at plan time in
   both stages, one text shared with DB: `queryKeptNotAllowed` becomes
   `keptReadNotAllowed = "kept variable %q is secret or was typed by the user; those are used in
   api_request only, never in %s. %s"`; DB passes `run_query`, `Nothing ran.` (byte-identical, DB
   contracts unchanged); kube passes the tool name, `Nothing was read.` Reason: kube args never carry
   a credential, and a secret read would force review with no use.
8. No `{{kept.name}}` templates in kube args. Prepare `kept.get` is the one read mechanism.
9. Approval `allow`: scripts run, no card, op log records each run (same as API and DB). P717's
   review settings still hold the result.
10. Review with a script: P717's hold carries `Text` = envelope, `Raw` = tool JSON, `Script`,
    `Keep` = `stagedViews()`, `staged` (as DB `heldOf`). Staged values commit only after Send.
11. Cluster colour line: no (clusters have no colour). Own phase if wanted.
12. Info lines: logs "Kira masks nothing in logs" (neutral), describe of `v1/secrets` "Secret values
    reach the agent as byte counts only" (neutral).
13. Design gate: approve this plan now, screenshots from the real frontend at chapter end (as P716,
    P717). Old prototype shots in `scratchpad/p716/proposal/` show the deleted chain panel: superseded.
    `scratchpad/p716/before/*.png` stay valid as before shots.

	Prepare   string `json:"prepare,omitempty"`

// the statement and the read use the same values.

	Kind, Name, Namespace, LabelSelector, Pod, Container string
	Previous, Timestamps                                bool
	Tail, MaxRows                                       int
}
var kubePrepareKeys = map[string][]string{ /* decision 4 */ }

func (s *Server) prepareKube(ctx context.Context, tool string, in kubeRequest, sc *apiScripts) (kubeRequest, string)
func (s *Server) transformKube(ctx context.Context, call kubeCall, raw json.RawMessage) *kubeScriptOutcome

- `openKubeScripts`: nil without script; `!scriptsOn()` gives `apiScriptsOff + ". Nothing was
  read."`; empty gives `apiScriptEmpty`; `checkScript` per stage; `keptRunFor(keptScope(ctx), sc,
  "Nothing was read.")`; every `get` site in both stages must resolve (`unknownKeptText`) and be
  plain (decision 7). Runs before the cluster is touched.
- `prepareKube`: `execScript` stage prepare, bindings `request` (JSON of `kubeRequest` per tool's
  keys) plus `sc.kept.Bindings(stagePrepare)`; `Validate` runs `applyKubePrepared`; failure text
  `prepare script failed: %s. Nothing was read.`; sets `sc.Changed`.
- `transformKube`: as `transformQuery` (input check, `execScript`, `Validate` masks with
  `sc.kept.mask`, which removes `setSecret` values). Failure texts: `script failed: %s. The read ran;
  its result is not returned.` plus the size hint (`Ask for fewer rows or a smaller tail.`).
- `keptSourceOfKube`: `Source{Kind: script, MCP: "kube", Tool: <tool>, Request: "<context>:
  <kubectl command>"}` capped 512 bytes.

`kube_tools.go` (on top of P717's `kubeRun`):

- Arg structs gain `Script *kubeScriptArgs` (list, describe, logs). Handlers build `kubeRequest` and
  a `kubeCall{tool, op, clusterID, req, script}`.
- `kubeRun(ctx, call, statement func(Cluster, kubeRequest) string, read func(ctx, kubeRequest) (any,
  error))`. Order: open scripts, resolve cluster, prepare, card (unless `allow`) inside `watchKept(
  ctx, sc.kept.uses)`, after approval re-resolve and recheck `scriptsOn` (`apiScriptsOff + ". Nothing
  was read."`), read with final `req`, marshal once, transform, P717 hold when review is on
  (scripted `heldOf`), then `commit(keptSourceOfKube(...), "")`, envelope. `defer sc.dropKept()` so
  every other exit drops staged values (as `deliverAPI`). Withheld, timeout, client cancel: nothing
  kept.
- Schemas: shared helper `pinScriptObject` extracted from `fixScriptSchema` (API keeps its `input`
  fix); kube schemas drop `script` while scripts are off; descriptions append
  `DbmcpToolKubeScripts` while on (as `run_query`).

`approval.go`, `approval_item.go`:

- `ApprovalCluster` gains `Tool string`, `Request kubeRequest`, `Changed []string`, `Script
  *apiScripts`. Kept reads ride on existing `ApprovalRequest.Kept` (comment widened to kube.read).
- `kubePayload` adds `tool`, `request` (`kind, name, namespace, labelSelector, pod, container,

- New `DbmcpToolKubeScripts` (`dbmcp.tool.kube.scripts`, KindSuffix, keys like
  `DbmcpToolRunQueryScripts` :901), shared by the three tools. Draft:
  "Optional script, JavaScript run by Kira in a sandbox: no network, files, timers or console; Date is
  fixed for the run and UTC; 2 s and 256 MiB. Each part is a function body that ends with return. The
  user sees both. script.prepare runs before approval on the global request (your args without
  clusterId) and returns args that replace yours; it cannot change clusterId or the tool.
  script.transform runs on the global result (what the tool returns) and request; you receive only
  {kind: \"script\", output, input: {operation, rowCount, truncated}}. Result input up to 8 MiB, output
  up to 4 MiB. Kept: kept.get(\"name\") reads a plain kept value; in transform kept.set(\"name\",
  value) keeps a plain value the user can preview, kept.setSecret(\"name\", value) a secret the user
  reveals only behind their fingerprint (1 MiB, 16 per run), for a later kube read, api_request or
  run_query. Names are literal strings. Kept values are stored only once the result is sent; you get
  kept: [{name, type, items, secret, expiresInSeconds}], never a value. Secret kept values and values
  the user typed cannot be read here."
- Args per tool: `script` (~70 runes), `script.prepare` (lists that tool's keys, ~150),
  `script.transform` (names the `result` shape per tool, ~120).
- `DbmcpInstructions` :768: "`kube_*` tools are read only" gains "; their reads take scripts too", and
  the kept sentence names kube prepare `kept.get` beside `{{kept.name}}` and `params`. Budget
  `dbmcp.instructions` 1460 raised to fit.
- `list_kept_variables` note (`kept_tools.go:71`): add "or `kept.get` it in a kube read's prepare
