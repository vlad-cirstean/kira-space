## 1. Decisions

1. Mechanism: Sortable's existing `forceFallback` pointer drag. A drop whose `pointerup` lies
   outside the viewport becomes one bound call with client coordinates. Go derives the screen point
   from the source window's `Bounds()`, hit-tests live workbench windows, moves the tab. No cgo, no
   HTML5 DnD, no new dependency.
2. Screen point: `Bounds()` plus client offset, never `PointerEvent.screenX`. WebKit reads `0,0`
   under synthetic input and mixed-DPI `screenX` on WebView2 is unverified; `Bounds()` is in the
   same space as every target's `Bounds()`, so the hit-test stays self-consistent (spike risk 1).
3. Drop zone: whole target window (strip or body). The tab appends at the end of the target's strip
   for its module and becomes active. Strip-only drop needs per-window strip rects: not worth it.
4. Overlap: most recently focused window wins (focus sequence from `events.Common.WindowFocus`).
   Wails has no z-order; a never-focused window under another can win wrongly (accepted, spike
   risk 3). Hidden or minimised windows and ephemeral windows (review, files, proof, capture, host
   view, config sync) are never targets.
5. Miss (desktop, or only ephemeral windows under the point): new workbench window, same size as the
   source, placed so the grab point sits under the cursor; `EnsureOnScreen` clamps it.
6. Drop inside the source's own frame (Windows title bar): no-op.
7. Last tab: after a successful move, a source window with zero tabs (every workspace, every kind)
   asks Go to close it. Go closes only a live non-ephemeral window with no tab rows and at least one
   other real window. A window holding pinned repo tabs or a terminal is not empty.
8. Esc during the drag cancels the out-of-window drop too (shared `dragCancelled`).
9. Incognito tabs move the same way. The record travels in the call; Go writes no row for it, the
   target marks it incognito before its first save.
10. Movable kinds: database and API kinds only (`STUDIO_TAB_KIND_MODE`, Go `dbTabKinds`). Runs-module
    tabs are `terminal` and `script-run`: not movable this phase (section 2). Git-module kinds stay
    out of scope (SPEC: studio, api, runs).
11. Dirty tab: same question as closing it (`confirmCloses`: kind's own `confirmClose`, else the
    generic discard). Decline moves nothing. Moving drops in-memory page stores and drafts in the
    source; the target reloads (`onOpened(record, true)` hydrates only against a connected
    connection).
12. Ids: the tab keeps its id. Go refuses a move whose id another window owns
    (`ErrTabOwnedElsewhere`). Duplicates by identity (same kind and path) are allowed in the target,
    as `duplicateTab` already allows.
13. Keyboard and Wayland path: tab context menu "Move to new window" and "Move to window ▸
    Window N". Shift+F10 / ContextMenu key on a focused tab opens that menu (new `menu.open`
    binding on the strip; Chromium fires `contextmenu` natively, WebKit does not).
14. Wayland: drag-out disabled (in-strip reorder unchanged), menu path works. Without global
    positions Go cannot tell "dropped on window B" from "dropped on desktop"; always opening a new
    window would contradict what the user aimed at.
15. No new shortcut chord. Chrome has none for this either; the menu is reachable by keyboard.
    `shortcuts.ts` is untouched (P720 owns it this chapter).
16. New-window button: icon only (`TooltipIconButton`, `empty-window`, title variant), tooltip
    "New window" with the `window.new` chip (N19 display site kept), `aria-label` "New window",
    `aria-keyshortcuts` from the shortcut prop. Native menu "New Window ⇧⌘N" (`internal/shell/menu.go`,
    `ItemNewWindow`) stays text: menus are labels.
17. Visual feedback: the drag clone clips at the window edge (no API to draw outside). While the
    pointer is outside the viewport the strip shows a small pill "Release to move to another window".
    No live window follows the cursor (spike risk 5: a new window taking focus can end the source's
    implicit grab).

## 2. Why terminal and script-run tabs do not move (and what it takes later)

- Not persisted (`persistableTabs`), so no row to re-key; the record alone is not enough.
- A terminal's PTY session is owned by its window key in `terminal.Registry`
  (`internal/terminal/session.go:644` `CloseWindow` kills every session in `byWindow[key]`), and
  output is pushed with `EmitTo(windowKey, ChannelTerminal)`. A moved tab in window B would show no
  output and die when window A closes.
- `script-run` tabs render the run's terminal session the same way (`isLiveTab` reads
  `terminalSession(id)`).
- Later phase needs: `Registry.Reown(sessionID, fromKey, toKey)` moving `byWindow` and the emit
  target atomically; a scrollback replay for the target's xterm (the renderer holds the buffer
  today, the backend does not); move payload carrying the session id; script-run state re-keyed in
  the target's automations workspace. Record in ARCHITECTURE "Known open items".

## 3. Bound calls and wire types

All on the existing `TabsService` (`apps/kira-space/internal/bridge/tabs.go`); no new service, so
the bound-service count in ARCHITECTURE stays 37. Go types:

```go
type TabDrop struct {
	ClientX     float64 `json:"clientX"`     // pointerup, CSS px, may be negative or past inner size
	ClientY     float64 `json:"clientY"`
	GrabX       float64 `json:"grabX"`       // pointerdown that started the drag, client coords
	GrabY       float64 `json:"grabY"`
	InnerWidth  float64 `json:"innerWidth"`  // window.innerWidth / innerHeight at drop
	InnerHeight float64 `json:"innerHeight"`
}

type TabsMoveArgs struct {
	WindowKey string          `json:"windowKey"` // source
	Tab       model.TabRecord `json:"tab"`
	Incognito bool            `json:"incognito"`
	// Exactly one of Target, NewWindow, Drop.
	Target    string   `json:"target"`
	NewWindow bool     `json:"newWindow"`
	Drop      *TabDrop `json:"drop"`
}

type TabsMoveResult struct {
	WindowKey string `json:"windowKey"` // where the tab now lives; source key = nothing moved
	Created   bool   `json:"created"`   // a new window was opened
}

type TabInbound struct {
	Tab       model.TabRecord `json:"tab"`
	Incognito bool            `json:"incognito"`
}

type TabWindowTarget struct {
	Key    string `json:"key"`
	Number int    `json:"number"` // 1-based by stored order among live real windows, source included
}

type TabCaps struct {
	DragOut bool `json:"dragOut"` // false on Wayland and in builds without a shell
}
```

Methods:

- `Move(TabsMoveArgs) (TabsMoveResult, error)`.
- `Inbound(TabsListArgs) ([]TabInbound, error)`: pops this window's inbox (pull, like
  `OpenedFilesService.Pending`).
- `Targets(TabsListArgs) ([]TabWindowTarget, error)`: other live real windows.
- `Capabilities() TabCaps`.
- `CloseEmptyWindow(TabsListArgs) (bool, error)`: true when Go asked the window to close.

Errors: all refusals are `ipcerr.Contract`: missing `windowKey`, not exactly one destination,
unknown or ephemeral source or target, target equals source, kind not movable, invalid record
(`ErrInvalidTab`), id owned by a third window ("tab id belongs to another window"), `Drop` while
`DragOut` is false, no shell ("this build cannot open a window"). Storage faults are `Internal`.

Events: `ChannelTabsInbound = "kira:tabs:inbound"` (EmitTo target, nil payload: a nudge to pull)
and `ChannelWindowsChanged = "kira:windows:changed"` (broadcast, nil payload, on registry change).
Server build: `EmitTo` broadcasts; each window pulls only its own inbox, so no filter is needed.

TypeScript mirrors in `packages/workbench/src/bridge/createCoreControl.ts` (`b.tabs` typing,
`TabDrop`, `TabsMoveResult`, `TabInbound<T>`, `TabWindowTarget`, `TabCaps`) and control methods
`tabsMove`, `tabsInbound`, `tabsTargets`, `tabsCapabilities`, `tabsCloseEmptyWindow` (each sends
`windowKey`), listeners `onTabsInbound`, `onWindowsChanged`. Channels in
`packages/shared/protocol/events.ts` (`tabsInbound`, `windowsChanged`).

### 4.4 `internal/shell/tabdrop.go` (new, pure)

```go
type WindowGeom struct {
	Key       string
	Order     int
	Bounds    WindowBounds
	Ephemeral bool
	Hidden    bool   // !IsVisible() || IsMinimised()
	FocusSeq  uint64 // higher = focused more recently
}
type DropInput struct{ ClientX, ClientY, GrabX, GrabY, InnerWidth, InnerHeight float64 }

// clientOrigin: non-client inset from frame size minus inner size; 0 on macOS FullSizeContent.
func clientOrigin(src WindowBounds, innerW, innerH float64) (x, y float64)
// DropPoint: src origin + client inset + client coords.
func DropPoint(src WindowBounds, in DropInput) (x, y float64)
// DropTarget: inSource when the point is inside src.Bounds; else the live, visible,
// non-ephemeral window other than src containing the point, highest FocusSeq; ok=false on miss.
func DropTarget(geoms []WindowGeom, src string, x, y float64) (key string, inSource, ok bool)
// TornBounds: src size, origin = point - client inset - grab.
func TornBounds(src WindowBounds, in DropInput) WindowBounds
// WindowPositionsKnown: false on Linux Wayland unless GDK_BACKEND forces x11.
func WindowPositionsKnown(isWayland func() bool) bool
```

Containment is half-open (`x >= X && x < X+W`). Inset: `ix = max(0, (W - innerW) / 2)`,
`iy = max(0, H - innerH - ix)` (side borders equal, bottom border equals a side border).
`WindowPositionsKnown`: `runtime.GOOS != "linux"` true; else `GDK_BACKEND` contains `x11` true;
else `!isWayland()` (`isWayland` nil uses `IsWayland`, `internal/shell/hotkey.go:33`).

### 4.6 `apps/kira-space/internal/bridge/tabs.go`

`TabsService` gains:

```go
Windows TabWindows // set by BindShell; zero value = no shell
inbox   tabInbox   // mutex-guarded map[windowKey][]TabInbound
```

```go
type TabWindows struct {
	Geometry   func() []shell.WindowGeom
	Open       func(rec shell.WindowRecord) // nil Bounds = cascade
	Focus      func(key string) bool
	Close      func(key string) bool
	Positions  func() bool // WindowPositionsKnown
}
```

`Move` flow:

1. Validate args and `model.IsMovableTabKind(args.Tab.Kind)`; `geo := Windows.Geometry()`; source
   must be in `geo`, non-ephemeral.
2. Destination:
   - `Target`: in `geo`, non-ephemeral, not source.
   - `Drop`: `Positions()` must be true. `DropPoint` from the source's bounds, then `DropTarget`.
     `inSource`: return `{WindowKey: src}`, nothing moved. Hit: as `Target`. Miss: new window.
   - `NewWindow` or drop miss: `key := ids.NewID()`, order = max stored order + 1
     (`Deps.Repos.Windows.List()`), bounds = `TornBounds` for a drop, nil for the menu path;
     `Deps.Repos.Windows.Create`.
3. `appstorage.MoveWindowTab(Windows repo, Tabs repo, src, dst, tab, !incognito)`. On failure after
   step 2 created a row: `Windows.Delete(key)`, return the error.
4. `inbox.push(dst, TabInbound{tab, incognito})`.
5. Created: `Windows.Open(rec)`; the page boots, hydrates, pulls. Existing:
   `Deps.Events.EmitTo(dst, ChannelTabsInbound, nil)`, then `Windows.Focus(dst)`.
6. Return `{WindowKey: dst, Created}`.

`Inbound` pops and returns the entries (empty slice, never nil). `Forget(key)` drops an inbox
(window closed before pulling). `Targets` sorts live non-ephemeral `geo` by `Order`, numbers from 1,
drops the source. `Capabilities` = `{DragOut: Windows.Geometry != nil && Windows.Positions()}`.
`CloseEmptyWindow`: source live non-ephemeral, at least one other live non-ephemeral window,
`Tabs.List(key)` empty; then `Windows.Close(key)`, true. Otherwise false, no error.

## 11. Unverified on macOS, Windows and Linux X11 (manual checklist for the user)

Run on a real build with two Kira windows side by side, then overlapping:

1. Tear a Studio tab off onto empty desktop: new window opens under the cursor with the tab active.
2. Drag it back onto the first window's strip, then onto its body: attaches at the end, active,
   window comes to front (Windows may only flash the taskbar: foreground lock).
3. Overlap two windows, drop on the overlap: last focused wins.
4. Tear off the only tab of a window while another window exists: source closes.
5. Esc while outside the window, then release: nothing moves.
6. Incognito tab: moves, stays incognito, never persisted in either window.
7. Second monitor, mixed DPI (Windows): new window lands on the monitor under the cursor.
8. Windows: maximised source, and drop on the source's own title bar: no-op.
9. Linux X11: frame versus client inset (GTK may report client size; point off by the title bar).
10. Wayland: drag out does nothing; menu "Move to window" works.
11. New-window button: icon only, tooltip "New window" with ⇧⌘N, screen reader reads "New window".
