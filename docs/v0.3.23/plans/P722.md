## 1. Decisions

1. Mechanism: Sortable's existing `forceFallback` pointer drag. A drop whose `pointerup` lies
   outside the viewport becomes one bound call with client coordinates. Go derives the screen point
   from the source window's `Bounds()`, hit-tests live workbench windows, moves the tab. No cgo, no
   HTML5 DnD, no new dependency.
2. Screen point: `Bounds()` plus client offset, never `PointerEvent.screenX`. WebKit reads `0,0`
   under synthetic input and mixed-DPI `screenX` on WebView2 is unverified; `Bounds()` is in the
   same space as every target's `Bounds()`, so the hit-test stays self-consistent (spike risk 1).
3. Drop zone: whole target window (strip or body). The tab appends at the end of the target's strip
   for its module and becomes active. Strip-only drop needs per-window strip rects: not worth it.
4. Overlap: most recently focused window wins (focus sequence from `events.Common.WindowFocus`).
   Wails has no z-order; a never-focused window under another can win wrongly (accepted, spike
   risk 3). Hidden or minimised windows and ephemeral windows (review, files, proof, capture, host
   view, config sync) are never targets.
5. Miss (desktop, or only ephemeral windows under the point): new workbench window, same size as the
   source, placed so the grab point sits under the cursor; `EnsureOnScreen` clamps it.
6. Drop inside the source's own frame (Windows title bar): no-op.
7. Last tab: after a successful move, a source window with zero tabs (every workspace, every kind)
   asks Go to close it. Go closes only a live non-ephemeral window with no tab rows and at least one
   other real window. A window holding pinned repo tabs or a terminal is not empty.
8. Esc during the drag cancels the out-of-window drop too (shared `dragCancelled`).
9. Incognito tabs move the same way. The record travels in the call; Go writes no row for it, the
   target marks it incognito before its first save.
10. Movable kinds: Studio and API kinds (`STUDIO_TAB_KIND_MODE`, Go `dbTabKinds`) plus Runs tabs:
    `script-run`, and `terminal` with `workspaceId: 'automations'`. A live Runs terminal keeps
    running: its PTY is re-owned by the target window and its screen replays there (section 2).
    Git-module kinds, repo terminals included, stay out of scope (SPEC: studio, api, runs).
11. Dirty tab: same question as closing it (`confirmCloses`: kind's own `confirmClose`, else the
    generic discard). Decline moves nothing. Moving drops in-memory page stores and drafts in the
    source; the target reloads (`onOpened(record, true)` hydrates only against a connected
    connection).
12. Ids: the tab keeps its id. Go refuses a move whose id another window owns
    (`ErrTabOwnedElsewhere`). Duplicates by identity (same kind and path) are allowed in the target,
    as `duplicateTab` already allows.
13. Keyboard and Wayland path: tab context menu "Move to new window" and "Move to window ▸
    Window N". Shift+F10 / ContextMenu key on a focused tab opens that menu (new `menu.open`
    binding on the strip; Chromium fires `contextmenu` natively, WebKit does not).
14. Wayland: drag-out disabled (in-strip reorder unchanged), menu path works. Without global
    positions Go cannot tell "dropped on window B" from "dropped on desktop"; always opening a new
    window would contradict what the user aimed at.
15. No new shortcut chord. Chrome has none for this either; the menu is reachable by keyboard.
    `shortcuts.ts` is untouched (P720 owns it this chapter).
16. New-window button: icon only (`TooltipIconButton`, `empty-window`, title variant), tooltip
    "New window" with the `window.new` chip (N19 display site kept), `aria-label` "New window",
    `aria-keyshortcuts` from the shortcut prop. Native menu "New Window ⇧⌘N" (`internal/shell/menu.go`,
    `ItemNewWindow`) stays text: menus are labels.
17. Visual feedback: the drag clone clips at the window edge (no API to draw outside). While the
    pointer is outside the viewport the strip shows a small pill "Release to move to another window".
    No live window follows the cursor (spike risk 5: a new window taking focus can end the source's
    implicit grab).
18. Runs tabs persist nothing (`persistableTabs` excludes `terminal` and `script-run`). Go moves
    them without a row (`persist = false`, like incognito); the record travels in the call and the
    inbox.

## 2. Moving Runs tabs

No hard blocker. Window ownership of a terminal sits in exactly three places, all re-keyable:

- `Registry.byWindow[key][id]` (`internal/terminal/session.go:392`), read by `CloseWindow`
  (`:644`, kills with `CauseWindow`) and `WindowOf` (`:630`).
- The unregister closure built in `Registry.Open` (`:463`), `r.remove(p.WindowKey, p.ID)`: it
  captures the open-time key.
- `outputCoalescer.windowKey` (`internal/terminal/service.go:157`), the `EmitTo` target of every
  `kira:terminal:data` event.

Everything else is keyed by terminal id, so it follows the session for free: `Write`, `Resize`,
`Close` (`bound.go`), output taps (`Arbiter.Output` mobile ring, `scriptruns.Service.Output` tail),
the exit hook, and the run state badge (`runStates.ts` mirrors the global TanStack run list; every
window already holds it). `WindowOf` callers (`appwire/wire.go:450,509`, `bridge/adetask.go:1318,1482`)
read the new owner after a re-key.

The one real gap: the backend keeps no scrollback. The source window's xterm holds the only screen.
Fix: the source serializes its xterm (`@xterm/addon-serialize`), the backend buffers bytes produced
between that snapshot and the target's adoption, the target writes snapshot then buffer then live.

### 2.1 `script-run`

Backend-backed (`ScriptRunView` reads `useScriptRun(runId)`, TanStack, broadcast list) and
`dropResources` is a no-op (`scriptRunTabKind.ts:33`). Moves by record like a Studio tab, with
`persist = false`. Nothing else changes.

### 2.2 Exited or failed Runs terminal

No session in the registry. The source serializes the screen; the target shows it with the stored
status, exit code and error. No `Hold`, no `Reown`. "Restart" in the target opens a fresh session
there, as today.

### 2.3 Live Runs terminal: hold, move, adopt

Source window, `tabWindowMove.move`:

1. `terminalHold({ terminalId })`: Go marks the coalescer held and returns `{ end, live }`. `end` is
   the cumulative byte count already emitted to the source. Bytes produced after this go to the
   hold buffer, not to any window.
2. Wait until the store has routed every event up to `end` (new `end` field on each terminal
   event; event and call-response transports do not order against each other), then
   `term.write('', cb)` so xterm has parsed it. Timeout 2 s: on timeout move anyway (a few bytes may
   show twice in the target, never lost).
3. `serializeTerminal(tabId)`: `SerializeAddon.serialize({ scrollback })` plus cols and rows.
4. `tabsMove({ ..., terminal: { snapshot, cols, rows, status, exitCode, error, shell } })`.
   Go, after the row transaction: `Terminals.Reown(id, src, dst)` moves `byWindow`, the session's
   own key and the coalescer's pending target to `dst`. From here closing the source no longer
   kills the PTY.
5. Success: `detachTerminalSession(tabId)` (store entry, sink and drain gone; no `terminalClose`),
   then `removeMovedTab` (its `closeTerminalSession` now finds no entry and sends nothing; the
   renderer's tab-runtime cleanup disposes the xterm).
6. Failure (refusal, storage fault): `terminalRelease({ terminalId })`: Go emits the held bytes
   to the source as one event, clears the hold, output resumes live. Tab stays.

Target window, inbox pull (`installTabInbox`):

1. `receiveTab(record)` plus, when the entry has `terminal`, `adoptTerminalSession(tabId, payload)`
   before the strip mounts the tab: seeds `byTabId` (status, shell, cwd from the record state), so
   `useTerminalMount` sees an existing session and never calls `terminalOpen`; stores the snapshot
   for the sink; marks the id adopting (live chunks queue, not drop).
2. Live: `terminalAdopt({ terminalId, windowKey })` atomically retargets the coalescer to this
   window and returns `{ data, end, exited, exitCode, error }` (held bytes, base64). Order into the
   drain: snapshot, held data, then queued live chunks whose `end` exceeds the adopt `end`.
   Held exit is applied through `applyTerminalStatus`.
3. Mount: `onTerminalOutput` writes snapshot then drain into the fresh xterm at the snapshot's
   cols and rows; the next fit resizes to the target's own size (`terminalResize`, the TUI redraws).

Hit versus miss differs only in when the target pulls: an existing window pulls on the
`kira:tabs:inbound` nudge; a new window (drop miss, "Move to new window") pulls on boot after
`hydrateTabs`. Output produced while the new window boots waits in the hold buffer.

Hold buffer: cap 1 MiB per session; overflow drops the oldest chunk and sets `truncated`, and the
target writes a dim "[output truncated during move]" line before the held data. Held state ends at
`Adopt`, `Release`, or `Forget(windowKey)` for a closed window (drops holds whose pending target or
owner is that key; `CloseWindow` has already killed the session there).

Rules:

- `canMove` for a terminal also needs status not `starting` (no session id to hold yet).
- One move per terminal at a time: a second `Hold` on a held session is `E_CONTRACT` "terminal is
  already moving".
- Mobile take-over (`mobileterm.Broker`) is id-keyed: a phone holding the terminal keeps it across
  the move; the target's xterm stays read-only as before.

### 2.4 Risks

- Transport order: Wails delivers events and call responses on separate paths. The `end` offset
  plus `waitRouted` and the adopt-side `end` filter remove loss and duplication; the 2 s timeout
  path can duplicate a few bytes (never lose them).
- Serialize fidelity: `SerializeAddon` restores text, SGR attributes, cursor and the alternate
  screen, not mouse modes or bracketed paste state set earlier. A TUI redraws on the target's first
  resize (SIGWINCH), which repairs most of it. Modes set before the move and not re-sent stay off
  until the program re-sends them (checklist item 11).
- Snapshot size: up to 4 MiB through two bound calls (`Move`, `Inbound`) and kept in the inbox
  until pulled. Halving scrollback past the cap bounds it.
- Hold overflow: past 1 MiB the oldest held chunks drop (notice shown). A new window that boots
  slowly under a chatty process hits this first.
- Orphan: a target that never adopts (renderer crash before pull) leaves the session owned by that
  window key with output held; it dies when that window closes or the app quits, as any terminal.
- Source dies mid-move (between `Hold` and `Move`): `CloseWindow(src)` kills the session as today
  and `ForgetMoves(src)` drops the hold; nothing moves.
- Registry lock order: `Reown` takes `Registry.mu` then `outputCoalescer.mu`; `flush` takes only
  `outputCoalescer.mu` and never `Registry.mu`, so no cycle. The unit test runs with `-race`.
- Overlap: no committed plan in `plans/` (as of this revision: `P723.md`, `batch-1.md`) names
  `internal/terminal` or the terminals store. P719/P720/P716 plans live in their streams; the
  orchestrator confirms before landing.

```go
type WindowGeom struct {
	Key       string
	Order     int
	Bounds    WindowBounds
	Ephemeral bool
	Hidden    bool   // !IsVisible() || IsMinimised()
	FocusSeq  uint64 // higher = focused more recently
}
type DropInput struct{ ClientX, ClientY, GrabX, GrabY, InnerWidth, InnerHeight float64 }

// clientOrigin: non-client inset from frame size minus inner size; 0 on macOS FullSizeContent.
func clientOrigin(src WindowBounds, innerW, innerH float64) (x, y float64)
// DropPoint: src origin + client inset + client coords.
func DropPoint(src WindowBounds, in DropInput) (x, y float64)
// DropTarget: inSource when the point is inside src.Bounds; else the live, visible,
// non-ephemeral window other than src containing the point, highest FocusSeq; ok=false on miss.
func DropTarget(geoms []WindowGeom, src string, x, y float64) (key string, inSource, ok bool)
// TornBounds: src size, origin = point - client inset - grab.
func TornBounds(src WindowBounds, in DropInput) WindowBounds
// WindowPositionsKnown: false on Linux Wayland unless GDK_BACKEND forces x11.
func WindowPositionsKnown(isWayland func() bool) bool
```

Containment is half-open (`x >= X && x < X+W`). Inset: `ix = max(0, (W - innerW) / 2)`,
`iy = max(0, H - innerH - ix)` (side borders equal, bottom border equals a side border).
`WindowPositionsKnown`: `runtime.GOOS != "linux"` true; else `GDK_BACKEND` contains `x11` true;
else `!isWayland()` (`isWayland` nil uses `IsWayland`, `internal/shell/hotkey.go:33`).

`Move` flow:

1. Validate args and `model.IsMovableTab(args.Tab)`; `Terminal` only with kind `terminal`;
   `geo := Windows.Geometry()`; source must be in `geo`, non-ephemeral.
2. Destination:
   - `Target`: in `geo`, non-ephemeral, not source.
   - `Drop`: `Positions()` must be true. `DropPoint` from the source's bounds, then `DropTarget`.
     `inSource`: return `{WindowKey: src}`, nothing moved. Hit: as `Target`. Miss: new window.
   - `NewWindow` or drop miss: `key := ids.NewID()`, order = max stored order + 1
     (`Deps.Repos.Windows.List()`), bounds = `TornBounds` for a drop, nil for the menu path;
     `Deps.Repos.Windows.Create`.
3. `appstorage.MoveWindowTab(Windows repo, Tabs repo, src, dst, tab, persist)` with
   `persist = !incognito && !model.IsSessionTabKind(kind)`. On failure after step 2 created a row:
   `Windows.Delete(key)`, return the error.
4. Kind `terminal`: `Terminals.Reown(tab.ID, src, dst)`. False (session already exited or never
   live) is fine: the snapshot plus held exit carry it.
5. `inbox.push(dst, TabInbound{tab, incognito, terminal})`.
6. Created: `Windows.Open(rec)`; the page boots, hydrates, pulls. Existing:
   `Deps.Events.EmitTo(dst, ChannelTabsInbound, nil)`, then `Windows.Focus(dst)`.
7. Return `{WindowKey: dst, Created}`.

`TabsService.Terminals TabTerminals{ Reown func(id, from, to string) bool }`, set in appwire from
`terminalRegistry.Reown`; zero value: terminal moves refused (`E_CONTRACT` "this build cannot move
terminals"). `Inbound` pops and returns the entries (empty slice, never nil). `Forget(key)` drops an
inbox (window closed before pulling). `Targets` sorts live non-ephemeral `geo` by `Order`, numbers from 1,
drops the source. `Capabilities` = `{DragOut: Windows.Geometry != nil && Windows.Positions()}`.
`CloseEmptyWindow`: source live non-ephemeral, at least one other live non-ephemeral window,
`Tabs.List(key)` empty; then `Windows.Close(key)`, true. Otherwise false, no error.

### 4.7 `internal/terminal` (session hold, re-own, adopt)

`BoundService.svc()` builds a fresh `Service` per call (`bound.go:91`), so move state lives on the
shared `Registry`.

- `session.go`:
  - `Session.windowKey` (guarded by `Registry.mu`); `Open` sets it and the unregister closure calls
    `r.removeSession(p.ID)`, which looks the key up on the session instead of the captured
    `p.WindowKey`.
  - `Registry.outs map[string]*outputCoalescer`, `trackOutput(id, c)` / `untrackOutput(id)`.
  - `Reown(id, from, to string) bool`: under `r.mu`, id must be in `byWindow[from]`; move it to
    `byWindow[to]`, set `sess.windowKey`, set the coalescer's `pending = to`. Fires `OnChange`
    unchanged (count is the same). False when the id is not live under `from`.
  - `ForgetMoves(key)`: drop coalescer holds whose owner or pending target is `key` (their
    sessions die in `CloseWindow(key)`; order between the two does not matter). Appended to `OnWindowClosing` after `CloseWindow` (harness: `App.CloseWindow`,
    `flowharness/harness.go:579`).
  - `Hold(id)`, `Adopt(id, key)`, `Release(id)`: look up `outs[id]`, delegate.
- `service.go` `outputCoalescer` gains `mu sync.Mutex` and `end int64`, `held bool`,
  `pending string`, `buf [][]byte`, `bufBytes int`, `truncated bool`, `final *outputCoalescerFinal`.
  - `flush` runs under `c.mu`: held: append (drop oldest past 1 MiB, `truncated = true`), record
    `final` when done; else `end += len(data)` and `EmitTo(windowKey, ..., End: end)` inside the lock,
    so the reported `end` and emission order agree. `appevent.Coalescer` is untouched: setting `held`
    under `c.mu` alone splits "emitted" from "held" exactly, since every flush takes `c.mu`.
  - `hold() (end int64, err)`, `adopt(key) (AdoptResult, err)` (key must equal `pending`; then
    `windowKey = key`, clear hold, return buffer and final), `release()` (one event with the buffer to
    the current `windowKey`, then the final if any, clear hold).
  - `OpenWithCoalescedOutput` tracks the coalescer; the exit final untracks it unless held (then
    `adopt`, `release` or `ForgetMoves` untracks).
- `bound.go`: `Hold`, `Adopt`, `Release` with `ipcerr.Required`/`Contract` as in section 3.
- `apps/kira-space/internal/bridge/terminal.go`: nothing beyond regenerated bindings (the bridge
  embeds `*terminal.BoundService`).

## 11. Unverified on macOS, Windows and Linux X11 (manual checklist for the user)

Run on a real build with two Kira windows side by side, then overlapping:

1. Tear a Studio tab off onto empty desktop: new window opens under the cursor with the tab active.
2. Drag it back onto the first window's strip, then onto its body: attaches at the end, active,
   window comes to front (Windows may only flash the taskbar: foreground lock).
3. Overlap two windows, drop on the overlap: last focused wins.
4. Tear off the only tab of a window while another window exists: source closes.
5. Esc while outside the window, then release: nothing moves.
6. Incognito tab: moves, stays incognito, never persisted in either window.
7. Second monitor, mixed DPI (Windows): new window lands on the monitor under the cursor.
8. Windows: maximised source, and drop on the source's own title bar: no-op.
9. Linux X11: frame versus client inset (GTK may report client size; point off by the title bar).
10. Wayland: drag out does nothing; menu "Move to window" works.
11. Runs terminal running `top` (or an agent TUI): tear off; target shows the same screen, keeps
    updating, typing works; first window closed afterwards: terminal survives.
12. Runs terminal printing fast (`yes | head -c 5000000`) during the move: no gap except the
    truncation notice; no duplicated lines beyond a few on the 2 s timeout path.
13. Phone holding an agent terminal (mobile take-over): move it; phone keeps control.
14. New-window button: icon only, tooltip "New window" with ⇧⌘N, screen reader reads "New window".
