### Answers

1. Prepare for kube: yes. Kube args are structured; prepare returns a subset of the same args, through
   the same validation and clamps, before the card. The card shows the final read with each
   script-set field underlined and listed in Details "Set by script". User approves what runs, as
   with API. Prepare can never change `clusterId`, the tool or the verb: those are not prepare keys.
2. Allowed prepare keys, per tool:
   - `kube_list_resources`: `kind`, `namespace`, `labelSelector`, `maxRows` (clamped 1-2000).
   - `kube_describe`: `kind`, `namespace`, `name`.
   - `kube_pod_logs`: `namespace`, `pod`, `container`, `previous`, `timestamps`, `tail` (clamped 1-5000).
   - `kube_discover`: transform only (no data-bearing args).
   - `kube_list_clusters`: no `script` argument.
   - No `script.input` (API's free JSON input): kube args are few and typed; kept values cover chaining.
   - Unknown key or wrong type: refused, nothing read (same shape as `applyPrepared`).
   - Required args stay required after prepare (`kind`, `name`, `namespace`, `pod` per tool).
3. Transform returns: global `result` = the JSON the tool returns today; global `request` = the final
   args (after prepare, without `clusterId`). Agent gets
   `{kind:"script", output, input:{tool, rowCount|lines, truncated}, kept, keptNotSaved}`. Input cap
   8 MiB, output 4 MiB (DB constants). Kube has no result review, so `commit` runs right after a
   successful transform.
4. Secret masking: kube reads refuse secret and user-typed kept values (reuse `queryKeptNotAllowed`
   shape, kube wording). So kube scripts never hold a Kira secret and kube-kept values are always
   non-secret. Cluster data keeps today's redaction (describe Secret bytes only). Logs stay unmasked;
   card shows a neutral info line on `kube_pod_logs` and on describe of `v1/secrets` (shots 6, 5).
5. Chaining across kube calls: kube transform `kept.set("pod", ...)`, next kube prepare
   `kept.get("pod")` (shot 8). Across MCPs: kube-kept entries carry Source{Kind script, MCP `kube`,
   Tool `kube_*`, Request `<context>: <kubectl command>`}; API reads them via `{{kept.pod}}` or
   prepare (shot 9), DB via `params` or script. Kube reads values kept by API or DB unless secret or
   user-typed.
6. Shared versus new:
   - Shared, unchanged: `jsengine`, `checkScript`, `execScript`, `scriptsOn`, refusal texts,
     `keptRunFor` and the whole `keptRun`, `watchKept`, transform view payload
     (`apiScriptPayloadOf`), op log rows `jsPrepare`/`jsTransform`, frontend `ChainSteps`,
     `KeptVariablesPanel`, `JsScriptBlock`, `TransformScriptBlock`, P715 card parts.
   - New: kube script args and `applyKubePrepared`, `kubeRun` script and kept steps, kube payload
     fields, `KubeRequestLine.vue`, `KubeReadDetails.vue`, kube verdict and risks in `kinds.ts`,
     prompt suffix and arg texts.
7. Scripts under `allow`: they run today with no card for both API (prepare even runs before the
   decision) and DB. Recommendation: kube does the same. Reasons: sandbox has no network; prepare sets
   only what the agent could pass itself; transform reshapes data the agent would get anyway; kube
   reads touch only non-secret kept values; op log records each run.

Every element maps from P715; no kube-only layout.

- Header and queue: unchanged P715 (title, "1 of N", Deny all).
- Connection row: `ClusterIcon` (exists, simple-icons Kubernetes mark), cluster context name, muted
  `server · namespace` (`All namespaces` when empty). No colour line: clusters have no colour (open

- Verdict row: kind badge `Read` (hue read, eye icon, lock), tooltip "Read-only: Kira sends only GET

  cluster or the tool. Countdown right.
- Focus box, in order:
  1. `ChainSteps` when kept values are read: earlier step (`<context>: <kubectl>` from the kept

     `api-resources`), resource plural bold with group muted (`deployments.apps`), name; one flag per

     colour, operator meta, value string), `-c`, `--previous`, `--tail`, `--timestamps`. Script-set
     field: amber dotted underline, tooltip "Set by the prepare script". Discover: two rows

- Warnings (neutral info lines): logs "Log lines reach the agent as written; Kira masks nothing in

- Details (collapsed, `KubeReadDetails.vue`): Command (full kubectl with `--context`), Server, Options

## Tool arguments and prompts (`internal/llmprompts/registry.go`)

New entries, terse, checkprompts style rules, budget lines added to `testdata/budget.tsv`:

- `dbmcp.tool.kube.scripts` (KindSuffix, title/purpose/usedBy keys like `DbmcpToolRunQueryScripts`
  :901), shared by the four read tools. Draft (about 700 runes):
  "Optional script, JavaScript run by Kira in a sandbox: no network, files, timers or console; Date is
  fixed for the run and UTC; 2 s and 256 MiB. Each is a function body that ends with return. The user
  sees both scripts. script.prepare runs before approval and returns args that replace yours; it
  cannot change clusterId or the tool. script.transform runs on the result in the global result; you
  receive only {kind: \"script\", output: <its return value>, input}, never the result unless it
  returns it. Result input up to 8 MiB, output up to 4 MiB. Kept: kept.get(\"name\") reads a kept
  value; kept.set(\"name\", value) in transform keeps one (1 MiB, 16 per run), for a later kube,
  api_request or run_query call. Names are literal strings. Secret kept values and values the user
  typed cannot be read."
- Args per tool: `script` (~70), `script.prepare` (per tool, lists its keys, ~150),
  `script.transform` (~120, names `result` shape per tool). Discover gets `script` and
  `script.transform` only.
- Goldens: `go test ./internal/llmprompts -run TestGolden -update`. i18n title/purpose/usedBy keys in
  `en.json`.
